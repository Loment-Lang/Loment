# 314 · 域进入代码：`domain` 块、值的空间、自动守卫

> 状态: **设计稿**（2026-11-07）
> 上游: `docs/306`（形状/极性/时律）· `docs/307`（语境类）· `docs/308`（嵌套）
> 一句话: **域不再只是文件顶部的声明，它是一个 `{}` 块；块里的访问自动受它检查。**

---

## 0. 问题

0.1.5.1 的域是这样写的：

```rust
capability blk_write : disk[0..4]

fn write_slot(slot: u32) -> u32 {
    guard blk_write(slot);
    return slot;
}
```

它有三个毛病，都是"声明"与"代码"分家造成的：

1. **域是环境权威**：声明一次，单元里任何函数都能 `guard` 它，谁在什么语境下用它看不出来；
2. **域不进入代码**：除了那一行 `guard`，域对块的其余语句没有任何约束——`a[i]` 照旧裸访问；
3. **寿命没有载体**：`consumed` / `witnessed` / `reachable` 的状态是全局表，循环第二圈就耗尽，
   而"这一轮"这个概念在语法里不存在。

结论：域的载体必须是**代码块**，不是文件顶部的一张表。

---

## 1. 三层模型

| 层 | 写法 | 作用域 | 用途 |
|---|---|---|---|
| 项目 / 单元 | `capability c : space[lo..hi] …` | 整个单元（顶层保留） | 整份程序共享的权威声明 |
| 块 | `domain d : space[lo..hi] … { … }` | 只在 `{}` 内 | 一段代码的局部权威，寿命 = 块 |
| 值 | `let a: [u32; 64] in space` | 这个绑定 | 让访问**自动**落到块的域上 |

顶层 `capability` **不删**：它声明的是整个项目/单元共享的东西，合法。
`domain` 块补的是"这一段代码里的权威"，两者并存。

---

## 2. 语法

```rust
fn fill(a: [u32; 64] in disk, b: [u32; 16] in disk, i: u32, j: u32) {
    domain buf : disk[0..63] {
        a[i] = 1;        // 自动 guard buf(i)
        guard buf(j);    // 显式守卫仍然可用
        b[j] = 2;        // 同一个空间、同一个块 -> 也走 buf
    }
    // guard buf(i);     // 编译错误：buf 不在作用域
    // a[i] = 3;         // 不受 buf 管（块外）
}
```

要点：

- 块名 `buf` 只在 `{}` 内可见；块外引用它是编译错误。
- 空间写在**值的绑定上**：`let a: [u32; 64] in disk`、参数 `a: [T; N] in disk`、
  `let p: ptr in mem`。只有数组 / 切片 / 指针可以带空间。
- `domain` 的名字可以省略：`domain disk[0..63] { … }` 是匿名块（没有 `guard` 可点名的名字，
  但自动守卫照常生效）。
- 形状与时律的写法与 `capability` 完全一致（`[()..hi]`、`epoch(N)`、`consumed(1)`……）。
- 嵌套：同一个空间的内层域必须**落在**外层形状里（`docs/308` C1）；跨空间可以自由嵌套。

---

## 3. 自动守卫

块内每条**下标访问**（`x[i]`、`x[i] = …`、切片下标）如果满足：

1. `x` 是本块的绑定，且它的空间等于某个外层 `domain` 的空间；
2. 取**最内层**的那个域；

那么在按下标取址之前自动插一次 `guard`：

```
a[i]        ->  guard buf(i);  a[i]
```

- 显式 `guard buf(i);` 仍然可以写；它和自动守卫是同一条判决，重复不会"多扣一次"
  （无状态域）—— 但**有状态域按次数扣**，所以块里同时写显式和访问，会扣两次。
  这条写进诚实边界。
- 失败即 trap，且不写审计（`docs/146` 属性 1/2 不变）。
- 指向别的空间的访问不受影响；没有空间标签的绑定不受影响。

### 3.1 嵌套链

同空间嵌套时，自动守卫检查**整条链**（外层先、内层后），但审计只记被点名的那一层
（`docs/308` §1.2 / §1.5）：

```rust
domain whole : disk[0..63] {
    domain half : disk[0..31] {
        a[i] = 1;    // 先判 whole(i)，再判 half(i)；只给 half 记一条审计
    }
}
```

---

## 4. 寿命与状态

`domain` 块是**实例**，不是常数表：

- 进入块 = 新实例开始；退出块 = 实例结束。
- 有状态的域（`consumed` / `witnessed` / `reachable`）的状态在**当前栈帧**上分配
  （块入口一条 `alloca`），因此：
  - 循环每跑一圈都是新实例——"这一轮用过没有"第一次可以写出来；
  - 递归的每一层各有一份，互不干扰。
- 无状态的域不分配任何东西。

顶层 `capability` 仍用全局表（它没有实例的概念）。

---

## 5. 审计

审计表按**声明点**编号：顶层 `capability` 与每个 `domain` 块各占一格，总数在编译期确定。
`域内通过 ⇒ 审计 +1` 的旧性质不变；块的实例寿命不影响审计（审计是累计的），
这与"状态随块重置"是两件事，分开写清楚。

---

## 6. 实现

两个实现都要改（`tools/lomentc.py` 与 `loment/selfhost/*.lomt`），判据仍要求逐字节一致。

| 层 | 改动 |
|---|---|
| 语法 | `let` / 形参类型后可选 `in SPACE`；语句 `domain [NAME :] SPACE[shape] [law]? { … }` |
| 检查器 | 域的词法作用域；嵌套包含（C1）；有状态域宽 ≤ 64；`guard NAME` 先查作用域再查顶层能力；自动守卫的绑定分析 |
| IR | `@__loment_guard2` 多一个 `state` 指针参数（无状态传 `null`）；块域的 `alloca [W x i64]`；审计表按声明点数定长 |
| 自举 | 同上，按 token 扫；变量的空间表 + 域作用域栈 + 下标发射时插守卫 |
| 生成物 | 种子与 genesis provenance 按既有流程重算 |

两条实装时撞出来的约束，记在这里：

- **`domain` 是上下文关键字**，不是保留字：只有 `domain NAME : SPACE[` / `domain SPACE[`
  才算块。理由很实际 —— `lompi/store/internet/0.1.0/sock.lomt` 有 `sock_new(domain: u64, …)`，
  把 `domain` 整个收走会让一份已经发布的库编不过。
- **PE 的栈提交抬到 8 MB**（`tools/lomelf.py`）：Windows 在"保留够、提交不够"时**不替
  进程长栈**，而自举编译器的递归下降在 `std/ansi.lomt` 这类大单元上要得更深 ——
  1 MB 直接访问违例（ELF 的 8 MB 默认栈没这个问题）。判据在 `loment_pe_test` 的头部自洽里。

## 7. 判据（每条先红）

| 判据 | 喂什么 | 期望 |
|---|---|---|
| 作用域 | 块外 `guard d(i)` | 编译错误 |
| 自动守卫 | `a[i]` 越界（空间相符） | 运行期 trap；同一下标在值上不 trap |
| 空间不符 | `b[j]`（另一个空间） | 不检查、不 trap |
| 每帧实例 | 循环里 `consumed(1)` 每轮 guard 一次 | 每轮都通过（不是只第一轮） |
| 递归 | 递归函数里各 guard 一次 | 每层都通过 |
| 嵌套包含 | 内层形状超出外层 | 编译错误 |
| 链式判决 | 外层拒绝、内层本可通过 | trap（外层先判） |
| 只记叶子 | 两层链守一次 | 只有内层审计 +1 |
| 双子 | 同一份源 | 两套实现 IR / Potato 逐字节一致 |

## 8. 诚实边界

- **空间标签不进类型**：`[u32; 64] in disk` 传给 `[u32; 64]` 形参后，标签就丢了；
  被调函数里的访问不会自动受检。要把权威传下去，用 `docs/307` 的线性票（未实装）。
- **自动守卫只覆盖直接下标**：`ptr_add(p, i)` 这类裸指针运算不经过域。
- **显式 + 自动会扣两次**（有状态域）：它们是一次判决的两个入口，不是去重的一对。
- **闭锁 / 撤销级联**仍是设计（`docs/306` §3.3、§6.1）。

---

## 9. 这一版没做的（补在 §8 之后）

- **Potato 形式对象里还没有块级域**：`domains` 列的是顶层 `capability`；
  块级域不进 form object（两个实现一致）。要让发布出去的清单也答"这个块碰了什么"，
  得给 form object 加一条带作用域的条目 —— 那是下一个版本的事。
- **空间标签不过调用边界**：`a: [u32; 64] in disk` 传给 `[u32; 64]` 形参后标签就没了，
  被调函数里的下标访问不会自动受检（§8 第一条）。
- **显式 + 自动会扣两次**：有状态的域在块里既写 `guard` 又访问同一位置时，两次都会记。

## 10. 下一步：域循环（`docs/315`）

块本身只围住一段代码；**遍历**它的是 `domain:for`：

```rust
domain buf : disk[0..7] consumed(1) {
    domain:for i { a[i] = a[i] + 1; }   // 头一次守卫，回边推钟
}
```

`domain:for` 是**透明的一层**：它不占审计槽、不切断外层域；体内同位置的访问不再
重复守卫。回边自动 tick 与 `choose domain_clock_explicit` 的逃生舱也在那一页。
