> 一句话: **在 `choose lvm_dismemory_true` 下，内存里没有"地址"这个东西 —— 指针不是数，
> 是一颗**体**的句柄；访存只能发生在体内，离开体是 fault 而不是"走到隔壁"。
> 体被藏进一个**不重叠的三维格子**里；程序看不见坐标，但移动体（重定位）永远不会
> 留下悬空指针 —— 因为没有任何指针编码过位置。**

## 0. 为什么不是"坐标即地址"

把线性地址换成 `(x, y, z)` 只是换了一套编号：程序仍然可以问"隔壁是什么"、可以算
"加 8 个字节"、可以把指针转成整数再转回来。**那还是地址**。

本档把三件事一起拿掉：

1. **数域里的地址**：`ptrtoint` / `inttoptr` 不是 no-op，是 **F04**；
2. **跨体的算术**：一个句柄加一个整数只在**它自己的体**里移动；离开体是 **F01**，
   不是"进入下一块内存"；两个体的相减/比较是 **F05**；
3. **可观察的位置**：体在三维格子里的坐标**不进程序**（没有内建函数能读），
   只在诊断与台账里出现；重定位因此是**免费的**（没有指针要修）。

"三维"不是装饰：体是**实心长方体**，任意两个活体的体积**不重叠**（空间排他）；
排版是确定性的；重定位会把体搬到新的位置。程序能感到的只有"我的器官还在"，感不到
"我在哪"。

## 1. 模型

### 1.1 体（body）

一次分配（全局 / 栈帧 / `alloca` / 堆块）产生一颗**体**：

```
body = { id, gen, kind, origin (x,y,z), extent (dx,dy,dz), bytes }
```

* `kind` ∈ {global, frame, alloca, heap, heapspan}；
* `extent` 由 `size` 定：`dx·dy·dz ≥ size`，三轴尽量接近立方（`ceil(size^(1/3))`）；
* `bytes` 是体的内容，长度 = `size`；**体素**是 `extent` 里 `offset < size` 的那些格子；
* `origin` 由排版器决定（§1.3），**不暴露给 guest**；诊断与台账可以打印它。

### 1.2 令牌（token）

guest 侧的"指针"是一个 64 位**不透明令牌**：**值里既没有体的编号，也没有偏移**。
它的唯一含义是"运行期令牌表里的那一行"：

```
 0xD1 | serial(48)      —— 序号单调递增、**永不复用**；表把令牌映射到 (体, 偏移)
```

* 表的另一边 `(体编号, 偏移)` **只活在运行期**：诊断能打印，guest 拿不到；
* 代码引用（`@fn` / `call %fp`）是**另一张表**，不参与内存令牌表 —— 两个域不混；
* `0` 不是令牌（它是 `null`）→ **F03**；
* **索引不是"给令牌加字节"**：`getelementptr` / `add` 在表里**派生一个新令牌**
  （查表 → 新偏移 → 查/插表）。同一个 (体, 偏移) 只发**一个**令牌，所以
  `a[i]` 取一万次也只烧一个序号；
* **指针域是闭的**：令牌只能来自分配、内存里的复制、或体内派生；`inttoptr` /
  `ptrtoint` 被拒（F04），随便一个整数进不来；改令牌位的算术也被拒（F04/F05）。

### 1.7 身份：序号、退休与耗尽

令牌里**没有可复用的字段**：序号 48 位，从 1 开始、只增不减、**永不复用**。于是：

| 资源 | 预算 | 到顶/退休时 |
|---|---|---|
| 令牌序号 | 2^48（约 2.8e14） | **F06**（106），点名；不会回绕 |
| 令牌表 | 运行时内存 | 表满 ⇒ **F06**；不静默驱逐活令牌 |
| 体内偏移 | 32 位（4 GiB/体） | 申请更大的体 ⇒ **F06** |
| 体编号 | 运行期内部（Python int / 引擎自己的表），**不进值** | 只受内存限制 |

* **没有代号，也没有 ABA**：体退休时把它名下**所有令牌**从表里删掉；旧令牌从此
  "不在表里" ⇒ **F02**。序号不复用，所以旧令牌**不可能重新指到一颗新体** ——
  ChatGPT 提的那个"代际回绕 / 身份复用"在这里被结构性地消掉了，而不是靠代号位。
* **墓碑**只服务诊断：退休的令牌记住它最后的体（有上限的环形），打印时能说"它曾属于
  #N（alloca）"；墓碑不参与任何判决。
* **派生去重**：同一个 (体, 偏移) 只有一个令牌（表里正反两张映射）。热循环里的
  `a[i]` 不烧序号；只有**不同的引用点**才消耗。
* **重定位**只改 §1.3 的隐藏坐标，令牌与表一行都不动。
* **不主张无限**：2^48 是"够长"，不是"没有顶"。真到顶是 F06 —— 显式失败，不是静默
  复用。

### 1.3 排版与空间排他

* 三维格子是稀疏的整数格；一颗体占据一个**实心长方体**；
* 排版器按体 id 顺序 first-fit：从原点起、沿 z→y→x 找第一块**完全空**的盒子；
* **任意两个活体的盒子不重叠**（判据会穷举检查）；边界相接是允许的，但相接不产生
  任何可达性 —— 访问只在**自己**的 `offset < size` 里；
* `--dismemory-relocate-every K`：每 K 步把全部活体按新基准重排一次（K=0 关闭）。
  句柄不变；测试要求 K=0/1/7 的 stdout / 退出码 / 台账逐字节相同。

### 1.4 访存与算术

| 操作 | 规则 |
|---|---|
| `load`/`store` 宽度 `w` | 解码句柄；体活且 gen 相等（否则 F02）；`offset + w ≤ size`（否则 F01）；`offset` 映射到体素，越界行给出体素坐标 |
| `getelementptr` / `add` / `sub`（句柄 ± 整数） | 体内偏移算术；结果 `offset' ∈ [0, size)`，否则 F01 |
| `sub` 句柄 − 句柄 | 同一颗体 → 整数偏移差；不同体 → F05 |
| `icmp eq/ne` | 允许（body+gen+offset 相等） |
| `icmp` 有符号/无符号序 | F05（没有地址序） |
| 其它算术（`mul`/`and`/`or`/`xor`/`shl`/`lshr`/`sdiv`/…）含句柄 | F04（句柄不是数） |
| `ptrtoint` / `inttoptr` | F04 |
| `brk` | 只认"堆体的句柄 + 偏移"：`brk(0)` 返回堆体句柄；`brk(h + n)` 把堆体长大到 `n`（必要时重定位，句柄不变）；给别的句柄 → F05 |

### 1.5 帧、全局与堆

* **全局**：每颗一个体（kind=global），永不归还；`@g` 的值是它的句柄；
* **栈帧**：每次调用一颗体（kind=frame，`FRAME_SIZE`），`Frame.base` = 句柄 + 0；
  `alloca` 在同一颗体里要偏移；返回时体退休（gen+1），旧句柄 → F02；
* **堆**：`brk` 管一颗**堆体**（kind=heapspan），来宾分配器把空闲链写在里面；
  堆体长大 = 重定位，句柄不变；`alloc` 的返回句柄是堆体内的偏移；
* **`alloca` 单独成体**（与参考实现今天的行为一致）：kind=alloca，返回时一并退休。

### 1.6 与其它安全层的关系

* `dismemory` 与 `sw_cap` / `sw_tag` / `lms` 的**运行期检查**不叠加：本档自己的规则
  已经覆盖"谁能碰"（只有自己的体）与"碰哪"（体内偏移）。`--substrate` 必须为 `none`；
  写了别的基质 → 点名拒；
* 它与 `gc` **正交**：重定位不是回收；体退休沿用分配器的 `free`；
* 它与 `fp`（间接分派）**不冲突**：代码句柄是另一域，直接 `@fn` 与 `call %fp` 照常；
  但 `ptrtoint @fn` 是 F04（要构造函数指针就给 `@fn` 本身）。

## 2. 怎么激活

```loment
choose lvm_dismemory_true
```

* 它是第五维 `lvm` 的**第三个取值**（`lvm` / `no_lvm` / `lvm_dismemory_true`）；
* 参考编译器在 IR 末尾发一行 `; loment-memory: dismemory`（与
  `; loment-gc: no_gc` 同一条路）；Potato 的第五维记成这个取值；
* **LVM** 读到这行就切进本档；没这行 = 今天的 LVM，行为逐字节不变；
* **原生档拒绝**这行（`lomelf` / `lomelf.lomt` 同名错误）：原生有地址，
  没有这套体/句柄语义 —— 让它"照常编出来"才是静默错编；
* 自举编译器与参考编译器必须接受同一个取值、发同一行 marker（孪生）。

## 3. 失败面

首行与 `docs/362` §3 同一形状，详细块用 Lomenterr 的块形；新增两个码：

| 码 | 名字 | 退出码 | 首行 |
|---|---|---|---|
| **F01** | `BOUNDS` | 101 | `lvm: F01 bounds violation at fn:blk#idx (offset=40 size=4 limit=16)` |
| **F02** | `DANGLING` | 102 | `lvm: F02 dangling reference at fn:blk#idx (token=0x… retired)` |
| **F03** | `NULL` | 103 | `lvm: F03 null dereference at fn:blk#idx (size=4)` |
| **F04** | `NOADDR` | 104 | `lvm: F04 no addresses at fn:blk#idx (a handle is not a number: ptrtoint)` |
| **F05** | `NOORDER` | 105 | `lvm: F05 no address space at fn:blk#idx (subtract two bodies)` |
| **F06** | `LIMIT` | 106 | `lvm: F06 identity exhausted at fn:blk#idx (token serials exhausted)` |

详细块（F01 的例子）：

```text
error[F01]: 越出体的体积（这一档没有"隔壁"）
  --> IR:main:entry#12
   | 令牌：0xD1.0000_0000_0000_0028
   | 体：heap（只报类别，不报编号与位置）
   | 访问：令牌内偏移 40，宽 4
   |
   = 事实：体是实心长方体；任何跨越体表的访问都是 fault —— 不是地址空间的下一页。
   = 建议：检查下标；要跨越多个体，就用多个令牌 / 显式链接，而不是加法。
```

**详细块不能成为第二条观察通道**（`docs/371` §3.5）：它只报**令牌相对**的事实
（令牌、体类别、体内偏移、宽、是否退休、站点），**不报体号、不报坐标、不报体素**。
判据 K 把同一故障在 K=0/1/7 下的整段 stderr 逐字节比 —— 文案里任何对排版的依赖
都会在那里现形。

### 3.5 可观察代数与可辩护的主张

"没有地址"这句话只有在说清**对谁**没有地址时才可证伪。本档的**可观察代数 O** 是：

> **O =（stdout 字节、stderr 字节、退出码、syscall 返回值、每步寄存器）。**
> 排版不在 O 里；令牌的值、体号、坐标、体素、墙钟也不在 O 里。

**主张（窄的、可辩护的）**：存在一个 guest 语义，其中
1. 指针值是**不透明令牌**，其代数里没有"地址"（无加法换址、无跨体序、无整数互转）；
2. 隐藏三维排版**不通过 O 的任何一项**可观察 —— 故障详细块与时钟都按令牌/指令数
   归一（K/L 判据）；
3. 因此"屋子里有没有外面"在 O 上**不是一个可以回答的问题**：外面的存在影响不到
   O 的任何一项。

**它不主张**："三维格子不存在"或"物理上不可能存在地址" —— 那是形而上学的说法。
**下一步（未做）**：
* **布局双模拟**：对**所有**程序、所有合法排版给同一份 O —— K 抽样只是证据；
* **硬件**：真硅的缓存/DRAM 延迟仍按布局泄漏时间；要连这一半也钉死，只有
  **均匀延迟阵列**（或把时间从 O 里拿掉）才行；
* **令牌序号**：十六进制里的序号给出分配先后（身份序，不是空间序）—— 要在 O 的
  定义里明确它算不算可观察。

**时钟的换算与量程**：虚拟钟的单位是「1 条已执行指令 = 1 ms」（*不是*说要花 1 ms，
只是给时间一个确定的标尺）。于是 **`lgc` 的毫秒预算在 dismemory 下就是步数预算**，
两边按同一个除法读。量程：镜像的 `C_STEPS` 与参考的 `executed` 在 `STEP_CAP`
（5×10⁷ 条）之前都不会溢出 32 位；越过 `STEP_CAP` 本来就点名拒，不给钟先撞上限。
`201` 的虚拟**绝对值**从 0 起，很小 —— **绝对值不是判决面**（与 `docs/243` §3.4
"只比先后与差"同一条口径）；拿它当墙钟是误读。

**今天还漏着的一条（诚实写）**：syscall 的指针实参要写成 `ptr as u64`，而那是
`ptrtoint` → **F04**；所以 dismemory 的 guest **今天没有任何 I/O 路径**（连 `write`
都过不去）。判据 L 因此用**退出码**观察虚拟钟。这不是模型的定义，是运行时还没给
"令牌实参"的 syscall 通道。补它的形状应当是**一小族带类型的指针入口**
（`sys_write(fd, p: ptr, n)` 之类，lowering 时 `ptr` 形参不 ptrtoint、直接把令牌交给
运行期解码；`print` 走同一条），而不是把 `syscall4` 开成一个无类型的 64 位口子。
那是 **L0/ABI 变更**：要单独一笔提交、在 `lom/net.lom` 或内建表里写清"指针实参在
dismemory 下是令牌"、留下游影响一行 —— 不顺手做。

## 5. 我不主张

1. **不主张这是商品级内存模型**：它是"地址不存在"的极端研究档；性能、碎片、并发都
   没谈。
2. **不主张句柄不可伪造到密码学强度**：tag + gen + body 让"随手一个整数"进不来，
   但生成器、RNG 与侧信道不在本档的威胁模型里。
3. **不主张三维排版是最优的**：first-fit + 立方体只是确定性的最小实现；后续的下一步才谈空间局部性、八叉树与重定位策略。
4. **不主张它能跑所有现有程序**：任何依赖 `ptrtoint`/跨体算术/地址序的程序会被
   F04/F05 拒掉 —— 那是本档的定义，不是回归。
5. **不主张“宇宙里没有地址”**：主张的是 §3.5 那条窄命题（guest 的代数与本体论里
   没有地址运算，且排版不进 O）；布局双模拟与真硅的均匀延迟都还没做。
6. **不主张 guest 今天能 I/O**：syscall 的指针实参是 `ptrtoint` → F04（§3.5 末尾）。
