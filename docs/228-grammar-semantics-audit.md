## 0. 一句话

**大部分是对的，但"对"是各门自己补出来的，不是核给的。** 七个整数语义里六个在**每一门**
都与真工具链一致；而**块作用域**与**负字面量的比较**这两处，`c`/`cpp`/`java`/`csharp`
在翻译器里**各自补偿**、`go`/`python`/原生**没有** —— 于是**同一份程序按哪种语法读，
会算出不同的数**。`docs/188` §0 那句"表层语法只决定拼法，不决定语义"在今天的代码上
**不成立**（filed as `#237`）。

## 3. 逐条判定

### 3.1 根一：核**没有块作用域**，各门自己补

`tools/trans_core.py:929-931` 明写着这件事：

> 外层已经有同名 ⇒ 源语言里这是**遮蔽**（块作用域），而本语言**没有块作用域** … 所以**改名**

于是 `c`/`cpp`/`java`/`csharp` 改名外提（`let y__1`），跑出来与源语言一致；`go` 不改名，
`python`/原生/`rust` 也没有 —— 三者的同形程序给 **50**，而 `cpp` 给 **10**（g++ 10）。

* **`#235`**（go 不补 → 静默算错）
* **`#234`**（c/cpp 的改名器在"遮蔽 + 初始化式引用旧名"时发出 `let x__1 = (x__1 + 100)` → 合法源**编不过**；2026-10-18 **已修**：初值在声明生效**之前**发射，右边读**外层**那个名，见 `docs/186` §5.2）
* **`#237`**（同一程序按不同语法给不同的数 —— `docs/188` §0 的反例）

### 3.2 根二：**负字面量**的比较

`if -1 < 0`：`c`/`cpp`/`java`/`csharp` 给 **1**（对），`go`/`python`/原生/`rust` 给 **0**。
**变量**写法（`let a: i64 = -1; if a < 0`）在**每一门**都对 —— 差在"负整数字面量进入比较时
怎么定型"，不在比较本身。已登记为 `#131`，但那条挂在 `choose write grammar c` 名下，
而 C 今天**已经修好**（实测 1）；核那一侧仍在（本文件 §4）。

### 3.3 csharp 独有：混合宽度比较静默收窄

`int x = 1; long y = 2147483647; if (x + y > 0) …` → C# 给 **7**，这一门给 **8**。
**同一份程序在 `grammar c` 上是对的**（7）—— 所以不是共享核的算术，是 C# 方言表这一格。
开为 **`#236`**。

### 3.4 子集拒收（都是设计，不是缺陷）

`++`/`--` 与 `+=`（c/cpp/java/csharp/go 全体）、混合宽度落绑定、Java 的多重赋值/
`switch`/`range`、Python 的 `and` 当值用、Rust 的再赋值（`#77`，两种拼法凑不出交集）。
这些一律**前门响亮拒**，不产错单元。

## 6. 诚实边界

* **Java / C# 的块作用域那格是 `n/a`，不是 `✓`** —— 两种语言**禁止**局部变量遮蔽
  （`javac` CS0136 / `dotnet` CS0136 一类），所以这个形状在那两门**写不出来**，
  装置也就比不了。**"测不到"不等于"对"**。
* **`natural` 与 `loment` 不在这张表里**：`loment` 是参考本身（没有外部对照）；
  `natural` 是我们自己发明的语法，它的对照是仓里现成的 `.nl`/`.lomt` **孪生对**
  （判据要求两边翻出来逐字节相同）—— 我单独跑过 `Sample` 47/47、`Surface` 24/24，**一致**。
* **Rust 那门的"对照"不对称**：它是**原生读法**（用户 2026-09-22 裁定），所以要**多抹一行
  `module <名>`** 才是合法 Rust。表里标"两边拒"的那格（隐式 `i32+i64`）是**写法本不在交集**，
  不是任何一方的错。
* 每门只跑了十类探针（C 那门另跑了 31 条对抗性边角）。**没跑到的不等于没有** ——
  `docs/211` 的 38 条就是那么来的。
