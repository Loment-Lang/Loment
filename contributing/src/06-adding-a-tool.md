# Adding a tool

Every tracked Python file under `tools/` is part of the release ledger. Adding a file is not
finished until it appears in **two** lists, in the **same position**. This is the registration step
that catches people first.

## The two lists

| File | What it is |
|---|---|
| `tools/loment_release.py` → `GLOBS` | The Python list of files that make up the tooling. |
| `loment/tools/lomrel.lomt` → `globs_text()` | The self-hosted copy of the same list, one path per line in one multi-line string. |

Two criteria compare them:

- `loment_tools_test::test_every_tool_is_in_the_release_manifest` fails when a tracked
  `tools/*.py` is missing from `GLOBS`;
- `loment_rel_test::test_lomrel_globs_match_python_globs` compares the two lists item by item,
  including order. The error can be "same set, different order" — the manifests would differ on
  disk while having the same length.

## The rule

1. Add the path to `GLOBS` where it belongs thematically.
2. Add the same line to `globs_text()` at the **same index**.
3. Run both suites.

```console
$ python tools/loment_tools_test.py
$ python tools/loment_rel_test.py
```

A tool that does not ship still belongs in the ledger. The ledger is not "what is packaged"; it is
"what can change without anyone noticing". Anything tracked under `tools/` is in it.

## What does not go in

- Test fixtures and corpora that the tooling reads. They are inputs, not tools; the ledger names
  the code that runs them.
- Generated artifacts (`loment/build/*.ll`, release manifests, `SHA256SUMS`). Those have their own
  flow — see [Releases](10-releases.md).

## Why the ordering matters

The release manifest is generated by walking the Python list; the self-hosted side normalizes the
same list from `lomrel.lomt`. If the two orders differ, the two manifests differ byte for byte
while naming the same files. The criterion reports it as a mismatch, and the fix is to move one
line, not to sort both lists.

## A worked example

This book's own tools went through it:

- `tools/loment_book_test.py` and `tools/lomentlings.py` were added when the usage book landed;
- `tools/loment_book_site.py` and `tools/loment_book_site_test.py` were added when the Pages site
  landed.

Both times the first gate run was red on `test_every_tool_is_in_the_release_manifest`, and both
times the fix was two lines in two files at one position. That is the intended cost.
