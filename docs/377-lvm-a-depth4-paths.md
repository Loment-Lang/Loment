# 377 · 深度 4：引用是**路径**，不是偏移

> 状态: **设计 + 参考侧实装中**（2026-11-22）
> 上游: `docs/375`（深度 3：体不再有连续字节数组）· `docs/368`（dismemory 的 O 与故障码）
> 判据: `lvm_dismemory_test`（新增路径判据）· `lvm_twin_test`（镜像同答）
> 一句话: 深度 3 把**连续字节数组**拿掉了，但令牌里仍然写着"体内第几个字节"；
> 这一层把它也拿掉 —— 引用 = 从体根出发的**类型化路径**（数组元素 / 结构字段），
> 没有"基址 + 偏移"这个运算，也没有可以加减的字节数。

---

## 1. 深度 3 之后还剩什么

`docs/375` §2 的第二层（L2）当时只做到"没有连续数组"：

* `Dismem.tokens` 的值是 `(body, off)` —— `off` 是一个整数，含义是"体内第几个字节"；
* `getelementptr` 用 `gep_offset()` 先算出一个**字节位移**再 `add_off`；
* 访存是 `cells[(off + k + shift) % size]`；`shift` 只是把这个字节号换个桶兜一圈；
* 系统调用读写一段内存，是"从令牌指向的字节开始，连续 n 个字节"。

这些都不是地址，但**仍然是位移**。用一个整数的加法和取模去指"下一个字节"，
与"地址 = 基址 + 偏移"在代数上是同一件事，只是把基址藏起来了。

## 2. 新概念：引用 = 类型化路径

> 一个引用不再指"体里的某个字节"，而是指**体的结构里的一个位置**：
> 从体根出发，依次经过若干步 —— 数组的**第 i 个元素**、结构的**第 f 个字段**。
> 每一步都带它所在容器的**长度**与元素的**宽度**，所以越界在**派生时**就拒绝。

### 2.1 路径

```
path ::= [ step, ... ]              -- 体根是 []
step ::= ELEM(index, count, width)  -- 数组：第 index 个元素（共 count 个，每个 width 字节）
       | FIELD(index, width)        -- 结构：第 index 个字段
```

* **没有字节偏移**：`ELEM` 的 `index` 是数组下标，`FIELD` 的 `index` 是字段序号；
  两者都不是"往前推多少个字节"。
* 每一步的 `count` / `width` 是从 **GEP 的类型** 得到的（LLVM 的 GEP 本来就带
  被指类型 T 的下标），不需要体的布局表。
* 令牌表里存的是 `(body, path, leaf )`，`leaf` 是最后一步的元素宽度（根路径用体长）。
  **表里没有一个"offset"字段。**

### 2.2 运算

| 操作 | 深度 3 | 深度 4 |
|---|---|---|
| `getelementptr T, ptr %p, i...` | 算出**字节偏移**再加到令牌上 | 把 `i...` 变成 `ELEM/FIELD` 步；越界（`i >= count`）**在派生时** F01 |
| `load/store T` | 在偏移处读写 `sizeof(T)` 字节 | 在路径这个**叶**上读/写；叶宽由路径给出 |
| 聚合 load/store | 当成一坨字节 | 按类型**逐叶**组装/拆开：体里永远只有叶，没有"聚合 blob" |
| `ptr_add` / `ptr_sub` | 体内偏移（允许） | **F04**：指针没有可加的整数；要下一个元素就写 `a[i]` / GEP |
| 令牌相减 / 比较 | 同体允许 | **F05**（没有地址空间，也就没有序） |
| 字节串（字符串 / I/O 缓冲） | 从令牌起连续 n 字节 | 只能沿 `[u8; N]` 的**数组轴**走：`p` 必须是某个 `ELEM`，`p+k` 是同一数组的下一个元素 |

第三条是这一层最容易被写歪的地方：`get_run` 不是"读 n 个字节"，而是
"沿着**那一根 u8 数组**取 n 个元素"。如果令牌指向的是 `[4 x i32]` 的某个元素，
对它做字节读是**字节重解释**，按设计 **F04**（这一档不主张能解释字节）。

### 2.3 帧与槽

帧仍然是一颗体（`docs/368` §1.5），但它的形状是 `[u8; FRAME_SIZE]`：
槽 = 这个字节数组的元素（`ELEM(slot_off, FRAME_SIZE, 1)`），值表区同理。
**"第几个槽"是数组下标**，不是地址；解释器没有任何"= 基址 + n"的量。

### 2.4 摆法与重定位

深度 3 的 `shift` 是"把字节号换个桶"，深度 4 没有字节号可换：
`--dismemory-shuffle` 保留 CLI 形状（脚本不炸），但**在深度 4 下是空操作** ——
体是一张 `path -> 叶` 的映射，没有物理布局可摆。判据 M 仍然通过（平凡地成立），
而它的**意义**从"表示层摆法不变"变成"没有表示层摆法这回事"。

## 3. 表示

### 3.1 参考 T0

* `_DismBody.cells: dict[path, bytes]` —— 键是步骤元组（步骤本身含 count/width），值是叶。
* `tokens: dict[token -> (bid, path, leaf)]`；`rev[(bid, path) -> token]` 仍做去重。
* `get/put` 是叶访问；`get_agg/put_agg` 用类型树递归拆/装；`get_run/put_run`
  沿 u8 数组轴走；`cstr` 是 run 到 0 为止。
* 故障详情报"路径长度 / 最后一步的 index / 类型"，**不报字节偏移**（那东西不存在了）。
  报文与重定位/摆法仍然逐字节不变（K/M）。

### 3.2 镜像（S6b）：路径摘要就是引用的身份

镜像不另存"步骤表"，它把**整条路径折成 64 位摘要**：

* 每个令牌带 `(dlo, dhi)` —— 路径的摘要；以及 `(plo, phi)` —— **去掉最后一步**的
  前缀摘要（推进同一根数组轴时用它与新下标重算，不必保存整条路径）；
  再加叶宽与最后一步的 `(kind, index, count, width)`（`DG_OFF`，与令牌表同下标）。
* `ELEM/FIELD` 各有一个 32 位步骤摘要；新路径 = `fold(前缀, 步骤)`。
  **没有任何地方存"体内第几个字节"作为引用的含义。**
* 去重表 `PH_OFF`（开放寻址）按 `(body, dlo, dhi)` 找令牌 —— 同一路径在两次派生
  里得到同一个令牌（`a[i]` 取一万次只烧一个序号）。
* 格的**物理下标**仍是 `GEP` 累加出来的字节序号（与 S2 的 `shift` 同一层：
  实现层的桶，不是引用的含义、也不是 guest 能看到的量）。聚合与字节 run 因此
  不需要第二套遍历；`MAX_DB/DT/DR/CT/PH` 用尽仍 F06。
* 数组/字段的计数来自 GEP 的类型文本（`arr_n` / `fld_ty`），越界在派生时 F01；
  `ptr_add/sub`、引用相减/排序在镜像里也是 F04/F05。

**诚实的一句**：参考侧"路径就是键"；镜像侧"路径的摘要是身份，字节下标只是
实现层的桶"。两边对 guest 给出同一个 O，但内部编码不同（与 S2 的摆法同一层）。

### 3.3 快照（S6c）

`CP_VERSION` 2。参考的 `flags = 3` 段把路径**逐步**写出来（令牌行与格行都带
`(kind, index, count, width)`）；镜像的同侧段写 `DG` 的九个字段（摘要/前缀/叶宽/
最后一步）并在装回后重建 `PH`。**同侧**的边界与 `docs/375` §2.5 一致：
参考的快照不喂给镜像（帧与路径编码两边不同），跨实现的 dismemory 快照不在命题里。

## 4. 判据

* **Q 路径派生**：`a[i]` 的越界在**GEP 时**就是 F01（不是等到 load）；`a[i].f`
  的路径步数与类型嵌套一致；同一个 `(体, 路径)` 只发一个令牌。
* **R 没有指针算术**：`ptr_add/ptr_sub`、令牌相减/比较都是 F04/F05 —— Loment 源里
  写不出这些，用**手写 IR** 钉（与 `docs/375` 同一条理由）。
* **S 字节重解释被拒**：对 `[4 x i32]` 做 `store8`/`write` → F04；`[u8; N]` 的
  run 正常。语料里的字符串与 I/O 全部走后者。
* **T 语义保留**：`docs/375` 的 M/N/P 语料在深度 4 下同答；快照往返同答（S6c）。
* **U 镜像同答**：孪生的 dismemory 语料、故障码/站点、快照（同侧）不变。

## 5. 不主张

* **下标仍是整数**：`a[i]` 的 `i` 还是整数，它只是"这一层数组里的第几个"；
  没有整数就没有数组。彻底没有整数 = 不可变树，现有程序全部不兼容。
* **不主张所有程序都能跑**：字节重解释、把内存当 blob 的写法按设计 F04。
* **不主张跨实现快照**：与 `docs/375` §2.5 同一条（帧的表示两边仍不同）。
