# 284 · 安全点强制重映射：把活着的帧链改指到新镜像（`#1152`）

> 上游：`#1146`（伞）、`#1151`（双槽装载器）、`#1149`（帧布局 + 调用点表）。
> 实现：`loment/lib/hotswap.lomt` 的 `hot_remap`；产侧：`tools/loment_hotload.py`；
> 判据：`tools/loment_hotcore_test.py`（6 条）、`tools/loment_hotload_test.py`（13 条）。

## 1. 为什么要它

`#1151` 只换了**槽表**：翻转之后**新**的调用进新镜像，可**已经在栈上的帧**还是旧代码，
它们返回时按旧偏移继续跑。对一个常驻的 LSP，这意味着"换完之后旧版本还在跑一会儿" ——
而 `#1146` 要的是**换完就是新的**。

v1 的做法是**安全点强制重映射**：在装载的那一刻，把整条帧链上每个返回地址改指到新镜像
的同一处调用点。不是"等旧帧跑完"，是**当场改**。

## 2. 帧链长什么样

`lomelf` 给每个函数发的序言是 `push rbp; mov rbp, rsp; sub rsp, frame`，于是

```
[rbp]     = 调用者的帧指针
[rbp + 8] = 返回地址（调用点之后的第一条指令）
```

栈向下长 ⇒ 沿 `[rbp]` 走上去，每个 `rbp` 都**更大**。走到 `[rbp]` 不比当前大就停：
那是根（`_start` 的调用者是入口桩/内核，那里的槽不是帧指针）。

## 3. 从哪拿到 `rbp`

语言没有"读当前帧指针"的内建，而固定核是 Loment 写的。唯一的入口是**入口闸**（`#1150`）：
它在每个函数入口被调用，`[rbp]` 正好是那个函数的帧指针，于是它把这 8 字节写进
`epoch + 8`（`docs/280` §1）。

**这个格子只有一次机会**：函数里只要调了任何东西，被调函数的闸就把它换成**被调函数
自己的**帧指针。所以 `hot_install` 的开头**一个 `call` 都不能有** —— 连 `l32` 都不行，
因为 `l32` 也是一次调用。取帧指针的那一段因此只用 `load8`（**内建，不发 `call`**）
自己拼出 `self_base`、`self_gate`、闸里那条 `movabs` 的立即数，再读 8 个字节。

> 这一条是执行面判据逼出来的：第一版把读取放进一个辅助函数 `snap_frame`，
> 拿到的永远是 `snap_frame` 自己的帧指针，整条链从第一步就错了。

## 4. 装载件里的两张表

`.lomhot`（`docs/279`）给了每个函数两张东西：**帧布局哈希**与**调用点表**
（`callee@序号` + 函数相对偏移）。装载件把两侧合成一张表（`docs/281` 的文件头）：

```
nfunc × (slot, self_entry, cand_entry, flags, ncalls, pad)
ncalls × (self_off, cand_off)      —— 按函数顺序、按调用点顺序
```

- 配对是**按位置**的：两侧的调用点 id 序列相同（`flags == 0` 的前提）时，第 k 个旧调用点
  就是第 k 个新调用点。序列不同就不配对，直接给 `flags = 2`。
- `flags` 是准入侧（`loment_update.remap_plan`）算好的结论：`0` 可映射 / `1` 布局变了 /
  `2` 调用点 id 序列变了 / `3` 一侧没有这个函数。

## 5. 规则

1. **只改表里有的地址。** 帧的返回地址与某个调用点逐字节相等才改；入口桩、外部代码、
   固定核里没有调用点的位置**原样留着**。
2. **拒绝发生在动手之前。** `hot_install` 先走一遍**只检查**的遍历：整条链上只要有一帧
   落在 `flags != 0` 的函数上，就整份拒绝，一个字节都不动。拒绝码是
   `(flags << 12) | 槽号` —— 调用方按槽号点名那个函数。
3. **比的是调用者的布局。** 返回地址落在**调用者**的代码里；旧帧被新代码按同一套 rbp
   相对偏移读，所以要让调用者的帧布局相同，而不是被调方的。
4. **先翻槽表、再改帧、最后发 `READY`。** 改完的帧一旦继续跑，它发出的调用必须已经走新
   槽表；`SWAPPING` 窗口里单线程不会有人插进来（多线程是拒绝条件，见 §7）。
5. **改了几帧要能看见。** `save + 16384` 记下写入的帧数，探针拿它断言"每一帧都到了"。

## 6. 换完之后：`hot_restore` / `hot_release` 不再可用

这是这一格**改变语义**的地方。一次成功的强制重映射之后，调用者恢复执行的位置在**新槽
里** —— 它已经不在旧镜像上跑了。于是：

- `hot_release(slot)`（`munmap` 新槽）会把**正在执行的页**撤掉，当场段错误；
- `hot_restore` 只能改旧镜像的槽表，而跑着的代码已经不看它了。

所以 `hot_restore` / `hot_release` 的适用面收窄成：**调用者没有被重映射时**（今天的拒绝
路径，以及将来固定核住进独立不换页区域之后）。回滚不再是 `restore`，而是**再装一次反向
的候选**（`#1157` 的"线上回滚"）。

判据里因此把 install / restore 拆成两条，不再串成一个"装完再撤"的探针。

## 7. 判据

| 判据 | 问法 |
|---|---|
| `test_every_live_frame_continues_in_the_new_image` | N = 1/2/16 层嵌套，换完之后**每一层**读到的版本常量都来自新构建？ |
| `test_the_swap_reports_one_epoch` | 装完 epoch 是 `READY`？ |
| `test_tampered_digest_is_refused` | 候选的闸改一个字节 → 返回 7，槽表与帧都没动？ |
| `test_slot_shape_mismatch_is_refused` | 槽表条数不同 → 返回 4，没装？ |
| `test_frame_layout_change_is_refused_by_name` | `nest` 多一个临时量 → 拒绝码点名它的槽，旧代码照跑？ |
| `test_call_id_change_is_refused_by_name` | `nest` 改调同形的 `nest2`（布局不变、id 变）→ 拒绝码点名？ |
| `test_gate_records_the_callers_frame_pointer` | 闸的 33 字节与文档逐字节相同、imm64 落在共享数据段？ |
| `test_the_blob_pairs_old_and_new_call_sites` | 装载件里每一对偏移都与两侧 `.lomhot` 对得上？ |
| `test_the_model_remaps_a_chain_into_the_slot` | 模型：整条链搬进新槽，表外地址一个不动？ |
| `test_remap_refuses_a_changed_frame_layout` | 模型：拒绝码 = `FLAG_LAYOUT << 12 | 调用者的槽`？ |

版本常量是 `nest` 函数体里的**字面量**：它变成 2 只能是因为那一帧真的在新镜像里执行。
副作用（每帧入口的计数器）必须恰好一层一次 —— 重映射不重放任何东西。

## 8. 这一版**不**做到的

1. **单线程。** 别的线程存在时应当拒绝；这一版没有实现线程计数，只在文档里钉住前提。
2. **布局变了的函数只能整份拒绝。** 没有任何帧在它上面时本可以放行（推迟到帧消失再换，
   tier B），这一版不做。
3. **没有语言层的 release/acquire。** 顺序靠 x86-64 的对齐 32 位 store + TSO，换到弱内存序
   的机器要补。
4. **不改 `[rbp]` 本身。** 帧布局相同是前提，所以保存的帧指针链不需要平移。
5. **固定核自己的返回地址也在链上。** `hot_install` 的返回地址落在调用者（探针的
   `nest`）里，所以它会被改写 —— 这正是"调用者恢复在新镜像里"的那一条。
