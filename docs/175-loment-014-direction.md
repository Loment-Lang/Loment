## 0. 一句话

**Loment 的核心继续保持小，长的是外层。** 模式（`choose`）是项目级不变量，
std 是**分层**而不是替换，多语法落在**前端**（产出 L1 文本）而不是核心 ——
三条都为了同一个目的：**让"Agent 写的东西能不能跑、能碰什么"变成可独立校验的**。

## 1. 为什么顺序不能反：兼容层是这件事的前提

用户已把顺序定为"**完成兼容库之后**"。这不只是排期，是**依赖关系**：

多语法前端要有一个能表达"那些语言干的事"的靶子。Python 调库、Rust 调 FFI、
Go 起进程 —— 这些 Loment 表面**表达不了**，只能靠出口：

| 出口 | 已有 | 位置 |
|---|---|---|
| `extern fn` + `--link` | ✅ 0.1.4-pre2 | `docs/173` |
| 进程桥 `use proc` / `proc_sh` | ✅ 0.1.4-pre2 | `loment/lib/proc.lomt` |
| 归档 / 动态库 / 运行期嵌入 | ⛔ 阶段 2/3/4 | `docs/173` §2 |

**先有出口，翻译才有意义。** 倒过来做，就是往一门还调不动 `numpy` 的语言里翻译 Python。

## 2. 定位修正：中心点是"能力域 + Potato 形式对象"

原文（用户 2026-09-17）是"抛向 AI 训练 / 系统开发的**绝对中心点**"。**AI 训练那一半是空的**：
数值 / BLAS / GPU 是十年的生态，Loment 赢不了，也不该去赢。

真正只属于它的中心点是一件事：

> **谁能在什么范围内跑什么，且这件事能被独立校验。**

| 资产 | 已有的东西 | 起什么作用 |
|---|---|---|
| **能力域** | `capability` / `guard` / `excluded` / `revocable`（`docs/146`） | 划定"能碰什么" |
| **Potato 形式对象** | v1 已强制导出 + **两份独立实现**交叉判定（`docs/147`） | 让"能碰什么"**不读源码**就能判 |
| **兼容层** | `extern` / 进程桥（`docs/173`） | 让划定范围内的外部调用真的发生 |

AI 训练与系统开发是**这个中心的消费者**，不是两门要各自精通的手艺。Agent 生成的代码
要能放心跑（训练侧）与要能进内核（系统侧），问的是同一个问题。

**顺带一处文档不一致**：`docs/140` §9.2 的表里 Potato 仍写"实现**闭源**"，
但 `docs/142` §1 记着 2026-09-08 用户已覆盖该决定（规范与实现**一并开源**）。
§9.3 的"闭源污染"硬理由因此**已经不成立**——它现在还在替一个死掉的反对意见说话。

## 3. `choose`：项目级模式与 GC 档（**每维恰好一次**，≤ 300 行）

### 3.0 定下来的规则（用户 2026-09-17；**2026-09-22 改了一次次数口径**）

| 情形 | 结果 |
|---|---|
| 不写 `choose` | **`std`**（默认）；GC 那一维见 §3.4（默认 `gc_manual`） |
| `choose std` | `std`，与不写等价；**建议写**（口径显式），但不强制 |
| `choose no_std` | **freestanding**，只能用核那一层 |
| **`choose` 写几行** | ~~写两次（任意组合）→ 报错~~ → **最多 300 行**（2026-09-22 用户放宽） |
| **同一维写两次** | **仍然报错** —— "每维一行"（见下） |
| **库写 `choose`** | **仍然报错**（这条没动，理由见 §3.2 第 1 条） |

**2026-09-22 这次放宽改的是什么、没改什么**：

- 改的是**总数**：原来"全项目恰好一次"太紧 —— 它把"模式"与"GC"两个**互不相干**的轴焊成
  一条规则，加第三档就得再破一次例。现在口径是**按维**：`choose` 可以写多行（上限 300 行，
  与 `use` 那条上限同一个量级、同一种"容量闸"形状），**每一维恰好一次**。
- **没改**的是那条规矩买到的收益（§3.1）：模式/GC 各自仍是**整个程序的不变量**，
  编译器照样能全局拦住"半 hosted、半不是"，Potato 对象里照样是一个字段。
  "每维恰好一次"就是把这个收益从一条规则挪成两条。
- **300 行这个数是"容量闸"，不是"你该写 300 行"**：今天只有两维（模式、GC），
  所以实际只会写 1–2 行。上限存在的意义与 `use` ≤ 300 相同 —— 让"无界增长"这件事
  在编译期有个明确的天花板，而不是等它哪天变成一张巨表。
- ⚠ **"每维恰好一次"是我按你"每维一行"那句推出来的**（同一维写第二次 = 报错，
  而不是"后写覆盖前写"）。若你要的是后者，说一声 —— 但那会**丢掉** §3.1 那条收益
  （最后一行说了算 = 读源码的人得读到最后才知道，校验器更是只能信最后一行）。

### 3.1 为什么是项目级，以及为什么这比 Rust 好

Rust 的 `#![no_std]` 是**按 crate**，组合起来会出问题。Loment 的单元模型
（库 = 目录、依赖 = 源码里的 `use`，`docs/168`）照搬 per-module 会掉进同一个坑。

**项目级 + 每维恰好一次**（§3.0 那张表：总数 ≤ 300 行）把每一维都变成
**整个程序的不变量**，于是白拿到两样东西：

1. 编译器能**全局**拦住"半 hosted、半不是"——这种混合在链接期才炸是最难查的；
2. 模式只是 Potato 形式对象里的**一个字段**，独立校验器**不读源码**就能判
   "该产物声明自己是 `no_std`，而它引用的原语全在 freestanding 子集里"。
   **这是"恰好一次"这条规矩真正的收益**，不只是防手滑。

### 3.2 三条要定死的规则（本文的主张）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | `choose` **只能出现在根单元**，**每一维恰好一次**（总数 ≤ 300 行，`docs/175` §3.0）；**库不许 `choose`** | 只限次数是不够的：一个**依赖**能替你的项目做这个决定，方向是反的 |
| 2 | **默认是 `std`**：不写 `choose` 就是 std；要用 `no_std` **必须显式写** `choose no_std`。`choose std` 可写可不写（**建议写**，但那是开发者自己的事） | 用户 2026-09-17 定（本文原主张"必写"，被覆盖）。代价是"忘了写"会静默拿到 hosted。**缓解**：Potato 形式对象里把 `mode: std` 与"是否显式声明"**分开记** —— 于是"意图是 freestanding 却没声明"这件事**仍然可审计**，不必拿强制语法去换 |
| 3 | 模式**必须进 Potato 形式对象** | 不导出就没法审计，3.1 第 2 条收益直接归零 |

### 3.3 库怎么表达自己的需要：用**能力需求**，不是模式

库不许 `choose`，那它要 hosted 的 `fs` 怎么办？**声明能力需求**——
而 `docs/168` 的工具已经在算这个了：`loment.py lib cap`（能力需求闭包，**带来源链**）。

所以：

```
项目: choose no_std
库 A: use fs            <- 需要 hosted 才能满足的需求
编译: 错误 —— no_std 项目里 fs 不可满足
      来源链: A -> B -> (根单元)      <- 报得出是谁拉的
```

**复用已有机制，不新造。** 库写的是"我要什么"，项目定的是"这个项目给什么"。

### 3.4 **GC 两档**（用户 2026-09-22 新增）：`choose gc_auto` / `choose gc_manual`

**规则**（与 §3.0 同一张次数表：**按维**恰好一次，库不许）：

| 写法 | 结果 |
|---|---|
| 不写 | **`gc_manual`**（与今天的行为一致，见下） |
| `choose gc_manual` | **手动回收**：回收由程序显式做 |
| `choose gc_auto` | **自动回收**：运行期负责回收 |
| 同一维写两次 | **报错**（"每维一行"） |
| `choose gc_auto` + `choose no_std` | **暂时报错**（理由见下 ⚠） |

#### 这一档为什么不能照 §3 前两档抄：**"手动档"看着有、其实没有**

`docs/140` 写的差异点是「**确定性：无 GC**，显式所有权」，`docs/175` §4 又说
freestanding / 无 GC —— 听起来像"今天就是手动档"。**实测不是**，而且比"缺一个函数"更难看：

| 事实 | 出处 |
|---|---|
| `free(p: ptr) -> u32` **是内建，两个实现都认**（参考实现的内建表、自举侧 checker / codegen / interp 都点了名） | `SKILL.md` 内建表 · `tools/lomentc.py` · `loment/selfhost/checker.lomt` |
| 但它是**占位**：`SKILL.md` 那一行原文就是「**占位（bump 堆不真回收）**」 | `SKILL.md` §内建表 |
| `alloc` 是 bump 堆、**64 KiB 上限**，同样不归还 | `docs/189` §542 |

⇒ **名字在、语义不在**：写 `free(p)` 编得过、检查得过、跑起来**什么都不发生**。
这是本仓反复认过的那种形状（**发得出去但行为不对** —— 与 `docs/188` §0 那条
"宁拒勿猜"、`docs/189` 第 53 条链式泛型是同一个病）：一个**已经被允诺、却不会兑现**的接口。

所以这两档的**性质完全不同**，不能当同一件事记账：

| 档 | 缺什么 | 代价量级 |
|---|---|---|
| `gc_manual` | **把 `free` 兑现** —— 一条**能归还**的分配器 + 两个实现 + codegen 与运行期都认。名字不用加（已有），**语义要新写**；而且要先决定**占位期怎么写实**（继续静默不管，还是**出声**说"本模式下 free 无效果"） | 与"改一个内建的真实语义"同层：**大概率不碰 L0**（`alloc`/`free` 都不在 `lom/*.lom` 里），但要按 `docs/176` §6.1 那条判据**先确认一次** |
| `gc_auto` | **一个运行期** —— 收集器要知道根在哪（栈 / 全局），于是"确定性"这条差异点被这一档**局部让掉** | **多轮**的工程；且**很可能要新 L0 原语**（根注册 / 归还接口），因此**与 hosted 层同一道门**：`docs/176` 的 **B0** |

⚠ **`choose gc_auto` + `choose no_std` 暂时报错的理由**（用户 2026-09-22：**暂时**这样，
"到时候看社区反应"）：自动回收要一个**运行期**，而 `no_std` 的定义是"只能用核那一层"
（§4 那张表）。两者放在一起，等于要求**核里带一个收集器** —— 那不是"核保持小"。
这不是"技术上绝不可能"（arena / 引用计数都不依赖 OS），而是**这一档先划窄**：
真有人要，再按 §4 那条"能独立校验"的路子把它开成一个**受约束的子集**，
而不是现在就把核的定义放宽。

**这一对的判决住在哪（#1019）**：不是手写的配对表，而是每一档自己的
`needs` / `forbids`（`tools/lomentc.py` 的 `CORE_NEEDS` / `CORE_FORBIDS`）——
两者相交即冲突；有开出条件的（`CORE_OPENINGS`）判 `narrowing`，其余判 `contradiction`，
由 `core_conflicts()` 现算。

#### 它和 §4「std 是分层」是同一件事的两面

**核一直是 freestanding、确定性、无 GC** —— 这句话在加了 `gc_auto` 之后**依然成立**，
因为 `gc_auto` 是**外层**的选择（和 `std` 一样），不是核的性质。这正是 §0 那句话的又一次
应用：**核心保持小，长的是外层**。所以：

- 默认（不写 `choose`）= `std` + `gc_manual` = **今天的行为**，加了这一维**不改变任何现有程序**；
- `gc_auto` 是**新开的一档**，用它的项目就把"确定性"这件事显式换掉了 —— 而这个交换
  **记在 Potato 形式对象里**，于是"这个产物放弃了确定性"是**不读源码可判**的（§3.2 规则 3）。

#### 判据（都能证伪）

| 判据 | 证伪方式 |
|---|---|
| 这一维进 Potato | 从形式对象里删掉 GC 字段 → 独立校验器**必须**红 |
| 每维恰好一次 | 写两行 `choose gc_auto` → **必须**报错 |
| 库不许 | 把 `choose gc_auto` 挪进一个依赖 → **必须**报错 |
| 暂时禁止的组合 | `choose no_std` + `choose gc_auto` → **必须**报错（且**话里点名这两档为什么冲突**，不是泛泛的"非法组合"） |
| 默认不变 | 现有语料（不加任何 `choose`）→ 产物**逐字节不变**（这一维不许悄悄改变默认行为） |

**前四条 2026-09-23 已落地**（第五条由 `loment_potato_emit_test` 的逐字节孪生守着）。
落点：`CORE_DIMS` 那张表（两个实现各一份）、Potato **v8**、一致性套件里三条新案例。

#### `gc_auto` 的收集器先进在哪（2026-09-23 的设计）

**一句话：主流 GC 要运行期去"发现"根，而 Loment 不需要发现 —— 根是编译器知道的。**

三条，每条都是从语言**已经有的**性质推出来的，不是新发明：

| 主流收集器必须做的 | 它为什么要做 | Loment 这边 |
|---|---|---|
| **保守扫栈**找根 | 它不知道栈上哪一个字是指针 | 类型静态 + 所有权静态（`docs/206` 那张表）⇒ **根表由编译器发出来**：哪个槽是活的、活到哪一行，编译期就知道 |
| **读屏障 / 卡表**记跨代引用 | 分代要维护 remember set | 同上：指针位由**布局描述符**给（每个分配点的类型是静态的），所以标记阶段是**精确**的，不需要写屏障 |
| **safepoint**（任意位置可停） | 运行期要能随时打断 | **收集点由编译器放**：只在"活集已知"的位置收（例如 `alloc` 将要耗尽 arena 之前），于是**不需要任何 safepoint 机制** |

于是它买到的东西恰好是本仓最不肯让的那一条：**确定性没有丢**。
从产物本身就能说出收集器**什么时候跑、看什么**（根表规模与收集点数量进 Potato），
而"什么时候跑"在主流 GC 里是个**运行期才知道的**答案。

**一条更正**：`docs/176` 当年判 `gc_auto` "**大概率要** L0 原语"（根注册 / 归还接口）。
复核之后那句话要收窄：**要 L0 的是"问 OS 要页"**（把堆长起来、还给系统）。
一个**在固定 arena 内**的收集器**不问 OS 要任何东西** —— 它只在程序自己的内存里标记与清扫，
所以它**不过 B0 那道门**。先前把两件事并成一件了。

### 3.4.1 `choose gc_auto_alpha`：**混合**档（用户 2026-09-23 定的方向）

> 原话：**"先进的 GC 不再是一个组件，而是静态内存管理 + 动态 GC 混合系统……GC 在 Loment
> 里不再是个外挂，而是深度融合编译器、类型系统、硬件、操作系统内核……不是 ZGC 那种
> 亚毫秒短暂 STW，是**不存在任何需要冻结全部业务流程的阶段**……完全自适应，
> `choose gc_auto_alpha` 启动这个版本，且应该是**算法策略池**。"**

这一档**独立成一个取值**（不是 `gc_auto` 的同义词），因为它的**主张不同**，而主张要能被证伪。

#### 一、三条**定义性**主张（每条各配一条判据）

| 主张 | 它**不是**什么 | 判据（可证伪） |
|---|---|---|
| **混合**：静态内存管理 + 动态回收 | 不是"一个运行期收集器"，也不是"纯静态" | 同一份程序，`gc_auto_alpha` 下**编译期放掉的分配**占比 > 0，且该占比**进 Potato**（`gc_alpha.static_frees` / `runtime_kept`）—— 两个数都在对象里，不读源码可判 |
| **不冻结**：不存在任何需要冻住全部业务的阶段 | 不是 ZGC 那种"亚毫秒 STW"—— 亚毫秒**也是**一个全局阶段 | 收集器的每一次推进都**有界**且**可在编译期说清上界**（`gc_alpha.step_ops` 进 Potato）。判据：一段长跑程序里，**任意一次收集推进的工作量** ≤ 那个上界；没有"整堆扫描"这种无界步 |
| **自适应**：策略池 | 不是"编译期定死一种分配策略" | 策略**池**进 Potato（`gc_alpha.strategies`：每个分配点选了哪一个、为什么），且**同一份源在不同负载下可以选不同的策略** —— 判据是"策略选择随观察量变化"，而不是"永远选第一个" |

#### 二、它为什么**深度**融合，而不是外挂

不是"编译器旁边挂一个收集器"，而是**每一层各出一半**：

| 层 | 它出什么 | 没有它会怎样 |
|---|---|---|
| **类型系统** | 指针位：哪些偏移是引用（布局描述符） | 就只能保守扫描 —— 那是"发现"，不是"知道" |
| **权限/所有权**（`docs/206`） | 活到哪一行结束 —— 于是"编译期能放掉的"是**算得出来**的 | 只能全部留给运行期，那就退回成纯 GC 了 |
| **编译器** | 根表 + 收集点 + 布局描述符 | 运行期要自己找根、自己找安全点 |
| **能力域 / Potato**（`docs/146`/`docs/147`） | 让上面三样**可被外部核对** | "自适应"就只能靠运行期自证 —— 那是不可审计的 |

**核那边照旧**：这一档是**外层**的选择（与 `std` 同层），`no_std` 与它**冲突**（`CORE_FORBIDS` ∩ `CORE_NEEDS`，`core_conflicts()`），
所以"核保持小"这条没有被这一档动到。

#### 三、`alpha` 这三个字母是**明说的**

`gc_auto_alpha` 这个名字把"它在动"写进**源码**了（`choose` 那一行、Potato 的 `gc` 字段里
都看得见）。用户 2026-09-23 定它叫 alpha —— 于是"用这一档的项目**认**它在动"是**可判的**，
不需要谁去读 changelog。

#### 四、现在到哪儿了（诚实账）

| 层 | 状态 |
|---|---|
| **`gc` 那一维**（三个取值 / 按维一次 / 三个校验器 / 冲突规则） | ✅ **已落地**，两个实现逐字节一致 |
| **`gc_manual`：`free` 真的归还** | ✅ **已落地**（bump + 地址序空闲链表 + 拆分 + 前沿回退），判据是一对程序（带/不带 `free`） |
| **`gc_auto_alpha` 的取值本身** | ✅ 已进语言、进 Potato、进一致性套件 —— 但**它现在与 `gc_manual` 行为一致**（下两行的东西没做） |
| **静态那一半**（编译器放 free + `static_frees` 计数进 Potato） | ⬜ **没做** —— 这是"混合"的前一半 |
| **动态那一半**（根表 / 布局描述符 / 有界步 / 策略池） | ⬜ **没做** —— 设计在本节，判据在第一节的表里 |

**这份账是有意留在文档里的**：这一档的名字里带 `alpha`，而"哪几格是空的"不该只存在于
某次对话里。下一轮从**静态那一半**开始 —— 它是"混合"里先能落地、也先能证伪的一边。

### 3.5 它进语言，而不是进 `loment.conf`

`loment.conf` 现在装的是**工具链**配置（名字形式 `use` 找什么后缀，`docs/174` 上一轮加的）。
`choose` 不一样：它是**语义属性**，必须被编译器检查、被 Potato 导出。
放配置文件里，校验器就读不到了。

**代价要说清**：新关键字 = 动**冻结面**（`docs/158` §2），要走 §5 那四条
（规范 → 一致性套件 → **两个实现同一次提交且逐字节一致** → 静态门禁）。

### 3.6 第三维：**运行期在不在** —— `choose runtime` / `choose no_runtime`

> 用户 2026-09-23：**「运行期是海量工程必经之路，我们不得不利用 `choose` 开关启动/关闭
> runtime」** —— 并否掉了"Loment 无运行期"这条我此前当成立身之本的说法。

**这条纠正成立，而且错在我。** §4 那张表一直写着"核 freestanding、外层是 hosted"——
**无运行期说的是核，不是语言**。我先前拿"无运行期"去反对这一维，是拿一句我自己写过、
又被自己收窄过的话去反对它。

**取值刻意只说"有没有"，不说"里面装了什么"。**

| 写法 | 结果 |
|---|---|
| 不写 | **`no_runtime`**（默认）—— **一句保证**：产物里没有运行期，会带就编译期拒（见下面那条 **2026-10-10 兑现**） |
| `choose runtime` | 产物里**一定**有运行期（用不到也带） |
| 同一维写两次 / 取值拼错 | **报错** |
| `no_runtime` + `gc_auto`（含 alpha） | **报错**（定义上矛盾） |
| `runtime` + `gc_manual` | **合法** —— "要运行期、但内存我自己管" |

**为什么不把"里面装了什么"写进取值名。** 这一维今天装的是**收集器**（`gc_auto` 要的
那一个：根表、收集点、收集器本身），明天可能是线程、宿主服务、调度。写成
`runtime_collector` / `runtime_full` 这种名字，等于**把今天的内容钉成这一维的身份** ——
两年后加一项能力就得回头改定义，而"加维不用回头改前两维"正是这一维该满足的判据。
取值是**存在开关**，内容是被它打开的那个箱子。

**两条冲突理由不同，所以各写一份。** §3.4 ⚠ 那条 `no_std` + `gc_auto` 的措辞是
"**暂时**划窄，到时候看社区反应"；`no_runtime` + `gc_auto` 不是暂时：自动回收**要的就是**
那个运行期，两者是同一件事的正反面。反过来 `gc_manual` **不**与 `no_runtime` 冲突 ——
要线程/宿主服务、但内存自己管，是系统语言里正当的一档。

**一条容易混的边界**：`no_runtime` **不等于** `no_std`。前者说"产物里不带运行期"，
后者说"只用核那一层"。一个 hosted 项目完全可以选了 `std` 却不要运行期。

#### 判据（都能证伪）

| 判据 | 证伪方式 |
|---|---|
| 这一维进 Potato | 从 v9 对象里删掉 `runtime` → 独立校验器**必须**红 |
| 按维恰好一次 | 写两行 `choose runtime` → **必须**报错 |
| 取值只有两个 | `choose runtime_x` → **必须**报错 |
| `no_runtime` + `gc_auto` | **必须**报错，且话里点名这两档为什么矛盾 |
| **合法的那一对不许拒** | `runtime` + `gc_manual` **不许**报错（`potato_test` 的合法样本 `v9-runtime-on` 钉它） |
| 默认不变（**2026-10-10 收窄**） | 补了标注的现有语料 → 产物**逐字节不变**；**不补不再合法**（见下），所以这条从"不加 `choose` 也不变"收窄成"**补上之后**逐字节不变" |
| **保证成真**（2026-10-10 新增） | 一份 `no_runtime` 的产物里**必须**没有 `@__loment_*`；有 ⇒ 编译期报（`docs/227` 判据 A/B） |
| **强制带**（2026-10-10 新增） | 一份用不到运行期的程序 + `choose runtime` ⇒ 产物差**恰好**是那段（`docs/227` 判据 C） |

**2026-09-23 已落地**：`CORE_DIMS`（两个实现各一份）、Potato **v9**、两个校验器、
一致性套件三条新案例（`BUDGET` 73 → **76**）、`potato_test` 的 v9 正例 + 四条反例。
冲突改成**两两查**（`CORE_DIM_ORDER`）而不是写死 `(mode, gc)` 那一对 ——
第三维进来时那一段**一行都没动**，这是 §3.4 那次重构（把"维"变成一张表）付的红利。

**2026-10-10 兑现 —— 这一维不再是"只声明"**（全文见 **`docs/227`**）。

那一版的诚实账写的是"运行期本身还没有"；**那半早就过期了**（四层 GC 梯、分配器、
freestanding 文本块都在产物里）。还欠的不是内容，是**开关**：`runtime` 这一维对产物
**零影响**（`lomentc.py` 里除 Potato 导出之外一处都不读它）。用户 2026-10-09 裁决：
**按字面做**（"我们要是不做，Loment 初衷之一**激进**就不成立"），规格该改就改。于是：

* **`no_runtime`（默认）成了一句保证** —— 凡会把运行期拖进产物的构造（`/` `%` `alloc`
  `free` `str_concat` `str_eq` `panic` `guard`）在这一档下**编译期点名拒**（E022）；
* **`runtime` 是它的另一半** —— 强制把那段带进产物（`_IR_HEAP` 仍按需：那是 64 KiB 的
  零初全局，给一个只会除法的裸机程序凭空装上就是"给承诺加税"）；
* **一条既有规则让了路** —— 从前"库不许 `choose`"让 `loment/lib/proc.lomt` 这类要除法的
  库**两面堵死**（当根编要写、当依赖又不许写）。新规矩：依赖的声明**是需求**，根必须
  满足它；依赖用了拖运行期的构造却什么都没写，也要报（那句老报错本来就写着"库该声明
  **能力需求**"）。

**代价照例明写**：默认档**不再**"老程序一行不改照编"——仓里动了 **233 份 `.lomt`**
（`loment/` 91 + `lompi/` 142；绝大多数是补那一行）加三段文档示例；姊妹仓（内核线）的纯 Loment 产物同样要补
（这是**语言面**变更，不动 `lom/`，但要知会 compat 线）。**产物逐字节不变**这条是量过的：
那 233 份里本来就用得到运行期的，补完 IR 一位都没动。

## 4. std 是**分层**，不是替换

"不再 no_std"这个说法危险。Loment 在系统侧的差异点**就是** freestanding、确定性、无 GC；
而内核线（`FujoOS-compat`）现在手上全是纯 Loment 产物，是**跨线契约**（`CLAUDE.md` 第 1 条）。

所以 std 做两段，`choose` 选的是**给不给上层**：

| 层 | 内容 | `no_std` 项目 | `std` 项目 |
|---|---|---|---|
| **核** freestanding | 已有的：`alloc` / `free` / `str_*` / syscall 包装 / 平台垫片；`loment/lib/` 的 `json` / `sha256` / `proc` | ✅ | ✅ |
| **hosted 层** | libc、文件系统、线程、时间、网络… | ⛔ 引用即错误 | ✅ |

**不是"Loment 不再是 no_std"，而是"Loment 的核一直是 freestanding，hosted 层现在有了"。**

⚠️ **2026-10-10 的一处措辞订正**（`docs/227`）：上表把 `alloc` / `free` / `str_*` 列在**核**里
—— **它们仍是核原语**（`no_std` 项目照用）。但**用它们要声明 `choose runtime`**：那几个原语
的**实现**（`_IR_RUNTIME` + 分配器）就是 §3.6 那一维说的"运行期"，而那一维现在是**保证**。
两句话不矛盾 —— **原语属核，它的运行期实现属那一维**；就像 `no_std` 与 `no_runtime`
本来就不是一回事（§3.6 末尾那条边界）。绕开它的路照旧存在：`sys_alloc` / `brk`（自举编译器
自己走的就是这条，所以 `loment/lib/` + `loment/selfhost/` 28 份真代码里只有 4 个 `alloc`
站点）。

⚠️ **对兼容线的契约影响**：std 一引入原语，`lom/*.lom`（L0，跨线冻结契约）里就**必须能区分
freestanding 原语与 hosted 原语**。否则 `choose no_std` 的项目可能引用到一个只在 hosted 里成立的
原语 —— 而那个错误会以"**内核线编译不过**"的形式出现，不是在语言层被拦住。
这属于 `CLAUDE.md` 第 1 条要单独提交并知会 compat 线的改动。

## 5. 多语法：落在**前端**，产出 L1

### 5.1 位置

```
.py / .rs / .go / .c 源  --[前端]-->  L1 .lomt 文本  --[冻结核心，一行不动]-->  IR -> 产物
```

**为什么不放进核心**：核心的规矩是"两个实现同一次提交、语料逐字节一致"（`docs/158` §5，
今天 55 个文件钉着）。多语法进核心 = 每加一门语法都要在 `lomentc.py` 与
`loment/selfhost/*.lomt` 各写一遍并对齐字节。放前端就完全绕开这笔税。

**前端产出 L1（`.lomt`）而不是 L0（`.lom`）**：L0 是跨线冻结契约（`CLAUDE.md` 规则 1），
拿它当前端目标是自找 churn；而 `.lomt` 是书写层，`CLAUDE.md` 明说"`.lomt` 随便改"。

### 5.2 这是**恢复** Potato 的职责，不是新增

`docs/110` §1 原话：让大模型对训练密集的语言做快速**结构识别与转写**。
是 `docs/140` §9 把它收窄成"只管看"。用户第 6 条把**转写**拿回来 ——
**应该写成"恢复"，而不是"给 Potato 加新功能"**：裁定不一样，读文档的人得到的信号也不一样。

而且它正面回答整个语言计划里最大的风险：**零语料**。`docs/140` §9.2 给 Loment 的对冲是
"Rust 子集语法"；多语法是第二个、大得多的对冲。**两条策略并存，不要互相假装对方不存在。**

### 5.3 五种语法不是五种语法，是五种**语义**

"用 Python 语法写 Loment"只可能是**套着 Python 皮的 Loment 语义**：
静态类型、无 GC、无字符串常量、显式所有权。这层边界不明说，用户就会试
`import numpy`、生成器、异常 —— 失败方式是"**Loment 骗人**"。

**必须在每个前端的第一行文档里写死："这是语法，不是语义。"**

### 5.4 ⚠️ 前端是**模式相关**的（用户 2026-09-17 追加的约束在此处生效）

Python 语义蕴含运行期。所以：

| 项目模式 | Python / Java 前端 | Go / C / Rust 前端 |
|---|---|---|
| `choose std` | ✅ 可用（它们本来就要运行期） | ✅ |
| `choose no_std` | ⛔ **拒绝**，或只放行它一个 freestanding 子集 | ✅（子集） |

不这么定，就会造出一种"看着像 Python、但什么都 import 不了"的东西 —— **比不支持更糟**。
这条把第 3 条与 5+6 条焊在一起；现在不说清，以后就是一个自相矛盾的特性。
