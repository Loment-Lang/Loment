# 380 · 信任商团：推导、独立内核与 K-of-N 根

> 状态: **R0–R5 已落地**（2026-11-22）。R4 的商团覆盖 core 档，L0 档仍是单内核；
> `seed : Compiler` 的语义（种子真的实现编译器）仍是假设，不在已落地内。
> 上游: `docs/358`（只信产物）· `docs/370`（LNotary）· `docs/344`（LSPE）·
> `docs/349`（语义 oracle）· `docs/356`（Dissigsegv）· `docs/368`/`docs/369`（工具链代际）·
> `docs/373`（Dismemory）· `docs/376`（可重演链 V0）· `standard/LLS.md`
> 基准: `origin/main` `55c20dd8`（2026-11-22，PR #2143 已合）
> 一句话: **信任链的终点是 K 个互不共享代码的检查器对同一份推导的共同接受；
> 种子、程序、规范都只是推导里的节点，编译器可以删掉。**

---

## 0. 它看起来完全不可能

把「信任链」这个词拆开，会得到五个断言。每一个都能单独杀死本文：

| # | 断言 | 杀死它的那条链 |
|---|---|---|
| 1 | 链可以删掉，留下推导 | **接地**：推导总要有公理 |
| 2 | 编译器可以删掉 | **生产**：谁把源码变成产物 |
| 3 | 种子不特殊 | **引导**：第一份推导从哪来 |
| 4 | 单一的根可以删掉 | **商团也是根**：K 个内核的共同接受仍是一个根 |
| 5 | 根不必可读 | **规则谁读**：没人读的规则可以一起错 |

本文做两件事：把五条链写死（§1），再逐条拿掉它们依赖的假设（§2）。拿完之后剩下的
是一个**推导商团**（§3–§4）：判断、推导、内核、商团、预算。然后给一个八步演示（§5）、
判据（§6）、不主张（§7）与前史（§9）。

**这不是 `docs/358` 的增量。** 358 让一个产物带一份可核的安全声明；本文让**整条工具链**
带一份可核的推导，并把「谁来核」从一个小验证器换成 K 个独立内核。编译器、种子、单一根
三样都在信任边界外。

## 1. 五条不可能性（先写死）

### A · 接地链

1. 推导是一棵树，叶子是公理。
2. 公理不能被推导出来，否则无限回退。
3. ⇒ **公理不可消。**

**能拿掉的只有「公理必须是一个程序」这条。** 公理可以是一组**有限的推理规则**；
规则不是程序，内核才是程序的实现。根从「一粒 7.47 MB 的种子」缩成「一张几百行的规则表 +
它的语义」。规则表仍然要有人读，但它比种子小三个数量级。

### B · 生产链

1. 源码到产物需要一个变换。
2. 变换可以写成程序，也可以写成证明搜索。
3. 一个不可信的证明搜索 + 一个可信的检查器，等价于一个可信的变换。
4. ⇒ **「必须信任编译器」可以拿掉，代价是证明体积与检查时间。**

这条与 PCC / TAL 同形（Necula 1996；Morrisett 1998）。本文的差别在**粒度**：
每个产物带**逐步骤的翻译验证证书**，不做整编译器的正确性证明。编译器可以恶意；
它只能产出检查器接受的东西。

### C · 引导链

1. 第一份推导总要有作者。
2. 作者可以是人、另一个内核、或一个更小的公理集。
3. 若第一份推导被内核接受，它的「种子」身份就没有特权。
4. ⇒ **「种子是根」可以拿掉，代价是内核必须能检查 `seed : Compiler` 这个判断。**

今天的种子是 7,468,507 B 的 IR（`origin/main`，2026-11-22）；在本文里它只是一份**推导的结论**。换一粒种子、换一份推导、
甚至换一个编译器，只要内核接受，信任不变。种子的字节数从「根的预算」降为「缓存的预算」。

### D · 单一根链

1. 一个内核可以被攻破：一行 bug 就能接受一份坏证明。
2. 一个内核的语义可以被误读：实现与规则一起错。
3. ⇒ **单一内核不是根，K 个独立内核的共同接受才是根。**

商团仍是根，但它是一个**协议**，不是一段代码。攻击者要攻破至少 `N-K+1` 个互不共享代码的
实现，或者攻破它们共同读的那份规则表。这把「信任一个程序」换成「信任一个多数 + 一份公开规则」。

### E · 可读性链

1. 根要被人检查，人才能相信它。
2. 一粒 7,468,507 B 的种子没人读得完。
3. 一个 K-of-N 商团里的单个内核也可以没人读得完。
4. ⇒ **「根必须可读」可以拿掉，改成「规则表必须有限可述，且至少有两种独立读法」。**

可读性从「读实现」搬到「读规则 + 读规范」。内核可以是 opaque 的；商团的**独立性**承担了
「单一读者」原本承担的工作。这条是 `docs/376` §2.5 的继续：可读性可以被替换，但不能被取消。
被替换的是实现，被保留的是规则。

## 2. 能合法拿掉的假设

| 假设 | 换成 | 代价 |
|---|---|---|
| 信任是一条链 | 信任是一棵推导 DAG | 证明格式与检查器 |
| 编译器必须可信 | 编译器是不可信的证明生产者 | 每产物的翻译验证证书 |
| 种子是根 | 种子是可推导的节点 | 内核要检查 `seed : Compiler` |
| 一个根程序 | K-of-N 个独立内核 + 一份规则表 | N 份实现与独立性审计 |
| 根必须人类可读 | 规则表有限可述 + 至少两种独立读法 | 规则表与规范的维护 |
| 构建是运行编译器 | 构建是检查一份推导 | 证明体积与检查时间 |
| 热更新只需要摘要相等 | 热更新带一条 refinement 推导 | 语义方向的可证化 |

## 3. 定义

### 3.1 判断

```rust
// 展示用 rust 围栏，理由见 CLAUDE.md
Γ ⊢ a : φ
```

* `Γ` 是环境：规则表 `R`、公理 `Ax`、源码哈希、构建配方、工具链声明。
* `a` 是产物：ELF / PE / LVM 字节码 / Potato。
* `φ` 是结论：一个**合取**，至少包含
  `Sem(a, LLS)`（语义）、`Prov(a, src, seed, recipe)`（出处）、
  `Safe(a, LSPE)`（安全台账）、`Repro(a, recipe)`（可复现）。

判断是**内容寻址**的：`H(Γ, a, φ)` 是它的名字。同一个判断换一个字节就是另一个判断。

### 3.2 推导

```
        Γ ⊢ p1 : φ1   ...   Γ ⊢ pn : φn
        ───────────────────────────────  (Rule)
                 Γ ⊢ c : φ
```

推导是一棵树；每个节点是一条规则的应用。叶子是公理。推导**不执行**；它只被检查。

### 3.3 规则表

第一版收十二条；R5 加一条 `REFINE`，共十三条。每条规则的形状是「前提判断 + 边条件 ⇒ 结论判断」：

| 规则 | 前提 | 结论 | 边条件 |
|---|---|---|---|
| **AX-K** | — | `⊢ K : Kernel` | 内核规范的内容哈希 |
| **AX-S** | `⊢ K : Kernel` | `⊢ seed : Compiler` | 种子字节 + 启动配方 |
| **PARSE** | —（源码字节 + 词法/语法规范） | `⊢ src : L1` | 词法/语法/检查器的判决 |
| **TV-L1** | `⊢ src : L1` | `⊢ ir : L1→L2` | 逐节点翻译证书 |
| **TV-L2** | `⊢ ir : L1→L2` | `⊢ elf : L2` | 逐指令翻译证书 |
| **LINK** | `⊢ o_i : Obj` | `⊢ elf : Linked` | 符号表 + 重定位表 |
| **SEM** | `⊢ elf : L2` | `⊢ elf : Sem(LLS)` | 语义 oracle 的证明项 |
| **SAFE** | `⊢ elf : L2` | `⊢ elf : LSPE` | 站点表 + `fault_ladder` + 证据根 |
| **CAP** | `⊢ elf : LSPE` | `⊢ elf : Caps⊆` | 子权能 ⊆ 父权能 |
| **PROV** | `⊢ elf : L2` | `⊢ elf : Prov(src, seed, recipe)` | 376 的 provenance/闭包 |
| **REPRO** | `⊢ elf : L2` | `⊢ elf : Repro(recipe)` | `--verify` 的判决 |
| **COMPOSE** | `⊢ a : φ1` `⊢ b : φ2` | `⊢ a⊕b : φ1∧φ2` | 组合边条件 |
| **REFINE** | `⊢ a' : Repro`（新代完整推导） | `⊢ a' : Refines(a, Δ)` | `a` 以容器字节 + 哈希绑定；`d(a') ⊆ d(a)`；Δ 逐项对账 |

`AX-K` 是唯一不能由别的规则推出的公理。`AX-S` 把种子变成结论：种子不再特殊。
`TV-*` 是**翻译验证**：编译器为每一步生成一份证书，内核按固定规则复查；不做整编译器证明。

### 3.4 内核与商团

```rust
struct Kernel {
    id: str,
    impl_hash: str,       // 实现的内容哈希
    rules_hash: str,      // 它实现的规则表哈希
    lang: str,            // "loment" | "c" | "coq" | ...
    imports: [str],       // 必须为空（零工具链 import）
}

struct Quorum {
    n: u32,               // 内核数
    k: u32,               // 接受阈值
    kernels: [Kernel],
    diversity: [str],     // 独立轴：语言 / 作者 / 组织 / 代码谱系
}
```

商团判决：`accept(a, D, φ)` 当且仅当至少 `k` 个内核接受同一份 `(a, D, φ)`，且**没有**内核
在「接受/拒绝」上与其他内核相反。一个被攻破的内核（永远接受）不能单独放行；一个实现 bug
（误拒）会触发分歧，商团拒绝而不是猜测。

### 3.5 产物与预算

```rust
struct Artifact {
    bytes: [u8],          // ELF / PE / LVM
    derivation: Derivation,
    conclusion: Formula,
    trust: TrustBudget,
}

struct TrustBudget {
    rules: u32,           // 规则条数（目标 <= 32）
    rule_lines: u32,      // 规则表行数
    spec_lines: u32,      // LLS + 本文
    n: u32, k: u32,       // 商团
    diversity_axes: u32,  // 独立轴数量（目标 >= 3）
    proof_bytes: u64,     // 推导体积
    check_ms: u64,        // 单次检查时间
    assumptions: u32,     // 显式假设条数
}
```

**种子的字节数不在信任预算里。** 它仍在 `provenance` 里，作为缓存大小与复现输入记录；
它不再决定根的可信度。这是对 `docs/376` 的正面反转：376 把种子标价，377 把种子降级为节点。

`trust.json` 增加 `quorum` 与 `budget`：

```json
{
  "quorum": {
    "n": 3, "k": 2,
    "kernels": [
      {"id": "loment-kernel", "lang": "loment", "imports": []},
      {"id": "c-kernel", "lang": "c", "imports": []},
      {"id": "coq-kernel", "lang": "coq", "imports": []}
    ],
    "diversity": ["language", "author", "code-lineage"]
  },
  "budget": {
    "rules": 12, "rule_lines": null,
    "spec_lines": null, "n": 3, "k": 2,
    "diversity_axes": 3,
    "proof_bytes": null, "check_ms": null,
    "assumptions": null
  }
}
```

上面的 3/2 是**目标形态**。本仓库 R4 的实装是 2/2（python + c，core 档），
`diversity_axes` 只记 1（language）；差异见 §11。

## 4. 定理与边界

### T1 · 相对规则表的健全性

> 若商团接受 `(a, D, φ)`，且规则表 `R` 的每条规则在它的语义下是健全的，
> 则 `a` 满足 `φ`。

证明是归纳：叶子是公理，每个节点按规则的前提与边条件展开。它**不**声称 `R` 本身健全；
那是 §1A 的地板。

### T2 · 编译器独立性

> 对同一份规则表，接受只依赖 `(a, D, φ)` 与 `R`，不依赖生产者的身份：
> 若生产者 A 能产出一份被接受的推导，生产者 B 的身份不会让同一份推导被拒；反之亦然。
> 生产者的**完备性**（是否总能找到证明）不在定理内。

证明：接受只依赖 `(a, D, φ)` 与 `R`，不依赖生产者的身份。推论：换编译器、换种子、
换构建脚本，只要推导被接受，信任不变；找不到证明是拒绝，不是坏证明被接受。

### T3 · 种子非特权

> 若 `⊢ seed1 : Compiler` 与 `⊢ seed2 : Compiler` 都被商团接受，内核不因种子身份
> 区别对待；用它们构建的产物仍需各自的推导。若 `seed3` 没有可接受的推导，它不能成为根。

证明：`AX-S` 只把种子当结论；内核不读种子的「身份」，只读它的判断。这条把
`docs/376` 的「种子哈希绑定」降级为「推导的一项前提」。

### T4 · 商团安全

> 在 `n` 个内核、阈值 `k`、至多 `f` 个被攻破（永远接受）的假设下，若 `f < n-k+1`，
> 则被攻破的内核不能单独放行一份坏证明；若出现接受/拒绝分歧，商团拒绝。

这不是新的 BFT 定理；它是把 BFT 的阈值搬到证明检查上。代价是 `n-k+1` 个独立实现。
**健全性与 liveness 分开**：被攻破的内核可以永远拒绝，制造分歧并让商团拒绝（拒绝服务）；
这不违反 T4，但 T4 不保证系统继续出活。沉默按拒绝处理，商团不猜。

### T5 · 组合

> 若 `⊢ a : φ1` 与 `⊢ b : φ2` 都被接受，且 `COMPOSE` 的边条件成立，
> 则 `⊢ a⊕b : φ1∧φ2` 被接受。链接、插件、库的组合走这一条。

### T6 · 代际 refinement

> 若热更新 `T → T'` 带一条推导 `⊢ T' : Refines(T, Δ)`，且 `Δ` 只减少偏差
> （`docs/369` 的 `d(T') ⊆ d(T)` 的可证形式），则商团接受这次更新；否则拒绝或降级为
> 「功能变更」的单独审批。

这把热更新的五道摘要换成一条**语义方向**的推导。`docs/369` 说 PC 一辈子证不了；
T6 不要求证 PC，只要求每次更新带一条**可检查的 refinement 证据**。证不出来就拒绝，
不拿摘要冒充方向。

### 边界

| 在定理内 | 在定理外 |
|---|---|
| 规则表健全时的产物语义 | 规则表本身是否健全 |
| 同规则表下的编译器独立性 | 证明生产者是否总能找到证明（完备性） |
| K-of-N 的阈值安全 | 所有内核共享同一误读（规则表错） |
| 同产物/同链接的组合 | 跨语义域（FFI、系统调用、硬件） |
| 代际 refinement 的可证部分 | 不可证的 liveness / 并发 / 物理故障 |

## 5. 最小演示（八步，每步一条先红判据）

| 步 | 动作 | 今天的先红判据 |
|---|---|---|
| **1** | 写一个 12 条规则的判断语言与内核 | 内核不存在 ⇒ 红 |
| **2** | 写一个玩具编译器：源 → LVM，逐步骤发翻译证书 | 编译器只发字节、不发推导 ⇒ 红 |
| **3** | 内核检查 `(artifact, derivation, φ)`；**删掉编译器** | 内核 import 编译器 ⇒ `ImportError` ⇒ 红 |
| **4** | 篡改产物一个字节 | 内核仍接受 ⇒ 证明是装饰 ⇒ 红 |
| **5** | 篡改一条推导/一个规则名 | 内核仍接受 ⇒ 检查器是空的 ⇒ 红 |
| **6** | 第二个独立内核（另一种语言/作者）对同一批推导给同一判决 | 只有一个实现 ⇒ 空判据 ⇒ 红 |
| **7** | 商团：一个内核被改成永远接受，其余内核拒绝 | 商团仍接受 ⇒ 阈值是假的 ⇒ 红 |
| **8** | 种子非特权：两粒不同种子各有有效推导，都被接受；无推导的恶意种子被拒 | 内核按种子身份放行 ⇒ T3 是假的 ⇒ 红 |

第 3、4、5 步是整份提案的生死线：**删掉编译器还能验**、**改一个字节就红**、
**改一条推导就红**。第 6、7 步是「商团」这个词的全部意思：**一个内核不够**。

### 演示的产物形态

```
hello.lvmb          # LVM 字节码
hello.deriv         # 推导（内容寻址的节点图）
hello.phi           # 结论（Sem ∧ Prov ∧ Safe ∧ Repro）
kernel/             # 零 import 的内核；它的哈希在 hello.deriv 里
quorum.json         # N/K 与独立轴
```

把 `hello.*` 与 `kernel/` 交给一个只相信规则表的人；他不需要源码、不需要编译器、
不需要网络。商团版本再给 `quorum.json` 与第二/第三个内核。

## 6. 判据（每条先红）

| # | 判据 | 证伪方式 |
|---|---|---|
| **C1** | 内核接受一份有效推导 | 内核不存在 ⇒ 红 |
| **C2** | 删掉编译器后，内核判决不变 | 需要编译器 ⇒ 不独立 |
| **C3** | 篡改产物一个字节 ⇒ 拒绝 | 接受 ⇒ 证明是装饰 |
| **C4** | 篡改一条推导/规则名/前提哈希 ⇒ 拒绝 | 接受 ⇒ 检查器是空的 |
| **C5** | 内核零 import：`sys.modules` 里没有编译器/LSPE/LNotary | 共享代码 ⇒ 自我证明 |
| **C6** | 第二个独立内核给同一判决 | 只有一个 ⇒ 空判据 |
| **C7** | 商团：`f < n-k+1` 时坏证明不能放行；分歧 ⇒ 拒绝 | 放行 ⇒ 阈值是假的 |
| **C8** | 种子非特权：两粒有效种子等价；无推导种子被拒 | 按身份放行 ⇒ T3 假 |
| **C9** | 翻译验证覆盖每个输出节点；改一个输出节点 ⇒ 拒绝 | 漏一个 ⇒ TV 是装饰 |
| **C10** | 组合：链接后的推导是两部分的合取 | 不组合 ⇒ 只能验单文件 |
| **C11** | 代际：refinement 推导被接受；反向/新增偏差被拒 | 摘要相等就放行 ⇒ T6 假 |
| **C12** | 预算：规则/行数/N/K/证明体积/检查时间进 `trust.json`；涨了要同提交改 `docs/379` | 不记 ⇒ 信任不可定价 |
| **C13** | 第三方只用规则表 + 内核 + 推导复现判决 | 要 `tools/` ⇒ 重演没有离开开发者 |
| **C14** | 内核自身可被第二个实现重建（引导） | 只能由原编译器重建 ⇒ 根又回来了 |

C5 与 C6 是「独立」的生死线；C12 是「可定价」的生死线；C14 是「引导」的生死线。

## 7. 我不主张

1. **不主张这是新理论。** de Bruijn 准则、PCC、TAL、翻译验证、BFT 都在前；本文是组合与搬移。
2. **不主张规则表健全。** 它是新的根；一枚错规则可以接受坏证明。
3. **不主张规范完备。** 「没有后门」不是可判定的性质；规则表只能覆盖它写下来的性质。
4. **不主张证明生产者完备。** 找不到证明时系统拒绝；这是安全方向的失败，不是健全性失败。
5. **不主张证明体积可接受。** 逐节点 TV 证书可能比产物大几个数量级；预算可能爆。
6. **不主张 N 个内核真的独立。** 同作者、同语言、同规范误读会一起错；独立性要审计。
7. **不主张覆盖硬件/OS/FFI。** 结论停在 LVM/语义层；物理层是另一条线。
8. **不主张今天就能做。** 它是 R0–R5 的研究梯子；先有玩具内核，再谈 Loment 全量。
9. **不主张商团能解决 xz 式社会攻击。** 它把技术根变小；人/组织的那层仍在。
10. **不主张它与 `docs/358` 二选一。** 358 的封印/验证器是本文规则表的一格；本文是它的商团化。

### 7.5 更激进的选项，以及为什么不选

| 选项 | 为什么看起来更激进 | 为什么不选 |
|---|---|---|
| **根完全不可读，也不可述** | 连规则表都不要 | 无限回退；两个内核无法被判定为实现同一规则。可述性是「同一规则」的前提 |
| **没有规则表，只靠行为一致** | 不需要规范 | 一致不证明对；`docs/349` 的共错盲区就是反例。行为一致最多是证据，不是证明 |
| **信任硬件 / TEE** | 把根交给芯片 | 根换位置，不缩小；芯片里仍是程序 + 规范，且不可审计 |
| **只靠社会共识 / 透明日志** | 不要技术根 | 技术根仍在；xz 证明社会层可被攻破；日志只见证，不证明 |
| **只靠随机差分** | 不写证明也能抓后门 | 只能证伪，不能证明；触发条件窄的后门可以躲过采样 |
| **把根做成一个不可变的物理常数** | 彻底不可改 | 不可改不等于可核；物理常数不表达语义 |

这张表的结论：**「更激进」的常见形态是把根藏起来或换位置；本文选择把根缩小、写成规则、
交给一个多数。** 前者听起来更猛，实际只是把同一个问题推远；后者要付证明体积与 N 份实现的账，
但它把账摆在明面上。

## 9. 前史（先点名）

| 本文用到的 | 谁先做过 | 本文差在哪 |
|---|---|---|
| 可信小检查器，不信大证明器 | de Bruijn 准则；LCF / HOL / Coq | 本文把检查器做成 K-of-N 商团 |
| 代码携带证明，宿主验证 | PCC（Necula 1996）、TAL（Morrisett 1998） | 本文的证明覆盖出处 + 语义 + 安全 + 可复现 |
| 翻译验证 | Pnueli–Siegel–Singerman 1998；Necula 2000 | 本文按产物逐节点发证书，不做整编译器证明 |
| 编译器正确性证明 | CompCert（Leroy 2009）、CakeML、seL4 | 本文不要求整编译器证明；它要求每产物可检查 |
| 证明可组合 | Proof-Carrying Data（Chiesa–Tromer 2008） | 本文只组合同语义域的产物 |
| 多样化双编译 | Wheeler 2005（DDC） | 本文把多样性从编译器搬到**检查器** |
| 多实现共识 | N-version programming；BFT | 本文的共识对象是「推导是否被接受」 |
| 从极小种子重建 | Guix full-source bootstrap、live-bootstrap | 本文不再把种子当根；种子是结论 |

| 逐站点安全台账 | Dissigsegv（`docs/356`）、LSPE | 它们是 `SAFE` 规则的前提 |

**组合没有检索到现成物**：per-artifact 翻译验证 + 出处/闭包 + LSPE/站点台账 + K-of-N
独立内核 + 代际 refinement，五件同时出现在一个语言工具链里。没检索到 ≠ 没有。

R4 增量：第二内核 + 商团。`tools/trust_kernel_c.c` 用 C 重写同一张规则表（自带 JSON、
SHA-256、玩具解析器、静态栈检查与解释器），与 Python 内核零共享代码。`tools/trust_quorum.py`
只做策略：按推导档位取覆盖内核，至少 k 票接受且没有相反判决；崩溃/沉默按拒绝，
「未覆盖」是回避而不是接受；重复实现、异构规则表、非法 k 直接拒。

覆盖边界：C 内核只覆盖 core 档。带 `l0` 或 `l0_safe` 的推导（R2/R3）只有 Python 内核
覆盖，商团在 k=2 时明确报 `coverage:` 并拒绝 —— 它不会被当成第二个接受票。

R5 增量：`REFINE`（第 13 条规则）。新代 `T'` 的完整推导作为前提；旧代 `T` 以容器字节 +
哈希绑在判断里。内核各算两代的偏差集 `d(·)`（玩具里是 PRINT 站点），要求 `d(T') ⊆ d(T)`，
并要求 `delta.removed` / `added` 与两集合逐项相等；新增偏差直接拒。演示：旧代两个 PRINT、
新代一个 -> 接受；反向 -> 拒绝；改 delta / 旧代字节 / 新代产物 -> 拒绝。
边界：`T` 自身的推导不在 REFINE 的前提里（宿主已有），宿主必须核对
`from_artifact_sha256` 就是已部署的 T；偏差集只表达方向，不证明语义等价；
`seed : Compiler` 的语义仍是假设 —— AX-S 只检查种子哈希的形状，不检查种子真的实现了编译器。

覆盖的判据：有效推导、两单元组合、改产物、改规则名、改前提、改 SEM 期望输出、提权、
两粒不同种子、删掉 `AX-S`、确定性、零工具链 import、**删掉编译器后仍接受**、四类畸形推导、
预算记录、TV 输出节点/映射变异、真实 L0 provenance、L0 记录/路径逃逸/闭包文件篡改、
真 LNotary bundle、lawspace claim、站点等级、fault edge 与 Potato `gc_ladder` 篡改；
R4 再加：C 内核与 Python 在 8 份 core 推导上判决一致、两内核商团接受、一个永远接受的内核
被诚实内核挡住、接受/拒绝分歧拒、单独一个接受票不足 k 拒、L0 档按覆盖取票、六类坏配置拒、
商团的 n/k/轴数进 `trust.json`。
R5 再加：只减不增的 refinement 被接受、新增/反向偏差拒、delta 与两代偏差集逐项对账、
旧代字节/哈希篡改拒、新代产物篡改拒、C 内核在 4 份 refinement 推导上判决一致、
两内核商团接受只减不增的更新。
§3.5 的 `null` 是「未测」；实测在上表。

**不成立的独立性**：语言与代码谱系两条成立；作者与组织两条**不成立**（同一维护者）。
`diversity_axes` 只记机械可测的 1 条（language），§3.4 的目标 ≥3 未达。C 内核也不覆盖
L0 档，所以 L0 推导的商团仍是 n=1。这两条是 R4 的余项，不计入「已落地」。

未落地：R4 的 L0 覆盖与第三/第四个独立内核；R5 的 `seed : Compiler` 语义（种子真的实现
编译器），以及 `docs/369` 的完整语义方向（今天的 `d(·)` 只是玩具偏差集）。

## 12. 一句话

信任链是一个错误的心智模型：链条要求每一环可信，推导只要求每一步可检查。把链条换成推导，
把编译器换成证明生产者，把种子换成结论，把单一的根换成 K 个独立内核的共同接受——根没有消失，
它从「一整个工具链」缩成「一张有限的规则表 + 一个多数」。
