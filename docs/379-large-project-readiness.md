# 379 · 大型项目就绪度：以银行收银系统为标尺的五层缺口

> 状态: **盘点 / 议程**（2026-11-22）。本文不提出新机制，只把"今天缺什么"按可证伪的判据列出来。
> 上游: `docs/210`（GC 与 arena）· `docs/241`（internet）· `docs/245`（线程）·
> `docs/329`（store 缺口）· `docs/350`（Flomtc）· `docs/356`（Dissigsegv）·
> `docs/378`（PE 垫片）· `docs/311`（LVM guest ABI）· `docs/158`（冻结面）
> 一句话: **语法层已经够写业务；离一个可上线的银行收银系统，缺的是事务型持久化、
> 生产级 TLS/DNS、支付与外设、可增长堆与线程安全 GC、以及运维/合规五层。**

## 0. 口径

- 本文按 `origin/main`（`d65cea4d`，2026-11-22）核对。当前检出 `feat/potato-v10-gc-ladder`
  落后于 main 上的类、函数指针、Flomtc 等提交，所以"已有"清单以 main 为准。
- "大型项目"拆成两组：**语言/运行时规模**与**行业交付栈**。两组都过线，才谈得上"能上线"。
- `guest ABI 网络族 R` 出自 `docs/311` §4.4：41…54 归 R 的理由是 LVM 的 T0/T2/T3
  没有 fd 表可以等；现行 `docs/243` §3.4 的规则是表外号回 `-ENOSYS`。它限制 LVM 内的
  guest，不影响原生产物：PE 垫片现在有 146 个派发号、385 个 Linux 号各有处置
  （`docs/378`），`internet` 库能跑。收银系统按 native 交付时，网络从原生产物这一侧开始。
- 本文把"缺"分三档：**完全没有** / **有但不生产可用** / **有但规模化不足**。

## 1. 标尺：一个银行收银系统的最小闭环

先定验收面，避免把"能写业务"当成"能交付系统"。

| 能力 | 今天有什么 | 结论 |
|---|---|---|
| 本地交易账本（ACID、崩溃恢复、日结/对账） | 文件原语 + 内存表 | **缺** |
| 支付受理（收单协议/终端 SDK、退款/冲正） | 无协议模块、无终端绑定 | **缺** |
| 外设（小票打印、钱箱、扫码、读卡） | `tty` / HID 级原语 | **缺** |
| HTTPS 到银行/云、DNS、断网重试 | TCP/UDP/HTTP 报文 + 窄 TLS 内核 | **半** |
| 权限与审计（收银员/班次/折扣/退款留痕） | 能力域/LSPE 是语言级，不是业务审计 | **半** |
| 商品与库存（目录、价格、税率） | 容器/JSON/CSV/TOML 有，缺业务模型 | **半** |
| 报表与导出（日结、流水、CSV/PDF） | CSV/JSON/PNG 有，无 PDF | **半** |
| 部署与升级（门店服务器、回滚、备份） | 单静态二进制 + 工具链热更新 | **半** |
| 可观测性（日志、指标、崩溃转储） | 文本日志 | **缺** |
| 合规（PCI/EMV、密钥管理、审计） | 加密原语 + RFC 向量 | **缺** |

## 2. 五层缺口

### 2.1 事务型持久化：完全没有

**现状。** 文件层是齐的：`os/fsops` 提供 tmp+rename+fsync 的原子写、`os/mmapfile`
能把文件映射进地址空间、`os/lockfile` 提供锁、`std/memdb` 提供内存表。序列化也有
JSON/CSV/TOML/INI/CBOR/MessagePack 一类的模块。

**缺什么。** 随包 store 里没有 SQL 模块，也没有 SQLite/Postgres/DB2 的绑定；没有事务、
隔离级别、索引、WAL/崩溃恢复、schema 迁移、备份/恢复、对账。多终端并发写同一份账本时，
今天只能自己设计锁与日志。

**为什么这是硬伤。** 收银系统的核心是账本。账本要求"一笔交易要么完整落盘，要么完全
不落盘"，以及断电/崩溃后能恢复到一致状态。文件原语能拼出这个形状，但那是一个存储引擎
项目，不是业务代码该顺手做的事。

**判据。** 一条程序打开真数据库文件，完成"提交 / 回滚 / 进程被杀后重开"三件事，且
提交后的行数与回滚后的行数都可核；今天这条判据是红的（模块不存在）。

### 2.2 生产级网络：有但不生产可用

**现状。** PE 垫片的派发面已到 146 个号，385 个 Linux 号各有处置（`docs/378`），
socket/epoll 等网络面在两平台都有实现；`internet` 包给出 `ip` / `uri` / `http` /
`dns` / `sock` / `tcp` / `udp` / `unixsock` / `httpsrv` / `tls`；`system/epoll` 与
`os/eventloop` 提供事件循环；crypto 原语覆盖 AES-GCM、ChaCha20-Poly1305、X25519、
Ed25519、HKDF、SHA-2/3。基础件不缺。

**缺什么。** `internet/tls` 的边界写在文件头：套件只有
`TLS_CHACHA20_POLY1305_SHA256`、密钥交换只有 x25519、证书只有 Ed25519 叶证书，
并明确写"不声称与真实服务器互通"（`lompi/store/internet/0.1.0/tls.lomt:9-13`）。
生产 HTTPS 需要 RSA/ECDSA 证书链、SNI、ALPN、会话恢复、主机名校验；这些都没有。

DNS 只有 RFC 1035 的报文编解码，没有解析器（`docs/241:46`）；`http` 不做 HTTP/2、
不做重定向、不集成 gzip（`docs/241:51`）；`httpsrv` 不做 keep-alive、不做 TLS
（`lompi/store/internet/0.1.0/httpsrv.lomt:16-18`）；lompi registry 只支持
明文 HTTP + IPv4 字面量（`docs/236:8`）。

**为什么这是硬伤。** 银行网关、支付平台、云同步、包仓库都在 HTTPS 后面。TLS 内核的
算术正确，不等于能和真实证书链握手；收银系统不能要求对端换成 Ed25519 叶证书。

**判据。** 对一个使用 RSA/ECDSA 证书的真 HTTPS 站点完成握手并取回 200；主机名不匹配时
必须拒绝。今天这条判据是红的。

### 2.3 支付与外设：完全没有

**缺什么。** 没有 ISO 8583 / ISO 20022、EMV/APDU、PIN block/DUKPT、ESC/POS 打印、
钱箱、读卡器、OPOS/JavaPOS 的随包模块或绑定。`os/tty` 只提供 `isatty`、`winsize`、
`get_attr` / `set_attr`、`raw_into`；波特率、校验位、流控要自己填 termios。没有 USB HID
封装。扫码枪通常按 HID 键盘工作，这一条今天能走；打印、钱箱、读卡走不了。

**Windows 侧的外部库更硬。** PE 的系统调用垫片已经补到 146 个号（`docs/378`），垫片
自己会调用 kernel32/ws2_32 等系统 DLL；但用户程序没有这条通路：`--link` 配
`--target pe` 仍被明确拒绝（`docs/173:121`，#1262），`windows` 包的 6 个模块只是
声明面（`docs/329:57`）。门店收银常见的 Windows 外设 SDK 是 DLL，今天调不进来。
Linux 侧可以手写 `extern fn` + `--link` 接 C 库，但没有现成绑定。

**为什么这是硬伤。** 收银系统的"收钱"和"打票"两条腿都在语言外。支付受理还叠着
PCI PTS / EMVCo 的整套认证，这不是补一个模块就能解决的。

**判据。** 一条票据模板经 ESC/POS 打印出的字节与参考实现逐字节相同；串口的
baud/parity/flow 可显式设置；一条 ISO 8583 报文与录制样本逐字节相同。今天三条都红。

### 2.4 运行时与规模化：有但规模化不足

#### 2.4.1 堆

内建 `alloc` 是 64 KiB 固定 arena（`tools/lomentc.py:1011`），`str_concat` 也走它；
`gc_auto` 按 32 KiB 触发，活集超过约 32 KB 就会耗尽（`docs/210:64`），
`gc_auto_alpha` 也只把上限抬到接近整个 64 KiB arena（`docs/210:66`）。

`std/mall`、`std/arena`、`std/pool` 提供的是"调用方给缓冲"的分配器：`mall` 在调用方
给的 arena 上做首次适应，容器不自动扩容（`lompi/store/std/0.1.0/mall.lomt:1-20`）。
大程序可以自己 `brk`/`mmap` 做内存层（自举编译器就是这么干的），但那是一个内存设计
项目，标准容器与字符串不会自动使用它。

**判据。** 一份 `choose gc_manual` 的程序在 1 GiB 活集上分配/释放不耗尽；今天的
64 KiB 版本必红。

#### 2.4.2 线程

`thread_spawn` 之后，自动收集在本进程剩余的生命里不再运行（`docs/245:274`），
线程程序里堆只增不减（`docs/245:283`）。原子操作只有 `atomic_add`，没有 CAS、没有
`xchg`、没有 fence 内建（`docs/245:243`）；非原子的同址读写是数据竞争，行为未定义
（`docs/245:245`）。没有 `Send`/`Sync` 式的类型级约束，也没有 `unsafe` 边界标记
（`docs/245` §10.5）。

对收银系统来说，后台打印、同步、心跳都可以用线程或事件循环写；但一个长跑的多线程
进程要么自己 `free`，要么堆会一直涨。线程本身能用；今天不成立的是"线程 + 自动回收"
这一格。

**判据。** 同一份 `gc_auto` 程序，单线程版与 `thread_spawn` 版在固定轮数后堆占用相同，
且 `join` 点之后回收真的发生；今天这条判据是红的。

#### 2.4.3 编译

`use` 是源拼接：依赖被并入同一个单元，顶层名字在一个单元里是平的，不做 mangling；
依赖深度上限 8 层（`tools/lomentc.py:3600`，`loment/selfhost/driver.lomt:44`）。
这是跨线 ABI 与静态调用图买来的性质，不是随手可改的实现细节。

规模上的现状：Flomtc 在 5045 行/360 函数的中等程序上基线 1987 ms，目标是 1000 ms
（`docs/350:18`）；但"模块数平方"仍是文档点名的未承诺面：1011 模块的前端是 192 s
（`docs/226:210`，`docs/350:61`）。单模块改动会重编整个单元；IR 缓存能救参考链路的
重复构建，但救不了"只改一个模块"的增量编译。

**判据。** 1000 个模块的工程改一个模块，只重编该模块；增量构建时间有一个可复现上界。
今天这条判据是红的。

#### 2.4.4 内存安全

LMS 默认七级，但第 3 级的检查只覆盖 `alloc(<const>)` 的直接指针；`ptr_add`、切片、
结构体字段不检查（`loment-safety` skill §8.2）。Dissigsegv 想买的是"安全子集内不出现
SIGSEGV，且判决写进产物"，状态还是研究稿、未实装（`docs/356:3`）。

这一格的安全检查是有的，覆盖面还不够宽：静态 E028 只认字面量下标，运行期 guard 只认
`alloc(<const>)` 的直接指针；`ptr_add`、切片、结构体字段不检查。长跑服务里一次越界写
就可能把账本写坏，所以收银系统需要比今天更强的边界。

**判据。** 安全子集内的下标/切片/派生指针访问要么被证明、要么被检查；产物里能读出
每个站点的判决。今天这条判据是红的。

#### 2.4.5 语言面：这一格不是缺口

struct / enum / match / 泛型 / 闭包 / 类 / 线程 / 通道都已经有；函数指针与类在
`choose fp` / `class` 后面，默认关（`docs/348:12`），默认档保持静态调用图。写框架、
插件、回调需要显式开维，这是设计选择，不是能力缺失。

性能也不是主要矛盾：`--opt` 档在五个 kernel 上达到 C 的 0.6–2.1×，内存型负载反超
C `-O2`（`docs/365`）。默认档慢，但它买的是逐字节可复现。

### 2.5 工具链、运维与合规

- **调试。** DAP 支持断点、单步、栈、作用域与 `variables` 请求，但局部变量的值读不出来
  （`tools/loment_dap.py:40`）。
- **测试。** `loment test` 生成 Rust harness，只跑纯逻辑（`docs/148` §7）；socket/
  真实 syscall 的行为要另写 Python 判据；没有 mock/fixture/隔离。
- **观测。** 文本日志有；应用级 metrics、tracing、崩溃转储、profiler 没有。
- **部署。** 单静态二进制是优势；工具链热更新有（`docs/368`/`docs/369`），但应用级
  滚动升级、回滚、schema 迁移没有现成方案；有 daemon/watcher 原语，没有 supervisor。
- **生态。** 13 个随包包、至少 332 个模块（`docs/329:103`），都是标准库；第三方生态
  几乎为零；registry 仍是明文 HTTP（`docs/236:8`）。
- **平台。** 只有 x86_64：Linux ELF / Windows PE。aarch64 还没有执行过，也没有
  aarch64 包（`docs/162:253`）；没有 macOS；PE 侧没有 FFI（`docs/303:280`，#1262）。
- **合规。** 加密原语是自研 + RFC 向量，但没有 FIPS/PCI 认证、HSM/TPM/密钥库、
  安全审计；POS 的 PCI PTS / EMVCo 是整套认证。也没有商业支持/LTS 承诺。

## 3. 今天能做什么、不能做什么

**能做。** 单机工具、内部管理后台、文件/CSV/JSON 数据流、内网明文 HTTP 或自制 TLS、
TUI、走 HID 的扫码枪、自己拼 ESC/POS 字节的小票、日结脚本。适合内部工具和演示。

**不能做。** 能上线的银行收银系统：交易账本、支付终端、证书链、硬件 SDK、认证和
运维都缺。

## 4. 优先级

| 级别 | 事项 | 为什么这个顺序 |
|---|---|---|
| **P0** | 通用可增长堆 + 线程安全 GC（或明确的通用分配器） | 决定任何大程序能不能在默认运行时上跑 |
| **P0** | SQLite 绑定（Linux 先行） | 决定账本能不能落地；也是最快的 ACID 路径 |
| **P0** | 生产可互通的 TLS 1.3（RSA/ECDSA 证书链 + SNI + 主机名校验）+ DNS 解析器 | 决定能不能接真实世界 |
| **P1** | PE 侧 FFI / Windows import library | 决定 Windows 外设 SDK 能不能接 |
| **P1** | ESC/POS + 串口参数 + 钱箱；ISO 8583/EMV 或厂商 SDK 绑定 | 决定"收钱/打票"两条腿 |
| **P1** | 模块级分离编译 + 名字空间 | 决定多大规模还能维护 |
| **P2** | 调试器局部变量、profiler、结构化日志/指标、原生测试框架 | 决定能不能运维 |
| **P2** | 应用级升级/回滚/迁移、LTS/合规 | 决定能不能交付给银行 |

## 5. 为什么收银系统不是下一站

收银系统把"语言能力缺口"和"行业认证 + 硬件生态"叠在一起。后者不是写代码能补的：
PCI PTS / EMVCo 是整套认证，支付终端与打印机是厂商 SDK，银行网关有准入流程。

更合适的验证目标是"门店库存 + 小票打印 + 日结 + 单机 SQLite + 内网 HTTPS 管理后台"。
它同样会逼出上面五层里的四层（持久化、TLS/DNS、运行时规模、运维），但不需要 PCI/EMV
认证。做完这一套，再决定要不要进支付与外设。

## 6. 判据：每格怎么算补上

每条判据都按同一条纪律：**先在今天的树上跑红，再修**。修完变绿还不够，把对应的开关
关掉必须重新变红，否则判据可能在测一个不存在的路径。

| # | 缺口 | 判据 | 今天应红在哪 |
|---|---|---|---|
| 1 | 可增长堆 | `choose gc_manual` 程序分配/释放 1 GiB 活集不耗尽 | `alloc` 固定 64 KiB arena |
| 2 | 线程安全 GC | `gc_auto` + `thread_spawn` 固定轮数后堆占用不单调增长 | 起过线程后自动收集不再运行 |
| 3 | SQLite | 打开真文件，提交/回滚/进程被杀后重开，行数可核 | 没有 SQL 模块或绑定 |
| 4 | 生产 TLS | 对 RSA/ECDSA 证书的真 HTTPS 站点握手并取回 200；主机名不匹配必须拒 | TLS 只到 Ed25519 叶证书且不互通 |
| 5 | DNS | 主机名解析 A/AAAA，与 `dig` 对拍 | 只有报文编解码，没有解析器 |
| 6 | PE FFI | Windows 上 `--link` 一个 import library 并调用 Kernel32 | `--target pe` 配 `--link` 被拒 |
| 7 | ESC/POS | 票据模板输出字节与参考逐字节相同；串口 baud/parity/flow 可设 | 无模块；`tty` 只有 raw/winsize |
| 8 | 模块级编译 | 1000 模块改一个模块只重编该模块，增量时间有上界 | 单单元；模块数平方 |
| 9 | DAP 局部变量 | `variables` 返回局部变量值 | 明确不支持 |
| 10 | 运维 | 结构化日志/指标可导出，崩溃转储可读 | 只有文本日志 |

## 7. 关系与边界

- `docs/329` 是 store 的缺口账，本文是"以应用交付为标尺"的缺口账；两者可以互相引用，
  但不要合并：前者按包，后者按能力。
- `docs/210` / `docs/245` 给出堆与线程的现行边界；本文只把它们翻译成"收银系统会怎么
  撞上"。
- `docs/350` / `docs/365` 给出编译与运行速度的现状；本文不把性能列为主要缺口。
- 本文**不做**：不选数据库/支付厂商，不定版本号，不承诺排期，不提出新语言机制。
- **什么会推翻这份盘点**：某条判据在 main 上已经绿；或者某份上游文档已经把某一格
  接走。出现这两种情况时，改这一行，不要保留"曾经缺过"的叙事。
