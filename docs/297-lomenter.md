# 297 · Lomenter：Loment 自己的 LLVM

> 状态：**设计**（2026-11-03）· 上游：`docs/212`（逃生舱：3.8× + 2.8×）· `docs/226`（性能账）·
> `docs/229`（LVM 的基座与两处空白）· `docs/243`（IR 的第四个读者）· `docs/249`（去优化的硬不变式）·
> `docs/285`（`par`）· `docs/286` §6.1（执行乘法）· `docs/210` §3/§5（`gc_ladder`）
> 一句话：**Lomenter 不是"更小的 LLVM"，是换了中心合同的那一套。**
> LLVM 的中心是"更快"；Lomenter 的中心是"**优化之后，产物里那几条可数的性质必须还成立**"。

---

## 0. 先换问题

"给 Loment 造一个自己的 LLVM"有三种读法，先挑一种：

| 读法 | 是什么 | 裁决 |
|---|---|---|
| **甲 · 重写** | 从零做一个与 LLVM 同规模的基础设施 | **不可能**（§1.1/§1.2），写死 |
| **乙 · 借用** | 用 LLVM 做后端，Loment 只管前端 | **已经在用**（`docs/212` 粒度 A：IR → `clang -O2`，实测 0.27×），作为**兼容环**保留 |
| **丙 · 换中心** | 自己做 IR / 分析 / pass / 后端，但**中心判据不是峰值性能**，是"优化不许改变账" | **本文做这个** |

丙不是甲的低配版。甲和丙共用零件表（SSA、phi、支配树、mem2reg、线性扫描），
但**验收标准相反**：甲问"比 LLVM 快多少"，丙问"**优化之后，还有没有第三方
不读源码就能重算出同一张账**"。

**为什么这个问法成立**：`docs/229` 已经把 Loment 能站住的独特性收敛到两处 ——
执行模型进产物、**内部缺席作为一等可验收主张**。这两处都不是 VM 带来的，
而是"**产物里的可数性质**"。优化恰恰是最容易把这些性质悄悄弄丢的一步：

* LLVM 可以**合法地**把循环变成 `memset`/`memcpy` 调用（loop idiom recognition）——
  在 `no_runtime` 的 freestanding 产物里，那是**未定义符号**；
* LLVM 可以合法地丢掉 metadata、改掉函数属性，因为那里没有"账"的语义。

**这不是 LLVM 的 bug，是它的合同允许的。** 所以"Loment 能不能把产物交给一个
不认这份账的优化器"是**语言问题**，不是工程口味问题。

## 1. 先把不可能写死（四条）

### 1.1 广度不可能

LLVM 有 ~20 个正式目标、上百个 pass、二十年人年；还有 TableGen、SelectionDAG、
GlobalISel、MC、ORC、LTO、PGO、Sanitizer 一整套。**Lomenter 不会、也不该在可见的
版本里追平这张清单。** 任何"Lomenter 要能替代 LLVM"的验收都必然失败，别设。

### 1.2 峰值不可能（这条有实测）

`docs/226` §2.1：同一份 `sum`，`lomelf` 原生 **56.6 ms**；**同一份 IR 交给 `clang -O2`
是 15.3 ms**；手写 C `-O2` 是 **11 ms**。也就是说 Loment 的**前端产物本身只比手写 C
慢 1.4×**，差的 5.1× 全在"没有优化器 + 栈机"这一段。

自己写的 pass 在 0.1.x 追上 LLVM 的向量化/循环优化**不现实**。
⇒ Lomenter 的数值目标**不是** C -O2，而是先把 `docs/212` §1 拆出来的
**3.8×（栈机税）** 拿掉，再谈 **2.8×（优化税）**。

### 1.3 单一 IR 不可能

native 要虚拟寄存器与物理寄存器，VM（`docs/243`）要栈槽，`lomelf` 今天就是栈槽机
（`tools/lomelf.py:19`）。**能共享的是语义与账，不是表示。**

`docs/243` 的"第四个读者"原则在 **LIR 层**成立；到了 MIR 层，native 与 VM 必然分叉。
把它写成"一份 IR 打天下"会让两边都变形。

### 1.4 双实现逐字节 + 优化器 —— 常规写法不可能

`docs/158` §2 钉的是"参考实现与自举侧逐字节相同"。一个**优化器**用常规写法
（哈希表遍历、指针作键、profile 驱动、浮点代价模型）产出的 IR 顺序**不可复现**，
两个实现在第一毫秒就分叉。

⇒ 这条**不是研究难题，是约束**：它一次性排除掉一大类标准实现。§10.2 是那张
"允许/禁止"清单。**本设计最贵的一笔就在这里**，比写 pass 本身贵。

## 2. 拿掉五条假设

| # | 假设 | 拿掉得到什么 | 代价 |
|---|---|---|---|
| 1 | Lomenter 必须定义**新** IR | 复用 `lomentc.py --emit-llvm` 的现有子集（`tools/lomelf.py:20`"任何产出同一子集 `.ll` 的东西都能喂进来"），只加一段**旧读者会忽略的账** | 新特性只能长在那份子集上；子集的天花板就是表示的天花板 |
| 2 | 优化器必须**快** | 0.1.6 只要求"不超过自举护栏"，先把对的做出来 | 编译器自身编译时间会先变差（§10.4 有预算，不能无限放弃） |
| 3 | Lomenter 要**取代** `lomelf` | `lomelf` 留作 **oracle 与降落伞**：每一波优化的默认路径都是"新 pass 关掉 = 旧产物逐字节不变" | 两条码路要同时维护到平价门（P0）打开为止 |
| 4 | 优化**默认开** | 先 opt-in（`loment build --opt`），平价之后才改默认 | 用户默认拿不到收益，直到 P0 全绿 |
| 5 | 可以用 **UB 换速度** | 放弃 LLVM 式"UB 即授权"；Loment 的语义是定义好的回绕/错误码，优化不许利用未定义 | 丢一批 LLVM 的强优化（§3 第二行）——这是**换合同**的价格，不是省下来的 |

**总价（先记在这里，别到后面才发现）**：

1. **每个 pass 写两遍**（Python 参考 + 自举侧），且要逐字节相同；
2. **自举编译时间**上升，而 60 s 护栏只剩 ~1%（`docs/226` §3，`docs/212` §1）；
3. **种子与容量**：自举侧固定容量越界是段错误（§10.3）；
4. **丢掉 UB 类优化**，峰值必然低于 LLVM；
5. **两条码路并存**到 P0 平价。

这五条**不是风险，是预算**。不在预算里做的波次，都是借来的时间。

## 3. 合同差异表

| 维度 | LLVM | Lomenter |
|---|---|---|
| 中心判据 | 峰值性能 | **账不变**（facts-preserving） |
| 未定义行为 | 优化器的授权书 | **不许利用**；LIR 里能触发 UB 的指令要么被语义收紧，要么 verifier 拒绝 |
| 可观察行为 | as-if | as-if **+ 账段逐项相同或单调精化** |
| 调用图 | 间接调用是一等公民 | **全静态**（`tools/lomelf.py:1034` 不支持间接调用），这是分析免费的前提 |
| 运行期 | 允许隐式 libcall / 分配 | `no_runtime` 档：**最终产物零分配器、零外部符号**；优化器引入的一律拒绝 |
| 产物 | 依赖宿主、版本、flag | **逐字节可复现**，且双实现逐字节相同 |
| 目标面 | ~20 个目标 | 先 x86-64 ELF / PE；aarch64 与 LVM 字节码随后 |
| 与语言的关系 | 与前端解耦 | IR 的**账**就是语言承诺的延续 |

一句话：**LLVM 把"编译器能假设什么"写在 UB 里；Lomenter 把"编译器必须保住什么"
写在账里。**

## 4. 架构（五层）

```text
 .lomt ──lomentc──> LIR ──analyses──> passes ──> LIR' ──┬─> MIR ──regalloc──> ELF / PE
                                                         ├─> LVM bytecode (T0/T2/T3)
                                                         └─> clang（兼容环，可选）
```

| 层 | 名字 | 职责 | 不做 |
|---|---|---|---|
| L0 | 前端 | `.lomt` → LIR（今天已有） | 不属于 Lomenter |
| L1 | **LIR** | 带账段的文本 SSA；旧读者可读 | 不做机器相关决定 |
| L2 | 分析 | 支配/循环/活跃/指向/逃逸/效果/调用图 | 不改 IR |
| L3 | pass | 规范化、mem2reg、内联、逃逸、DCE、账重算 | 不许违反 §7.2 三条 |
| L4 | **MIR** | 虚拟寄存器、栈槽、帧、调用、安全点 | 不做标量语义决定 |
| L5 | 发射 | x86-64 ELF/PE、LVM 字节码、DWARF 行表 | 不做优化 |

**边界**：Lomenter 不含前端、不含链接器（`lomelf` 的链接部分）、不含 GC 运行期。
它只拥有"从 LIR 到产物"这一段 —— 正好是今天最空的一段。

### 4.1 为什么不是"给 `lomelf` 加几个 pass"

因为 `lomelf` 的 `plan_frame`（`tools/lomelf.py:618`）是**单向降级**：SSA 直接落栈槽，
没有 use-def 图可回头改。`mem2reg` 需要 SSA 与支配信息，寄存器分配需要虚拟寄存器 ——
这两样在 `lomelf` 的模型里不存在。继续往里加，就是把它重写成 Lomenter，
同时**失去 P0 需要的那个未改动的 oracle**。所以：

* `lomelf` **冻结为参考**（只修 bug，不加优化）；
* 新东西全部落在 Lomenter；
* 平价门 P0 用两条独立码路对拍。

### 4.2 命令行面

复用既有子命令机制（`loment foo` 跑 `loment-foo`）：

```bash
loment enter prog.ll --O2 --target x86_64-linux --verify -o prog
loment enter prog.ll --passes=mem2reg,inline --facts-json
loment enter prog.ll --verify-facts --verify-deopt      # 只验，不发射
```

`--O0` 必须**逐字节等于**今天的 `lomelf` 产物（P9 的工具形态）。`--verify*` 系列
只读 IR/产物，不读源码 —— 这样第三方也能跑。

## 5. LIR：现有子集 + 三样东西

### 5.1 账段（facts）

以注释形式附在 IR 上，**旧读者天然忽略**：

```text
; @loment.facts v1
; module {"gc":"gc_manual","runtime":"no_runtime","mode":"std","alloc_sites":3}
; fn @f {"alloc":0,"effects":"pure","calls":["@g"],"indirect":0,"ladder":"L0=2,L1=1,L2=0,L3=0"}
; @loment.facts.end
```

两条规矩：

1. **账不是权威，是被证的主张。** `loment enter --verify-facts` 忽略账段、从 IR 体重算，
   与账段不一致就拒。第三方同样能跑这一步 —— 这就是 §9 的见证。
2. **账覆盖 IR 体**（不含账段自身）的 sha256 可进 lompi，做内容寻址。

为什么用注释而不是新语法：clang 与 `lomelf` 都把 `;` 行当注释跳过
（`tools/lomelf.py:20` 只吃文本 IR），所以**加了账的 LIR 仍能被旧路吃下**。
兼容环因此不需要第二种格式。

### 5.2 效果格（effects）

每个指令一个效果，函数一个摘要；格按并集闭合：

| 元素 | 触发 | 缺席的含义 |
|---|---|---|
| `pure` | 算术/比较/GEP（无副作用） | —— |
| `read` | `load` 可变内存 | 无读 |
| `write` | `store` 可变内存 | 无写 |
| `alloc` | `__loment_alloc` / `alloc` | **零堆分配** |
| `trap` | 除零、`unreachable`、越界检查 | 不会异常终止 |
| `syscall` | 内联汇编 `syscall` | 不与世界通话 |
| `extern` | `extern fn` 调用 | **零外部符号** |

摘要按强连通分量做定点（初值 = 函数内指令的并，迭代 = 并入 callee 摘要）。
因为调用图全静态，这个定点是**精确的**（相对于别名近似保守，但不是"可能有间接调用"
那种保守）。

### 5.3 区域标记（regions）

`lomelf` 与 LVM 都不认识块作用域。LIR 用可忽略的注释标记把 Loment 的回收区间显式化：

```text
; @region begin %blk.r7
  ...
; @region end %blk.r7
```

* 旧读者忽略 → 兼容；
* 逃逸/区域 pass 用它把 `free`/栈化插到正确位置；
* 账重算时 `ladder` 的 L1/L2 从区域与循环得出，**不再依赖源 AST**（§9.1）。

### 5.4 宽度与 phi 语义是 LIR 的一部分

两条从 `docs/243` §2 抄来的、**不许在规范化时抹掉**的语义：

* **宽度截断**：每条算术的结果按声明宽度截断后回写；`get` 零扩展、有符号比较走
  符号扩展。这不是代码生成细节，是语言语义。
* **phi 的并行语义**：SSA 消除时必须按**两趟**做（先读全部源，再写全部目标）。
  `lomelf` 的 `_emit_phis_then` 两趟就是因为一趟会自我覆盖。Lomenter 的
  `destroy_ssa` 必须证这一点。

## 6. 分析（第一批只要七个）

| 分析 | 为什么现在就要 | 确定性要求 |
|---|---|---|
| 支配树 / 后支配 | mem2reg、DCE、安全点 | 块序 = 规范化 RPO，平局按块名 |
| 循环森林 | L2 纪元、LICM、去优化边界 | 同上 |
| 活跃 / use-def | 寄存器分配、去优化物化 | SSA 编号 = 首定义序 |
| 指向（流敏感、字段敏感） | 逃逸、别名、`par` 足迹 | 工作列表 = 有序集合 |
| 逃逸 | L3→L0/L1 精化（§7.3） | 同上 |
| 效果摘要 | 账重算、`no_runtime` 拒绝 | SCC 按规范序 |
| 依赖图 | `par` 的任务切分（`docs/285` §4.2） | 同上 |

**`par` 的依赖图放在这里，不放在 `par` 里**：`par` 是消费者，Lomenter 是产出者。
`docs/286` §6.1 的"一份 IR → 所有执行模型"与 §6.2 的并发乘法，落点都是这一层。

**为什么指向分析可以做得比 LLVM 更准**：Loment 今天没有间接调用
（`tools/lomelf.py:1034`）。⇒ 调用图是**全程序精确图**，别名分析的上下文可以按
SCC 传，不需要 LLVM 那样为"可能被任何函数调用"付代价。
这是语言换来的，不是实现技巧。⚠ 函数指针那条线（`docs/245` 线 B）若落地，
这一条前提要重写 —— 那时 Lomenter 的指向分析也得退一档，账要重新记。

## 7. pass：第一批三条正好对上那两笔账

`docs/212` §7 已经点过三行；`docs/226` §2 把每一行量成了数。**第一批不做别的**：

| 波 | pass | 治哪一段 | 预期 |
|---|---|---|---|
| W1 | `mem2reg` + 规范化（CSE/DCE/复制传播） | 3.8× 的大半（满屏 `alloca`/冗余 load） | 先对齐 C -O0 |
| W2 | 线性扫描寄存器分配 | 3.8× 的剩下一半 | 原生进入 C -O0～-O1 区间 |
| W3 | 内联（预算确定、无 profile） | 调用密集 4×（`docs/226` §2 的 `fib`） | 调用点塌下去 |
| W4 | 逃逸 + 区域 + 账重算 | 把 L3 抬到 L0/L1，同时保住 `ladder` | 分配站点变少，账不变弱 |

### 7.1 每个 pass 的合同

一个 pass 必须申报四样：

1. **读**哪些分析；
2. **毁**哪些分析；
3. **账**怎么变（逐项：可能增大/减小/不变）；
4. 在哪些 `choose` 维下**禁止运行**（例如 `runtime=no_runtime` 下任何可能引入
   `extern` 的 pass 一律不跑）。

### 7.2 三条不许（违反即拒，不是警告）

1. **不许引入新的效果元素**：pass 若把 `pure` 变成 `alloc`/`extern`/`syscall`，
   在声明了对应缺席的模块里**拒绝该 pass**（不是"记一笔"）。
2. **不许把直接调用变成间接调用** —— 那是 §6 分析精确性的前提。
3. **不许让产物依赖宿主**：时间、路径、环境变量、哈希序、浮点舍入 —— 一出现就判失败。

⚠ 第 1 条有真实前车：LLVM 的 loop idiom recognition 会把循环**合法地**变成
`memset`/`memcpy` 调用。Lomenter 允许同样的变换，**但只能内联到自己的
`__loment_memset`**（`tools/lomentc.py:84` 已经有一份），否则拒绝。

### 7.3 梯子是单调的

`docs/210` §5 的 `gc_ladder` 是 `l0 + l1 + l2 + l3 = total_sites` 的四元组，
从强到弱 **L0 > L2 > L1 > L3**（`tools/lomentc.py:4002` 的 `_count_gc_ladder` 原话是
"从强到弱、先到先得"）。

**优化只能往上抬，不能往下拽**：

* 逃逸分析证明某站点不逃逸 ⇒ L3→L0 合法；
* 优化**不许**把一个 L0 站点变成 L3（例如为了内联而复制分配，或把区域拆开）；
* 若某个 pass 会让某站点变弱 ⇒ 该 pass 在这个模块上**被拒**，除非模块显式
  声明"允许降级"（默认不允许）。

这条约束不是洁癖：`claim` 是**源级承诺**，`realize` 是**优化后兑现**。
允许降级就等于允许编译器悄悄撕掉承诺。

## 8. MIR 与后端

### 8.1 MIR 是什么

LIR 做 SSA 消除（phi 两趟）之后，每个值落到虚拟寄存器或栈槽；显式帧、显式调用、
显式安全点。MIR 仍然**目标无关**；机器相关只在"选指令"与"分寄存器"两步。

### 8.2 寄存器分配

线性扫描，**确定性**：

* 区间按 `(首定义 SSA 号, 块 RPO, 槽名)` 的全序排；
* 溢出选择按同一全序，不按浮点近似的"最远下次使用"；
* 溢出槽不影响语言级分配账（栈不是堆），但 MIR 要标出来，供 `--verify-facts` 区分。

### 8.3 去优化元数据是**分配器的副产物**

`docs/249` §4 那条承重不变式是：

> 在每一条守卫之前，所有"不可重物化"的值必须已经在栈槽里。

今天靠 T3 实现手写维持；在 Lomenter 里它变成**分配器的一个约束**：

1. 分配器拿到 LIR 的守卫点集合（来自剖面/T3 的降级决定）；
2. 对每个守卫，把不可重物化（白名单之外：`load`/`store`/`call`/内联边界/汇编）
   且未被活跃性证明已死的值**强制落槽**；
3. `--verify-deopt` 独立重算一遍，不一致就拒。

这样 `docs/249` 的判据从"信实现"变成"可复查的产物属性"。

### 8.4 目标

| 目标 | 状态 | 备注 |
|---|---|---|

### 8.5 调试信息

今天 native 的 DWARF 靠 clang（`--debug` 发 `DILocation`，`tools/lomentc.py:6584`）。

这是 W2 的**验收项**，不是可选。

## 9. 账与见证（唯一可能新的地方）

### 9.1 三张表

产物里带三张**可被独立重算**的表：

| 表 | 内容 | 谁能重算 |
|---|---|---|
| `claim` | 源级分析给出的承诺（今天的 `gc_ladder` 就是从**单态化前的源 AST** 数的，`tools/lomentc.py:4257`） | 前端 |
| `realize` | 优化后 IR 上的实际分配站点与层级 | Lomenter 的 verifier，只读 LIR |
| `witness` | 每条缺席声明对应的**符号计数**（0 次就是 0 次）与**跑过的 pass 列表** | 任何人，只读产物 |

**关键分界**：`claim` 是**承诺**，`realize` 是**兑现**，`witness` 是**证据**。

今天这三样被混成了一个数：`gc_ladder` 在源 AST 上数出来，直接印进产物。
一旦有优化器，这个数就会**说谎** —— 优化把 L3 抬成 L0，产物里印的还是源上的旧数。
Lomenter 必须把它们分开，并要求 `realize` **逐站点不弱于** `claim`。

### 9.2 为什么 LLVM 做不到

LLVM 的 metadata（`!prof`、`!annotation`、函数属性）是**咨询性**的：优化器可以丢弃、
可以违反，且没有"这个产物必须零分配"的语义。LLVM 的 verifier 验的是**类型良构**，
不是**账**。要让它做到，得给它加一套新合同 —— 那套合同就是 Lomenter，
只是名字还叫 LLVM。

**措辞纪律**（照 `docs/229` §7）：这里主张的是"**优化后的产物仍可独立重算同一张账**"，
不是"这个想法没人做过"。检索面的边界写进 §13 第 4 条。

### 9.3 与 LSPE 的分界

LSPE（`docs/262`）审**安全**（内存、并发、义务），Lomenter 审**账**
（分配、效果、缺席、确定性）。两者共用 LIR，但**不互相替代**：

* LSPE 可以拒绝一个"账全对但不安全"的程序；
* Lomenter 可以拒绝一个"安全但账对不上"的产物。

## 10. 自举与孪生

### 10.1 三阶段

| 阶段 | 实现 | 判据 |
|---|---|---|
| S0 | Python 参考（`tools/lomenter.py`） | 与 `lomelf` 平价（P0） |
| S1 | Loment 实现（`loment/selfhost/lomenter/`） | 与 S0 在语料上逐字节相同（P3） |
| S2 | 用 S1 编 S1 | stage2 与 stage3 **逐字节相同**（P6） |

### 10.2 确定性允许/禁止清单

| 允许 | 禁止 |
|---|---|
| 有序容器（列表 / 平衡树） | 哈希表遍历顺序 |
| SSA 编号 = 首定义序 | 指针值 / 对象地址作键 |
| 块序 = 规范化 RPO + 名字平局 | 递归 / 工作列表的"栈序"直接进产物 |
| 整数代价模型 | 浮点启发式 |
| 固定的 pass 顺序与版本号 | 环境变量 / 时间 / 路径影响产物 |
| 显式 opt-in 的剖面（带哈希） | 隐式 PGO |

**校验手法**：debug 模式下每个 pass 后跑一次 `normalize`；IR 文本变了就说明该 pass
不规范化。这条比"两个实现比对"更早发现问题，也更容易定位是哪个 pass 不纯。

### 10.3 容量与种子

⚠ 自举侧有固定容量（源文件槽 `SLOT`、标签表 `TB_LBL_MAX`），**越界是段错误不是报错**；
种子还有 ~3.71 MB 的悬崖（issue #441；2026-10-17 复测 3.88 MB 通过）。

⇒ Lomenter 的 S1 实现必须**按流式设计**（不建整模块大表），否则先撞容量；
确实要建表时，先扩容量并补一条判据，不能"跑了再说"。

### 10.4 预算

自举编 `codegen.lomt` 今天 ~5.9 s，60 s 护栏只剩 ~1%（`docs/226` §3）。
Lomenter 自己会变慢（多跑 pass），**它的自身编译时间必须进判据**：
每一波结束记一次绝对时间，超过预算就回退该波，而不是调护栏。

## 11. 波次（依赖顺序，不是预算顺序）

| 波 | 内容 | 出口判据 |
|---|---|---|
| W0 | LIR 账段 + 区域 + verifier（**零优化**） | 现有语料 IR 逐字节不变；账段可重算 |
| W1 | mem2reg + 规范化 | P1（≥1.3×）；P0 仍绿 |
| W2 | 寄存器分配 + 自有 DWARF | P1（≥2×）；P0；P4 |
| W3 | 内联 + 逃逸/区域 | P2（账不弱）；P5 |
| W4 | LVM T2/T3 吃 LIR | P7（去优化继续跑） |
| W5 | Loment 实现 S1 | P3 |
| W6 | S2 定点 | P6 |

⚠ **W0 必须先于一切**：没有账段与 verifier，W1 之后的每一波都是"改完再补账"，
必然补不上。这也是本仓的老教训：`boundary` / `gc_ladder` 都是**先定形状、再填实现**。

⚠ **W1–W3 每波都先跑 P0**：新 pass 关掉时必须与今天的产物逐字节相同；
否则你不是在优化，是在改语义。

### 11.1 止损点

**如果 W2 达不到 P1（≥2×）**：这条线停，回到 `docs/212` 粒度 A（`clang -O2`，实测 0.27×），
并把 W0/W1 的账段与 verifier 单独留下 —— 它们即使不配优化器也有用（账可被独立重算）。
写在这里，是为了不让沉没成本替我们决定下一步。

**如果 W3 的账开始说谎**（P2 红）：先停优化，把 `claim`/`realize`/`witness` 三张表
补成硬门禁，再恢复。**账错一次，后面所有性能数字都不作数。**

## 12. 判据（每条先在未修的实现上跑红）

| # | 判据 | 证伪方式 |
|---|---|---|
| **P0** | **平价**：同一份 LIR，Lomenter 产物与 `lomelf` 产物 stdout + rc 逐字节相同 | 任何一条语料不同 ⇒ W1+ 不许改默认 |
| **P1** | **收益**：`docs/226` 四条负载上，Lomenter ≥ 1.3×（W1）/ ≥ 2×（W2）/ ≥ 3×（W3）于 `lomelf` | 没到 ⇒ 这一波没做完，别进下一波 |
| **P2** | **账不变弱**：`realize` 逐站点不弱于 `claim`；`no_runtime` 产物里 `__loment_alloc` 计数 = 0、外部符号 = 0 | 任何一条变弱 / 出现符号 ⇒ 拒绝该 pass |
| **P3** | **孪生**：S0 与 S1 在同一语料上产出的 LIR' 逐字节相同 | 任一不同 ⇒ 该 pass 的确定性不合格 |
| **P4** | **不用 UB**：`x*2/2` 在有符号溢出夹具上必须保留回绕值（Loment 语义），不得折成 `x` | 折了 ⇒ 换了合同，不是实现 bug |
| **P5** | **无 clang**：在无 clang 的容器里从种子构建 + 跑语料全绿 | 任何一步要 clang ⇒ 这条线没断奶 |
| **P6** | **自举定点**：stage2 == stage3（逐字节） | 不等 ⇒ S2 没成立 |
| **P7** | **去优化**：`docs/249` §5.1 的副作用判据（守卫前有且仅有一次副作用，守卫失败后仍只发生一次）；且 `--verify-deopt` 独立通过 | 发生两次或验不过 ⇒ `docs/249` 的不变式没被分配器强制 |
| **P8** | **预算**：自举编译 `codegen.lomt` 的绝对时间不超当前值 × 1.5 | 超 ⇒ 回退该波 |
| **P9** | **默认档不变**：不写 `--opt` 的构建，产物与今天逐字节相同 | 变了 ⇒ 违反 `docs/175` §3.4 的"默认档一行不动" |

**方法论要求**（本仓既有纪律）：P0–P9 每一条都要在**尚未实现**的树上先跑红，
再实现；"空判据"比没有判据更坏 —— 下游条件替你挡下的那一条，永远不知道自己没测。

**一条不要写的判据**：墙钟比值当门禁。同一个量能测出 3.2× / 4.13× / 5.4×，
界 5.0 落在机器散布里（`docs/226` §2.2 的记账）。P1 的倍数只作**波次出口**，
进 `ci.py` 的只能是**确定性量**（IR 指令数、分配站点数、符号计数、产物哈希）。

## 13. 我不主张

1. **不主张 Lomenter 是新的 IR 或新的优化技术** —— 零件全是 LLVM/SGI 那一族的既有物。
2. **不主张能追上 LLVM 的峰值** —— §1.2 有实测，追不上；目标是拿掉栈机税。
3. **不主张现在是 0.1.6 的范围** —— 这是一条从 W0 开始的长期线，0.1.6 只可能落到 W2。
4. **不主张 §9 的"可重算的账"没人做过** —— 只主张"没检索到把**优化后产物的账**
   作为加载期可核对象的编译器"。已查过的相邻物：Wasm 的空 import 段是**接口语法**；
   eBPF 是白名单；PCC 是**另生产的证明**（成本位置不同，`docs/229` §2.3 的分界照用）。
   **没检索到 ≠ 没有。**
5. **不主张已经量过所有目标** —— 只量过 x86-64 ELF 的栈机与 clang 路；
   PE / aarch64 / LVM 的数值一个都没有。
6. **不主张这条线能替代 `par` / LSPE / 热更新** —— 它只提供分析层；那些线各自还有
   自己的判据与成本。
