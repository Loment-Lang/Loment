# 341 · 字符串插值：`f"…"` / `rf"…"`（前端改写）

> 状态：**已落地**（2026-11-11，两套实现）· 版次：Tur 2026.3 及以后
> 上游：`docs/296` §5（字符串插值 / 格式化那一项）· `docs/337`（`str_num`，它的底）
> 判据：`loment_grammar_test::test_str_interpolation`、
> `loment_p8_test::test_m104_str_interpolation_twin`

---

## 1. 表面语法

```rust
module demo
choose runtime

fn main() -> u32 {
    let n: u32 = 42;
    let s: str = "hi";
    let b: bool = true;
    print(f"n={n}");              // n=42
    print(f"{s}/{n}!");           // hi/42!
    print(f"{b} {n=}");           // true n=42   （`=` 调试图：原文 + `=` + 值）
    print(f"{s!r}");              // "hi"        （`!r`：加引号并转义）
    print(rf"raw\n{n}");          // raw\n42     （`rf`：不处理反斜杠转义）
    print(f"{{lit}}");            // {lit}       （`{{` / `}}` 是字面量花括号）
    return 0;
}
```

| 形状 | 语义 |
|---|---|
| `f"…"` | 插值字符串；转义表与普通字符串同一张（`\n \t \r \0 \\ \"`） |
| `rf"…"` | **不处理转义**的插值字符串；`\` 就是 `\`，花括号规则相同 |
| `{{` / `}}` | 字面量花括号（两种串都一样） |
| `{expr}` | 孔；`expr` 是**任意表达式** |
| `{expr=}` | 调试图：先印 `expr` 的原文与 `=`，再印值 |
| `{expr!s}` | 走 `str_show`（对 `str` 是恒等） |
| `{expr!r}` | 走 `str_repr`：`str` 加引号并转义 `\\ \" \n \t \r`；整型 / 布尔同 `!s` |
| `{expr:>W}` / `{expr:<W}` / `{expr:^W}` | 宽度 W，右 / 左 / 居中（走 `str_pad`） |
| `{expr:0W}` / `{expr:W}` | 用 `0` / 空格填充、右对齐（宽度不够才分配） |

孔里的值收三种：`str`、`bool`（印 `true` / `false`）、**任意整型**（有符号带 `-`）。
其它类型（结构体 / 枚举 / 数组 / 切片 / `ptr`）在 `str_show` 那一层报 E001。

**不做**：跨行的插值字符串与跨行的孔；孔里再嵌一层插值字符串；格式说明里的
**动态宽度**（`{x:>{w}}`）与千位分隔 / 浮点 —— 语言没有浮点。这些都**响亮地拒**。

## 2. 它不是语法构造，是**读法**

整段的改写在前端完成，lexer / parser / checker / codegen **一行都不动**：

```
f"a{x}b"   →   str_concat(str_concat("a", str_show(x)), "b")
```

* 文本段变成**普通的字符串字面量**（所以转义、字符串常量编号、`.str.<fn>.<n>`
  的编号全都照旧）；
* 孔里的表达式**原文照抄**，外面包一层 `str_show(` / `str_repr(`；
* 多个片段**左结合**折成 `str_concat` 链。

这与 `docs/296` §2.1 的 Tur 2 纯糖、`choose write grammar` 的抹除是同一条做法：
**"怎么读"属于前端，不属于语法**。好处是语言面不必为它加产生式，两套实现的
parser 与 codegen 都不用动；代价是**读 L1 源的其它入口**（`lomfmt` / `lomdoc` /
LSP / 编辑器的着色）还没认它 —— 它们会把 `f"…"` 当普通字符串原样留着，不坏，
但也不高亮、不检查（见 §6）。

### 在哪里改

| 侧 | 落点 |
|---|---|
| 参考实现 | `tools/loment_fstr.py`（扫描 + 列号映射）；`lomentc.load` 在 `_tur2_sugar` 之后调用，**只在生效版次是 2026.3 时** |
| 自举侧 | `loment/selfhost/driver.lomt` 的 `interp_rewrite`；`load_file` 在 `tur2_sugar` 之后按 `PROF_OFF == 2` 调用 |

**自举侧是原地改**：先按字节在槽里量出新长度，再把尾巴挪开/挪拢（`iw_move` 处理
重叠），最后把改写结果写回去。写之前把这一段抄到槽顶的 64 KiB 暂存区
（`IW_SCRATCH`）—— 输出通常比原文长，就地写会追上读游标、把还没读到的那几字节盖掉
（实测：`str_concat` 被写成 `r_concat`）。一段插值字符串超过暂存区、或源大到与
槽顶暂存区重叠，都**报错退出**，不静默截断。

两边产出的文本必须**逐字节相同** —— 那是 IR 逐字节相同的前提（`loment_p8_test`
的 M104 钉着它）。

## 3. 三个内建

| 名字 | 签名（实际接受） | 落点 |
|---|---|---|
| `str_show` | `str` / `bool` / 任意整型 → `str` | `str` 恒等（一个字节都不发）；整型同 `str_num`；`bool` 走 `@__loment_bool_to_str` |
| `str_repr` | 同上 | 整型 / 布尔同 `str_show`；`str` 走 `@__loment_str_repr`（`"` + 转义 + `"`） |
| `str_pad` | `(str, u32, u8, u32) -> str` | 宽度 / 补零：够宽就原样返回，否则分配并填 `fill`、按 `align` 放（`@__loment_pad`） |
| `str_num` | 任意整型 → `str`（`docs/337`） | 十进制；插值里整型孔的底 |

四个都是**全版次的内建**（累积命名空间，与 `str_num` 一样）—— 但插值本身只在
2026.3 起才有，因为改写在版次那一层判。

三个运行期 helper 与 `_IR_NUM_TO_DEC` 同一形状：**只在真用到时随产物发**。
判据是**源里有没有这两个调用**（名字 + 紧跟 `(`、且不是 `fn` 后面的声明），
不是"产物文本里有没有那两条 call" —— 自举侧的运行期块写在函数体**之前**，
它那时还不知道实参类型；两边用同一条 token 判据，产物才逐字节同。多发的代价是
一段没人调用的 `internal` 函数。

## 4. 与运行期那一维的关系

`str_show` / `str_repr` 都进了 `_RUNTIME_SITES`（`no_runtime` 会点名拒）。
**这是保守的**：`f"{s}"` 其实编成恒等、一个字节都不分配，但这一维的判据长在
token 上，看不见实参类型 —— 按 `docs/217` 那条不对称（多报 = 一次点名拒，
漏报 = 保证失效），往"会拖运行期"那侧偏。要纯 `str` 的插值又不想开运行期，
直接写那个变量。

## 5. 列号映射表

改写只在一行之内增删字符（跨行的串与孔都拒），所以**行号一字不动**。列号用
`loment_fstr.ColMap` 映射回去：

* 逐字节照抄的片段（文本段、孔里的表达式原文）**线性**映射；
* 合成出来的片段（`str_concat(` / `str_show(` 与前缀 `f` 的位置）**塌到**它所属
  孔的边界：`(` ← `{`，`)` ← `}` —— 孔里少写东西时解析器报在合成的 `)` 上，
  用户该看到的是自己写的那个 `}`；
* 片段之后的列按累计位移校正。

`lomentc.load` 在词法 / 解析两处把 `LomError` 的列过一遍这张表。自举侧的诊断本来
只带行号，没有要映射的东西。

## 6. 宽度与补零（`{x:>5}` / `{x:05}`）

格式说明只认四种形状（`[0]?[<>^]?W`，W 是 1..65535 的十进制）：

| 写法 | 对齐 | 填充 | 例子（值 `42` / `"hi"`） |
|---|---|---|---|
| `{n:>5}` / `{n:5}` | 右（缺省就是右） | 空格 | `   42` |
| `{n:<5}` | 左 | 空格 | `hi   ` |
| `{n:^5}` | 居中 | 空格 | ` hi  ` |
| `{n:05}` | 右 | `0` | `00042` |

改写是**再包一层**：`f"{n:>5}"` → `str_pad(str_show(n), 5, 32, 1)`。

* `str_pad(s, width, fill, align) -> str` —— 第四个实参 0 = 左、1 = 右、2 = 居中；
  `s` 已经够宽时**原样返回、不分配**（与 Python 一样：宽度是**下限**，不截断）；
  否则分配 `width` 字节、用 `fill` 填满、把原字节按对齐拷进去。
* 填充字符写成**整数字面量**（空格 32、`0` 48）—— 语言里没有字符字面量。
* 运行期那一段是 `@__loment_pad`（`memset` + `memcpy`），只在真用到 `str_pad` 时
  随产物发；`str_pad` 与 `str_show` / `str_repr` 一样进 `_RUNTIME_SITES` 与堆站点。
* 列号映射：`str_pad(` 与 `, W, F, A)` 都是合成片段，塌到孔的 `{` / `}` 上。

## 7. 明确不做

* **格式说明**（宽度 / 补零 / 对齐）：下一阶段；
* **跨行**：v1 为了让行号不动刻意拒绝；
* **孔里嵌插值**：外层孔的扫描按普通字符串读内层，报"未闭合"；
* **读 L1 源的其它入口**（`docs/182` §1.9 那段清单）：
  * **`tools/loment_lsp.py`（开发口的语言服务）**补了同一条改写（`_parse` 里；版次口径
    与 `load` 相同，解析错的列号过 `ColMap`）。不补的话，一份编得过的插值源在它那里报
    假解析错（实测 `6:12 期望 )，得到 'n={n}'`）。判据
    `loment_lsp_test::test_python_lsp_reads_interpolated_strings`；
  * **`lomfmt`** 学会"前缀与字符串粘着"（**两个实现都改了**）：此前它把 `f"…"` 排成
    `f "…"`，把一条读法拆成两个 token（格式化后的文件编不过）。判据
    `loment_fmt_test::test_fmt_keeps_interpolated_strings_glued`；孪生的边界用例里也
    加了一份插值源，两边逐字节同；
  * **出厂的 `lsp.lomt`** 不在此列：它按 **Tur 1 口径**读（`#262`），Tur 2 的纯糖
    （`def` / `and` / `or` / …）本来就不认 —— 插值与那些糖同一档，不在本次范围；
  * **`lomdoc` / 编辑器着色**仍把它当普通字符串：文档不展开孔，着色按字符串走
    —— 不坏，但是没有孔的高亮。
* **运行期求值顺序**：链是左结合的，孔从左到右求值（与书写顺序一致）。
