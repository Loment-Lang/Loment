# 262 · LSPE：Loment Safety Police Espace —— 安全系统的自我审查

> 状态: **设计**（2026-10-18，第三稿）· 落点: `docs/262` · 输入: `docs/205`（R1/R5/C5）、
> `docs/253`（LMS 七级）、`docs/210`（LGC 四层梯）、`docs/206`（所有权边界）、
> `docs/208`（声明式不可观察）、`docs/182`（`choose` 与诊断码）、`docs/191`（错误报告）
>
> 一句话: **编译器先审问自己;审不动了,才轻声问人;每一次放行都必须有来源,
> 每一次回答都必须进产物。**
>
> **审的是编译器自己的判决 —— 不是用户的程序,更不是写程序的人。**
>
> **它不是上帝，是店员。**
>
> **LSPE 由四件组成：质疑器、反问器、警察 LSPC、台账。**
> 质疑器对内，审自己的判决；反问器接住它证不出来的格子；
> LSPC 在编译前贴条；台账把每一次放行与每一次不修都记下来。
>
> **反问器一出,绝对就破了一个口 —— 因为它把结论的一部分交给了人。**
> 补这个口的是 **LSPC**:编译前把残余风险摊开,你爱修不修;
> 它保证的不是"程序无缺陷",而是"**不存在你还不知道就承担了的风险**"。
>
> 命名: 全称 **Loment Safety Police Espace**，缩写 **LSPE**（读作 L-S-P-E）。
> **不写 LSP** —— 那个缩写在本仓已属 Language Server Protocol
> （`loment_dap.py` 与语言服务那一线）。

---

## 0. 一句话与管辖面

LSPE **不是第七套检查器**。它是**督察 + 台账**：

> **执法者不变；新增的是"谁批准了这次放行"与"哪一次没批下来"的可复核记录。**

| 安全面 | 问什么 | 今天的执法者 | LSPE 的位置 |
|---|---|---|---|
| 生命周期 | 这块内存**什么时候归还** | **LGC**（四层梯 + 三档 + `gc_ladder`，`docs/210`） | 读它的判决，进台账 |
| 合法性 | 这个单元**凭什么碰**这块内存 | **LMS**（七级 + `lms` 一维，`docs/253`） | 读它的判决，进台账 |
| 权限 | 这次访问**落在谁的域里** | `capability` / `guard` / `excluded` / `revocable`（`docs/146`） | 读它的判决，进台账 |
| 运行期 | 这份产物**能不能不带运行期** | `runtime` / `port` 两维（`docs/182`） | 读它的判决，进台账 |
| 所有权 | 移动/借用**在哪个子集里被证** | E006/E007/E012（`docs/206`） | 读它的判决，进台账 |
| **可复核性** | **上面每一条判决，凭什么** | **没有** | **质疑器** |
| **编译前告知** | **这份代码将来会在哪儿需要你背书** | **没有** | **LSPC** |

**LSPE 由四件组成**（用户 2026-10-18 定）：

| 件 | 在哪 | 一句话 |
|---|---|---|
| **质疑器** | 编译中，**对内** | 审自己的判决 |
| **反问器** | 编译中，**转交** | 把洞交给开发者：选项、默认、后果 |
| **警察 LSPC** | **编译前** | 贴条：风险、归责、你爱修不修 |
| **台账** | 产物 | 记下谁开的、谁关的、谁背的书 |

**Espace 不是修饰词，是这套系统的作用域。** 一个编译单元 `U` 的 LSPE 空间是：

```rust
Espace(U) = <Sites, Obligations, Evidence, Questions, Ledger>
```

四件都在这一个空间里活动：质疑器在 `Sites` 上生成 `Obligations`，
反问器把 `Questions` 交给开发者，LSPC 站在**空间门口**贴条，台账是空间的记忆。
**空间的边界就是站点普查（§5.1）**：普查之外没有站点，`Espace` 之外没有放行 ——
越界的站点一律 E035。

**报警的是警察，不是上帝**（§1.3）：LSPC 贴条、开单，**不审判**。

**不重命名既有组件。** `LMS` / `LGC` / 能力域的名字已经进了 `lom/*.lom` 契约、
Potato 字段与 ~1700 处文档引用；改名是**契约变更**，不是"统一"。
统一发生在**状态层**：所有安全组件把判决交给同一本台账，由 LSPE 做交叉对账。

这不是妥协，是 `docs/253` §1.4 那条新颖面的直接兑现：

> **不是"更强的检查器"，而是把"凭什么放行"印在产物里。**

LSPE 就是那个"印"。而**印的过程**，就是质疑器。

### 0.1 质疑器审问的是谁

**不是用户。不是用户的代码。是编译器自己的判决。**

| | Rust | LSPE |
|---|---|---|
| **谁被审问** | **用户的程序**（"它满足借用规则吗"） | **编译器自己的判决**（"我这次放行，凭什么"） |
| **谁举证** | 用户（改代码、加标注、拆结构） | **编译器自己**（找来源、找反例、对质另一个实现） |
| **用户何时出场** | **第一时刻** | **两处**：编译前的告知（LSPC）与编译中的填洞（反问器）；**都不是被审问** |
| **证不出来时说什么** | "**你的代码**不满足规则" | "**我的证明**在站点 S 有洞" |

箭头方向：

```
Rust:     rustc ──质问──▶ 用户的代码 ──不满足──▶ 用户必须举证

LSPE:     质疑器 ──质问──▶ 编译器自己的判决
                              │
                          证不动
                              ▼
                           反问器 ──转交"我的洞"──▶ 开发者
```

**这不是修辞。** 它决定三件可检查的事：

1. **证不出来时，不能说"你的代码有问题"。** 只能说"我在站点 S 的证明有洞"（Q 码）。
2. **用户出手之前，三问必须都跑过。** `tried[]` 缺任何一问 ⇒ **E036**
   —— 自审没做完就转交，是越权。
3. **程序只是判决的论域，不是被告。** 质疑器的输入是 `Judgment`，输出是
   `Derivation` 或 `Hole`；代码只在"这个判决说的是哪段程序"的意义上出现。

第三点尤其要守住：**把输入写成"程序"，质疑器就会退化成 Rust 那种"审代码"的东西；
写成"判决"，它才是在审自己。**

## 1. 前史：方向本身就是分歧

`docs/253` §1 已经把 Rust 2026-10-13 那两条不健全缺陷（#164250 / #164243）与
"未标注的地板"讲透了，**这里不重述**。本节只取两件那篇没有展开的事。

### 1.1 方向

| | Rust | LSPE |
|---|---|---|
| 编译器问的问题 | 「**这段代码**满足规则吗？」 | 「**我这个判定**凭什么成立？」 |
| 谁举证 | **开发者** | **先编译器，后开发者** |
| 证不出来时 | **编译错误** | **一个带选项的问题** |
| 编译器能不能说"我证不出" | 不能 —— 它只有"过 / 不过" | **必须说**，否则 E034 |
| 地板 | **无标签** | **每个站点都有 id** |
| 关闭安全机制 | `unsafe` 块 —— 仍是**断言** | `lspe_close_admin` —— **选择不被审计**，检查一条不少 |

§0.1 已经把"审谁"单独拎出来了；这一节只说**方向**。

**"背道而驰"具体是哪一条？** 是**举证责任的方向**。

Rust 的编译器把自己放在**判定者**的位置：它不下场，只宣布结果。
`docs/253` §1.2 的教训是，这个位置**不可复核** —— 判定者错了十一年，事后无人能看出来。

LSPE 把编译器放回**当事人**的位置：它是作出放行决定的那一方，所以它先要为自己的决定
找依据、找反例、对质另一个实现；三条都过不去，才把问题交给人。
**"我证不出来"是一等公民**，而不是一个被吞掉的异常。

### 1.2 那两条缺陷里，哪一条直接塑造了质疑器的形状

#164243（`exit` 触发 TLS 双重析构）在 std 里，质疑器管不到 —— 那是运行期。
**#164250 才是本节的骨头**：它的机制是

> **统一化（unification）时不重查 lifetime bound。**

换成任何语言的通用形状：

> **一个在替换前成立的良构性（well-formedness）义务，在类型变量被替换之后
> 没有被重新证一遍。**

这不是"少写了一条 if"。这是**义务的生命周期**问题：
一条义务在替换后**失效了**，但系统把替换前的证据当成了替换后的证据。

⇒ 质疑器必须有一条**一等公民的 `WF` 义务**，并且**每一次替换都要重证**（§5.7）。
这条要求不是从"安全"里推出来的，是从 Rust 那次缺陷里**反向抄下来的**。

### 1.3 不是上帝，是店员

> **Rust 的借用检查器是上帝。LSPE 是店员。**

"上帝"不是骂人，是说它的**位置**：判定者，站在程序之外，只宣布结果，不解释依据。

| | 上帝（Rust 借用检查器） | 店员（LSPE） |
|---|---|---|
| 位置 | 判定者，站在程序之外 | **服务者，站在交易之内** |
| 说话方式 | "不行。" | "这件没有；这件有，但需要你确认。" |
| 结果 | 二值 | **三值 + 一张小票** |
| 举证 | 你证明给我看 | **我先自己找，找不到才问你** |
| 依据 | 不必解释（编译器说了算） | **必须点名**（站点、义务、来源） |
| 地板 | 不告诉你它假设了什么 | **逐条标价** |
| 出错时 | 十一年无人能复核（#164250） | **有小票可查**（派生树 / 台账） |
| 关闭 | `unsafe`：你向神申请豁免 | 关掉审计：**你在小票上签字** |
| 权威来源 | 编译器自身 | **公开的店规**（`standard/LLS.md`） |

**"店员"不是修辞，它约束四件事**：

1. **店员不宣称自己是店主。** LSPE 不拥有语义；每条义务都点名语义所有者
   （`docs/210` / `docs/253` / `docs/146` / `docs/206`）。它只负责把判决记清楚。
2. **店员必须报价。** 每一族残余风险都要有"如果它不成立会怎样"（LSPC 预检单，§7.2）。
   **不报价的店员不是店员，是骗子。**
3. **店员会问，但不命令。** 找不到就转交（反问器，§6），给选项、给默认、给后果；
   不说"你必须"。
4. **店员有小票。** 每一次放行有派生树，每一个不修为有 `ack`，每一次关掉审计有记录。
   **上帝不需要小票；店员的一切都可复核。**

**边界：店员不是无原则的服务员。**

- **店规是公开的**：`REFUTED`（有可构造反例）仍然是**硬拒绝**，不给"你爱修不修"；
- **店员可以拒卖**：`--lspe-mode=strict` 下未回答的问题升级成 E034；
- **店员的错也能被查**：E036 是自检码，坏台账夹具必须让它红。

> **如果 LSPE 开始说"你必须"，它就不是店员，是上帝换了个柜台。**

这句是本设计的**退化判据**：一旦出现一条**点不出站点、点不出义务**的硬拒绝，
就说明质疑器在某处退回了二值断言。

### 1.4 把权力还给用户

> **事实归编译器，决定归用户。**

Rust 的借用检查器把两件事混在一起：它既判定**什么是真的**（这段代码是否满足规则），
也替你决定**你愿意承担什么**。LSPE 把它们拆开：

| | 归谁 | 形态 |
|---|---|---|
| **事实** | 编译器 | 义务、证据、反例、来源 |
| **决定** | **用户** | 修 / 接受 / `lspe pass` / 关闭审计 |
| **知情** | LSPC | 编译前把残余风险摊开 |
| **归责** | 台账 | 谁开的、谁关的、谁背的书 |

四件在这个目标下各有位置：

- **质疑器**：取消编译器的"我宣布"资格，它必须先作证；
- **反问器**：把决定权交出去，而不是替你决定；
- **LSPC**：让交权变成**知情同意** —— 没有告知的授权不是自由，是骗局；
- **台账**：让自由带账本 —— 你可以下御令，但不能假装没下过。

**边界：编译器保留"反例否决"。** 有可构造的反例时仍然硬拒绝。
那不是权力，是事实 —— 主权者可以决定风险，不能决定 1+1=3。
**决定可以下放，事实不能。**

这也是 `lspe pass` 不会退化成 C 的原因：**C 给你自由，但不给你记录；LSPE 两样都给。**

对外故事：中文可以直接说"上帝"；英文用 judge / oracle ——
"Rust made the compiler a judge. LSPE gives the verdict back to you."

## 2. 先把不可能性写死

按 `docs/210` §1 / `docs/253` §2 的规矩：**不要问概率，问哪一条假设可以合法删掉。**

**A. 完备的自证不可能。**
"这段程序绝对安全"是不可判定的（Rice 那一族）。⇒ LSPE **不承诺**"没有漏洞"。

**B. 自动消解全部 UNDECIDED 不可能。**
若编译器能自动判定所有未决，它就已经是那个不可判定的判定器。⇒ 反问器必须**存在**，
且必须把决定权交回人。

**C. 零成本的问答不可能。**
每一个问题、每一个回答都要进产物；不进产物的"温柔"就是 Rust 那块无标签的地板。
⇒ **不记账的 defer 一律非法**（E036）。

**D. "更安全 = 检查更多"不可能。**
`docs/253` §2 已证明「完备 + 零成本 + 不改语言」是闭合的死链。
再加一层检查，不会把不可判定变成可判定。⇒ LSPE 的安全不是**更强**，是**更可复核**。

**E. 单一机制不可能。**
Rust 自己的教训：一个全局承诺，一处漏检就整体崩塌。
⇒ LSPE 不合并检查器，只合并**台账**；每一格判决仍由原组件负责。

**F. 一个不膨胀的质疑器不可能。**
如果质疑器只问"有没有来源"，那它就是一个查表 pass —— 而 Rust #164250 证明，
**查表挡不住"证据在替换后失效"**。要挡住那一类，质疑器必须**带义务图、带替换日志、
带重证**。这是它尺寸的**下限**，不是上限。

**G. 绝对无缺陷不可能；绝对告知可能。**
"程序绝对安全"是不可判定的（A）。但"**每一个风险都被告知过**"是**过程性质**：
可枚举、可判定、可离线核对。⇒ 这是 LSPC 唯一能"绝对"的那一层（§7.4）。

**⇒ LSPE 能承诺的只有一句：**

> **没有一条放行是无声的。**

不是"没有 bug"，是"没有**未被标注**的放行"。
LSPC 把这句话**提前到编译之前**：不是等到放行时再标注，
而是在你按下编译前，先把"将来会在哪儿需要你背书"摊开。

## 3. 可以合法拿掉的三条假设

### 3.1 「编译器是判定者，不是当事人」—— **拿掉**

拿掉它，编译器就必须先审问自己。这正是质疑器（§5）存在的理由。

### 3.2 「错误必须当场回答」—— **拿掉**

拿掉它，问题可以被**推迟**。但推迟**不等于消失**：
`defer` 是一个**有记录的状态**，不是一个空操作。Rust 没有这个状态 ——
它只有"编译失败"，于是所有"我知道这里可疑但说不清"的知识都被迫留在人脑里。

### 3.3 「安全状态只能在运行期观察」—— **拿掉**

`docs/253` §3.3 已经拿掉过一次（组成可以是产物里的一个数）。
LSPE 拿掉的是**剩下那一半**：不只是"这份产物安不安全"可数，
**"这套安全系统自己现在处于什么状态"也可数**（§8）。

## 4. 方向：负担转移表

| 问题 | Rust | LSPE |
|---|---|---|
| **被审问的对象** | **用户的程序** | **编译器自己的判决** |
| **用户何时出场** | 第一时刻 | 编译前（被告知）与最后时刻（填编译器已命名的洞） |
| **"绝对"在哪一层** | 无 —— 承诺的是程序性质 | 程序性质不可绝对（§2·A）；**告知与归责可绝对**（LSPC，§7） |
| 谁先举证 | 开发者 | 编译器 |
| 编译器证不出时 | 静默或报错 | **UNDECIDED**，带义务链与三问记录 |
| 交给人的形式 | 错误信息 | **问题**：后果 + 默认 + 可撤销 |
| 人的回答 | 改代码 | `answer` / `defer` / `refuse`，**都进台账** |
| 回答失败（不答） | 编译不过 | **默认 = 允许但标注**（`lspe_open_admin`） |
| 关闭 | `unsafe`（仍是断言） | `lspe_close_admin`（**选择不被审计**，并写进产物） |

**温柔不是更松。** 温柔是**把"你错了"换成"我证不出来，这是你的选项和后果"**。
松紧由 `lspe` 状态与 `--lspe-mode` 决定（§10），不由语气决定。

## 5. 质疑器：LSPE 的绝对核心（它审的是自己）

### 5.0 它为什么必须这么大

**先把签名钉死** —— 这是 §0.1 的形式版：

```rust
questioner    : Judgment -> Derivation | Hole
counter_asker : Hole     -> Question
```

`questioner` 的输入是**一个判决**，不是源文件；`counter_asker` 的输入是**一个洞**，
不是一段代码。两个签名里都没有"用户"，也没有"作为被告的程序"。

> **这是整个 LSPE 与 Rust 的分水岭。**
> rustc 的借用检查签名是 `borrowck(Program) -> Accept | Reject`；
> LSPE 是 `questioner(Judgment) -> Derivation | Hole`。
> 前者的论域是代码，后者的论域是**编译器自己的判断**。

**三问全部对内**：

| 问 | 质问的对象 |
|---|---|
| Q1 来源问 | **我**这次放行的依据是什么 |
| Q2 反证问 | **我**这条检查本身有没有效力（关掉它会不会有探针变红） |
| Q3 对质问 | **我的另一个自我**（自举实现）同不同意 |

没有一问是"你（用户）为什么这么写"。**用户不会出现在质疑器里。**
他只出现在两处：**LSPC**（§7，编译前被告知）与**反问器**（§6，编译中填洞）；
两处都不是被审问。

先破一个误解：**"大"不是行数。** 本仓有 46 KB 的种子被要求逐字节可复现，
拿行数当规模是自欺。这里说的"大"，是**必须要有的结构一件都不能少**。

Rust 的借用检查不是一个 pass，是一整套机器：

| rustc 里的部件 | 它解决什么 | LSPE 的对应物 |
|---|---|---|
| MIR | 把源码变成可分析的控制流图 | **QIR**（§5.1） |
| liveness / loans / conflicts | 借用的局部事实 | **义务图**（§5.2） |
| region inference / NLL | 区域约束求解 | **证据搜索**（§5.3–5.5） |
| trait obligations / selection | 待证子目标与求解 | **安全义务求解**（§5.2/5.5） |
| borrowck diagnostics | 结构化解释与反例 | **Q 码问题 + 派生树**（§5.9/5.10） |
| incremental query cache | 增量 | **站点级缓存**（§5.13） |
| 一套实现 | 一致性 | **两套实现 + 逐字节对质**（§5.14） |

而 LSPE 有 **四种 Rust 不需要做的事**，每一件都逼出额外机器：

1. **第三种结果**：Rust 只有 过/不过；LSPE 有 `PROVED / UNDECIDED / REFUTED`。
   第三种结果要**携带理由**，否则它就是"静默放行"换了张脸。
2. **证明对象**：每一次 PROVED 要能吐出一棵**派生树**，而不是一个布尔。
3. **两套实现**：同一份 QIR 要在 Python 与自举两侧逐字节一致。
4. **零运行期 + 固定容量**：分析器自己不能靠堆、不能静默越界
   （`docs/251`：226 处容量、170 处沉默）。它必须**自己先说话**。

⇒ **质疑器的体量，下限就是 rustc borrowck 的体量；上限由那四件事决定。**

> 朴素版（只有 Q1 来源问）是**查表**。这一版是**证明搜索系统**。
> 两者的差别，就是"能发现证据失效"与"不能发现证据失效"的差别 ——
> 而后者正是 Rust #164250 的形状。

### 5.1 质询 IR（QIR）：质疑器自己的中间表示

质疑器不能直接站在 AST 上问。AST 没有"站点"，没有"义务"，没有"证据的依赖"。
它需要自己的 IR。

#### 节点

| 节点 | 字段 | 说明 |
|---|---|---|
| `Site` | `id`, `kind`, `unit`, `fn`, `span`, `ordinal` | **一个放行点**。id 是**内容寻址**的，不是行号 |
| `Claim` | `site`, `proposition`, `obligations[]` | **编译器自己的命题**：「我判定：这次访问在域内」 |
| `Obligation` | `kind`, `args`, `goal`, `accept_set` | 待证子目标 |
| `Evidence` | `kind`, `source`, `span`, `strength` | 一条放行理由 |
| `Assumption` | `id`, `text`, `owner`, `span` | 人标的假设（地板） |
| `Question` | `obligation`, `tried[]`, `options[]`, `default`, `state` | 反问器的输出 |
| `Derivation` | `claim`, `children[]`, `evidence` | 一棵证明树（DAG） |
| `Budget` | `level`, `steps_left`, `depth_left` | 预算（§5.12） |

#### 边

| 边 | 从 → 到 | 语义 |
|---|---|---|
| `requires` | `Claim` → `Obligation` | 证这条 claim 需要这些子目标 |
| `discharges` | `Evidence` → `Obligation` | 这条证据能销掉这个子目标 |
| `delegates` | `Obligation` → `Summary` | 交给被调函数的摘要 |
| `propagates` | `Obligation` → `Obligation` | 沿 CFG 传播（初始化、存活） |
| `assumes` | `Assumption` → `Obligation` | 人替它背书 |
| `contradicts` | `Evidence` → `Evidence` | 两条证据互斥（→ REFUTED） |

#### 站点 id 必须内容寻址

`docs/253` 已经付过一次学费：**行号会漂，码号不会**。
站点 id 同理。P0 用 `(unit 名, kind, 站点内容, 重复序数)` 作 id ——
站点内容是 `guard <cap>` 或 `<lhs>[<inner>]` 的 **token 文本**，
重复序数只区分**完全相同**的表达式；**不用行号，也不用全局序号**：

- 格式化（`loment fmt`）之后 id 不变；
- 在前面插一个**无关**站点，已有站点的 id 不变（全局序号会让它们全部重编号）；
- 反问器的 `lspe.answers` 不会因为插了一行注释或另一个访问而错位。

**这是一条会持续收利息的决定**：它让"同一个站点"在两次构建之间真的是同一个站点。

#### 站点普查（census）

质疑器开跑前，先做一次**普查**：

1. 从 IR **枚举**所有放行点（这是唯一真源）；
2. 每个安全组件**登记**它认识的站点；
3. 两个集合必须相等。

不等 ⇒ **E035**（幽灵站点 / 漏登）。这条是 §8 的 I1，也是"审计者不能漏人"的地基。

### 5.2 义务系统：十四种待证子目标

义务是质疑器的**约束变量**。每一条义务都点名一个**语义所有者** ——
LSPE **不发明语义**，只负责把已有的语义判决变成可证子目标。

| # | 义务 | 参数 | 由谁产生 | 语义所有者 | 什么能销掉它 |
|---|---|---|---|---|---|
| 1 | `InBounds` | `ptr, lo, hi, site` | 指针运算 / 下标 | `docs/146`、E028 | 常量折叠 / 类型 / guard / 局部流 |
| 2 | `Alive` | `block, site` | 解引用 | `docs/210`、E029 | 局部流 / 摘要 / GC 梯级 |
| 3 | `InDomain` | `cap, access, site` | 能力域访问 | `docs/146` | 类型（域）/ guard |
| 4 | `Exclusive` | `ptr, site` | 可变借用 | `docs/206`、E007 | 局部流 |
| 5 | `Initialized` | `local, site` | 读局部 | `docs/206`、E006 | 局部流 |
| 6 | `NotDangling` | `ref, site` | 返回/存引用 | `docs/206`、E012 | 局部流 / 摘要 |
| 7 | `NoRuntime` | `site` | 产物里的运行期构造 | `docs/182`、E031 | 语法 / 类型 |
| 8 | `FreeOwnership` | `block, free_site` | `free` | `docs/210` | 局部流 / 摘要 |
| 9 | `LadderLiability` | `site, level` | 每次 `alloc` | `docs/210` | GC 梯级判决 |
| 10 | `CapabilityLive` | `cap, site` | `revocable` 的访问 | `docs/146` | 类型 / 全局不变量 |
| 11 | **`TypeWellFormed`** | `type, subst, site` | **每次替换** | `docs/158`、`docs/147` | **替换后重证**（§5.7） |
| 12 | **`DropHonest`** | `destructor, site` | 每个析构器 | `docs/253` §1.2 | **只能 `Assumed`**（§5.8） |
| 13 | `GuardHolds` | `pred, site` | `guard` 内访问 | `docs/146` | 语法 / 局部流 / 不变量 |
| 14 | `SummaryContract` | `callee, pre, post` | 跨函数调用 | `docs/210` §7 | 过程间摘要 |

**两条设计纪律**：

- **义务不合并。** `InBounds` 与 `Alive` 是两条，哪怕它们经常一起被证。
  合并会让"只证了一半"变成一个说不清的格子。
- **每条义务有 `accept_set`。** 哪种证据能销掉它，写在义务种类上，不写在引擎里。
  这样"引擎"可以增删，而语义不变。

### 5.3 证据系统：不是全序，是接收关系

朴素版想写一条"证据强度从弱到强"的链。**那是个陷阱** ——
语法证明和类型证明不是同一条轴上的东西，硬排全序就是"对称不是证据"的翻版
（`docs/253` §5.1.2 的教训）。

正确的形状是**两种东西**：

1. **证据种类**（有限集合）；
2. **每条义务的接收关系** `accept : ObligationKind → P(EvidenceKind)`。

| 证据 | 来源 | 能否单独销掉义务 |
|---|---|---|
| `Axiom` | 语言规范（`standard/LLS.md`） | 是（少数） |
| `Syntactic` | 字面量 / 常量折叠 | 是 |
| `Typed` | 类型 / 能力域 | 是 |
| `LocalFlow` | 函数内数据流 | 是 |
| `Interproc` | 被调函数摘要 | 是 |
| `GlobalInvariant` | 循环不变式 / guard 谓词 / 归纳 | 是 |
| `Assumed(id)` | **人标的假设** | 是（但记 `floor`） |
| `Differential` | 两套实现一致 | **永不** —— 它只是闸门（§5.4） |

**求解用的格**：每个义务的证据是上述种类的**子集**，按**包含关系**构成有限格
（8 种 ⇒ 每个义务至多 2⁸ 个状态）。传播函数只做并集 ⇒ 单调 ⇒ 定点有限步收敛。

> **为什么不用"强度"全序**：那会逼着回答"类型证明和语法证明谁更强"，
> 而这个问题没有语义答案。**接收关系是语义的；强度不是。**

### 5.4 八个引擎

每个引擎是一个 `solve(obligation, ctx) -> P(Evidence)`。引擎只**产证据**，不投票。

| 引擎 | 证什么 | 成本 | 默认级别 | 确定性要求 |
|---|---|---|---|---|
| **E1 常量** | 字面量下标、常量偏移、常量界 | 极低 | L0 | 纯语法 |
| **E2 类型/能力** | 域内、名义类型、`excluded`、`revocable` | 低 | L0 | 类型检查器之后 |
| **E3 局部流** | 初始化、存活、独占、悬垂 | 中 | L1 | CFG 顺序固定 |
| **E4 过程间** | 摘要：deref-only、guard 透传、free 所有权 | 中高 | L2 | 摘要按固定序 |
| **E5 全局不变量** | 循环不变式、guard 谓词、归纳 | 高 | L3 | 不依赖墙钟 |
| **E6 替换/WF** | 替换后的良构性重证 | 中 | **L1（强制）** | 替换日志全序 |
| **E7 差分对质** | 两套实现的判决+来源一致 | 高 | L3 | 逐字节 |
| **E8 反证探针** | 关掉检查有没有探针变红 | 低（离线） | L0 | 探针注册表机械生成 |

**三条硬规则**：

1. **E7 永不单独产生 `PROVED`。** 它只产生 `Differential` 证据，而
   `Differential ∉ accept(k)` 对任何 k 成立。理由见 §5.5。
2. **E8 的探针注册表从测试文件机械生成**，不手抄
   （手抄的清单第一次改代码就漂 —— `feedback_diff_measurement_beats_scans` 的同一条）。
3. **引擎之间不互相否决。** 例外只有一个：E8 找到反例 ⇒ 直接 `REFUTED`，
   因为反例是**构造性**的，构造性证据优先于一切非构造性证据。

### 5.5 求解器：工作列表 + 定点

```
worklist = 所有 Site 的所有 Claim
while worklist 非空:
    o = pop()
    if o 已有答案且证据集未变: continue
    for engine in 固定顺序:
        E(o) = engine.solve(o)            # 可能为空
    E(o) |= propagate_from_successors(o)  # CFG / 调用边
    if E(o) 变化: 把 predecessors 重新入队
```

**终止性**：证据集只增不减（并集），每种义务的状态空间有限（≤ 2⁸），
所以每个义务至多被"有意义地"更新有限次。递归调用图需要摘要定点：
用**深度上限 + 摘要未知**收口，超限记 `UNDECIDED(depth)`，**不静默**。

**确定性**（本仓的硬纪律，`docs/253` §11.1 第 2 处）：

- 引擎顺序**手写固定**，不靠 dict/set 迭代序；
- 同分证据按 **site id** 字典序取，不按时间；
- 工作列表是**有序队列**，不是哈希集合；
- 同一棵树跑两遍，QIR 序列化逐字节相同（判据 §12·6）。

**复杂度**：`O((S + E_edges) × K × I)`，其中 `S` 站点、`E_edges` 义务边、
`K ≤ 8` 证据种类、`I ≤ 2^K` 迭代上限。实际值由 §5.12 的**步数预算**截断。

> ⚠ **预算按步数，不按墙钟。** 同一个量在墙钟上有 3.2×/4.13×/5.4× 的散布，
> 把门禁钉在比值上就是钉在机器噪声里（`feedback_no_wallclock_ratio_criteria`）。
> 步数是确定性的，能进判据。

### 5.6 上下文敏感度五级

| 级 | 看多大范围 | 典型能证的 | 成本 | 默认 |
|---|---|---|---|---|
| **L0** | 站点本身 + 常量 | 字面量界、类型域 | 极低 | —— |
| **L1** | 函数内 CFG | 初始化、存活、独占、本地 WF | 低 | —— |
| **L2** | 调用边 + 摘要 | 跨函数 deref-only、free 所有权 | 中 | —— |
| **L3** | 整个单元定点 | 循环不变量、跨块流 | 高 | ✅ |
| **L4** | 跨单元（库摘要） | 库函数的契约 | 很高 | 显式开 |

**上下文级别不是 `choose` 维，是构建旋钮**（`--lspe-level=N`）。理由：

- 它**不改变判决语义**，只改变"多少站点能证出来"；
- 把它做成语言维会多一条登记链（`docs/253` 十三处），而它不配拥有那十三处；
- 但它**必须进台账**：`lspe.level` 写进产物，否则"用低级别换绿灯"就是新的无标签地板。

级别降低 ⇒ `UNDECIDED` 变多 ⇒ `floors` 变多。**这个数会说话。**

### 5.7 替换与 WF 重证：直接回答 Rust #164250

这是质疑器**不能省**的那一段，也是它区别于"查表 pass"的地方。

**规则**：

1. 任何带类型变量的义务，其证据的键是 **`(obligation, substitution)`**，
   不是 `obligation`。
2. 每一次 `unify` / `instantiate` / 泛型单态化，都写一条**替换日志**。
3. 替换发生后，**所有受影响站点**的 `TypeWellFormed` 义务**重新入队**。
4. 替换前已证、替换后未重证的站点，状态是 **`UNDECIDED(stale_wf)`**，不是 `PROVED`。
5. `stale_wf` **不能**被 `Differential` 销掉 —— 两套实现可以一起没重证。

**为什么这条能挡住 Rust 那次缺陷**：Rust 的 bug 正是"统一化后没重查 bound"。
在 LSPE 里，那条 bound 是一条 `WF` 义务，它的证据键含 substitution；
替换发生 ⇒ 旧证据**自动失效**（键不匹配）⇒ 重新入队。
**不是靠谁记得去查，是靠键的形状让它不可能被忘掉。**

> 这是整个设计里最像 Rust borrowck 的一处：**把"容易忘"变成"表示上不可能"。**

### 5.8 地板义务：`DropHonest`

`docs/253` §1.2 说 Rust 的地板是"每一个 `Drop` impl 都诚实"，且**没被标注**。
LSPE 把这句话变成一条**一等义务**：

- 每个析构器产生 `DropHonest(destructor)`；
- 它**不能**被静态证明（析构体是任意代码）；
- 默认证据 = `Assumed(#floor-drop-<id>)`；
- 台账里 `floors.drop_honest = 析构器个数`；
- 开发者可以给一条手写证明/注解来销掉它，否则它**永远是标注状态**。

**这就是"温柔但更安全"的落点**：
Rust 假设了同一件事，但不说；LSPE 假设同一件事，**每一条都记在产物里**。
两者在这一点上的"安全性"差别不是定理多少，是**地板有没有标签**。

### 5.9 派生树与产物

每个 `PROVED` 携带一棵派生树（DAG，摘要共享）：

```
Claim(S47: a[i] in d)
 ├─ Obligation(InBounds(a, 0, 64, S47))
 │    └─ Evidence(Typed, capability d : buf[0..64], line 7)
 ├─ Obligation(Alive(block_12, S47))
 │    └─ Evidence(LocalFlow, free at S52 unreachable from S47)
 └─ Obligation(InDomain(d, a[i], S47))
      └─ Evidence(GuardHolds(i < 64), guard d(i), line 12)
```

**产物里存什么**：

- Potato `lspe` 里存 **`proof_hash`**（每站点一个）与计数；
- 完整派生树进旁挂文件 `<unit>.lspe`（可选，供离线复核）；
- `loment lspe why S47` 重建并打印上面的链；
- `loment lspe verify <artifact> <sidecar>` 逐站点核对哈希。

**为什么不把整棵树塞进 Potato**：产物大小会炸（每个站点一棵树）。
哈希进产物、树进旁挂，是"可复核"与"可发布"的折中；折中本身写在这里，不藏。

### 5.10 诊断体系：错误与问题分开

**两个命名空间**，因为它们是两种东西：

| 命名空间 | 含义 | 默认是否阻断 |
|---|---|---|
| **E034–E037** | **账错了** | E034 默认否（`--lspe-mode=strict` 是）；E035–E037 是（内部/管理错误） |
| **Q001–Q012** | **问题**（反问器的输出） | **永不**（`--lspe-mode=strict` 把未答升级成 E034） |

问题码（初版 12 种，按义务族 + 失败模式分）：

| 码 | 问什么 |
|---|---|
| `Q001` | 找不到来源 |
| `Q002` | 检查是惰性的（关掉也不红） |
| `Q003` | 两套实现分歧 |
| `Q004` | 替换后 WF 未重证（`stale_wf`） |
| `Q005` | 步数预算耗尽 |
| `Q006` | 过程间深度到顶 |
| `Q007` | 析构诚实性无法证明 |
| `Q008` | 域未知（能力域覆盖不到） |
| `Q009` | 别名不确定 |
| `Q010` | `free` 所有权歧义 |
| `Q011` | 运行期泄漏 |
| `Q012` | 假设已过期（源码变了） |

**每条 Q 的固定模板**（结构化的，不是散文）：

```
claim       这次放行说的是什么
chain       义务链（哪一条没销掉）
tried       哪些引擎试过，各自返回了什么
options     选项 + 后果 + 成本
default     默认选项
reversible  能不能撤销 / 撤销后回到什么状态
```

`loment build --json` 里以 `suggestions[]` 的形状输出（沿用 `docs/191`）。

### 5.11 覆盖率与普查：把"大"变成可数的数

质疑器每个单元都吐一张**覆盖表**：

| 计数 | 含义 |
|---|---|
| `sites` | 普查到的放行点总数 |
| `obligations` | 生成的义务总数 |
| `proved` | 被至少一条证据销掉 |
| `undecided` | 未销掉（按 Q 码分桶） |
| `assumed` | 靠 `Assumed` 销掉 |
| `floors` | `assumed` + `stale_wf` + `budget`（**所有替人背书或被截断的格子**） |
| `per_kind` | 每种义务的 proved/total |

**三条用法**：

1. **棘轮**：覆盖率只许升不许降（与 `gate-floors.txt` 同一条纪律）。
2. **回归信号**：某次改动让 `undecided` 从 30 跳到 300，就是一次可读的退化。
3. **诚实**：`floors` 是**公开的数**。它不藏在"编译通过"后面。

### 5.12 预算耗尽与降级

一个这么大的分析器**一定会**撞预算。撞了怎么办，是设计的一部分：

| 情况 | 结果 | 记什么 |
|---|---|---|
| 步数超限 | `UNDECIDED(budget)` / `Q005` | `floors++` |
| 过程间深度超限 | `UNDECIDED(depth)` / `Q006` | `floors++` |
| 上下文级别太低 | 对应的 `UNDECIDED` | `lspe.level` 进台账 |
| 引擎内部容量越界 | **走 `E033` 那一族**（单元太大 / 表容量），响亮的错误 | 绝不允许像 `docs/251` 那 170 处一样**沉默写穿** |

**新增的容量必须自己报数**：
`docs/251` 量到编译器有 226 处固定容量、170 处越界时沉默。
质疑器会新增一批容量（QIR 节点池、义务表、证据集、派生树节点、替换日志）。
**每一个都要有一条会说话的失败路径**，并且进 `loment_caps_test` 的名单。
否则"LSPE 让编译器更安全"这句话会被一次静默段错误当场证伪。

### 5.13 增量与确定性

- **缓存键**：`(site_id, obligation_kind, unit_hash, dims, lspe_level)`；
- **命中要求**：重建出的 `proof_hash` **必须相同**；不同 ⇒ 缓存是错的，判据红；
- **跨级别不复用**：L2 的 `UNDECIDED(depth)` 不能被 L3 复用；
- **冷/热构建同一产物**：`lspe` 字段逐字节相同；
- **缓存目录不在任何 `GLOB` 目录里**（`feedback_temp_files_must_leave_glob_dirs`）。

### 5.14 双实现与容量：这是最贵的一段

质疑器必须在 **`tools/lomentc.py`** 与 **`loment/selfhost/*.lomt`** 两侧各有一份，
且 QIR 序列化逐字节一致。

**三条已经量过的代价**（不是猜的）：

1. **自举侧每加一个函数 ≈ +4.7s 启动时间**，60s 护栏只剩 ~1%
   （`project_selfhost_change_costs`）。
2. **自举侧有固定容量，越界是段错误不是报错**（`reference_selfhost_fixed_caps_segfault`）。
   质疑器是编译器里最大的新增，**先量 `SLOT` 再写**。
3. **种子过 ~3.88 MB 会发出坏 stage1**（`project_genesis_seed_size_cliff`，2026-10-17 复测已过）。
   质疑器会把 `codegen.lomt` 撑大；如果逼近那道墙，**先把质疑器拆成独立 `.lomt`**，
   而不是硬塞。

**落地纪律**（与 `docs/158` §5 一致）：

- 手写一条提交、生成物一条提交；
- 种子永远 `python tools/loment_seed.py --emit`，不手合；
- 孪生判据只证一致不证对 ⇒ 另配**故意的分歧探针**（同源，两边都必须给同样的 Q 码）。

### 5.15 "和 Rust 一样大"的可证伪定义

不拿行数说事。拿**十个数**：

| # | 维度 | 下限 | 为什么是这个下限 |
|---|---|---|---|
| 1 | QIR 节点种类 | ≥ 8 | 少于这个数就退化成 AST |
| 2 | 义务种类 | **≥ 14** | §5.2 已经列了 14 条；少一条就少一类缺陷 |
| 3 | 证据种类 | ≥ 8 | §5.3 |
| 4 | 引擎 | **≥ 8** | §5.4 |
| 5 | 上下文级别 | **= 5** | §5.6 |
| 6 | 问题码 | ≥ 12 | §5.10 |
| 7 | 派生树节点/站点 | 每个 PROVED 至少 1 条证据 | 0 条 = 无来源 |
| 8 | 覆盖率棘轮 | 语料上只升不降 | §5.11 |
| 9 | 双实现 | 两侧都存在且 QIR 逐字节一致 | §5.14 |
| 10 | 容量 | 每个新容量都有会说话的失败路径 | §5.12 |

**再加一条反向判据**：

> 如果把这十个数里的任意一个降到"朴素版"（比如义务只剩 1 种、引擎只剩 1 个），
> 那么 **Rust #164250 那一类缺陷必须重新变得不可见**。
>
> 能通过这条反向判据，说明规模是**挣来的**，不是堆出来的。

## 6. 反问器：把质疑器自己的洞转交出去

**反问器不是质疑器在跟用户说话。** 它是质疑器在说：

> 「我这里有一个洞。我已经把它**命名、定界、试过三种自证**，还是填不上。
> 这是它，这是选项，这是默认。」

开发者不是被告，是**来填一个编译器已经画好的空**。

| 不是 | 是 |
|---|---|
| "你的代码不安全" | "**我的**证明在 S47 有洞" |
| 审问用户 | **转交**一个已命名的洞 |
| 要用户证明自己的代码 | 让用户从编译器给的选项里选一个 |
| 可以随时发问 | **三问都跑过且失败**才允许发问（否则 E036） |

**只在 UNDECIDED 时启用。** 不碰 REFUTED（那是普通错误），不碰 PROVED。

它发出的**不是错误**，是一个 Question（Q 码）：

```rust
question Q004 at site S47 {
    claim: "type Vec<T>::get is well-formed under T = &'a local",
    chain: [
        TypeWellFormed(Vec<&'a local>, subst σ12, S47)  -- undischarged
    ],
    tried: [
        E2: "bound `T: 'static` did not survive σ12",
        E6: "stale_wf: discharged before σ12, not after",
        E7: "selfhost agrees (both stale)"
    ],
    options: [
        A: "add `T: 'static` at line 9"
             -> "E6 re-discharges; cost: one bound",
        B: "assume the bound holds for this substitution"
             -> "labeled floor; artifact records assumption #A7",
        C: "let LSPE refuse"
             -> "E034 under strict; build stops"
    ],
    default: B,
    reversible: true
}
```

**五条硬规则**：

1. **不阻断构建**（`--lspe-mode=strict` 除外）。
2. **默认不是"允许"，是"允许但标注"**。标注本身就是产物。
3. **同站点、同原因只问一次**。重复提问是骚扰，不是温柔。
4. **不威胁**。问题文本里不出现 `unsafe` / `undefined behavior` / `memory corruption`；
   它说的是"我证不出来"与"选这个的后果"。
5. **转交前必须先自审。** `tried[]` 必须覆盖 Q1 来源 / Q2 反证 / Q3 对质；
   缺任何一问 ⇒ **E036**。这是"审自己"与"审用户"之间那条不可越过的线。

**回答出口**：

| 方式 | 用法 |
|---|---|
| `--answer S47=B` | 单次构建 |
| `lspe.answers` 旁挂文件 | 团队共享、可评审、进版本库 |
| `loment build --ask` | 本地交互；**CI 不用** |

三种回答 —— `answer` / `defer(reason)` / `refuse` —— **都进台账**。
`defer` 不消失：下一轮还问（同因只问一次），产物写 `deferred`。

**`lspe_close_admin` 是什么？** 它不是"不检查"，是**跳过审问与台账**。
检查照旧跑，判决照旧下 —— 只是没人记录"凭什么"。
所以 `lspe_close_admin` **本身必须写进产物**：你选择了一块没有标签的地板。

## 7. LSPC：警察，编译前贴条

### 7.0 它为什么存在

**LSPC 是这套系统里对外执勤的警察。** 如果把 LSPE 比作整个警局，
LSPC 就是街面上那个警察。警察不是上帝（§1.3）：
它不审判，只**贴条、开单、告诉你后果**。

因果链只有四步：

1. **质疑器**对内，审自己的判决；
2. 它证不动时，产生一个 `Hole`，交给**反问器**；
3. 反问器把 `Hole` **转交给开发者** —— 于是结论的一部分**交给了人**；
4. 人会答错、会 `defer`、会不修 ⇒ **Loment 从此不再是"绝对安全"的**。

这不是缺陷，是诚实：**任何最后要问人的系统，都不能声称绝对无漏洞。**

能补的不是"更严的检查"，而是把一个**过程性质**做到绝对 —— **告知**。

> **绝对安全（LSPC 义）= 不存在"你还不知道就承担了"的风险。**

不是"没有缺陷"，是"**没有未被披露的残余风险**"。

形式化：

```
∀ risk r : disclosed(r) ∨ (disclosure_explicitly_disabled(r) ∧ recorded(r))
```

这条**可判定、可枚举、可离线核对**。它是编译器在不解决不可判定问题的前提下，
唯一能给得起的"绝对"。

### 7.1 它在流水线的哪一格

```
源码
 │
 ├─ 解析 / 名字解析 / 类型检查
 │
 ├─ LSPC：预检单（告知，不阻断）
 │
 ▼
质疑器（对内）→ 反问器（转交）→ 台账 → 代码生成
```

- **在代码生成之前**：风险要在你花掉整次编译之前知道；
- **在类型检查之后**：要读能力域与类型，才说得具体；
- **不依赖质疑器的派生树**：所以它便宜、可单独跑 —— `loment lspc check`。

⚠ **"编译前"在这里的确切含义**：指**代码生成之前**，不是一个字都不编译。
名字解析与类型检查必须先跑，否则 LSPC 只能给出泛泛的警告。
若要在"完全不产出"的前提下跑，`loment lspc check` 只跑前端然后停下 ——
这就是"编译前"的操作形态。

### 7.2 预检单：一行一族，五列

| 风险族 | 你现在靠什么 | 如果它不成立 | 修法 | 不修的后果 |
|---|---|---|---|---|
| 非字面量下标 / 裸指针偏移 | `guard` 的运行期 trap | 越界写穿 | 加 `guard` 或改常量界 | trap 或踩内存（看档） |
| `free` 无所有权路径 | L1 定活插的 `free` | 双重释放 / 悬垂 | 显式 `free` 或换 `gc_auto` | 原生下 UB |
| `Drop` 析构器 | **假设它诚实**（`DropHonest`） | 二次释放（#164243 同形） | 审计析构体 / 手写证明 | 归你 |
| `revocable` 能力 | 撤销后不再访问 | 使用已撤销能力 | 去掉 `revocable` 或加检查 | 归你 |
| `extern fn` / `--link` 边界 | C 侧遵守约定 | ABI / 生命周期错配 | 收窄边界 / 加封装 | 归你 |
| `no_runtime` 里的运行期构造 | E031 拒 | 产物拖进运行期 | 去掉该构造 | 编译期就拒 |
| `gc_manual` 的 `alloc` | 你负责归还 | 耗尽 / 泄漏 | 加 `free` / 换档 | 归你 |
| 非字面量 `guard` | 运行期 trap | trap 或性能损失 | 改常量界 | 运行期 trap |
| 上一轮遗留的 `defer` | 台账里的 `deferred` | 未决问题被遗忘 | 回答或删除 | 归你 |
| 过期假设（源码已变） | `lspe.answers` 里的假设 | 假设不再成立 | 重答 | 归你 |
| 跨单元库契约（L4 未开） | 库摘要未验证 | 跨库假设错 | 开 L4 / 读库源 | 归你 |
| `lspe_close_admin` / `lspc_off` 本身 | 你选择了不审计 | 上面全部看不见 | 打开 | 归你（但这块地板有标签） |

最后一行是递归的：**把告知关掉这件事本身，也必须被告知。**

### 7.3 "你爱修不修"的四条规则

1. **不阻断**（默认）。退出码 0，除非 `--lspc=strict`。
2. **不改代码**。LSPC 没有 autofix。
3. **不唠叨**。同站点同族只说一次；`quiet` 只给总数。
4. **不消失**。不修 = 默认 `ack`；产物写 `lspc.acked`；关掉 = 写 `lspc: off`。

**"后果自付"不是威胁，是归责记录**：产物里写明这条风险何时被披露、
你选了修还是不修。**归责不等于免责** —— 它只是把"谁知道的"写清楚。

### 7.4 绝对在哪一层（本文的哲学核心）

| 能绝对 | 不能绝对 |
|---|---|
| **披露完整**：每一族都有一行 | 程序无缺陷 |
| **默认不隐藏**（除非显式关掉并记录） | 用户会改 |
| **归责可追**：ack 有站点、有原因、有构建 id | 未来的代码仍安全 |
| **预检单可离线复核** | 人答对 |

**关键的一句**：LSPC 的保证是**过程性质**，不是**程序性质**。
过程性质可判定、可枚举、可核对；程序性质不可判定（§2·A）。
**把"绝对"放在过程上，是唯一不撒谎的放法。**

> 与 `docs/253` §1.2 同构：**地板不是丑闻，没被标注的地板才是。**
> LSPC 就是那块"在你编译之前就标出来"的地板。

### 7.5 与反问器的分工

| | 反问器 | LSPC |
|---|---|---|
| 时机 | 编译中 | **编译前** |
| 对象 | 一个具体的 `Hole` | **整份代码的风险族** |
| 输出 | 问题（选项 + 默认） | **预检单**（告知 + 归责） |
| 不答 / 不修 | 默认标注（`deferred`） | 默认 `ack`（后果自付） |
| 记录 | `lspe` | `lspc` |
| 形状 | **点** | **面** |

反问器说"我证不出这一处"；LSPC 说"你整份代码里有哪些地方将来要你背书"。

### 7.6 开关：构建旋钮，不是第八维

`--lspc=full|quiet|strict|off`，默认跟随 `lspe`：

| `lspe` 状态 / 模式 | `lspc` 默认 |
|---|---|
| `lspe_open_admin` + `--lspe-mode=full` | `full` |
| `lspe_open_admin` + `--lspe-mode=quiet` | `quiet` |
| `lspe_open_admin` + `--lspe-mode=strict` | `full`（预检是告知，不升级成错误） |
| `lspe_close_admin` | `off`（并记录） |

- **构建旋钮**，理由与 `--lspe-level` 相同：不改变判决语义；
- 但 `lspc: off` **必须进产物**；
- `--lspc=strict` 是唯一会阻断的形态，且只对"未 `ack` 的高风险族"。

**不做成 `choose` 第八维**：那会再复制一遍十三处登记，而它不配 ——
**它不改变任何语义。**

### 7.7 LSPC 也读上一轮的账

- 上一轮 `deferred` → 本轮的预检项；
- 上一轮 `assumed` 的假设，若源码变了 → "过期"；
- 上一轮 `lspe_close_admin` → 本轮的"你上次没有审计"。

⇒ LSPC 是**跨构建记忆**的载体：它让"上次我跳过了"这件事不会在下次静默消失。

### 7.8 命名

LSPC 的 C 本文读作 **Checker**（编译前检查器）。它也能读作 **Certificate** ——
两种读法指向同一件东西：**一张在编译前发出的、可复核的告知单**。

## 8. 台账：LSPE 的第四件

**台账（`lspe`）不只是计数，它就是安全状态本身。**
它是**编译期对象**，进 Potato **v16** 的 `lspe` 字段：

```json
{
  "lspe": {
    "state": "lspe_open_admin",
    "set_by": "default",
    "mode": "full",
    "level": 3,
    "sites": 1234,
    "obligations": 5210,
    "proved": 1200,
    "undecided": 30,
    "deferred": 4,
    "refused": 0,
    "floors": 4,
    "floor_detail": { "assumed": 2, "stale_wf": 1, "budget": 1, "drop_honest": 12 },
    "per_kind": { "InBounds": "400/410", "Alive": "390/400", "...": "..." },
    "interrogations": { "provenance": 1234, "falsification": 1180, "cross_exam": 1234 },
    "invariants": { "i1": "ok", "i2": "ok", "i3": "ok", "i4": "ok", "i5": "ok" }
  }
}
```

**五条不变量**（LSPE 对**安全系统自己**下的判据）：

| # | 不变量 | 违反时 |
|---|---|---|
| **I1** | **站点对账**：普查集合 == 各组件登记集合（无幽灵、无漏登） | E035 |
| **I2** | **来源覆盖**：每条 allow 要么有 Q1 来源，要么有 `assumption(id)` 标注 | **E034** |
| **I3** | **维度不矛盾**：`no_runtime` 产物零运行期站点；`gc_manual` 无未记账 `free`；`sealed` 无 hosted 调用 | E035 |
| **I4** | **地板可数**：`floors == assumed + stale_wf + budget + drop_honest`；不存在"既没回答、也没默认"的 UNDECIDED | E036 |
| **I5** | **孪生同源**：同一站点，两个实现的判决 + 来源逐字节相同 | E035 |

**三个现行错误码 + 一个保留码**（现行最高 `E033`，见 `tools/loment_diag.py`）：

⚠ **`E034` 由 LSPE 占用**。`#662` 是**另一件事**：`lomenterr` 会**伪造**出不存在的码。
占住 `E034` 不会修好它 —— 它可能接着伪造 `E038`。
所以 #662 的判据必须是「**不伪造任何码**」，而不是「避开某个号」。

| 码 | 含义 | 性质 |
|---|---|---|
| **E034** | **无来源放行** | 合同性错误；`lspe_close_admin` 下不产生；`--lspe-mode=strict` 下才阻断 |
| **E035** | **台账矛盾**（幽灵站点 / 维度互斥 / 孪生分歧 / 容量越界） | 内部一致性错误 |
| **E036** | **反问未记账** | **自检失败** —— 见 §8.1 |
| **E037** | **策略锁死**（**保留**）：源码取反被策略 `locked` 的 LSPE | 策略层今天不存在，**不会发出**；为未来留号 |

### 8.1 LSPE 审问 LSPE

**台账自己也要有台账。** 这一节是自审的递归闭包：

1. **E036 是自检码。** 它**不应该在生产中产生**。如果产生了，说明台账自己漏了一条。
   配一条**故意的坏台账夹具**：喂进去必须红 —— 证明自检器抓得住自己
   （`#369` 不静默死亡的同形判据）。
2. **台账必须可复现。** 两个实现各自生成 `lspe`，逐字节相同（I5）；种子重算后仍相同。
3. **来源集合由语言规范定义，不由任一实现定义**（`standard/LLS.md`）。
   这是唯一不靠孪生的那一腿 —— 因为 Q3 只证一致。
4. **`lspe_close_admin` 也要被记录。** 审计者被关掉这件事本身，是一条台账记录。

**一句话**：LSPE 的完整性判据不是"它找到了多少问题"，而是
**"它能不能证明自己漏了一条"**。

## 9. 与 Rust 的对比：温柔与安全各是什么

### 9.1 温柔（可证伪）

> **同一份程序，`lspe_open_admin` 不会把 `lspe_close_admin` 下能过的东西变成硬错误。**

判据：全量语料两档各编一次，**判决集合相同**（除 `--lspe-mode=strict`）。
找到一处不同 ⇒ 温柔这条声称破了。

`lspe_open_admin` 会让**产物内容**不同（多了台账），但**判决**不变。
"温柔"约束的是判决，不是字节。

### 9.2 至少 Rust 安全（可证伪）

把"安全"定义成一句可检查的话：

> **没有一条放行是无声的。**

- 对 Rust 静态能证的子集：LSPE 也必须给出**来源**（能力域 / 类型 / LMS / guard）。
- 对 Rust 证不了的：LSPE **不假装证了** —— 它给 `UNDECIDED` 与标注。
- **Rust 的失败模式**（#164250：替换后的义务没重证，十一年无人可见）
  在 LSPE 下的对应物是 `Q004 stale_wf` —— **一条带站点 id、可离线读的记录**。

判据：任何一条 allow，若 `source` 为空且无 `assumption`，就是 **E034**。

**第四条（LSPC 补的）：编译前的告知。**
Rust 的地板是**没被标注**；LSPC 在编译前把每一族残余风险标出来。
判据：预检单必须覆盖 §7.2 的**全部风险族**；缺一族 ⇒ 红。
这一条与上面三条不同 —— 它保证的不是"放行有来源"，是"**风险没有静默**"。

### 9.3 更强（Rust 没有的三件）

| 性质 | Rust | LSPE |
|---|---|---|
| 判决**在产物里**，离线可复核 | 否 | 是（`lspe` + 旁挂派生树） |
| 编译器**必须报告**"我证不出" | 否 | 是（Q001–Q012） |
| **替换会让旧证据失效** | 否（#164250 就是这么漏的） | 是（证据键含 substitution，§5.7） |
| **编译前告诉你哪里要你背书** | 否 | 是（LSPC 预检单，§7） |

### 9.4 不声称的东西

**LSPE 不声称比 Rust 证得更多。** 它声称的是**可追责性**，不是完备性。
把这两件事混为一谈，就是 `docs/253` §5.1.2 那次"对称不是证据"的过度声称。

**LSPC 也不声称降低缺陷数量。** 它降低的是**未被告知的残余风险** ——
这两件事在账上是两个数（§8 的 `floors` 与 §7 的 `lspc.acked`）。

## 10. 开关 `lspe`：`_admin` 关闸 + 构建旋钮

### 10.1 `_admin` 后缀是一条仓级规则，不是 LSPE 的发明

> **任何关闭关键安全系统 / 关键系统的 `choose` 取值，必须带 `_admin`。**

理由有三条：

1. **关闭是一次管理动作，不是普通配置。** 名字必须让人在读源码时就知道
   "这是管理员级决定"，而不是一个手滑的开关。
2. **它与"店员"那条同构（§1.3）**：开门不需要签字，**关门需要经理签字**。
3. **它让规则可判定。** `CORE_DIMS` 里凡是关闭关键系统的取值，缺 `_admin` 就是红 ——
   不需要人去记哪一维算"关键"。

| 系统 | 现行值 → 新值 | 状态 |
|---|---|---|
| `lms` | `lms_close` / `lms_open` → **四个档名，非满档带 `_admin`** | ✅ **2026-10-18 结掉**（不是改名，见下） |
| `lspe` | 新维：**`lspe_close_admin`** / **`lspe_open_admin`** | 本设计 |

**现行六维里只有 `lms` 有真正的"关闭"语义。**
`gc` / `runtime` / `port` / `vm` / `mode` 是**模式选择**，不是关闸 ——
不要机械改名，否则 `_admin` 会退化成装饰。

⚠ **`lms` 那一行最后不是"改名"**（`docs/253` §11.3 / `docs/265` §3.5）：用户 2026-10-15
裁定默认 = 满档，于是**"关"这个取值不存在了** —— `lms_close` / `lms_open` 被四个**档名**
取代，非满档（= 降级）一律带 `_admin`，满档不带。规则因此第一次变成**机械检查**：
`tools/lomentc.py` 的 `LMS_TIERS` 在导入期逐行核，`loment_lms_test` 也钉着。

⚠ **Potato 里的取值跟着变了**（v17 起 `lms` 是档名，另加 `lms_levels` 七个布尔）；
那是**单独一次提交**（`docs/158` 的纪律），没有混进别的改动。

### 10.2 核心维是二值的：开 / 关

`lspe` 只有两个取值：

| 值 | 含义 | 默认 |
|---|---|---|
| **`lspe_open_admin`** | 启用审计（质疑器 + 反问器 + LSPC + 台账） | ✅ |
| **`lspe_close_admin`** | **关审计**：跳过审问与台账；**检查一条不少** | 否 |

⚠ **`lspe_close_admin` 关的是警察，不是法律。**
`lms` / `gc` / `runtime` / 能力域的检查照旧跑；关掉的只是"凭什么放行"的记录。
这一点必须写死，否则名字会被读成"关闭安全系统"。

### 10.3 行为模式降为构建旋钮

`full` / `quiet` / `strict` 不再是语言取值，而是构建旋钮：

| 旋钮 | 取值 | 默认 | 记录 |
|---|---|---|---|
| `--lspe-mode` | `full` / `quiet` / `strict` | `full` | `lspe.mode` |
| `--lspe-level` | `0..4` | `3` | `lspe.level` |
| `--lspc` | `full` / `quiet` / `strict` / `off` | 跟随 `lspe` 状态 | `lspc` |

理由：**它们不改变"审计是否存在"，只改变审计的强度。**
语言层只需要回答一个问题：**开不开**。其余是构建选择，进台账即可。

### 10.4 优先级与 `set_by`（策略层是**未来面**）

> ⚠ **策略层今天不存在。** 这一节写的是**未来可能发生的系统**；
> 现行编译器只有两层：**默认**与**源码**。

| 层 | 今天 | 未来（若策略层落地） |
|---|---|---|
| 默认 | ✅ `lspe_open_admin` | ✅ |
| 策略 | ❌ **不存在** | 关闭或打开；可 `locked` |
| 源码 | ✅ `lspe_open_admin` / `lspe_close_admin` | ✅ |

**今天的行为**：

- 什么都不写 ⇒ `open_admin`，`set_by = "default"`；
- 写 `lspe_close_admin` ⇒ 关审计，`set_by = "source"`；
- 写 `lspe_open_admin` ⇒ 开（默认），`set_by = "source"`。

**未来若策略层落地**：

- `lspe_open_admin` 永远能覆盖"策略导致的关闭"；
- 策略 `locked = true` 时，任何与策略相反的源码取值报 **E037（策略锁死）**；
- `set_by` 多一个 `"policy"` 值。

**E037 今天只保留，不会发出。** 它存在是为了让未来那一层不用再抢码号。

### 10.5 为什么不与任何 choose 冲突

1. **LSPE 读其它维，不写其它维。** 它不改六维的任何判决。
2. **`CORE_CONFLICTS` 不加。** 与 `lms` 那次同一条逻辑（`docs/253` §11.2）：
   没有一对取值互斥 —— `lspe_open_admin` / `lspe_close_admin`
   在六维的**每种组合**下都合法。
3. **唯一改判决的 `--lspe-mode=strict` 是构建旋钮**，由同一状态门控
   （`lspe_close_admin` 下不生效）；它不进 `CORE_DIMS`，所以不可能跨维冲突。
4. 跨维矛盾（I3）只**报告**，不通过"拒绝另一维的取值"来解决。

**默认 `lspe_open_admin` 安全吗？** 安全 —— 判决不变，代价只是编译期多一本账。
这与"默认档不许改变任何现有程序的行为"不冲突：**行为**指判决与运行期行为，
LSPE 两样都不动。

### 10.6 0.1.4.7 渠道闸：发行版拒 `choose lspe_*`

第一部分（维度 + 台账 + 站点普查）**不在 0.1.4.7 发行版里兑现**。发行版种子把
`LOMENT_CHANNEL` 注入为 `1`，`check()` 里那一个读取点据它把 `choose lspe_*`
报成 **E022**；dev 通道照常收。

这与 LVM 当初同一条形状（用户 2026-10-18 定：**和之前 lvm 一样**）：

> **写得出、却什么也拿不到，比写不出来更坏。**

边界：

- **只在自举侧**：发行包由自举驱动器构建，`LOMENT_CHANNEL` 是打包期的注入点；
  Python 参考实现是 dev 工具链，没有渠道概念。
- **只有一个读取点**：`let rel = LOMENT_CHANNEL;` —— 每多一处读取，发行版种子与
  dev 种子就多差一个字节，`loment_channel_test` 的判据 F 会红。
- **探针留着**：`loment_channel_test` 的 `PROBE_LSPE` 期望发行版**拒**、dev **收**。
  将来放开时把期望**反转**，不删探针 —— 与 `use libl` / `choose hosted` / `choose vm`
  同一条棘轮。
- **用户看得见**：报的是 E022（`choose` 那一族），不是一条静默的空实现。

### 11.1 五级

## 13. 已关闭的路（带理由）

| 关闭 | 理由 |
|---|---|
| **用模型做质疑器** | 概率性审问会把"未标注的地板"重新引进来。每条义务必须是确定性检查器 |
| **自动修复 UNDECIDED** | §2·B：那等于宣称不可判定可判定 |
| **交互式必答** | 构建不确定，CI 不可复现。回答走文件/参数 |
| **`lspe` 与其它维建冲突表** | 违反"不与任何 choose 冲突"；且没有互斥对 |
| **把 E034 设为默认错误** | 那就成了"更严的 Rust"，与"温柔"相反 |
| **重命名 LMS / LGC** | 会动 `lom/*.lom` 契约与 Potato 字段；统一在台账层 |
| **让 E7（孪生）单独产生 PROVED** | 只证一致，不证对；`docs/253` §5.1.1 的教训 |
| **把证据排成全序** | "类型证明 vs 语法证明谁更强"没有语义答案；用接收关系 |
| **用墙钟做预算** | 墙钟散布 3.2–5.4×；步数才是确定性的 |
| **把整棵派生树塞进 Potato** | 产物会炸；哈希进产物、树进旁挂 |
| **"你必须"式的硬拒绝** | 除非有可构造反例（`REFUTED`）或显式 `--lspe-mode=strict`；否则那是上帝换了个柜台（§1.3） |
| **LSPC 自动修复** | "你爱修不修"意味着决定权在人；autofix 会把"告知"变成"替你决定" |
| **LSPC 默认阻断** | 阻断是 `--lspc=strict` 的显式选择；默认只告知 |
| **把 LSPC 做成 `choose` 第八维** | 它不改变语义，不配那十三处登记；构建旋钮 + 产物记录足够 |
| **声称风险族穷尽** | 只覆盖语言机制定义的封闭族；新机制必须新增一族（判据 22） |

## 14. 我不主张

1. **不主张 LSPE 能找到更多内存错误。** 它找的是**没有来源的放行**与**失效的证据**。
2. **不主张 P0 就覆盖所有义务。** 先三族；覆盖率是量出来的数。
3. **不主张反问器的问题质量高。** 它只问机械可判的问题。
4. **不主张 0.1.5 全落完。** P0 是底线，P2 是分水岭，P3/P4 可进 0.1.5.x。
5. **不主张十个规模数就等于 Rust borrowck。** 它们是**审计面**；
   真正的等价物是"每一类缺陷都有一条可触发的反向判据"。
6. **不主张 `lspe_close_admin` 安全。** 那正是被记录的选择 ——
   安全与否取决于你接不接受"没有审计"。
7. **不主张"编译器证不出来"等于"你的代码有问题"。** 前者是 **Q 码**（我的洞），
   后者是 **E 码**（一段可构造的反例）。把这两个混用，
   就是偷偷把**对内的审问**换回**对外的指责** —— 那正是本设计要背道而驰的东西。
8. **不主张 LSPC 让程序更安全。** 它让**残余风险不可静默**；程序性质仍不可判定（§2·A）。
9. **不主张风险族集合已经完备。** 它是**棘轮**：新语言机制进来必须新增一族，判据 22 盯着。
10. **不主张"后果自付"等于免责。** 它是**归责记录**，不是法律或道德上的免责声明。
11. **不主张 LSPE 有最终权威。** 权威在规范（`standard/LLS.md`）与各语义所有者；
    LSPE 只是**店员** —— 它报价、开小票、把找不到的货告诉你，不宣布真理（§1.3）。
12. **不主张策略层存在。** 它是**未来面**；今天只有默认与源码两层，
    E037 只保留、不发出（§10.4）。
