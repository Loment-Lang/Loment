# 266 · LVM 的 A4：超级指令 —— **合并的是同一串动作，不是一次猜测**

> 状态: **已落地**（2026-10-19，issue #647）· 上游: `docs/248` §3.1（A4）· `docs/259`（T2）
> · `docs/250`（紧凑形）· `docs/226`（怎么记账）
> 判据: `tools/lvm_fusion_test.py`（7/7）· 实装: `tools/lvm_t2.py`
> 一句话: **纯值指令的两条一组、执行期一次分派** —— 没有假设、没有守卫、没有去优化，
> 因为合起来的那串动作和原来**逐条是同一串**。

---

## 1. 它在 A 堆里的位置

`docs/248` §3.1 把优化分成两堆：背假设的（要守卫 + 去优化）和不背的。A4 在**不背**那堆里：

* 合并前后是**同一串动作**（同一批 op、同一个顺序）；
* 没有"这次是这两条、下次可能是别的"这回事 —— `add` 后面跟 `add` 是**静态可判**的形状；
* 所以判据只有一条：**语义逐字节相同**。

这也是它排在 A 堆第一位的原因：不欠 `docs/249` 那套去优化，却真能挪动一个数。

## 2. 做成什么：一张**派生**的计划，不是一种新 op

`_CFunc.plan` 是每块一张 `[(起始下标, 条数, 形状名), ...]`。它**完全由 `blocks` 决定**：

* 不进紧凑形、不进缓存 —— 解码之后按 op 重算，所以直编 / 紧凑形 / 缓存拿到**同一张计划**；
* 下标是 **IR 里的原下标**。剖面按 (函数, 块, 指令下标) 记边与调用点，融合不许把站点挪走；
* 关掉（`fuse=False`）时计划全是单条，执行器走原来的路径。

**只有两种 op 一组**（`_PAIR_OK`）：`arith+arith`、`load+arith`、`arith+store`、`icmp+br`。
每对都有**就地展开**的处理器，不是"把两条再分派回去"。

> ⚠ 这条限制是**量出来的**，不是设计洁癖。第一版把"连续纯值指令最多 4 条"都合成一组，
> 组内用 `_run_value` 逐条执行 —— 结果 T2 从 **5.5× 掉到 4.1×**（对 T0）。省下的外层分派
> 远小于多出来的一次 Python 函数调用。现在组内**就地展开**；同一份分派密集夹具上是
> **1.10×**（见 §5）。

## 3. 报告（`--fusion-out`）

一个**关着就一个字节都不写**的产物，格式与 T1 剖面同一套纪律（`docs/247`）：

```
# lvm fusion v1
# site = (function, block, first-instruction-index); shape = the fused op sequence
# order = IR parse order; [patterns] is sorted by shape
[sites]
__loment_memcmp	loop	1	icmp+br
...
[patterns]
arith+arith	22
icmp+br	9
```

**没有这份报告，判据只能量"变快了"，说不出"合了什么"** —— issue #647 的原话。

## 4. 从剖面里选（`--fusion-profile`）

给了 T1 剖面就只在**它点过名的块**里融合（`parse_hot_blocks`）：没有数的块一律不优化
（`docs/248` §2："猜"不是证据）。空的剖面 = 一处都不融合。不给剖面 = 每块都融 ——
A4 不背假设，所以"多融一处"不会多一份风险，只会多一份报告。

## 5. 数字（记账，不是判据）

同一进程交替跑、`min of 3`、本机：

| 夹具 | T2 不融合 | T2 融合 | 比值 |
|---|---:|---:|---:|
| `lumtui_demo`（语料里最重的一份） | 1202 ms | **1168 ms** | 1.03× |
| 分派密集循环（3×10⁷ 条纯算术） | 4949 ms | **4507 ms** | 1.10× |

**为什么语料上只有 3%**：`lumtui_demo` 的热点是访存与 `lvm.arith` 本身，分派不是大头；
A4 省的正是分派。分派密集的夹具把这一项放大到 10%。**两个数都记在 `docs/226`**，
判据只判符号（融合 < 不融合），不判倍数。

## 7. 我不主张

1. **不主张语料上能到 10%。** 10% 是分派密集夹具的数；真实程序通常更接近 3%。
2. **不主张它替代 T3。** A4 不改变"算什么"，只改变"分几次派"；B 堆（常量特化等）仍要走
   `docs/249` 的守卫/去优化。
3. **不主张计划是产物的一部分。** 它**不序列化**：紧凑形与缓存里的 op 不变，计划在解码后
   重算。这是有意的 —— 否则缓存会被"上一版的融合策略"绑死。
4. **不主张上限可以随便加。** 每加一种形状都要一个**就地展开**的处理器；用 `_run_value`
   凑数的形状比不融合还慢（§2 那次回归）。
