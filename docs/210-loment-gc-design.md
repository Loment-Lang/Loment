## 0. 一句话

> **主流 GC 是"一个算法管全堆"。本文说：回收是逐站点的一份合同 —— 每个 `alloc` 站点在编译期被分到某一层梯上，而"这份程序有多少内存不归 GC 管"是一个产物里的数。**

## 1. 前史先行（`docs/207` 的教训：先点名，再说话）

本文的四层梯**不是发明**。每一层都有先行工作，本文的新颖面窄得可以一句话说完（§3）。

| 层 | 先行工作 |
|---|---|
| **栈上分配 / 逃逸分析** | 主流 JIT 与 Go / Swift 的编译期逃逸分析：不逃逸的分配直接进栈 |
| **插 `free`（定活点）** | 编译期插入释放（区域推断 Tofte–Talpin 一系、线性/唯一性类型、Koka 的 Perceus） |
| **纪元 / 区域批量回收** | 区域推断、MLKit、arena；**Baker 1992** 已经把"回收 = 反向的子计算"与**栈纪律**写在摘要里 |
| **精确根表** | 类型静态 ⇒ 精确 GC；**但见 §4 第二条**：Loment 的 `alloc` 是**无类型**的，块内精度不免费 |
| **四级/多级混合** | 分层/混合内存管理（静态 + 动态）是成熟方向，不是新方向 |

**本文没有新机制。** 见 §3 那一句。

## 2. 设计：四层梯

每个 `alloc` 站点，在编译期被**证到**某一层。**从强到弱，先到先得**（证得住就往上层放）：

| 层 | 编译器要证什么 | 谁回收 | 代价写在哪儿 |
|---|---|---|---|
| **L0 静态** | 形状是 `let NAME: ptr = alloc(<整数字面量>);`，且 `NAME` 在**本函数体内只出现在两处**：那一处声明，以及若干处**恰好作为 `load8`/`store8`/`atomic_add` 的整个首参**（§2.2） | **栈**。根本不进堆，于是**没有回收问题** | 栈帧变大 |
| **L1 定活** | 形状是 `let NAME: ptr = alloc(...)`、**声明在函数体顶层**，且 `NAME` **只被 `load8`/`store8`/`atomic_add` 当整个首参透过**（与 L0 同一条"不外逃"判据）；于是"最后一次用处"是**可数的**（§2.5） | 编译器在"最后一次用处之后最早那条 `return` 之前"，否则**函数末尾**插 `free` | **只在 token 流证得到的范围内**：落点之后还有 `free` 够不到的路径（早返回那一支）就**漏一次** —— 是漏，不是错 |
| **L2 纪元** | `while`/`for` 的**体**里，每一处 `alloc` 都长成 `let NAME: ptr = alloc(...)`，且那些 `NAME` **一处都不出体**（§2.3）—— **编译器自己认出纪元，不用手写** | 体末尾**批量**归还（前沿回退，**不用链表**、不扫描） | **整格取消**：体里**一个**分配出体，整个体这一格就不能归还；且有四条明写的边界（§2.3）。这是"用表达力换零成本"，不是缺陷 |
| **L3 运行期** | 上面都证不到 | 收集器 | 收集器的全部成本 |

**这个梯子的形状是"证得越多、付得越少"**，而**每一层的价钱写在它旁边** —— 不藏在脚注里。

### 2.1 三档怎么落到这个梯子上

| `choose` 那一档 | L0 | L1 | L2 | L3 |
|---|---|---|---|---|
| `gc_manual`（默认） | — | — | — | **不回收**（与今天逐字节一致；程序自己管） |
| `gc_auto` | — | — | — | ✅ **已实现**（标记-清扫 + 精确根，§2.4） |
| `gc_auto_alpha` | ✅ **已实现** | ✅ **已实现**（§2.5） | ✅ **已实现** | ✅ **已实现（自适应 §2.6 + 分代 §2.7）** |

**`gc_manual` 一行都不动** —— 默认档不许改变任何现有程序（`docs/175` §3.4 那五条之一）。

**`gc_auto` 的收集器有一个明写的边界**（`docs/210` §7 也记一条）：触发按**分配量**记
（32 KiB 收一次），而 arena 是 64 KiB —— 所以 `gc_auto` 档**活集超过约 32 KB 的程序照样会耗尽**。
**这条上限是 `gc_auto` 这一档的，不是语言的**：`gc_auto_alpha` 的收集器是**自适应**的（§2.6）——
阈值跟着**活集**走 + **空间触发**，把上限抬到"活集接近整个 arena"（判据：活集 44 KB，`gc_auto`
耗尽 / alpha 跑通）。

**`gc_auto` 与 `gc_auto_alpha` 的差别因此是**可测的**：同一份程序，两者的 Potato 数不同，且**在某个程序上行为不同**（alpha 跑得通的那个，auto 会耗尽）。这就把 `docs/175` §3.4.1 那句"混合"从形容词变成了**一对程序**。
**两半都做到了**（2026-10-01）：那一对程序的**行为差**在 `loment_elf_test` 里；"Potato 数不同"那半由 v10 的 `gc_ladder` 给 —— `gc_auto` 下恒为 `{0,0,0,total}`，`gc_auto_alpha` 下四层各领走一部分（`docs/210` §5 第一行、§7）。

### 2.2 L0 的判据**刻意长在 token 流上**（已实现）

L0 的规则不是"在 AST 上走一遍"，而是**在函数的 token 跨度上扫一遍**。这不是实现细节，
是这一层能**两个实现逐字节一致**的原因：token 流是两边**唯一都完整持有的**表示。
AST 走法有两个自举侧补不平的洞 ——

* **有几处"名字"不在表达式位置上**：`for x in …` 的 `x`、`match P::V(x)` 里的 `V`/`x`、
  被调函数名、struct 字面量的字段名。在 AST 里它们是**字符串**，递归遍历**看不见**它们，
  于是 AST 侧会**多**提升；自举侧扫 token，看见的是一个无法归类的名字；
* **反过来**，AST 里有些节点根本不递归下去（例如以字段名为键的 dict），
  于是 AST 侧会**少**看见使用 —— "漏列一处就是静默放宽"。

规则原文（两个实现各有一份实现，`lomentc._l0_promotable` / `codegen.lomt` 的 `l0_size`）：

1. 候选形状只有一个：`let NAME: ptr = alloc(<整数字面量>);`（尺寸必须是**字面量** ——
   命名常量也不行；十六进制算字面量）；
2. `NAME` 不是形参；
3. 本函数体内 `NAME` 这个**标识符 token** 只出现在两种位置 ——
   (a) **恰好一处**紧跟 `let` 之后（就是那条声明本身）；
   (b) 其余每一处都紧跟 `(`，而那个 `(` 紧跟**只解引用首参**的内建，且 `NAME` 后面紧跟
   `,` 或 `)`（即**恰好是整个第一个实参**）。

(b) 等价于"只被读/写透过、从不外逃"：没被存进别处、没被传参、没被返回、没被重新赋值。
提升后的缓冲是**入口块的一条 alloca**，活满整个函数调用，所以**不需要**"引用不出块"那条
约束 —— 先前的稿子多要了它，而它**买不到任何东西**，只是让规则更难镜像。

**(b) 里"只解引用首参的内建"今天就三个：`load8` / `store8` / `atomic_add`。**
这份名单**只有一个来源**：`BUILTINS` 里 `ptr` 出现在首参的那几个 ——

| 首参是 `ptr` 的内建 | 算不算 | 为什么 |
|---|---|---|
| `load8` / `store8` / `atomic_add` | **算** | 内联降级，**只解引用**：不把指针存到别处、不产生派生的指针值 |
| `free` | 不算 | 它把块**还回去**；栈上的缓冲还给分配器是灾难 |
| `ptr_add` / `ptr_sub` | 不算 | 它们**产生一个派生的指针值**，而那个值会流到哪儿这里看不见 |

**`load16/32/64`、`store16/32/64`** 不是内建（在 `loment/examples/bytes.lomt` 里用
`load8`/`store8` 拼出来的 pub 函数）—— **但这不等于它们不安全**。原先把它们排除的理由是
"那是一次**跨函数调用**，`p` 进了别人的栈帧，编译器不知道那个函数会不会把 `p` 存起来"。
**2026-10-09 这一步被做掉了**（正是 §7 点名"最该先做的那次放宽"）：只要一个函数的**首参
不外逃**（在本体内只当**安全被调的整个第一个实参**透过），调它就与调内建**一样安全** ——
全局不动点把 `load32 -> load16 -> load8` 一层层解开。于是 `bytes.lomt` 的库函数对
L0/L1/L2 都成了安全被调（`lomentc_test::test_l0_rule_pair` 里的 `consume`、`test_l2_block_epoch_rule`
里的 `ld`、`test_l1_definite_lifetime_rule` 里的 `eat` 就是这次放宽的座位）。

> **这是 L0 那一处最窄的放宽。** 一句"这层有多宽"的诚实回答仍留在 §7 末：判据里那对程序有
> **16 个 `alloc` 站点，L0 从提走 5 个变成提走 7 个** —— 仍是**玩具尺寸**，真实语料的比例还没量。

`if let` 已被解析器反糖成 `match`，所以它的绑定名落在这两种位置**之外**，**取消资格**
（自举侧看见的是 `(` 后面一个不认识的调用名，同判）。

### 2.3 L2 落地成"**编译器自己推断的块纪元**"（已实现，零新语法）

原稿写的是"分配落在**显式 `epoch { … }`** 里"。实现时那条假设被**拿掉**了 ——
而拿掉之后它反而更贴近那句宣言：**"编译器与运行时共同预测对象的生命周期。"**

**纪元边界不必手写**：函数体与循环体本来就是块，只要"**体内分配的指针一处都不出体**"，
体末尾就能把分配器的前沿整段退回去。于是：

* **零新语法**（不动冻结面、不加关键字、不改 `lom/*.lom`）；
* 它是**推断**出来的，不是声明的 —— 同一份程序在 `gc_auto_alpha` 下自动拿到纪元；
* 代价由**规则**明写（下面四条边界），不藏在脚注里。

规则（`lomentc._l2_ok` / `codegen.lomt` 的 `l2_ok`，**同样定义在 token 流上**）—— 一个
`while`/`for` 的**体**能开纪元，当且仅当：

1. 体内**至少有一处** `alloc`；
2. 体内**没有 `str_concat`** —— 它落的也是堆，而 `str` 的逃逸在这里看不见（`str_ptr` 会把
   里面的指针变成一个整数交出去）；
3. 体内**没有 `free`** —— 这一条是"末尾一条 `store` 就够"的**证明**，而它管的范围比体内
   那一层调用大（**被调函数里也能 `free`**），所以证明分两步：
   ① 能把前沿往**下**的只有 `__loment_free`，而它**只在"释放的那块正好顶到前沿"时才往下**；
   ② 顶到前沿的那块，要么是**体内分配的**（那要把它**交给**别人 —— 被调函数 / 另一个变量 /
   返回 / 派生指针，第 4 条已经挡住），要么是**体外分配的** —— 而它**不可能跨过 `sv`**
   （跨过就与体内那些块重叠了，而分配器不给出重叠的块）。
   于是体末尾 `off` 必然 `>= sv`，写回 `sv` 就是回退。
   **（顺带：`min` 要 `select`，而自举镜像链接器 `lomelf.py` 的 `lower` 里没有 `select` ——
   而包内链接器就是它。所以这一条既是设计，也是那道硬约束逼出来的形态。）**
4. 体内**每一处** `alloc` 都长成 `let NAME: ptr = alloc(...)`（**尺寸随便** —— 常量是 L0 的事），
   且那些 `NAME`：不是形参、在体内只有一处声明、不被重新赋值、**在体之后一处都不出现**、
   在体内只出现在声明处或**恰好作为** `load8`/`store8`/`atomic_add` 的整个第一个实参。

**四条边界（都写在这儿，因为它们都会被当成"缺陷"报上来）**：

| 边界 | 为什么 |
|---|---|
| **整格取消** | 体内**一个**分配出体，整个体就不能归还 —— 不是只废掉那一个。要更细的粒度就得看生命周期，那是 L1/L3 的活 |
| **只查体之后，不查体之前** | 体**之前**不可能用到体里声明的那个名字（作用域），所以那里出现同名不算逃逸。这一条是**能做的**那一半保守 |
| **同名循环会互相挡** | 体**之后**出现同名标识符即取消 —— **即使那是另一个循环自己的局部**。token 流上认不出"哪个 `p`"，所以要保守。真正的解法是作用域解析，见 §7 |
| **L0 已经提到栈上的名字豁免** | 它根本不碰 arena：既不欠这次归还，也不该因为它挡掉旁边那些真在堆上的分配 |

**这一层与 L0 是叠加的**，顺序有意义：L0 先提走能提的（栈上，连 arena 都不碰），L2 再给
剩下的那些把前沿退回去。于是**残差**（要 L3 收集器管的那部分）就是"既不是常量尺寸、又活过
了自己的块"的那些分配 —— `docs/210` §3 那句话说的就是这个组成。

### 2.4 `gc_auto` 抄了市面自动 GC 的哪几条（**逐条**，含没抄的）

用户 2026-09-25 给这一档的定义是「**自动 GC 按照市面上各大语言的自动 GC 优点集合**」。
那就得逐条点名：**抄了哪几条、没抄哪几条、各自为什么**。沉默不是理由（§6 的体例）。

**抄了的（都落在产物里，可判）**：

| 抄的是哪一条 | 在这儿长成什么样 | 代价 |
|---|---|---|
| **精确根** | 根**不是猜的**：编译器发一张槽表 `@__loment_roots`（形参在前、局部按声明序），表里存**槽的地址**。这是与保守式 GC（连栈都当字节扫）**方向相反的一个取舍** —— 假指针不会从根上冒出来 | 每个"持有指针的函数"入口 push、每个 `return` 前 pop |
| **标记-清扫、不搬移** | 清标记 → 扫根 → 传播到定点 → 清扫，四趟。这是最老的那一格，也是最省的一格 | 碎片不消（无 `coalesce`）；换来**没有指针修正**，于是没有搬移带来的停顿放大 |
| **按分配量触发** | `@__loment_gcbytes > 32768` 收一次并清零。主流那几家都是这个口径（"自上次以来分配了 N 字节就收"），不是"堆满了才收" | O(1)、可预期；代价是**看不见活集**（§2.1 末尾那个上限就是从这儿来的） |
| **分配前触发**（collect-before-allocate） | **每个分配点**前一句 `@__loment_maybe_collect(请求字节数)` —— 就是 `alloc` 与 `str_concat` 共用的那一个发射点（`lomentc.alloc_ir`）。与"分配失败再 GC 重试"同效 —— 那是所有收集器的兜底 | 好处：**不动 `__loment_alloc` 一个字节**，于是 `gc_manual` / `gc_auto_alpha` 两档的产物**逐字节不变** |
| **零注解** | 不写 `choose` 就是默认档，写 `choose gc_auto` 就全都有了。对比：Rust 的 `Rc`/`Arc`/生命周期标注、C++ 的智能指针、JVM 那一串 `-XX:` 调参 | 反面是**没有逐对象的策略** —— 要精细就换档，不在这一档里塞旋钮 |
| **收完立刻能用**（不降级） | 清扫把死块挂回**地址序空闲链表**；"顶到前沿的块"走**前沿回退**。两条路都是分配器本来就有的（`docs/175` §3.4），收集器只是把死块**交还**给它 | 无额外代价；这条是"不搬移"能成立的前提 |

**没抄的（逐条带理由）**：

* ~~**分代** —— 本后端有一条既有事实：**指针只能存在局部/形参槽里**（`struct`/枚举的字段
  只装标量，§4.2）。于是"老年代指向年轻代"这件**写屏障唯一要管的事**几乎不存在，
  加一套卡表**买不到什么**。等字段能装指针了再谈。~~ —— **这条理由是错的，2026-10-10 更正**
  （§2.7）：`p as u64`（M67 的 `ptrtoint`）今天就有，`store64`（`bytes.lomt` 用 8 条 `store8`
  拼出来的）写得完 —— 于是**指针本来就能进堆块**，「老年代指向年轻代」不是几乎不存在，
  而是**收集器那趟保守传播一直在替它兜底**。分代因此**落了**（§2.7），代价明写：
  每一次 `store8` 多一条屏障调用。
* **搬移 / 压缩** —— 不是懒，是**做不了**：块内是**保守**扫的（`alloc(N)` 无类型），
  搬一块得知道块里每个字的类型，而"保守"恰恰就是"不知道"。**保守与搬移绑在一起，
  只能两样一起拿或一样都不拿。**
* **增量 / 并发 / 亚毫秒**（ZGC、Shenandoah、Go 的并发标记那一类）—— 两个理由：这个后端
  **单线程、无信号**，没有并发可言；而用户给「**不存在任何需要冻结全部业务流程的阶段**」
  那一定性挂的是 `gc_auto_alpha`（§4.4）。`gc_auto` 这一档**老实 STW**，不冒充。
* ~~**自适应策略池 / 生命周期预测** —— 那是 `gc_auto_alpha` 的目标~~ —— **这一档抄了**（§2.6，
  2026-10-10）：`gc_auto` 仍是**固定**触发（老实 STW、「优点集合」那一档不冒充自适应），
  而 alpha 的 L3 收集器换成**阈值跟活集走 + 空间触发**的自适应那一支 —— 两档的差别因此
  是一个**可测的**事实（同一份源，alpha 收得下 44 KB 的活集，`gc_auto` 在 32 KB 处耗尽）。
* **弱引用 / 终结器** —— 语言面还没有对应构造（没有 `weak`、没有 `Drop`）。
* **大对象区 / TLAB / region** —— 没有线程，也没有页的管理层。
* **`coalesce`（相邻空闲块合并）** —— `docs/175` §3.4 已记着它没做。收集器**不替它补**：
  合并是分配器的活，收集器只负责把死块**交回**分配器。

**这一档的代价（明写）**：

* 用到 `alloc`/`free` 的 `gc_auto` 单元，产物**恒加约 5.2 KB** 收集器文本 ——
  **不用 `alloc` 的单元不带**（收集器嵌在"要发堆"那一支里，与参考实现同形）；
* 根表 1024 格，**满了点名拒**，不静默写穿（递归深了才可能撞上）；
* **活集 ≳ 32 KB 会耗尽**（§2.1 末尾那条上限）；
* 块内保守 ⇒ 块里一个**长得像指针的整数**会让整块活着 —— 那是**不精确**的回收，
  不是**不安全**的回收。

判据三条，都写出来了（§5）：静态那条钉"痕迹在不在、在几处"，动态那条钉"真的回收"，
字节一致那条钉"两个实现同形"。

### 2.5 L1 落地成"**最后一次用处之后立刻还**"（已实现，零新语法）

L1 要证的是"这一块**定活**"—— 它活到哪儿为止是**可数的**。落地的形状与 L0/L2 一样：
**规则定义在 token 流上**（理由同 §2.2：那是两个实现唯一都完整持有的表示）。

**为什么不靠 `docs/206`（这一句原先写错了，2026-09-25 更正）**：那条路的证据是 E006
（非 Copy 的变量移出之后不许再用），而 `_is_copy_type` 只把 `struct` 与数组算作非 Copy
—— **`ptr` 是 Copy** ⇒ 按值传一个指针**根本不算"移出"** ⇒ E006 对 `alloc` 出来的指针
**一句话也说不了**。所以 L1 与 L0/L2 同一条纪律，`docs/206` 不是它的依据。

**规则**（`lomentc._l1_place` / `codegen.lomt` 的 `emit_l1` 各一份）：

1. 候选形状 `let NAME: ptr = alloc(...);` —— **尺寸不限**（要字面量那是 L0 的事）；
2. `NAME` 不是形参、只声明一次、不被重新赋值，且除声明外**每一处都恰好是
   `load8`/`store8`/`atomic_add` 的整个第一个实参** —— 与 L0 **同一条"不外逃"判据**
   （`_ptr_only_uses`，两边共用这一句）。不外逃 ⇒ **块只有这一个入口** ⇒ 还掉它别处摸不到；
3. 声明必须在**函数体顶层**（不在任何 `{` 里）。这条是**安全**要的，不是洁癖：局部槽在
   入口块统一 alloca，而**赋值只发生在声明那一处** —— 声明若在条件里、那一支又没走，
   槽里是**未初始化**的值，在末尾 `free` 它就是在 free 一个垃圾指针；
4. **落点**：**最后一次用处之后、最早那条 `return` 之前**（求值完、`ret` 之前）；
   一条都没有（void 函数）就落**函数末尾**。两者共同点是**都在"最后一次用处之后"**：
   最后一次用处按 token 序取，而 token 序是**动态序的超集**（文本上更靠后的用处必然更晚
   执行），所以"所有用处都在这个位置之前"在两种序下都成立。`return` 是**终结**语句、
   每次调用至多执行一次 —— 哪怕它本身在循环体里，插在它前面也不会多跑一遍。

**四条边界（都明写）**：

| 边界 | 代价 |
|---|---|
| 只有"**只被解引用透过**"的指针接得住（与 L0 同一条名单） | 原先是"用 `load32`/`store32`（`bytes.lomt` 的库函数）的代码拿不到"；**2026-10-09 那次跨函数 deref-only 放宽把这一行开了**（§2.2 末 / §7）：`load32`/`store32` 现在是**安全被调**。剩下真正的缺口是**首参之外**的实参（`load32(p, off)` 的 `off` 不在这条名单上）与**派生指针**（`ptr_add`/`ptr_sub` 仍不算） |
| 声明必须**在函数体顶层** | **循环体内分配的那一类不接**（那是 L2 的地盘）。明写的代价，不是缺口 |
| 落点只有一个 | 落点**够不到的路径**（例如最后一次用处之后还有一条早返回）就**漏一次** —— 是漏，不是错 |
| 与 L2 **不可能指同一块**（L2 要分配在循环体内，这一层要声明在顶层） | 白送的性质：不用再单独判 `s.l2`，也就没有 double free 那条路 |

**原稿的第三个落点（"含最后一次用处的最外层循环之后"）撤掉了**：它要求知道**外层**循环的
跨度，而自举侧的发射器手上只有**当前**这一层的跨度（它不维护循环栈）。为了那一点更早的回收，
在两个实现里多一处容易写歪的推理，不划算 —— 换掉的代价就是上表第三行。

**`if` 的两支也算块**（2026-10-11）：每一支与循环体是同一个形状的块，规则还是 `_l2_ok`
那一条，只是"体"换成那一支的 token 跨度。这一格补上之前，**写在分支里的分配**（不在
函数体顶层 ⇒ L1 也接不到）只能等收集器。判据：真值表六格（`lomentc_test::test_l2_if_branch_rule`，
含"支里没分配""名字出支""已被 L0 提走"三个不该开的方向）+
动态一对（`loment_elf_test::test_l2_if_branch_epoch_bounds_the_heap`：40000 次 × 64 B ≈ 2.56 MB
过 64 KiB arena，`gc_manual` 耗尽 / alpha 跑通）+ 逐字节（`m89` 多跑一对 `if` 源）。

**与 L0/L2 的分工**：L0 先提走字面量尺寸的（连 arena 都不碰）、L2 给循环体开纪元，
**剩下的**才轮到 L1 逐个还。它**不需要新语法**：产物就是用户手写 `free(NAME);` 时那两条
IR（先 `load ptr`，再 `call void @__loment_free`）。

### 2.6 `gc_auto_alpha` 的 L3 落地成"**自适应**收集器"（2026-10-10）

L0/L1/L2 是**编译期**证得住的那些（§2.2/§2.3/§2.5）。**证不住的那些（L3 残差）此前没人收** ——
`gc_auto_alpha` 档的 `alloc` 只剩分配器（bump + 空闲链表 + 前沿回退），**没有收集器**
（这是 §2.1 "alpha 的 L3 只剩残差" 的本意）。这一节把它补上，而且**是自适应的**。

**与 `gc_auto` 的区别只有触发那一支**（本体是同一段 mark-sweep：精确根 + 标记-清扫 + 前沿回退）：

| | `gc_auto`（§2.4 的"优点集合"） | `gc_auto_alpha`（这一档） |
|---|---|---|
| 触发 | **固定**：累计请求量过 32 KiB 收一次 | **自适应**：阈值 `= 活集 × 2`（下限 32 KiB），**或** 空间触发（前沿 + 本次 + 头 > arena − 余量） |
| 已知上限 | **活集 ≳ 32 KB 必耗尽**（活集 + 至多 32 KiB 垃圾 ≤ 64 KiB，装不下） | 抬到"**活集接近整个 arena**"—— 空间触发在快满时先收 |
| 两实现 | 逐字节一致 | 逐字节一致（同一段本体、只换触发支） |

**"自适应"具体是什么**：每收一次，清扫完**标记还在**，于是量得出**活集字节数**
（`@__loment_livebytes` 扫一遍标记块的 size 加总），把下次的**触发阈值设成 `活集 × 2`**（下限
32 KiB）。活集小 ⇒ 收得勤而便宜；活集大 ⇒ 收得稀，让 arena 装得下 —— 再加一条**空间触发**兜底。
**不用 `select`**（下限那一格走分支）：自举镜像链接器 `lomelf` 的 `lower` 里没有它（§8 那条硬约束）。

**判据三条**：静态 `lomentc_test::test_gc_alpha_adaptive_collector_text`（alpha 有收集器 +
`thresh`/`livebytes`；`gc_auto` 那支碰都不碰）+ 动态
`loment_elf_test::test_gc_alpha_adaptive_bounds_a_large_live_set`（活集 44 KB：`gc_auto` 耗尽
rc=132 / alpha 跑通 rc=7）+ 逐字节（`loment_p8_test` 的 m88/m89/m91 —— 它们本来就跑 alpha）。

**顺带修的一个既有暗伤**：根表那两个全局**从收集器里拆了出来**（`_IR_ROOTS`），跟着 `gc_any` 发。
此前"**有根没堆**"的单元（`gc_auto` 只带一个 `fn f(p: ptr)`、或 alpha 把 `alloc` 全 L0 提走之后）
会发出**引用未定义全局**的产物 —— 实测有，不是设想。

### 2.7 L3 的第二级：**分代**（`minor` / `major`，2026-10-10）

**为什么先前没做**：§2.4 原先写"指针只能存在局部/形参槽里 ⇒ 写屏障买不到什么"。**那条是错的**：
`p as u64`（M67 的 `ptrtoint`）今天就有，而 `store64`（`loment/examples/bytes.lomt` 里用 8 条
`store8` 拼出来的）把它写得进块里 —— 于是**堆里本来就有指针**。「老年代指向年轻代」不是
"几乎不存在"，而是**收集器那趟保守传播一直在替它兜底**。既然有真事可管，一套卡表就买得到东西。

**两代怎么切**：**老年代** = 地址 < `@__loment_oldtop`，**年轻代** = 其余。这一刀切在**地址**上，
不是"对象的岁数" —— 非搬移收集器的"晋升"是在**每次小回收末尾**把 `oldtop` 推到当前前沿
（这次活下来的从此算老）。分配器是 bump + **地址序空闲链表**，所以"复用一块老空闲块"会落在
老年代里（按地址算老）：那是**保守**的一侧（它要等下一次全量才可能被收），不是不安全的一侧。

**五个部件**：

| 部件 | 是什么 |
|---|---|
| `@__loment_cards` | 1024 张卡 × 64 B = 整个 arena |
| `__loment_wb(ptr)` | **写屏障**：地址落在老年代 ⇒ 那张卡置脏；落在堆外（栈 / 只读段）或年轻代 ⇒ 什么都不做 |
| `__loment_minor()` | 清**年轻代**标记 → 扫根 → **扫脏卡** → **只传播年轻代** → **重置空闲链表 + 清扫整堆** → **晋升** |
| `__loment_major()` | `__loment_collect`（全量）+ 把 `oldtop` 推到前沿 + 清卡表 |
| 策略 | 该收时**先小回收**；收完前沿**还顶在装满那一档**，再跟一次**全量**兜底 —— 「要么收够、要么确实装不下」 |

**省下来的是哪一趟**：清标记与传播**只覆盖年轻代**（贵的就是这两趟）。清扫那一趟照旧覆盖整堆，
而且**必须**这样 —— 理由见下一条。

**一个踩进去的坑（值得写下来）**：最初的小回收是"只清扫年轻代、**不**重置空闲链表"。那是**坏的**：
前沿退回去之后再长上来，同一块会被再 `free` 一次（`__loment_collect` 里那句注释警告的正是这件事），
链表一坏，`alloc` 就可能返回一个**低地址的假大块** —— 于是判据里那个"年轻块"**一出生就算老的**，
**判据空转**（实测：拆掉写屏障那一趟，判据照样绿）。当时的修法是**每次重置链表**。

**而这个「修法」本身后来变成了 bug（2026-10-15，`FujoJTOP/loment#366`）**：重置的理由是
「本来就在链上的块会被再 `free` 一次（双重插入，链就毁了）」—— 可那条理由**站在 `#164` 之前**：
当时 `free` 不验所有权，谁调都往里挂。`#164` 之后 `__loment_free` 只认**借出中**的块
（块头 `next` 是负数，见 §2.8），已经在链上的一律**惰性返回** —— 于是重置**防不住任何东西**，
却把**当前所有空闲块**从分配器手里**永久**丢掉：清扫撞上它们时那道守卫拒绝重挂，
而清扫**不会**把它们放回去。字节还在 arena 里、还在前沿之下，`alloc` 再也摸不到 ——
64 KiB 的 arena 约**八次回收**就见底。

**落地的修法是那一行直接删掉**（`__loment_collect` 与 `__loment_minor` 两处都删），
不留"重置"这个动作。判据两条互补：
`loment_elf_test::test_a_collection_keeps_the_free_list`（单只程序，直接量"收完还在不在链上"）
与 `::test_collection_keeps_blocks_that_were_already_free`（三只同源，第三只是**证伪**：
不 `free` 的那一份必须耗尽）。

**同一处还有一半是"漏了"而不是"错了"（`FujoJTOP/loment#367`）**：触发那句原先只挂在 `alloc`
这个**内建**的发射点上，而 `str_concat` 走的是同一个分配函数、却不经过那个点 —— 于是一份
**只拼字符串、自己从不 `alloc`** 的程序，`@__loment_gcbytes` 永远是 0，**收集器一次都不会被叫醒**
（判据 `loment_elf_test::test_every_alloc_site_arms_the_collector`：修之前 `gc_auto` 那只也是
rc = 132）。修法是把触发搬进那个共用发射点，**每个分配点都得问**。

**第三个坑：分配器自己写坏了一条不变量，而**所有**遍历都按它走（2026-10-15，`FujoJTOP/loment#368`）**。
`__loment_alloc` 的 `take` 有一句 `store i32 %need, ptr %hp`，位置在 `taken:` —— 也就是**无论拆没拆**
都把块头的 `size` 改写成请求量。真拆了的时候那是对的（余下那截在 `cur + need` 处另立了一块）；
**不拆**（余量 < 16 字节，所以没切）的时候就是错的：块的**跨度**仍是 `%bsz`，**记录尺寸**却小了
`%bsz - %need`。于是每一趟**按 `size` 往前走的遍历**（首次适配、`__loment_sweep`、`__loment_propagate`、
以及收集器那两趟清标记）都会从 `cur + need` 继续 —— 那不是下一块，是**块的内部**；载荷里那些字
多半是 0 ⇒ `i += 0` ⇒ **死循环**。症状是"第二次回收之后程序不再返回"（`perf` 的样本全落在清标记
那一趟的小循环里），而那几十个字节也从此谁都找不到。修法很小：那句只在 `split:` 里写，
`nosplit:` 原样留着 —— **块的记录尺寸永远等于它的实际跨度**。
判据 `loment_elf_test::test_a_recycled_block_does_not_derail_the_walks`（`#368` 的复现；
修之前 `gc_auto` 那只被 timeout 杀掉，rc = 124）。

**第二个坑（2026-10-14 挖出来的，比上面那个更疼）**：修上面那条时，顺手在释放那一格加了句
「**释放前把标记清零**」—— 写成 `store i32 0, ptr %smp`。那不是清一格，是**越界清**：
`@__loment_mark` 是**每 8 字节堆一位**的位图，`%smp` 指向的是一格**字节**，而 `store i32` 一次抹掉
**4 格 = 256 字节堆里的全部块**；就算写成 `store i8 0`，也照样抹掉同一 64 字节里另外 7 个块的位。
要命的是**清扫是往上走的**：它刚把一块垃圾交回去，就顺手抹掉了**后面 256 字节内那些还活着的块**的位，
走到它们时看到的已经是 0 ⇒ 一并当垃圾收掉。**两档都中**（`gc_auto` 与 alpha 共用这一个
`__loment_sweep`）—— 判据是 `loment_elf_test::test_sweep_keeps_a_live_block_next_to_garbage`
（同源、只差 `choose` 一行；两档各退 3 就是它红的样子）。而清零**本来就不需要**：走到那一格的
**前提**就是「这一位是 0」（`%smsm` 为假），所以那一行是**删掉**而不是写窄 —— 位图里没有
「多余那几位」可以放心清。

**由此立一条规矩，两处都适用：清标记只能清自己那一位。** `__loment_minor` 清年轻代标记那一趟
原来写 `store i8 0`（整格字节），于是 `oldtop` 落在自己那一格的中间时（它**不保证 64 字节对齐**），
`oldtop` **下面**那几个旧块的位会被一起抹掉 —— 而 `propagate` 只从 `oldtop` 起走、旧块整段不扫，
抹掉就再也标不回来。改成按位清之后，那一趟清的就**只剩它自己走过的那些块**。
**这一半没有最小复现**：它是读代码读出来的（改动方向是**单向**的 —— 新写法清的是旧写法所清位的
一个子集，只会**少收**、不会多收），所以它跟着第一条一起进来，判据只钉第一条。

**代价（明写）**：每一次 `store8` 多一条**间接调用**（`atomic_add` 也一样）。`gc_auto` 那一档
**不带**屏障 —— 它老实做全量，也就不该替每一次**写**付这条税。**门槛是两条一起**：alpha 档
**且这份单元真的要那块 arena**（`heap_needed` 预扫描）—— 一份把 `alloc` 全 L0 提走的单元
没有堆，那儿的屏障既是白费、又是引用不到符号的产物（2026-10-12 补，`FujoJTOP/loment#239`）。值不值要看「写的次数 ÷ 收的次数」。

**量过一次，只留下确定性的那一半**：一份「写多收少」的负载（3e6 圈 × 8 条 `store8`）上，
alpha 的 **IR 比 auto 长 1.37×** —— 屏障是每个 `store8` 站点一条调用，**站点数由静态判据钉着**，
所以这个倍数不会漂。

**墙钟补上了**（2026-10-16，`FujoJTOP/loment#365`）：同一份源**只差 `choose` 一行**，
**一次 shell 里跑 5 遍取最小**（`docs/226` 那条"别每样本起一次 wsl 计时"的同一条手法），

| 档 | 墙钟 | 与 auto 之比 |
|---|---|---|
| `gc_auto`（**不发**屏障） | 9.5 ms | 1.00× |
| `gc_auto_alpha`（每站一条 `wb`） | 30.1 ms | **3.18×** |

负载刻意是**写重、几乎不分配**（循环里一次 `alloc` 都没有 ⇒ 两个档的差别**只有**那条屏障，
没有收集器掺进来）—— **每圈 8 条 `store8` 打在同一块上、跑 1e6 圈**，活集就那一块。
**注意那个坑**：`alloc(4096)` 写成字面量会落到 **L0**、被提到栈上，于是**根本没有堆**、
连屏障都不发（实测：那样量出来是 1.01×，等于在量一条空循环）。所以分配**要让它逃逸**
（经 `fn mk(n: u32) -> ptr` 返回），落到 L3 才真的走堆。

⇒ **IR 只贵 1.37×，墙钟贵 3.18×** —— 两件事不矛盾：那 1.37× 数的是**指令条数**，
而墙钟里还有调用开销与多出来的分支。所以要拿"墙钟贵多少"说事时，用下面这个数，别用 IR 那个。
判据 `loment_elf_test::test_the_generational_barrier_has_a_measured_cost`（界取 5×，
抓的是**形状**变化；比值印在每轮的 `PASS` 行上）。

**判据三条**：

* **静态**：`lomentc_test::test_gc_alpha_adaptive_collector_text` —— alpha 有卡表 / 屏障 /
  `minor` / `major`，`gc_auto` **一个都不沾**；而且**写屏障的挂点数**要对（本程序两个 `store8`
  ⇒ 正好两条屏障），符号在而挂点漏了是**静默地少收一块**。
* **动态（这一条能证伪）**：
  `loment_elf_test::test_gc_alpha_minor_keeps_a_young_block_reachable_from_an_old_one` ——
  **老块里存着一个指向年轻块的指针**，写完再 churn 若干轮，末尾读回来必须还是当初那个标签。
  **拆掉 `__loment_minor` 里那趟脏卡扫描，它立刻红**（实测 `rc=110`：块被回收、字节被后一轮垃圾
  改写）。这份程序刻意绕开三个"会让目标块不年轻"的机关（尺寸独一无二 ⇒ 只能从前沿分配 /
  在第一轮之后分配 ⇒ `oldtop` 已立起来 / 之后换尺寸 churn ⇒ 年轻代才真的长起来）—— 三个都是
  实测踩出来的，写在判据的 docstring 里。
* **逐字节**：`loment_p8_test` 的 m88 / m89 / m91 —— alpha 的产物本来就含收集器，两个实现同形。

### 2.8 `free` 的所有权校验（2026-10-13，`#164`）

**问题**：块头的 `+4` 以前只有"空闲链下一跳"一个用途，于是 `free` 分不清"第一次"与"第二次"。
第二次释放把同一块**同时**放在 bump 前沿与空闲链表上 ⇒ 随后两次 `alloc` 拿到同一段 ⇒
**两段活内存互相写**。它的错法不是崩溃，是**静默串味** —— 所以只有"跑起来"的判据抓得住它。

**标记**：`alloc` 发出去的块在 `+4` 写 **`-1`**（借出中）。这个字只有两种合法值：空闲块记的是
链上的后继（`0` = 链尾，或 ≥ 8 的偏移），**永远不是 `-1`**。于是不换块头尺寸、不动布局，
就多出一个"这块正借在外面"的位。

* `alloc` 的 bump 臂与链表臂**都**写 `-1`（后者以前把旧链接留在那儿）；
* `free` 的挂链臂不用改 —— 它写的后继本来就不是 `-1`；
* `split` 余下的那块保留真链接 —— 它仍然是空闲的。

**`free` 的顺序**（都便宜；失败**惰性返回**，不是 `abort` —— 一个野指针不该把整个产物带走，
但它绝不能进空闲链表）：

| # | 检查 | 挡的是 |
|---|---|---|
| 1 | `d32 >= 16` | 头之前 / 头里面 |
| 2 | `d32 <= @__loment_off` | 前沿之外 |
| 3 | `d32 & 7 == 0` | 未对齐（`alloc` 用 `(size + 15) & -8` 取整，载荷必 8 对齐）|
| 4 | `next == -1` | **已经释放过**（双重释放）|
| 5 | `size >= 8` 且 `hi + size <= @__loment_off` | 头本身不合常理 |

1–3 必须排在**读头之前**，否则野指针会先读到越界的字。尾块那条"正好顶到前沿就回退"的路由
第 2 条与第 5 条一并挡住（回退过的块，`d32` 已落到前沿之外）。

**残余边界（写清楚，不假装关掉了）**：一个**对齐得正好**、指进某块中间的派生指针，如果它后面
那个字恰好是 `-1`，仍会被接受。要堵住得回答"这是不是一个块首"——那要么走一遍块链（O(n)，
清扫路径上太贵），要么另存一张分配位图。**这条留在已知边界里。**

**判据**（`tools/loment_elf_test.py` 三条，都在"程序跑起来"这一层，不是看 IR）：
`test_free_refuses_a_double_free`（`a` 后面还有 `b` ⇒ `a` 是**非尾块**，走挂链那条路）·
`test_free_refuses_a_pointer_it_does_not_own`（远在 arena 之外的派生指针）·
`test_free_still_reuses_the_block_it_just_freed`（**回归**：LIFO 复用照旧 —— 别把正常那一次释放
也挡掉，那会变成"内存一路涨且不报错"）。第一条**已验可证伪**：把参考侧还原成旧分配器，它立刻红。
参考与孪生两处文本逐字节同，由 `loment_p8_test` 的 m88 / m89 / m90 / m91 钉住。

### 2.9 块内精确：**同一张证明的第三次使用**（2026-10-13）

§4.2 那条诚实边界（"精确 GC 对根成立、对块内不成立"）到这里收口。**路不是文档原先写的那条**：
"给 `alloc` 带类型"今天**做不到** —— 后端不许聚合字段装指针
（`native M23: struct 字段类型 ptr 暂只支持标量`），于是**没有任何一个类型能描述"这块的
第 1 个字是指针"**。§4.2 那句因此是**堵死的**，理由记在 `FujoJTOP/loment#286`。

走的是**推断**，而且用的是**同一张证明**：L0/L1 已经有一条"这块不外逃"的判据
（`_ptr_only_uses`），块内精确就是把它再用一次 —— 判据一样，付的钱不一样：

| 层 | 规则 | 付什么 |
|---|---|---|
| **L0** | 不外逃 + 尺寸是字面量 | 提到栈上 |
| **L1** | 不外逃 | 最后一次用处之后 `free` |
| **块内精确** | **每一处用法都是一次看得见的 `store8`/`load8`** —— 比 L0/L1 **更严** | 一张**槽掩码** |

候选是 `let P: ptr = alloc(...);`。**别名**（`let Q: ptr = R;`）算同一个集合，**最多 4 个
名字**，超了退回保守。集合里每个名字在函数体内**每一处**都只能是：那条声明、一条别名声明、
`store8(N, <字面量>, <值>)` 或 `load8(N, ...)` 的**第一个实参**。别的用法 —— 交给函数
（`w64(p, 8, head)` 那种）、`as u64`、`ptr_add`、`free`、被赋给别的变量 —— **一律取消资格**。

掩码**一位一个字**（8 字节）：`store8(N, <off>, V)` 写的那个字置位，**除非** `V` 是整数字面量。
名字、表达式、转型**一律**算"可能是指针" —— **宁严勿宽**：多算一个槽只少一格精度，漏算一个槽
就是**把活着的指针当垃圾**。`L1` 过得去的站点**不要掩码**（它到不了收集器），所以这一格
**只对 L3 可能成立**。

**钱付在哪儿**：掩码得让收集器**按块**读到。块头那个字在借出时是 `-1`，精确站点改成
**`-(mask + 2)`**（`-1` 恰好还是原先那个数 ⇒ 保守），`free` 的守卫从"恰好 `-1`"放宽成
"**任意负数**"。**掩码不进任何表** —— 掩码本来就是**每个站点一个常数**，而头上那个 32 位字
装得下（所以 `_SLOT_WORDS` 是 30，留出符号位与"`-1` = 保守"那一格）。精确站点多发三条指令
（`ptrtoint` / `sub i64` / `inttoptr`，理由见下面那条硬约束），保守站点一个字节不变。

**三句必须先说的话**：

* **行为上几乎看不见。** 收集器那条保守判据是**看值不看槽**的（一个字只要"长得像堆内地址"
  就留着），而能被证成非指针的值**本来就不会长得像地址** —— 于是精确与保守扫出来的是**同一批字**。
  **唯一**看得见差别的角落是**陈旧字节**：复用来的块里，新主人从没写过的那个字还留着上一任
  住户的地址。这不是缺陷，是这一格**给不出更多**的原因：它买的是**承诺**（"精确 GC"这句话
  从此对块内也成立）与**前置**（§4.2 说搬移/压缩卡在"块内保守扫"上），**不是吞吐**。
* **`store16/32/64` 不算"看得见的写"**：内建表里只有 `load8`/`store8`，其余在 `bytes.lomt`
  里是**用户函数**（`w64` 那样按字节拼）。所以真代码里点得着的站点少 —— 与 §7 那条
  "被量的东西太少"是同一件事。
* **掩码只有 30 位**：一位一个字 ⇒ 一个站点最多认前 30 个载荷字（240 字节），超了退回保守
  —— 它要跟"`-1` = 保守"一起挤进块头那个 32 位字。截断成"只扫前 240 字节"是**不安全**的，
  所以只能退回。

**硬约束又逼了一次**（§8 那条，与 L2"体内不许 `free`"同源）：头在 `%p - 4`，但
`getelementptr ... i32 -4` **不能发** —— 包内镜像链接器把 `i32` 立即数**零扩展**进 64 位，
`-4` 于是变成 +4294967292，产物当场**段错误**（clang 路没事，正是这条差别暴露的）。所以指针减 4
走 `ptrtoint`/`sub i64`/`inttoptr` 三步。链接器那一侧的缺陷另记（`FujoJTOP/loment#313`）。

**判据两处**，都是逐格/逐字节的：`lomentc_test::test_slot_table_rule`（四个站点四格：字面量值
⇒ 掩码 0；非字面量值 ⇒ 那一位置位；交给用户函数 ⇒ 不精确；偏移是变量 ⇒ 不精确；外加
"只有精确站点改写块头"与"掩码真的带上去了（`-2` / `-4`，且没有表）"两条钉子）与
`loment_p8_test::test_m92_slot_table_is_byte_identical`（同一份源，两个实现**逐字节一致**）。
**动态那一半为什么缺席，写在 §7。**

## 3. 窄新颖面（一句话）

> **把"每一层的份额"写进产物，于是 GC 的组成是一个不读源码可判的数。**

主流 GC 的**策略**是运行时现象：你只能在跑完之后看停顿分布、看吞吐。
本文把**策略的组成**变成**编译期产物**：几个站点走静态、几个走定活、几个走纪元、几个留给收集器。

**这不是"更快的 GC"，是 GC 的可观测性换了一个层面** —— 从"跑起来什么样"换成"**编出来是什么**"。它与本仓既有的两样东西是同一条思路：Potato（`docs/147`）与 `boundary.total_sites` 那条**自洽规则**（`docs/205` R5）—— 校验器读不到源码，但判得了"这几个数自相矛盾"。

## 4. 疯狂的那几格

按"能不能证伪"排序，不按好不好听排。

### 4.1 **编译期拒绝，而不是运行期退化**

L3 的**最坏情形**如果能被界住（例如"循环内的分配 × 循环上界"可判），而它超过 arena，**编译器点名拒**。

> 「内存不够」从**运行期灾难**变成**编译期的一个诊断**。

**诚实边界**：L3 的最坏情形**通常界不住**（分配次数依赖输入）。所以这一条**只对能界的那个子集成立** —— 但对那个子集，"**会不会 OOM**"是**可判的**，而这在主流语言里根本不是个能问的问题。

### 4.2 **根表是一个可审计的产物**

根 = 指针类型的局部槽。类型静态 ⇒ 编译器知道；编译器知道 ⇒ **能发出来**。

于是「**收集器认为什么活着**」**不运行就能 review**。主流 GC 的策略是不可见的运行期行为；这一条把它变成**产物里的一张表**。

~~**诚实边界**：Loment 的 `alloc(N)` **无类型** —— 程序用 `store8/32/64` 往里写，编译器**不知道**块内哪几个字是指针。所以**根**可以是精确的（编译期发的表）；**块内**只能**保守**扫（把每个 8 字节字当可能的指针）。~~

—— **这一条 2026-10-13 收口了**（§2.9）：块内也有了一张**编译期发的表**（每个分配站点一行
槽掩码）。文档原先指的路（"让 `alloc` 带上类型"）**是堵死的**：后端不许聚合字段装指针，
所以没有任何一个类型能描述"这块的第 1 个字是指针"（`FujoJTOP/loment#286`）。走的是**推断** ——
与 L0/L1 **同一张不外逃证明**的第三次使用。

**收口要连着读 §2.9 那三句**：这一格买的是**承诺**与**前置**（搬移/压缩卡的就是"块内保守扫"），
**不是吞吐** —— 保守判据是看**值**不看**槽**的，所以精确与保守扫出来的是同一批字。

**L0 的提升缓冲也算"根"**（2026-10-15，`FujoJTOP/loment#362`）：提升到栈上的 `[K x i64]` 缓冲
在根表里占 **K 格** —— 每个 8 字节字一格（登记的是**字**的地址；收集器照旧"读那一格、看它像不像
堆内地址"）。不这么做，登记进去的会是**局部槽**的地址，而那个槽里存的是**栈**地址：根扫按
`值 − 堆基址 < arena` 判，栈地址直接跳过 —— **整块缓冲从来没人扫**。而 L0 的规则**并不禁止**
缓冲里装堆指针：`_ptr_only_uses` 会把"只解引用"的用户函数吸收进安全集，于是那种函数可以把
任意 u64 写进缓冲（容器就是这么干的）。漏掉的后果是**静默的**：只被缓冲指着的对象被当垃圾
收掉、块被复用，程序读回别人的字节。
判据 `loment_elf_test::test_a_promoted_buffer_is_scanned`（`#362` 的复现，末尾那块 `alloc(32)`
是**探测块** —— 对象真被收了它就一定落在目标那块上；修之前读回 200，rc 3）。
**代价记在根表容量上**：1024 格里一格一个字的算法，让"提升了大缓冲"的程序比从前更早撞到
那道**点名拒**的闸（不是静默写穿）。

### 4.3 **残留是"没人认领的"，不是"被发现的"**

方向的倒转：收集器**不发现垃圾**。凡是**证得死**的，L0/L1/L2 已经处理掉了。**送到收集器手上的，恰好是没人愿意认领的那部分。**

⇒ 收集器的职责从"全堆"缩到"**残差**"，而**残差的比例是一个编译期已知的数**（§5 第一条判据）。

### 4.4 **纪元是唯一"不扫描"的批量回收 —— 而它买的是栈纪律**

L2 之所以能不扫描，是因为**严格后进先出**：前沿退回去，整段消失。这不是本文的发明（Baker 1992 的摘要里就点了栈），而且**它不是免费的**：**任何非后进先出的回收在 L2 里表达不出来。**

**所以 L2 是一个"用表达力换零成本"的档，不是"更好的 L2"。** 把它写成更漂亮的样子，就是把价钱藏起来。

**落地之后这一条的价钱更具体了**（§2.3）：代价不是"编译错"，而是**那一格静默地拿不到纪元**
（`l2` 判成假），于是它**退到 L3 那一层**去 —— 在 L3 还没做之前，就是**不回收**。
而"哪一格拿到了、哪一格没有"是**编译期就知道的数**，逐格钉在真值表里（§5 第六行）。

### 4.5 **常态是"没有一个叫 GC 的组件"**

若一份程序的 L3 残差是 0，产物里**没有收集器** —— Potato 里 `L3 == 0` 就是证据。**"这份程序不需要 GC"因此是一个可判的事实，不是一种期待。**

（**今天还只能到 L0 这一半**：一份**全 L0** 的 `gc_auto_alpha` 产物里连**分配器**都不剩 ——
`lomentc` 是按"发射出来的文本里还有没有 `@__loment_alloc`"决定要不要带那份 6 KB 运行期的，
所以提干净了它就自己掉出去。自举侧同判：`codegen.lomt` 的 `heap_needed`/`runtime_needed`
要**跳过被提升掉的 `alloc`**，不然两边会差一份运行期 —— 那是 `loment_p8_test` 的
`test_m88_l0_alpha_pair_is_byte_identical` 抓到的第一个差异。
"`L3 == 0` 就是证据"那半仍等 Potato v10。）

这与 `docs/175` §3.6 那个 `runtime` 维接得上：`runtime` 开着但 `L3 == 0` 的产物，**运行期存在而不被使用** —— 那正是这一维该能表达的一格。

**"L0 真的发生"这一格最后落成了静态形式**（产物里没有分配器了），而不是原先写的动态形式
（`gc_manual` 下耗尽 / alpha 下跑通）。理由是**前者更强也更快**：一条 `call @__loment_alloc`
都不剩，就**不可能**还有内存来自那个 arena —— 而动态形式要跑 ELF、依赖退出码，
是对同一件事更弱的一个观测。**动态那一对仍然值得写**（它是"整条链跑得通"的证据），
记在 §7。

## 6. 已关闭的四条路（**带理由**，不是"以后再说"）

这一节是本文最该被读的部分：它挡住四条**看起来很深**的路，而那四条都有人走过、或者本文这一轮走过。

### 6.1 **可逆回收（`unfree` / 回卷深度 `d`）—— 关闭**

**理由不是"难"，是别名。** 要对**每一步**都留够能倒着跑的历史，而别名满地都是（每个可变局部、每次经指针的写都不可逆）⇒ 留下的是**整段计算** ⇒ `d → ∞` ⇒ 内存无界。**有界的 `d` 就是检查点回滚**，不是"程序的逆运算"。

**前史**：Baker 1992 《NREVERSAL of fortune》（IWMM '92, LNCS 637, 507–524）已经把"回收 = 反向的子计算"和**栈**写在摘要里。**本文这条线是重发现，不是发现。**

### 6.2 **`excluded` / `closed` / `Obs*` 当回收判据 —— 关闭（箭头反了）**

`Obs*` 回答的是「这个单元能把数据**送到**哪些空间」（**外向**许可）；回收要问「哪些指针还**摸得到**这块内存」（**内向**可达）。**同一条图上相反的方向。**

⇒ `closed` 做到多传递都**不可能是回收判据** —— 不是缺口待补，是**箭指错了方向**。**也不是补一层流向分析能救的**：那个分析会说"外部不可观察 ⇒ 可丢"，而程序**正用 `*a`/`*b` 读着它**；要判它可丢，就得同时知道**内部指针的活跃性** —— 那就是可达性本身，**兜回来了**。

（这一条来自 `docs/208` §2.2，本文照收。）

### 6.3 **率失真 —— 关闭**

`R(0)` 只是**商集的熵**，是一个**单点**，不是曲线；它给"不可约信息"一个标准名字（**Wu 2026** 覆盖的范围），**不带来定理**。率失真真正的内容在 `D > 0`，而那要求语言先有**声明的误差预算** —— 那是**另一个词**，不是 GC。

### 6.4 **Landauer / 热力学当设计依据 —— 关闭（挂错了轴）**

税挂在**复用**上，**不挂在回收上**：`free(p)` 不擦任何东西（写几个字节块头）；压实式收集器是**遗弃**不是擦；抹熵的是**下一次覆盖写**，而那次写程序自己也要做。

⇒ **这条账分不出"有 GC"与"没 GC"**，它分的是"**复用与不复用**"。而且它比一次 CMOS 开关的 `½CV²` 小 **3–6 个数量级**。

**真正约束 GC 的物理量在别处**：**保有时耗电**（DRAM 每 64 ms 刷新一遍，随存活字节量线性增长）与**数据搬运**（摸一次 DRAM 比摸一次 L1 贵两个数量级）。**要物理目标函数，用这两个，别用熵。**

     两侧各补一格（`lea`），**不落 `zext`**（两边同形，否则 ELF 不逐字节同）。

  **真 bug**：`lomelf` 把 `#dbg_declare` 当成**不支持的指令**直接拒 —— 于是 `--debug` 的 IR
  **链不出来**，而 `docs/167` §4 第 7 行写的是"元数据**被忽略**、原生产物没有行表"。文档与

  判据两条，都在 `loment_elf_test`：`test_debug_flag_adds_metadata_and_nothing_else`
  （L0 与 L2 各一份，`--debug` 的 IR 与不带的那一份**必须不同**、带 `#dbg_declare`、
  过 `lomelf` 后**逐字节相同**、跑起来退出码一致）与 `test_debug_ir_links_the_same_through_the_mirror`
  （同样的 IR 喂镜像，与参考**逐字节相同**）。**自举侧仍然没有 `--debug` 这一档**
  （`--debug` 是参考实现的旗标）—— 那是既有的边界；这一次核的是"参考实现发的 debug IR，
  **两个**链接器都认，且产物不受影响"。
* ~~**块内精确性做不到**（§4.2 那个诚实边界）：`alloc` 无类型。要精确得先给 `alloc` 带类型，
  那可能要过 B0。~~ —— **做了**（2026-10-13，§2.9）：**推断**出来的每站点槽掩码，与 L0/L1
  **同一张不外逃证明**。`alloc` 带类型那条路**走不通**（聚合字段装不了指针，`#286`）。
  **动态那一半缺席，写明理由**：掩码今天只有**写**那一半（编在块头那个字里，`free` 只看它的
  **符号**）。收集器的判据是**值**（"这个数看起来像不像地址"），而编译器证得出"不是指针"的值
  本来就不会长得像地址 ⇒ **有没有掩码，扫描选中同一批字**。所以"掩码少一位 ⇒ 活指针被当垃圾"
  这条**今天造不出可红的判据** —— 要让那一格可证伪，得先有一个**读**掩码的消费者（搬移/压缩
  那一类）。这一格买的是**承诺**与**前置**，**不是吞吐** —— §2.9 第一句话就说了为什么。
  **它需要的那个形状，判据已经在了**：`loment_elf_test::test_gc_alpha_keeps_an_object_behind_a_young_written_edge`
  ——"目标只经由另一个块里按字节写的引用可达"。那条**一度立不住**：`__loment_sweep` 清标记
  清宽了 4 个位图字节（= 256 字节堆），**垃圾块后面 256 字节内的活块会被顺手收掉**，于是
  `gc_auto_alpha` 丢、`gc_auto` 留（**#312**）。那一处 2026-10-14 修了（§2.7 / **#363**），
  这条判据才真的钉住东西。
* **收集器的算法已经落地**（§2.4 是它的全部取舍），但**这一版有一处明写的上限**：
  ~~触发按分配量（32 KiB）而 arena 是 64 KiB ⇒ **活集 ≳ 32 KB 的程序照样耗尽**。~~

  （阈值跟活集走 + 空间触发），活集接近整个 arena 也能收。**分代也已经做了**（§2.7）——
  §2.4 原先那条理由（字段还不能装指针 ⇒ 写屏障买不到什么）**是错的**，更正在 §2.4 与 §2.7。
* ~~**收集器没有在真实语料上量过**：§2.4 所有数字都来自判据里的玩具程序。~~ —— **量过了**
  （2026-10-12）。工作量是 `loment/examples/gc_heap/main.lomt` —— **仓里第一份真拿 `alloc`
  在堆上建结构**的程序（一张**单向链表**，节点 16 B，下一个节点的地址用 `as u64` 存进块里；
  一个**长命**节点 + 每圈一个**短命**节点）。它的 `gc_ladder` 是 `{0,0,0,1}`：那一个站点
  **本来就该归收集器**（尺寸是命名常量 ⇒ L0 接不到；指针从 `return` 出去 ⇒ L1 接不到；
  分配在辅助函数里、调用方的循环体没有 `alloc` ⇒ L2 接不到）。三个档位各编一次、都在 64 KiB
  arena 里跑 **120000 圈 × 16 B ≈ 1.9 MB**：

  | 档 | 退出码 | 墙钟（**一次 WSL 里跑 5 遍**取最小） |
  |---|---|---|
  | `gc_manual` | **132（耗尽）** | 3 ms（早死） |
  | `gc_auto` | 7 | **343 ms** |
  | `gc_auto_alpha` | 7 | **336 ms** |

  **两件事先读出来**：`gc_manual` 在这份工作量上**跑不完**（那是"默认档不回收"的直接观测）；
  而两个回收档**都跑完、几乎打平**（2% 之内）。所以这一版里档位的差别**不是吞吐**，是**上限**
  （§2.6 / §2.7 那两条）与**代价形状**（§2.7 那条写屏障、§2.6 那趟活集扫描）。**别拿前面那两组
  合成负载推断"哪一档更快"** —— 它们的活集与写读比比这一份极端得多（那边 alpha 反而慢）。

## 9. 收口

**Loment 的 GC 不该是"一个更好的算法"。** 它应该是**一次分类**：把每一块内存按"编译器证得到多少"分到四层梯上，让**证得到的部分根本不进收集器**，并把**每一层各有多少**写进产物。

**这样得到的东西，主流 GC 那一栏根本没有对应项**：不是更短的停顿，而是**一个可读的组成** —— 而且它的每一格都能被一对程序证伪。
