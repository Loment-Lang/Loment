> 状态: **已实装**（2026-11-20），参考 T0 + 自举镜像（镜像是对齐的地址那一半，见 `docs/371` §6）

---

## 0. 它落在 `docs/360` 的哪一格

`docs/360` 把 LVM 写成一台抽象机，六个原语里前四个是运行期指令：

| 原语 | 本文的落法 | 代码 |
|---|---|---|
| **P1** `site(pc)` | 站点 = `(函数, 块, 块内指令序号)`，与 `llvm.trap` 同一套 | `lvm.py::Executor._run_loop` |
| **P2** `cap_check` | 访问前查对象表的 `base`/`limit` | `SwCap.check` |
| **P3** `gen_check` | 对象表里的 `gen`；归还时加一 | `SwCap.retire_oid` |
| **P4** `fault(kind, site)` | `_Fault` → 退出码 `100 + kind` + 一行站点 | `lvm.py::fault_exit` |

**P5（checkpoint）与 P6（模型规范）不在本格。** 本格只把「对象从哪来、能力怎么走、
代在哪加一」写成可跑的东西。

`sw_cap` **默认关**（`--substrate none`）：关着时每一处检查都是
`if self.sub is not None`，被解释程序的行为与从前逐字节相同（判据 A）。

## 1. 对象从哪里来

对象表 `SwCap` 只有五个字段：`base` / `limit` / `gen` / `alive` / `kind`。
五种来源：

| 来源 | 何时登记 | 何时归还 | `kind` |
|---|---|---|---|
| **全局** | 启动时（`_place_globals`） | 永不 | `global` |
| **`command_main` 的 argv** | `entry_values` 铺完命令行之后 | 永不 | `argv` |
| **`brk` 授予的区** | `brk(want)` 真的把堆往前推时 | 永不（缩堆不登记） | `brk` |
| **`alloca`** | **每执行一次**一条指令就登记一个 | 栈帧返回时 | `alloca` |
| **堆对象** | `__loment_alloc` **返回之后** | `__loment_free` **返回之后** | `heap` |

两条"之后"是有意的：分配器自己要写块头、写空闲链、擦已归还的载荷 —— 那是基座的活。
`__loment_*` 帧因此是**特权帧**（`Executor.priv > 0`），在它们里面能力检查跳过。
这不是漏检，是 `docs/360` W2 的原文：对象表要覆盖的是 guest 的可达内存。

---

## 2. 能力怎么走

`Cap` 不是机器字 —— LVM 的 `ptr` 仍是 64 位裸地址。它是解释器 SSA 侧的一对整数
`(obj_id, gen)`，按 SSA 名挂在帧上（`Frame.caps`）。传播规则：

| 指令 | 能力 |
|---|---|
| `alloca` | 新登记的对象 |
| `getelementptr` | **基操作数**的能力（边界由对象管，不由地址管） |
| `load ptr` | 指针存储的影子表 `shadow[addr]`；没有就按地址找 |
| `store ptr` | 把它写进 `shadow[addr]`（指针进内存，能力跟着进） |
| `call` 返回 `ptr` | 按返回地址找；`__loment_alloc` 在返回后对象已经登记 |
| `inttoptr` | 按地址找（洗过的指针只能这样） |
| `phi` | 选中入边的能力（两条入边不同就不猜） |
| **函数形参** | 调用点实参的能力（指针过函数边界不丢） |
| 其它 | 没有 —— 访问时按地址找 |

**为什么 `getelementptr` 用基操作数而不是结果地址**：`a[10]` 在 `[u32; 4]` 上算出来的
地址可能正好落进栈上另一个局部（或堆上另一块）。按地址找会把越界**归错对象**、
然后放行。按基操作数就只有一个答案：这块对象只有 16 字节，偏移 40 越界。

---

## 3. 一次访问判什么

`SwCap.check(addr, width, cap, site)`：

1. `addr == 0` ⇒ **F03**；
2. 有 `cap` ⇒ 对象必须还活着、`gen` 相等、`off + width ≤ limit`，否则 **F02 / F01**；
3. 没有 `cap` ⇒ 先看**最内层**归属：
   * 最内层是已归还对象 ⇒ **F02**；
   * 最内层是活对象 ⇒ 宽度必须在界内（否则 **F01**）；
   * 谁也不盖 ⇒ **F01**。

第 3 条里"最内层"是必须的：堆对象住在 `@__loment_heap` 这个全局里面，全局**永远活着**、
覆盖整块 arena。只问"有没有活对象盖住"，归还之后每个地址都还能落进那个外层全局，
悬垂永远抓不住。（第一版就是这么错的，判据 C 当场把它纠出来。）

## 4. fault 与退出码

| 码 | 名字 | 退出码 | 报文 |
|---|---|---|---|
| **F01** | `BOUNDS` | **101** | `lvm: F01 bounds violation at fn:blk#idx (offset=40 size=4 limit=16)` |
| **F02** | `DANGLING` | **102** | `lvm: F02 dangling reference at fn:blk#idx (address=… was freed (object 9))` |
| **F03** | `NULL` | **103** | `lvm: F03 null dereference at fn:blk#idx (size=4)` |

码与 `docs/356` §5.2 的提案一致；退出码 `100 + kind` 照那一节，与 `128 + 信号` 的区间不撞。
站点格式与 `llvm.trap` 的 `lvm: llvm.trap at fn:blk#idx` 同形 —— 同一个程序里两种
语言事件，第三方读出来的位置一样。

## 5. 边界（诚实写清楚）

1. **裸地址，能力会丢。** `ptrtoint` → 整数算术 → `inttoptr`（语言里是 `as u64` / `as ptr`）
   之后，只剩地址。地址被下一次 `alloc` 复用之后，旧指针与一个新指针**长得一模一样**
   —— 这一档抓不住。非概率的对象代要求指针本身携带代（胖指针 / 槽表），
   那是 `docs/360` §3.3 的 `hw_cap` 与 `docs/320` S1 的事。**本文不主张它是完备的。**
2. **只在 T0。** `tools/lvm_t2.py` / `tools/lvm_t3.py` / 紧凑形都还没有它；
   `--substrate sw_cap` 对它们**点名拒**。自举镜像 `loment/tools/lvm.lomt` 有**按地址**的
   那一半（没有 SSA 能力表），三条故障与语料由 `lvm_twin_test::test_cap_*` 钉住；
   checkpoint/封印在 `docs/371`，自举 checkpoint 与 `sw_tag` 在 `docs/364`。
3. **没有封印字段。** `docs/360` §3.4 的 `substrate` 剖面还没有进 Potato；
   今天是 CLI 开关 + 旁挂封印（`tools/lvm_seal.py`），不是默认产物里的字段。
4. **解释器体积预算（B8）与 `hw_cap` 的真跑没有。** `docs/360` §7 的八条里，
   B1/B2/B3 由 `lvm_cap_test` 落，B4/B5/B6/B7 由 `docs/371` 落；
   B8 今天只给**验证器**标了价，解释器本身仍未标价。
5. **零误报只在 10 份语料上量过。** `loment_elf_test.CORPUS` 每一份两种基质同答
   （判据 E）。这是实测，不是证明；语料扩了要重新跑。
6. **性能没测。** 每次访问多一次对象表查找；对象表随 `alloc` 次数增长（上限 `1<<20`，
   越过就是基质自己的失败）。`docs/226` 的纪律：不给比值门禁。

## 7. 我不主张

1. **不主张 LVM 现在就是下一代硬件。** 它是**一台软件抽象机**，`sw_cap` 是它的第一档基质。
   时间桥梁的硬判据 B5（两种基质同一份字节码哈希）要第二档基质，本文没有。
2. **不主张完备。** 能力在裸地址上会丢（§5.1）；地址复用之后悬垂抓不住。完备边界要靠
   指针携带元数据，那是另一档。
3. **不主张默认档变了。** `--substrate none` 是唯一默认；`choose vm` 的产物一个字节没动。
4. **不主张性能。** 未测。
5. **不主张它是第二套语义。** 合法程序在两种基质下逐字节同答（判据 A/E）——
   加了检查，没加行为。
6. **不主张封印已经落地。** `substrate` 剖面还在 `docs/360` §3.4 的提案里。
