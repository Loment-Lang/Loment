# 336 · 报错码细分：27 个族码 → 207 个码（2026-11-10）

> 用户 2026-11-10（原话）：**「从 main 更新报错系统，开始细分报错码，现在很多都是聚在一起的，
> 每个码全部拆分，至少到 E0200-E0300」**；编号形状追加一句：**「100 往上需要前面加个 0，
> 也就是 E0xxx，和 1 一样」**。
> 上游：`docs/182`（报错器）、`docs/244`（覆盖计划）、`docs/191`（16 门语言对照）。

## 0. 一句话

**"类型不对"不再是一个码。** 172 种编译器诊断模板，每一条有自己的码、自己的标题、
自己的五段说明卡；码表从 41 个用户码涨到 **207** 个。

## 1. 先量：现状有多粗（实测）

按 `tools/lomentc.py` 里 `errs.append` / `LomError` 的调用点枚举**诊断模板**（172 条），
再逐条过 `loment_diag.classify()`：

| 族码 | 它当时一个人兜着多少种消息 |
|---|---|
| E004 能力域 | **29** |
| E001 类型 | **26** |
| E041 生命周期/域 | 16 |
| E022 `choose` | 13 |
| E013 重复定义 | 10 |
| E015 字段/下标 | 9 |
| E008 匹配/枚举 | 8 |
| E002 未声明 | 7 |
| E003 实参个数 | 6 |
| 其余 18 个族码 | 1–5 各自 |

于是"E001"这一个码，用户在 `loment explain E001` 里读到的是一张讲"类型必须一致"的卡，
而实际撞到的可能是 `if` 条件不是 bool、可能是 `slice_len` 收了标量、可能是
`thread_spawn` 的入口不是字面量 —— 三件事，三种修法，一个码。

## 2. 编号：两条规则

1. **数字连续**（1..207）。既有不变式"用户码从 1 起连续"没动 —— `surface_data.n_codes()`
   仍然是上界，`loment codes` / `explain` 一行没改。
2. **显示形状**：`< 100` 写 `E0xx`（`E042`），`>= 100` 写 `E0xxx`（`E0100`）。
   这是用户定的形状，与今天 `E001` 的写法连起来读就是"`E0` + 补零到足够宽"。

`code_num()` 两侧都放宽到 **4 位数字**（原来 3 位）：改的是**形状**判据，不是"码表到几"。
`E4294967298` 这种仍然被拒（位数上限还在）。

## 3. 旧码不删：它们是**族码**

E001..E041 全部保留，作用变成两件：

* **兜底**：将来新增的消息如果还没写细分规则，仍然落到它这一族 —— 不会掉进 E0999；
* **兜底卡**：细分码的 `why` / `yes` / `no` 缺省**继承族码**。这三段讲的是"这一族的语言
  规则"，族内各处境共用；`what` 与三条 `fixes` 一律逐条写 —— 那才是"这一条要你做什么"。

所以卡片的形状没变（五段都在），变的是**颗粒度**：结论段更具体，规则段仍是一族一套。

## 4. 落点

| 层 | 在哪 | 改了什么 |
|---|---|---|
| 数据 | `tools/loment_diag.py` 的 `FINE` 表 | 166 条细分规则：`code / family / 正则 / 标题(中英) / what(中英) / 三条 fixes(中英)` |
| 安装 | `_install_fine()` | 把 `FINE` 摊进 `RULES`（**插到族码规则之前**，先命中者胜）、`CARDS`、`CARDS_EN`、`TITLE_EN`、`ASCII_ONE_LINER` |
| 前缀 | `_install_fine()` | `^` 锚点自动放过 `12: ` 那个**行号前缀**（语义错带它，解析错不带） |
| 渲染器 | `loment/tools/lomenterr.lomt` | `code_num` 收 1..4 位数字 |
| CLI | `loment/tools/lomcli.lomt` | `wcode3` 按 `<100` / `>=100` 补零 |
| 生成物 | `loment/tools/surface_data.lomt` | 134 KB → **522 KB** |

**为什么细规则插在最前**：`RULES` 是"第一条命中者胜"，而族码的规则是宽形状
（`类型 .*应为` 这类）。细分规则全部更具体，插在前面才不会被族码吃掉。

## 5. 判据

* `test_every_message_the_compiler_can_print_has_a_code`（既有）—— 172 条模板**全部有码**，
  0 条 E0999；
* **新增** `test_every_template_has_its_own_code` —— 172 条模板**全部落到细分码**
  （`code_num > 41`），一条都不许退回族码。加了新诊断却没写细分规则，这里当场红；
* **新增** `test_code_numbers_use_the_two_display_widths` —— `<100` 是 `E0xx`、
  `>=100` 是 `E0xxx`，且 `code_num` 两侧都解得出；
* `loment_tools_test` 原来那几条（键集相等、每族 ≥3 条修法、中英条数相等、
  两段各自连续）继续管着新表。

## 6. 自举侧：第二份实现也得跟（用户 2026-11-10 追问「自举跟上了吗」）

码在**自举编译器**里是**数**（`checker.lomt` 的 `E_DUP` / `E_TMISMATCH` 常量，**没有消息文本**），
所以 Python 侧一细分，两侧立刻对不上 —— `loment_rule_parity` 第一次跑出来是
**122 条口径漂移**（`py=[126] loment=[12]` 这种）。

迁的时候动的是四处：

| 文件 | 改了什么 |
|---|---|
| `loment/selfhost/checker.lomt` | 98 个 `chk_pub` / `sym_pub` 点改成分细码；合并型的点**拆开**（内建元数按 `slice_len`/`print_num`/其余三分；`if` 与 `while` 各一码；借用冲突按掩码分 109/110） |
| `loment/selfhost/checker.lomt` | `check_type` 多一个 `code` 形参 —— 「未知类型」五种处境（字段/载荷/返回/形参/`let`）靠调用方传 182–186 |
| `loment/selfhost/switches.lomt` | `sw_err` 多一个 `code` 形参：超上限 167 / 重复 168 / 未定义 169，嵌套仍是族码 22 |
| `loment/selfhost/checker.lomt` | 数组字面量把**裸整型字面量**当"类型未知"（与参考实现 `expr_type(IntLit) is None` 同口径），否则 `[1, true]` 会报成"两种实类型"（148）而不是"整型字面量混入 bool"（149） |

结果：`loment_rule_parity` **135/135 等价，假阳性 0、漂移 0、探针失效 0**。

**教训（写下来免得下次重踩）**：这一层是**两套独立实现**，"改一套"永远等于"改两套"。
对拍判据 `loment_rule_parity` 是唯一能当场说"没跟上"的东西 —— 它比的是**码集**，
不是消息文本，所以细分码一改它就红，而不是等到用户那边看见两个码。

## 7. 这一轮没做的事

* **没有给细分码加新的"支持/不支持"文案**：`yes` / `no` 继承族码。逐条重写 207 份
  "支持什么"是把同一件事抄 207 遍 —— 属于本仓最反对的那种重复。
* **没有改编译器的消息原文**：这一层是**分类与解释**，`lomentc` 一个字符没动。
* **自举侧的少数自检点仍是族码**（能力域时律参数、生命周期里三条自举独有的检查）：
  它们没有对应的细分码（参考实现没有同形状的消息），留在族码上是对的。
* **没有把"码"做成稳定 ABI**：`docs/182` §17 那条"报错器有自己的版本号"照旧 ——
  这一轮把版本推到 `0.1.3`（码表大改，渲染面看得见）。
