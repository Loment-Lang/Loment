## 2. 深度 3：偏移也是地址吗

### 2.1 三层地址

| 层 | 是什么 | 第一期后 |
|---|---|---|
| **L1 全局地址** | 一个整数能指到任意字节、能跨体加减/排序 | guest 侧已无（令牌 + F04/F05）；参考的体已是**各自 bytearray** |
| **L2 体内字节偏移** | `body.data + off`；跨字段相加；把偏移当数 | **仍在**：参考 `DismBody.data[off]`、镜像 `d_addr` 的平坦下标、帧槽的 `base+n` |
| **L3 表示层的坐标** | 三维放置的 `x/y/z/dx/dy/dz`、平坦帧窗口 | 仍在（对 guest 不可观察，但解释器用它算） |

深度 3 的目标：**L2 从语义里消失**（L3 只作为“摆法标签”，不再参与寻址）。

### 2.2 什么叫“没有偏移”

一条字节可寻址的数组，定义上就有“第 k 个字节”。把 k 拿掉不是删变量，而是**换语义**：

> **体 = 有类型的路径树。** 体的内容是一张 `path → cell` 的持久映射，`path` 是
> **字段/元素下标**的序列（`[u32;4]` 的第 3 格是路径 `(3)`，结构体的 `x` 字段是
> `(x)`），不是字节位移。`getelementptr` 在构造路径；`load/store` 按**单元类型**
> 读/写一格；没有“base + 字节数”这个运算。

这样做的后果，要写明：

* `load8(p, k)` / `store8(p, k, v)` 变成“字节格 k”，**k 只是格号**，不是地址；它不能
  与另一个格号相加去“走到隔壁体”，跨体仍是 F05。
* 依赖**字节重解释**的程序（把 `[u32;4]` 当 16 字节 blob 扫、memcpy、按字节打包）仍然
  能跑 —— 每个字节是一个格，但**没有连续字节数组**这个对象；`sizeof` 只用于布局
  检查，不用于寻址。
* 依赖“相邻字段可以越界访问”的程序本来就被 F01 拒；这条不变。
* 编译器为 `alloca`/全局/堆生成的布局**只决定格的命名**，不决定位置；重定位不再
  改任何可计算的量。

**不可拿掉的那一层（诚实写）**：格号本身仍是一个整数；`a[i]` 的 `i` 仍是整数。
“彻底没有整数”等于把数组换成一棵不可变的树，现有数组程序全部不兼容。深度 3 的
准确说法是：**整数只作为“这一层结构里的下标”存在，不再是“空间里的位置”** ——
没有全局基址、没有字节位移、没有跨结构的序。

### 2.3 表示怎么落

* **参考 T0**（**S2 已落**）：`_DismBody.data: bytearray` → `cells: dict[int, int]`
  （逻辑格号 → 字节）。`Dismem.put/get` 从 `data[off+k]` 改为 `cells[key]`；
  `alloc` 只建空映射，**不再按 size 铺缓冲区** —— 分配 1 MiB 不会产生 1 MiB 的存储。
  逻辑格号仍是整数（§2.2 那条诚实的边界），但它在代码里只作为**这一颗体的格号**
  参与运算；解释器没有任何"体基址 + 字节数"的量。
* **镜像**（S3 已落）：体表从“arena 里的平坦字节 + `data+off` 下标”改为**固定
  开放寻址格表**（`CT` 区，每条 `体号/物理格号/字节/状态`，写 0 = 墓碑）。
  访存不走地址：`d_loc` 只回 `(体号, 偏移)` 的打包值，读/写/拷贝一律按格
  （`d_cget` / `d_cput` / `d_copy_in` / `d_copy_out`）；系统调用的缓冲区走一块
  宿主暂存（`IOS` 区）。`MAX_DB/DT/DR/CT` 用尽 → F06（与参考对齐）。
  **帧与聚合仍是宿主区** —— 它们从来不进 guest 值，也不可被指针指到；这一层不在
  深度 3 的命题里（写清比假装改过更诚实）。
* **L3 摆法**（参考侧 S2 已落）：每颗体带一个**不参与寻址**的 `shift`
  （`(shuffle·2654435761 + bid·40503) & 0x7FFFFFFF`，再对体尺寸取模），物理键是
  `(逻辑格号 + shift) % size`。`--dismemory-shuffle N`（镜像 `shuffle=N`）只换 shift：
  逻辑格号、令牌、可观察量都不动。

### 2.4 判据（B）

* **M 表示不变性**：同一程序在 `shuffle=0/1/7` 下 stdout/stderr/退出码逐字节相同；
  随机 100 次摆法也同样（用固定种子，判据可复现）。
* **N 体内没有连续字节数组**（**S2 已落**）：分配 1 MiB 只写 2 字节时，体背后只有
  2 个格，体对象上没有可按下标寻址的 `data`；换摆法只改物理键、不改逻辑内容。
  至于"把格号当数做运算"，仍归 D 那一类（ptrtoint / inttoptr / 位运算 → F04）。
* **O 镜像同答**：参考与镜像在 `shuffle` 下同答；快照带上体映射与令牌表。
* **P 语义保留**：语料里所有合法程序（数组、结构体、alloc/free、字符串）在深度 3 下
  仍逐字节同答 —— 这是“换表示不是换语言”的证据。

### 2.5 快照（S4 的形状）

dismemory 的 guest 状态不在那 4 MiB 平坦区里，所以快照不能再照抄"整块内存"。
两侧共用一个 **flags = 3** 的布局（`none/cap/tag = 0/1/2` 不变）：

| 段 | 内容 |
|---|---|
| 头 + ctx + 全局表 | 同今天；全局那格从"地址"换成**令牌**（8 字节拆两格） |
| 对象表 | 同今天（dismemory 下 `sw_cap` 不共存，这一段实际上为空） |
| 续延栈 `CONT` | 同今天，但 `base/cfr` 填 0 |
| 帧令牌 | 每层一个 `(lo, hi)`：帧**本身**是一颗体 |
| 格表 | `count` + 每条 `体号 / 逻辑格号 / 字节` —— **只写非零格** |
| 令牌表 | `count` + 每条 `令牌 lo/hi / 体号 / 偏移` |
| 体表 | `count` + 每条 `体号 / 类别 / 尺寸 / 摆法 / 活否` |
| 计数器 | `next_bid`、`next_serial` |
| 扩展 | 同今天：phi 中途的待写回值（令牌是 64 位，原有 `u64` 字段够用） |

帧里的 SSA 值走**帧体自己的格**（写进 `FRAME_VALS` 区，和今天写进平坦帧同一套
偏移），于是"恢复后从同一条指令接着跑"这条语义不需要第二套名字表。

**不做**：退休令牌的墓碑表不进快照（恢复后它们按 F02 处理，报文只差"retired"
那句细节）；`sw_cap` / `sw_tag` 与 dismemory 互斥，flags=3 不组合。

**今天只主张同侧**：参考的帧是**体**，镜像的帧仍是密排区（`docs/368` §1.5 那一层
两边本来就不同，见 §2.3 末条）。所以 dismemory 快照**参考存 → 参考恢复 / 镜像存 →
镜像恢复**，并各自与一口气跑完同答；**参考的快照不能喂给镜像**。这一条写死在这里，
判定在 `lvm_twin_test` 的 `test_dismemory_checkpoint_matches_on_both_sides`。
镜像的 `sw_tag` 快照（`flags = 2`）同侧同理：对象标签 / 每帧值能力 / 影子表整段进
快照，悬垂在续跑后仍撞同一处（`test_sw_tag_checkpoint_keeps_the_tags`）。

## 3. 带类型指针入口（issue #2135 的优化形状）

原提案是每个 syscall 一族函数。优化成**两层**，ABI 面最小：

```rust
// 原语：只把一个槽声明为 ptr；lowering 不 ptrtoint，令牌直接进寄存器
syscall4p(nr: u64, a0: u64, p: ptr, a2: u64) -> i64
syscall6p(nr: u64, a0: u64, p: ptr, a2: u64, a3: u64, a4: u64) -> i64

// 一族包装（库/语法糖，不带新 ABI）
sys_write(fd, p: ptr, n) -> i64    // = syscall4p(1, fd, p, n)
sys_read(fd, p: ptr, n) -> i64     // = syscall4p(0, fd, p, n)
sys_openat(dirfd, p: ptr, flags)   // = syscall4p(257, dirfd, p, flags)
```

包装落在 `loment/lib/sysio.lomt`（`module sysio`）。**不叫 `sys`**：商店里已有
`os/0.1.0/sys.lomt`，同名会让"先搜哪一层"变成隐藏语义（`docs/143` §2.3 那条
mem/interp 是同一形状）。

`print` 走 `syscall4p(1, 1, p, n)`。运行期按 `nr` 解码令牌；非 dismemory 档照旧把
`ptr` 当普通地址（同一条 lowering，不分支）。

登记面（两套编译器、内建表、自举 checker/codegen、`BOUNDARY_BUILTINS`、文档、判据）
按“加一个内建”的六处登记做；**L0 单独一笔**，`lom/net.lom` 或内建表写清
“dismemory 下指针实参是令牌”，留一行下游影响。

判据：一份 dismemory 程序 `print(...)` + `exit`，`relocate=0/1/7` 下 stdout 逐字节
相同；同程序在普通 LVM 下仍按地址工作（两条路各自钉住）。

## 6. 双模拟声明（S5）

**观察代数 O**（`docs/371` §3.5 那一份，口径不改）：一次运行的
`(退出码, stdout 字节, stderr 字节)`；故障时再加 `(F0k, 函数:块#序号)`；
虚拟钟的读数；以及"从某个停点恢复后的继续运行"。

**命题**（本文实装的范围）：

1. 对 `choose lvm_dismemory_true` 下能通过检查的每个程序 P，任何表示层摆法
   `shuffle = N`（含 `N = 0`）给出的 O 相同。证据：`lvm_dismemory_test` 的 M
   （0/1/7 加 100 次固定种子随机摆法）与 N。
2. 同一份 P 在普通档与 dismemory 档的 O 相同（排除项见 `_P_EXCLUDED`）。
   证据：同文件的 P。
3. 参考与镜像在同一份 IR 上给出相同的 O —— 普通档、`sw_tag`、dismemory
   （含 `shuffle`）、以及**各自**的 checkpoint/resume。证据：`lvm_twin_test`。
4. 表示层换掉之后，**程序能看到的东西**里没有"体号/坐标/字节位移/摆法"这些量：
   故障详细块对重定位与摆法逐字节不变（K、M）。理由：它们只活在解释器内部，
   而所有 guest 可观察的出口都过 O。

**不主张**（与 §2.2、§4 的"不主张"合成一处，写死）：

* 不是"整数不存在"：格号仍是整数，仍是数组下标；
* 不是"参考与镜像的快照可以互换"：帧的表示两边不同（§2.5），只主张同侧续跑同答；
* 不是"时间在真硅上不可观察"：均匀延迟阵列仍是唯一办法；
* 不是"所有程序都能跑"：字节重解释、把令牌当数算的写法按设计 F04。

## 7. 性能账（S5，墙钟只报告不设门禁）

口径同 `docs/226` §2.2：**数字带形状、A/B 背靠背，秒数不进判据**。

夹具：一份 `store32/load32` 各 2000 次的循环（`alloc(256)` 一颗体，`use bytes`），
T0，Python 3.11，本机；同一份源只差一行 `choose lvm_dismemory_true`。

| 档 | 墙钟 | 说明 |
|---|---|---|
| 普通（`Mem`/bytearray） | 0.99 s | 基线 |
| dismemory `shuffle=0` | 3.27 s | 稀疏格 + 令牌，≈3.3× |
| dismemory `shuffle=7` | 3.68 s | 摆法只换哈希桶，量级不变 |

**探针纠出的一件事**：第一版在 2000 次循环上要 **57.6 s（59×）** —— 根因不在稀疏格，
而在摆法：`d_place` 每次都扫**这辈子造过的所有体**，而循环里每次函数调用都会
`alloca` 出体（帧也是体），于是 O(n²)。改成"只扫活体"之后回到 3.3×。镜像侧
（`d_overlap` 扫 `C_DNB` 行）同一个形状，同一次修掉（`C_DNL` + `LIVE_OFF`）。

这条不是判据，是一条**记账**：以后再加表示层的活，先拿这个夹具跑一遍 A/B，别让
"每次分配都要看全表"这种形状悄悄回来。
