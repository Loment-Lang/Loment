## 0. 它接上 `docs/359` 的哪几堵墙

| 墙 | 在原生档上 | 在 LVM 上 | 剩下什么 |
|---|---|---|---|
| **W1** 指令级标记 | 要反汇编 x86 | **消失**：IR 是固定格式，逐条可枚举 | 无（在 LVM 档内） |
| **W2** 完备边界 | 元数据三个位置都贵 | **变成成本**：对象表在软件里 | 每次访问多一次表查，未测 |
| **W3** 非概率对象代 | 本世代没有 | **变成成本**：代在对象表里 | 同上 |
| **W4** 语言级故障 | 只有信号 | **变成指令**：`fault(kind, site)` | 可恢复仍做不到 |
| **W5** 精确快照 | 微架构状态不可见 | **变成可行**：guest 状态就是全部状态 | 系统调用与外部输入 |
| **W6** 硅片不可核 | 公理 | **下移一层**：公理变成"CPU 正确执行解释器" | 公理仍在 |

**一句话读法**：LVM 把"本世代没有硬件"换成"本世代用软件实现同一套语义"。
它没有消灭 W6，它把 W6 变小了。

## 1. 先把"模拟"说准

"让 LVM 模拟下一代硬件"有三个层次，混在一起会说不清：

| 层 | 做什么 | 例子 | 本文 |
|---|---|---|---|
| **ISA 模拟** | 模拟另一颗 CPU 的指令编码 | QEMU | **不做** |
| **原语模拟** | 在本颗 CPU 上实现另一套语义 | 软件能力表、软件对象代 | **做** |
| **契约模拟** | 把"另一套语义"写成抽象机，两个实现都兑现 | 一台可移植的能力机 | **做** |

LVM 今天已经是第三层的雏形：它不吃自己的字节码，它吃 **`lomelf` 已经吃的那份 IR**
（`docs/243` §0："VM 只是它的第四个读者"）。同一份 IR，原生档给 CPU，LVM 给解释器。
这条"同一份输入、不同基质"就是桥梁的桥面。

## 2. 为什么是 LVM：四个既有事实

这一节只列已经在仓里、有判据的东西。

1. **同一份 IR 的第四个读者。** T0 吃的是 `lomelf` 支持的子集（`docs/243` §1）。
   这条性质有现成的地基。W1 在 LVM 档内没有墙。
2. **四档已存在。** T0 解释、T1 剖面、T2 基线编译、T3 守卫特化 + 去优化
   （`docs/243` / `247` / `259` / `261`）。四档都是同一份 IR 的执行者。
3. **跨产物同答已有判据。** 原生 / T0 / T2 / T3 四份产物在 LMS 语料上
   **`rc + stdout` 逐字节相同**，`llvm.trap` 在 VM 里是 132 且报站点（`docs/264` §2 D）。
   这就是"同一程序、不同基质、同一答案"的第一条实测。
4. **VM 是显式状态机。** T2/T3 是槽机，每个值都在自己的槽里（`docs/261` §3）；
   T1 的剖面要求"同一份程序 + 同样输入 ⇒ 逐字节相同"（`docs/247` §4）。
   显式状态是 checkpoint 的前提（W5）。

所以桥梁的地基已经浇好一半。缺的两半是：**能力与代**（W2/W3），以及**封印里的基质剖面**。

## 3. 抽象机 LVM-A：六个原语进契约

### 3.1 状态

```rust
// 提案，未冻结；展示用 rust 围栏，理由见 CLAUDE.md
struct Vm {
  pc: Pc,
  slots: [Slot],            // 槽机：每个值一个槽
  frames: [Frame],
  heap: [u8],
  objtab: [Obj],            // base / limit / gen / perms
  captab: [Cap],            // cap -> (obj, off, width)
  sites: [Site],            // pc -> site_id（静态，不进运行期状态）
  journal: [Event],         // checkpoint 用；可为空
}

struct Obj { base: u64, limit: u64, gen: u32, perms: u8 }
struct Cap { obj: ObjId, off: u64, width: u8, perms: u8, gen: u32 }
```

**guest 状态就是全部状态。** 解释器自己的宿主栈是实现的细节，不是 guest 的状态。
这条性质是 W5 在 LVM 上成立的全部原因。

### 3.2 六个原语

```rust
fn site(pc: Pc) -> SiteId;                                        // P1
fn cap_check(cap: Cap, off: u64, width: u8) -> Result<(), Fault>; // P2
fn gen_check(cap: Cap, obj: ObjId) -> Result<(), Fault>;          // P3
fn fault(kind: FaultKind, site: SiteId, witness: u64) -> !;       // P4
fn checkpoint(vm: &Vm) -> Checkpoint;                             // P5
fn resume(vm: &mut Vm, cp: &Checkpoint);                          // P5
// P6 不是指令：它是 LVM-A 的模型本身（§6）
```

六条对应 `docs/359` §0 的 P1–P6。前四条是运行期指令，第五条是状态操作，
第六条是一份规范。

### 3.3 四种基质

| 基质 | P1 解码 | P2 边界 | P3 代 | P4 故障 | P5 快照 |
|---|---|---|---|---|---|
| **`sw_cap`** | IR 解码 | 对象表 + 能力表 | 对象表里的 `gen` | `fault()` | guest 状态序列化 |
| **`hw_cap`** | 固定解码 | CHERI 能力字 | 硬件代 + 撤销服务 | 硬件 trap | 硬件 checkpoint（未来） |
| **`sw_tag`** | IR 解码 | 能力表 | 4 位 tag 模拟 | `fault()` | guest 状态序列化 |
| **`hw_tag`** | 固定解码 | 能力表 | MTE（概率） | 硬件 trap | 未来 |

`sw_cap` 是本世代可交付的那一档。`hw_cap` 是下一代的目标。`sw_tag` / `hw_tag`
是中间态，声明要降级（`docs/320` §1.2 ⑧：MTE 是检测，不是保证）。

### 3.4 封印里的基质剖面

`docs/358` 的 Seal 加一个字段：

```rust
struct Substrate {
  profile: u8,          // sw_cap | hw_cap | sw_tag | hw_tag
  guarantees: [u16],    // 这一档真的兑现了哪几条原语
  assumptions: [u16],   // 这一档只当公理的哪几条
}
```

规则只有一条：**`guarantees` 里不许出现这一档没有的东西。**
本世代跑 `hw_cap` 的封印，验证器要么拒，要么把缺的原语移进 `assumptions` 并把
对应 `Law.verdict` 降成 `floored`。这就是"声明不随换代失效"的机械形态。

## 4. 逐堵墙

### W1 · 指令级标记 —— 消失

`docs/359` 的墙是"验证器怎么知道哪条指令是访存"。在 LVM 档内，IR 是固定格式，
每一条 `load` / `store` / `getelementptr` 都是可枚举的。验证器按 IR 逐条扫，
不需要反汇编器。

**剩下什么**：无。这是六堵墙里唯一一堵在 LVM 档内完全消失的。

### W2 · 完备边界 —— 变成成本

每次 `load` / `store` 前，软件做一次 `cap_check`：查能力表、比较 base/limit。
元数据住在对象表里，不在指针里，不在影子内存里，不在 tag 里。

**剩下什么**：每次访问多一次或几次表查。成本未测。
这一档的"完备"是有条件的：对象表必须覆盖所有可达内存；`ptr` 算术越界的路径必须被
`cap_check` 拒掉。`docs/253` §11.2 已经指出，`ptr_add` 之后是 g3 的规模，是一个**可数的数**。

### W3 · 非概率对象代 —— 变成成本

`free` 时把 `objtab[obj].gen` 加一；每次访问做 `gen_check`。
`docs/320` §5.3 已经给了三种载体的分工；LVM 选"对象表"这一种，因为它是无界的，
而槽表只覆盖有界槽。

**剩下什么**：对象表本身是状态，会被写坏。它必须在 guest 不可达的区域，或者被
`cap_check` 保护。这是 `docs/253` §11.2 那条"有状态的东西可以被写坏"的直接后果，
要单独一条判据钉住（B2）。

### W4 · 语言级故障 —— 变成指令

`fault(kind, site, witness)` 是一条同步操作。今天的 VM 已经有一条同形的：
`llvm.trap` 在 T0/T2/T3/紧凑形里都定成 132，并往 stderr 写
`lvm: llvm.trap at <函数>:<块>#<指令序号>`（`docs/263` §2.1）。

**剩下什么**：可恢复仍做不到。`docs/356` §11 第 5 条已经写死：第一期只做到
"定义退出 + 可读消息"。LVM 能把它做得更好的是**站点稳定**，因为站点是 IR 里的位置。

### W5 · 精确快照 —— 变成可行

guest 状态是显式的，所以快照就是序列化 `Vm`；恢复就是反序列化。
这是原生档做不到的：原生档的 cache/TLB/分支预测不是架构可见状态。

**剩下什么**：系统调用与外部输入。一个停在 `read` 上的 guest，恢复时要重放或阻塞。
`docs/247` §4 的确定性要求（同一程序 + 同样输入 ⇒ 逐字节相同）是这一档的前提；
外部输入必须进日志，或者快照只在纯计算阶段做。这条边界要写进封印的 `assumptions`。

### W6 · 硅片不可核 —— 下移一层

这是最深的一堵，LVM 不会让它消失。它换了一个位置：

| 档 | 公理 |
|---|---|
| 原生 | "这颗 CPU 正确实现了 x86-64/ARM64" |
| LVM | "这颗 CPU 正确执行了 LVM 解释器" |

第二条比第一条**小**，因为解释器是一个可读、可对拍、可形式化的程序；
x86-64 的出货硅片没有可核契约。它没有变成零，它变成了一层更薄的假设。

## 5. 时间桥梁的形状

### 5.1 同一份字节码 × N 个基质

```
             ┌──────────────┐
   IR / 站点表 ──►│  LVM-A 契约   │
             └──────┬───────┘
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
     sw_cap      sw_tag      hw_cap
    （本世代）   （中间态）   （下一代）
```

字节码哈希、站点表、封印里的 `laws` 全部不变。变的只有 `substrate.profile`
与 `guarantees`。这就是"时间桥梁"的准确形状：**换代不重编。**

### 5.2 成本（能引的引，没测的写没测）

| 项 | 数 | 出处 |
|---|---|---|
| T2 相对 T0（最重语料） | **6.1×**，且明确"不可移植" | `docs/259` §6 表；同页明写倍数只记账、不做门禁 |
| T2/T3 的语义与 T0 | `rc + stdout` 逐字节相同（LMS 语料） | `docs/264` §2 A/D |
| 软件 `cap_check` / `gen_check` 的成本 | **未测** | — |
| 解释器本身的体积 | **未测**；必须进预算（B8） | — |

**不给比值门禁**：`docs/226` 的教训是同一个量能测出 3.2× / 4.13× / 5.4×。
这里的数是量级锚点，不是判决。

### 5.3 迁移路径

| 阶段 | 基质 | 字节码 | 封印 |
|---|---|---|---|
| 今天 | `sw_cap` | 不变 | `substrate = sw_cap` |
| CHERI 到手 | `hw_cap` | **不变** | `substrate = hw_cap`，`guarantees` 多两条 |
| 未来 | `hw_cap` + 硬件 checkpoint | **不变** | 多 P5 |

"不变"这三个字要能被判据钉住：**同一份 IR，两种基质的字节码哈希相同**（B5）。

## 6. 信任链下移

`docs/358` 的信任基座是"产物 + 封印 + 验证器 + 种子哈希"。LVM 档把它变成四层：

| 层 | 是什么 | 多大 | 怎么核 |
|---|---|---|---|
| **1 字节码 + 封印** | IR + 站点表 + laws | 产物大小 | `docs/358` 的验证器 |
| **2 LVM-A 模型** | 一台小状态机的规范 | 一页可读完 | 形式模型 / 语义 oracle（`docs/349`） |
| **3 解释器** | `tools/lvm.py` 与 `loment/tools/lvm.lomt` | 未测 | 两套实现对拍（`lvm_twin_test`，`docs/264` A） |
| **4 宿主 ISA** | x86-64 / ARM64 | — | **公理**（W6） |

四层比一层长，但每一层都更小、更可核。这是"桥梁"的代价与收益：
**信任的层数变多，每层要信的东西变少。**

两条必须写死的边界：

1. **解释器进 TCB。** 它必须小到能被审，且两套实现不能共享代码路径（`docs/349` 的三方判据）。
   如果解释器膨胀到几十万行，这座桥只是把信任搬进一个更大的东西。
2. **解释器自己也要用安全档编。** 这是 dogfooding：LVM 跑在原生档上，
   它自己的越界与悬垂要靠 LMS/DSG 抓。`docs/356` §11.4 已经点明：
   让编译器自己用 DSG 档编，是 dogfooding，不是保证。

## 7. 判据（每条先红）

| # | 判据 | 先红的方式 |
|---|---|---|
| **B1** | 同一份 IR，原生 / T0 / T2 / T3 的 `rc + stdout` 逐字节相同（安全子集） | 已有 `docs/264` D；扩到本站点表的语料 |
| **B2** | `sw_cap` 抓住一次 use-after-free（F02 + site）；`sw_none` 抓不住 | 今天没有对象表 ⇒ 红 |
| **B3** | `sw_cap` 抓住动态下标越界（F01 + site）；原生档的同一条不抓 | `docs/356` §3.3 探针 (b) 就是它 |
| **B4** | 在循环中间 checkpoint、resume，输出逐字节相同 | 今天没有 checkpoint ⇒ 红 |
| **B5** | 同一份 IR 的 `sw_cap` 与 `hw_cap` 封印，字节码哈希相同 | 不同 ⇒ 换代要重编，桥断了 |
| **B6** | 在没有硬件的宿主上跑 `hw_cap` 封印 ⇒ 拒，或降级进 `assumptions` 并标 `floored` | 静默接受 ⇒ 声明造假 |
| **B7** | 两套解释器对同一故障给同一 code + site | 只有一套 ⇒ 空判据 |
| **B8** | 解释器的行数/字节数 ≤ 预算，且预算进封印 | 不标价 ⇒ 信任只是搬家 |

B5 是"时间桥梁"这条主张的唯一硬判据。它不成立，整篇就只是一台更慢的 VM。

## 8. 前史（先点名，再说话）

| 本文用到的 | 谁先做过 | 差在哪 |
|---|---|---|
| 用软件模拟能力机 | **CHERI 的 QEMU 模拟**、Morello 的模拟器 | 它们模拟**指令与寄存器**；本文模拟**抽象机语义** |
| 便携字节码 + 验证器 | **JVM**、**WebAssembly**、**eBPF** | 它们验类型/结构；内存安全由引擎或运行期兜住 |
| 软件边界与代 | **SoftBound/CETS**、**Fil-C**、ASan | 它们改 ABI 或插桩；本文把语义收进 VM |
| 同一程序多执行档同答 | 本仓 T0/T1/T2/T3（`docs/264` D） | 本文把它扩成"多**基质**同答" |
| 形式化小机器 | Sail（RISC-V）、CompCert 的中间语言 | 本文的机器只有六个原语 |
| 可移植的信任基座 | PCC、proof-carrying data | 本文把封印与站点表一起搬过代 |

**组合没有检索到现成物**：逐站点封印 + 基质剖面 + 软件能力/代 + 跨代同一字节码。
**没检索到 ≠ 没有**（`docs/356` §11.2 同一条）。

## 9. 我不主张

1. **不主张这是新 VM。** LVM 四档已经在仓里；本文加的是抽象机契约与基质剖面。
2. **不主张性能。** 解释器比原生慢；软件 `cap_check` 再往上加，未测。这座桥卖给
   可移植的保证，不卖给速度。
3. **不主张 W6 被解决。** 公理下移了一层，仍然在。
4. **不主张覆盖所有代码。** 原生档仍是默认；LVM 档是"要强声明"的那一档。
5. **不主张解释器一定小。** 它可能膨胀到无法审；那样这座桥就失败（B8）。
6. **不主张任意状态快照。** 系统调用与外部输入要进日志，或只在纯计算阶段快照（§4 W5）。
7. **不主张 `sw_tag` 是保证。** MTE 模拟是检测；声明必须降级（§3.3）。
8. **不主张今天就该做。** 它是 0.1.6 之后的方向；`docs/357` §8 的 W0–W3 先落。
