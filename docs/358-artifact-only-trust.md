# 358 · 只信产物：把 PANGU Ω 压成一个封印

> 状态: **激进提案**（2026-11-20）；Seal / verify / derive 的第一实现落在 `docs/363`
> 上游: `docs/357`（PANGU Ω 对账的三件增量）· `docs/253`（LMS 七级）· `docs/320`（权能时序）·
> `docs/356`（Dissigsegv / `fault_ladder`）· `docs/344`（LSPE 框架）· `docs/349`（语义 oracle）·
> `docs/270` §4（信任地板）· `docs/245`（`thread_spawn`）
> 基准: `origin/main` `a460b90e`（2026-11-20）
> 一句话: **一份产物的安全信任基座 = 二进制 + 封印 + 一个可数的小验证器 + 一个种子哈希。
> 编译器、源码、运行期、操作系统全部移到信任边界外。**

---

## 0. 它看起来完全不可能

把 PANGU Ω 的"宇宙"剥到只剩一条可核的句子，会得到五个断言。每一个都能单独杀死它：

| # | 断言 | 杀死它的那条链 |
|---|---|---|
| 1 | 编译器可以删掉，安全性照样可核 | **A 完备性**：验证器看不到源码，怎么知道没漏站点 |
| 2 | 子宇宙的安全声明由父 + 差量推出 | **B 组合性**：证明没有通用的组合规则 |
| 3 | 验证器可以验证自己 | **C 自证**：无限回退 |
| 4 | 没有运行期，也不段错误 | **D 零运行期**：故障通路本身要代码 |
| 5 | 宇宙可以递归创世 | **E 无界**：进程树无法静态枚举 |

本文做两件事：把五条链写死（§1），再逐条拿掉它们依赖的假设（§2）。
拿完之后剩下的是什么（§3–§4），以及怎么用一个七步演示证伪它（§5）。

**这不是 PANGU 的实现。** 它比 PANGU 激进，也比 PANGU 小（§6）。

## 1. 不可能性（先写死）

### A · 完备性链

1. 要声称"安全子集内没有漏检的访存"，验证器必须知道**所有**访存站点。
2. 验证器只读产物。
3. 站点表由编译器写入产物。
4. 编译器在信任边界外，一个恶意编译器可以不写某个站点。
5. ⇒ **只读产物 + 源码级完备，不可能。**

**这条链只有一处可以合法松动：把"完备"的定义换掉。**

> 完备性从「源码里的每个访存」改成「**产物里的每条访存指令**」。

验证器不核对源码。它核对机器码里的每一条访存与站点表的一一对应：

- 恶意编译器漏写一个站点 ⇒ 产物里多出一条**无主访存** ⇒ 验证器当场红；
- 编译器多写一个站点 ⇒ 站点表里多出一条**无主条目** ⇒ 同样红。

于是信任从"编译器没有漏"移到"**验证器会数产物**"。
这一步与 PCC 的原始动作同形（Necula 1996）：证明跟着代码走，校验器只查代码与证明的对应。

**代价**：需要一个**标记过的访存子集**。两种落法：

| 落法 | 验证器要做什么 | 大小 |
|---|---|---|
| 通用反汇编 | 独立识别所有访存编码 | 巨大，预算必爆 |
| **固定指令子集 + 站点节** | 按偏移核对固定指令模式，并独立扫描该子集 | 小 |

Loment 自己发射代码，所以第二种可行：`load8` / `store8` / 下标 GEP 降级成一组**稳定模式**，
站点节记录每条的偏移。验证器不需要懂 x86，只需要懂 Loment 自己那几种模式。

⚠ **还有一个更硬的问题：谁来认定"哪些指令是访存"？** 如果由编译器标记，
恶意编译器可以不标，A 链原样杀回来。所以验证器必须**独立解码**：

- **LVM 字节码**上这很便宜 —— load/store 是固定操作码，逐条扫就能枚举；
- **x86 机器码**上这需要一个反汇编器，预算会爆。

⇒ 第一版演示把 **LVM 字节码当作 claim 载体**；原生 ELF 只带一条较弱的 claim
（`docs/356` 那套逐站点台账，验证器按站点节核对，不主张"没有未标记的访存"）。
这是把一个强声明放在解码成本低的那一档上；代价写进了上一段的二选一。

⚠ **前提：降级必须固定。** 走 `lomelf` 时降级在仓内、可复现；走 clang 时
同一份源的字节随本机 LLVM 版本变（`docs/275`：clang 版本不同，逐字节比是假红机；
`docs/192` §3 同一条）。所以第一版演示钉 `lomelf` / LVM，不钉 clang。

### B · 组合性链

1. "父 + 差量 ⇒ 子宇宙的声明"要求证明可组合。
2. 跨进程、跨堆、跨权能的证明没有通用组合规则。
3. ⇒ **任意子宇宙的证明传递，不可能。**

**松动点：把创世限制成"同产物派生"。**

子与父是**同一份 artifact**，差量只有 `(caps, budget, depth)`。
代码、证明、站点表全部共享；权能收缩是单调的。这条定理写得出来（§4 T1）。
跨产物创世需要链接级的组合证明，本文**明确关掉**，并写进封印的 `genesis.mode = same_artifact`。

### C · 自证链

1. 验证器验证自己 ⇒ 要么无限回退，要么在某处假设。
2. ⇒ **强自证，不可能。**

**松动点：把假设量化。**

封印里写验证器的 `id / version / bytes / sha256 / lines / max_bytes`。
信任从"某个验证器是对的"变成"**一个 N 行的东西是对的，N 印在产物里**"。
这就是 `docs/253` §8.2 "地板是可数的"往证明平面上的直接延伸。

一句话：**自证做不到，自证的假设可以标价。**

### D · 零运行期链

1. `no_runtime` 要求产物里没有运行期组件。
2. fault 通路需要代码。
3. 栈耗尽需要信号处理，信号处理是运行期。
4. ⇒ **完整 `no_segv` + `no_runtime`，不可能。**

**松动点：两格分开声明，各自说清范围。**

| 格 | 声明 | 允许什么 | 不允许什么 |
|---|---|---|---|
| `no_runtime` | 产物里没有运行期组件 | 一段**固定、只含 syscall** 的 fault stub（`docs/356` §5.3），大小与哈希进封印 | 影子表、收集器、信号处理器 |
| `no_segv` | 安全子集内的错误是语言事件 | 边界 / 悬垂 / 空指针 / 除零 / OOM / panic | **F04 栈耗尽**（要信号处理，归 `runtime` 档） |

这条链的教训与 `docs/270` §3.1 同形：**不可实现的句子要换成可实现的句子**，
并把换掉的代价写明白。

### E · 无界链

1. 宇宙可以创建宇宙 ⇒ 进程树无界。
2. 静态枚举不可能。
3. ⇒ **递归创世的完备检查，不可能。**

**松动点：递归有界，预算进封印。**

封印里写 `genesis { max_depth, max_children, max_total, mode }`。
"递归创世"落成一条**带预算的有限树**：超过预算就拒绝，不是"理论上可以无限"。
PANGU 的"宇宙生态"因此缩水成一个有限深度的派生树。这是它能被检查的唯一形态。

## 2. 合法拿掉的五条假设

`docs/210` §1 的判据：不要问概率，去问"不可能性证明的哪一条假设可以合法地删掉"。

| 假设 | 怎么拿掉 | 代价 |
|---|---|---|
| **编译器必须可信** | 信任移到产物 + 验证器 + 种子哈希 | 站点表进产物；验证器要能数产物 |
| **验证需要源码 / IR** | 只读产物 | 站点表必须与机器码一一对应 |
| **证明属于一次构建** | 证明内容寻址、同产物派生 | 跨产物创世关掉 |
| **宇宙 = 进程** | 宇宙 = `(产物, caps, 预算, 封印)` | 进程成为实现细节 |
| **递归无界** | 递归有界，三个数进封印 | 生态缩水成有限树 |

拿完之后，仍然剩下一条**不能拿掉**的：**种子与验证器本身**。
这条是 Thompson 的地板（`docs/270` §4）。本文的贡献是把它标价、印进产物，
减少到"一个哈希 + 一个 N 行的验证器"。

## 3. 定义

### 3.1 四个对象

```rust
// 提案，未冻结；展示用 rust 围栏，理由见 CLAUDE.md
struct Site {
  id: u32,
  kind: u8,       // "index" | "slice" | "raw" | "guard" | ...
  offset: u64,    // 产物里的指令偏移
  grade: u8,      // proven | checked | unsafe
  rule: u8,       // proven 必填，指向规则表 R1–R4
}

struct Seal {
  schema: u32,
  artifact: {
    format: u8,
    bytes: u64,
    sha256: [u8; 32],
    sites_offset: u64,
    site_count: u32,
  },
  laws: [Law],                  // 承诺 / 排除 / 证据根，形状同 docs/357 §4.1
  proofs: { root: u64, rules: u32 },
  verifier: {                   // ← 被标价的假设
    id: str,
    version: u32,
    bytes: u64,
    sha256: [u8; 32],
    lines: u32,
    max_bytes: u64,
  },
  genesis: {
    mode: u8,                   // 0 = same_artifact
    max_depth: u16,
    max_children: u16,
    max_total: u32,
  },
  floor: { seed_sha256: [u8; 32] },
  sum: [u8; 32],                // 对上面全部字段的规范序列化取哈希
}

struct Universe {
  artifact: [u8; 32],           // 根产物的哈希
  seal: Seal,                   // 根产物的封印（全部派生共享同一个对象）
  caps: CapSet,
  budget: Budget,               // heap / steps
  depth: u16,
  sum: [u8; 32],                // H(parent.sum ‖ canonical(delta))，根 = seal.sum
}

struct Delta {
  caps: CapSet,
  budget: Budget,
}
```

`Site.offset` 是这条设计的关键：**站点与指令的对应关系写进产物**，
验证器不需要源码，也不需要编译器。

**Seal 与 Universe 分开**：Seal 是产物级的静态事实（代码、站点、证明、验证器、地板），
同产物的全部派生共享它；Universe 是派生级的授权事实（权能、预算、深度）。
派生改变的是 Universe，不是 Seal。这条分界让 T1 与 T2 各自只证一件事。

### 3.2 两个操作

```rust
fn derive(parent: Universe, delta: Delta) -> Result<Universe, Why>;

fn verify(artifact: Bytes, seal: Seal, chain: [Universe], verifier: Bytes) -> Verdict;
```

`derive` 的五条规则：

| # | 规则 | 失败时 | 谁判 |
|---|---|---|---|
| G1 | `delta.caps ⊆ parent.caps` | `cap_escalation` | `derive` |
| G2 | `delta.budget ≤ parent.budget` | `budget_escalation` | `derive` |
| G3 | `parent.depth + 1 ≤ parent.seal.genesis.max_depth` | `depth_exceeded` | `derive` |
| G4 | 本层子数 `< max_children`；全树 `≤ max_total` | `tree_exceeded` | 本层 `derive` 判前者；后者要整棵树，归 `verify` |
| G5 | `child.sum = H(parent.sum ‖ canonical(delta))` | — | `derive` |

`verify` 的八条检查：

1. `verifier.sha256 == seal.verifier.sha256`，且 `verifier.bytes ≤ max_bytes`；
2. 站点节可解码，`count == site_count`，偏移严格递增且落在代码段内；
3. **标记子集里每一条访存指令恰好有一个站点条目**（A 链的落点）；
4. 每个站点 `grade` 合法；`proven` 必带 `rule`；`checked` 必带 fault 边；
5. ladder 恒等式（`gc_ladder` / `fault_ladder` 各一条）；
6. 每条 `Law` 的义务号在登记表里，`exclusions` 覆盖全部 `unsafe` 站点；
7. `genesis` 三个数与 `mode` 自洽；
8. 重算 `sum`，与封印里的字节逐字节同。

第 3 条是整份提案的生死线。它做不到，A 链就杀回来了。

## 4. 定理与边界

### T1 · 静态衰减

> 在声明子集内，若 `derive(parent, delta)` 成功，则一、子共享父的 Seal（律集合与排除集不变）；
> 二、子的预算不超过父的；三、子的权能面是父的子集。

证明是 G1–G3 的直接展开。注意它**只覆盖静态面**：子能碰到的东西变少了，
但"哪些 `unsafe` 站点在子的权能下真的到得了"是可达性问题，不在定理里（§9）。
律集合与排除集保持不变的读法是：**同代码、同证明、不同的授权面**。

### T2 · 派生确定性

> 同一 `parent.sum` 与同一 `delta` ⇒ 子的 `sum` 逐字节相同，整条 `chain` 也逐字节相同。

这条只要求 `canonical(delta)` 是确定的（字段顺序、整数编码固定），不要求整份构建可复现。
构建可复现是另一条判据（`docs/229` §3.2 的"默认产物逐字节相同"），本文不搭它的便车。

### T3 · 完备性相对产物

> `verify` 通过 ⇒ 产物里每一条安全子集访存都有判决。

它**不**保证源码里没有别的访存 —— 源码不在输入里。这正是 A 链换定义换来的东西：
一句更弱但可核的话，替换一句更强但不可核的话。

### 边界

| 在定理内 | 在定理外 |
|---|---|
| 同产物、同 artifact 哈希的子宇宙 | 跨产物创世 |
| 静态权能衰减 | 可达排除集 |
| 站点与指令的一一对应 | 源码级的"没有别的访存" |
| 声明子集 | FFI / `syscall*` / `load8` / `store8` |
| 站点节的完整性 | 物理攻击、被污染的种子、被污染的验证器 |

### 一条必须二选一的分界

E 链（零运行期）与 A 链（完备扫描）不能在同一份产物上同时拿满：

| 载体 | 强声明 | 弱声明 | 执行时信谁 |
|---|---|---|---|
| **LVM 字节码** | 完备：验证器独立解码每条访存 | — | LVM 引擎（一个被点名的假设） |
| **原生 ELF + `no_runtime`** | 没有运行期组件 | 完备只到**编译器标记的子集** | 谁也不信（除了 OS） |
| 两者都不覆盖 | — | 跨产物派生、FFI、物理层 | — |

一份产物只能选一格。硬把两格叠在一起，就会得到 `docs/253` §2F 那条闭合死链。
这是两条不可能性同时成立的直接后果，记在这里，不当缺陷修补。

## 5. 最小演示（七步，每步一条先红判据）

这是整份提案的可证伪形态。做不到这七步，本文就是散文。

| 步 | 动作 | 先红判据 |
|---|---|---|
| **1** | 写一个 `no_runtime` + `lms_full` + `lifetime_auto` 的小程序 | 今天的产物里**没有站点节** ⇒ 红 |
| **2** | 发射 **LVM 字节码** + 站点节 + 封印 | 今天的 `emit_potato` **没有封印** ⇒ 红 |
| **3** | 移走 `tools/` 与源码目录 | 今天的验证器**不存在** ⇒ 红 |
| **4** | 验证器从产物 + 封印重算判决 | 若它 import 编译器 ⇒ `ImportError` ⇒ 红 |
| **5** | `derive(parent, {caps ⊆, budget ≤})` ⇒ 子宇宙；验证子 | 今天 `thread_spawn` **无 capset** ⇒ 红 |
| **6** | 篡改：删一条站点 / 加一个权限 / 改一个 budget | 若不拒绝 ⇒ 封印是装饰 ⇒ 红 |
| **7** | 换一棵树 / 另一个会话的验证器实现，判决一致 | 只有一个实现 ⇒ 空判据 ⇒ 红 |

第 3 步与第 6 步是这套东西的全部。**删掉编译器还能验**是它跟"把安全押在编译器上"
那一类的分界；**改一个字节就红**是它跟"验证器只是装饰"那一类的分界。

### 演示的产物形态

```
hello.lvmb         # LVM 字节码（第一版演示的 claim 载体）
hello.seal         # 封印（sidecar，与 .lspe 同形）
hello.sites        # 站点节（也可以内嵌进自定义节）
verifier/          # 零 import 的小验证器；它的哈希在 hello.seal 里
```

`hello.seal` 是自足的：把它与 `hello.lvmb` 交给一个只相信 `verifier/` 的人，
他不需要源码、不需要工具链、不需要网络。原生档的对应物是 `hello.elf`，
它在同一套封印下只主张"标记子集完备"（§4 的二选一）。

## 6. 为什么它比 PANGU Ω 激进，也比它小

**更激进。** PANGU 让宇宙创造宇宙。本文让**编译器、源码、运行期、操作系统都不在信任边界内**。
前一句是一张层级图，后一句是一条外人可以动手核的断言。

今天没有一个已发布的语言把"删掉编译器之后的**完备内存安全声明**"做成产物的一部分：

| 系统 | 信任落在哪 |
|---|---|
| Rust | 编译器（借用检查器） |
| Java | JVM（verifier 能离开 javac 跑，内存安全由运行期兜住） |
| CHERI | 硬件 |
| WebAssembly | 宿主 + 验证器（只验类型/结构；内存安全由引擎的边界检查兜住） |
| **本文** | **一个哈希 + 一个可数的验证器**（原生档的声明不含运行期；完备扫描在 LVM 档） |

Java 与 Wasm 也能在没有编译器的情况下复查字节码，这一点要承认。
本文的差别在**信任基座被标了价**：验证器通过之后，原生档不需要任何运行期兜底，
LVM 档的引擎是一个被点名的假设，不是藏在基座里的一层（§4 那条二选一）。

**更小。** PANGU 七层、五大技术、P0–P6。本文只有四个对象（产物、封印、验证器、种子）、
两个操作（`verify`、`derive`）、五个数（验证器行数/字节、递归深度、子数、总数）。
判据能一条一条跑。

这就是"看起来不可能"的正确形状：**范围缩到最小，断言推到最硬。**
`docs/253` §8.1 说"拒，而不是退化"；本文把它用到信任边界上：**不退化成一个更大的信任基座，而是把基座标价。**

## 7. 前史（先点名，再说话）

| 本文用到的 | 谁先做过 | 差在哪 |
|---|---|---|
| 产物携带证明，小验证器复查 | **PCC**（Necula 1996）、Foundational PCC | 本文的证明是**逐站点台账**，不是逻辑公式 |
| 证明可沿计算组合 | **Proof-Carrying Data**（Chiesa–Tromer 2008 起） | 本文只组合同产物派生，不做通用 PCD |
| 子权能 ⊆ 父权能 | **Redell 1974**；seL4 CDT；Fuchsia handle rights | 本文把派生结果写进封印 |
| 信任地板可命名 | Thompson 1984；Diverse Double-Compiling（Wheeler 2005） | 本文给地板**标价**（验证器行数/字节进封印） |
| 二进制先验证后运行 | JVM bytecode verifier、Wasm validation | 它们验类型/结构，不验内存安全 |
| 逐站点判决进产物 | 本仓 `gc_ladder` / `lms_levels` / `lspe` / `fault_ladder` | 本文把四张账合成一个封印 |
| 签名清单 / 来源证明 | SLSA provenance、in-toto | 它们证明"谁构建的"，不证明"构建出来的东西安全" |

**组合没有检索到现成物**：逐站点台账 + 封印 + 零 import 验证器 + 同产物派生 +
标价的信任地板，五件同时出现在一个系统里。**没检索到 ≠ 没有**（`docs/356` §11.2 同一条）。

## 8. 判据（每条先红）

| # | 判据 | 证伪方式 |
|---|---|---|
| **C1** | 移走编译器与源码后，`verify` 给出同一判决 | 需要源码 ⇒ A 链未断 |
| **C2** | 验证器 `bytes ≤ max_bytes` 且 `lines` 进封印；改一行 ⇒ `sum` 变 | 不标价 ⇒ 信任只是搬家 |
| **C3** | 站点节与标记子集的访存**一一对应**：多一条 / 少一条都红 | 有漏 ⇒ 完备性是假的 |
| **C4** | `proven` 无规则引用 ⇒ 红 | 自由标签 ⇒ 证明是装饰 |
| **C5** | 子 capset ⊄ 父 ⇒ `derive` 拒 | 放行 ⇒ 衰减是假的 |
| **C6** | 超深度 / 超子数 / 超预算 ⇒ 拒 | 放行 ⇒ 无界链未断 |
| **C7** | 同父同差量 ⇒ 子的 `sum` 与 `chain` 逐字节同 | 不同 ⇒ 派生不确定 |
| **C8** | 第二个独立实现的验证器给同一判决 | 只有一个 ⇒ 空判据 |
| **C9** | 原生档 `no_runtime` 产物无运行期符号；fault stub 的哈希与封印一致 | 多一个符号 ⇒ 声明是假的 |
| **C10** | 篡改封印任意一个字节 ⇒ `sum` 不匹配 | 能改 ⇒ 封印无效 |

C2 与 C8 是这份提案最容易自欺的两条：C2 防止"验证器膨胀到没人能审"，
C8 防止"两个实现一起错"。`docs/349` 的三方判据在这里是必需的，不是可选的。

## 9. 我不主张

1. **不主张这是新理论。** PCC、PCD、CDT、DDC 都在前；本文是组合与标价（§7）。
2. **不主张源码级完备。** 完备性只到产物（T3）。这是换定义换来的，代价写在 §1A。
3. **不主张可达排除集。** 哪些 `unsafe` 站点在子权能下真的到得了，需要可达性分析，本文没做。
4. **不主张跨产物创世。** `mode = same_artifact`；跨产物的组合证明关掉。
5. **不主张任意运行期状态 fork。** 只对 `no_runtime` 或显式状态的 LVM 有意义
   （`docs/357` §3 的 I4）。
6. **不主张物理攻击、被污染的种子、被污染的验证器在定理内。** 它们是地板（§2 末）。
7. **不主张性能。** 站点节体积、验证器成本、标记降级的指令开销，全部未测。
8. **不主张验证器一定小。** 它可能撑爆 `max_bytes`。那样的话这份提案就失败，
   **预算是它的生死线**，不是它的修饰。
9. **不主张今天就该做。** 它是 0.1.6 之后的方向；W0–W3（`docs/357` §8）先落。
