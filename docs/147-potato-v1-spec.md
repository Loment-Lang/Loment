## 1. 与 v0 的差异

v0（docs/142）只覆盖标量/数组/struct/枚举/布局/能力域。P3/P4 之后语言多了
泛型单态化、切片、`str`、`()`、trait/impl、`guard` 审计站点 —— v1 把这些全部导出：

| 新增字段 | 来自 | 说明 |
|---|---|---|
| `generics` | `fn f<T>` / `struct S<T>` / `enum E<T>` | 泛型声明（单态化前的本单元视图，含预置 `Option`/`Result`） |
| `instances` | 单态化 | `{kind, name, of, args}` —— 哪个泛型以哪些实参被实例化（**名字怎么拼见 §2 命名层**） |
| `traits` | `trait T { fn m(self) -> R; }` | trait 及其方法名 |
| `impls` | `impl T for X` | 实现关系（方法名为 trait 中声明的名字，不含 `X_` 前缀混淆） |
| `guards` | `guard cap(idx)` | 本单元的审计站点数（A2 断言的输入） |
| 类型语法 | — | 签名类型新增 `[T]`、`mut [T]`、`str`、`ptr`、`()` |

`potato` 字段取 `"v0"`/`"v1"`。**v0 对象仍然合法**（回放，见 §5），但 v0 不允许 v1 字段。

## 2. 校验规则（规范性）

校验器仅凭对象本身判定，不读源码、不读二进制。规则分三层：

**结构层**：顶层字段白名单（按版本）；`unit`/`language`/`imports` 形态；
各表元素必须是对象、名字是标识符且表内唯一；`types` 与 `enums` 共用一个类型命名空间
（跨表同名 = 非法）。

**类型层**：合法类型 = 基类型 `{u8,u16,u32,u64,i8,i16,i32,i64,bool,str,ptr,()}` ∪ 已声明
`types`/`enums` 名 ∪ `[T; N]`（N>0）∪ `[T]` ∪ `mut [T]`（元素递归合法）。
`layouts` 字段只允许定宽整型，且 `offset + width ≤ size`、区间不重叠。

**语义层**：
- 能力域：`space` 标识符、`lo ≤ hi`、`lo ≥ 0`、`revocable` 布尔；
- 枚举载荷键必须是已声明变体，载荷类型必须已声明；
- `generics`：`kind ∈ {fn,type}`、参数非空且唯一、`(kind,name)` 唯一；
- `instances`：`of` 必须是同 `kind` 的已声明泛型、实参数量等于形参数量、实参是合法类型、实例名唯一；
- `traits`/`impls`：trait 名唯一、方法非空且唯一；`impl.trait` 必须是已声明 trait 或内建
  `Drop`（方法集 `{drop}`）；`impl.for` 必须是合法类型；impl 方法必须出现在 trait 声明中；
- `guards`：非负整数。

**命名层**（**生产者义务**，校验器不查 —— 理由见下）：

`instances[].name` 由**类型表达式**构造，规则是 **分隔的长度 = 嵌套深度**：

* `Base` 与它的实参之间放 **depth 个下划线**（最外层 1 个，往里每层 +1）；
* `,` 在同一层用**同长度**的分隔；类型表达式里的空格丢掉。

```
Box<u32>                 -> Box_u32
Outer<Inner<u32>>        -> Outer_Inner__u32
Outer<Inner, u32>        -> Outer_Inner_u32
Wrap<Outer<Inner<u32>>>  -> Wrap_Outer__Inner___u32
```

**规则存在的理由只有一个：不撞名。** `Outer<Inner<u32>>`（一个嵌套实参）与
`Outer<Inner, u32>`（两个实参）必须产出**不同**的名字 —— 1 个与 2 个下划线把它们分开。
（2026-09-23 之前没有这条规则，两边都按 `base + "_" + "_".join(args)` 拼，于是嵌套会拼出
`Outer_Inner<u32>`：`<` `>` 还在名字里，**不是标识符**，被校验器拒掉。那天同时给它定了规则、
两个实现一起改、并补了夹具 `loment/examples/nested_gen/main.lomt`。）

⚠ **校验器查不了这条**：对象里的 `args` 是**改过名之后**的形式（`["Inner_u32"]`），而名字里
嵌的是改名前那一段（`Inner__u32`）—— 从 `(kind, of, args)` 反推不出名字。所以它是**生产者的
义务**，由"两个实现逐字节相同"那条判据钉住（`loment_potato_emit_test` 的
`test_nested_instance_name_follows_the_rule` 另钉一遍**规则本身**），**不是**由校验器钉。

**哪些实参进得了这个名字。** 只有两种：**基类型名**（标识符）与**嵌套泛型**（递归）。
别的形状 —— `Box<[u8; 4]>` / `Box<[u32]>` / `Box<mut [u32]>` / `Box<*mut u8>` ——
**没有名字规则**：按上面的拼法它们会拼出 `Box_[u32]`，那不是标识符。

⚠ **但争命名之前先看这一步：真正的卡点在后面，不在名字上。** 后端 `native M23`
（**struct 字段暂只支持标量**）先把整族形状挡住了 —— **`Box<ptr>` 是最好的证据**：它的名字
完全没问题（`Box_ptr`），IR 那一步照样拒（`struct Box_ptr 字段类型 ptr 暂只支持标量`）。
而全树**零处**这么写（2026-09-23 实测：`grep` 命中的都是 `<<` 移位与注释）。

⇒ 现在的处置是**点名拒** —— 两个实现都给**有名字的拒绝**，不是内部错误（参考侧 2026-09-23
之前是"形式对象自检失败"那种崩：名字拼成 `Box_[u32]`、被它自己的校验器抓住）。
**要收它得先收 M23**（让 struct 字段支持非标量），然后才轮到照同一条思路延伸命名规则。

反例完备性由 `tools/potato_test.py` 的 33 条变异保证：规范里每一条规则至少有一条反例被拒。

## 3. 强制导出（M46）

`tools/lomentc.py` 的**任何**代码产出路径都必须同时产出形式对象：

1. `emit_potato()` 在返回前调用独立校验器 `potato.validate()`，有错即 `LomError`（编译失败）；
2. CLI 层：`--emit-rust` / `--emit-llvm` 必须同时给出 `--emit-potato`，否则退出码 2；
3. 仓库层：`lom_audit` 要求 `loment/examples/*.lomt` 每个示例都有一份**逐字节一致**的
   `loment/build/<name>.potato.json`，且该对象通过独立校验器。

三层都不可关闭 —— 没有"跳过导出"的开关。

## 4. 形式对象 → 内核断言绑定（M50）

`tools/potato_assert.py` 只消费形式对象，生成 `loment/build/cap_asserts.rs`
（Rust 静态表 + `assert_a1_a4()`）。绑定规则：

| 公理 | 形式对象侧判据 | 生成字段 |
|---|---|---|
| A1 无越权执行 | 能力域必须有名空间 + 有限区间 | `a1 = space 非空 && hi ≥ lo` |
| A2 可审计 | 每个 `guard` 站点必须落审计计数 | `a2 = guards ≥ 0`（编译器保证 guard ⇒ `__loment_guard` + 审计） |
| A3 模型缺席仍运行 | 单元不得申请模型/AI 能力空间 | `a3 = space ∉ {ai, model, llm, net_llm, infer}` |
| A4 失败计数与降级 | 可撤销能力必须声明 `revocable` | `a4 = revocable` |

当前产物：2 条能力断言（`demo` / `native_cap`），A1–A4 失败 0。**内核侧 `include!` 接入
归 P7（M39/M42）** —— 本阶段只保证"表由形式对象驱动且逐字节对账"。

## 5. 版本化与回放（M51）

- 对象自带版本号；校验器接受 `v0` … **`v22`**，未知版本 = 非法。
  **版本是"字段集合"的台阶，只往上加** —— 往旧版加必填字段会让既有对象全变非法，而旧版
  是**承诺过能回放**的（本节的最后一条），所以每加一个必填字段就升一版：

  | 版本 | 加的字段 | 出处 |
  |---|---|---|
  | `v0` | （基线） | `docs/142` |
  | `v1` | `generics` · `instances` · `traits` · `impls` · `guards` | §1 本文 |
  | `v2` | `mode` | `docs/178` |
  | `v3` | `switches` | `docs/182` §1 |
  | `v4` | `dialects` | `docs/184` §9 |
  | `v5` | `bodies` | `docs/185` §7 ① |
  | `v6` | `grammar` | `docs/188` §2 |
  | `v7` | `boundary` | `docs/205` R5 |
  | `v8` | `gc` | `docs/175` §3.4 |
  | `v9` | `runtime` | `docs/175` §3.6 |
  | `v10` | `gc_ladder` | `docs/210` §3 / §5 |
  | `v11` | `port` | `docs/222` §4 |
  | `v12` | `surfaces` | `docs/224` |
  | `v13` | `vm` | `docs/231` |
  | `v14` | `net_ladder` | `docs/237` |
  | `v15` | `lms` | `docs/253` §11.3 |
  | `v16` | `lspe` | `docs/262` §8 |
  | `v17` | `lms_levels` | `docs/253` §11.4 |
  | `v18` | `lms_budgets` | `docs/253` §11.2.1 |
  | `v19` | `gc_ladder.l0_5` | `docs/210` §2.10 |
  | `v20` | **`systems`**（六个系统的索引；读者从这里开始读） | `docs/304` |
  | `v21` | **`gc_control`**（`lgc` 的暂停/恢复/窗口计数 + `manual_collector`） | `docs/309` |
  | `v22` | **`lifetime`**（`lifetime_no` / `lifetime_auto` / `lifetime_manual`） | `docs/299` §8 |

  台阶是**累积**的：`v22` 要求它下面每一版的字段都在。

- **`gc`（v8）**：**回收档**之一 —— `gc_manual`（回收由程序显式做）、`gc_auto`
  （运行期负责回收）、或 `gc_auto_alpha`（**混合**档：静态内存管理 + 动态回收，
  不存在冻结全部业务的阶段，自适应、带策略池 —— `docs/175` §3.4.1；名字里的 `alpha`
  是**明说的**，用它的项目认这一点）。**与 `mode` 同级同形**：一个字符串取值、**必填**、只有根单元能定。
  于是"这个产物是在哪一档下编的"（以及它**有没有放弃「确定性」这条差异点**）是
  **不读源码可判**的 —— 这正是 `docs/175` §3.4 要的那一条。
  校验器还**独立判得了两档互斥**：`mode=no_std` 与 `gc=gc_auto` 同时出现即非法 ——
  两个取值都在对象里，不需要读源码。理由见 `docs/175` §3.4 ⚠：自动回收要一个运行期，
  而 `no_std` 的定义是「只能用核那一层」。

- **`runtime`（v9）**：**产物里有没有运行期** —— `runtime` 或 `no_runtime`（默认）。
  与 `mode` / `gc` 同级同形：一个字符串取值、**必填**、只有根单元能定，于是
  "这个产物带不带运行期"是**不读源码可判**的。
  取值**刻意只说"有没有"**，不说"里面装了什么"（今天装的是 `gc_auto` 要的收集器，
  明天可能是线程、宿主服务）—— 把内容钉进值名，两年后加能力就得回头改这一维的定义。
  校验器**独立判得了**的那一条：`runtime=no_runtime` 与 `gc=gc_auto`（含 alpha）
  同时出现即非法 —— 自动回收要的就是那个运行期，两者定义上矛盾。
  **`gc_manual` 不在这一条里**：`runtime` + `gc_manual`（"要运行期、但内存我自己管"）
  是合法档，不许拒。理由见 `docs/175` §3.6。

  **2026-10-10 起这一维是一句保证**（`docs/227`）—— 上面那句"不读源码可判"从
  **承诺**变成了**断言**：`no_runtime` 的产物里**一定没有**那段运行期，凡会把它拖进来的
  构造（`/` `%` `alloc` `free` `str_concat` `str_eq` `panic` `guard`）在**这一档下编译期拒**
  （E022）；`runtime` 反过来**强制**把那段带进产物。**字段形状一个字没动**（不升版、
  不加字段），变的是这句话的分量；`gc_manual` + `runtime` 那条合法档照旧。
- **`port`（v11）**：**产物通不通着世界** —— `sealed`（封闭，默认）或 `hosted`（对外）。
  与 `mode` / `gc` / `runtime` 同级同形：一个字符串取值、**必填**、只有根单元能定，
  于是"这份产物允不允许有对外端口"是**不读源码可判**的 —— 这正是 `docs/219` §7 那句
  "测量强于声明"在这一维的落法（不问"源码里写没写 `choose hosted`"，读对象里的那个值）。
  取值**刻意不带生态名**（今天是 libc/zlib，明天是 JVM/CPython）—— 与 `runtime` 同一条纪律。
  校验器**独立判得了**那两条：`port=hosted` 与 `mode=no_std`（`no_std` 说「底下没有
  东西」、`hosted` 说「往下链东西」，`docs/222` §4.2），以及 `port=hosted` 与
  `gc=gc_auto_alpha`（混合档的 L2 是分配器前沿回卷，而外部库把指针放进它自己的结构里，
  那些指针在 Loment 的栈之外 —— `docs/219` §6.1）。
  **`gc_manual` / `gc_auto` 不在这一条里**：`hosted` + 手动或自动回收
  （"要对外、但内存我自己管"）是合法档，不许拒。

- **`boundary`（v7）**：一份单元里越过语言保证的那些**调用点**有几个 —— 机调用
  （`syscall4`/`syscall6`/`syscall7`）、裸指针变换（`ptr_add`/`ptr_sub`/`str_ptr`）、以及调用本单元
  `extern fn` 声明过的名字。**口径是词法的**：只看"这个名字被调用了没有"，不判类型、
  不判危险 —— `docs/204` R5 那一格要的正是"可 grep、可计数、可审计"。
  形状是五个非负整数 `{extern_declared, extern_calls, syscalls, ptr_transforms,
  total_sites}`，其中 `total_sites` 必须等于后三项之和。**那一条是校验器独立判得了的**：
  它读不到源码，所以判不了"这几个数数得对不对"，但判得了"它们自相矛盾"。
  `loment stat` 报的是**同一组数**（那份由参考实现真正的词法器独立对过）。
  那份内建清单（`syscall4`/`syscall6`/`syscall7`/`ptr_add`/`ptr_sub`/`str_ptr`）住在
  `tools/potato.py` 的 `BOUNDARY_BUILTINS` —— 放在那儿是因为这个校验器按 M47
  **不许 import 编译器**，而"哪些内建越界"恰恰是审计要用的东西。

- **`surfaces`（v12）**：把 `boundary.syscalls` 数的那**同一批站点**按"面"分一分 ——
  `{面名: 站点数, …, total_sites}`，面名由用的人定（`file`/`mem`/`net`/`proc` 是本仓库的划法，
  `other` 是兜底：首参不是整数字面量的、或号不在表里的）。零计数的面不写出来（零站点写
  `{"total_sites": 0}`）。校验器独立判得了**两条**：各面之和等于 `total_sites`，
  而且 `total_sites` **等于 `boundary.syscalls`**（每个站点落在恰好一个面里 ⇒ 两处数的是
  同一批站点）。号 → 面那张表在 `tools/lomentc.py::SURFACE_NUMBERS`，它必须与 PE 运行时
  的派发表逐条相同（`loment_pe_test::test_pe_surface_table_matches_the_artifact_counter`）。
  全貌见 `docs/222`。

- **`v6` 曾经只有 `tools/potato_from.py` 在发**（那一档的产出方是"翻译出来的单元"）。
  主编译器是**加 `v7` 的时候才把 `grammar` 一起接上**的：台阶累积，而它此前一直发 `v5`，
  一升就撞上"缺 `grammar`"的**自检**。记一笔 —— 它说明"台阶累积"这件事本身有条判据守着：
  **漏接一版，编译器自己的自检当场就红**。

- `python tools/potato.py replay FILE...` 按对象自带版本回放校验，`--expect-version` 可断言版本；
- 冻结样本 `loment/build/legacy/demo.v0.json` 是 P5 之前编译器产出的真实 v0 对象，
  由 `potato_test` 持续回放 —— 旧对象不会因为新版本发布而失效。

## 6. 跨实现一致性（M53）

同一形式对象必须被两份独立实现判成同一个结果：

| 实现 | 位置 | 独立性 |
|---|---|---|
| FujoOS 侧 | `tools/potato.py` | 编译器自检也用它（但编译器只 import 它，反向禁止） |
| LinuxFUAI 侧 | `LinuxFUAI/tools/potato_verify.py` | 按本规范独立实现，不 import FujoOS 代码 |

`tools/potato_cross.py` 对**已提交对象 + 合法夹具 + 33 条反例变异**逐例对照，要求 100% 一致
（当前 50/50）。M47 另断言 `potato.py` 的 import 里不出现 `lomentc`。

## 7. 转写工具（M49）

`tools/potato_from.py` 把 Python（`ast`）/C（轻量解析）/Rust（轻量解析）源码转成形式对象，
并给出报告：

- 实体粒度 = 函数 / 类型 / 常量（**字段不计实体**，字段映射失败单独记入 `fields_skipped`，只影响保真度不影响分母）；
- `entities_seen` 只统计识别器**看见**的实体；`potato_measure.py` 另用宽松模式独立估计
  `entities_est`，两者之比 = **识别率**，暴露识别器自身的盲区；
- 两臂：`strict` 不猜测（映射不出就跳过）；`lenient` 按固定规则放宽（未知类型→`ptr`、
  Python 未标注→`i64`）。两臂都确定性、可复现，**不使用随机数**。

## 8. 波 C 测量协议（M54）

**语料**：`loment/corpus.json` 固定 12 个仓库真实文件（每语言 4 个）；每个文件的
sha256 前 16 位记入 `loment/build/wave-c-results.json`，测量与内容绑定、可复现。

**指标**（按语言 × 臂聚合）：

| 指标 | 定义 |
|---|---|
| 估计实体 | 宽松模式匹配到的候选实体数（独立于转写器） |
| 识别率 | 识别器看见的实体 / 估计实体 |
| 转换率 | 已转写实体 / 识别到的实体（**条件于识别**） |
| 95% CI | Wilson 区间，样本量 n = 识别到的实体数 |
| 对象合法率 | 通过独立校验器的对象数 / 文件数 |

**样本量**：当前 n = 48(Python) / 33(C) / 116(Rust)。Wilson 区间在 n<30 时明显偏宽，

读法与诚实边界：

- **Python 的瓶颈是注解质量，不是缺注解**：严格臂 27.1%，跳过主因是 `list[str]`/`dict`/`object`
  这类无 Potato 对应物的容器类型；宽松臂把它们降级为 `ptr` 后转换率 93.8%，但保真度下降
  （论文必须同时报两列，不能只报高的那个）。
- **C 的瓶颈是识别器**：识别率 89.2%，4 个多行/宏签名对正则不可见 —— 转换率 100% 是
  "条件于识别"的比率，必须与识别率一起读。
- **Rust 最好转**：静态类型 + 显式 `&[T]`/`mut [T]`，严格臂 91.2%；剩余跳过是
  `&'static [u8; N]`（N 为常量）、`!`、元组返回。
- **对象合法率 100%** 说明工具链臂不会产出非法对象 —— 它宁可少转也不乱转。

## 9. 未覆盖边界（诚实清单）

- **LLM 臂只用本地小模型**（§8）：A/B 的"宿主 LLM"那一侧是 `qwen3:4b` / `llama3.2:3b`，
  前沿模型那一格还是空的 —— 对照尚未成立，别当成"LLM 打不过工具链"的证据；
- **M50 只到产物层**：`cap_asserts.rs` 尚未被内核 `include!`，A1–A4 的运行时断言要等 P7；
- **转写器是结构识别，不是语义等价**：不保证转出的函数与原函数行为一致，只保证类型/签名结构；
- **Python 的容器类型无 Potato 对应物**：`list[T]`/`dict[K,V]`/类实例一律 strict 跳过；
- **C 的多行签名/宏不可见**：识别率上限受正则能力限制；
- **v1 不含 AI 能力空间语义**：A3 只检查"没申请 AI 空间"，不检查 AI 调用是否越界。
