# 308 · 域嵌套与域循环

> 状态: **设计稿；只实装了 `tick;`（显式虚拟钟），嵌套与环未实装**（2026-11-05 设计 / 2026-11-06 实装，见 §7）
> 上游: `docs/306` §6（域树 / 域图）· `docs/307`（语境类与转移）· `docs/246`（安全点）
> 一句话: **嵌套是"合取 + 寿命取交"，循环是"回边即 tick"。**
> 两者合起来才有完整语义：树的边决定成员关系，循环的边决定它什么时候过期。

---

## 0. 先把两个词拆开

用户说的"域循环"其实有两种东西，本文分开设计：

| 词 | 本文叫法 | 是什么 |
|---|---|---|
| 域嵌套 | **嵌套链** `C = [d₀ … dₙ]` | 域树上的父子关系，守卫时逐层判 |
| 域循环 ① | **驱动环** | 控制流里的回边，是时律续期的唯一驱动源 |
| 域循环 ② | **耦合环** | 域图里 `⇄` 边形成的环，续期必须原子 |

分开的理由：驱动环是"时间怎么走"，耦合环是"谁和谁一起走"。混成一个词，
实现时会在"循环里的 `⇄`"这一格上撞车。

## 1. 域嵌套

### 1.1 语义：嵌套就是合取

一条链 `d₀ ⊃ d₁ ⊃ … ⊃ dₙ`（`d₀` 是根，`dₙ` 是被守卫的叶子）：

```
guard dₙ(x) 通过 ⟺ ∧_{i=0..n} member(dᵢ, x)

member(d, x) = x ∈ P_d     当 π_d = allow
             = x ∉ P_d     当 π_d = deny
```

三个直接推论：

1. **语义可交换**：`∧` 与顺序无关，所以"父在前还是子在前"不改变通过集合。
   顺序只在**寿命**与**撤销**上有意义（§1.3、§1.5）。
2. **同一空间是前提**：`x` 要在每个 `dᵢ` 里都有意义，所以嵌套链只能在**一个空间**里。
   跨空间 → 不是链，是森林（§1.6）。
3. **祖先只判成员，不做转移**：转移（消耗）只发生在被点名的那个域上（§1.5）。

### 1.2 嵌套守卫是事务性的

```
guard dₙ(x):
  ① 全链求值 → bool
  ② 任一为假 → 拒绝；不改写任何域的 Γ
  ③ 全为真 → 只对 dₙ 施加转移（消耗 / 审计）
```

这保住了 `docs/307` 那条"失败的 guard 不改写 Γ"，并且**穿过整条链**：
中间某层拒绝时，叶子不会被扣一次。

**唯一例外**：危险域的闭锁。拒绝会改写危险域自己的状态（只增不减的封存）。
这条要写进语义：

> 拒绝不改写语境；唯一允许的状态变化是危险域闭锁，它单调、不可逆、只能由工具域复位。

### 1.3 寿命包含（C1 的时间版）

`docs/306` §6.1 的 C1 是空间上的封顶：`child ⊆ parent`。嵌套之后要补一条时间上的：

```
life(I_{dₙ}) = [t, min( next_renewal(dₙ), min_{a ∈ ancestors} next_renewal(a) ))
```

> **C1t：子域实例的有效期 ⊆ 每一层祖先实例的有效期。**

三个后果：

1. **祖先续期会截断子域**——即使子域自己的律还没到点，它的实例也当场结束。
2. **只守叶子就够**：祖先的续期通过 C1t 自动传导，不需要在每层各写一条 `guard`。
3. **陈旧守卫跨层触发**：`guard@k lane(id)` 在 `dma` 换段时也要抛陈旧实例，
   不只是 `lane` 自己的周期到了才抛。

### 1.4 极性合成：四格表

| 父 | 子 | 通过集合 | 读法 |
|---|---|---|---|
| allow | allow | `P ∩ C` | 细化（最常见的嵌套） |
| allow | deny | `P ∖ C` | **洞**：安全域里的禁区 |
| deny | allow | `C ∖ P` | 外黑内白？——见下 |
| deny | deny | `S ∖ (P ∪ C)` | 禁区取并 |

**一个必须讲清的负结果**：`deny` 父 + `allow` 子**做不出"禁区里的白岛"**。
它得到的是 `C ∖ P`，即"子域里、但不在禁区里"的那部分；要真正的白岛，
需要图上的减法边 `∖`（`docs/306` §6.2）或扩展域。嵌套只能做交与差。

### 1.5 消耗挂在哪一层

> **一次 guard 只消耗它点名的那个域。**

祖先只负责成员判定，不负责消耗。理由：否则守一次叶子会把整条链各扣一次，
"一次使用"就变成了"一次使用 n 次"。

反过来也成立：如果祖先自己声明了 `consumed`，**必须显式守它**才会扣：

```rust
guard lane(id);       // 成员检查走到 dma / ring / lane；只扣 lane
guard dma(id);        // 如果 dma 是 consumed(1)，这一句才扣它
```

所以嵌套省掉的是**成员检查**，不是消耗。

### 1.6 跨空间：森林，不是一棵树

包含关系只在同一空间里有意义（`x ∈ P` 要求 `x` 与 `P` 同型）。所以一个多空间程序有：

```
mem    ── heap
dev    ── dma ── ring ── lane
trace  ── win
auth   ── tok ── grant
quota  ── budget
```

**五个根，一片森林。** 跨空间只有三条合法的"腿"：

| 腿 | 是什么 | 例子 |
|---|---|---|
| 流向 `→` | 边的成员关系 | `move p -> id`（唯一允许两空间各取一个位置） |
| 委托 `→` | 能力转移，不转移位置 | `tok -> grant` |
| 联动 `⇄` | 续期同步，不涉及位置 | `budget ⇄ ring` |

除此之外任何"跨空间包含"都应当编译期拒绝。这条同时保护了 `docs/306` §7 的"跨空间禁止"。

### 1.7 多层守卫的成本与可折性

运行时逐层判是 O(链长)。可折的规则只有一条：

> **一般类（常量）祖先可以在编译期折掉；时类祖先不能。**

因为时类祖先的形状随 tick 变，折掉就把"祖先续期截断子域"这条 C1t 丢了。
所以运行期实际成本是 **O(链上时类祖先的个数)**，不是链长。

## 2. 域循环

### 2.1 驱动环：回边即 tick

```
每条循环回边 = 一个安全点 = 虚拟钟前进一次
```

这是 `docs/306` §4.2 虚拟钟的落地方式：**不引入定时器，时间由控制流推进**。
于是同一个回边同时驱动所有时律：

| 时律 | 在回边上发生什么 |
|---|---|
| 周期域 | `tick % P` 回绕 |
| 遥远域 | 段用尽 → 原点跳到段尾 → 新段 |
| 代域 | 到代边界 → 旧代整段翻成危险域 |
| 消耗域 | 已经按次扣，回边不额外扣 |
| 可达域 | 义务的 deadline `−1` |

**规则 L1**：循环体里若守卫了时类域，则**每条回边必须是 tick**。
否则该域在循环里永远不续期——"冻结的域"是静默错误，必须编译期拒。

### 2.2 守卫的循环不变性

守卫不是循环不变量，只有一种情况例外：

```
guard 是循环不变的 ⟺ 链上所有域都是一般类，且没有任何一层 consumed
否则                ⟺ 每轮一次，禁止 hoist / CSE / 跨分支重排
```

**规则 L2**：这是 `docs/307` §2 那条"不能 CSE/hoist"的正式表述。
判据要落在 IR 差分上：同一段源码，守卫必须仍在循环体内。

### 2.3 钉住实例：跨续期就炸

```rust
let g: u64 = generation_of(heap);   // 循环外钉住
while i < n {
    guard@g heap(p);                // 第 512 tick 换代 → 这里抛「陈旧实例」
    i = i + 1;                      // 回边 → tick
}
```

**规则 L3**：钉住守卫不因循环而失效，只在实例真的换了时失效。
这是特性不是缺陷：它抓的正是"拿着句柄跨了设备重置"。

### 2.4 义务跨轮：`reachable` 在循环里

一条 `reachable(k)` 义务如果活过一次回边，就叫**跨轮义务**：

```
跨轮义务成立 ⟺ 编译期能证：从守卫点到 discharge 的回边数 ≤ k
否则        ⟺ 拒绝（或要求显式降级 dynamic）
```

**规则 L4**：

- 循环上界 ≤ k → 静态可证；
- 上界未知 → 编译期拒，除非写 `dynamic`（登记运行期义务，到点 trap）；
- 某条路径在回边前没 discharge → 直接红（和 `docs/307` 的分支漏 discharge 同一条规则）。

### 2.5 耦合环：SCC 是续期单位

`⇄` 边可以成环。环里的域**必须同一 tick 原子续期**，否则"谁先谁后"会变成可观察行为。

**规则 L5**：

- 把 `⇄` 子图求强连通分量，**一个 SCC 就是一个续期单位**，同 tick 原子换实例；
- `≺`（时序）边必须无环——它在说"A 的实例在 B 之前"，成了环就是矛盾，编译期拒；
- SCC 里同时含 `≺` 与 `⇄` 且形成环 → 拒，不做隐式取舍。

### 2.6 循环不变量：能断言什么

每一轮结束时，全域状态是 `(tick, 每个域的实例号, 每个消耗域的计数)` 的函数。
可核的循环不变量只有三类，够用且便宜：

1. **实例单调**：同一域在回边上实例号不减；
2. **不跨代复用**：`guard@k` 的 `k` 在本轮没能续期时，本轮不得再通过；
3. **消耗有界**：任意 `N` 轮里，某消耗域的通过次数 ≤ `N × cap`。

这三条不需要新语法，作为诊断/判据输出即可。

## 3. 组合示例（把 §1、§2 叠起来）

```rust
// 树：dev 空间三层嵌套；auth 空间两层
domain dma  : root_of(dev)          // far：段尾 = 新原点
domain ring : child_of dma          // cyclic(1024)
domain lane : child_of ring         // consumed(1)
domain tok  : root_of(auth)
domain grant: child_of tok          // reachable(4)

fn pump(n: u64) -> u64 {
    let done: u64 = 0;
    let p: u64 = 0;
    let g: u64 = generation_of(heap);

    while done < n {                 // 回边 = tick（L1）
        let id: u64 = done % 16;

        // 只守叶子：dma / ring 的成员检查与续期由 C1t 隐式传导
        guard lane(id);              // 扣 lane；不扣 dma / ring

        // 若 dma 也声明了 consumed，才需要这一句
        // guard dma(id);

        guard@g heap(p);             // 跨代边界抛陈旧实例（L3）
        guard grant(id);             // 4 次回边内必须 submit（L4）

        fill(id, p);
        submit(id);                  // discharge

        done = done + 1;             // 本行所在回边推进虚拟钟
    }
    done
}
```

这段和上一版（`docs/307` 那段压力测试）的差别，就是嵌套设计买到的东西：

| 之前 | 之后 |
|---|---|
| `guard dma` / `guard ring` / `guard lane` 三条 | 一条 `guard lane` |
| 三层成员检查各写一次 | 链上自动判 |
| 祖先续期不传导 | C1t 自动截断子域实例 |
| 三条审计 | 一条审计 + 链摘要 |

## 4. 判据

| 判据 | 喂什么 | 期望 |
|---|---|---|
| 事务性 | 三层链，中间层拒绝 | 叶子不被扣，四计数全不变 |
| 极性四格 | `{allow,deny}² × 三个位置` | 与 §1.4 的表逐格一致 |
| 白岛反例 | deny 父 + allow 子，取"父内子内"的点 | **必须拒绝**（证明嵌套做不出白岛） |
| 寿命包含 | 父域提前续期 | 子域 `guard@k` 立刻抛陈旧实例 |
| 只扣叶子 | 三层链守一次 | 只有叶子的计数 +1 |
| 空间森林 | 跨空间写 `child_of` | 编译错误 |
| 流向例外 | `guard move p -> id` 跨空间 | 放行（唯一例外） |
| 回边 tick | 循环守时类域但回边不是安全点 | 编译错误（L1） |
| 禁止 hoist | 循环内守卫 | IR 差分里仍在循环体内（L2） |
| 跨轮义务 | 循环上界 > k | 编译错误，除非 `dynamic`（L4） |
| SCC 原子 | `⇄` 成环 | 同 tick 换实例，实例号一致（L5） |
| `≺` 成环 | `≺` 构成环 | 编译错误（L5） |
| 消耗有界 | N 轮回放 | 通过次数 ≤ N×cap |

**第一条红判据**：把"三层各守一次"改成"只守叶子"后，若中间层拒绝时叶子仍被扣，
就是事务性没实现——这条必须在未改代码上先红。

## 6. 开放问题

1. **tick 的粒度**：只认回边的话，一段没有循环的长直线代码会让时类域永远冻结。
   候选：(a) 回边 + 每次函数进/出；(b) 显式 `tick()`；(c) 每个基本块。
   我倾向 (a) + 显式 `tick()` 逃生舱——它把两次 tick 的间距绑在函数大小上，可判。
2. **嵌套深度上限**：链长影响诊断可读性与编译期展开。要不要硬上限（比如 8 层）？
3. **审计粒度**：只记叶子 + 链摘要，还是每层各记一条？后者能直接答"哪层拦的"，
   但会把条目数乘上链长。
4. **危险域闭锁与事务性的冲突**：拒绝本是"无副作用"，闭锁却是副作用。
   本文把它列为唯一例外；要不要连它也改成"只记录不改变状态"？
5. **跨空间的 `⇄`**：`budget ⇄ ring` 是合法的第三条腿，但它意味着两个空间的
   续期单位绑在一起——SCC 跨空间时，"原子"是按什么时钟算的？

## 7. 实装状态（2026-11-08 更新）

实装了三件：

1. **`tick;`**（§2.1 的显式虚拟钟）：`docs/306` §12 的时律判决读 `@__loment_now`，
   `tick;` 把它加一。
2. **回边自动 tick**（§2.1 的 L1，2026-11-08）：单元用了虚拟钟（有任何 `guard` /
   `tick;` / `domain`）时，`while` / `for` / `continue` 的每条回边都发一次
   `@__loment_tick`。不用域的单元一个字节不发。逃生舱：`choose domain_clock_explicit`
   回到"只有 `tick;` 推钟"。细节与判据在 `docs/315` §1–§2。
3. **`reachable(K)` 的 dynamic 档**（§2.4）：`guard` 登记义务（`now+K`），
   `discharge cap(x);` 结清；重复登记、过期结清、未登记结清都 trap。

**未实装**：守卫的循环不变性分析（L2 —— 今天守卫落在原地，不做 hoist，语义上已经满足）、
静态的跨轮义务证明（L4 的另一半）、SCC 原子续期（L5）、以及 `docs/306` §6 的
域树 / 域图 / 扩展域 / 工具域。嵌套链（§1）在**块**这一层已由 `docs/314` 落地；
`domain:for`（§2 的驱动环）在 `docs/315`。

另：`guard cap(x, aux);` 的第二个实参是 `docs/307` 语境类的参数（主体号 / 票号 /
目标节点），**不是**嵌套链——嵌套要等域树落地。
