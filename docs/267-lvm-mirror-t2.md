# 267 · 镜像的 T2 —— **同一套设计，用 Loment 写**

> 状态: **已落地**（2026-10-19，issue #586）· 上游: `docs/259`（参考实现的 T2）· `docs/243`（T0）
> 判据: `tools/lvm_mirror_t2_test.py`（5/5）· 实装: `loment/tools/lvm.lomt`
> 一句话: **会随货走的那份解释器**不再在执行期逐条重解操作数与类型 —— 解析完、全局落位之后
> 折成一张编译表，执行期只读表。

---

## 1. 为什么不是机器码

`docs/259` §7 已经写过：Loment 没有函数指针类型、没有间接调用（`docs/245` 的线 B 未开始），
所以把 x86 写进 `PROT_EXEC` 内存**跳不进去**。但镜像**不需要**机器码 —— 它在执行期付的
是**文本解码**的价钱，同一套"预解码 + 槽下标"用 Loment 就做得出来。

## 2. 表（arena 里追加的三张 + 两张小表）

| 表 | 一条记录 | 存什么 |
|---|---|---|
| `CC_OFF` | 12 × u32 | 每条指令：kind / sub / 目标槽 / 操作数区间 / 位宽 / 大小 / 附加池指针 |
| `COP_OFF` | 4 × u32 | 操作数描述符：`槽(号, 名字 span)` / `立即数(lo,hi)` / `零聚合(size)` / `全局地址` |
| `CX_OFF` | u32 池 | GEP 的每一步、phi 的 (前驱块, 操作数)、switch 的 (值, 块, 位宽) |
| `CSL_OFF` | 2 × u32 | 每个槽的名字 span（**错误消息要用**） |
| `FS2_OFF` | 4 × u32 | 每函数 `first_slot` / `nslots` |

**槽号是帧内下标（局部）**，名字表是全局的：`槽 = first_slot + 局部号`。帧里的值表
`VAL_REC` 还是 T0 那一份（名字 + 值），T2 只是**按号**访问它，不再线性 `vfind`。

**"写过没有"**：帧里加了一张 128 字节的位图（`FR_INIT`），T2 在函数入口把槽名铺进帧、
清位图；写一个值就置一位。读一个没写过的槽 → 与 T0 同一句话 `读未定义的值 <名字>`。
`FR_SLOTS` 因此从 16392 挪到 16520 —— **`alloca` 的地址整体 +128**。程序若把地址本身
打印出来会看到这个差；比较两个地址的程序不受影响。这是唯一一处可观察的布局变化。

## 3. 接受集合与 T0 对齐

编译是**整份程序**做的（不是懒编译），所以解不出来的指令**不能**在编译期就打死程序 ——
那会把不可达代码里的坏指令变成硬错误，而 T0 只在**执行到**它时才报（`docs/259` §4.4）。
所以解不出来的记成 `K_CERR`（码 + 原文 span），执行到才发：
`实参个数与形参不符` / `没有这个函数（extern 不接 FFI …）` / `只认直接调用…` /
`GEP 的这一步 T0 没实现:` / `这个指令 T0 没实现:`。**句子与 T0 逐字相同。**

## 4. 判据（`tools/lvm_mirror_t2_test.py`，5/5）

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | 原生 / 镜像 T0 / 镜像 T2 的 stdout + 退出码逐字节相同 | 9 份语料；两条路**同一个 argv[0]**（命令单元读 cmdline） |
| **B** | 剖面在镜像 T0/T2 下逐字节相同，且**非空** | `tour` / `switch`，114 行不是空文件 |
| **C** | 执行期解码次数：T0 **> 0**、T2 **= 0** | `tour` 实测 10,519 / **0**；反向一半也断言 |
| **D** | 镜像 T2 比镜像 T0 快（**只判符号**） | `lumtui_demo` 交替跑、`min of 3` |
| **E** | 孪生：参考实现（T0）与镜像 T2 的 stdout + 退出码 + 剖面逐字节相同 | `tour` / `user_hello` |

C 的计数器落在**解码函数本身**（`operand`/`ty_span`/`seg_*`/`ty_size`/`fld_*`/`gaddr`/
`fn_find`/`blk_of`/`vfind`），只在 `C_EXEC=1` 的那一段加。**编译期不算**（那时本来就该解）。

## 5. 数字（记账，不是判据）

同一进程交替、`min of 3`、本机：

| 程序 | 镜像 T0 | 镜像 T2 | 倍数 | 解码次数 T0 -> T2 |
|---|---:|---:|---:|---:|
| `tour` | 10 ms | **7 ms** | 1.29× | 10,519 -> **0** |
| `lumtui_demo` | 6357 ms | **1902 ms** | **3.34×** | 20,913,498 -> **0** |

（另一次测量里 `lumtui_demo` 是 5614 -> 1247 ms，4.53×；墙钟比值随机器与 WSL 状态散布，
**只有符号进判据**，倍数进 `docs/226`。）

## 6. 怎么选档

镜像的实参：`lvm IN.ll [PROFILE] [tier] [stats]`。

    lvm in.ll                  # T0（默认，行为与以前逐字节相同）
    lvm in.ll /tmp/p t2        # T2
    lvm in.ll /tmp/p t2 /tmp/s # T2，并把执行期解码次数写到 /tmp/s

**默认仍是 T0** —— 换引擎是显式的，与参考实现的 `--tier` 同一纪律。`stats` 只为判据存在，
不填就一个字节都不写。

## 7. 我不主张

1. **不主张 T2 打得过原生产物。** 它要打赢的是镜像的 T0；对原生仍慢两到三个数量级
   （`docs/226` §2.2）。
2. **不主张机器码那条路不用等。** 函数指针/间接调用（`docs/245` 线 B）没来之前，
   Sparkplug 形状的那一格仍然做不了 —— 这一页做的是**不需要它的那半**。
3. **不主张表不用容量。** 槽 32768、操作数池 131072、附加池 65536 是**按语料取余量**的；
   超了**点名报**（`T2 槽表满了` 等），不是静默写坏邻表。
4. **不主张它改变了 T0。** T0 的代码路径一行没动（只多了计数器的 `ctx_get` 与帧布局那
   128 字节）；默认档的行为逐字节不变。
