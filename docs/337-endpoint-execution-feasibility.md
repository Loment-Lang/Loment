# 337 · 末点运行可行性：构建期预初始化能做到“无程序级冷启动”

> 状态: **研究稿 + 实测**（2026-11-11）
> 基准: `origin/main`（`2d9215b2`，2026-11-11）。探针在
> `deliverables/endpoint-research/`；本检出的 `docs/` 落后，引用以 `origin/main` 为准。
> 实测环境: WSL2 Ubuntu / Ryzen 9 7945HX / Loment 参考链
> （`tools/loment.py ir` + `tools/lomelf.py`，默认 `tur2026.3`）。
> 上游: `docs/336-endpoint-execution.md`（设计草案）· `docs/210-loment-gc-design.md` ·
> `docs/225-loment-runtime-gaps.md` · `docs/229-lvm-base-and-novelty.md` ·
> `docs/262-lspe-safety-police-espace.md` · `docs/284-hot-update-remap.md` ·
> `docs/308-loment-domain-nesting-and-loops.md` · `docs/309-loment-gc-timing.md` ·
> `docs/315-loment-domain-loops-and-geometry.md` · `docs/298-lomentfaster.md`
> 一句话: **程序级冷启动可以消掉 —— 构建期把初始化后的 64 KiB 堆镜像写进 ELF，
> 实测把 6.24 ms 的初始化压到 ~1 µs，校验和与冷启动逐字节一致；
> OS 级进程地板（~241 µs）消不掉。**

---

## 0. 结论（三句话）

1. **能做的是 I-point（初始化末点），不是 S-point（循环稳态点）。**
   I-point 是“初始化已完成、工作负载还没开始”的那个点；它拷贝的是**精确状态**，
   所以正确性由构造保证，不需要商投影的忠实性证明。
   构建期预初始化（A 形）已经端到端跑通：冷启动 **8.04 ms/次** → 预置 **1.69 ms/次**
   （总时间 **4.8×**；启动到可工作 **~21×**），校验和 **475176** 两边完全相同。
2. **OS 级冷启动消不掉。** `execve` + 装载 + 映射 + 调度在这台机器上是
   **~241 µs**（最小 Loment ELF，2000 次平均）。快照不碰这一段；
   要把它也摊掉，只有 zygote / 预 fork 或常驻进程，不是快照。
3. **S-point 仍是另一条更难的线。** 整堆 49 KiB 哈希实测 **185 µs**
   （64 KiB 线性外推 ~245 µs），连续全堆监视对紧循环不划算；
   而“商投影是否忠实”仍未解决。`docs/336` 的循环稳态设想是 S-point；
   “让软件不再需要冷启动”是 I-point。本文把两者分开。

## 1. “冷启动”分解与可测基线

### 1.1 四层

| 层 | 内容 | 能否消掉 | 依据 |
|---|---|---|---|
| **OS 级** | `execve`、ELF 装载、段映射、首次缺页、调度 | **不能**（快照）；zygote / 常驻进程可摊掉重复请求 | 最小 ELF 实测 ~241 µs |
| **运行期级** | libc 初始化、TLS、构造器、JIT 预热 | Loment **没有**这些（无 libc、无 JIT、静态 ELF） | `docs/225` §0 |
| **程序级** | 全局初始化、配置解析、缓存/索引/表/模型构建 | **能**（A 形构建期预初始化；B 形运行期快照） | 本文 §5 |
| **预热级** | 分支预测、CPU 缓存、连接池、惰性加载 | 部分能，不是本文目标 | 不在本文范围 |

Loment 的剖面很特殊：它是**静态、非 PIE、无 libc、无 JIT** 的 ELF，
运行期层几乎是零，所以“冷启动”里真正可消掉的就是**程序级初始化**。
这也是为什么“无冷启动”在 Loment 上比在 JVM/Node 上更干净：没有 VM 预热来混淆账目。

### 1.2 基线（main 实测）

| 探针 | 内容 | 实测 |
|---|---|---|
| `hello.lomt` | 最小 ELF，只写一行、退出 | **240.7 µs/次**（2000 次）；另一次 200 次平均 264.6 µs（有负载） |
| `initprobe.lomt` | 填充 49 152 B，再扫 8 轮 | init **166–173 µs**；steady **1.37–1.41 ms** |
| `initheavy.lomt` | 200 万次 LCG + 稀疏写 49 152 B，再扫 8 轮 | init **6.28–6.54 ms**；steady **1.39–1.41 ms** |
| `hashprobe.lomt` | 49 152 B 的 FNV-1a，100 次 | **184–189 µs/次** |
| 冷启动总时间 | `initheavy` 端到端 | **8.04 ms/次**（200 次） |
| 预置总时间 | `preinit-patched` 端到端 | **1.69 ms/次**（200 次） |

**读法**：

- 程序级 init 的上限由 **64 KiB arena** 约束，但 init 的**计算量**不受约束：
  状态可以只有 49 KiB，初始化可以跑 200 万次甚至更多。
  这就是快照的价值：**状态有界，计算无界**。
- 轻初始化（166 µs）与整堆哈希（185 µs）同量级 ⇒ 对轻初始化做运行期快照**不划算**；
  重初始化（6.24 ms）⇒ 快照收益 **~30×**。断点约在 **200 µs**（§5.5）。
- 总时间 8.04 → 1.69 ms 是 **4.8×**；启动到可工作（总时间减稳态）是
  6.66 ms → 0.315 ms，约 **21×**。稳态越长，总时间的倍数越小；
  启动延迟的倍数不变。

## 2. 两种末点：I-point 与 S-point

### 2.1 定义

| | **I-point（初始化末点）** | **S-point（循环稳态点）** |
|---|---|---|
| 位置 | `init()` 返回后、`run()` 开始前（或顶层 `_start` 的初始化循环之后） | 循环进入稳态后的某个回边/循环头 |
| 拷贝什么 | **精确状态**：堆 + 分配器元数据 + 活动栈槽 + 继续点 | **商投影** `π(s)` + 一个代表状态 |
| 正确性 | **由构造保证**：状态逐字节相同 | 需要 `π` 对可观察行为忠实（未解决） |
| 适用 | 短命/初始化重/启动敏感的程序 | 长驻/循环形/需要稳态特化的程序 |
| 状态 | **已端到端验证**（§5） | **设计 + 模型**（`docs/336`） |

### 2.2 为什么先做 I-point

1. **没有商投影问题。** I-point 拷贝的是真实状态，不是“等价类”；恢复后的程序
   和冷启动走的是同一份状态，正确性不需要额外证明。
2. **收益可测且大。** §5 的重型初始化把 6.24 ms 压到 ~1 µs。
3. **和 Loment 的既有资产对齐。** 固定非 PIE 布局、64 KiB 堆、栈机、分配器偏移
   元数据，让“精确拷贝”比 CRIU 简单一个量级。
4. **S-point 的门槛没有被绕过。** 全堆哈希 185 µs、商投影忠实性未解，
   S-point 仍是研究线，不应与 I-point 混在一起承诺。

> 用户原始提案里的“算好最终执行点、把循环尾接回循环头”是 **S-point**；
> “让软件不再需要冷启动”是 **I-point**。两者可以共用一套产物/指纹/回退机制，
> 但**不能共用同一套正确性论证**。

## 3. 机器状态：到底要拷什么

### 3.1 ELF 布局（main 实测）

| 项 | 值 | 说明 |
|---|---|---|
| ELF 类型 | `ET_EXEC`（非 PIE） | `readelf -h`：Type EXEC，入口 `0x400000` |
| 文本段 | vaddr `0x400000` | 固定 |
| 数据段 | vaddr `0x800000`，`p_align=0x1000` | 固定 |
| 堆全局 | `@__loment_heap = [65536 x i8] zeroinitializer` | 64 KiB |
| 分配器元数据 | `@__loment_off: i32 = 8`；`@__loment_freehead: i32 = 0` | **偏移，不是指针** |
| 根表 | `gc_manual` 下**没有**；`gc_auto` 才有 `@__loment_roots` | v1 走 `gc_manual` / `no_gc` |
| 栈 | lomelf 是栈机：每个 SSA 值一个栈槽 | `_start` 只有 10 个 `alloca` |

**关键发现（实测踩到的）**：**堆基址不是常量**。
链接器把 `.bss` 全局放在 `DATA_VADDR + len(initialized data)`（`tools/lomelf.py` 的
`g.addr = DATA_VADDR + len(data)`），所以：

| 探针 | `.data` 大小 | 堆基址 | 第二个 `alloc` 返回（`buf`） |
|---|---|---|---|
| `addrprobe` | `0x30` | `0x800030` | `0x800060` |
| `preinit` / `initheavy` | `0x50` | `0x800050` | `0x800080` |

第一次打补丁按 `0x800060` 写，校验和是 **444176**，比冷启动少 31000；
偏移诊断发现正好差 **+32 字节**，改成 `0x800080` 后校验和回到 **475176**。
⇒ **快照/预置必须记录二进制自己的堆基址**，不能写死一个常量；
指纹里也要有 ELF 哈希（或堆基址 + `.data` 长度）。

### 3.2 状态清单

| 组件 | 进快照？ | 依据 |
|---|---|---|
| **堆** `[65536 x i8]` | **进** | 固定地址，但基址随 `.data` 长度变 |
| **分配器** `off` / `freehead` | **进** | 都是 i32 偏移；free list 不存指针 |
| **全局标量** | **进** | `.data` / `.bss` 里的模块级全局（今天语言没有模块级 `let`，但运行期/常量在） |
| **活动栈槽** | **进**（I-point 顶层/调用边界） | 栈机；`_start` 10 个槽；深栈要帧链 |
| **继续点** | **进** | 恢复标签/PC |
| **根表** | `gc_manual` 不进；`gc_auto` 要进并重定位 | `docs/225` §0 |
| **外部 fd/socket/句柄** | **不进**，只进指纹 | v1 `sealed`；`hosted` 要 `reacquire` |
| **真实时间 / RNG** | **不进** | `docs/309` §2.5：PE/内核上时钟还可能回 0 |
| **线程 / 锁** | **不进** | `docs/284` §8 单线程前提 |
| **LSPE 台账** | 编译期对象；如有运行期状态要进或拒 | `docs/262` |

### 3.3 堆里有没有指针

当前语言的三条事实让堆几乎是**无指针**的：

1. 结构体/枚举字段**装不了指针**（`docs/225` §3.1）；
2. `&` 只能作用于**数组**（得到 `u64`），不能对普通局部取地址
   （实测：`&x` 报“`&` 只能作用于数组”）；
3. `alloc` / `str_ptr` / 切片指向的是**固定段**（堆 `0x800000+`、数据段、文本段），
   不是栈。

所以对正常程序，堆快照是**纯字节拷贝**，恢复时不需要重定位。
**边界**：`&local_array` 会得到栈地址（u64），可以逐字节写进堆。
v1 用一条**保守守卫**兜住：在写快照前扫一遍堆，8 字节对齐的字只要落在
`[initial_rsp, current_rsp]` 就拒绝（误报只损失优化，不损正确性）。
模型里这条守卫已通过反例（§5.4）。

### 3.4 栈机为什么让恢复变简单

`lomelf` 的每个 SSA 值都在栈槽里，没有“寄存器文件”要捕获。
I-point 在**顶层 `_start` 帧**或**调用边界**时：

- 栈是一个帧，槽布局由编译器已知（IR 的 `alloca` 序列）；
- 恢复时按布局把槽写回新栈帧，设置 `rsp`/`rbp`，跳到继续标签；
- 深栈（S-point 在多层调用里）才需要帧链序列化；v1 直接拒绝，
  或要求把稳态循环放在顶层。

`docs/284` 的活帧重映射提供了帧布局哈希与调用点表；I-point 复用它的**布局描述**，
但不需要“改活帧”——恢复是新建进程，不是原地换镜像。

## 4. 四种“无冷启动”形状

| 形 | 是什么 | 适合 | 代价 | 状态 |
|---|---|---|---|---|
| **A · 构建期预初始化** | 构建时跑 init，把堆镜像写进 ELF 数据段；启动即稳态 | **确定性 init**（sealed、无外部输入） | 产物 +64 KiB；构建要跑 init；与二进制绑定 | **已端到端验证** |
| **B · 运行期快照** | 首次运行在 I-point 写 `.lomsnap`；后续启动指纹匹配则恢复 | **环境相关 init**（配置/文件/环境变量） | 哈希/校验 + I/O；指纹不匹配就冷启动 | 设计 + 模型 |
| **C · zygote / 预 fork** | 父进程持有初始化后的状态，每请求 `fork` | serverless / 短请求 | OS 相关；COW；不做序列化 | 未做；替代方案 |
| **D · 常驻进程** | 进程不退出，重复请求复用 | 长驻服务 | 首次/重启仍冷；不是语言特性 | 运维层 |

**选择规则**：

1. init **确定性** ⇒ A（最便宜、最快、无需运行期校验）。
2. init **依赖环境**，但环境稳定 ⇒ B（指纹 + 全有或全无）。
3. 请求**短且频繁**，进程可复用 ⇒ C（A/B 的补充；连 OS 地板一起摊掉）。
4. 长驻服务 ⇒ D；A/B 只影响首次启动。

## 5. 实测与端到端原型

### 5.1 探针

`deliverables/endpoint-research/`：

| 文件 | 作用 |
|---|---|
| `hello.lomt` | 最小 ELF 基线 |
| `initprobe.lomt` | 49 152 B 填充 + 8 轮扫描（轻 init） |
| `initheavy.lomt` | 200 万次 LCG + 稀疏写 + 8 轮扫描（重 init） |
| `preinit.lomt` | 同 `initheavy`，但**删掉 init 循环** |
| `hashprobe.lomt` | 49 152 B FNV-1a ×100（监视器成本） |
| `addrprobe.lomt` | 打印 `alloc` 返回地址（确认堆基址） |
| `patch_preinit.py` | 计算堆镜像、写进 ELF 数据段 |
| `snapshot_model.py` | 快照/恢复模型 + 负例 |

### 5.2 构建

```bash
# 在 origin/main 检出的根目录跑（loment.py 按 cwd 解析 lom/）
TREE=/path/to/origin/main
HERE=/path/to/Loment-DEV/deliverables/endpoint-research
cd "$TREE"
PYTHONUTF8=1 python tools/loment.py ir "$HERE/initheavy.lomt" > /tmp/initheavy.ll
PYTHONUTF8=1 python tools/lomelf.py /tmp/initheavy.ll -o /tmp/initheavy
PYTHONUTF8=1 python tools/loment.py ir "$HERE/preinit.lomt" > /tmp/preinit.ll
PYTHONUTF8=1 python tools/lomelf.py /tmp/preinit.ll -o /tmp/preinit
# 按实际 buf 地址打补丁（preinit 的 .data 是 0x50，buf 在 0x800080）
PYTHONUTF8=1 python "$HERE/patch_preinit.py" \
  --src /tmp/preinit --dst /tmp/preinit-patched --buf-vaddr 0x800080
```

> 探针用 `choose runtime`（main 的 `no_runtime` 会拒 `alloc`）。
> 产物是 Linux ELF，在 WSL 里跑；Windows PE 是另一条垫片，不在本文实测内。

### 5.3 结果

| 运行 | init | steady | checksum |
|---|---|---|---|
| `preinit`（无 init，空堆） | 0.9–3.0 µs | 1.52 ms | **0** |
| `preinit-patched`（构建期预置） | **~1 µs** | 1.37 ms | **475176** |
| `initheavy`（冷启动，运行期 init） | **6.24 ms** | 1.38 ms | **475176** |

（单次代表值；范围见 §1.2 的多轮表。）

**校验和相同** = 预置的堆镜像与冷启动初始化产生的堆**逐字节等价**
（`snapshot_model.py` 独立算出 475176，与两边一致）。

端到端 200 次平均：

| 二进制 | 每进程时间 |
|---|---|
| `hello-main`（地板） | 264.6 µs |
| `initheavy-main`（冷） | **8.04 ms** |
| `preinit-patched`（预置） | **1.69 ms** |

- 总时间：**4.8×**。
- 启动到可工作（总时间 − 稳态）：6.66 ms → **0.315 ms**，约 **21×**。
- 产物：同源 `preinit` **16 816 B → 86 104 B**（+69 288 B ≈ 64 KiB + 对齐）；
  冷 `initheavy` 是 **20 912 B**（多出 init 循环的文本）。

### 5.4 快照/恢复模型（`snapshot_model.py`）

| 项 | 结果 |
|---|---|
| 冷跑 / 恢复后校验和 | **115568 / 115568**（与真实 `initprobe` 一致） |
| 原始 blob | **65 734 B**（64 KiB 堆 + 10 个栈槽 + 头） |
| zlib（探针模式） | 726 B（真实堆压缩率会低；只作下界参考） |
| 篡改一个字节 | **拒绝**（校验和不匹配） |
| 指纹不匹配 | **拒绝** |
| 外部 fd | **拒绝**（v1 sealed-only） |
| 堆里混入栈地址 | **拒绝**（保守守卫） |

模型验证的是**状态代数与全有或全无规则**，不是编译器集成；
编译器的实际集成是 §10 的下一步。

### 5.5 断点

- 运行期快照的恢复成本 ≈ 整堆哈希（49 KiB **185 µs**；64 KiB 外推 ~245 µs）
  + 64 KiB 拷贝（`rep movsb`，~10 µs）≈ **200–250 µs**。
- 轻 init（166 µs）**不值得**；重 init（6.24 ms）**值得 ~30×**。
- A 形（嵌入 ELF）不需要运行期哈希：完整性由 ELF 的构建校验/签名承担，
  恢复只是映射 + 拷贝；代价是产物 +64 KiB。
- 因此：**确定性 init 优先 A；环境相关 init 才用 B，并接受 ~200 µs 的校验成本。**

## 6. 可行性矩阵

| 维度 | 可行？ | 机制 | 证据 / 边界 |
|---|---|---|---|
| **确定性 init** | **是** | A（构建期嵌入） | 端到端 475176；8.04 → 1.69 ms |
| **环境相关 init** | **条件** | B（运行期快照 + 指纹） | 模型；未端到端 |
| **外部 fd / socket** | **否（v1）** | 只进指纹；`hosted` 要 `reacquire` | 模型拒绝 |
| **深栈** | **否（v1）** | 要求调用边界/顶层循环；否则帧链序列化 | `docs/284` 有布局表；未做 |
| **`gc_auto` 根表** | **条件** | 进快照并重定位根地址 | 未测；v1 走 `gc_manual`/`no_gc` |
| **多线程** | **否** | 拒绝 | `docs/284` §8 单线程前提 |
| **跨编译器版本** | **否** | 指纹拒绝 | 模型 |
| **跨机器** | **条件** | 同 ABI/CPU/内核才可；否则拒绝 | 指纹 |
| **状态 > 64 KiB** | **否（今天）** | 需要改 arena；不在本文范围 | 64 KiB 上限 |
| **秘密进快照** | **条件** | 构建期不得快照秘密；运行期加密或拒绝 | 安全边界 |
| **PE / Windows** | **未测** | PE 垫片是 8-syscall；`clock_gettime` 可能缺 | `docs/309` §2.5 |
| **`no_runtime`** | **否** | `alloc` 需要 `choose runtime` | main 实测拒 |
| **`gc_manual`** | **是** | 无根表，纯字节拷贝 | 本文探针 |

## 7. 不可能性与边界（先写死）

1. **OS 级冷启动消不掉。** 快照不减少 `execve`/装载/调度；这台机器 ~241 µs。
   要摊掉它只有 zygote/常驻进程。
2. **一般程序的收敛/极限不可判定。** S-point 的商投影忠实性仍是开放问题；
   本文只把 I-point 做到端到端。
3. **跨版本/跨 ABI 快照必须拒绝。** 指纹不匹配就冷启动，不许“尽量兼容”。
4. **外部状态不可序列化。** fd、socket、真实时间、RNG、线程都不进快照。
5. **堆基址随 `.data` 长度变。** 不能写死；快照必须记录基址/ELF 哈希。
6. **`&local_array` 可把栈地址写进堆。** 类型系统不区分“整数”与“地址”；
   必须用保守的栈区间扫描守卫，或拒绝。
7. **整堆哈希 ~185 µs（49 KiB）。** 连续全堆监视对紧循环不划算；
   S-point 必须用**小投影**或采样。
8. **构建期 init 必须可复现。** 时钟/RNG/环境变量要在构建夹具里钉死；
   否则预置的镜像与冷启动不等价。
9. **快照会携带堆里的数据。** 如果 init 读了秘密，预置镜像就带着秘密；
   构建期必须知道这一点。

## 8. 与既有资产的关系

| 资产 | 关系 |
|---|---|
| **非 PIE / 固定 vaddr** | 堆/全局在同一地址；恢复可免重定位（栈除外） |
| **64 KiB arena** | 快照上界小；产物 +64 KiB，可嵌入 ELF |
| **栈机（每值一槽）** | 无寄存器文件；I-point 的帧可重建 |
| **`gc_ladder`**（`docs/210`） | 告诉快照哪些分配在 L0/L1/L2/L3；v1 只关心仍可达的堆面 |
| **`gc_manual` 无根表** | 纯字节拷贝；`gc_auto` 才要根表重定位 |
| **热更新安全点**（`docs/284`） | 帧布局/调用点表可复用；I-point 不需要改活帧 |
| **Potato**（v22） | `settle`/`preinit` 字段可进 v23；默认不写则产物不变 |
| **LSPE**（`docs/262`） | 预置/快照证书可作为 evidence；级别“已测”不是“已证” |
| **`lgc`**（`docs/309`） | 快照期间停收；真实时钟不进快照 |
| **LomentFaster**（`docs/298`） | 稳态特化是 S-point 的另一半；与 I-point 正交 |

## 10. 下一步

1. **把 I-point 写成语言/构建层的形状。**
   `init()` 返回 → `run(handle)` 的调用边界，或顶层 `_start` 的 `settle`。

## 11. 前史与我不主张

**先给结论**：`endpoint execution` / `last-point execution` **不是**既有术语
（检索不到标准用法）；但“末点运行”拆成七条线，每条都有几十年先例。

| 线 | 先例 | 时间 | 它做了什么 | 对应本文的 |
|---|---|---|---|---|
| **保存活状态并恢复** | Smalltalk-80 image | 1980 / 1983 | 整个对象内存（含栈/进程）写回 image，启动时从断点继续 | I-point |
| | Emacs `temacs` / `unexec` / `dump` | 1980s | 构建时跑 Lisp 初始化，把进程内存 dump 回可执行文件 | A（构建期预初始化） |
| | Condor checkpoint | 1988 | 用户级检查点 + 迁移；`setjmp`/`longjmp` + core | I-point |
| | DMTCP / CRIU / BLCR | ~2009–2013 | 用户态/内核态检查点恢复；容器 live migration | I-point（B） |
| | 正交持久化：PS-algol / Napier88 | 1981 / 1983 | 持久堆跨进程存活；持久性与类型无关 | I-point / D |
| **构建期预初始化** | Emacs dump | 1980s | 初始化一次，冻结进产物 | A |
| | V8 startup snapshot | 2015 | JS 内建/上下文快照进二进制 | A |
| | GraalVM Native Image | 2018 / 2019 | AOT + 堆快照；“Initialize Once, Start Fast” | A |
| | JVM CDS / AppCDS | 2004 / 2018 | 类元数据共享归档；启动少做类加载 | A（部分） |
| | Unikraft 预初始化快照 | 2019+ | 重 init 一次，恢复 <10 ms | A |
| **复用热进程** | Apache prefork / Chrome zygote / Android zygote | 1990s / 2008 | 父进程预加载，`fork` 出子进程（COW） | C |
| | AWS Lambda SnapStart | 2022 | Firecracker microVM 快照，恢复即热 | C / B |
| **稳态执行 / 跳过序言** | 软件流水（Lam 1988；Rau 1994 modulo scheduling） | 1988 / 1994 | prologue → kernel（稳态）→ epilogue；直接进稳态 | S-point / S3 |
| | 同步数据流稳态调度（Lee & Messerschmitt 1987） | 1987 | 静态周期调度；initial vs steady-state epoch | S-point |
| **算循环闭包 / 极限** | 循环加速（Finkel & Leroux 2002；Bozga et al. 2016） | 2002 / 2016 | 仿射/Presburger 循环的传递闭包 | “折叠 T^n” |
| | 抽象解释不动点（Cousot & Cousot 1977） | 1977 | 抽象域上的最小不动点 | 商投影 |
| | 自稳定（Dijkstra 1974） | 1974 | 从任意状态回到合法状态 | 收敛 |
| **复用/更新先前计算** | 自适应计算（Acar / Blelloch / Harper） | 2002–2013 | 依赖图 + 记忆化，只重算变化部分 | “运行时更新终点” |
| **推测 + 守卫 + 回退** | JIT 去优化（V8 / Truffle） | 2008+ | 猜一个不变式，失败回退 | 证书 + 回退 |
| | 翻译验证（Pnueli 1998）/ PCC（Necula & Lee 1996） | 1996 / 1998 | 证据随产物走，宿主验 | 证书是证据 |
| | 超优化（Massalin 1987；STOKE 2013） | 1987 / 2013 | 搜索更短指令序列 | 稳态体特化 |

**最接近的“完整先例”**（各覆盖一段，没有单一系统覆盖全部）：

- **Smalltalk image**：最接近“在活状态上继续跑”，但它快照整个 image，
  没有“稳态/循环”概念，也没有语言级证书。
- **Emacs dump / GraalVM Native Image / Unikraft 预初始化**：最接近“构建期预初始化、
  无程序级冷启动”，但它们预初始化的是整个运行时，不是本文的“小、固定布局、可审计”状态。
- **软件流水 / SDF 稳态调度**：最接近“稳态执行”，但它是编译期调度变换，
  不是运行期状态快照。
- **循环加速**：最接近“算 T^n”，但只对受限仿射/Presburger 循环可判定；
  一般堆/数组不可判定。
- **Lambda SnapStart / CRIU**：最接近生产级“无冷启动”，但整进程/microVM，不是语言级。
- **Sista（2017）**：把优化后的代码存进快照以跳过 JIT 预热；与 S-point 的
  “稳态特化”最接近。

**没有一块砖是新的。** 本文的贡献是**包装方式**：把“初始化后的精确状态”做成
Loment 产物里一份**小、固定布局、可审计、可整体回退**的镜像，
并用 64 KiB 有界堆 + 非 PIE + 栈机把它压到可实现。

**我不主张**：

1. 不主张“无冷启动”是零成本。OS 地板 ~241 µs 仍在；zygote 才能摊掉重复请求。
2. 不主张 S-point 已解决。商投影忠实性仍是开放问题；本文只把 I-point 做到端到端。
3. 不主张跨版本/跨机器快照可用。指纹不匹配必须拒绝。
4. 不主张所有程序都有收益。一次性、轻初始化、长稳态的程序收益小；
   收益在**初始化重、启动敏感、短命/短请求**的程序上。
5. 不主张 PE/Windows 已验证。本文实测是 Linux ELF。
6. 不主张性能数字可外推。4.8×/21× 是这份 49 KiB/200 万次探针的数；
   换负载要重测。
