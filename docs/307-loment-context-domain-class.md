# 307 · Loment 能力域第三类：语境类（guard 从判定变成转移）

> 状态: **激进设计稿；消耗域已实装，其余四条未实装**（2026-11-05 设计 / 2026-11-06 实装，见 §12）
> 上游: `docs/306`（一般类 / 时类）· `docs/146`（现行 guard 语义）· `docs/206`（移动/借用子集）·
> `docs/208`（声明式不可观测）· `docs/262`（LSPE 的声明图）· `lom/fuai.lom`（`dom_bind` 0x8108）
> 一句话: **一般类的 guard 是判定，时类的 guard 是带钟的判定，语境类的 guard 是转移。**
> 第三类拆掉的假设是"一个域是位置的谓词"——成员关系变成 `(位置, 语境)`，而 guard 会**改写语境**。

---

## 0. 三类的位置

| | 域是什么 | guard 做什么 | 状态从哪来 |
|---|---|---|---|
| **一般类** | 一元谓词 `D(x)` | 判定（纯） | 编译期常量 |
| **时类** | 带钟的谓词 `D(x, t)` | 判定 + 读钟 | 钟自己走（安全点） |
| **语境类** | 关系 `D(x, Γ)` | **转移** `(ok, Γ') = δ(x, Γ)` | guard **自己改写** Γ |

一句话说清差别：

> **时类的钟不由 guard 推动；语境类的语境由 guard 推动。**

`docs/146` 的 guard 其实已经不是纯的（它写审计表），但审计表**不反过来影响判决**。
语境类第一次让"判过的次数"影响"下一次能不能判过"——这就是从谓词跨到自动机的那一步。

```
一般类：  D ⊆ S
时类：    D ⊆ S × T          t 由外部推进，δ 不改 t
语境类：  D ⊆ S × Γ          δ: (x, Γ) → {拒} ∪ {(通过, Γ')}
```

Γ 与时间无关。Γ 是**主体 / 用量 / 证据 / 边 / 续延**——五种域各取一个。

---

## 1. 主体域（subject）

**Γ = 当前主体 `s`**（一个不可伪造的令牌）。

```
guard c(s, x);        // 通过 ⟺ (s, x) ∈ D
```

拆掉的假设：**"一个程序只有一个隐含主体"**。

- 同一个位置，对不同主体判决不同 ⇒ 域不再是全局常量表，而是一张 `主体 × 位置` 的矩阵。
- 这直接对上 L0 已有的 `dom_bind`（0x8108，"bind current context (0=system)"）——
  **主体域就是 `dom_bind` 在 L1 的显式化**，不是新造的东西。
- 激进之处：现行 `capability` 是环境权威（ambient authority）：声明一次，全程序共享。
  主体域把"谁在问"变成一等参数，于是"同一句话在回调里比在顶层弱"第一次可以写出来。

**前提**：主体不可伪造。字符串/整数当身份一律不算——否则自己报一个 id 就提权了。
这条只能由 §2 的线性值提供。⇒ **主体域站在消耗域上。**

---

## 2. 消耗域（consumed）—— 第三类的基石

**Γ = 用量向量 `n`**（每个位置一个计数）。

```
guard c(x);           // 通过 ⟺ n[x] < cap(x)；通过后 n[x] += 1

capability fd   : proc[0..()] consumed(1)     // 一次性的
capability nonce: auth[0..()] consumed(1)
capability sess : chan[0..7]  consumed(4)     // 每个通道最多用 4 次
```

拆掉的假设：**"guard 判过之后，世界没有变"**。

- 能力第一次变质：它可以是**线性/仿射的**。一次性的 fd、nonce、会话类型、单次令牌，
  全都归这一条。
- 这是第三类里**唯一一条今天就能实装**的：纯编译器侧（一个计数数组），不需要任何 L0 原语。

**代价必须讲清**（这是它激进的地方，也是它贵的地方）：

| 影响 | 说明 |
|---|---|
| 不能 CSE | 两次 `guard c(x)` 不再等价于一次 |
| 不能提出循环 | 原先可以 hoist 出去的守卫，现在每次迭代都可能耗尽 |
| 不能跨分支重排 | 历史相关，动一下就变语义 |
| 静态可判性下降 | "字面量放行"只在**首次使用**成立；之后要有**用量分析**才判得动 |

⇒ 消耗域要真落地，必须借 `docs/206` 那套移动/借用（E006/E007/E012）的线性分析。
**它不是一条语法糖，它是把线性类型塞进了能力系统。**

**审计语义**（改 `docs/146` §2）：一个计数器不够了，要拆成四个：

```
attempts[c] / passes[c] / denials[c] / exhausted[c]
```

`passes[c] == Σ n[x]` 仍然是可核对的——旧断言 S2 不废，只是不再等于"调用次数"。

---

## 3. 见证域（witnessed）

**Γ = 出示的证据 `w`**（一个值，不是一段数据）。

```
guard c(x) with w;
```

拆掉的假设：**"能力是环境给的"**。

- 这是 object-capability 的核心主张：能力必须**作为参数出现**，不能靠"我在这个进程里"默认拥有。
- 语法上它只多了一个 `with`，语义上它把 guard 从"查表"变成"验票"。
- 有一批语言做了 capability 类型，但很少把**证据作为 guard 的第二个参数**并让类型系统保证它不可伪造。

**前提**：`w` 的类型必须是线性/仿射的（用完即废），否则就是可重放的字符串令牌。
⇒ **见证域也站在消耗域上**：`w` 的线性性就是 `consumed(1)`。

---

## 4. 流向域（flow）

**Γ = 一条边 `(src, dst)`**。成员不是位置，是**边**。

```
capability leak : flow[()..()] ;      // 形状是边集，不是区间
guard leak a -> b;                    // 通过 ⟺ (a,b) ∈ D
```

拆掉的假设：**"域是位置的一个集合"**。这里域变成**关系**。

- `docs/208` 当年想要"声明式不可观察 ⇒ 能证什么"，结论是那条落不到堆上、
  只能落在**信息流**上。流向域就是把它补上：**信息流控制成为能力层的东西**，
  而不是类型层的一个附加分析。
- 落地有现成地基：`docs/262` 的 LSPE 已经有声明图
  （`Evidence(Typed, capability d : buf[0..64], line 7)` 那种形状）。

**可判性**：只要流图是**声明出来的、有限的**，边的成员关系就是有限集上的查询，可判；
静态 IFC 可以在这张图上直接推，不需要求解器。

**代价**：IR 里域的形状要从"区间"变成"边集"，`guard` 的实参从 1 个变 2 个。
这是本文五条里**唯一改域的数据形状**的一条。

## 5. 可达域（reachable）——把不可能性写死

**Γ = 未来 `k` 步的续延**。

```
guard c(x) reachable(4);   // 通过 ⟺ 存在长度 ≤ 4 的合法续延把 x 用掉
```

拆掉的假设：**"成员关系由当下决定"**。

### 5.1 先说它为什么不可能

> 令 `k = ∞`，则 `guard c(x)` 通过 ⟺ 存在一条合法执行续延。
> 这件事归约到停机问题 ⇒ **不可判定**。

所以"无界可达域"不是一个还没实现的特性，它**不可能**是一个编译期特性。这条要写死。

### 5.2 再指出可以拿掉的假设

把 `k` 从"∞"降成**语法里必填的参数**，它就变成**有界模型检查**：

- 可判定；代价是 `k` 的指数（状态空间展开）。
- `k` 不可省略：**不写 `k` 就不是可达域**，编译器直接拒。这是刻意的设计——
  让"你要验多远的未来"成为程序员显式付的账。

### 5.3 它和消耗域是一对

```
消耗域：Γ = 过去用掉了什么        （往回看）
可达域：Γ = 将来还能怎么用        （往前看）
```

同一个 trace，一个向后读、一个向前读。这是第三类里最对称的一对，
也是它为什么该和消耗域同属一类、而不是时类：时类读的是钟，这两个读的是**程序的迹**。

**判据要带单调性**：`k` 增大 ⇒ 域只会更宽（可过的只会变多）。这条比单点判决更难伪造。

## 6. 五条之间的依赖（为什么基石是消耗域）

```
            消耗域（线性）
           ╱      │      ╲
      见证域    主体域    可达域
      （票）    （身份）   （续延）
                  │
              流向域（关系，独立但常与主体域同用）
```

- 见证域要"票不可伪造" → 线性；
- 主体域要"身份不可伪造" → 线性；
- 可达域要"续延" → 一个会消耗的自动机；
- 流向域不依赖线性，但它改的是域的数据形状，属于另一条轴。

所以第三类的实装顺序是强制的：**先消耗域，其余才有地基**。

## 7. 对既有断言的冲击（要逐条改）

| 断言 | 现行（`docs/146`） | 语境类之后 |
|---|---|---|
| S1 域内 | 通过 ⇒ idx ∈ [lo,hi] | 通过 ⇒ `(x, Γ) ∈ D`；转移后 Γ 合法 |
| S2 审计保真 | 审计数 = 通过次数 | 拆四个计数器；`passes == Σn` 仍可核 |
| S3 无副作用越界 | 失败只 trap | **保持**，并且要加强：失败的 guard **不得改写 Γ** |
| 静态字面量 | 编译期判越界 | 只在"首次使用 / 线性分析证明未耗"时成立 |
| 优化前提 | guard 可 CSE / hoist | **全部撤回**（消耗域、可达域都历史相关） |

第三行是这一类的定义性约束：**转移只在成功时发生**。失败即无操作。
否则"试一下"就会变成一种攻击面。

## 8. 判据

| 判据 | 喂什么 | 期望 |
|---|---|---|
| 主体矩阵 | 同一 `(x)` 对两个主体 | 判决不同，且审计按主体分开 |
| 主体伪造 | 自己构造一个 "subject id" | 编译期就没有入口（不是运行期拒） |
| 消耗边界 | `cap=1`，连用两次 | 第二次 trap；`exhausted` +1 |
| 失败无副作用 | 在耗尽后连续拒 100 次 | Γ 不变，重开一次后行为可复现 |
| 禁用 CSE | 循环里两次同守卫 | 不许被折成一次（IR 差分） |
| 见证重放 | 同一 `w` 用两次 | 第二次 trap（线性性） |
| 流向 | 未声明的边 / 声明的边 | 前者 trap，后者过 |
| 可达下界 | 构造 `k` 步内必死路的例子 | trap，且 `k+1` 时可能过（单调） |
| 可达单调 | `k` 从 1 涨到 8 | 通过集合单调不减 |
| 三类对拍 | 同一程序在一般类/时类下的旧行为 | 逐字节不变（不许回归） |

**第一条红判据**必须是"消耗域在未加计数前会放行第二次"——先红再修。

## 9. 落地阶梯

| 级 | 内容 | 改哪里 | L0 |
|---|---|---|---|
| C1 | **消耗域**（`consumed(n)` + 四计数器 + 禁用 CSE/hoist） | 编译器 + 线性分析 | 否 |
| C2 | **见证域**（`with w` + 线性票） | 借 `docs/206` | 否 |
| C3 | **主体域**（显式主体 + 包 `dom_bind`） | L1 门面 | 否（读已有 0x8108） |
| C4 | **流向域**（域形状 = 边集） | IR 数据形状 | 否（IR 内部） |
| C5 | **可达域**（有界模型检查） | 独立工具，不进日常编译 | 否 |

结论和 `docs/306` 一致：**这一整类也可以先全在语言侧落地，不动 L0。**
唯一的外部依赖是 C3 读 `dom_bind`、C4 接 `docs/262` 的声明图。

## 10. 诚实边界

| 条目 | 判断 |
|---|---|
| 主体域 | 能做；但"多主体"在没有多线程/多租户之前是空转，建议和线 B（`docs/246`）一起 |
| 消耗域 | **今天就能做**，是这一类唯一成熟的 |
| 见证域 | 能做，但取决于线性值做得够不够硬；半吊子的线性 = 可伪造的票 |
| 流向域 | 能做，代价在 IR；收益是把 `docs/208` 那条断掉的线接回来 |
| 可达域 | **是论文不是特性**；`k` 有界后能做，但只该进独立验证工具，不该进日常编译 |

**一句话**：五条里只有一条（消耗域）是工程，一条（可达域）是研究，
其余三条是"有地基但没需求"——所以这一类的正确姿势是**先把基石落下，其余写成规格等驱动程序**。

## 11. 开放问题

1. 消耗域的计数放哪：全局静态数组（简单、不可嵌套）还是随实例走（能做嵌套/递归）？
2. 主体域的主体是"域 id"还是"能力令牌"？前者对上 `dom_bind`，后者对上 object-capability——
   两者不能同时为真，要选一个当规范。
3. 见证域的 `w` 是类型系统的事还是能力系统的事？（我倾向能力系统：它就是 `consumed(1)` 的票。）
4. 可达域的 `k` 超了怎么办：编译期拒、运行期 trap、还是降级成"保守拒绝"？
5. 三类能不能混：`consumed` 的域再套 `far` 时律，是"每段重置计数"还是"整域共享计数"？
   （这是 `docs/306` 的 §6.3 扩展域该回答的，本文没答。）

## 12. 实装状态（2026-11-06）

**已实装：消耗域** `capability tok : auth[0..7] consumed(N)`。

- 判决在 `@__loment_guard2` 的 kind=7 分支：`bound && used[cap][idx-lo] < N`，
  放行后 `used` 加一；
- 每格一个计数器（`@__loment_used[16][64]`），所以域宽上限 64；
- **只扣被点名的域**（§1.5 那条规则落到实现上就是"一次 guard 只碰一个 cap 的计数"）；
- 审计与失败语义不变：失败不写审计、也不加计数。

**未实装**：主体域（要不可伪造主体）、见证域（要线性票）、流向域（要把域的形状从集合
变成边集）、可达域（有界模型检查）。这四条各自的前置条件见 §10。
