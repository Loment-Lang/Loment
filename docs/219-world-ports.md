# 219 · 世界端口：`U` 不是"未定义的"，是"通向世界的地址"

> 状态: **激进提案**（2026-10-09，第三版；前两版同日、被本文取代，理由见 §1）
> 输入: `docs/183` V1（静态 libc）· `docs/173` §5b（归档与固定点成员选择）· `docs/205:44`（C1）·
> `docs/208`（声明的不可观测）· `docs/210`（GC 四层梯）· `docs/188`（不猜，报错）
> 一句话: **一个产物有多纯，等于它到世界的端口数 —— 而这个数，链接器本来就在算，
> 只是它现在把这个数当错误杀掉。**
> **并且**：这个数只有在**每条边都有名字、且名字的另一端在我们手里**时才算数（§5）。

---

## 0. 一句话展开

链接结束时还剩着的未定义符号，**不是"缺"**，是**这份产物通向外部世界的全部地址**。

今天 [tools/lomelf.py:2443](tools/lomelf.py:2443) 在这里**死掉**：

```
xxx.o: 引用了未定义的符号 malloc —— 到链接结束都没人提供它 (第 2 阶段仍不链 libc, docs/173 §3)
```

改法不是"把这些符号补上"（那是第一版，见 §1），而是**换个问题**：
不问"这段机器码**做什么**"，改问"这份产物**能到哪**"。后者可判定，而且**今天已经在算** ——
[tools/lomelf.py:2375](tools/lomelf.py:2375) 那段"需求有两个来源：① 我们自己 `declare` 的外部符号；
② 直接给的 `.o` 里未定义的符号"，**那份需求集就是端口表**，只差一个分类、一个计数。

⇒ `docs/205:44` 那条"产物无未定义符号"的判据，**可以一个字不改**地变成：**端口表为空。**

**但"能到哪"是一个名字级的量，它管不了"名字背后做什么"。** 这是本文最该被攻击的地方，
§5.1 与 §11.2 把它写死，并用一条**设计规则**（而不是一句形容词）接住。

## 1. 前两版为什么不够（自我诊断）

**第一版（收编）** 换了**满足端口的方式**，没换"端口必须被满足"这条假设。于是每一块都能被指到名字：

| 第一版的机制 | 谁先做的 |
|---|---|
| GC 堆顶替 `malloc`，交给 C 库用 | **Boehm GC**（`REDIRECT_MALLOC`）· **Crystal**（`GC.malloc`） |
| 宿主运行时 + 把 libc 当租户托管 | **Unikraft**（`unikraft-lib-musl`）· **rump kernels** · **Drawbridge** |
| 不链系统 libc，自己当 libc | **Cosmopolitan** |
| 逐函数计数、写进构建元数据 | 只剩这一条 —— 而它**是一个会计装置，不是一种新能力** |

**第二版** 换对了问题（"能到哪"代替"做什么"），但**把"能到哪"直接当成了"碰什么"** ——
那是一步没证的跳跃。§5.1 说清它为什么**会崩**，§5.2 给出接住它的**两条充要条件**。

## 2. 更深的死链

- **A.** 要真的用上世界上的库（zlib / openssl / sqlite3 是 `.a`，见 `docs/183:87`）。
- **B.** 用了它们，就想知道**代价**：这份产物还是确定的吗？
- **C.** 要知道代价，就得知道**这些库碰了世界的什么**（时间、随机、环境、文件…）。
- **D.** 而库是**不透明的机器码** —— "碰了什么"是关于它**语义**的问题。
- **E.** 语义问题**不可判定**（停机问题的近亲）。
- **F.** ⇒ **「用世界的库」与「知道自己的确定性」不可兼得。**

这条链今天被当成公理。`docs/183` §3.1 的解法是"用 `choose` 开关**声明**"——
因为既然测不出来，就只能相信一个声明。**这就是退让的起点：测不出来，于是放宽。**

---

## 3. 被拿掉的那条假设：D 里的"语义"

D 假设"碰了什么"是一个**语义**问题。**严格说它不是我们要问的那个问题。**

我们要问的从来不是"这段码会不会读时间"——那是语义，不可判。
我们要问的是**"这份产物有没有一条经重定位可达的路径到 `time`"**。

**后者是可判定的，而且链接器已经在算它。** `docs/173` §5b 那格"归档 `.a`：`ar` 解析 +
**固定点成员选择**（✅ 2026-09-17）"就是这件事：收一个成员 → 它引用的未定义符号进需求集 →
重复到不动点（[tools/lomelf.py:2299](tools/lomelf.py:2299)）。

⇒ **D 断。不是靠更聪明的分析，是靠换了一个问题：**
从"这段码**做什么**"（不可判）换成"这份产物**能到哪**"（可判，且已在算）。

**代价是这一步把问题降级了**：答案从"行为"降级成"名字"。**这个降级是本文的全部风险** ——
§5.1 正面处理它，而不是绕过去。

## 4. 新名词：**世界端口表**（port table）

> **端口表 = 链接结束后仍然未闭合的符号集合，逐条带一个类别。**

- **极性**：**纯 = 空表。** `docs/205:44` 那条"`llvm-nm` 无 `U`"**就是零端口** ——
  判据**一字不改**，只是从"一个该禁止的状态"变成"一个该被**测量**的状态"。
- **来源**：**从字节读，不从声明读。** 谁都不能"承诺"自己的库是纯的。
- **类别**：

  | 类 | 例 | 在表上的处置 |
  |---|---|---|
  | **可闭合** | `memcpy` `malloc` `free` `errno` | 由收编面提供 ⇒ **从表上划掉**（§6） |
  | **世界** | `time` `getrandom` `getenv` `read` `write` | **留在表上** —— 它就是这份产物的世界面 |
  | **不可闭合** | `dlsym` `dlopen` `__libc_start_main` | **拒**（§5.1） |

- **家族**：与 `gc_ladder` 与 `boundary` **同族** —— 而这不是我贴上去的，`docs/210` §3 自己
  就把它们点成"同一条思路"："**把'每一层的份额'写进产物，于是 GC 的组成是一个不读源码可判的数**"，
  并点名 Potato（`docs/147`）与 `boundary.total_sites`（`docs/205` R5）。
  三张表三个问题：**内存怎么没的 / 越界几步走 / 世界在哪。**

### 4.1 这一步的概念动作：世界从**令牌**变成**清单**

最接近的祖先是 GHC/Haskell 的 `State# RealWorld`：`IO a = State# RealWorld -> (# State# RealWorld, a #)`
（Launchbury & Peyton Jones，"Lazy Functional State Threads" 1994 / "State in Haskell" 1995）。
它保证的正是"世界只被用一次"——**但那个世界是一个没有结构、没有数的线性单例。**

**本文把它换成一个具名的端口表：世界第一次有了基数。**
一句"这个程序碰世界几次"从此是一个**不读源码可判的数**（§11.3 把这一条标为本文仅有的两处新颖面之一）。

## 5. 这个数什么时候算数：**两条充要条件**

### 5.1 先说它会崩在哪（这一节是本文最该被读的地方）

"链接器已经算得出来"**按字面是错的**，必须当场修：

- 链接器算的是**未定义符号的传递闭包** —— 一个**导入集**。它**不是**系统调用集，
  **也不是**语义意义上的纯度：`malloc` 会不会走 syscall 与**名字**无关；
  **内联 `syscall`**（x86-64 的 `0f 05`）在符号表里**根本没有名字**。
- **Sysfilter 那一族（RAID 2020 起）正是为此才去反汇编**：**名字不决定行为**
  （§11.1、§11.2 点名）。
- ⇒ 本文量与反汇编量**不是同一个数**。**宣称它们一样，就是本文会崩的地方。**

**接住它的不是一句话，是一条设计规则**（§5.2）。规则把"会崩"变成"被拒"。

### 5.2 规则：**每一条到世界的边，必须是一条有名字的边，且名字的另一端在我们手里**

两条条件，各自可验：

**条件一 —— 世界访问必须经名字。**

会"藏边"的有两类，两类都**毒化**（把该对象标成"最大不纯"），不静默：

- **按名解析**（`dlsym` / `dlopen` / 惰性绑定）：它把"到哪"变成**运行期才知道的字符串**。
  而按名解析**就是动态链接**。
- **内联 `syscall` / 裸 asm**：它在符号表里没有名字。处置是一趟**字节扫描**（`0f 05`）——
  廉价、可在安全方向上过近似（假阳性=把无害字节当 syscall，代价只是把一个对象判脏，可接受）。

**条件二 —— 名字的另一端在我们手里。**

这一条把"名字级"补成"行为级"：一个端口之所以能被**划掉**，不是因为它叫 `malloc`，
而是因为**那个 `malloc` 是我们写的**（§6）。
⇒ 收编面的覆盖面，**就是**这张表的可信度。**这不是两件事，是同一件事的两种说法。**

### 5.3 于是那条身份从"限制"翻成"价格"

> **完备 ⇔ 没有按名解析 ⇔ 没有动态链接。**

- `docs/183` §2 说三条二进制路线"**都要**"：静态 libc · **动态库装载（阶段 3）** · 运行期嵌入（阶段 4）。
- **本文说：阶段 3 与本文互斥，必须选一边。** 动态装载做的事，恰恰是**把边的另一端拿出去**。
  ⇒ 你买到了 `.so`，卖掉了**确定性证明**。
- 这不是"以后再说"。它是一条**要写进 `docs/173` 的取舍**；而且它把 Loment"无动态链接"
  这条看起来寒酸的设定，翻成新能力的**前提**。**身份不是限制，是价钱。**

**2026-10-17 兑现（`#406`）**：这条取舍不再是"要不要走"的假设，而是**两条并存的路**，
由用户逐产物选：

| 选哪条 | 拿到什么 | 卖掉什么 |
|---|---|---|
| **静态**（`lomelf` + 真 `.a`，`docs/183` V1） | §4 那张表**仍然完备**：产物里每一个通向世界的名字都在表上，端口数可在跑之前数出来 | 库的字节被搬进产物（体积、许可证、CVE 都跟着走） |
| **动态**（链接一个 `.so`，`docs/183` V2） | 用系统已有的库；产物里只有 `DT_NEEDED` 与 PLT | **按名解析的完备性**：真正的绑定在 loader 里发生，名字的另一端不在我们手里 |

**所以"完备"这句话从此要带条件说**：它是**静态那条路**的性质，不是 Loment 的性质。
两条路都在工具链里，选哪条是**用户的**决定 —— 这正是不把它写死在语言里的理由。

## 6. 于是"收编"不是方案，是一条**推论**

一旦有端口表 + §5.2 那两条，第一版那套东西自动落下来：

1. **可闭合**类 → 逐条提供（`memcpy` 一族照 C 标准与 LLVM `RuntimeLibcalls.def` 收；
   `malloc/free/realloc/calloc` → `@__loment_alloc`，[tools/lomentc.py:154](tools/lomentc.py:154)，它今天就在）。
2. `malloc` 那一类**从表上划掉** —— 它仍然是个未定义符号，但它**不再通向世界**，它通向我们的堆。
   **"划掉"这个动作，按 §5.2 条件二，只在实现是我们的时候才成立。**
3. **世界**类留在表上 → 它们**就是**这份产物具名的世界面，进 Potato（与 `gc_ladder` 同一格形状）；
   **而它们的实现也在收编面上**（我们写 `time`/`read` 的确定版本）—— 否则"世界"是被别人定义的。
4. **不可闭合**类 → 拒。

⇒ 第一版的"收编"是端口表算完之后自动落下来的形状，不是一条独立的策略。

### 6.1 推论之一：与 GC 的交点（这一条必须写下来）

收编把 C 库接到 Loment 的堆上，于是**碰了 GC 的边界**（`docs/210` 四层梯刚落地）：

- **堆要从静态 arena 变成"问 OS 要页"。** 今天是
  `@__loment_heap = internal global [65536 x i8]`（[tools/lomentc.py:276](tools/lomentc.py:276)），
  而 `docs/210` §2.1 明写 `gc_auto` 的上限是"触发 32 KiB / arena 64 KiB ⇒ 活集 ≳ 32 KB 必耗尽"。
- **`choose hosted` 与 `choose gc_auto_alpha` 必须互斥，点名拒。** L2（块纪元）是**前沿回卷**
  （`docs/210` §2.3），它买的是**栈纪律**（`docs/210` §4.4）；而 C 库把指针放进**它自己的结构**里
  （zlib 的 `z_stream`），那些指针在 Loment 的栈之外。前沿一回卷，C 还持有的指针就成了**悬垂**。
  拒法与 `docs/175` §3.4 那条 `no_std` + `gc_auto` **完全同形** —— 现成机制，不是新范式。

**这一条把 libc 从"FFI 的事"变成"GC 的事"**（判据 §8 C6）。

## 7. 从"开关"到"表"：声明换成测量

`docs/183` §3.1 把解禁方式设计成 `choose <二进制开关>`（默认禁，写了才开）。
**那是声明**：它要求你**保证**这份产物是纯的，而没有任何东西替你验。

有了端口表，默认档可以更强：**不是"开关必须关"，而是"表必须为空"** ——
并且**表是算出来的**，所以"我说它是纯的"这句话不再有意义。
**测量强于声明**；这一条顺手把 `docs/205` §0.2 那条"零沉默"纪律推广到外部代码。

## 8. 判据（每一条都能证伪）

| # | 主张 | 判据 |
|---|---|---|
| **C1** | 真库能跑 | `loment run` 调 **zlib** 的 `compress`/`uncompress`，解压回原文（**`docs/183:87` 的原文判据，一字不改**） |

| **S2** | **第一个真库** | 一个只用"可闭合 + 世界"两面的真库链进来并跑通 | §8 C1（zlib）—— `.rodata`/`.data` 那关已由 **S1f** 关掉 | **部分**（2026-10-11）：**真 zlib 链得进来**（15 个成员全读得进来；定点选出 deflate/inflate/trees/zutil/adler32/crc32/inffast）且 **`crc32` 算得对**（`crc32(0,"AAAA",4)` = `0x9b0d08f1`，与 CPython 逐位一致）。`compress` 还差三件，见下。**在发行版里这条路锁着**（2026-10-12，见下）。**2026-10-15**：**V1 的验收格在两侧都过了** —— 真 `libz.a`（16 个成员）经两个链接器各自**定点**挑出 10 个成员，产物**逐字节相同**，`compress → uncompress → 原文` rc=0；证伪件（比对方向写反）报 40。三件里原记的一条已不复现，真正拦住的是另外两条（局部符号、栈对齐），加上 arena 与自举侧读归档 —— 四条各带判据。**2026-10-17 齐了**：动态那一半（`#360`）落齐 —— 同一份程序**不链** `libz.a`、链系统 `libz.so`，产物里只有 `DT_NEEDED` + PLT/GOT，参考与自举两侧**逐字节相同**，`compress → uncompress → 原文` rc=0，四条失败模式都是命名错误；开闸（`#406`）同日落地（§8c）。 |
| **S3** | **开关 + 阶跃约束** | `choose` 官方开关（`docs/182` §C4）；`hosted` × GC 档互斥 | §8 C4 / C6 | 未开工 |

**S1a 的粒度是"有没有外部对象"，不是"有没有人要它"。** 精确到后者要链接器先算出需求集，
而自举侧 `lomelf.lomt` 一次只驻留一个外部对象 —— 那一格是 **S1b**。这**不影响测量**：
"这份产物到底要哪几个"始终是尺子（S0）的活，链接器发的是**超集**。

**S1c 的判据刻意不是"C 能 malloc 出东西"**（那太弱：另起一份分配器也成立），而是**地址同一** ——
只有 `free` 真接到我们的空闲链，第二次 `alloc` 才会命中同一个地址。C2 在文档里本来就带反面。

**S1e 落了 A，但**与那一格的原文有两处**有意的偏离**，记在这里免得以后拿行号对不上（`docs/228` §2/§3.1）：

1. **闸门是 `choose port hosted`，不是"所有程序"**。原文是"前沿从 64 KiB 静态数组换成 `brk`/`mmap`"，
   那会改**每一份**产物。但 `sealed` 承诺的正是"这份产物不依赖外面"，而一次分配器调用是**运行期**
   对外面的依赖 —— 给它加上就等于把那条定义改掉。于是 `sealed` 走原来那段文本，**逐字节不变**。
2. **要的是 `malloc`，不是 `brk`/`mmap`**。`hosted` 的产物本来就由 C 工具链链（`loment_hosted_test`
   链的是真的 `libz.so`），所以宿主分配器就是"OS 那一层"在这条路上的正确接口；raw syscall 反而要
   **多一张平台表**，与本文 §5 的记账面重复。原文那个形状是**未加闸门**那一版（`sealed` 没有宿主，
   只能自己发 syscall）。

**A 的判据是一对方向**（`docs/228` §5 A3）：同一份分配 200000 字节的程序，`hosted` 跑出 7，
`sealed` 必须死在 `lomentc.py:218` 那条 `boom` 上（SIGILL）。只判"`hosted` 能跑"会被
"把 `65536` 改大"骗过 —— 而那一改 `sealed` 那条保证就没了。

**B1 也已落地（`docs/230`）**：`hosted` + `gc_auto` 一起吃到平台那一块 —— 收集器**跟着换**
（标记表的行数本来就是 arena/8，所以换 arena 必须同时换表的口径与两处根扫边界）。
判据是**一源两档**且**两个方向**：同一份程序先要 200000 字节、再 churn 到触发收集器跑，
`hosted` 读回全对（7），去掉 `choose hosted` 的那一份死在 `boom` 上（SIGILL）。

**仍未做**：多段 / 无上限增长（偏移是 i32，多段 = 重写分配器与收集器）与位图标记表
（现在是每 8 字节一个 i32 ⇒ arena 的一半是 `.bss`）—— 见 `docs/228` §4 的 B2/B3，
其中 **B3 是 B2 的前置**。

**边界（如实列）**：发出去的是 `memcpy`/`memset`/`memcmp`/`malloc`/`free` 五个。
`memmove`/`calloc`/`realloc`/`strlen` **还没发** —— `memmove`/`calloc`/`realloc` 在尺子那张表上是
`unknown`（拒），`strlen` 是 `close` 而链接器发不出来，**表说的就是实话**：要它们的产物
照样在链接期报未定义符号。`malloc`/`free` 还多一条条件 —— **堆在才发**（见 §8b 表 S1c 行）。

**S2 剩下的三件 —— 2026-10-15 重测：原记的三条里有一条已经不在，而真正的拦路虎是另外两条**
（`FujoJTOP/loment#359`。下面三条都是**当场量出来的**，不是估计）：

1. **堆只在程序自己 `alloc`/`free` 时才发** —— 这条记对了。一份"只调外部库、自己不分配"的
   Loment 程序因此拿不到 `malloc`，而 C 库**总是要**（zlib 的 `zutil.o` 就要它）。
   修法就是原文写的那个：**"有 `extern fn` 就发堆"**（且根开着运行期；`no_runtime` 不跟 ——
   那一维是**保证**，产物里不带运行期）。已落到**两个实现 + 种子**。
2. **局部符号在成员之间重名** —— 这条**原来没记**，而它是"读回来是垃圾"的真凶。
   `.LC0` / `.L.str` / `my_version` 这种名字是**编译器按对象取的**、每个成员里都有，
   而标签表是**按名字**查的、而且"先来的为准"：`deflate.o` 排在 `zutil.o` 之前时，
   `zlibVersion()` 返回的指针就落到 deflate.o 的常量上（**静默指错地址，不报任何错**）。
   它与 S1f 修过的**节符号**是同一类，只是当时没顺手修普通局部符号。
   修法：局部符号（`bind == 0`）一律**按对象改名**，**登记与查找两处同一条规则**。
3. **C 调用点的栈没按 SysV 对齐** —— 这条**原来也没记**，而它是"当场崩"的那一半。
   System V 要求 `call` 那一刻 `rsp ≡ 0 (mod 16)`；我们自己的约定实参走栈、帧不对齐，
   于是**"某些调用恰好过、某些当场挂"**。症状是 `SIGSEGV` + `si_code=SI_KERNEL` +
   `si_addr=NULL` —— **那不是段越界，是 16 字节 SSE 访问对不齐**：zlib 的 `compress`
   死在 `movaps %xmm0,-0x70(%rbp)` 上。修法：extern 调用点用 `rbx` 存原 `rsp`、
   `and rsp, -16`、`call`、再恢复（`rbx` 是 SysV 的**被调方保存**寄存器，而 Loment
   生成的代码不用它）。

**并**：原文第 1 条"堆只有 64 KiB"**仍然在**，只是它不是"残留缺陷"那一类 —— zlib 的
`deflateInit` 要 **256–512 KB**（实测：512 KiB 起 `compress` 才跑得完），而 arena 是
编译期常量。这一格属于 **S1e**（"前沿从 64 KiB 静态数组换成向外面要"）。
而原文第 3 条那个症状（`zlibVersion()[0]` 读到 0、`deflateInit_` 返 `Z_VERSION_ERROR`）
**在 S1f 之后已经不复现**：重测时它读回 `1.3.1`；`deflateInit_` 仍报 -6，但原因是第 2 条
—— 那条版本检查比的正是被串掉的常量。

#### 2026-10-15 落地：三条各修在两个实现里，各自带判据

| # | 改了什么 | 两侧各一处 | 判据 |
|---|---|---|---|
| 1 | **局部符号按对象改名**（`bind == 0`） | `lomelf.py` 的 `name_of` / `lomelf.lomt` 的 `copy_local_name`（**登记与查找同一条规则**） | `loment_ffi_test::test_local_symbols_do_not_collide_across_members`（`-O0` 编出真局部符号；两个成员的 `.LC0` 不许解析到同一个名字）+ `loment_elf_test` 的镜像格 `ffi7`（与参考**逐字节**同） |
| 2 | **extern 调用点按 SysV 对齐** | `Emitter._call` 的 extern 支 / `do_call_extern`（`mov rbx,rsp` · `and rsp,-16` · `call` · `mov rsp,rbx`） | `test_extern_call_sites_are_sixteen_byte_aligned`（C 侧 inline asm 报进入时 `rsp % 16`，要 **8**）+ 镜像格 `ffi8` |
| 3 | **arena 给够**（1 MiB，**封在产物里**） | `_IR_HEAP_FFI`（与宿主那一份**共用 BODY**，只换 arena 那一段）/ `emit_heap_ffi` | `lomentc_test::test_ffi_artifacts_get_an_arena_big_enough_for_a_real_library` |

第 3 条**落在哪一档是量出来的**，不是定的：`extern fn` 且根开运行期 ⇒ 1 MiB 的**静态**块
（`sealed` 没有宿主的 `malloc` 可问）；**不是** `hosted`（它本来就吃平台那一块，更大）；
`gc_auto` **跟着换同一份收集器**（标记表 = arena/8 行 ⇒ 16384）；**`gc_auto_alpha` 明写地
留在 64 KiB**，而且**说出来**（`; loment-heap: static 65536`）—— 那一档的收集器是**直接
寻址 arena** 的，换 arena 就要连它一起换、再抄一份那段文本；而 `hosted` 与 alpha **定义上
冲突**，仓库里没有"间接寻址的 alpha"这份先例。**代价也明写**：`[1048576 x i8]` 是 `.bss`，
而本仓的链接器把 `.bss` 按零字节摆进数据段（S1f 的取舍）⇒ **产物文件大 1 MiB**；
"向外面要"（`mmap`/`brk`，即 S1e B）不在这一格里。

**判据要两个方向一起判**：同一份源**去掉 `extern fn`** ⇒ 必须还是老样子（64 KiB、直接
寻址、产物里一个字不提 arena）。只判"FFI 那一份很大"会被"给**所有**程序都加大"骗过 ——
而那正是 `sealed` 那条保证被改掉的样子（同一个坑 `docs/228` §5 的 A1 已经踩过）。

#### 顺带修掉的一处、顺带探到的一件

1. **`.eh_frame`：两侧行为不一致**（**本笔修掉**）。参考实现把"指向**元数据节**
   （`.eh_frame` / `.debug` / `.comment` / `.note`）的重定位**无害丢弃**，而自举那份
   **硬拒**（"重定位指向非代码节"）—— 同一份真 clang 产物（`-O0` 带的 `.eh_frame`）
   参考链得过、镜像链不过。现在两边同一条规则（`is_rela_to_lay`）。这是"孪生判据只证明
   **一致**、不证明**对**"那条教训的另一面：**行为不一致本身就是缺陷**，只是它一直没被测到
   —— 镜像那 8 例里原来**没有一格**是带 `.eh_frame` 的对象。
2. **自举链接器不吃 `ar` 归档**（**本笔做了**，`FujoJTOP/loment#405`）。参考实现的
   `Archive.select` 是**固定点成员选择**（某成员**定义**了当前需要的符号就收它，收完把它引用的
   未定义符号也加进需求，重复到不变；**不整包收** —— 整包收会把 `gz*` 那些成员的
   `fopen`/`printf` 拖进来，端口门于是把整个库拒掉）。自举那份原来一次只驻留**一个** `.o`。
   现在两侧同一条：`loment_elf_test::test_lomelf_selfhost_links_a_real_archive` 拿**真
   `libz.a`** 过镜像，产物与参考**逐字节相同**且跑出原文（证伪件报 40）。两条踩过的坑各留了
   一句话在代码里：`span_eq` 只在**同一个**缓冲里比名字（需要集在输入缓冲、成员名字在
   `M_OBJ`，拿它去比就是"一个成员都挑不出来"的静默空手）；以及"空归档是错、**一个都没挑中
   不是**"（后者该以"未定义的标签"报出来，方向才对）。

两半表不许分叉这件事有一条判据钉着（`loment_ports_test` 的
`test_the_linkers_conscript_surface_is_inside_the_rulers_provide_set`）。

### 8c. 发行版里这条路**曾经**是锁着的（2026-10-12）→ **2026-10-17 开闸**（`#406`）

用户原话（2026-10-12）：「**锁掉 LibC，在 0.1.4.5（即将发布）中不可调用 LibC，因为这尚未完工**」。
当时两扇门都关：编译器在发行版里把 `choose hosted` 判成**编译错误**（`tools/lomentc.py` 与
`loment/selfhost/checker.lomt` 各一条），启动器在发行版里**永不**给链接器 `--allow-ports`、
并把 `--hosted` 点名拒（命令行那只绕过编译器，所以要单独挡）。理由只有一句：
**承诺落空比拒绝更坏**。

**开闸（2026-10-17，`#406`）**：那句话的**前提已经不成立** —— 静态一侧（`#359`：真 `libz.a`，
`compress → uncompress → 原文`，参考与自举两侧逐字节相同）与运行期一侧（`#360`：系统 `libz.so`，
`DT_NEEDED` + PLT/GOT，参考与自举两侧逐字节相同）都落齐了。于是：

| 门 | 之前的锁 | 现在 |
|---|---|---|
| **声明的门**（`choose hosted`） | 发行版里是编译错误 | **拆掉**：两个渠道都收（判据的探针留着、期望反转） |
| **`--hosted`**（命令行） | 发行版启动器点名拒 | **拆掉**：那条分支不存在了 |
| **`--link` 的门**（`--allow-ports`） | 发行版启动器永不传 | **两个渠道都传** |

**链接器自己的默认没有变，也不该变**：它是一只被启动器调起来的独立工具，**不知道渠道**
（自举侧那份连渠道常量都看不见）。所以"默认拒 + 启动器显式开"这条形状保留下来 —— 变的是
启动器**两个渠道都开**。这样"哪一步忘了做"的后果仍然是**当场不好用**，而不是**悄悄开着**。

**开闸之后仍然关着的两条**（`#406` 第三条）：

1. **名字必须有人提供**：未定义的标签只在两处能落地 —— 我们自己发的**收编面**
   （`memcpy`/`memset`/`memcmp`/`malloc`/`free`/`__stack_chk_fail`）与链上那个 `.so` 的
   **导出表**。两边都没有 ⇒ **链接期点名拒**（不是运行期崩，也不是静默放过）。
2. **只知道链上的那一个 `.so`**：它的依赖（如 `libc.so.6`）在运行期对 loader 是可见的，
   但**链接期**我们的解析面只有那一个 `.so` 的导出表 —— 想要 `malloc` 就把 `libc.so.6` 链上，
   而不是指望从 `libz.so` 的依赖里顺带拿到。

判据：`loment_channel_test`（发行版**收** `choose hosted`、两份启动器两个渠道都传旗、
**发行版 + 真 `libc.so.6` 链成动态产物并跑出答案**、没人提供的名字仍然点名拒）；
`loment_ffi_test`（真 `libz.so` 的端到端 + 四条失败模式 + 发行通道默认拒）；
`loment_elf_test`（**自举**链接器同样链真 `.so`、产物与参考逐字节相同、不给旗就拒）。

**零字节的承诺没变**：**自闭合**的对象（一条未定义符号都没有）走的还是老路，
`docs/173` 一直在发的 FFI 形状、`docs/177` 那 10 个语言一个字都没动。

## 9. 一条推论（**不是**新东西）：运行期可复现

## 10. 代价 / 不做什么

1. **这个量是名字级的。** §5.1 已写死；**别把它当成 Sysfilter 那个数**（§11.2）。
2. **条件一（世界访问经名字）会拒掉一批编译方式**（`-fno-builtin` 之外的裸 asm 用法、

3. **动态装载（`docs/173` 阶段 3）与本文互斥**（§5.3）。要它就必须放弃 §4 那张表 ——
   这是一个**要用户拍的价**，不是本文能替他定的。

5. **不把 FFI 构建交回 clang/lld**（`docs/183` §6 不变）；**不做"从声明生成绑定"**（`docs/173` §0）。
6. **§9 只留一条，不扩张。**

### 11.2 会崩的地方（**先写崩在哪**）

已在 §5.1 写死，此处只点名出处：**Sysfilter 那一族去反汇编，正是因为符号名不足以断定行为**
（`malloc` 走不走 syscall 与名字无关；内联 `syscall` 没有名字）。
⇒ **"链接器已经算得出来"是一个名字级的命题，不是行为级的。** 本文量与 Sysfilter 量不同。

### 11.3 于是窄新颖面（**只剩两条**）

1. **把"未定义符号"当成通向世界的端口，在链接时数出来、写进产物**，与 GC / 边界的计数同族。
   最近的两个邻居各在**另一个基质**上：WASI（Wasm 的 imports = 能力面）与 Java 字节码的纯度推断。
   **原生 ELF 上未见。**
2. **把"世界"从令牌变成清单。** GHC 的 `RealWorld` 是一个没有结构、没有数的**线性单例**；
   本文换成**具名的端口表** —— 世界第一次有了**基数**。检索未见有人这样做。

### 11.4 旁注：这条死链在文献里是散的

检索未见任何正式论证"保留确定性就不可能调用真 C 库"；常见的只是一张**障碍清单**
（malloc 的全局状态、TLS `errno`、`atexit`/`__cxa_atexit`、PLT 惰性绑定）。
**障碍清单不是不可能性证明。** §2 那条 A→F 是本文自己写闭合的 —— 如实说。
