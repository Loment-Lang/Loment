# 369 · 热更新是朝标准的一次单调下降（补丁守恒猜想）

> 状态: **猜想稿**（2026-11-21）。没有实现，也不打算在这里加判据。
> 上游: `docs/278` §5（Pre-Release 不出包与 tag 的形状）· `tools/loment_projection.py` 的
> `DIGEST_KEYS`（`docs/287` §3 讲其中 surface/cli 两项）· `docs/368`（工具链代际，在 PR #2128 里）·
> `standard/LLS.md`（语言标准）
> 实测: 2026-11-21，本检出；§3 的三个例子来自仓里已登记的 issue（三个都**不是**反例，理由在那一节）
> 一句话: **被准入的热更新只能让程序从"错"走到"对"，不会把"对"改成"另一个对"** —— 这句如果成立，
> 它能买下的东西比今天整条热更新线加起来还多；如果不成立，它指出的是"五道摘要只是语法防火墙"。

---

## 0. 一句话展开

今天的热更新闸门是**语法**的：`tools/loment_projection.py` 的 `DIGEST_KEYS` 是

```
("language", "contract", "capabilities", "surface", "cli")
```

五项相等就放行，配 `tools/loment_update.py` 的契约 / 能力 / 固定核等式。**没有一项在问语义**
—— 载荷把 `a + b` 发成 `a - b`，五道摘要也不会动。

"补丁守恒"（Patch Conservation，PC）是一个关于**方向**的断言：

```
准入(T, T')  ⇒  d(T') ⊆ d(T)
```

其中 `d` 是工具链与《语言标准》的偏差集合。它说的不是"载荷是对的"，是"**载荷只会减少偏差，
不会新增偏差**"。这是一个比"闸门能挡住功能"强得多、也漂亮得多的主张：功能变更与修复变更在语义上
是可分的，而五项摘要恰好是那条分界线的一个**充分**判据。

---

## 1. 形式化

**工具链** `T`：一次构建产物（`bin/` 的全部工具 + 它随包的 `share/` 那部分）。热更新把 `T` 变成 `T'`。

**可观察语义** `S(T)`：所有 well-typed 闭程序 `P` → 它的终止轨迹集合
`{(exit, stdout, stderr, 文件系统副作用)}`。取"终止"是为了绕开超时与并发；本猜想不谈 liveness。

**标准** `LLS`：`standard/LLS.md` 的条款，加上它点名的参考行为。`LLS(P)` 是标准对一个
well-typed 程序要求的行为集合。

**偏差** `d(T) = {(P, b) | P well-typed, b ∈ S(T)[P] \ LLS(P)}`。它是个**集合**，不是数：
包含关系是偏序，"下降"是 `⊆` 方向，不是某个指标的数值下降。

**准入**：`Admit(T, T')` 当且仅当五项接口摘要逐条相等、能力表相等、固定核相等、载荷签名有效
（即今天 `loment_projection` 第 3 关 + `loment_update` 的全套检查）。

**猜想 PC**：`Admit(T, T') ⇒ d(T') ⊆ d(T)`。

**强形式 PC⁺**：对任意基线 `T0`，存在有限序列 `T0 → T1 → … → Tn`，每步 `Admit`，且 `d(Tn) = ∅`。

**与"回归"的关系**：PC 禁止的正是回归 —— 一个在 `T` 下符合 LLS 的程序，在 `T'` 下不符合。
回归测试是在**样本上**找 PC 的反例；PC 声称热更新线**结构性地**没有这类反例。

---

## 2. 为什么一辈子证不了

三条理由各自独立，去掉任何一条，另外两条仍然成立。

1. **`d` 不可计算。** 要判 "`b ∈ LLS(P)`"，需要 LLS 的完整形式语义；要对每一个 well-typed 程序计算
   `S(T)[P]`，等价于判定程序等价，一般情况下不可判定。所以 `d` 只能逐样本近似，"全部 well-typed 程序"
   这个量词永远到不了。
2. **它量化"今后所有 fix"。** PC 不是关于某一笔提交的定理，是关于**这条线永远不会发生的事**的陈述。
   今天对 0.1.5.1 证完，明天一笔 fix 就作废；而热更新线的寿命等于项目寿命。
3. **它要求"语法闸门 ⇒ 语义单调"，这等于给接口摘要出一个全抽象（full abstraction）证明。**
   PL 里几十年没有普遍解。而且 LLS 目前是散文 + 参考实现，连"标准"这一侧都没有可机检的形式。

想让 PC 变成可证的，最小代价的路线是：先给 LLS 建形式语义（十年量级），再对每个候选做 refinement 证明。
即使都做完，得到的也只是"**某个基线**是对的"，不是猜想本身。

---

## 3. 仓里已有的三个形状：闸门对它们一无所知

取"与基线一致"当"对"，PC 等于什么都没说 —— 基线自己就会错。取 LLS 之后它有内容，而仓里已经
有三处**行为在准入之外被改动**的形状，值得逐条看（三份都在 issue 里有可复跑的证据）：

| issue | 形状 | 对 PC 的意义 |
|---|---|---|
| `#224`（open）`bool` 期望类型被套到整型运算上 | 一个**完全合法的程序**（`A + B <= 300`）被发成 `add i1 100, 200`，静默算错 | 修它**改变了合法程序的输出**：错 → 对，是合法下降。同时说明"准入不改变行为"是假的，以及五道摘要对 checker 的健全性一个字都没说 |
| `#205`（open）指针比较发 `icmp == ptr`（非法 LLVM） | 源码对、**产物被 clang 拒** | 失败 → 成功，仍是下降。偏差在 codegen，源码语义证明覆盖不到 |
| `#316`（closed）`bool != bool` 自举发 `i64`、参考发 `i1` | 自举侧的值偏离标准 | 下降。但它提醒："两份实现一致"只证明一致，不证明对 —— 若当时两侧一起错，一次"修好"就会把 PC 违反掉 |

三处**都不是** PC 的反例：每一处的改动都是朝标准方向的。但它们合起来说明一件更要紧的事：

> **闸门对这三次改动没有任何判断力。** 五道摘要没动一条，载荷照样被准入；行为变了，而且是
> 朝对的方向变 —— 这只能说明"这次运气好、作者改对了"，不能说明"准入保证了方向"。

所以 PC 今天的真实地位是：**没有被检验过**。热更新线还没有过一次 Release，也就没有过一次
"准入的载荷里带着一个新增偏差"的观测。仓库里"新红"那套机制证明的是**判据层面的回归**会
发生（每一笔被复跑确认的新红都是），而 PC 说的正是：这种回归如果进了热更新载荷，方向就错了。

## 4. 修正：把"对"锚在标准上，别锚在基线上

```
d(T) = {(P, b) | P well-typed, b ∈ S(T)[P] \ LLS(P)}
```

这样一改，PC 变成一句关于**方向**的话，而不是关于"与谁一致"的话：

> 每一次准入，把工具链朝标准的距离**非增**地推了一步。热更新是这条距离上的下降方向。

注意这里的"距离"是集合包含，不是数值。想要数值就得选一个测度（比如"失败的轨迹条数"），
**每个测度的选择都是一次建模决定**，也是 PC 从"定义"滑向"经验定律"的地方。这一点必须明写，
否则"下降"会变成用一个自己挑的指标证明自己。

---

## 5. 可拿掉的假设（按代价从便宜到贵）

| 拿掉 | 剩下什么 | 代价 / 收益 |
|---|---|---|
| "LLS 是完备 oracle" | 经验定律：观测到的一次违反就是一个反例 | **最便宜**，也最诚实：我们永远只能证伪它。§6 的探针就是在这个形态下工作 |
| "对所有 future fix 量化" | 单基线、单次更新的 refinement 证明 | 十年量级工程；不回答原问题，但能先给"这一笔是下降"一个可机检的说法 |
| "从二进制算" | 源码级证明（可复现种子两端对得上） | 仍要形式语义；`#205` 那种"源码对、产物错"的 bug 落在证明之外 |
| "well-typed" | 连 `#224` 都算违规 | 平凡假，没有讨论价值 —— 未定义行为的程序本来就不在标准的承诺里 |
| "五项摘要相等" 作为准入 | 直接对 `S` 做差分 | 那就不再是"能不能热更"的判据，而是"两次构建是否等价"的判据：**它退化成 §7 的对偶** |

---

## 6. 对偶猜想：交换性

把 PC 的"方向"换成"顺序"：

**对偶（PC×）**：同一基线上的任意两次准入**交换** —— `T+F1+F2` 与 `T+F2+F1` 观察等价。

若 PC× 成立，热更新集合构成一个**交换幺半群**：每条 fix 是一个生成元，整条线是单参数子群。
推论会很硬：

- **代际可以塌缩**："A/B 两格 + 指针"退化成"一条单调路径 + 游标"，存储是差分而不是整份工具链；
- **rollback 精确**：回到的不是"另一格"，是同一个语义点；
- **投影可以排序**：`loment_projection` 不必按提交顺序重放，可以按"最小语义影响"排序，少剔除。

PC× 的反例很好造（两个 fix 同时改一个函数的边界）；我押它**一周内**就能被证伪。证伪本身有用：
它给出的是一条"fix 之间不独立"的具体形状，比继续相信"投影是线性的"强。

## 7. 如果成立，能买什么

1. **不做人工评审的热更新**。闸门本来就只验签名与摘要；PC 给它加上"即使作者写错，也只会让某个错误
   消失或另一个错误留下，不会凭空制造新错误"——于是"要不要装"只剩"要不要现在修"的问题。
2. **信任根问题自己消解**。今天 `docs/368` 把更新器排除在载荷外，理由是"载荷不能替换验签者"。
   若载荷在语义上只能减少偏差，替换更新器就是一次普通修复，`fixed_core` 的不动点从"必须"变成"方便"。
3. **发行线可以完全由热更新走完**（PC⁺）。完整包退化成种子；"版本"仍然是一个数（LLS 那一条），
   但"发布"这个动作消失，只剩"线又下降了一步"。

这三条里任何一条成立，都比今天整条热更新线的价值大。它们也解释了为什么这条猜想值得写下来：
**它是这套设计唯一的"为什么可以这样做"**，而今天的设计只有"我们这样做了，且看起来没事"。

## 8. 怎么便宜地证伪（一周内可做）

PC 在弱形式（§5 第一行）下是一个可跑的探针，不需要形式语义：

1. 取两个工具链 `T`（基线）与 `T'`（基线 + 一笔声明为 fix 的提交），用 `docs/368` 的代际目录并排放；
2. 语料取 `loment/examples/` + `tools/loment_p8_test.py` 的样本集（已有）；
3. 对每个程序跑两遍，收集 `(exit, stdout)`，与**同一份源码在参考实现下**的结果比对；
4. 任一 `(P, b)` 在 `T` 下与参考一致、在 `T'` 下不一致 —— PC 被证伪，且证据直接是一条回归。

这个探针的形状与本仓已有的"孪生判据"不同：孪生只证明**一致**，这条问的是**朝标准的方向**。
换句话说，它是"三方差分"的一条新用法：真实工具链 / 被验实现 / 独立推的期望值。
`#1830` 与 `#1828` 是已经发生过、且方向正确的两次下降（rc 132 → 0；rc 13 → 0），可以先拿它们当正样本。

**代价诚实**：这个探针只能证伪，不能证明。跑一万个程序通过，也不构成 PC。

## 9. 与今天这条线的关系

- **闸门**：`tools/loment_projection.py` 的第 3 关（五项摘要）与 `tools/loment_update.py` 的等式，
  是 PC 的**前提**。PC 若成立，它说明这组前提是充分的；若不成立，它说明需要第六条摘要
  （语义指纹），而那条今天没有任何实现。
- **代际**（`docs/368`）：`gen/a|b` 是 PC 的实验台 —— 两个工具链同时在场，正好是 §8 探针的输入。
- **标准**：`standard/LLS.md` 是 PC 的右侧。它今天是一层"框"，还不是可机检的语义；PC 的价值之一
  是给"LLS 什么时候算写完了"一个外部判据：**当 `d(T) = ∅` 可判定时**。

---

## 10. 边界：这份文档不声称什么

1. **不声称 PC 为真**，也不声称它可证。它的用途是当尺子：每次热更新都问一句"这次是下降吗"。
2. **不提出新的准入规则**。若 PC 被证伪，修法是另一份文档的事（第六条摘要 / 语义差分），不是把闸门放松。
3. **不把"没观测到反例"当证据**。§8 的探针能证伪；通过只说明还没撞上。
4. **不覆盖并发与非终止**。`S` 只看终止轨迹；线程、信号、超时的语义留给 `docs/245` 那一线。

---

## 11. 两句话收束

- **猜想**：准入的热更新是朝语言标准的一次单调下降；强形式说这条线能走到 `d = ∅`。
- **它的真实含义**：五道摘要**不是语义防火墙，是语法防火墙** —— 而我们今天在靠它发货。
