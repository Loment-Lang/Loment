# 256 — 失败消息的交付：用户敲的是 `loment`，不是 `fujoc-s`

> 起因：`#8`。状态：已落地（`E031`/`E032`/`E033` 三个新码 + 两个实现一起改）。

## 1. 报的是什么

`loment check` 遇到一个**读不到的文件**时，用户看到的是这一行：

```
fujoc-s: 打不开 \0nosuch.lomt
```

四个毛病叠在一句话里，`#8` 逐条点了名：

1. **`fujoc-s` 不指向任何他手上的东西。** 那是自举驱动的旧内部名；用户敲的是 `loment`。
2. **语言与 CLI 的其余部分不一致** —— 启动器说英文，这一句是中文。
3. **流里有杂散字节。** 中间那个 `\0` 是**手数字节数**写出来的：文案是 19 字节，
   代码写的是 20，多出来的一字节正是字符串常量的 NUL。任何把它当 C 串读的消费者
   只看得到前半截。
4. **补救指向 `docs/189 §4.1` / `docs/188 §1`** —— 那两个文件**不在包里**，
   读者打不开。他真正有的东西是 `loment skill --print` 与 `loment codes` / `explain`。

同一条链上还有第二个实例（`#8` 的第二条评论）：`lomelf` 写不了产物时只说
`lomelf: 写不了输出` —— 不说**是哪个路径**，而那正是唯一有用的一条信息
（「父目录不存在」看一眼路径就明白）。

## 2. 这一类的分界

不是所有失败都能走同一条路。分界是**指不指得出源码位置**：

| | 例子 | 交付方式 |
|---|---|---|
| **有位置** | `module` 缺失、`use` 名字解析不了、`use` 超 300 条、库写 `choose`、依赖嵌套超限 | 结构化诊断（`--diag-out`）+ 那一行文本；码沿用 `E018`/`E019`/`E020`/`E022`/`E023`/`E024` |
| **没有位置** | 输入文件读不到、产物写不出去、单元超出固定容量 | 结构化诊断，`line` 写 **0**；码是新的 `E031`/`E032`/`E033` |

第二行是这一轮新开的。它之前**一行都不写**：`lomenterr` 只能渲染 JSONL，而这些失败
只往 stderr 打一句裸话，于是启动器只能**原样回吐**（`docs/182` §10.2 第 3 条记着这个
兜底）。现在它们也吐记录，渲染器那一边负责把话补齐。

**`line = 0` 不是"编了一个行号"，是"没有位置"**：`lomenterr` 的 `num_raw` 本来就是这个
口径（字段缺失 = 没位置）。渲染器因此**不印 `:0`**（那个 0 看着像第 0 行，编辑器会照着
跳），**也不去源里切那两行** —— 这几个码的 `file` 常常根本不是源码（`E032` 那个是一条
**还不存在**的产物路径，印「读不到源文件」只会让读者以为源码有问题）。

`tools/lomentc.py` 里那句「`line == 0` 就不写结构化诊断」的注释**仍然成立**，它管的是
**源码类**诊断；新开的那三条不属于它，所以它们写，而且 `line` 明写 0。

## 3. 三个新码（按「码按修法分」）

| 码 | 说的是什么 | 用户要做的事 |
|---|---|---|
| `E031` | 输入文件读不到（不存在 / 是目录 / 读不了 / 空文件） | 查路径、给文件别给目录、把源码写进去 |
| `E032` | 产物写不出去 | 先建父目录、换个 `-o`、查权限、关掉正在运行的 exe |
| `E033` | 单元超出这套编译器的**固定容量**（词法缓冲 / 符号表 / codegen 表 / 回填表） | 把门面拆小、少几层 `use` |

三条**各自一个码**而不是并成一条，理由是本仓那条老规矩：**码按修法分**。查路径、建目录、
拆门面是**三件不同的动作**，并在一起就会给出「照着建议改却没解决」的消息。

**⚠ 号是 31 起，不是 28，也不是 30。** 这一笔落地时写的是 `E028`/`E029`/`E030`，与 `main`
合并时**连撞两次号**，每次都按「**已经落地的那份不改、分支顺延**」整体后移：

| 撞号的一轮 | 主线先占了 | 我这份顺延成 |
|---|---|---|
| 并 `#414`（LMS 第 1 级，`docs/253` §5.1） | `E028` 定长数组越界、`E029` use-after-free | 30 / 31 / 32 |
| 再并一轮（未知类型那一条） | `E030` 未知类型（浮点不存在也从这里说） | **31 / 32 / 33** |

两边说的都是"源码之外那一层的失败"这个大方向，但**修法与受众都不同**，所以是错开号，
不是并成一条。**这也说明「码」是稀缺、会撞的资源**：分支上先写的号不作数，落地那一刻
以 `main` 的表为准。

`RULES` 是**有序**的，第一个命中就赢 —— 这三条的模式偏宽（`cannot open` / `打不开`
这类），所以**排在最后**，免得抢走上面那些更精确的模式（`E028` 的 `越过定长数组的界`
就在更前面）。

## 4. 两个实现一起改

自举侧与参考实现在这四处**原本都交不出话**，只是坏法不同：

| | 自举侧（包里的那个） | 参考实现（开发者工作区那条 CLI） |
|---|---|---|
| 读不到输入 | `fujoc-s: 打不开 <path>`（中文、带 NUL） | **没接住的 `FileNotFoundError`** —— 甩 Python 栈 |
| 写不了输出 | `lomelf: 写不了输出`（不说路径） | **没接住的 `OSError`** —— 甩 Python 栈 |

两边这一轮都补：自举侧吐结构化记录 + 一行英文，参考侧改吐一句话（也进 `--diag-out`）。
参考实现自己的消息文本**仍然保持中文**（`docs/182` §5.3 那条分工没变）；变的是
**它不再甩栈**。

## 5. 消息文本的写法

面向用户的失败消息一律：

* **`loment: ` 开头**（`lompi:` / `lomenterr:` 不在此列 —— 那两个名字用户真的会敲）；
* **纯 ASCII 英文** —— 与 `E031`..`E033` 的卡片同一个理由（`docs/169` §3a：Windows 控制台
  按 936 代码页解 UTF-8，中文是乱码，而 PE 垫片没有 `WriteConsoleW`，程序侧无从补救）；
* **长度交给 `str_len`** —— `fail` / `failp` 把前缀与换行写死在一处，用点只给话。
  原先 50 个用点各写一遍 `write_all(2, ..., N)`，写错一处就是 `#8` 那个 NUL；
* 补救指向**读者手上真有的东西**：`loment skill --print`、`loment codes`、
  `loment explain E0NN`。

给 `lomelf` 加了 `--diag-out`（启动器传，与驱动同一个文件：驱动成功时那个文件是空的，
不会被覆盖），它的 `E032` 由此走同一条渲染路。

## 6. 判据

* `loment_tools_test::test_no_shipped_tool_prints_an_internal_name` —— **扫源码**：
  包里那些工具的字符串字面量不许以 `fujoc-s` / `lomelf` / `lomfmt` / `fujofmt` /
  `lomdoc` 开头。纯静态，秒级，管的是「新加的消息别再带内部名」。
  在**未修**的树上是**红的（96 行）**。
* `loment_err_test::test_a_position_less_record_carries_no_line_number` —— 渲染器：
  `line = 0` 的记录印 `--> <file>`（不带行号）、不去源里找第 0 行，`--short` 同理。
* `loment_p8_test` 的入口装载那条 —— 跑真驱动：缺文件那句话里**没有 NUL**、
  `--diag-out` 里**真有一条 `E031` 且 `line` 是 0**、而给人看的那一行**仍然照打**
  （直接跑 `loment-driver` 的人手上没有报错器，把话只留在 JSONL 里等于没报）。

## 7. 已知的边界

* **`没有 _start 入口` 没有自己的码。** 那条检查埋在 `lomelf` 的 `emit_all` 深处，
  够不到输出路径，而「链接器答不出从哪开始跑」这件事也没有源码位置可指。它现在是一行
  英文 `loment:` 文本（说清了两种补法），但进不了渲染器。要给它一个码，得先把那条检查
  挪到 `run()` 那一层 —— 那是另一轮的事。
* **`loment fmt` / `loment doc` 只有消息面。** 启动器直接 exec 它们，不传 `--diag-out`，
  它们也没有诊断通道。所以那两个工具这一轮只改了文案（`fujofmt:` / `lomdoc:` → `loment:`，
  并点上文件名）。
* **这一轮踩到的一个坑，记在这里免得下一个人重踩**：改了 `loment/selfhost/*.lomt` 之后
  **必须整包重建**（`loment_dist.py --emit`）才拿到新驱动 —— 而构建失败时 `loment/dist/`
  下那份 **zip 还是上一次的旧包**。这一轮我先拿旧 zip 验了一轮，看到「消息变了、结构化记录
  没进去」，白查了一阵。构建日志要连着退出码一起看，别只看产物在不在。
