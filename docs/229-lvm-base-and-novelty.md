## 0. 一句话

> **两件事，别混。**
> **① 基座**：LVM 照 **V8**（零件清单：分层执行 / 反馈向量 / 去优化 / 分代并发）与
> **GraalVM**（框架形态：自优化解释器 + 部分求值 / 语言无关工具链 / AOT 的 closed-world）建。
> **② 新颖面**：基座是**别人的成熟工程**，所以"VM 做得比别人好"这个问题**答不出来也不该答**。

> 按这个问法只剩两处：**执行模型进产物**（检索不到对应物）；**内部缺席**作为一等可验收主张
> （已落地，`docs/227`；主流那一栏没有对应物）。两处**都不是 VM 带来的**。

## 1.5 基座（用户 2026-10-11 定）：**V8 与 GraalVM**

### 1.5.1 它们各贡献什么

两座基座不是同一类东西，**一个回答"零件清单"，一个回答"怎么组装"**。

| | **V8** | **GraalVM / Truffle** |
|---|---|---|
| 是什么 | 产品级 JS 引擎 | **语言实现框架** + 虚拟机 + AOT 工具 |
| 贡献的那一极 | **工程实现** | **架构形态** |
| 分层执行 | **Ignition**（字节码解释器）→ **Sparkplug**（基线编译）→ **Maglev**（中间层）→ **TurboFan**（优化 JIT） | Truffle 的**自优化 AST 解释器**；JIT **不是写出来的，是从解释器经部分求值派生出来的** |
| 运行期剖面 | **反馈向量**（类型 / 分支 / 调用点）喂给上层编译器 | 由 `@Specialization` 节点自身携带 |
| 回退 | **去优化**（bailout 回 Ignition） | 同样的角色，由部分求值的**守卫**失败触发 |
| 内存 | **Orinoco**：分代 + 并发/并行标记 + 增量标记，**精确** | 由宿主运行时提供；Native Image 侧是 AOT 的堆 |
| 启动 | **快照**（堆快照烘进二进制）+ 惰性编译 | **Native Image 的 AOT**：closed-world、无解释器、无动态加载，带 PGO |
| 语言无关的能力 | — | **Instrument API**：调试器 / 剖面 / 覆盖率 / 多语言互操作，**任何 Truffle 语言白拿** |
| ⚠ 与本文相关的一件 | — | **Sulong**：GraalVM 上跑 **LLVM bitcode** 的那条路 |

### 1.5.2 为什么这两条对 Loment **不是外来的**

两条在**形状上已经是对上的**，这决定"基座"不是硬接：

* **Loment 发的是文本 LLVM 子集 IR**，而 GraalVM 有 **Sulong**（把 LLVM bitcode 跑在 Truffle 上）
  ⇒ 两边是**同一种东西**（不是今天就接得上，是**形状通**）。
* **`lomelf` 本来就是"每个 SSA 值一个栈槽"的栈机**（`tools/lomelf.py:19`）
  ⇒ **V8 的 Ignition 是同一件事的成熟版**；两者差的是**分层与去优化**，不是形状。

### 1.5.3 它**撞到了什么**（必须写死，否则这是一句空话）

| 撞到 | 处置 |
|---|---|
| ⚠ **`docs/205` J2：「JIT（运行时画像）**明确不抄**」** | **这份基座直接推翻它。** 但要把理由说清：J2 当年拒的是"**运行期画像换峰值、代价是预热期与不可预测**"；而 `choose vm` 是**显式 opt-in** 的一维，默认档一行不受影响 ⇒ **冲突面从"整个语言"缩到"选了 `vm` 的那一档"**。**这是基座决定能成立的前提，必须与 J2 正面结账**，不能绕过 |
| ⚠ `docs/204:49` 给"字节码 + VM"记的代价（"多了一层**永远存在**"） | 靠 `choose` 挡掉，见 §3.2。**这是唯一能正面顶回 J1 的东西** |
| ⚠ `docs/205` §2「不插 VM」 | 见 §3.1：那条挡的是"**可移植性**靠 VM"，而 §1 第 1 条已判为假 ⇒ 不成立。但账上那一行要改得明白 |
| ⚠ **"两个实现逐字节相同"** 这条纪律被**放大** | V8/GraalVM 那一档的产物若要可复现，就得照 `docs/212` §6 对付 LLVM 那样：**钉死版本 + 把产物哈希进 lompi**。**这是价格，要认**，不是可以绕的 |

### 1.5.4 两个读法（**必须挑一个，本文不替你挑**）

"以 V8 / GraalVM 为基座"有两种落法，**代价完全不同**：

| | **读法甲 · 架构参照系** | **读法乙 · 直接建在之上** |
|---|---|---|
| 是什么 | LVM **自己实现**：零件的清单照 V8、框架的形态照 Truffle，代码是自己的 | Loment 做成一个 **Truffle 语言**（或走 **Sulong** 那条 LLVM bitcode 的路），基座是**别人的代码** |
| 拿到 | 那两处空白（§4）**还在自己手里** | 性能、工具链（调试/剖面/覆盖率）、多语言互操作 **白拿** |
| 代价 | 全要自己写；每一个零件都要**两个实现逐字节对齐** | **把"这门语言允许 VM 是什么"交给一个不接受缺席声明的基座** —— Native Image 的 **closed-world** 与 Loment 要的"可核的缺席/组成"**方向相反**；V8 侧的嵌入形态更远 |
| 与 `no_runtime` 的关系 | 可选：VM 档带运行期、默认档不带 | 运行期**恒在**（宿主）⇒ `no_runtime` 在这一档**表达不出来** |

**我的建议：甲。** 理由只有一条，而且是这份文档自己的结论：
**乙能拿到性能与工具链，拿不到独特性** —— 而独特性正是 `docs/175` §2 定的中心点。
但**这一条该由你拍**：若"开发目标"这一栏你要的是"**先把性能和工具链拿到**"，那乙对，
而且甲可以晚一档再做。

### 1.5.5 开发目标（照 V8 的分层，落成一格一格的）

照 `docs/213`/`214` 的体例：**每格要能被证伪，不许写"做一个 JIT"**。

| 档 | LVM 要做到的 | V8 / GraalVM 的对应物 | 判据（可证伪） |
|---|---|---|---|
| **T0** | 字节码 + 直接解释 | Ignition | 与原生产物 **stdout + rc 逐字节相同**（与 `loment_elf_test` 同一把尺子） |
| **T1** | **反馈向量**（类型 / 分支 / 调用点剖面） | V8 feedback vectors | 剖面**进产物**且第三方可读；关掉剖面 ⇒ 产物逐字节不变 |
| **T2** | **基线编译**（无优化，只为去掉解释开销） | Sparkplug | 同一程序 T2 显著快于 T0，**语义逐字节相同** |
| **T3** | **优化编译 + 去优化** | TurboFan / Graal | 去优化后**结果与原生产物相同**（这是 T3 唯一的硬判据） |
| **T4** | **分代/并发回收** | Orinoco | `docs/210` §2.4 今天明写"不做分代"（写屏障无处可放）⇒ **不是本档能顺手做的** |

⚠ **T1–T3 每一档都要重打 `docs/205` J2 那一仗**（它们就是运行时画像）。**T0 不要** ——
T0 是纯解释器，与 J2 无关，所以 **0.1.6 落在 T0 不欠任何账**。

## 2. 前史先行（这一节不许跳）

`docs/207` 的教训：**先点名，再说话**。本节两路检索都是 2026-10-11 做的；**"没检索到 ≠ 没有"**。

### 2.1 证据随产物走、宿主加载期裁决

| 系统 | 验了什么 | 能验**缺席**吗 | 结局 / 代价 |
|---|---|---|---|
| **PCC**（Necula & Lee 1996/97） | 代码**自带**一份安全策略的形式化证明；宿主只验证明有效 + 结论合于己方策略 | 只证"声明的策略成立"，非通用缺席 | 证明由**生产方**生成（要定理证明器、体积大）；宿主验证快。**与本文的距离在 §2.3 末** |
| **TAL**（Morrisett 1998）/ **翻译验证**（Pnueli 1998） | TAL 把类型系统压到汇编层；翻译验证在**每次编译后**证"输出等价于输入意图" | 否，证类型正确 / 语义等价 | TAL 停在研究；翻译验证是逐次补偿，不是一次性信任 |
| **eBPF 校验器**（Linux） | 沿所有路径模拟：类型安全、内存安全、初始化、调用纪律、引用释放；**证不了就拒** | **否** —— 没有"本程序永不调用某 helper"的机制；helper 按程序类型**白名单授予**（"允许集"，不是缺席声明） | 加载期强制，已上生产 |
| **.NET CAS** | evidence → permission set | **曾试过**：`RequestRefuse`（声明"我拒绝某权限"） | ⚠ **被弃**（.NET 4 起）。理由之一正是"`RequestRefuse` 需要你穷举不想要的权限 ⇒ **不是有效的最小权限模型**"。见 §4.3 |
| **JVM 校验器**（Java 6 起 stack map frames） | 加载期验类型安全、操作数栈一致、控制流良构 | 否 | 生产级 |
| **WebAssembly** | validation 证**类型良构**；import section 逐条列全部外部依赖 | **最接近**：空 import 段 = "无任何外部依赖"，是加载期可核的**结构事实**。但那是**接口的语法属性**，**不声明**内部"无分配/无 GC" | component model 以 import 为**唯一**能力通道，未新增"声明缺席"机制 |
| **NaCl / SFI** | 加载期**静态**验证（白名单指令、32B 边界、受限寄存器） | 否，是"白名单合规" | 项目已死 |
| **CHERI** | 硬件在**每次访问**强制能力边界 | 否 | 硬件级，不留"缺席声明"的证据面 |

**术语检索**：`"verifiable absence"` —— **检索不到**标准学术用法；`"proof of absence"` 主要见于
Merkle 非包含证明，不是加载期验证术语；`"absence property"` **有**（形式化方法里指"证明某事不发生"，
如 HASE 2012 那篇 B-Method 的）；`"negative capability declaration"` / `"capability absence"` —— 检索不到。

### 2.2 一份 IR、多种执行模型、可开关

| 系统 | 同一份 IR 多后端？ | 开关粒度 | 选择**进产物**吗 |
|---|---|---|---|
| **V8** | 是（Ignition 字节码 → Sparkplug/Maglev/TurboFan 多层），但**都随构建一起打包**，不是"选一种" | **运行级**（引擎自己按热度升），**不是项目级** | 否 |
| **Android ART** | **是**。一份 dex 可被解释器 / JIT / AOT(oat) 执行，逐方法混用 | **项目级**（`pm.dexopt.*`、`PRODUCT_DEX_PREOPT_DEFAULT_COMPILER_FILTER`） | **否** —— 落在系统属性与服务里 |
| **GraalVM / Truffle** | 否（无独立 IR）。解释器是自优化 AST；JIT 由对解释器**部分求值**派生；Native Image 是另一条链 | 运行 / 构建级 | 否 |
| **PyPy / RPython** | 一份 RPython → 生成 C 解释器 + 自动派生的 JIT | 构建级 | 否 |
| **Erlang BEAM** | 加载 `.beam`，code server 支持热替换 | 运行级 | 否 |
| **LLVM MCJIT / ORC** | 同一 IR 既可 compile 也可 JIT —— 但是**同一编译器**的时机之差；`lli` 解释器已废 | 运行时 API | 否 |
| **Hermes** | AOT JS→bytecode 或 JS→native，运行时含解释器 + baseline JIT | 构建级（只有 JIT 开关） | 否 |
| **Wasmtime** | `wasmtime compile` 产 AOT 模块，或运行时 JIT / 解释 | 构建 / 运行级 | 否（模块序列化，但不含"模式"字段） |
| **NativeAOT / CoreRT · GraalVM Native Image** | 否 —— 纯 AOT、closed-world，**不留解释器** | 构建级二选一 | 否 |

**最接近的是 ART**（唯一"一份输入、三种执行模型共存、且有项目级开关"的），但它把选择放在
**系统属性与服务**里，**不写进 dex/oat**。⇒ **"把 AOT 还是 VM 印进产物、成为可审计字段"—— 检索不到对应物。**

### 2.3 自报（照 `docs/210` §3 的体例）

> **没有一块砖是新的。** 证据随产物走 + 宿主加载期裁决 = **PCC**（1996）；
> "证不了就拒"的加载期验证器 = **eBPF / JVM / NaCl**；空 import 段 = **Wasm**；
> 一份输入多执行模型 + 项目级开关 = **ART**；分层执行 / 反馈向量 / 去优化 = **V8**；
> 框架化的语言实现 = **Truffle**。
> **可能新的是"这门语言原本就有的那几样东西（编译期证得的缺席、组成可读、静态调用图），
> 走 VM 这条路时才露出来的那两处"**（§4）。**没检索到。没检索到 ≠ 没有。**

**与 PCC 的那一处距离（必须写清，否则 §4.2 会被读成 PCC）**：PCC 的证明是**额外生产的** ——
得写定理证明器、证明体积大、成本压在生产方。本文说的那两样是**编译器的常规产物**：
`@__loment_alloc` 出现没出现、`gc_ladder` 那张表、端口表 —— **产出它们不需要为"证据"多付任何工**。
这是**成本位置**的差别，不是概念的差别；§4.2 站得住的地方只有这一条。

## 3. 先把不可能性写死（四条）

### 3.1 「不插 VM」—— **可绕过**，但要在账上改得明白

`docs/205` §2 写的是：可移植性走**编译期**，**不插 VM**；J1（字节码 + VM 解耦）的裁决是
"**换形式抄**：要'语言可换'，不要 VM"。

**那条挡的是"可移植性靠 VM"** —— §1 已裁决第 1 条动机是假的，所以这条冲突**不成立**。
但 `docs/205` 是一份**账**（它自己 §5.3 说"零沉默"）：那一行得改成
"**不靠 VM 换可移植性；允许有一个可选的执行 VM，理由不是可移植性**"。
**这不是修 bug，是改裁决** —— 要有单独一次提交与一条新判据。

### 3.2 默认档**逐字节不变** —— **不可绕过** ⇒ 只能 opt-in

`docs/175` §3.4 那条"**默认不变**"（不加任何 `choose` ⇒ 产物逐字节不变）是本仓**不可协商**的一条；§3.2 的"核心模式每维一次、库不许 `choose`"是它的形状。
⇒ VM **只能是显式写出来的一档**。

**而这条恰好是唯一能正面顶回 J1 的东西。** `docs/204:49` 给"字节码 + VM"记的代价是：

> 多了一层**永远存在**；启动与内存有底噪；能干什么受 VM 暴露面限制。

**"永远存在"就是当初拒它的实质理由**（另两条是它的推论）。`choose` 把它变成
"多了一层，**但你可以不要**"—— 而"要不要"这件事**写进产物**（§4.1）。
**它不是新机制，是既有的 `choose` 用在新的一维上。**

⚠ **2026-10-19：这一条被 LMS 绕过一次，留痕在这里**（`docs/253` §13.1 / `docs/269` §6）。
用户 2026-10-15 裁定「LMS 默认 = 满档」，而满档会**改变默认产物**：`alloc(<常量>)` 派生出的
`load8`/`store8` 上多一条内联界检查（`docs/269` §3.3）。所以：

* **§3.2 仍然是本仓的规则** —— 绕过它需要一次**明说的**裁定，而且必须记在**发现它的那份文档**里，
  不能只在 `docs/253` 自己那边写一句"我绕过了"；
* **这次绕过的边界**：变的只是**指令**（一条 `cmp` + 两个块），**没有新符号** ——
  `lomentc_test` 那条「默认档一点 `@__loment_` 痕迹都没有」**照旧成立**（`docs/253` §13.2 第三格）；
* **VM 那一维不受影响**：`choose vm` 仍然只能是显式写出来的一档，它与 LMS 是两件事。

⇒ 以后再有"默认要开一个会改产物"的裁决，照这一段办：**在 `docs/229` 这里留一行**，
而不是让下一份设计文档自己去说"那条已经不适用了"。

## 4. 剩下的两处空白

每处按同一格式：**是什么 / 最近前史 / 为什么可能还是新的 / 怎么证伪**。

### 4.1 执行模型**进产物**，而不是进构建脚本

* **是什么**：一份产物**声明**它是给 VM 的还是原生的，且第三方**不读源码**就能核。
  形状与 `mode` / `gc` / `runtime` / `port` **同一张表**（`tools/lomentc.py:976` `CORE_DIMS`）。
* **最近前史**：⚠ **Android ART** —— 唯一有"一份输入、三种执行模型共存、项目级开关"的系统。
  **V8** 是运行级自动升层，不是项目级选择。另见 §2.2 整张表。
* **为什么可能还是新的**：**ART 把执行模型当构建配置**（系统属性、服务），
  **这里把它当语义声明** —— 与"回收档""运行期有没有""通不通着世界"并列。
  别人优化的是"用哪种跑得更快"，这里要的是"**用哪种是可审计的**"。
* **怎么证伪**：找到任何一个系统，它的产物里带着一个第三方可核的字段说明"我是 AOT 还是解释执行"。
  找到 ⇒ 这一处不是新的。

### 4.2 **内部缺席**作为一等可验收主张

* **是什么**："这个产物里**没有**运行期 / 没有分配器 / 没有收集器"是一条**可被承认、可被拒**的声明，
  由**编译器强制**（不是运行期探测），并**印在产物里**。
* **最近前史**：**Wasm 的空 import 段**（最接近，但那是**接口的语法属性**）；
  **.NET CAS 的 `RequestRefuse`**（唯一明确尝试"我声明不要某权限"，**结局是被弃**，见 §4.3）；
  `absence property` 在形式化方法里是**既有词**（但那一脉是**证明**，不是编译器强制 + 产物可核）。
* **为什么可能还是新的**：
  1. **"内部组成"这一格没人做过** —— Wasm 管的是"不依赖外部实现"，不是"内部没有分配组件"；
     eBPF 是白名单；JVM 是类型良构；PCC 证的是策略，不是缺席。
  2. **证据是常规产物，不是额外生产的证明**（§2.3 末那条距离）—— PCC 那一族的成本位置完全不同。
  3. **它已经落地了，不是提案**（§3.4）：`no_runtime` 的强制、`gc_ladder` 的组成读数。
     "缺席"是"组成"的退化情形（`l3 = 0` 且不发分配器）。
* **怎么证伪**（`docs/225` §4.① 的 B 项，今天**已经查了**）：拿一个 Wasm 工具链，问它能不能给出
  一份"**这个模块内部没有 GC / 分配组件**"的、加载期可核的声明。
  **答复：不能** —— 空 import 段只声明不依赖外部实现，component model 也未新增这一机制。
  ⚠ 但**必须与 §3.3 分开**：**外部**缺席那一半（"我不导入 X"）**是补课**，不要一起主张。

### 4.3 被 **.NET CAS 的失败**盯上的一格（必须处理，不能绕）

**CAS 弃用的理由里有一条直接命中这件事**：`RequestRefuse` "需要你穷举不想要的权限"，
因此**不是有效的最小权限模型**。这句话打在**穷举式负向声明**上。

⇒ 必须把两类**分开**，否则 §4.2 会被引用成 CAS 的同伙：

| | 穷举式负向声明 | 产物自证缺席 |
|---|---|---|
| 例子 | `excluded "net"`、CAS `RequestRefuse` | `no_runtime`（**已强制**）、`gc_strict`（`docs/225` §2，**设计**） |
| 形式 | **你要穷举**你不想要的 | **算法自身的性质**：编译器要么发了那段 IR、要么没发 |
| 判据 | 靠人写全 ⇒ 漏一个就静默 | **可数**：`@__loment_alloc` 零出现 / `gc_ladder` 全零 |
| 状态 | **已被证不可靠**（CAS 的结论；`docs/218` §5 第一版独立撞到同一堵墙） | **没检索到对应物** |

> **分界线一句话**：**"我不要 X" 是穷举，靠不住；"我里面没有 X" 是可数的，靠得住** ——
> 后者不要求任何人写全一张单子。
