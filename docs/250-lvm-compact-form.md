## 1. 先把这一条自己的动机纠正过来（用数，不用形容词）

`docs/229` §5 假设 1 写的是"**那份 IR 已经是字节码**"，代价记成"**解析与体积**"。
两个都是可以量的，量出来是这样（2026-10-15，本机，`tools/lvm.py`，`lumtui_demo` ——
语料里最重的一份）：

| 量的是什么 | 数 |
|---|---|
| 输入文本 | **375 KB** |
| **文件级解析**（`lomelf.parse_ll`，整份跑一次） | 53 ms |
| 整趟（解析 + 执行） | **8.8 s** |
| ⇒ 文件级解析占整趟 | **0.6%** |

**所以"省下解析"这个说法，在 T0 的尺度上几乎什么都不是。** 但同一份程序的
**cProfile** 说贵的东西在别处：

| 函数 | 调用次数 | 占的时间 |
|---|---|---|
| `lomelf.parse_type` | **4,067,192** | 6.5 s |
| `lvm.Vm.operand`（解一个操作数的文本） | 2,687,762 | 累计 **12.1 s** |
| `lomelf.parse_operand` | 2,687,762 | 2.5 s |
| `str.startswith` | **23,008,525** | 2.2 s |

> **真正贵的是：每执行一条指令，就把那条指令的文本再解一遍。**

⇒ 这条假设的**表述要改**：不是"IR 已经是字节码"（它不是），而是
"**那份 IR 的每一条指令，每次被执行都要重新解码一次**"。这句话把 #328 的动机从
"省点解析开销"改成"**把解码从执行里拿出去，只做一次**" —— 而这两件事的判据、
量法与工作量都不一样。

⚠ **这一节的数只能用来说参考实现**（Python）。**镜像（Loment）花的不是同一种时间**：
它**已经在解析期把指令的种类算好了**（`docs/243` §5.1）。所以"紧凑形能省多少"**要在两处
各量一次** —— 拿一处的数去说两处的话，正是这一仓最常犯的那种错。

## 2. 形态：它是**那张 IR 的序列化**，不是第二门语言

`docs/232` §4.1 那句话（"VM 是同一份 IR 的第四个读者"）在这一格要**照旧成立**：
紧凑形**不新开一门语言、不新加类型系统**，它就是把解析器**本来就要建的那几张表**
直接写成字节。对照 `tools/lomelf.parse_ll` 的产物：

| 文本形里是 | 紧凑形里是 |
|---|---|
| `%v = add i32 %a, %b` 一整行文本 | `kind = K_ADD`、`dest = 值下标`、两个**操作数下标** |
| `%x`（SSA 名） | **值下标**（一张值表，名字只留一份） |
| `@name`（全局名） | 全局**下标** |
| `label %b1`（块标签） | 块**下标**（分支直接是号，不用再找） |
| `"add i32 %a, %b"` 里的类型 | 类型**下标**（池里去重） |
| 行序 | **块表**与**每块的指令区间**（与镜像的 `BLOCK_REC` / `INSTR_REC` 同构） |

**"种类在解析期算好"这件事，镜像已经在做了**（`docs/243` §5.1 第二条）—— 紧凑形是把
参考实现**拉到同一个位置**，并且把它**写进一个文件**，好让"解码一次"这件事**跨进程**
也成立。

### 2.1 形态**必须被记下来**（读的人不许猜）

文件头里有一个字段说明"**这是哪一种形**"。理由与 `choose vm` 那一维同一条
（`docs/229` 的新颖点 1）：**可核的组成** —— 一个产物是什么，要能读出来，
不能靠"它多半是……"。这条不难，但它是一条**判据**（§3 D）。

## 3. 判据

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | **恒等** | 语料**每一份**，紧凑形与文本形跑出来的 **stdout + 退出码逐字节相同**。这是"它只是序列化，不是第二门语言"那句话的全部证据 |
| **B** | **体积** | 点名一份程序（`lumtui_demo`），**前后两个数**写出来 |
| **C** | **速度** | **必须说清分母**："快了多少"要问"相对**哪个** T0"。参考实现与镜像各量一次（§1 末尾那条） |
| **D** | **形态可读** | 读文件头就能说出是哪种形；且**喂错形**时**点名拒**，不是当成文本硬解 |
| **E** | **孪生** | 两个实现从同一份 IR 编出来的紧凑形**逐字节相同**（`docs/158` §5 的老规矩）。⚠ 这条会把 Python 那侧的中间结构**按格式钉死**，代价写在 §5。**2026-10-17：E 随镜像那一半一起走** —— 见 §3.1 末尾与 #586 |

**A 是这一格的主判据**：它同时钉住"行为不变"与"两个形是同一个东西"。
D 与 E 是形状判据，B 与 C 是数字 —— 与 `docs/248` §6 同一条纪律：**每条 A 堆式的改动都要有
"选中的是哪个"与"快了多少"两样，只报快慢的判据测不出实现有没有走那条路。**

### 3.1 落地实测（2026-10-17）

实装在 `tools/lvm_compact.py`：**序列化的就是 T2 编译出来的那批 op**（`docs/259`）——
所以"解码"这一步在紧凑形里根本不存在，读进来就是编译好的东西。判据
`tools/lvm_compact_test.py`（4/4）：

| 判据 | 结果 |
|---|---|
| **A 恒等** | 语料 **9 份**：文本跑与紧凑形跑的 stdout + 退出码**逐字节相同**，**剖面也逐字节相同** |
| **B 体积** | `lumtui_demo` **375.9 KB → 107.0 KB（28.5%）**；语料里最差的一份 31.5% |
| **C 加载** | 文本路（解析+编译）81.7 ms → 紧凑路（解码）24.7 ms，**3.31×**。⚠ 只是**加载**，执行时间两边一样 |
| **D 形态** | 头四个字节魔数 + 版本 + 形态；文本与错版本都**点名拒** |

### 3.2 解码器的边界（0.1.4.7，#689–#693）

这一形的解码器原来只对"正常产物"成立：截断抛 `IndexError`、尾部垃圾被丢掉、流里的计数
直接被拿去分配、零全局往返丢长度。五条各自有一条判据（`tools/lvm_compact_test.py`）：

| 判据 | 钉住的东西 |
|---|---|
| **E 往返** | `encode(decode(encode(x))) == encode(x)`；全零全局的长度记的是 `size_of(ty)`，不是 0 |
| **F 计数** | `tag=0` 的 `ln` 必须等于声明类型的大小；`nslots` 不许超过"形参数 + 指令条数" —— 34 字节的产物曾要求 816 MB |
| **G 尾部** | 读完之后**必须正好**到末尾；这一形没有校验和，长度是它唯一的身份 |
| **H 截断** | 任意前缀都是 `CompactError` 并**点名段**（字符串池 / 全局 / 函数 / 指令）；池里非 UTF-8 也是它 |
| **I 可编码集** | `encode_ir` **序列化整份程序**，所以比懒编译的解释器窄一档：用了 T2 未实现指令的死函数，解释器收、编码器**点名拒**（错误里带那条指令） |

**I 是 #693 要的那条边界**：不把这条写下来，"编码器拒绝某份语料"就会看起来像回归，
而不是这一形本来的范围。

⚠ **第一版把体积做大了三倍**，值得记下来：`@__loment_heap` 是 **64 KiB 的
`zeroinitializer`** —— 文本里几个字符，我却按字节原样写进文件，于是 `tour` 的"紧凑形"
是文本的 **330%**（`all_loment` 383%），而 **stdout 照样全对**。判据 B 反向那条
（"每一份都必须比文本小"）就是为这个写的。修法：全零的全局**按"零"记**（写长度，不写字节）。

⚠ **E（孪生）不在这一格**：它要与"镜像的编译档"共用同一份格式，而镜像那一半是 #586
（0.1.5）。本格只交参考实现 —— 与 #325 拆成 #586 是同一个决定。

### 3.3 写/读入口与镜像缺口（0.1.4.7，#723 / #724）

这一形原先**没有使用者**：`lvm.py` 里没有任何开关碰它，只有自己的判据在编/解 —— 一条判据
钉住一个没人写的格式，等于什么都没钉。现在入口在解释器本身上：

| 开关 | 做什么 |
|---|---|
| `--compact-out PATH` | 入口 -> IR -> 紧凑形写进 `PATH`，**不跑**（stdout 为空） |
| `--compact PATH` | 直接跑一份紧凑形产物（与 `entry` 二选一；给文本文件会**点名拒**） |

判据（`tools/lvm_compact_test.py`，走子进程**真入口**）：写出的文件以 `LVMC` 开头、文本路与
紧凑路的 **stdout + 退出码逐字节相同**、错形与非零退出码、两个开关不能同时给。

**镜像那一半仍然没有**（`loment/tools/lvm.lomt` 里 `grep -i compact` 无匹配）。所以 §3 的
**判据 E 对它不适用** —— "紧凑形的判据全绿"只说明 Python 这一侧自洽，不是孪生过了。
这条推迟记在 `docs/158` 已知口子第 13 条，并由
`lvm_compact_test.py::test_the_mirror_is_still_deferred` **钉住**：谁把紧凑形写进镜像，
它就会红，逼着按 `docs/158` §5 四条同时改两个实现并补上逐字节对拍。

## 4. 明写**不做**的

1. **压缩**。这是**编码**，不是**压缩**：字符串池去重是结构性收益，**不是**为了把文件变小
   而想出来的招。真要压，那是另一件事、另一个开关。
2. **版本迁移**。v1 只管 v1。读到别的版本号就**点名拒**（§3 D），不许"尽力而为地猜"。
3. **校验和 / 签名**。那是发布链的事（`loment_release.py` 那一套），不进文件格式 ——
   进了就会有两个真源。
4. **让它承载剖面**。剖面**不进产物**（`docs/247` §3），紧凑形也不进。两件事的边界不许并。

## 5. 我不主张

1. **不主张体积就是卖点**。375 KB 里的大头是**文本**，省下来的是"同一个名字写了一遍又一遍"。
   先量（§3 B），再谈值不值。
2. **不主张它是 T0 的提速**。§1 末尾：那些数是参考实现的数，镜像的账**要另算**。
   把参考实现的 profile 当成"VM 慢在哪"是**换错了量**。
3. **不主张它必须现在做**。它进这一格的**唯一**理由是 `docs/229` §5 那句"**做完 T2 再改，
   T2 就要重写一遍**" —— 也就是说，它是为了**不让 T2 返工**才排在 T2 前面的。
   哪一天这个理由不成立了（比如 T2 先落地、且它的中间结构本来就不吃文本），
   这一格的排序理由要**重打**。
4. **不主张判据 E 免费**。为了让两个实现**逐字节相同**，Python 那侧不能再"顺便用它方便的
   字典"，得按格式写字。这是真代价，写在 §3 E 那一行里，别装作没有。
