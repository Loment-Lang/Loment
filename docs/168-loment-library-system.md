# 168 · Loment 库系统（Alpha2.1）

> 主题：为 Loment 建一套库系统。判据先行 —— 下面 §2 的五条是**验收标准**，
> 实现要证明的是它，不是"功能看起来有了"。

## 0. 一句话

**一个库 = 一个目录里的一堆 Loment 文件。** 系统要的东西，要么语言里已经有（`pub`、
`use`），要么是**推导**出来的（依赖、能力需求），要么是**生成**的（锁）。作者不需要学任何
新东西 —— 这是第一条判据，也是整篇的宪法。

## 1. 为什么不能照抄 pip / Maven / C

| | 它们的做法 | Loment 的处境 |
|---|---|---|
| 动态链接 | `.so`/`.dll` + 稳定 ABI | **Loment 库没有**：目标是 freestanding PE/ELF，单一 `_start`，没有动态装载器。（**外部库另算** —— `extern fn` 是另一个明确模式，见 `docs/173-loment-ffi.md`；它消费的恰恰是"看不看得到源码都行"的外部码） |
| 二进制分发 | 编译好的库 + 头文件 | **Loment 库不可能**：泛型是类型定向单态化的（`Result_i64_u32`），使用方必须看得到源码才能定出实例。**外部库不受这条约束** —— 它们本来就不是 Loment 源 |
| 版本区间 | PEP 440 / semver + 回溯求解器 | **不需要**（见 §3），这是被"身份 = 内容哈希"消掉的一整类复杂度 |
| 清单 | `pyproject.toml` / `pom.xml` —— **第二门语言** | 不许。清单要能是 Loment 自己（`.lomp`） |

借的：C 的"接口/实现不必是一份文件"（但 Loment 的编译器读源码，所以不需要头文件那种**会漂的
重复描述**）；Python 的"源码优先分发 + 锁文件"；Java 的"元数据随包走"。
**不借**：全局可变环境、版本区间语言、冲突消解策略、注册中心服务端。

## 2. 验收判据（五条）

1. **学完 Loment 不该再学新东西**。写库与写程序是同一件事：`pub` 导出、`use` 依赖。
   任何"写库要额外学一门语法/格式/工具"的设计，直接判负。
2. **实例身份 = Merkle 递归哈希**：`id(P) = H(自身源码 ⊕ {边名 → id(子)})`。
   只看自身源码是**错的** —— 同一份源码在两个构建里绑到不同的依赖上，语义不同却会被错误合并。
3. **能力需求沿依赖闭包向上推导**，不是作者声明的。`requires(P) = 自身 guard 的域 ∪ ⋃ requires(子)`。
4. **编译器不知道版本**。它只吃一个**扁平的实例集合**；版本、区间、选版是解析期工具的事。
5. **环在解析期检测**。Merkle 身份**替代不了**它：A 里 `use B`、B 里 `use A`，两边哈希都算得出。

## 3. 模型

### 3.1 依赖从源码来，不从清单来

依赖**不需要声明** —— 它就是源码里的 `use`。解析器读一个模块的边，跟读它的函数一样自然。
于是"依赖列表"这种东西在 Loment 里**不存在**，也就没有"声明与实际不符"这种错。

### 3.2 `.lomp` 是可选的标签文件

`.lomp` 是 Loment 源码（**复用**，不是新格式），只放**给人看**的东西：

```rust
module pkg

pub fn name() -> str {
    return "mathutil";
}

pub fn version() -> str {
    return "0.1.0";
}
```

**为什么是函数不是常量**：语言只有**整数**常量 —— `pub const NAME: str = "x";` 是语法错
（`期望 number（整数），得到 'mathutil'`，2026-09-15 实测）。所以标签写成 `pub fn ... -> str`，
零语言改动。**不为此新增字符串常量**：那是双实现（参考 + 自举镜）都要跟的语言特性，
而它对这个设计没有必要。

- **没有 deps 段**（依赖在源码里，见 §3.1）。
- **可选**：没有它就用目录名当包名、版本记为 `0.0.0`。
- 只认**字面量返回**：清单是标签，不接表达式 —— 免得逼出"清单能算多复杂"这种问题。
- 它的唯一机制作用是**告诉工具"这是描述文件，别当程序编"** —— 这也是它需要独立后缀的
  **全部**理由（按种类分，不是按文件名加例外；Go 用 `go.mod` 而非 `go.go` 同理）。
- **版本号对机器只是标签**：机器的身份是内容哈希。所以没有版本比较、没有优先级、没有区间。

### 3.3 多版本共存 —— 代价怎么解掉

**允许同一个库的多个版本同时存在于一次构建里。** 不靠任何运行期技巧：

- 每个**实例**有自己的身份（Merkle 哈希），身份不同的就是不同的实例；
- 实例被**物化**成各自独立的模块（本实现见 §4.2），编译器眼里它们是**不同名字的模块**，
  于是同名类型是**不同的名义类型** —— 把 v1 的 `Point` 喂给要 v2 的地方是**类型错误**，
  这正是对的；
- **相同子树自动去重**：五个包依赖同一版 = 一份实例。

于是语义冲突**由类型系统抓住**，而不是靠"选一个版本"去回避。

### 3.4 能力需求是算出来的

编译器看得见每一个 `guard` 和每一个 `capability` 声明，所以"这个包需要哪些能力"是
**可计算的事实**。工具把它**打出来**（含"哪一段来自哪个依赖"），而不是让作者手写一遍
再赌他写对了 —— **写错的声明比没有声明更坏**。

## 4. 实现

### 4.1 解析期（`tools/lomlib.py`）

```
loment lib tree        DIR            # 依赖树 + 每个库的实例数
loment lib id          DIR            # 实例身份
loment lib cap         DIR            # 能力需求闭包 (带来源链)
loment lib check       DIR            # 冲突检查 (同名顶层项 / 同名不同域 / 入口)
loment lib materialize DIR --out DIR  # 物化成编译器能直接吃的树
```

与 `tools/lompkg.py`（M57）的**分工**：lompkg 是旧模型（`pkg.json` + 逐包哈希），有
`loment/tools/lompkg.lomt` 孪生和**逐字节 stdout 判据**，所以**不动它**，新模型另起一层。
旧模型的缺口正是这里要修的：`pkg_hash` 只哈希自身文件、不含解析后的边（会被错误合并），
去重按 manifest 路径做（同名多版本共存不了）。

- 边从 `use` 来，用 `lomentc` 的前端读 AST 字段 `name_imports`（**不新增解析器**）。
- **名字形式 `use <名字>` 不带分号**（语言如此：`loment/examples/demo.lomt:13` 是
  `use mathutil`）。写成 `use x;` 会被解析期拒绝。
- 落点：消费方自己的 `deps/<名字>/` 优先，然后才是内置的四个根。`deps/` 里的东西**不算
  本包的源码**（不参与本包身份）—— 否则会凭空多出依赖边，并把 vendored 副本算进身份。
  （2026-09-20 补：名字形式现在也命中**包内模块** —— `deps/<包>/<名字>.lomt` 与
  `<store>/<包>/<版本>/<名字>.lomt`。包不只有入口那一个模块，`use vec` / `use fs` 走的就是
  这一层；规矩与既有的层一致，见 `docs/143` §2 的"模块导入"那一行与 `docs/199`。）
- 身份：递归哈希（判据 2）；环：深度优先，**解析期**报（判据 5）。
- 同名且同身份 = **去重成一份**（菱形依赖）；同名不同身份 = **两个实例**（多版本）并**报冲突**。

### 4.2 物化（materialize）—— 多版本共存就在这一层解决

物化把实例集合摊成一棵编译器能直接吃的树，三步：

1. **模块名**带身份后缀（`mathutil__7509dbd4`）；
2. **`use <名字>`** 改写成指向**它绑定的那个实例**的显式路径；
3. **顶层名**也带实例后缀（`scale` → `scale__7509dbd4` / `scale__2d54513b`）。

第 3 步是多版本共存的关键。编译器的发射符号是**平的**（`funcs[name]`/`structs[name]`，
见 `emit_llvm`），同一库的两个版本必然导出同名顶层项。**在物化这层改名，而不是去改编译器
内核**，换来的是：编译器完全不需要知道"版本"存在（判据 4），参考实现与自举镜的发射符号
一个字节都不用动 —— 也就不牵动逐字节 IR 一致与自举定点。

**改名的规则**（`_ident_edits`）：按 token 改（位置从词法器给的 `line/col` 还原），解析顺序
是「本实例声明 → 直接 `use` 的实例 → 闭包唯一提供者」。**只动顶层名**：

| 不动 | 为什么 |
|---|---|
| 字段名 `item`、字段访问 `s.item` | 作用域在结构体内部，两个实例各有一份也不撞 |
| 枚举**变体**名与变体位 `K::item` | 同上，作用域在枚举内部 |
| 字段初始化/形参/绑定的名字位 | 那里是新绑定，不是顶层名 |
| 局部变量（哪怕与顶层名同名） | 声明与引用会被**一起**改名，遮蔽关系原样保留 |
| `_start` | 链接器要找的入口名 |

**为什么这么改是保语义的**：同一个文件里一个名字只有一个解析结果，所以逐文件统一改名
要么不动、要么一致地动。**失败模式是响亮的** —— 万一漏改或多改，编译器报"未声明/未定义"，
不会静默编错。判据把它压到不能再压：物化出来的**每一份文件单独编都要过**
（`test_rename_preserves_field_variant_and_local_names`）。

**边界（唯一一条）**：一个文件**同时**要用两个版本的同名项时，语言没有限定名语法可用 ——
`lib check` 精确报出来、`lib materialize` 拒绝。**这不是"没做完"**，是这套模型里的真歧义：
多版本共存的前提本来就是"没有一个文件同时点两个版本的同名项"（app 用 mid1/mid2，
两个 mid 各自用自己那份 mathutil）。

**曾走过的弯路**（留档，别再犯）：`::` 在词法上是**两个 `:` token**，所以"前导 `::`"要往前看
两个；把 `::` 当成注解冒号会让枚举名漏改。而且编译器对**依赖模块**的模式只做跨模块检查、
不做函数体检查，所以那种"名字对不上"的错**在单文件编译时才暴露** —— 这正是为什么判据要
压"每一份文件单独编都要过"，而不是只看 app 能不能跑。

### 4.3 不做的事

- 不做注册中心服务端、不做全局安装、不做版本区间语言、**不把 Loment 库做成二进制分发**。
  （2026-09-16 收窄：原文只说"不做二进制分发"，容易被读成"Loment 不能碰任何二进制"。
  `extern fn` 那条路消费的就是二进制外部库，见 `docs/173-loment-ffi.md` —— 两者不冲突：
  一个是**库怎么发**，一个是**程序怎么调别人**。）
- **不新增语法**：`.lomp` 复用现成前端，不引入第二个解析器（引进了就要在两个实现里各写一遍）。
  （`extern fn` 是加在 **L1 语言**里的，不是 `.lomp` 清单里的 —— 这条不变。）

## 5. 已知边界（诚实清单）

- **改名是 token 级的**（§4.2）：规则列在上面那张表里，靠"作用域在类型内部的名字不动" +
  "逐文件统一改名"保语义。它有明确的失效路径（漏改/多改 → 编译器报未声明），但它是**这一层
  的实现方式**，不是语言保证 —— 真要语言级保证得让编译器按实例做名字解析（那时这层就该删掉）。
- **真歧义拒掉**：一个文件同时点两个版本的同名项 → 报出来并拒绝物化（§4.2 末）。
- **孪生只覆盖了 `id`**（`loment/tools/lomlib.lomt` + `loment_lib_test` 里的逐字节 stdout 判据）：
  `tree` / `cap` / `check` / `materialize` 还没有 Loment 版。**别把"孪生"读成"全等"** ——
  文件头写着同一句话。孪生程序不认得仓库内置的四个根，只认 `<包>/deps/`（它不知道自己在哪个
  仓库里跑），所以判据的场景只用 `deps/`。
- **写孪生时抓到一条既有 bug**：`loment/tools/lompkg.lomt` 的文件排序**方向写反**（成了降序），
  而它的判据夹具每包只有一个 `.lomt`，所以一直没暴露 —— 多文件包上两个实现给出不同哈希。
  已修，并给 `loment_pkg_test` 补了多文件包夹具（补夹具后先红、修完再绿）。
- **自举镜有两处与参考实现产出的 IR 不一致**（2026-09-15 写 `lomlib.lomt` 时被 p8 语料抓到）：
  ① **指针 + 整数**用运算符写时，镜发 `add ptr`，参考发 `getelementptr`；
  ② **混宽比较**（`load8(...)` 是 u32 对 `as u8` 的右值）两边选的比较宽度不同。
  本文件因此一律写 `ptr_add(p, n)`、比较两侧对齐到 u32 —— **不是风格, 是绕开镜的洞**。
  两个洞本身没修（那是双实现 + 自举定点的事），记在任务里。
- **实例会重复进二进制**：多版本共存意味着体积按实例数增长。工具**显示**它
  （`lib tree` / `lib check` 打印同名多实例），**藏起来的多份**才是问题。
- **`_start` 冲突**：依赖里也定义 `_start` 时 `lib check` 报、`lib materialize` 拒 —— 入口只能有一个。
  这条**不是**改名能消掉的（两个版本各带一个入口都是错的）。
- 物化会**改写源码副本**（不改仓库里那棵），报错行号指的是副本；`materialize-map.json`
  记了副本回原文件的映射。
- 本层**不碰** `lom/*.lom`（那是冻结的跨线契约），也不改 `lompkg.py`（它有孪生判据）。

## 7. 信任模型（0.1.5.2）

这一节回答三件事：**身份证明什么、锁证明什么、注册表被信任到什么程度**（#17）。

| 对象 | 它证明什么 | 它**不**证明什么 |
|---|---|---|
| 包身份（`sha256`） | 这一组文件的名字与内容**精确**是这些字节（长度前缀分帧，文件集到身份是单射，#15） | 谁发布的；内容是否安全 |
| 锁文件 | 某个身份在**某个本地 store** 里存在且字节一致（`lompi verify`） | 锁本身没被换过 —— 它和包常常来自同一个通道 |
| 带外钉（`--registry-sha256` / `--foreign-index-sha256` / `--lock-sha256`） | 被钉的那份字节**就是**你从另一个通道拿到的摘要所指的那份 | 摘要的来源本身可信（那取决于你从哪拿到它） |
| `lompi.conf` 里的钉 | 同上，但对这台机器上的每次调用生效 | |
| 保留名（`std` / `libl` / `host` / `internet` / `os`） | 项目本地的 `deps/<名字>` 不能顶掉工具链自带的同名包 | 其他名字仍可被项目本地覆盖 |

**规则。**

1. **明文 HTTP 索引默认必须带外钉住**（`docs/236` §7.1 / `docs/283` §7）。没有钉就拒装；
   只有 `127.0.0.1` 上的本地注册表可以用 `--insecure` 放宽。
2. **`--from-lock` 只做一致性检查**。要让锁成为信任根，必须另给
   `--lock-sha256 <64 hex>`：那是从**另一个通道**拿到的锁摘要。典型做法是让发布会
   用 GPG 对锁签名（`tools/loment_sign.py` 的同一把钥匙），把摘要写进发布说明，再由
   使用者手工传给 lompi。
3. **锁与注册表现在都钉字节，不钉发布者。** 仓里没有 Ed25519 实现，Loment 侧无法
   在包管理器内部验证发布者签名；这一层由发布侧的 GPG 签名 + 带外摘要承担，
   明确写成已知边界，而不是假装锁自带身份。
4. **注册表索引里的 `name` / `version` / `path` 是不可信输入**：名字与版本只允许
   `A-Za-z0-9._+-` 且不许以 `.` 开头，`path` 必须是包内相对路径（不许绝对、反斜杠、
   盘符、`..` 段）。任何一条不过就**整份索引拒掉**，不跳过该行（#981）。
5. **`lompi fetch` 打印的计划可以安全粘贴**：注册表 URL 先过形状/字符白名单，打印时
   每个值再加单引号，并统一用 `-- ` 结束选项（#14）。
6. **保留名在注册表与安装两处都拦**：索引条目、显式安装、闭包里的任意实例，名字落在
   保留集里就拒（#980）。

**格式变更（0.1.5.2，#15）。** 身份的分帧从 `名字 \0 内容 \0` 改成
`u32 名字长度 | 名字 | u64 内容长度 | 内容`。这会让**每一个已有包的身份都变**，
旧锁与旧身份不再验证通过 —— 这是修"两个文件集共享一个身份"的代价，不是漂移；
