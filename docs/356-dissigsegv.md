## 0. 一句话展开

Dissigsegv（DSG）要买的是 Python 的那条承诺，按本仓的方式落：

1. **范围**：只对**声明的安全子集**承诺。`extern fn`、裸系统调用内建、`load8`/`store8` 与裸指针算术是
   声明的 unsafe 面，和 Python 的 `ctypes` 在同一边。
2. **判决**：每个内存访问站点要么被**证明**合法、要么被**检查**合法。证不出来又不检查的站点，
   产物里必须标成 `unsafe`，整份 `no_segv` 声明随之降级。
3. **可见**：证明与检查的判决写进产物（`fault_ladder`），形状与 `gc_ladder` 同构。
   “不会段错误”因此成为一个**可核的缺席**，与 `no_runtime` 同一类主张。

LVM 在这个设计里是**执行档之一**，它的义务是保持这份契约。重写 LVM 既不是必要条件，
也覆盖不到默认的原生档。

## 1. Python 到底承诺了什么

### 1.1 承诺的形状

CPython 的保证来自**完全中介**：纯 Python 代码能触发的每一次内存操作，都走一个检查过前提的
C-API 原语；前提不成立就抛一个 Python 异常。具体三类：

| 违约 | CPython 的行为 | 机制 |
|---|---|---|
| 容器越界 | `IndexError` | 每次下标走 `PyObject_GetItem` 一类，先查长度 |
| 递归过深 | `RecursionError` | 每次调用进出计数（`Py_EnterRecursiveCall`），另有 C 栈上限 |
| 分配失败 | `MemoryError` | 分配器返回空，调用点抛异常 |

**未捕获**时是 traceback + 退出码 1。这条也很关键：承诺的最低形态是“一个定义好的错误”，
可捕获是它的加强版。

### 1.2 Python 也有段错误

`ctypes`、C 扩展、`mmap`、坏指针、C 层深处的递归，都能让 CPython 进程收到 SIGSEGV。
所以“像 Python 一样”的准确读法是：

> **安全子集内，错误的形态是语言事件；安全子集外，错误可以是信号。**

本仓已经有一句同义的话：`docs/206` §3 —— “线以内是编译期错误；线以外**不许是 UB**”。
DSG 是这句话的兑现物，先把“线”画出来。

### 1.3 三格对照

| | CPython | Loment 今天 | DSG 目标 |
|---|---|---|---|
| 谁做检查 | 每个 C-API 原语 | 只有除零 / `guard` / OOM / 根表容量 / `panic` | 每个安全子集访问站点：证明或检查 |
| 违约是什么 | Python 异常对象 | `ud2`（SIGILL） | `__loment_fault(kind, site, witness)` |
| 未捕获 | traceback + exit 1 | 信号，无可读信息 | 结构化 fault + 定义退出码 |
| 安全子集外 | `ctypes` / C 扩展 | `extern fn` / 系统调用内建 / `load8` | 声明清单，写进产物 |
| 能第三方核吗 | 不能，只能信实现 | 不能 | **能：逐站点台账** |

## 2. 前史先行

`docs/210` §1 的规矩：先点名，再说话。这一节的结论是：**“不段错误”本身不新，
“把判决逐站点印进原生产物”这一组合，没检索到现成物。**

| 系统 | 承诺 | 机制 | 洞 / 结局 |
|---|---|---|---|
| **CPython** | 纯 Python 不段错误 | 完全中介 + 异常 | `ctypes` / C 扩展 |
| **JVM** | NPE / 越界是 Java 异常 | 显式检查；HotSpot 对小偏移用隐式空检查（故意让 SIGSEGV 转成异常） | JNI / `Unsafe` / 本地库 |
| **Go** | 越界、空指针是 panic | 显式检查；`sigpanic` 把 Go 代码里的 SIGSEGV 转成 panic；栈增长 + 守卫页 | cgo；栈溢出是 fatal，`recover` 拦不住 |
| **Rust** | 安全子集内存安全 | 借用检查 + 越界 panic | `unsafe`；栈溢出 abort；标准库与编译器的健全性 bug（`docs/253` §1.1） |
| **Swift** | 越界是 trap | 检查 + trap | trap 不可捕获；`Unsafe*` 指针 |
| **.NET** | 越界 / NPE 是异常 | 托管检查 | `unsafe` / P/Invoke；`StackOverflowException` 不可捕获 |
| **Wasm** | 模块验证 + 线性内存 | 加载期验证；每次访存对线性内存做界检查或 trap | 没有原生指针；宿主函数是信任边界 |
| **eBPF** | 加载期证明内存安全 | 验证器沿所有路径模拟，证不了就拒 | 白名单式能力；不是通用语言 |
| **CHERI** | 空间安全 | 硬件能力指针，越界是能力故障 | 要新硬件 |
| **MTE** | 概率性检测 | 内存标签 | 概率性；要新硬件 |
| **SoftBound + CETS** | 空间 + 时间安全 | 编译器插桩 + 影子元数据 | 约 2× 成本；研究 |
| **Fil-C**（Pizlo 2025） | C/C++ 完备内存安全 | InvisiCaps + 并发 GC，释放原子作废指针 | 不 ABI 兼容；全运行期 |
| **Checked C / Cyclone** | 安全方言 | 边界 / 区域类型 | 要改写源码；ABI 变化；停滞 |
| **PCC / TAL** | 代码带证明，宿主验 | 生产方出证明，宿主验证 | 证明体积与生成成本；未普及 |
| **Wasmtime 一类** | 快速界检查 | 守卫页 + 信号处理 | 实现技巧；保证仍来自 Wasm 验证 |

三条主流路线：**改语言**（Rust / Cyclone / Checked C）、**付运行期**（sanitizer / Fil-C）、
**改硬件**（CHERI / MTE）。三条都贵，而且都假设“安全是给已有程序加上去的”。
本仓可以拿掉最后这条假设：语言是自己的，产物也是自己的。

**PCC 是最近的一条。** 它的形状（代码自带判决、宿主只验）与 DSG 相同；差别在**判决的粒度与形式**：
PCC 证的是整段代码在某个逻辑里的性质，DSG 只要求每个站点在**一张固定的小规则表**里挑一条，
把规则号与操作数写进产物。前者要定理证明器，后者是一个模式检查器。

## 3. 今天的 Loment：段错误的入口

### 3.1 逐条

| 入口 | 今天 | 证据（本检出） |
|---|---|---|
| 数组下标 `a[i]` | **没有任何检查** | `_Ir.expr` 的 `Index` 支，`tools/lomentc.py:5664` 发 `getelementptr inbounds` |
| 切片下标 `xs[i]` | **没有任何检查**，长度就在切片值里却不比较 | 同处，`:5650`；切片是 `{ ptr, i64 }`，第二个字段从没被读 |
| 指针偏移 `p + k` | 没有检查 | 与 `load8`/`store8` 同路，`:5814` / `:5825` |
| `load8` / `store8` | 裸访问，按设计 | `:5810` / `:5820` |
| `syscall4` / `syscall6` | 裸系统调用，按设计（个别工具链版本是 `syscall7`） | `:5891` / `:5898` |
| `extern fn` | 外部代码，按设计 | `docs/173` |
| 栈耗尽 | 没有探针 | 后端不插栈检查（`alloca` 只在 `:5292`） |
| 堆耗尽 | `__loment_alloc` 的 `boom` → `__loment_abort` | `:213-215` |
| 根表容量 1024 | `__loment_abort` | `:5474-5478` |
| 除零 | `__loment_abort` | `:5761-5770` |
| `panic` | `__loment_abort` | `:5907-5909` |
| 能力域 `guard` | `__loment_abort` | `:6174-6188` |

### 3.2 现有的“trap”也是信号

`__loment_abort` 的定义在 `tools/lomentc.py:118`：

```llvm
define internal void @__loment_abort() {
  call void @llvm.trap()
  unreachable
}
```

`lomelf` 把 `@llvm.trap` 降成 `ud2`（`tools/lomelf.py:1081` 特判，`:1463` 发 `0F 0B`）。
`ud2` 在 Linux 上是 **SIGILL**，在 Windows 上是非法指令异常。后果有三条：

1. 进程被信号杀死，调用方拿不到退出码以外的信息；
2. 与“编译器自己发出的坏指令”无法区分；
3. 不能捕获、不能恢复，连“打印一行再退出”都做不到。

所以今天连“已有的 trap”都不满足 Python 的最低形态。把 `ud2` 换成一条定义好的 fault 通路，
是 DSG 最便宜的第一步，**不加任何检查**就能把五处 `ud2` 变成可读的退出。

### 3.3 三条探针（本检出实跑）

源在临时目录，编译器 `python tools/lomentc.py <源> --print llvm`，三条都**退出码 0、无诊断**。

**(a) 字面量越界：`[u32; 4]` 取 `a[10]`**

```llvm
%t5 = getelementptr inbounds [4 x i32], ptr %a.addr, i32 0, i32 10
%t6 = load i32, ptr %t5
```

`10` 落在 `[4 x i32]` 上，还带着 `inbounds`。走 clang 时优化器有权假设不越界；走 `lomelf`
时它不实现 `inbounds` 语义，直接算出地址踩过去（`docs/253` §4.4 已记过同一条）。

**(b) 切片动态下标**

```llvm
%t2 = extractvalue { ptr, i64 } %t1, 0     ; 只取指针
%t3 = load i32, ptr %i.addr
%t4 = getelementptr inbounds i32, ptr %t2, i32 %t3
%t5 = load i32, ptr %t4
```

长度（`extractvalue ..., 1`）一次都没被读。**这条最便宜**：检查所需的长度已经在手里，
只差一条 `icmp` 与一个分支。

**(c) `load8(p, 4)`**

```llvm
%t2 = getelementptr i8, ptr %t1, i32 4
%t3 = load i8, ptr %t2
```

这条没有 `inbounds`，但仍然没有任何界的信息。它属于 unsafe 面。

### 3.4 一句必须说准的话

`docs/205` C5 写着“越界在字面量时编译期拒、非字面量时运行期 trap”。这句话对**能力域 `guard`**
是真的（`docs/253` §4.4 逐格核过）；对**数组与切片下标**不成立。本节的三条探针就是它的反例。
DSG 的第一件事是把这句话的覆盖面说准，第二件事才是补上缺的那一半。

## 4. 不可能性（先写死）

**A.** “完备”要求每一次内存访问都被证明合法、或被检查合法。

**B.** 证明合法 = 判定“这个指针指向的块还活着，且偏移在界内”。别名问题不可判，“活着”是运行期事实
⇒ **静态完备不可能**（Rice 那一族；`docs/253` §2 已把这条链写全）。

**C.** 退到运行期检查 ⇒ 每次访问都要知道边界与身份 ⇒ 必须有元数据。

**D.** 元数据只有三条出路：进指针（胖指针 / 能力）、出带外（影子内存）、进硬件（tag）。
三条各付一样东西：ABI 与类型、运行期成本、新芯片。

**E.** 于是这条链是闭合的：

> **完备 + 零成本 + 不改语言 + 保留任意 FFI + 没有 unsafe 面。**

DSG 拿掉其中三条：

| 假设 | 怎么拿掉 | 代价 |
|---|---|---|
| **不改语言** | 语言是自己的；能力域 `(space, lo, hi, revocable)` 已经在语言里（`docs/146`） | 无额外代价 |
| **一种机制打天下** | 判决拆到**每个站点**，产物逐条记账 | 台账体积与校验器 |
| **安全是运行期行为** | 判决印进产物，离线可核 | 编译器与校验器两套实现 |
| **必须覆盖 FFI** | 声明 unsafe 面，`no_segv` 只覆盖安全子集 | 承诺范围变窄，但说清楚了 |

剩下必须付的：**检查或证明的成本**。这条没有免费的解，只能逐站点选择付哪一边。

## 5. 设计：四层 + 一个 ABI

### 5.1 四层

| 层 | 名字 | 做什么 | 失败时 |
|---|---|---|---|
| **L0** | 证明（prove） | 用固定规则表证“这次访问在界内且块活着” | 证不出 ⇒ 降到 L1 |
| **L1** | 检查（check） | 发射比较与分支；不成立跳到 fault 边 | `__loment_fault(...)` |
| **L2** | 围栏（fence） | 栈上限检查；守卫页 + 备栈信号兜底 | 转成 F04 / F09 |
| **L3** | 声明（declare） | unsafe 面清单 + `fault_ladder` + 校验器 | `no_segv` 降级或拒绝 |

L0 与 L1 的分界是**成本**：证明不花钱，检查花钱。L2 是**检查覆盖不到时的兜底**，
尤其是栈耗尽与“编译器自己发出的坏地址”。L3 是**承诺的边界**：它让“安全子集”成为一个
可判定的集合，而不是一句形容词。

### 5.2 fault 类

码号是提案，未进 L0 契约。命名空间与编译期 `E0NN` 分开，避免两张表混读。

| 码 | 名字 | 触发 | 层 | 今天 |
|---|---|---|---|---|
| **F01** | BOUNDS | `a[i]` / `xs[i]` / `p+k` 越界 | L0/L1 | 无检查 |
| **F02** | DANGLING | `free` 之后使用 | L0/L1/L2 | 只有 E029 的同一函数字面情形 |
| **F03** | NULL | 空指针解引用 | L1 | 语言无空字面量；FFI 归 unsafe |
| **F04** | STACK | 栈耗尽 | L2 | 无 |
| **F05** | OOM | 堆耗尽 | L1 | `ud2` |
| **F06** | DIVZERO | `/ 0` / `% 0` | L1 | `ud2` |
| **F07** | GUARD | 能力域越界 | L1 | `ud2` |
| **F08** | PANIC | 显式 `panic` | L1 | `ud2` |
| **F09** | INTERNAL | 不该到达的分支 | L1 | `ud2` |
| — | FOREIGN | unsafe 面内的故障 | L3 | 信号 |

**整数溢出不在表里。** LLVM 的 `add` 不带 `nsw`/`nuw` 时是定义好的回绕；回绕后的下标若仍在界内，
不会产生 SIGSEGV，只会产生错误的元素。要 Python 的整数语义是另一条轴（检查算术），
与 DSG 的“不段错误”分开算。

### 5.3 fault ABI

```rust
// 提案：一个 noreturn 函数，替换全部 __loment_abort 调用点
__loment_fault(kind: u32, site: u32, witness: ptr) -> noreturn
```

- `kind` 是 §5.2 的码；
- `site` 是站点的稳定编号（见 §6.2），用于把消息指回 `文件:行:列`；
- `witness` 是可选见证（例如 F02 的“在哪个站点被 `free`”，块头已有这个字段，见 `docs/253` §5.2）。

输出形态（提案）：

```
loment: F01 bounds violation at site 12 (src/x.lomt:7:18)
  index=10 length=4
```

进程退出码提案 `100 + kind`（F01 ⇒ 101）。这样测试可以断言一个确定的数，
而且与 `128 + 信号` 的区间不撞。Windows 侧走同一条 ABI，stub 用 `WriteFile` + `ExitProcess`。

**`no_runtime` 的张力**：fault 通路需要代码。解法是把它定义成一段**固定的、只含系统调用的
stub**（Linux 上是 `write` + `exit_group`，PE 上是 `WriteFile` + `ExitProcess`），
大小与哈希记进产物，并声明为 `no_runtime` 唯一允许的运行期组件。要连这段都不要，
就只能回到 `ud2`，那是 `sigsegv_close_admin` 档。

### 5.4 栈：三个选项

| 选项 | 成本 | 可移植性 | 能恢复吗 | 前史 |
|---|---|---|---|---|
| **深度计数** | 每调用一次增减 | 好 | 能（抛错后回到调用点） | CPython 的 `RecursionError` |
| **入口比较栈指针** | 每调用一次比较与分支 | 需要每 OS 初始化栈界限 | 不能，只能定义退出 | GCC `-fstack-check` 一类 |
| **守卫页 + 备栈信号** | 每调用零成本 | OS 相关 | 不能，只能定义退出 | Go / HotSpot 的兜底 |

建议：**入口比较栈指针**做主力（可移植、可预测），**守卫页 + 备栈**做兜底（覆盖 `alloca` 大帧与
外来帧），**深度计数**只进 debug 档。诚实边界：栈耗尽在一般情况下**不能恢复**，
DSG 对它承诺的只是“定义退出”，与 CPython 的 `RecursionError` 相比少一档。

L2 的信号处理只做一件事：在备栈上判断故障地址是否落在栈界限附近，是则走 F04，
否则走 F09（INTERNAL）。它必须 async-signal-safe：只写固定的字节，不分配、不加锁、不回溯。

## 6. 产物里：`fault_ladder`

### 6.1 形状

与 `gc_ladder` 同构，逐站点：

```
fault_ladder: [
  { site: 12, op: "index", grade: "checked", kind: "F01" },
  { site: 19, op: "index", grade: "proven",  rule: "R2"  },
  { site: 33, op: "raw",   grade: "unsafe"  }
]
claim: no_segv = (所有安全子集站点 ∈ {proven, checked}) ∧ (每条 checked 有 fault 边)
```

`no_segv` 的读法要与 `docs/225` §4.① 的“可验证的缺席”一致：
**它不是“跑起来没崩”，是“这份产物里没有一条能让安全子集走到信号的路”。**

### 6.2 证明规则表（L0）

`proven` 不许是一个自由标签。它必须引用一条**可被校验器复查的规则**，否则编译器应当发检查。
第一版只收四条：

| 规则 | 形状 | 校验器查什么 |
|---|---|---|
| **R1** | 常量下标 + 常量长度 | 下标 `<` 长度 |
| **R2** | 规范循环 `for i in 0..N { a[i] }`，且 `len(a) == N` | 循环上界与长度是同一个常量 / 同一个 SSA 值 |
| **R3** | 支配分支 `if i < len { a[i] }` | 分支条件与访问在同一基本块链上，且条件蕴含下标在界 |
| **R4** | 生命周期证明 | 该站点对应的块在 `gc_ladder` 里是 `L1`/`L2`，且没有跨过 `free` |

R2/R3 是**模式**，不是定理。它们抓的是绝大多数真实循环；抓不到就发检查（L1）。
这条与 eBPF 的“证不了就拒”同构，只是粒度从整程序降到站点。

**R4 是与 `gc_ladder` 的交叉点**：一条“这块内存还活着”的证明，必须能指到回收账上的具体一层。
两张台账对不上，校验器应当红。这是本仓已有的“两条账交叉”手法（`docs/253` §1.4 的后半句）。

### 6.3 站点编号

站点编号在类型检查之后、优化之前分配，一张映射表随产物走。优化器可以删除站点、合并站点，
但必须同步更新台账；**不许出现“台账里有、IR 里没有”或“IR 里有、台账里没有”**。
这条与 DWARF 行表的稳定性是同一类工程问题，`docs/190` 的调试信息那套可以复用。

### 6.4 落点

`fault_ladder` 是**单元的编译期性质**，与 `gc_ladder` 一样属于 Potato 的“这个单元是什么”。
建议加一档 Potato 维度（`vN` 的 `fault`）。六处登记按既有清单走：
`tools/potato.py`、`tools/lomentc.py:emit_potato`、`loment/selfhost/potato.lomt`、
`loment/tools/lompotato.lomt`、`tools/potato_test.py`、`docs/147` 的版本表。
这是契约变更，按 `docs/158` 单独一次提交；新版必须进 `_cases()` 的整组夹具，
否则孪生判据会“绿着却从没比过”（2026-11-13 实测过的那条坑）。

## 7. LVM 的位置

### 7.1 为什么改写 LVM 不在关键路径上

LVM 是 0.1.6 的执行档（`docs/229`），默认档是 `no_runtime` 的原生代码，`choose vm` 才会走它。
默认路径上的段错误由 `lomentc.py` 的原生发射器产生；把 LVM 重写一遍，默认档一个字节都没变。
DSG 的契约因此必须住在**IR/降级层**，LVM 只背“保持它”。

### 7.2 每一档的义务

| 档 | 义务 | 判据 |
|---|---|---|
| **T0 解释器** | 每个字节码访存走宿主侧检查原语；加载时核对台账 | 同一程序在 T0 与原生产物上给出同一 fault 码与 site |
| **T1 剖面** | 不改变语义，不改台账 | 关掉剖面 ⇒ 产物逐字节不变 |
| **T2 基线** | 检查一条不少 | 台账逐条相同 |
| **T3 优化** | 只许用 R1–R4 把 `checked` 升成 `proven`；去优化必须恢复检查边与 fault 状态 | 去优化后 fault 码与 site 相同 |
| **T4 回收** | 收集器自己的写不得违反台账 | 台账与 `gc_ladder` 交叉一致 |

T3 的那条是唯一有新意的：**优化器可以删检查，但删掉的每一条都要有规则号**。
这与 `docs/298` §1.3 的 f2“边界检查消除（复用 LMS 的证明面）”正好对接：
f2 需要一个可核的证明面，DSG 提供它。

### 7.3 如果默认执行档换成 LVM

那会变成 Python 的字面形状：所有访存都在解释器里过检查，段错误从构造上消失。
代价是 `no_runtime` 与原生档一起失去。这是产品决定，不是本设计的一部分；
本设计只把两条路的共同契约写出来，让这个决定可以在数据上做。

## 8. 开关与默认（待裁定）

| 决定 | 选项 | 建议 | 理由 |
|---|---|---|---|
| **范围** | 安全子集 / 全语言 | 安全子集 | 全语言会把 FFI 也算进去，那是做不到的承诺 |
| **交付** | 定义退出 / 可捕获 | 先定义退出，后可捕获 | 第一期不改语言面；Python 未捕获时也只是退出 |
| **开关** | 新维 `sigsegv_*` / `lms` 子开关 | `lms` 子开关 | 同一根轴（碰错了怎么办），避免新开核心维 |
| **默认** | `open` / `close_admin` | `open` | UB 程序没有已定义行为可保；其余程序字节不变 |

**与“默认档不改行为”的冲突要正面结账。** 今天的越界程序是 UB，没有“现有行为”可言；
加检查会让它们从“静默踩内存”变成“fault 退出”。这不是改变一个已定义程序的行为，
是把一个未定义的东西定义掉。其余安全子集程序在执行路径上只多一条可预测的分支。

关闭必须带 `_admin`（`docs/262` §10.1，仓级规则）。取值提案：
`sigsegv_open`（默认）/ `sigsegv_close_admin`（回到 `ud2`，产物里记一笔）。

## 9. 代价（没测的写没测）

| 项 | 预计 | 状态 |
|---|---|---|
| 边界检查 | 每次访问一条比较与分支；紧凑循环里通常几个百分点到几十个百分点 | **未测** |
| 栈上限检查 | 每次调用一条比较与分支 | **未测** |
| 台账体积 | 每站点约 8–16 字节 | **未测** |
| fault stub | 固定的一小段系统调用序列 | **未测** |
| 证明面比例 | 决定实际付多少检查钱 | **未跑**（与 `docs/225` §4.② 同一个数） |

测量计划：用 `docs/298` 那组已有负载（hello / 数行 / 素数筛 / 求和），固定迭代次数，
交替跑 N 次取中位数；判据用 IR 指令数或固定迭代下的稳定计时，**不拿墙钟比值当门禁**
（同一个量在机器间散布很大，`#442` 的教训）。证明面比例单独跑一次，
把“R1–R4 覆盖多少站点”印出来，作为检查成本的先行指标。

## 10. 判据

| # | 判据 | 证伪方式 |
|---|---|---|
| **1** | 每类 fault 一条负例：`returncode == 100 + kind`，stderr 含 site，且 `returncode >= 0` | 任何一条以信号结束 ⇒ 红 |
| **2** | 产物校验器：删掉一条检查 ⇒ 校验器红 | 删了还绿 ⇒ 判据是空的 |
| **3** | 跨档一致：原生 / `lomelf` / LVM T0 对同一程序给出同一 fault 码与 site | 任一档不同 ⇒ 红 |
| **4** | 台账完备：IR 里每个用户下标的 GEP 都有条目 | 漏一条 ⇒ 红 |
| **5** | 模糊：安全子集内随机下标与分配大小，零信号 | 出现一次信号 ⇒ 红 |
| **6** | 范围声明：含 `extern fn` / 系统调用内建 / `load8` 的单元，`no_segv` 为假或列出 unsafe 站点 | 声称 true 而含 unsafe ⇒ 红 |
| **7** | 成本：固定迭代下的稳定计时，记录 N 次中位数与 IR 指令数 | 用墙钟比值当门禁 ⇒ 判据本身红 |

判据 2 与 5 必须先**在未修的代码上跑红**（把检查关掉 / 用今天的产物跑），否则它们只是
“下游替它们挡了”的空判据（2026-10-14 的教训）。

## 11. 我不主张

1. **不主张整语言不可能段错误。** `extern fn`、系统调用内建、裸内存、硬件故障、外部 `kill -SEGV`
   都在承诺之外。能做到的是“安全子集内错误形态是语言事件”,这正是 CPython 的承诺。
2. **不主张机制是新的。** 完全中介、边界检查、守卫页、能力、PCC、eBPF 验证器都有人做过。
   本页的组合（逐站点判决 + 固定规则表 + 进原生产物 + 与回收台账交叉）没检索到现成物，
   但“没检索到 ≠ 没有”。
3. **不主张性能。** §9 全部未测。检查成本可能让紧凑循环明显变慢；这是 DSG 的价格，
   要由测量而不是直觉来定价。
4. **不主张编译器自身安全。** 自举编译器是另一个 Loment 程序，它自己的固定容量越界
   仍然可能让它崩。DSG 能让那类 bug 变成带 site 的 fault，前提是编译器自己也用 DSG 档编。
   这是 dogfooding，不是保证。
5. **不主张第一期可恢复。** 第一期只做到定义退出与可读消息；可捕获需要语言面新构造，
   是另一条线。
6. **不主张 LVM 是答案。** 默认档是原生；重写 LVM 覆盖不到它。
7. **不主张码号已定。** `F01`–`F09` 与退出码 `100+kind` 是提案，未进 L0 契约。
   真要进 L0，按 `CLAUDE.md` 的冻结阈值单独一次提交，并写下游影响。
