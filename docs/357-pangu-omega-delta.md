# 357 · PANGU Ω 的真实增量：LMS 与 Loment 安全的三件产物

> 状态: **研究稿**（2026-11-20），未实装
> 基准: `origin/main` `a460b90e`（2026-11-20）；写作时的本检出落后 origin **1727 个提交**，
> 所以本文的"今天"一律指 origin，不指本地树（`docs/253` §5.1 那条教训）
> 上游: `docs/253`（LMS 七级）· `docs/262`（LSPE）· `docs/270`（LMS 落地记录）·
> `docs/320`（权能时序安全）· `docs/328`（授权时序安全）· `docs/344`（LSPE 框架）·
> `docs/356`（Dissigsegv）· `docs/225`（可验证的缺席）· `docs/245`（真线程）· `docs/147`（Potato 版本台阶）
> 一句话: **PANGU Ω 七层里五层在仓里已有对应物；可落的安全增量只有三件 ——
> 法域封印、独立验证器、创世授权衰减。执行层的"因果织网"不进执行平面。**

---

## 0. 结论先行

把 PANGU Ω 逐层对着 origin 读一遍，能落成代码的句子只有三句：

| # | PANGU 的句子 | 今天 | 本文的判断 |
|---|---|---|---|
| 1 | **Lawspace**：宇宙的规律是一等对象 | 九维 `choose` + Potato v23 + v20 `systems` —— 规律**已经是**产物里的对象 | 补上**范围与排除**，再盖一个封印（§4.1） |
| 2 | **独立的 PCO Verifier，避免 LSPE 自我证明** | E7 比的是两份编译器实现一致；台账由同一个包产出 | **真空白**，三件里最该先做（§4.2） |
| 3 | **子宇宙不继承父宇宙的全部权限** | 只有 `thread_spawn`，共享地址空间与全部权能 | **真空白**，最贵（§4.3） |

其余五层与四条原则，要么已经成立（`law over instruction`、`proof over trust`），
要么是半成立（`identity over address`），要么不该在安全这条线上做
（`causality over sequence` 在**执行**平面，§5.1）。

**对提案本身的判断**：PANGU Ω 是一份**目标架构**，不是一份安全设计。
它最大的问题不在这五条原则，在于**通篇没有一个攻击者**。没有威胁模型的"安全架构"
只能产出形容词。本文先补威胁模型（§2），再把写不出判据的部分明确关掉（§5）。

## 1. 逐条对账：PANGU 的层与原则，仓里各有什么

### 1.1 七层

| PANGU 层 | 仓里的对应物 | 状态 |
|---|---|---|
| L0 Physical Substrate | 宿主硬件 / OS | 不在仓内 |
| L1 **PLO** Low Engine | 原生档（`lomentc.py` → IR → `lomelf.py`）+ LVM T0–T3 | **已存在**，PLO 是它的重新描述 |
| L2 **Genesis Engine** | 编译器 + 自举链 + Potato 发射 | **已存在** |
| L3 **PCO Lawspace** | `choose` 九维（`mode/gc/runtime/port/vm/lms/lspe/lifetime/fp`）+ Potato v23 | **已存在约 80%**（§1.2） |
| L4 **Universe Runtime** | LGC + LMS + 能力域 + LSPE + Dissigsegv（研究稿） | 四件已有，一件未实装 |
| L5 **Recursive Genesis** | `thread_spawn`（共享地址空间、无衰减） | **空**（§4.3） |
| L6 Cosmological Ecosystem | 无 | **空**，且没有威胁模型（§5.3） |
| LSPE Ω Governance | LSPE 14 义务 + 证据格 + 调度器 + 台账 | **已存在**，审查点全在**编译期** |

"Genesis Engine" 这个位置在 PANGU 是 L2，而 LSPE Ω 要到 P3 才接进来。
这个顺序在安全上是反的：**创世那一刻要检查什么，必须在创世之前定义**。
本文把"创世时的授权衰减"单独提出来（§4.3），就是把这个顺序正过来。

### 1.2 为什么说 Lawspace 已经有了

Potato 的九维里，每一维都是一条**可读的规律**，不是注释：

| 维 | 取值 | 产物字段 | 出处 |
|---|---|---|---|
| `runtime` | `no_runtime` / `runtime` | 顶层 | `docs/227`；**强制**"产物里没有那段运行期" |
| `gc` | 三档 + `gc_ladder` | v10 | `docs/210` |
| `lms` | 四档 + `lms_levels` + `lms_budgets` | v15 / v17 / v18 | `docs/253`、`docs/270` |
| `lspe` | 台账 + 证明根 | v16 | `docs/262` |
| `lifetime` | 三档 | v22 | `docs/299` |
| `fp` | `no_fp` / `fp` | v23 | `docs/348` |
| — | **系统索引** `systems`：六系统 × `{state, detail, cost}` | v20 | `tools/potato.py:155`、`:275` |

`systems` 那一条已经把"这份产物有哪个系统、明细在哪、数是多少"做成了
**校验器不读源码就能判**的三方一致（`tools/potato.py:275`）。
这就是 Lawspace 的骨架。缺的是三格（§4.1）：**义务、排除、封印**。

### 1.3 五条原则逐条判

| 原则 | 今天成立吗 | 依据 |
|---|---|---|
| **Law over Instruction** | **成立** | `choose` 是硬写法的核心模式；`no_runtime` 是一条被强制检查的保证（`docs/227`） |
| **Proof over Trust** | **成立** | 14 条义务、8 种证据、证据子集格上的定点求解、`proof_root` 进 v16 台账 |
| **Identity over Address** | **半成立** | `&T` / `ref T` / `ptr` 三态已写死（`docs/320` §5.2）；`ref` 的 S1 只有有界槽（§12） |
| **Causality over Sequence** | **执行平面不成立，证明平面成立** | LSPE 的阶段 DAG 与证据偏序已经是因果结构（`docs/344` §2.3）；LVM 与原生档都是顺序机 |
| **Genesis over Execution** | **空** | 只有 `thread_spawn`（`docs/245`），没有子进程/子域的权限面 |

第三行的"半"要说得更准：`docs/320` §5.3 已经把对象表与槽表的分工写清楚了
（有界槽用槽表、堆对象用对象头、栈对象靠静态区域、外部对象用外部句柄），
但那是**最终态**，S1 只落了有界槽的槽表。按地址还是按身份，今天仍然由引用形态决定，
产品里没有一条"这份产物不用宿主地址做身份"的可读断言。

## 2. 威胁模型（PANGU 缺的那一页）

安全的命题必须点名**谁对谁**。按 Loment 今天能表达的东西，攻击面只有四类：

| 类 | 攻击者 | 被攻击者 | 今天的覆盖 | 判据形态 |
|---|---|---|---|---|
| **A** | 有 bug 的非恶意程序 | 自己的进程 | LMS 七级 + DSG（研究稿） | 错误变成**语言事件**（fault 码 + 站点） |
| **B** | 恶意 Loment 程序 | 宿主 / 其它进程 | 能力域 + `excluded` + syscall 白名单 | 越权调用被拒，且**来源可点名** |
| **C** | 恶意**子宇宙** | 父宇宙 / 兄弟 | **无** —— 创世不存在 | 子集性、不继承、递归衰减（§4.3） |
| **D** | 被污染的编译器 / 工具链 | 全部产物 | 信任地板（`docs/270` §4：种子 + 字节数 + 哈希） | 三方判据 + 种子可复现 |

关键推论：

1. **PANGU 唯一新增的威胁面是 C。** A 已有 LMS/DSG，B 已有能力域，D 已有地板命名。
2. C 在创世能力出现之前**不存在**。所以"创世"与"授权衰减"必须同一天落地，
   否则等于给 B 类攻击者新开一扇不设防的门。
3. L6 的"多宇宙生态"在这张表里**没有格子** —— 它不增加任何一条可判性质。

## 3. 不可能性（先写死）

**I1 · 因果织网不产生安全性质。**
把全局程序计数器换成因果偏序，改变的是**调度**；"这个站点凭什么碰这块内存"的答案
一个字都不会变。任何"因果"陈述要能落成一条可判的偏序（谁依赖谁、依赖的见证是什么），
否则它只是形容词。证明平面的偏序已经存在（LSPE 证据格）；执行平面的偏序要另付一笔
确定性与热更新的账（§5.1）。

**I2 · 独立验证器不能与编译器共享代码路径。**
共享一行 import，自我证明就回来了一行。完全独立意味着**重新实现 IR 语义的一部分**
（至少是规则表与索引恒等式），两份实现必然漂（`docs/158` §5 的自举双实现就是先例）。
所以独立验证器必须配**第三条判据**：对拍只证明两份实现一致，证明不了其中一份对
（`docs/349` 的语义 oracle 是这条判据的起点）。

**I3 · 权限不继承要求权限集可静态枚举。**
动态生成的权能不能被父宇宙审批，也不能进封印。所以 G1（子集性）只对**声明式 capset**
成立；运行期"临时造一张新权能"的能力，必须在创世前就存在，否则这条性质不成立。

**I4 · 快照/迁移要保持证明有效，证明只能依赖产物内可重建的事实。**
任何依赖运行期状态的证明（第 2 级管理器的堆快照、LVM 的栈）在快照后都失效。
`no_runtime` 产物的"快照"就是重新执行；有意义的快照只在 LVM 档成立，
而 LVM 今天不是默认执行档。

**I5 · 完整性的根集必须点名（继承 `docs/320` I2）。**
寄存器、栈、堆、FFI、内核、网络，副本可能藏在这些地方的任意一处。
Lawspace 的封印也只能覆盖产物里的站点；FFI 之后的世界是声明的地板。

## 4. 三件真增量

### 4.1 法域封印：Lawspace Seal

**现状。** `systems`（v20）说"有哪个系统、明细在哪、数是多少"；
`lspe`（v16）说"审计过哪些站点"；`lms_levels`（v17）说"实际开了哪几级"；
`lms_budgets`（v18）说"每一级要不要运行期"。
四张表合起来，仍然回答不了三个问题：

1. 这份产物的**安全承诺**是哪几条？（`no_runtime`、未来的 `no_segv`、`lms_full`…）
2. 每条承诺**排除了什么**？（哪些站点是 `unsafe`、哪一级被显式降级）
3. 这些承诺之间**有没有打架**？（`systems.lms.state = open` 而 `lms_levels` 七个全假）

第 3 个今天靠校验器的三方一致（`docs/147` §5），前两个没有对象。

**设计。** 新增一个 Potato 字段 `lawspace`，内容只做三件事：列承诺、列排除、盖封印。

```rust
// 提案，未冻结；展示用 rust 围栏，理由见 CLAUDE.md
struct Law {
  id: str,            // "no_runtime" | "no_segv" | "lms_in_bounds" | ...
  tier: str,          // claimed | proved | checked | floored
  verdict: str,       // proved | checked | declared_floor | refused
  obligations: [u32], // LSPE 义务号，空数组表示不由 LSPE 支撑
  exclusions: [u32],  // unsafe / 降级站点的稳定编号（与 fault_ladder 同一套）
  evidence_root: u64, // 证明根；无证据时为 0
}

struct Lawspace {
  schema: u32,
  dims_hash: u64,     // 九维取值的规范序列化哈希
  laws: [Law],        // 按 id 排序；顺序进哈希
  systems: u32,       // 指向 v20 的 systems，不复制字节
  fault: ?{ table_version: u32, ladder_hash: u64 },
  floor: { artifact: str, bytes: u64, sha256: str },  // docs/270 §4
  seal: u64,          // 对上面全部字段的规范序列化取 sha256 的前 8 字节
}
```

四条约束：

1. **封印只描述"声称了什么"。** 它不声称"真的做到了"；后者由 §4.2 的验证器判。
   这条分界是 `docs/225` §4.① "可验证的缺席"的直接沿用。
2. **`exclusions` 与 `fault_ladder` 共用站点编号。** `docs/356` §6.3 已经立了站点编号的
   稳定性要求；两个台账对不上，验证器必须红。
3. **`systems` 是引用不是拷贝。** v20 已经定了"索引不复制明细"（`tools/potato.py:277`），
   lawspace 不破坏这条。
4. **封印对规范序列化取哈希**，不依赖 JSON 的字段顺序；两份实现必须逐字节同。

**判据（每条先红）。**

| # | 判据 | 先红的方式 |
|---|---|---|
| L1 | 删掉一条 `exclusions` 条目，验证器报"站点表与封印不一致" | 在今天的产物上手动改一条 |
| L2 | 把一条 `proved` 改成 `checked` 且 `fault` 缺失，验证器红 | 构造一份 `gc_auto` 而不带 fault 的封 |
| L3 | `systems.lms.state = open` 而 `lms_levels` 全假，验证器红 | v20 已有这条一致性；加封印后必须仍红 |
| L4 | 同一单元、同九维、同登记表 ⇒ `seal` 逐字节同 | 两个进程各跑一次 |

**代价。** 一个新 Potato 版本（v24，单独升一版，`docs/147` 的台阶只往上加）；
两套实现（`tools/potato.py` 与 `loment/selfhost/potato.lomt`）；产物变大；
发布清单重生成。**这一步不碰 L0。**

### 4.2 独立验证器：PCO Verifier

**现状。** 判决由 `loment/lspe/` 的包做出，台账也由同一个包写出（`docs/344` §1.1）。
E7 是两份**编译器实现**的差分，它证明两边一致，不证明其中一份对
（`docs/344` §2.3 的 P4：E7 永不单独 `PROVED`；同一句也在 §1.2 的表里）。`docs/356` §6 已经提出一个
`fault_ladder` 的产物校验器，但它只覆盖 fault 这一面。

**这是 PANGU 提案里最好的一句话**（"避免 LSPE 自我证明"），也是唯一一条今天
**没有任何对应物**的治理性质。

**设计。** 一个只读产物的验证器，三条独立轴：

| 轴 | 内容 | 与编译器共享什么 |
|---|---|---|
| **代码** | 独立实现，零 import 编译器/LSPE 包 | **什么都不共享** |
| **输入** | 只读 Potato + 旁挂（`.lspe`、`fault_ladder`）+ 可选 ELF 的只读节 | 不读源码、不读 IR |
| **输出** | 独立判决文件；**不写回** `lspe` 字段 | 不覆盖任何编译器产物 |

它核四类东西：

1. **自洽**：`systems` 三方一致、ladder 恒等式、`lawspace.seal` 与字段一致；
2. **规则**：每条 `proved` 必须引用一条可复查的规则（`docs/356` §6.2 的 R1–R4），
   规则表版本进封印；
3. **覆盖**：每个安全子集站点在 `lawspace.exclusions ∪ fault_ladder` 里恰好出现一次；
4. **蕴含**：`no_segv = true` 要求所有安全子集站点 ∈ `{proved, checked}`，
   且每条 `checked` 有 fault 边；`no_runtime = true` 要求 `lms_budgets` 里没有 `state`。

**三条独立判据要分清**（这一点 `docs/349` 与 `docs/353` 都没有写全）：

| 判据 | 证什么 | 不证什么 |
|---|---|---|
| **孪生对拍**（E7） | 两份实现给同一判决 | 判决本身对不对 |
| **语义 oracle**（`docs/349`） | 手推期望表与实现一致 | 编译器没漏站点 |
| **产物验证器**（本节） | 产物里写下的承诺没有自相矛盾，且每条 `proved` 指向可复查的规则 | 编译器没漏站点 |

三者缺一不可。只做孪生，"两边一起错"照绿（2026-11-13 的坑）；
只做验证器，"漏扫的站点"照绿（验证器读不到源码）。**这就是"三方"的必要性。**

**判据。**

| # | 判据 | 先红的方式 |
|---|---|---|
| V1 | 验证器对编译器**零 import**：依赖图里没有 `lomentc` / `loment.lspe` | 加一行 `import` 即红 |
| V2 | 用**另一个会话/另一棵树**产出的产物做夹具，验证器判决一致 | 手写夹具不算（夹具要用真实现的产物） |
| V3 | 删掉产物里的一条 fault 边，验证器红 | 与 L2 同源、不同实现 |
| V4 | 验证器给出一份**可读的拒绝理由**（哪条规律、哪个站点） | 只给 rc≠0 不算 |

**诚实边界。** 验证器不能证明编译器没漏站点；能证明的是"产物内部没有假账"。
这句要和 `docs/225` 的措辞一致：**可验证的缺席**，不是"跑起来没崩"。

**落点。** 先做成独立的 Python 包（`loment/pco/` 或仓外 `loment-verify/`），
再考虑自举侧。第一条判据 V1 是机械的，能立刻挡回"顺手复用编译器代码"。

### 4.3 创世授权衰减：Genesis Attenuation

**现状。** `thread_spawn("worker", stack_top, arg, done)` 四实参（`docs/245` §线 A），
走 `CLONE_VM`，与父共享地址空间（`docs/245` §5 的判据表里那条夹具就叫
`test_threads_accumulate_on_shared_memory`）；把一个可变 `ptr` 传进去只需一次
显式 `as u64`，编译期**不检查**（`docs/245` §10.1 表格的最后一行）。
产物里没有一条断言说"这个线程能碰什么"。进程层面只有 `syscall*` 内建
（`tools/lomentc.py` 的内建表里没有 `fork`/`exec`），属于声明的 unsafe 面（`docs/356` §3.1）。

**设计。** 不引入"宇宙"这个新词。落成一个具体构造：**带权能集与预算的派生执行体**。

```rust
// 拼写提案，未冻结
let child = spawn("worker",
                  caps { file_read, net_connect, domain("blk") },
                  budget { heap: 4096, steps: 1_000_000 });
```

三条性质，按代价从低到高：

| 性质 | 形状 | 什么时候判 | 代价 |
|---|---|---|---|
| **G1 子集性** | `child.caps ⊆ parent.caps` | 编译期（capset 是字面量）+ 创世时复核 | 几乎零 |
| **G2 不继承** | 未列出的权限在子进程里**没有名字** | syscall 面：调用即 fault | 要动 L0 syscall 契约 |
| **G3 递归衰减** | 孙 ⊆ 子 ⊆ 父（传递闭包） | 每一层创世时；可进 lawspace | 与 G1 同形 |

G2 的"没有名字"要说得准：不是"被禁止"，是**授权面里不存在这个入口**。
这与 `docs/320` 的 `ref T` 判决点同构 —— 一次比较，失效即 trap，
不需要扫描子进程的所有权能（`docs/320` §4.2 的定理）。

**与现有两轴的关系。** 这里容易混：

| | 管什么 | 时机 | 已有 |
|---|---|---|---|
| `docs/328` 授权时序安全 | 一张授权**活多久**（revoke / epoch） | 运行期每次使用 | S1 已落 |
| **本节 创世衰减** | 创世那一刻**给了什么** | 创世 | **空** |
| `docs/146`/`docs/306` 能力域 | 一个位置**让不让碰**（space） | 编译期 + 运行期 | 已落 |

三者正交：先给（本节），再管寿命（328），空间谓词管"在不在域里"（146/306）。

**判据。**

| # | 判据 | 先红的方式 |
|---|---|---|
| G1 | 子 capset 含父没有的权限 ⇒ 编译拒，诊断指出父缺哪一个 | 今天不存在，构造即红 |
| G2 | 子进程调用未授予的 syscall ⇒ fault 码 + 站点，**不退出整个系统** | 今天直接是宿主的调用 |
| G3 | 两层派生后，孙的 capset ⊄ 父 ⇒ 拒 | 与 G1 同源 |
| G4 | 父的 lawspace 里能读到子的 capset 摘要（可审计） | 与 §4.1 的封印同一套 |

**代价（这是三件里最贵的一件）。** 子进程要有独立地址空间，就要 `fork`/`exec` 一类
syscall；G2 要把 syscall 面从"内建函数"提升成"带权限位的入口"，这是一次 **L0 契约变更**
（`CLAUDE.md` 第一节的冻结阈值，单独一次提交，写下游影响）。

**为什么仍然值得做。** 这是 PANGU 提案里唯一一条**增加威胁面也增加防护**的东西；
其余部分要么已有，要么不该做。它也是"系统编程语言"这个定位上少有的、外人可以
用一个二进制 + 一份 lawspace 就复核的性质。

## 5. 明确不做的（带理由，不是"以后再说"）

### 5.1 Causal Fabric 替换全局顺序 —— 不做；但它有一条可拿走的落点

替换全局程序计数器与确定性、热更新、自举链三条现有保证同时冲突。可行性上它是一台
**数据流引擎**，不是一层治理。证明平面的偏序已经存在（LSPE 的固定阶段 DAG 与证据格，
`docs/344` §2.3）；执行平面要碰，另开一条线，且必须先证明它不降低可复现性。

可拿走的那一条在**线程**这一面。今天的并发模型写着：

> 非原子的同址读写 = **数据竞争，行为未定义**；唯一的同步原语是 `atomic_add`
> （`docs/245` §10.1）。

这与 `docs/206` §3 的"线以外不许是 UB"直接打架：在安全子集里起两个线程，
共享一个可变 `ptr`，编译期不报，运行期是 UB。LMS 管不到它（不是越界），
Dissigsegv 管不到它（不一定发信号），LSPE 的 14 条义务里也没有一条是"这次共享是安全的"。

所以"因果"原则唯一可实现的形态是**一个内存模型的性质**，不是执行模型：

| 性质 | 形状 | 可判性 |
|---|---|---|
| **R1 无数据竞争** | 同址的并发访问，要么全是原子，要么被一条 happens-before 边分开 | 编译期只做保守推导（`atomic_add` + fork/join）；推不出就声明 `race_unsafe` |
| **R2 所有权转移** | 共享可变指针过一次显式 `as u64`，那次转换按 `Send` 的方向记账 | 词法可数（`docs/204` R5 的口径） |
| **R3 声明** | `lawspace` 里一条 `race_free`，载明 R1/R2 的站点数与排除 | 与 §4.1 同一套 |

这条不进本文的"三件"，因为它要改运行时与语言面；但它应该是 `lawspace` 的第一条
**候选第四规律**，而且在三件落地之后立刻可排期。今天把它写在这里，是因为
"因果优先于全局顺序"在 PANGU 里是一句最高的原则，而在本仓它能落成的
**第一句具体的话就是这个**。

### 5.2 Ontological State Space 全面替换地址 —— 不做

`docs/320` §5.2/§5.3 已经给了最终态：`&T` / `ref T` / `ptr` 三态、有界槽用槽表、
堆对象用对象头。全面对象表（一次间接寻址）是**成本决策**，不是免费胜利。
它应该是一档开关（若做，按 `_admin` 规则命名 `identity_indirect_admin`），
永远不进默认档。今天连有界槽的 S1 都只落了一部分。

### 5.3 L6 多宇宙生态 —— 不做

威胁模型里没有它的格子（§2），判据写不出来。没有用户，没有攻击者，没有失败模式。

### 5.4 快照 / 冻结 / 迁移 / fork —— 不做（在有意义之前）

按 I4，快照要保持证明有效，只能依赖产物内可重建的事实。`no_runtime` 产物的"快照"
就是重新执行。有意义的只有 LVM 档，而 LVM 今天不是默认执行档。
先做，只会把错误的设计钉进 L0。

### 5.5 "宇宙"这个词 —— 不进代码与 API

它不是类型、不是能力、不是可判谓词。它增加解释成本，不增加任何一条判据。
用已有的词：**产物、进程、域、权能、预算、账本**。PANGU 作为叙事可以存在；
作为标识符会污染 grep（`docs/204` R5 的口径：可 grep、可计数、可审计）。

## 6. 前史（先点名，再说话）

| 本文用到的 | 谁先做过 | 落到哪 |
|---|---|---|
| 产物携带可核的证明 | **PCC**（Necula 1996）、Java bytecode verifier、Wasm validation | 二进制必须先被验证才能运行 |
| 独立验证器与生成器分家 | seL4 的 Isabelle 证明、CompCert、diverse double-compiling（Wheeler 2005） | 验证器比编译器小得多，且可被第三份实现复查 |
| 规律是数据 | Wasm 的模块类型段、JVM 的 class 文件约束、**SLSA provenance** | 规律在产物里可读 |
| 子权能 ⊆ 父权能 | **Redell 1974** 的 revoker；seL4 的 CDT；Fuchsia handle rights；CHERI | 派生即衰减，是能力系统的定义性质 |
| 创世时的预算 | Erlang/OTP supervision tree、MINIX 3 reincarnation server、cgroups | 子执行体有独立预算与重启策略 |
| 逐站点台账 | `gc_ladder`（本仓）、Sanitizer 的站点报告 | 判决拆到每个站点 |

**本文的组合没有检索到现成物**：逐站点判决 + 产物内封印 + **只读产物的独立验证器**
+ 创世时的 capset 衰减，四件同时出现在一个系统里。**"没检索到 ≠ 没有"**
（`docs/356` §11.2 同一条纪律）。

## 9. 我不主张

1. **不主张这是新的安全理论。** 四件都有前史（§6）；本文的组合是新的，机制不是。
2. **不主张 PANGU Ω 的大部分内容是新东西。** 七层里五层已经存在；五原则里两条已成立、
   一条半成立、一条不该在执行平面做、一条是空。这是对账的结论，不是贬低。
3. **不主张独立验证器能替代编译器检查。** 它读不到源码，也读不到 IR 的漏站点。
4. **不主张创世衰减在 W4 之前可用。** G1/G3 是编译期的，能先落；G2 要动 L0。
5. **不主张快照/迁移/多宇宙。** 理由在 §5.3/§5.4，不是"优先级低"。
6. **不主张"宇宙"进标识符。** 叙事层可以；代码层会污染 grep 口径。
7. **不主张封印的字段表已经冻结。** §4.1 的 schema 是提案；进 L0 要单独一次提交。
8. **不主张性能。** 封印是产物体积；验证器是离线成本；G2 是一次比较。
   三件都没有测过，不拿直觉定价。
