# 305 · Tur 2026.2 封版记录

> 状态：**已封版**（2026-11-05）· 上游：`docs/296`（版次与首批语法）·
> `docs/299`（Tur 2026.3 的生命周期设计）· 登记处：`tools/potato_from.py`
> 的 `FROZEN_EDITIONS` / `TUR2026_2_FEATURES`；期望哈希独立钉在
> `loment_grammar_test.py:FROZEN_TUR2026_2_SHA256` · 判据：

## 1. 为什么现在能封

`docs/296` §4 的六项全部落地，而且每一项都有两套实现逐字节一致 + 能跑的判据：

| # | 内容 | 判据 |
|---|---|---|
| 1 | 版次脚手架（`tur2026.1` / `tur2026.2`，三处出口） | `loment_grammar_test`、`loment_p8_test` M87/M89 |
| 2 | 纯糖：`def` / `elif` / `and` / `or` / `not` | `loment_grammar_test`、M90 |
| 3 | `for x in xs` + `break` / `continue` | M91 |
| 4a | 裸 `return;`（只限无返回类型的函数） | M94 |
| 4b | `defer f(a, b);`（块退出 LIFO、声明处求值） | M96 |
| 5 | `orelse` / `catch`（两变体、首个带载荷、兜底惰性） | M95 |
| 6 | `print_num`（任意整型、按符号扩到 i64） | M94 |

"落地"的口径不是"文档写了"：每一条都在**参考实现**与**自举实现**上逐字节相同，
并且在运行产物上真跑过（见 `docs/296` 各段的判据清单）。

## 2. 封的是什么

**`tur2026.2` 的名字、特性面与语义。**

```rust
FROZEN_EDITIONS = ("tur2026.1", "tur2026.2")

TUR2026_2_FEATURES = (
    "def", "elif", "and", "or", "not",
    "for-in", "break", "continue", "bare-return",
    "orelse", "catch", "print_num", "defer",
)
```

这份元组与它的 SHA-256 是**棘轮**：期望哈希作为**独立字面量**钉在
`loment_grammar_test.py:FROZEN_TUR2026_2_SHA256`（与出厂锁同一套写法），往这一版加
一条就必须同时改实现与那条判据；那一步会逼人回答"这是不是该开新版次"。
判据还钉住：

- `FROZEN_EDITIONS` 仍恰好是这两个版次；
- `TUR_EDITIONS` 与封版清单一致（当前没有未封版的新版次混进来）；
- 出厂锁里没有 `tur3` / `tur2026.3` / `tur2027.1` 这些还没开的别名。

封版之后，**`tur2026.2` 不再接受任何语法或语义变更**，包括"顺手放宽一点"。
修实现内部的 bug（不改变这一版的判决与产物语义）不受影响；改变用户可观察的
语法/类型/诊断/运行语义，就必须开新版次。

## 3. 明确不封的东西

- **实现与工具链内部**：缓冲区、表布局、优化、性能 —— 与 `standard/LLS.md` §6.3 同一条纪律。
- **诊断消息的措辞**：码与"码按修法分"的分组是冻结的；同一码的文案可以更清楚。
- **默认读法**：封版本身不改变默认。**2026-11-06 另有一笔裁定**把默认改成最新版次
  （`docs/312`）—— 那是默认策略的变化，不是 2026.2 封版的松动。
- **短名 `tur2`**：2026 年内仍接受；跨年后按 `docs/296` §1.1 拒绝并给出全名。

## 4. 怎么开下一版

1. 在 `potato_from.TUR_EDITIONS` 追加规范名（`tur2026.3` 或 `tur2027.1`），
   **不要动** `FROZEN_EDITIONS` 里已有的两个；
2. 把新语法写进 `docs/296` 的下一节或新文档，并给它独立的判据；
3. 同时改：`GRAMMAR_ALIASES`、`NATIVE_GRAMMARS`、自举 `strip_grammar_decl`、
   VS Code 的 `NATIVE_GRAMMARS`、`surface_data`（`docs/296` §1.1 规则 5）；
4. 更新本页：把新版次追加到"冻结面"的清单，并写清它带来的特性；
5. 两套实现逐字节一致 + 种子重算（按 `CLAUDE.md` 的生成物纪律单独成一条提交）。

**不要**通过修改 `tur2026.2` 的解析分支来"加一点"：那会让同一份 2026 年的源在
不同工具链上读出不同意思，正是版次机制要消灭的东西。

## 5. 已开的下一版：`tur2026.3`

2026-11-05 按 §4 的步骤开了 **`tur2026.3`**（`TUR_EDITIONS` 现在是
`tur2026.1` / `tur2026.2` / `tur2026.3`；`FROZEN_EDITIONS` 仍然只有前两个）。
它**继承** 2026.2 的全部语法（`TUR2_PLUS`），目前登记的新特性是
**`lgc`：手动 GC 时间控制**（`docs/309`）与**借用生命周期**
（`docs/299` §8：`choose lifetime_no | lifetime_auto | lifetime_manual`，
2026.3 起默认 `lifetime_auto`）。2026.3 尚未封版，后续特性继续按
"两套实现 + 独立判据"的规矩往上加。
