# 346 · 函数指针、闭包与第九维 `fp`（2026-11-12）

> 用户 2026-11-12（原话）：**「函数指针实装，并现代化，很多语言的写法太老了，在此之前
> ask我」**；问完后追加：**「自举侧镜像直接做完」**。
> 上游：`docs/245` 线 B（真线程那一轮里被搁下的"函数指针"）、`docs/232` §3.3
> （当年**刻意排除**的那一条）、`docs/208`（静态调用图这条前提本身）。

## 0. 一句话

**函数是值。** `fn inc(x: u64) -> u64` 这个名字可以赋给一个 `(u64) -> u64` 的局部、
可以传给别的函数、可以装进闭包记录里间接调用 —— 而**默认档一个字节都不变**，
因为它被包在第九维 `choose fp` 后面（默认 `no_fp`）。

## 1. 当年为什么排除，今天为什么回来

`docs/232` §3.3 把函数指针列在"**不做**"那一栏，理由只有一条：`docs/208` 的
**静态调用图** —— 整个工具链（L1 的定值生命期、L0 的栈提升、L2 的逃逸判定、
热更新槽表）都建立在"每个调用点都能在编译期指到一个确定的函数"之上。

那条前提**是真的**，但它只在**没开这一维**的时候需要成立。于是答案不是"砍掉这个特性"，
而是把它做成**一维开关**：

| `choose` | 调用图 | 产物 |
|---|---|---|
| `no_fp`（默认） | 静态 | 只有直接调用边，一个字节不变 |
| `fp` | 有间接边 | 多出闭包记录、包装函数、间接调用 |

这与 `gc` / `runtime` / `lifetime` 那几维同一个形状：**承诺进开关，出开关就不承诺**。
`docs/208` 那一节已经按这条改写过。

## 2. 语法：三件事，都只有一种写法

### 2.1 函数类型

```rust
let f: (u64, u64) -> u64 = add;
```

- 括号里是**形参类型**，逗号分隔，**不含形参名**；`->` 后面是返回类型。
- 与其它类型一样可以嵌套：`((u64) -> u64) -> u64`、`[&(u32) -> bool; 4]`。
- 空参数表 `() -> T` 合法；**无返回值的函数类型写不出来**（`() -> ()` 的 `()` 在类型位置上
  没有拼法 —— 与 `fn f() -> ()` 写不出来是同一条），但一个返回 unit 的函数**可以**当值用，
  它的类型从签名里来（`(u64) -> ()`），不需要写出来。

### 2.2 函数值：裸名字，或 `&名字`

```rust
let f: (u64) -> u64 = inc;      // 裸名字
let g: (u64) -> u64 = &inc;     // 与上面**同一个值**
```

`&fn` 只是允许的另一种写法，不是"取地址"（函数类型里没有借用那一层）。
`extern fn` **不能**当函数值：它走平台 ABI，与本语言的内部约定不是一回事
（E0218）。

### 2.3 闭包：`(x) => 表达式`

```rust
let k: u64 = 7;
let h: (u64) -> u64 = (x) => x + k;     // 体是一个**表达式**
```

- 体是**表达式**，不是块：`(x) => { … }` 不合法（要多条语句就写成 `fn`）。
- **捕获**：体里出现的、外层**变量**（形参与 `let`）自动捕获。
  默认**按值**（捕一份拷贝，可以逃逸）；`&名字` 取过地址的**按借**（捕地址）。
- 捕获集按**名字排序**进闭包记录 —— 那是两个实现逐字节相同的前提之一。
- 形参类型两条来源：写在参数上（`(x: u64) => …`），或从**期望类型**推
  （`let` 的标注、实参位置、返回位置）。两处都没有 ⇒ E0220。

### 2.4 调用

直接调用 `inc(1)` 与间接调用 `f(1)` 在**源码上完全同形**：`f` 是局部就间接，是函数名就
直接。判据是名字在不在作用域里，不是写法。

## 3. 运行期形状：一条记录，一条路

函数值与闭包在运行期是**同一种东西**：

```
闭包记录（堆上一条 8 的倍数）：
  +0   代码地址（i64）
  +8   第 0 个捕获
  +16  第 1 个捕获
  …
```

- **函数值** = 只含 +0 的记录；代码地址指向一条**包装** `@__fp_<名字>`，
  包装把统一的 `(ptr env, 实参…)` 约定接回直接调用。
- **闭包** = `{代码地址, 捕获…}`；代码地址指向 `@__lam_<函数>_<序号>`。
- **间接调用** = `load ptr` 取记录 → `load i64` 取代码 → `inttoptr` →
  `getelementptr i8, ptr rec, i64 8` 取环境指针 → `call`。

于是调用点只有一条路：**没有"直接调用 / 闭包调用"的二分**，
`docs/208` 说的"间接边"就只有这一种形状。

记录用 `@__loment_alloc` 分配（不是全局常量）：全局常量要 `ptrtoint` 初值，
两只链接器都得为它加一条初值形式；分配器这条路运行期与闭包**完全同形**，
链接器只为间接调用加一条指令形状。

## 4. 诊断（`docs/338` 的码表里是 217–222）

> 号是**撞出来的**：写这一维时先占了 210–215，可主干先一步把 210–216 分给了
> 插值 / `catch` / `auto`。合并时这六条整体挪到 217–222 —— 码号只增不改的含义，
> 撞号就往后排。

| 码 | 何时 | 修法 |
|---|---|---|
| **E0217** | 用了函数值 / 闭包 / 间接调用，而本单元是 `no_fp`（默认档） | 在根单元写 `choose fp` |
| **E0218** | `extern fn` 当函数值 | 写一个 Loment 包装函数，在它里面调 `extern fn` |
| **E0219** | 按值捕获的类型放不进一格（只有整型 / `bool` / `ptr` 收） | 把聚合放进 `ptr` 再捕 |
| **E0220** | 闭包形参类型推不出来（没标注、也没有期望类型） | 写 `(x: T) => …`，或放到有标注的位置 |
| **E0221** | 返回一个**带按借捕获**的闭包 | 改成按值捕获（捕的是拷贝，可以逃逸） |
| **E0222** | 闭包形参的标注写了个不存在的类型 | 换成真有的类型（与 `let` 的标注同一条规则） |

E0217 是这一维的"分界线"本身：**没写 `choose fp` 时，这三个入口一个都进不去**。

## 5. 两个实现

### 5.1 参考实现（`tools/lomentc.py`）

- 解析：`type_name` 的 `(` 分支、`parse_lambda`、`_lambda_ahead` 前瞻。
- 检查器：`_FP_ALLOWED`（`check()` 按生效维设置）、`_bind_lambda`（三个绑定站点：
  `let` 的标注、实参位置、返回位置）、`_free_idents` / `_ref_idents`（捕获分析）。
- 发射器：`_fn_value` / `_lambda_expr` / `_lambda_fn`。

**两处刻意的形状**：

1. **闭包体与包装不进 `globals`**，单独一列 `fn_defs`，追加在**全部函数体之后**。
   `globals` 的长度决定 `@.str.<fn>.<n>` 的编号 —— 函数体混进去会让字符串常量的名字
   随闭包数量漂移，而自举侧是**预扫描**编号的，两边必然对不上。
2. **闭包里的形参与捕获按源里的名字绑定**（`%x.addr`），不用 `%p0` 这类序号名。
   自举侧的变量模型是**按名字的**；序号名要它在每个取值点查一次"这个名字的地址是哪个
   临时值" —— 那是个到处都得改的耦合。按名字绑定之后，闭包体与普通函数体**同形**。

### 5.2 自举侧（`loment/selfhost/checker.lomt` + `codegen.lomt`）

- **检查器**：函数类型进类型表（`TY_FN` + 形参链 `TY_FP`，结构判等）、
  `chk_lambda`（形参 / 捕获 / 门 / 五个码）、间接调用与三处绑定站点。
  单元级那一趟调用检查要**收手**：它没有作用域，`f(...)` 的 `f` 可能是个函数类型的局部
  （`chk_let_named`）；真正的未声明判定在 `chk_body -> chk_tex` 那条路上。
- **发射器**：值 = 记录（`emit_fn_value` / `emit_lambda`），包装与闭包体**登记**进
  `CG_FDS` / `CG_LAMS`，全部函数体之后由 `emit_fdefs` 统一发。
  包装按**模块**去重（它是一条 `define`）。
- **链接器**（`loment/tools/lomelf.lomt`）：`call %reg` 一条（`FF D1`），
  外加 `@名字` 的标签回填（函数登记时不带 `@`，全局量带）。

## 6. v1 的边界（都是**点名**的，不是漏）

1. **捕获只能是一格宽**（整型 / `bool` / `ptr`）：闭包记录按 8 字节一格存捕获（E0219）。
2. **带按借捕获的闭包不能返回**（E0221）：按借存的是地址，那个地址活不过函数。
3. **`extern fn` 不是函数值**（E0218）。
4. **`globals` 里没有函数值**：本语言没有模块级 `let`，函数值只活在局部。
5. **GC 的根**：闭包记录是堆对象，落在具名局部里时按普通指针登记；
   闭包体内那几格捕获在 `gc_auto` / `lgc` 下按**同一张根表**登记
   （`roots_push` 的形参那一段），两个实现同序。
6. **Potato 形态对象**（`loment_runtime` 那一层）里，函数类型就是 `ptr`，与 `alloc`
   出来的指针同形（不单开一种形状）；这一维本身是一格新字段 `fp`（**v23**，
   紧跟 `lifetime` 之后，两个实现的字节次序是判据）。
7. **`emit_rust`**（`loment.py test` 那条自检链路）还不译闭包 —— 它**点名拒**
   （"闭包还不能翻译成 Rust"，`docs/346`），不是崩溃。原因：闭包要捕获的运行期表示，
   而那条链的约定是"一对一照抄语义"。要跑带闭包的自检，走原生后端。

| 判据 | 钉住什么 |

## 8. 一句话总结

**这一维买的不是"能写闭包"，是"默认档仍然只有直接调用边"。**
开关关着，`docs/208` 的每条前提都还在；开着，代价是明写出来的那一行 `choose fp`。
