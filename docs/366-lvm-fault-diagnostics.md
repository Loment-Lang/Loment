# 366 · 段错误详细化：LVM 的故障也要像 `lomenterr` 那样说话

> 状态: **已实装**（2026-11-21），参考实现 + 自举镜像
> 上游: `docs/182`（报错器 Lomenterr 的形状）· `docs/356` §5（语言级故障）·
> `docs/360` §3.2（P4 `fault`）· `docs/263`（上限表）
> 判据: `tools/lvm_cap_test.py` 判 J / 判 K · `tools/lvm_twin_test.py` 判 O（两边形状都在）
> 一句话: **首行不变（机器可读），后面跟一段 Lomenterr 形状的详细诊断（人可读）——
> 每一次段错误都说清"哪条指令、碰了哪个对象、越了多少、该查什么"。**

---

## 0. 之前有什么、缺什么

LVM 档早就有**站点**（`docs/356` §5.3）：一次故障是

```
lvm: F01 bounds violation at _start:entry#13 (offset=40 size=4 limit=16)
```

三样东西都在：**码**（F01/F02/F03 → 101/102/103）、**站点**（函数:块#序号）、
**见证**（偏移/大小/上限）。缺的是**解释**：`offset=40 size=4 limit=16` 要一个读得懂
对象表的人才知道"这是 `a[10]` 落在 16 字节的 alloca 上、右越界 28 字节"。

原生档更少：不经过 LVM 的产品拿到的是内核那一行（shell 的 `Segmentation fault`，
或启动器下的 139），进程自己一句话都没说。

这一页补的是 **LVM 档的详细化**（第一步）。原生档要另做（§5）。

## 1. 形状：首行稳定，详细块照 `lomenterr`

```text
lvm: F01 bounds violation at _start:entry#13 (offset=40 size=4 limit=16)
error[F01]: 访问越界（bounds）
  --> IR:_start:entry#13
   |
   |   store i32 99, ptr %t6
   |                 ^^^^^^^  这里访问 4 字节
   |
   = 对象 #2（alloca）：base=4178056 limit=4178072（16 字节），第 0 代，活着
   = 事实：地址 4178096 在对象内，偏移 40；访问 4 字节越过上限 28 字节（右越界）
   = 站点：函数 _start / 块 entry / 第 13 条指令；栈深 1
   = 建议：检查下标与对象长度：这一次访问跨过了对象的上限。原生档在这条路径上是 UB，
     LVM 把它变成这句话；上限表见 docs/263。
```

* **首行一个字都不改** —— 孪生判据（`lvm_twin_test::_fault_line`）与故障判据按它比，
  详细化不能把它们带红。这是"加东西"而不是"换东西"。
* 详细块与 `loment/tools/lomenterr.lomt` 同形：`error[码]: 标题` / `--> 位置` /
  源码行 + 插入符 / `= 事实` / `= 建议`。这里"源码行"是**IR 指令**，不是 `.lomt` 行
  （默认产物没有行表，见 §5）。
* 插入符画在**指针操作数**下面（`load` 的地址、`store` 的指针），不是整条指令。
* `= 对象` 给出对象表的现场：序号、种类、`base`/`limit`/大小、代、活着还是已归还。

## 2. 三种故障各说什么

| 码 | 触发 | 详细块补的三件事 |
|---|---|---|
| **F01** | 访问越过对象上限 / 地址不在任何对象里 | 对象那一行（活对象或"没有对象覆盖"）；偏移与**越界字节数**；建议查下标与长度 |
| **F02** | 能力指向已归还的对象，或地址落在归还窗口里 | 已归还对象那一行（base/limit/代）；如果地址现在住着另一个对象，点名它 |
| **F03** | 地址是 0 | 空指针；访问宽度 |

`llvm.trap`（退出码 132）也带一块同形状的诊断，标题是 `error[trap]` —— 它不是内存故障，
是"程序自己的崩溃器"（LMS 第 5 级）。

## 3. 两个实现

* **参考实现**（`tools/lvm.py`）：`SwCap.check` 多收一个渲染现场（指令文本、指针操作数、
  栈深），故障时 `_Fault` 带 `detail`；顶层 `fault_exit` 打首行 + 详细块。
* **自举镜像**（`loment/tools/lvm.lomt`）：`cap_check` 多收指令跨度与操作数跨度，
  `cap_fault` 按同一形状打块（它没有 `llvm.trap` 这一档，见 §5）。
* **不是逐字节一致**：对象序号（`#2`）与归还对象的写法两边可以不同 —— 被判据钉住的是
  **形状**（`error[码]` / `-->` / 插入符 / `= 事实` / `= 建议`），不是同一句话。
  与 `docs/182` §5.3 同一个口径：两侧的**码**与**形状**一致，文本各写各的。

## 4. 踩过的坑：detail 里不能放对象本体

第一版把 `_Obj` 本体放进 `detail`，到顶层渲染时才读它的字段 —— 于是**每一次越界都被
印成"已归还、代加一"**。原因是异常栈解开时帧的 `finally` 已经把这一帧的 alloca 全部归还，
渲染看到的是**之后**的状态。修法：故障发生时把对象**拷成快照**（`_ObjSnap`），
渲染只看快照。这条与 `docs/366` 的判据 J 一起钉住（合法对象的 `活着`、第 0 代）。

## 5. 我不主张

1. **这一页只做 LVM 档。** 原生档另开了一页：`docs/367` —— stage 0 是宿主报告器
   （ptrace，clang 产物也能用），stage 1 已把报告器与站点表嵌进 lomelf 产物
   （`--fault-report`，默认关）；stage 2 起自举镜像同形且**逐字节相同**，stage 2.5
   还能把未映射页置零后继续（`--fault-heal N`）。原生档没有对象表，所以拿不到这里
   这种对象现场。
2. **不主张能指回 `.lomt` 行号。** 默认产物的 IR 不带行表（`--debug` 才有 DWARF），
   所以"源码行"是 IR 指令。要指回 `.lomt`，得让 VM 读行表 —— 那是另一笔。
3. **不主张两边的详细文本逐字节相同。** 见 §3。
4. **不主张自举镜像有 `llvm.trap` 的详细块。** 镜像目前没有这一档；参考实现有。
5. **不主张诊断替代判据。** 判 J/K/O 钉的是形状与关键事实；"这句话够不够好"仍要人读。
6. **这一片有价格，且已经记在 B8 上。** 两份解释器从 7,478 行涨到 **7,936 行**（预算
   8,000）—— 详细化的代价是解释器本身变大。再涨一档就该动预算那个**决定**，而不是悄悄
   改数（`docs/371` §2 第 4 条）。
