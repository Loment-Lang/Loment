# 298 · Tur 2026.3：简洁的生命周期控制

> 2026-11-04 的用户指令：**开发简洁的生命周期控制，保持 Rust 的功能，却极端简洁地表达。**

## 1. 现状：今天没有生命周期，因为借用不能存

今天的引用只出现在**实参与形参**：`xs: [u32]` 配 `&xs` / `&mut xs`。类型位置写 `&` 是
解析错误 —— `struct V { data: &str }` 与 `fn f(a: &str) -> &str` 都过不了解析
（实测：`期望 ident（类型名），得到 '&'`）。结构体字段也只收标量（`str` 字段报
"字段类型 str 目前只支持标量"）。

所以今天**没有生命周期问题**，代价是**也没有零拷贝视图**：解析器、窗口、切片器都只能
在参数上借用，无法把借用存进结构体、也无法从函数返回。Rust 的能力正是卡在这一格。

## 2. 目标

把借用提升为**一等类型**（字段、返回、嵌套、泛型实参），同时**不引入 `'a`**：

1. 常见的借用 API **零标注**；
2. 需要分叉时，最多多写一个**参数名**；
3. 保证与 Rust 同级：借用不会比来源活得长、`&mut` 独占、没有自引用。

## 3. 语法

### 3.1 `&T` / `&mut T` 进类型位置

```rust
struct Cursor {
    data: &[u32],
    pos: u32,
}

fn next(c: &mut Cursor) -> Option<&u32> {
    ...
}
```

源码里**没有** `<'a>`、没有 `'a`、没有 `where`。`Cursor` 在类型系统内部携带一个
**区域参数**（`Cursor<R>`），但它不写在源码里，也不写在泛型实参里：
`Cursor` / `Option<Cursor>` / `[Cursor; 4]` 照常写。

### 3.2 省略规则（比 Rust 更少要写）

1. **一个引用入参**：所有引用出参都借自它（Rust 已有的 elision）。
2. **多个引用入参、一个引用出参**：出参区域取**所有入参里最短的那个**。这条 Rust
   没有；它保守、健全，让 `fn min(a: &[u32], b: &[u32]) -> &[u32]` 这类函数零标注。
3. **方法**：`&self` / `&mut self` 视作一个入参，出参默认借自 `self`（含 `self` 字段
   所携带的区域）。
4. 其余情况（多个出参、或出参只借自某一个特定入参）才需要 §3.3 的标记。

### 3.3 借用来源标记：`&a T`

```rust
fn pick(a: &[u32], b: &[u32]) -> &a [u32] { ... }   // 只借自 a
fn pair(a: &[u32], b: &[u32]) -> (&a [u32], &b [u32])
```

`&`（或 `&mut`）后面跟**参数名**，再跟类型。没有引号、没有声明、没有 `where`；
`a` 就是签名里那个形参的名字，工具链据此把出参的区域绑到它身上。

**解析怎么消歧**（两 token 前瞻，两套实现同一条）：`&` 之后若是
`ident ident` / `ident [` / `mut ident ident` / `mut ident [`，前者是来源标记；
`&u32`、`&Buffer<u32>`、`&[u32]` 仍是普通引用类型。标记指向的必须是一个引用类型的
形参（或 `self`），否则是诊断 —— 不做名字猜测。

### 3.4 结构体：构造即绑定，赋值按包含

```rust
let xs: [u32; 8] = [...];
let c: Cursor = Cursor { data: &xs, pos: 0 };   // c 的区域 = xs 的区域
```

- 区域**包含**规则：长区域的值可以当短区域用；`&T` 协变，`&mut T` 不变。
- 结构体不能借自己（自引用）；要自引用就用下标/偏移，或 `ptr`（§5）。
- 引用字段可以做参数、返回值、别的结构体的字段；泛型实参里也照常。

### 3.5 与 GC / `defer` / 退出路径

- **区域是静态证明，GC 是运行期回收**，两者不互相替代；
- `free(p)` 在 `p` 仍被借用时是**编译期诊断**（今天 `free` 只是占位，规则先立在这里）；
- `break` / `continue` / `return` / `?` 结束所离开块的区域；`defer` 在区域结束**之前**
  执行，所以 defer 体里不许使用已经结束的借用；
- 借用检查只在**同一函数体内**完成；跨函数的边界由**函数摘要**（出参借自哪些入参）
  表达，摘要本身也是检查出来的，不手写。

## 4. 明确不做（Rust 有，这里不收）

* `'static` 标注：全局与字面量的区域由检查器定成静态，源码不写；
* 高阶生命周期（HRTB）、生命周期 bound（`'a: 'b`）、显式 `<'a>` —— 全部不引入；
* `unsafe`：逃逸舱是已有的 `ptr`（裸指针不受区域检查，责任在写的人）；
* 自引用结构体（要它就换成下标/偏移）；
* 把 `str` 变成借用类型：`str` 今天就是 ptr+len 的值类型，`&str` 不新增含义。

## 5. 诊断（只增不改，每条都点名来源）

* 借用比来源活得长（指出是哪个变量、哪一行）；
* 返回局部变量的借用；
* 把借用存进活得更久的结构体/全局；
* 在仍被借用时释放；
* 借用来源标记指向非引用形参 / 名字不存在；
* 自引用结构体。

"生命周期错误"这种**不说来源**的话不许出现 —— 用户改不了它。

## 6. 实现成本（为什么归 Tur 2026.3）

* **参考侧**：`lomentc` 的检查器加区域环境与函数摘要；AST 上有类型，可行。
  预计 2 轮（区域推断 + 结构体/返回 + 诊断）。
* **自举侧**：检查器是 **token 级、没有 AST**，区域环境要挂在现有 env 上，函数摘要要
  从 token 流重建 —— 这是自举检查器迄今最大的一笔改动。预计 2–3 轮，且必须与参考侧
  逐字节一致。
* 交互面：`defer`、`?`、循环退出、切片、结构体字段、泛型实例化、GC 档位 —— 每一项
  都要一条判据，不能只靠"能编过"。

## 7. 验收（"极端简洁"是可检查的）

* 常见的借用 API（游标、视图、`split`、`min`）**一个生命周期标注都不写**；
* 需要分叉时只多一个参数名（`&a [u32]`）；
* 与 Rust 的对照只差在"没有标注"，安全性判据一一对应：悬垂、别名、释放后使用、
  自引用，各有一条负例；
* Tur 1 / Tur 2026.2 的引用规则**一个字节都不变**：这些是 2026.3 的新语法。

## 8. 落地记录（2026-11-08）：三档 `choose lifetime`

用户 2026-11-08 的裁定把"开不开"改成了**一维三档**（`docs/274` §2 的第八行）：

| 取值 | 含义 |
|---|---|
| `lifetime_no` | **绝对关闭**：`&T` 在类型位置仍是解析错误；旧版次的默认 |
| `lifetime_auto` | **默认**（`tur2026.3` 起）：区域推断 + §3.2 的省略规则，源码零标注 |
| `lifetime_manual` | 手动档：额外允许 §3.3 的借用来源标记 `&a T` |

默认值**随版次走**：`tur2026.1` / `tur2026.2` 仍默认 `lifetime_no`（`docs/305` 的
封版承诺），`tur2026.3` 起默认 `lifetime_auto`。旧版次里写这三个词是**点名拒**
（E022 的一条，消息 "生命周期控制从 `tur2026.3` 开始"），不是"未知开关"。

**这一轮落地的语义（v1，参考实现）**：

* 类型面：`&T` / `&mut T` 进形参、返回、结构体字段、泛型实参；切片借用
  `&[T]` / `&mut [T]` **规范化**到已有的 `[T]` / `mut [T]`（它们本来就是 ptr+len 的
  借用视图）。产物里 `&T` 是一个 `ptr`。
* 区域推断：返回值的借用来源按 §3.2 的省略规则算成**函数摘要**；调用一个返回借用的
  函数时，结果的来源**跟着实参走**。于是 `return id(&local);` 也能被看出悬垂。
* 判据：返回局部借用（E012，与今天那条同码）、没有引用形参却返回借用（E041）、
  区域标记写在不存在的形参上或在 `auto` 档里写（E041）、`free(p)` 时 `p` 仍被借
  （E041）、**存下来的** `&mut` 与后来的借用重叠（E007）。
* 语法面：多一个前缀 `*` 解引用（`*r`、`&*p`），只在 `lifetime != no` 时合法；
  `r.field` / `*r = v` 自动解一层借用。
* LGC 交互：借用是指针，收集器把它们当根（既有根表照旧）；`free` 与借用重叠是
  **编译期**拒绝；区域是静态证明，不替代运行期回收。

**明写的 v1 边界**：

* **不做 NLL**：存下来的借用活到函数末尾（行内的借用仍只活一次调用）。
* **切片上不写区域标记**：`&a [u32]` 在 v1 是诊断 —— 切片的区域由来源推断。
* **结构体字段不能带标记**：字段的区域由构造处的来源决定。
* **自举侧这一轮点名拒借用类型**（`checker.lomt` 的 E041，消息说"还没到自举侧"）：
  维度与 Potato v22 两边都落地了，类型面与区域检查按 §6 的顺序下一轮补。**这不是
  静默分歧** —— 同一份源在自举侧得到一条专属诊断，不是错的 IR。
* 自引用结构体、字段级移动、跨函数 `&mut` 的时效都还没做。
