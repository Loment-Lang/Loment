# 259 · LVM 第三格（T2）：**基线编译** —— 把解码搬出执行期

> 状态: **已落地（参考实现）**（2026-10-17，issue #325）· 上游: `docs/232` §4.4（梯子）·
> `docs/243`（T0）· `docs/247`（T1 剖面）
> 判据: `tools/lvm_t2_test.py`（4/4）· 实装: `tools/lvm_t2.py`
> 一句话: **那一格的价钱不在"解几次"，在"每执行一条就解一遍"** —— 所以它不是缓存，
> 是把解码**搬家**。

---

## 1. 这一格要什么

`docs/232` §4.4 的 T2 行，逐字：

> **基线编译**（去解释开销，不做优化） | Sparkplug | 同一程序 T2 显著快于 T0，**语义逐字节相同**

"每格要能被证伪，不许写'做一个 JIT'" —— 所以这一格的验收就是上面那两半：**显著快**、
**逐字节同**。判据里各钉一半（§5）。

**T2 不做**：寄存器分配、内联、冗余消除、类型特化。那些是 T3（`docs/248`），而且 T3 的
B 堆每一项都要先去优化（`docs/249`）—— 这一格一条都不沾。

## 2. 先说清楚：为什么"少解几次"撑不起这一格

T0 每执行一条指令就把那条指令的**文本**重解一遍。一个自然的想法是"把解析缓存起来"。
**量出来的答案是：不够。**

同一份 `tour`、同一进程交替跑、取中位数：

| | 中位数 |
|---|---|
| 原样 | 7.5 ms |
| 只把 `parse_type` / `parse_operand` 记忆化 | 6.7 ms |
| ⇒ 省下 | **11.2%** |

11% 不是一个"显著更快"的格子。所以 T2 换了个做法：**不是少解，是不在热路径上解** ——
解码整体搬到执行之前，一次做完。

（⚠ 这个 11.2% 是**决定这一格形状**的测量，不是判据：它是墙钟比值，随机器变。
判据 §5 C 用的是**解码次数**，那个是确定的。）

## 3. 编译成什么

每个 IR 函数编译成一个 `_CFunc`：

| T0 执行期每次要做 | T2 编译期做一次 |
|---|---|
| `startswith` 链 + 两三个正则认指令种类 | 整数操作码 |
| 每进一个块线性扫 `fn.blocks` 找标签 | **块下标**直接跳 |
| SSA 名当字符串键查 `fr.vals` | **槽下标**（`vals[i]`） |
| 每个操作数 `parse_type` + `parse_operand` | `(种类, 数)`：槽 / 立即数 / 零聚合 |
| `getelementptr` 的类型游走 | 常数偏移 + 若干"下标 × 步长" |
| `icmp` 谓词、`br`/`switch` 的边号 | 谓词函数、边号在编译期定死 |

**操作数三种**：`0` 槽下标 / `1` 立即数 / `2` 零聚合（`undef`/`null` 的聚合值，执行期给
`b"\0" * size`）。全局的地址在编译期就折成立即数（前提见 §4 第二条）。

**懒编译**：函数在**第一次被调用**时才编。理由不是省内存，是**语义**：T0 只在**执行到**
一条不认识的指令时才报错，而 `tour` / `all_loment` 的 IR 里就有 `declare @llvm.trap` 与它的
调用点 —— 在**走不到**的函数里。一次编完整份会让"根本没执行到的代码"把程序打死，
那是**换引擎顺带改了语义**。

## 4. 两处必须照抄、不许"顺手修好"的行为

### 4.1 `alloca` 每执行一次就往上 bump 一次

T0 的 `alloca` **每执行一次**就从帧里拿一段新的，所以在循环里它每次返回的地址都不同、
帧也会一直长。那是 T0 的**可观察行为**（程序可以比地址、可以打印它）。T2 换引擎，
**不许改变它** —— 要改是另一件事、另一条判据。

### 4.2 一个 VM 实例只能跑一次

`Mem` 是**被那次跑改写过的**（堆游标、全局都被写过），所以第二趟会分配不出来、走到
`__loment_abort`。T0 也是同一回事（每次 `run_ir` 新建一个执行体）。⚠ 这条是写判据 C 时
**当场踩出来的**：第一版"跑两趟、第二趟算数"在 `lumtui_demo` 上直接 trap。

### 4.3 编译必须在全局落位之后

`Global.addr` 是 `Vm._place_globals` 才赋的。所以前门是"先建执行体（顺带落位），再编译"。
反过来写的话，每个 `@global` 操作数都会被编成**地址 0** —— 而且它不会崩，只会算错。

## 5. 判据（`tools/lvm_t2_test.py`，4/4）

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | **产物等价** | 语料每一份：**原生产物 / T0 / T2** 三者 stdout 字节 + 退出码相同。**9/9**（`selfcheck` 由 `lvm_test` 那张棘轮点名出局） |
| **B** | **剖面不变** | T1 的剖面（`docs/247`）在 T0 与 T2 下**逐字节相同** —— 换引擎不许改变被记录的行为。**9 份**全同 |
| **C** | **执行期不再解码** | 把 `parse_type`/`parse_operand` 包起来数调用次数：T0 那一趟 **6,754,954 次**；T2 **编译期 32,838 次、执行期 0 次**。⚠ 反向那一半也要断言（T0 > 0、编译期 > 0），否则这条判据量到的是"包没接上" |
| **D** | **确实更快** | 同一进程里 T0 / T2 **交替跑**、取 `min`（`docs/226` 的记法）。**判的是"谁更小"这个符号**，不是某个倍数 |

**C 是这一格的自证，而且是确定性的** —— 它不靠计时，所以不受机器散布影响。它把这一格的
主张（"解码搬出执行期"）变成了一个可以数出来的数，而且是**两半**都数：热路径 0 次、
编译期 > 0 次。

**D 为什么只判符号**：墙钟比值当门禁会随机器散布（这条仓里有过教训：同一个量测出
3.2× / 4.13× / 5.4×）。倍数**只打印、只记账**，不做门禁。

## 6. 数字（记账，不是判据）

同一进程交替、`min of 3`、本机：

| 程序 | T0 | T2 | 倍数 |
|---|---|---|---|
| `lumtui_demo`（语料里最重的一份） | 6180 ms | 1017 ms | **6.1×** |
| `tour` | 8.3 ms | 6.7 ms | 1.23× |

`tour` 那一格只有 1.2×，因为它是**小**程序：编译一次要 62 ms（`lumtui_demo` 那份 IR），
而 `tour` 整趟才 7.5 ms —— 启动成本根本没摊回来。**这正是"编译型"该有的形状**：
程序越大越划算。拿 `tour` 的 1.23× 去说"T2 没用"是**换错了量**。

## 7. 范围：**镜像那一半不在这一格**（issue #586，0.1.5）

会随货走的 LVM 是**自举镜像** `loment/tools/lvm.lomt`，它在 Loment 里。它要做同样的
"编译档"，挡在两件已命名的事情上：

1. **机器码 T2 在 Loment 里做不了** —— 没有函数指针类型、没有间接调用（`docs/245` 的
   "线 B" 尚未开始），所以就算把 x86 字节写进 `PROT_EXEC` 内存也**跳不进去**。
2. 但它**不需要**机器码：镜像的 T0 在**执行期**同样在重解文本 —— 每个 SSA 操作数一次
   **线性** `vfind`（最多 1024 项、逐字节比），外加每指令若干次 `ty_span`/`seg_end`/
   `ty_size` 扫描。**同一套"预解码 + 槽下标"在 Loment 里做得出来**，不需要 x86 编码器。

⇒ **#586 = 镜像的 T2：同一套设计，用 Loment 写。** 它排在 0.1.5（与 #353/#354 那条
稳定化/性能线一起），本格（0.1.4.6）只交参考实现。

⚠ 这**不是**"T2 做了一半"：本格的判据 A–D 全绿，说的是**参考实现**有了一档基线编译。
**孪生不受影响** —— `docs/243` §5 的孪生比的是**行为**，镜像仍是 T0，两边照样逐字节同。

## 8. 我不主张

1. **不主张 T2 打得过原生产物**。它要打赢的是 T0，那是它自己的梯子；与 `lomelf` 那条路的
   比较在 `docs/226` 的账上。
2. **不主张 6.1× 是可移植的数**。它测于本机、语料里最重的一份；换机器会变。**比值只在
   同一次调用里比**才有意义（`docs/226`）。
3. **不主张这一格与 `lvm.lomt` 无关**。它是**参考实现**的 T2 —— 会随货的那一份还没有。
   §7 把这件事说清楚了，没藏着。
4. **不主张它已经是 T3 的地基**。T3 要用剖面（`docs/248`）与去优化（`docs/249`），
   而 T2 只保证"执行期不读文本"。
