# 261 · LVM 第四格（T3）**实装**：守卫特化 + 去优化

> 状态: **已落地（参考实现）**（2026-10-17）· 设计: `docs/248`（T3-a）· `docs/249`（T3-b）
> 判据: `tools/lvm_t3_test.py`（3/3）· 实装: `tools/lvm_t3.py`
> 一句话: **T3 只有一条硬判据 —— 去优化之后结果还对**。这一格把那条路真的走了一遍。

---

## 1. 实装的是哪一条，没做的是哪几条

`docs/248` §3 把优化集按"背不背假设"分成两堆。这一格只做了 B 堆的 **B1（常量特化）**，
因为它是**唯一需要去优化的**一条 —— `docs/248` §3.2 那句原话：

> 没有 B1，T3 就是一个"更快的 T0"而**永远不需要去优化** —— 那时该问的不是"怎么去优化"，
> 而是"这一格还是不是 T3"。

**A 堆（寄存器分配 / 一般内联 / 热块布局 / 跳转表 / 分派消除）一条都没做。** 这是记在天花板上的，
不是漏了（`docs/248` §5）。它们不背假设、不需要守卫，也就不需要这一格唯一的那条判据。

## 2. 它怎么工作

```
T2 跑一趟 + --values-out  ──►  值观察（哪个调用点、第一个实参见过什么、各几次）
                                        │
                                        ▼
                       --tier t3 --values-in
                                        │
        某个调用点的第一个实参占比 ≥ 90% 是同一个 C
                                        │
                    ┌───────────────────┴────────────────────┐
                    ▼                                        ▼
        被调是**单块、无分支、无调用**            否则
                    │                                        │
        摊平进来（参数按 C 绑死）+ 一道守卫            不特化，照常调用
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   实参 == C                 实参 != C
   跑摊平的那段            **记一条去优化** + 走通用调用
```

## 3. 为什么这里的"去优化"便宜 —— 而且是**老实的便宜**

`docs/249` §4 那条承重不变式是："**守卫之前，不可重物化的值必须已经在栈槽里**"。
它在这里**空成立**：T2/T3 是**槽机**，每个值都已经在它自己的槽里，**没有寄存器**。

⇒ 守卫失败时不需要"重建帧"，`vals` 就是解释器的状态，直接接着走。

⚠ **这不是"我们做对了"，是"这一格的地基让这个问题不存在"。** 真正的难点（从优化帧重建
解释器状态、重物化、spill-before-guard）是**寄存器分配**的代价 —— 而 A 堆一条都没做。
哪天 T3 上了寄存器分配，`docs/249` §3 那四档重建就要真写，这条便宜就没了。

## 4. 值观察为什么要另起一件产物

`docs/248` §2 原本写的是"给剖面加一个段（版本号 +1）"。落地时改成**独立产物**
（`--values-out` / `--values-in`），理由是硬的：

> **孪生判据（`docs/247` 判据 E）逐字节比剖面**，而镜像不记值。把值加进剖面，孪生当场分叉。

独立的另一件产物不动那个契约。格式与剖面同形（行文本、TAB、按 IR 解析顺序、可关掉）：

```
# lvm values v1
[values]
<fn>\t<block>\t<instr>\t<value>\t<count>
```

## 5. 判据（`tools/lvm_t3_test.py`，3/3）

| # | 判据 | 结果 |
|---|---|---|
| **A** | **语料不变** | 每一份：T2 记值 → T3 带特化跑，stdout + 退出码与 T0 **逐字节相同**。**9 份**，观察到 **607** 个调用站点 |
| **B** | **真的去优化过** | 夹具在这一次跑里**恰好**触发 1 次守卫，答案 rc=18（T0 同） |
| **C** | **副作用只发生一次** | 同一趟 stdout **正好** `A`×1001 + `B`（1002 字节）—— 重跑一遍会给 2002 个 `A` |
| **D** | **反例：零去优化** | 把"改成 9"那一行去掉，记录**空**，rc=14 |

**B 是判据非空的前提**（`docs/249` §5.1 第 2 条）：一个"没敢特化"的实现在 A 下**照样全绿**。

## 6. 落地时踩的三件事（都是"绿得看不出来"那一类）

1. **夹具写错了：两个站点 ≠ 一个站点。** 第一版把"先 1000 次 7、再一次 9"写成了
   `f(7)` 与 `f(9)` **两处调用** —— 那是两个站点，各自都只观察到一个值，于是**永远不会去优化**，
   而答案是**全对的**。判据 B（"必须恰好去优化一次"）当场把它抓了出来。
2. **内联把被调的帧边界弄丢了。** 内联之后被调的 `alloca` 直接长在**调用者的**帧游标上，
   `tour` 那种 1000 轮的循环把帧撑过栈顶 —— `写越界: 16777216`。修法是照抄真调用会给的
   基址：`STACK_TOP - (depth+1)*FRAME_SIZE`。**`alloca` 的地址是可观察的**，
   所以这不是"实现细节"，是语义。
3. **已特化的被调不许再内联。** `lumtui_off_nodes` 先被特化、又被摊进 `lumtui_nrec`，
   而 `_remap_op` 不认识 T3 那三条 op —— 顺序决定了成败，所以按**形状**拒（被调里只要有一条
   T3 op 就不内联），不靠顺序。

## 7. 我不主张

1. **不主张 T3 更快**。这一格没有 A 堆，B1 的收益也只在"调用点被内联掉"那一点上 ——
   而它的存在理由是**证明去优化这条路**，不是提速。
2. **不主张去优化便宜是普遍的**。§3：那是槽机的地基，换成寄存器分配就不成立。
3. **不主张 A 堆不做也没关系**。`docs/248` §3.1 那五条仍然是 T3 的正经工作，只是**不需要
   这一格的判据**（它们不背假设）。
4. **不主张阈值 90% 是对的**。它是拍的，`docs/248` §6 要求"先做哪几条由数字说话" ——
   这个数也该由数字说话，现在还没有那个数字。
