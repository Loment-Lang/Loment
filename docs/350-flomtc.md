# 350 · Flomtc：5000 行中等程序 1000 ms 编译的加速器设计

> 状态: **设计稿 + 基线实测 + V0 落地**（2026-11-18）
> 基准: `origin/main`（`b37ede78`，2026-11-18；初测在 `663b93ff`）
> 实测环境: WSL2 Ubuntu / Ryzen 9 7945HX / Python 3.11.15 / Loment 参考链
> 上游: `docs/226-loment-performance-ledger.md`（编译速度账）· `docs/298-lomentfaster.md`
> （运行时三档加速）· `docs/212-loment-offload.md`（逃生舱）· `docs/225-loment-runtime-gaps.md`
> （自举符号查找线性扫）· `docs/344-lspe-framework.md`（LSPE 调度器，检查段的加速面）·
> `docs/158`（冻结面与双实现）
> 一句话: **Flomtc 不是新的语言，也不是新的运行时；它把编译链从 Python 参考实现
> 换成一个原生前端 + 原生检查/IR/链接器，目标是在 5045 行中等程序上把 1987 ms
> 压到 1000 ms 以内，并且产物与参考实现逐字节相同。**

---

## 0. 三句话

1. **基线是 1987 ms**（in-process，5045 行 / 360 函数）：front **1105 ms**、
   check **662 ms**、IR **19 ms**、`lomelf` **201 ms**。前端 + 检查占 **89%**。
2. **目标 1000 ms 需要 ~2×**。一个原生前端（7× 的前端）+ 原生检查（3×）+
   原生链接器（3×）可以做到 **~500 ms**，留 500 ms 给诊断、冷启动、
   LSPE 强制检查与余量。
3. **硬约束是逐字节相同**：Flomtc 是第三份实现，产物（IR / ELF / Potato）
   必须与参考实现逐字节一致；不支持的构造**回退**到参考实现，并把回退计数写进
   产物。1000 ms 只对“快速子集 + 5000 行中等形状”成立，不是所有程序的保证。

## 1. 基线：5045 行中等程序

### 1.1 语料

- **5045 行 / 360 个函数 / 78,292 B**。
- 每个函数 12 行：`let` + `if` + `while` + 返回；`_start` 逐个调用 360 个函数。
- 形状是“中等程序”：**函数多、每个函数小、有控制流**，不是单个巨型函数。
- 生成器与文件：`bench5000.lomt`（研究脚本；不进仓）。

### 1.2 四段（in-process，main `b37ede78`；初测 `663b93ff`）

| 阶段 | 时间 | 占比 | 产物 |
|---|---:|---:|---|
| **front**（前门翻译 + 词法/语法 + LSPE 普查） | **1105 ms** | 56% | — |
| **check**（类型/CFG + LSPE 求解） | **662 ms** | 33% | 0 个错误 |
| **ir**（`emit_llvm`） | **19 ms** | 1% | 367,274 B IR |
| **lomelf**（汇编 + ELF） | **201 ms** | 10% | 237,944 B ELF |
| **合计** | **1,987 ms** | 100% | |

> **口径**：`lomentc.load_unit` / `check` / `emit_llvm` / `lomelf.compile_ll` 四段，
> 与 `docs/226` §3 同一套 API。CLI 的 `lomentc.py --check` 在初测 `663b93ff` 上是 **4,560 ms**、
> `loment.py ir` **2,449 ms**：CLI 在加载/诊断/审计上还有额外开销；Flomtc 必须走
> **in-process 路径**，不能把 CLI 的慢当成语言本身的慢。

### 1.3 与 `docs/226` 的对照

- `docs/226` §3.1 的 5000 **条语句**（单个大函数）：1.54 s（front 236 / check 552 /
  IR 602 / lomelf 153）。IR 602 ms 是因为单函数 IR 巨大；本语料的 360 个小函数
  只花 **20 ms**。
- `docs/226` §3.2 的“函数个数不是瓶颈”（单模块 2000 个平凡函数 0.16 s）与
  本语料不矛盾：本语料的 **LSPE 站点**（`if` / `while` / 初始化）才是前端的成本，
  不是函数个数本身。
- `docs/226` §3.3 的**模块数平方**（1011 模块 192 s）不在本目标的形状里；
  5000 行单模块是本文的验收面。

## 2. “5000 行 1000 ms”到底指什么

| 维度 | 本文的验收口径 |
|---|---|
| **形状** | 单模块、约 5000 行、几百个函数、普通控制流；不含病态长表达式/深嵌套/上千模块 |
| **阶段** | front + check + IR + lomelf + Potato；**含 LSPE 强制检查** |
| **审计** | 默认 `--fast-audit`：证明树 / LSPC 可延迟到 `flomtc audit`，但**延迟要记录**；`--audit` 跑全量 |
| **冷/热** | **冷启动、无缓存**；热构建另设 ≤200 ms |
| **机器** | 本文的 WSL2 / Ryzen 9 7945HX；其他机器按同一比例外推，不作保证 |
| **产物** | 与参考实现**逐字节相同**的 IR / ELF / Potato |
| **失败面** | 不支持的构造回退参考实现，回退计数进 Potato；回退路径不承诺 1000 ms |

**不承诺**：1011 模块的 192 s 前端、5 万条语句的 30 s、病态扁平表达式、
`--audit` 全量证明树、其他机器上的绝对毫秒数。

## 3. 时间花在哪

### 3.1 front 1105 ms

- 前门翻译 + 词法/语法 + **LSPE 站点普查**（`census.py` 的 E1–E4/E9/E10 站点扫描）。
- 每个函数约 3.1 ms；360 个函数、约 1000 个站点。
- 参考实现是 Python：token 列表、dict、字符串切分、逐函数重复建表；单线程。

### 3.2 check 662 ms

- 类型/CFG + **LSPE 求解器**：14 条义务、9 个引擎、证据格工作列表。
- 本语料没有显式 `guard`/`domain`/`borrow`，但 `if`/`while`/`let` 仍产生
  `Initialized` / `InBounds` / `TypeWellFormed` 等站点；求解器仍要跑。
- 参考实现是 Python；求解器是单队列、全局预算、单线程。

### 3.3 IR 19 ms

- 360 个小函数，IR 367 KB；`emit_llvm` 是字符串拼接，但每函数很小，
  所以这一段不是瓶颈。单巨型函数的 IR 才会贵（`docs/226` 602 ms）。

### 3.4 lomelf 201 ms

- 367 KB IR → 238 KB ELF；参考 `lomelf.py` 是 Python 的栈机汇编器。
- 这一段在 `docs/226` 里对 5000 语句是 153 ms；本语料的 201 ms 是可控的。

## 4. Flomtc 架构

### 4.1 总形状

```
flomtc（Rust 原生二进制）
├── front     词法 / 语法 / 前门翻译 / LSPE 普查
├── check     类型 / CFG / LSPE 引擎 + 求解器
├── ir        IR 文本发射（缓冲，不拼字符串）
├── link      ELF 汇编（lomelf 语义的原生实现）
├── cache     内容哈希 / 单元缓存 / 证明哈希复用
└── fallback  不支持的构造 → 参考实现（lomentc.py + lomelf.py）
```

**Flomtc 是第三份实现**：参考实现（Python）、自举实现（`.lomt`）、Flomtc（Rust）。
三者对同一份源必须给同一份 IR / ELF / Potato；差分判据是生命线。

### 4.2 为什么是原生前端

- `front` 1105 ms 是最大的一段；它做的是**重复的 token 扫描、字符串切分、
  逐函数建表**。原生实现可以用：
  - 字节级 lexer + 表驱动关键字；
  -  arena AST / 显式栈（不再有 Python 递归上限，见 `docs/226` §3.4）；
  -  符号 interning + FxHash；
  -  per-function 并行（rayon / 工作窃取）；
  -  不可变全局表，确定性合并。
- 目标：front 1105 → **150 ms**（7.4×）。

### 4.3 为什么是原生检查

- `check` 662 ms 里，类型/CFG 与 LSPE 求解器各占一部分。
- 原生实现：
  - 符号表用 dict/开放寻址，不再线性扫；
  - LSPE 引擎按 `docs/344` 的调度器**只跑适用的子类**（无域就不跑 E9，
    无借用就不跑 E10，无泛型就不跑 E6）；
  - 证据格求解器用位集 + 工作列表，按站点 id 确定性排序；
  - **快速审计**：默认只跑强制集（`TypeWellFormed` / `NoRuntime` /
    `InBounds` / `InDomain` / `E6`），E5/E7/E8 与证明树/ LSPC 延迟到
    `flomtc audit`；Potato 记 `audit_deferred=true`，**不静默**。
- 目标：check 662 → **220 ms**（3.0×）。

### 4.4 为什么是原生 IR/链接

- IR 19 ms 已经很快；原生缓冲发射目标 **10 ms**。
- `lomelf` 201 ms 是 Python 汇编器；原生 ELF 汇编目标 **70 ms**（2.9×）。
- 逐字节相同：IR 文本、ELF 段布局、Potato 序列化都要与参考实现一致；
  差分判据先红后绿。

### 4.5 缓存与并行

- **单元缓存**：源文件内容哈希 + 维度 + LSPE level → 缓存 IR/Potato/ELF；
  未变单元直接命中；热构建目标 ≤200 ms。
- **函数缓存**：同一函数源跨构建/跨单元复用检查结果；证明哈希相同才命中
  （`docs/262` §5.13 的缓存纪律）。
- **并行**：per-function 检查/发射；确定性输出顺序；LSPE 证据按站点 id 合并。
- **模块数**：多模块的平方成本不在 1000 ms 目标里；Flomtc 的缓存/并行是为
  热构建和多模块准备的，但本文不承诺 1011 模块。

### 4.6 回退

Flomtc 只覆盖“快速子集”：普通函数、控制流、类型、能力域、LSPE 站点、IR/ELF。
遇到未实现的构造（例如新的表层语法、复杂泛型、PE 目标、LSPE 的某个新引擎）：

- **回退到参考实现**：`lomentc.py` + `lomelf.py`；
- 产物是参考实现的字节（保证正确）；
- Potato 记 `flomtc_fallback=<原因>`；
- 回退路径**不承诺 1000 ms**；
- 回退计数是 Flomtc 的覆盖率指标，只许下降。

## 5. 时间预算

| 阶段 | 基线 | Flomtc 目标 | 手段 |
|---|---:|---:|---|
| front | 1105 ms | **150 ms** | 原生 lexer/parser、arena、interning、并行普查 |
| check | 662 ms | **220 ms** | 原生类型/CFG、LSPE 调度器、快速审计 |
| IR | 19 ms | **10 ms** | 缓冲发射 |
| lomelf | 201 ms | **70 ms** | 原生 ELF 汇编 |
| Potato/台账 | 含在 check | **50 ms** | 延迟证明树；只写必要字段 |
| **合计** | **1,987 ms** | **~500 ms** | 4.0× 余量 |

**1000 ms 的余量**：500 ms 用于诊断、冷启动、LSPE 强制检查、缓存未命中、
以及不同语料的波动。目标不是“刚好 999 ms”，是“稳定低于 1000 ms”。

### 5.1 先试最便宜的一档

在动手写 Rust 之前，先量两条低成本路径：

1. **PyPy / Nuitka 冻结**：把 `lomentc.py` 跑在 PyPy 3.11 或 Nuitka 冻结二进制上，
   前端/检查可能快 2–3×；1987 ms → ~700–1000 ms，**可能直接达标**。
   本机当前没有 PyPy/Nuitka（实测 `command not found` / import 失败），需要先装。
2. **缓存 + 并行**：如果验收允许热构建，单元缓存 + 多进程可以把 1987 ms 压到
   200 ms 以内；但冷启动目标仍要原生前端。

**建议顺序**：先做 5.1.1 的冻结测量（一天级）；如果达标，Flomtc 的 Rust 前端
可以降级为“下一档”；如果不达标，按 §4 做原生前端。

## 6. 快速审计：1000 ms 与 LSPE 的冲突

LSPE 是 Loment 的卖点；1000 ms 不能靠“关掉检查”换。规则：

| 模式 | 跑什么 | Potato | 承诺 |
|---|---|---|---|
| `flomtc build`（默认） | 强制集 + 适用引擎；**证明树/LSPC 延迟** | `audit_deferred=true` | ≤1000 ms |
| `flomtc audit` | 全量引擎 + 派生树 + LSPC | `audit_deferred=false` | 另计时 |
| `flomtc build --audit` | 构建 + 全量审计 | 完整 | 可能 >1000 ms |

- **强制集不能跳**：`TypeWellFormed` / `NoRuntime` / `InBounds` / `InDomain` /
  `E6`（有泛型时）必须跑；跳过的是**非强制证据**与**证明树/LSPC 的物化**。
- **延迟要记录**：`audit_deferred=true` 进 Potato；`flomtc audit` 补全；
  不静默。
- 这条与 `docs/262` §10.2 的 `lspe_close_admin` 同一条纪律：关的是审计的
  **记录**，不是检查本身。

## 7. 前史

| 先例 | 机制 | 对 Flomtc 的教训 |
|---|---|---|
| **Go 编译器** | 单趟、无优化器、原生、并行 | 编译速度是设计目标，不是事后优化 |
| **tcc** | 极小 C 编译器、直接出机器码 | 简单直接比“完整优化”快一个量级 |
| **esbuild** | Go 写，10–100× 于 TypeScript 工具链 | 原生 + 并行 + 少抽象是数量级差异 |
| **Zig / rustc incremental** | 增量、查询、缓存 | 热构建靠内容哈希与查询缓存 |
| **Clang / Roslyn** | 前端/后端分层、并行 | 分层与并行是可控的加速面 |
| **swc / oxc / biome** | Rust 重写 JS/TS 工具链 | 逐字节兼容 + 差分判据是重写的前提 |

**自报**：Flomtc 没有新算法；它把 `docs/226` 已经量过的瓶颈（Python 前端、
超线性符号查找、单线程）换成原生实现，并用差分判据保证产物不变。

## 8. 不可能性与边界（先写死）

1. **1000 ms 只对本文的形状**：单模块、约 5000 行、几百个函数、普通控制流。
   1011 模块（`docs/226` 192 s）、5 万条语句（30 s）、病态扁平表达式不在内。
2. **全量审计可能超 1000 ms**：默认 build 是快速审计；`--audit` 另计时。
3. **逐字节相同是硬约束**：Flomtc 是第三份实现；不支持的构造必须回退，
   回退路径不承诺 1000 ms。
4. **原生重写不是一天的事**：参考链 47.5k 行（`lomentc.py` 15.5k +
   `lomelf.py` 7.1k + 自举 23.7k + LSPE 1.1k）。Flomtc 先做快速子集 + 回退，
   不追求一次覆盖全部。
5. **本机没有 PyPy/Nuitka**：5.1 的冻结测量要先装工具；不假设它一定达标。
6. **墙钟是产品目标，不是门禁比值**：门禁用绝对天花板与确定性计数
   （`#442` / `docs/226` 的纪律）；1000 ms 不作 CI 的逐次比值门禁。
7. **机器相关**：本文的毫秒数只在 Ryzen 9 7945HX / WSL2 上成立；其他机器按比例外推。
8. **不能拿 1000 ms 换掉 LSPE 强制检查**：快速审计只延迟证明树/LSPC，
   强制集照跑，延迟进 Potato。

## 11. 我不主张

1. **不主张新的语言/运行时优化**。Flomtc 只动编译链；运行时的三档在 `docs/298`。
2. **不主张全量重写**。先快速子集 + 回退，不一次覆盖 47.5k 行。
3. **不主张 1000 ms 对所有程序成立**。只对本文的 5000 行中等形状。
4. **不主张跳过 LSPE**。快速审计只延迟证明树/LSPC，强制集照跑，延迟进产物。
5. **不主张墙钟比值门禁**。1000 ms 是产品目标；门禁用绝对天花板与确定性计数。
6. **不主张本机冻结一定达标**。PyPy/Nuitka 未安装；5.1 是测量，不是承诺。
7. **不主张跨机器绝对毫秒数**。按比例外推，不作保证。

## 12. V0 落地（2026-11-18，用户三刀）

用户 2026-11-18 定下三条形状，这一节记它们**落成了什么**：

1. **整个优化由 `choose flomtc_true` 启用**；
2. **`flomtc` 与 `lomenterr` 一样是独立存在，有自己的 exe**；
3. **有自己的 `flomtc.lomt`**（职责 = 编译器实现）。

### 12.1 第十维：`flomtc_false` / `flomtc_true`

- 登记在参考实现 `CORE_DIMS` / `CORE_DIM_ORDER` / `CORE_DEFAULTS` / `CORE_DIM_ZH`
  （`tools/lomentc.py`）与 `tools/potato.py` 的 `FLOMTCS` / `CORE_WORDS`。
- 自举侧：`checker.lomt` 的 `chk_core_dim`（第九格，槽位与哨兵各后移一格）、
  `chk_core_val`、`switches.lomt` 的 `sw_is_core` 同步。
- **不进 Potato 的顶层维度**：它说的是"这份产物怎么被编出来的"，
  不是"这份产物是什么"。`flomtc_false` 是默认档，默认产物**逐字节不变**。

### 12.2 快路径（两个实现）

- **参考侧**（`emit_potato`）：去掉整模块 `deepcopy`；只有**泛型使用**（impls /
  类方法 / try / guard / 泛型类型引用 / 泛型函数声明）才走完整 `prepare`，
  否则只过滤预置的未用泛型声明（浅拷贝，不动调用者手里的模块 ——
  `emit_potato` 在 `emit_llvm` 之前跑，2026-11-18 实测过这个次序）。
- **自举侧**（`potato.lomt`）：`pt_flomtc` 读输入单元的 `choose flomtc_true`；
  `pt_mono_used` 是 O(tokens × 泛型声明数) 的前置门 —— 没有泛型**调用点**时跳过
  `pt_mono_all`（实例数为 0，产物与走一遍相同）。
- **产物相同**：`loment_potato_emit_test` 新增一条，两份同源（只差这一行）
  在参考与自举两侧逐字节相同，且 Potato 里没有 `flomtc` 这一格。

### 12.3 实测（Windows 11 / 5045 行 / 360 函数 / best of 3）

| 阶段 | `flomtc_false` | `flomtc_true` |
|---|---:|---:|
| front | 555 ms | 618 ms |
| check | 410 ms | 429 ms |
| **potato** | **940 ms** | **380 ms** |
| IR | 10 ms | 12 ms |
| lomelf | 108 ms | 134 ms |
| **合计** | **2,022 ms** | **1,574 ms** |

`front`/`check` 的差是同一台机器的噪声（同一源、只多一行）；**可归因的是
Potato 940 → 380 ms（2.5×）**，产物三样（Potato / IR / ELF）SHA-256 相同。
离 1000 ms 还差 **1.57×**；front + check 现在是主项，属于 §4.2/§4.3 的 V1/V2。
本机同一轮的另一次实测 total 到过 1,223 ms —— 墙钟只作产品账，不作门禁
（§8 第 6 条）。

### 12.4 独立实体

- `loment/tools/flomtc.lomt`：**自己的入口**，`use "../selfhost/driver.lomt"`，
  跑的是**同一份编译器实现**（不抄第二份驱动）。
- `loment_dist.TOOLS` 新增 `("flomtc", "loment/tools/flomtc.lomt", ".")`：
  随包发一个独立 `flomtc` 可执行文件，与 `lomenterr` 同一种存在。
- 实测（本机现场链）：`flomtc.exe` 4,222,976 B；在 `flomtc_false` / `flomtc_true`
  两份语料上的 `--emit-potato` 与参考逐字节相同。
- ⚠ 一条已踩的 ABI 规则：单元的发散符号是平的 —— `flomtc.lomt` **不能**再写一个
  `_start`（会与驱动单元重名，检查器点名拒）。入口由被导入的驱动单元提供。
- **还没做**（如实记）：原生 front/check/IR/链接器（V1–V3）、缓存/并行（V4）、
  `flomtc audit` 的两种审计档（§6）、`flomtc` 自己的版本号与命令面。

### 12.5 V1 第一刀：冷路径 2122 → 991 ms

> 2026-11-19。口径修正：§12.3 的"best of 3"里 IR 命中了缓存（第二遍起 ~10 ms），
> 那不是冷启动。`tools/flomtc.py` 现在默认 `LOMENT_CACHE=off`（`bench --cache` 才量热构建）。

三处改动，全部只由 `choose flomtc_true` 开门：

1. **`prepare` 的快路径**（`tools/lomentc.py`）：只有泛型**声明**、没有使用时，
   不深拷贝整模块 —— 浅拷贝后过滤声明，再跑与泛型无关的三道解析
   （`_resolve_solid_aliases` / `_resolve_guards` / `_resolve_domains`）。
   `check()` 与 `emit_llvm()` 都走 `prepare`，所以 check 344 → 154 ms、IR 411 → 149 ms。
2. **AST 事实一趟走完**（`emit_potato`）：`boundary` / `surfaces` / `net_ladder` /
   `gc_control` / `gc_ladder` 原先各走一遍全树（每结点还要 `dataclasses.fields()`）；
   快路径用 `_call_facts` 并成一遍，字段表按类型缓存。Potato 842 → 143 ms。
3. **`loment_fstr.rewrite` 的恒等快路径**：没有 `f"` / `command` / `foruse` / `/*`
   时这一趟只是原样抄一遍源码，直接返回（输出相同；块注释仍走全扫，因为未闭合
   块注释由它在报错）。front 423 → 444 的噪声内，实测约省 80 ms。

冷启动实测（5045 行 / 360 函数 / best of 3 / Windows 11 / `LOMENT_CACHE=off`）：

| 阶段 | `flomtc_false` | `flomtc_true` |
|---|---:|---:|
| front | 423 ms | 444 ms |
| check | 344 ms | **154 ms** |
| potato | 842 ms | **143 ms** |
| IR | 411 ms | **149 ms** |
| lomelf | 102 ms | 101 ms |
| **合计** | **2,122 ms** | **991 ms** |

**2.14×**，首次进入 1000 ms 以内。产物（Potato / IR / ELF）SHA-256 相同。
覆盖判据：`COVERED` 的 **33 份单文件示例**在两种档上的 Potato 与 IR 逐字节相同
（`loment_potato_emit_test` 新增一条；开关写在 `module` 那一行，避免临时名随行号位移）。

余下的大项：front 444、check 154、IR 149 —— 原生前端（§4.2）与并行（§4.5）仍是下一档。

### 12.6 原生自举编译器的快路径：15.8 s → ~450 ms（默认档）

> 2026-11-20。"理论上能不能更快"的实测回答：991 ms 是 Python 参考实现的成绩；随包那份
> **原生** `flomtc`（自举实现）在同一语料上原本要 **15.8 s**，定位并修复后是 **~450 ms**
> （34×）。用户 2026-11-20 追加要求"自举默认进入 2000 ms 内"—— 这几处改动因此落在
> **默认档**，不再由 `choose flomtc_true` 开门。

**定位**（临时标记点，测量后已撤）：`--print-command`（只词法）86 ms，
`check_arena` 占其余全部。函数级拆分：`chk_moves` **11.9 s**、`chk_life` 0.45 s、
`chk_body` 0.08 s。规模扫描 45/90/180/360 → 0.33/1.04/3.59/13.5 s（接近二次方）；
每函数局部变量从 1 增到 8，时间再涨 12× —— 根因是名字表的线性查找。

**改动**（自举实现，**默认档生效**；参考实现 Python 不受影响，它的快路径仍由
`choose flomtc_true` 开门）：

1. **名字表哈希索引**（`checker.lomt`）：`chk_lookup_slot` 改为 FNV-1a + 开放寻址，
   8192 桶 × 4 字节接在类型表之后（arena 142,688 → 175,456 字节）。泛型形参
   （`decl_tparams`）也进索引 —— 漏掉它 `Option<T>` 的载荷 `T` 就查不到。
2. **`lms` 档缓存搬到整单元**：`chk_lms_c` 的缓存原先放在 `CHK_FR_ON` 并**每函数清零**，
   于是每个函数都重扫一遍 token 流（`chk_lms_on`，O(n²)）。缓存改放类型表与
   `moved` 表之间的空段（`CHK_LMS_ON = 1032`），整单元只算一次。
3. **move / life 检查的证明性跳过**：用户段没有 `&` / `free` / `struct` / `enum` /
   `str` / `[` / `fp` / **字符串字面量** / 大写开头的类型名时，这两趟证明不出任何
   诊断（移动要求非 Copy 类型、悬垂要求 `&`、E029 要求 `free`）—— 整段跳过。
   预置块（`pub enum Option` 起）不算用户段；触发项保守地多收。

**实测**（5045 行 / 360 函数 / best of 3 / Windows 11 / `LOMENT_CACHE=off`）：

| 实现 | `flomtc_false` | `flomtc_true` |
|---|---:|---:|
| 参考实现（进程内） | 2,122 ms | 991 ms |
| 自举 stage1（随包形态） | **441 ms** | 453 ms |

默认档 **441 ms**，进入 2000 ms 内（用户要求）；对这份语料，自举侧两种档已无差别。

产物：`--emit-potato` 56,347 B，与参考实现逐字节相同（`COVERED` 的 33 份示例默认档
33/33、开快路径 27/27；`loment_potato_emit_test` 12/12）。默认档的 33/33 是在
**证明性跳过生效之后**重测的 —— 有聚合 / 借用 / 字符串的示例照旧走完整两趟。

**离理论下限还有多远**（如实记）：30–100 ms 是单趟原生编译器的量级，今天还没到。
原生侧剩余大项（标记点实测）：词法 ~76 ms、check 前缀 ~98 ms、函数体 80 ms、
`potato_emit` ~165 ms。下一刀：`compute_safe` 与站点普查能否在"无 alloc / 无 guard"
的单元里证明性跳过；词法器的逐字节热循环。`chk_moves` 的根因（线性表）已由哈希解决，
但**有借用/聚合的程序**仍会走完整两趟 —— 那条路径没有变快。
