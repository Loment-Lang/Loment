# 265 · LVM 编译产物缓存 —— **第二趟不该再付一次编译的价钱**

> 状态: **已落地**（2026-10-19，issue #646）· 上游: `docs/250`（紧凑形）· `docs/259` §6（编译成本）
> 判据: `tools/lvm_cache_test.py`（6/6）· 实装: `tools/lvm_cache.py`
> 一句话: **把已经编译好的那批 op 放到输入旁边，下次读它** —— 不是再发明一种格式，
> 是给紧凑形套一层"这份缓存配不配这份输入"的头。

---

## 1. 它解决什么

T2 每次跑都把整份 IR 重新解析、重新编译。`docs/259` §6 记着 `lumtui_demo` 的编译成本
（62 ms），`docs/250` §3.1 记着紧凑形把载入从 81.7 ms 压到 24.7 ms。开发循环里同一份程序
反复跑，那一段每次都要再付。

现在缓存命中时第二趟只做"读文件 + 解码"：

| 程序 | IR 字节 | 冷（重新编译） | 热（读缓存） | 缓存大小 |
|---|---:|---:|---:|---:|
| `tour` | 22,115 | 10.1 ms | **0.3 ms** | 7,005 B |
| `lumtui_demo` | 384,574 | 88.5 ms | **1.0 ms** | 109,463 B |

（本机、取 3 次中位数。**这是记账，不是判据** —— 判据量的是解码次数，见 §4 C。）

## 2. 为什么缓存头里要记四样

`docs/250` 的紧凑形只回答"这份字节是什么"；缓存还要回答"它配不配**这份输入**"。所以头里记：

| 字段 | 它挡的是哪种旧数据 |
|---|---|
| 输入大小 | 改短/改长 |
| 输入 mtime | 内容没变但被碰过（保守：一律重编） |
| 输入内容哈希（blake2b-256） | 同大小、同 mtime 的替换 |
| **IR 文本哈希** | 入口一个字节没动，但它 `use` 的模块变了 |

**第四条是这一层唯一"看不出来"的过期。** 源文件的三样只能证明"入口没变"，证明不了
"被编译出来的那份 IR 没变"—— 依赖是另一批文件。所以缓存键取的是**IR 本身**的哈希；
前三样只是让"明显变了"的情况在算 IR 之前就能拒（`--tier t2` 的源输入今天仍要先过前端，
这一层省的是 IR 之后那一段，与 `docs/259` §6 记的是同一段）。

## 3. 旧缓存**点名拒绝**，不是"多半还对"

`lvm_cache.decode()` 任何一处对不上都抛 `CacheStale`，消息里带**缓存文件路径**和**是哪一样**
变了（大小 / mtime / 内容 / IR / 载荷长度 / 魔数 / 版本 / 形）。随后 `load_or_build()` 重编
并把新的写回去。

这不是"坏了就重编"那么弱：一份**另一份程序**的缓存如果被静默用下去，跑出来的是**另一个
答案**。判据 `test_stale_cache_is_refused_by_name` 喂的正是这份缓存，断言拒绝被看见，
并且重编后给出的是**新程序**的数。

## 4. 判据（`tools/lvm_cache_test.py`，6/6）

| # | 判据 | 证伪方式 |
|---|---|---|
| **A** | 冷/热两趟 **stdout + 退出码 + 剖面**逐字节相同 | 小夹具 + 语料 `tour` 各一遍 |
| **B** | 另一份输入 / 另一份 IR 的缓存 **点名拒绝** | 两条分支各喂一次，断言消息里带路径与原因，且重编后的答案属于新程序 |
| **C** | 热的那一趟 **0 次** `parse_type` / `parse_operand` | 冷的那一趟 > 0 **也断言** —— 否则量到的是"计数器没接上" |
| **D** | 文件头写着形；改形 / 改魔数 / 截断都点名拒 | 三种各一次 |

C 是这一层的自证，而且是**确定性**的：它把"第二趟没再编译"变成可以数出来的数。

## 5. 用法

    python tools/lvm.py prog.lomt --tier t2 --cache            # 缓存放 prog.lomt.lvmc
    python tools/lvm.py prog.lomt --tier t2 --cache out.lvmc   # 指定位置

- 只对 `--tier t2` 有效（缓的是那一格的编译产物）；与 `--compact` / `--compact-out` 互斥。
- 写失败（只读目录）只警告，不影响这一趟运行 —— 缓存是加速，不是运行的前提。
- 写是原子的（临时文件 + `os.replace`）：**半截缓存不如没有**。

## 6. 我不主张

1. **不主张它省掉了前端。** `.lomt` 输入仍要过 `lomentc`；省的是 IR -> op 那一段。
   要连前端一起缓存，得先有"依赖集合的哈希"，那是另一件事。
2. **不主张缓存可以跨档用。** 载荷是 **T2 的 op**；`--tier t0` / `t3` 不走这条路。
3. **不主张 mtime 变了但内容没变时该命中。** 保守地重编一次，比"猜它没变"便宜。
4. **不主张这个数可移植。** 上表是本机，比值只在同一次调用里比才有意义（`docs/226`）。
