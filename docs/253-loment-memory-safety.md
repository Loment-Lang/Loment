## 0. 一句话

Loment 的内存今天有两个正交的问题，而**只有一个有系统**：

| | 问什么 | 今天的答案 | 出处 |
|---|---|---|---|
| **生命周期** | 这块内存**什么时候归还** | **LGC**（四层梯 + 三档 + `gc_ladder`） | `docs/210` |
| **合法性** | 这个单元**凭什么**碰这块内存 | **没有系统** —— 只有三条界 + 一条散文 | `docs/206`、`docs/205` C5 |

这一页立的是第二格。**七级**（用户 2026-10-15 定，详表与理由见 §5.0）：

| 段 | 级 | 干什么 | 今天 |
|---|---|---|---|
| **梯子**（进程内降级） | 1 **检查器** | 平时：静态拒 | 只有 E006/E007/E012 三条界，且都不涉及内存访问合法性 |
| | 2 **管理器** | 法医：详细输出**所有**内存（占地极大） | 没有 |
| | 3 **保障器** | 内存溢出时**尝试拉回**（两个入口：用尽 / 越界） | `docs/206` §3 立了规矩（"线以外不许是 UB"），**没有兑现物** |
| | 4 **拒绝器** | 拉不回：**拒一切有问题的指令** | 没有 |
| | 5 **崩溃器** | 实在不行：**退出所有 Loment 进程** | 只有 `@__loment_abort`（`tools/lomentc.py:143`） |
| **地板**（进程外） | 6 **重启器** | **C 写的**，重启最小子集 | 没有 |
| | 7 **最小子集** | 从这里**编出全量 Loment** | **已有实物**：`loment/build/selfhost_driver.ll`（46 KB 种子） |

**轴的两半**（§4 详述）：合法性问"能不能"，能力域问"凭什么"。
`guard` / `excluded` 今天已经存在（`docs/146`、`tools/lomentc.py:576` 的 `__loment_guard`），
所以这一套**不是从零开始**，是把已有的两样东西接起来并补上运行期那一半。

**开关**（用户 2026-10-15 定）:套件名 **`LMS`**，开关维 `lms` —— 与 `gc` **正交**的一维。
它是**总闸（取档名）**：**默认 `lms_full`（七级全开）**，另有三个官方组合（§11.3 / §11.4）；
**七级每一级另有独立的细开关**（`set choose`），**显式开关覆盖档**（§11.4 的叠加规则）。

⇒ **默认是全量**，所以 §13 那条对 LLS 的越界**生效** —— 那张代价表要认。
登记处清单见 §11.1。

## 1. 前史先行（这一节不许跳）

`docs/210` §1 的规矩：**先点名，再说话**。这一线的前史分成两组 ——
一组是**十天前刚发生的**，另一组是三十年的**采用史**。

### 1.1 最紧的一拳：Rust 2026-10-13

2026-10-13，同一位报告者（`jsnell`）在同一天报出**两个不健全缺陷**，而它们**掉在不同的层**：

| | **#164250** | **#164243** |
|---|---|---|
| 标题 | `struct` 的 lifetime 要求可经**协变字段赋值**绕过 | 安全代码里 `process::exit()` 引发 **double free** |
| 机制 | `Holder<T: 'static>(Option<T>)` 构造后写 `holder.0 = Some(&local)` —— **统一化时不重查 lifetime bound**（`mem::swap` 同路可达） | thread-local 在 `with` 中途被 `exit` 触发析构，glibc 的 TLS 析构器再跑一遍 |
| 后果 | 自定义 `Drop` 把短引用搬进 `static` 容器 ⇒ **`stack-use-after-scope`**（ASan 确认）。PoC 带 `#![forbid(unsafe_code)]` | `free(): double free detected in tcache 2` |
| 潜伏 | 变体自 **1.18.0（2017）**，一份追溯到 **1.4** ⇒ **约 11 年** | 至少回溯到 1.85.0 |
| 修法 | **PR #164277**「require MIR local types to be well-formed」 | 未定；维护者倾向"`exit` 时不跑 TLS 析构器"，**在 macOS 上近乎无法实现** |
| **掉在哪一层** | **编译器**（约束检查漏了一处） | **std 运行期**（TLS 析构器） |

**这两条同一天出现，本身就是结论**：一个"安全"的承诺，其可信度**不等于语言的类型论**，
而等于**实现它的全部代码**（编译器 + 标准库 + 平台 ABI）。
`#164243` 尤其干净 —— 它**根本不在编译器里**，而 Rust 的安全论证只覆盖了编译器那一侧。

定级是 **I-unsound + P-high**（从 P-critical 降下来），理由是"潜伏 11 年未意外伤人"、
且复现需要"一个刻意构造的 `Drop`"。**降级的理由本身值得记下来**：
一条缺陷的严重度里，**"多久没人发现"被当成了减刑情节**。

> 相关的实证工作在 2026-08 已有人做：Sim / Ryu / Hong, *Rust's Type Checker Implementation
> Is Unsound: An Empirical Study on Soundness Bugs in rustc*, Proc. ACM SE 3(ISSTA), DOI 10.1145/3832220。
> ⚠ **本文只引用它的标题与作者**（正文是压缩对象流，本次检索读不出），
> **不引用它的结论** —— 这个仓不许把"读到过标题"说成"读过"。

### 1.2 那篇文章点破的是"地板"

同日那篇评论（`dev.to/slabb`）把 #164250 的意义说到了一层更深的地方：

> Rust 的承诺是一句话 —— **"If it compiles, the memory is safe."**
> 这条机器可检的保证一节一节往下传（借用检查 → 变型规则 → trait bound），
> 而它**落到一个没有任何检查器能执行的前提上**：
> **每一个 `Drop` impl 都诚实。**

作者给这个前提起了名字：**地板（the floor）**，并给了本文最该抄走的一句：

> **"The floor is not a scandal. An unlabeled floor is."**
> （地板本身不是丑闻。**没被标注的地板**才是。）

Rust 的问题**不是**它有地板（任何系统都有），而是那块地板**十一年没人标注**。

**这一句直接决定了本文的轴**（§4）：如果我只做一个"更严的检查器"，
复现的**正是** Rust 的失败模式 —— 一个静态承诺，其可信度等于实现它的那段代码的可信度，
而那段代码可以错十一年、且**事后无人能复核**。

### 1.3 历史教训七条（各自的死法）

第二组前史，每一行都问同一个问题：**它想证什么，最后怎么死的**。

| 系统 | 它想证的 | 结局 | **死因** |
|---|---|---|---|
| **.NET CAS** / **Java `SecurityManager`** | 域许可 | **被移除**（JEP 486 等） | **穷举式负向声明**：`RequestRefuse` 要你写全"我不想要的" ⇒ 漏一个就静默。本仓已收：`docs/229` §4.3 |
| **Cyclone** | 安全方言 + 区域 | 停滞 | 要人**改写代码**，收益归第三方 |
| **Checked C** | C 的边界检查扩展 | 停滞 | 同上；且要动 ABI |
| **Ada / SPARK** | 全证 | 存在，未普及 | **成本位置不对** —— 要证全，不是按需 |
| **ASan / MSan / HWASan** | 检测 | 广泛使用 | **检测不是保证**，且**只覆盖执行路径** |
| **SoftBound + CETS** | C 的空间 + 时间安全 | 研究 | **~2× 成本** |
| **CHERI / MTE** | 硬件能力 / tag | 研究中 / 部分部署 | **要新芯片**（MTE 还是概率性的） |
| **Fil-C**（Pizlo, 2025） | C/C++ **完备**内存安全 | **新** | **不 ABI 兼容**（pizfix / 重建 userland）；**全运行期**检查 |

**Fil-C 是最紧的一条，必须单独说**：InvisiCaps（不可见能力）+ 并发 GC，
让"释放"能**原子地作废所有指向它的指针** ⇒ use-after-free / double-free 一律 panic。
它在"能力 + GC"这条路上**已经把工程做完了**。

所以本文的新颖面**不是**"能力 + 回收"这个组合 —— 那个组合有人做完过。

**九条死因收敛到一句话**：

> **它们都假设"安全是给已有程序加上去的"。**

于是只有三条路：**改语言**（Rust/Cyclone/Checked C）、**付运行期**（sanitizer/Fil-C）、
**改硬件**（CHERI/MTE）。**三条都是真的贵** —— 而这是本文 §3 第 1 条的突破口。

### 1.4 于是新颖面缩到这一句

前史打完，剩下的是：

> **不是"更强的检查器"，而是把"凭什么放行"印在产物里，
> 并让回收层的每一个决定在安全层的账上当场兑现。**

前半句对应 §1.2 的"标注的地板"；后半句对应 §6 的交叉判据。
两半都不是"更安全"，是**安全的可复核性换了一个层面** ——
与 `docs/210` §3 那条窄新颖面（"GC 的组成是一个不读源码可判的数"）**逐字同构**。

## 2. 先把不可能性写死

**A.** 要"完备" ⇒ 每一条内存访问都必须被**证明**合法、或被**检查**合法。

**B.** 证明合法 = 判定「这个指针指向的块**还活着**，且偏移**在界内**」。

**C.** 这需要**别名与生命周期的联合判定**：
同一个块可经任意多条路径到达（别名问题不可判），而"活着"是**运行期**事实。
⇒ **静态完备不可能**（Rice 那一族）。

**D.** 退到运行期检查 ⇒ 每一次访问都要知道这块内存的**边界与身份** ⇒ **必须有元数据**。

**E.** 元数据只有三条出路，各付一样东西：

| 出路 | 代表 | 付的 |
|---|---|---|
| **进指针**（胖指针 / 能力位） | CHERI、Cyclone、Rust 的类型 | **改 ABI 与类型** |
| **出带外**（影子内存 / 不可见能力） | Fil-C、ASan | **运行期成本**；且要让失效原子还得**有 GC** |
| **进硬件**（tag） | MTE | **要新芯片**（且是概率性的） |

**F.** ⇒ **「完备 + 零成本 + 不改语言」是一条闭合的死链。**

## 3. 可以合法拿掉的三条假设

`docs/210` §1 的判据：**不要问概率，去问"不可能性证明的哪一条假设可以合法地删掉"**。

### 3.1 「不改语言」—— **拿掉**

Fil-C 明说不 ABI 兼容；CHERI 要新芯片；Cyclone / Checked C 改了语言。

**而 Loment 是自造语言的编译器** —— "不动语言"这条约束**在这里根本不成立**。
拿掉它 ⇒ 元数据可以**进源语言的域**（`docs/146` 的四元组 `(space, lo, hi, revocable)`），
于是检查器能在**编译期**做掉 §2·D 那一层里的一部分，而不必全推给运行期。

### 3.2 「一种机制打天下」—— **拿掉**

已有系统都是一个机制覆盖全体（一个借用检查器 / 一个 tag / 一个 GC）。
而 **Rust 这次的教训恰恰是**：**一个全局承诺，一处漏检就整体崩塌，且十一年不可见。**

LGC 已经证明**一个性质可以拆成逐站点的份额**（`gc_ladder`，Potato v10）。
拿掉这条假设 ⇒ **安全也拆**，而且拆开之后：

> **没有一个"整体"可以悄悄崩塌** —— 每个站点自己带一条判决，那判决印在产物里。

### 3.3 「安全是运行期行为」—— **拿掉**

已有系统的"安不安全"只能在**跑完之后**说（停顿分布、panic 日志、sanitizer 报告）。
Potato 已经证明**组成可以是产物里的一个数**。

拿掉它 ⇒ "**这份产物安不安全**"变成**不读源码可判**的数，
并且能与 `gc_ladder` **交叉对照**（§7）—— 而那一格是 **#362 那一类缺陷今天唯一的入口**。

## 4. 轴：为什么是两条（用户 2026-10-15 把这条判给我）

用户把"管哪一条轴"判给了本文（原话：「吸取 Rust 2026 年 10 月内存问题的教训，与历史教训自己选择」）。
**裁决与理由如下。**

### 4.1 裁决

> **轴 = 指针合法性（问"能不能"）+ 能力域（问"凭什么"）。**
>
> 合法性是**结论**，能力域是那个结论的**来源**。

### 4.2 理由：这是 §1.2 那块"地板"的直接推论

Rust 的判决是「**编译器放行了它**」—— 这是一条**不可复核**的陈述：
编译器是那个十一年前就错了的东西。本文要的判决是：

> 「站点 S47 落在**域 D** 的许可里，许可由 `guard` 在第 12 行授予。」

**同一句话，但可以点名是谁发的许可。** 这就是"把地板标出来"在内存轴上的具体形态：
**每一个"放行"都必须有一个来源，而不是一次"检查器说没问题"。**

### 4.3 而这两半，仓里已经各有一半

| 半 | 今天有什么 | 出处 |
|---|---|---|
| 能力域 | `capability` / `guard` / `excluded`，四元组 `(space, lo, hi, revocable)` | `docs/146`；`tools/lomentc.py` 的 `class Capability`（`:672`）、`__loment_guard`（`:576`）、`excluded` 的强制在 `_walk_expr`（`:4218`） |
| 指针合法性 | 只有 E006/E007/E012 三条**界**，且都不涉及越界 | `docs/206` §1 |

**`guard` 已经是运行期的**（越界即 `abort`，`tools/lomentc.py:7559`），
而**越界本身今天没有任何检查** —— 见 §4.4。

### 4.4 ⚠ 一块没被标注的地板：C5 的「已有」，覆盖面比字面小

`docs/205` §1.1 C5（`:48`）写着：

> 指针要、**无边界不要**：越界访问在**字面量时编译期拒**、**非字面量时运行期 trap**（**已有**）

**这句话是真的** —— 但它只覆盖**一格**：`guard`。

| 越界的形状 | 今天 | 证据 |
|---|---|---|
| `guard cap[i]`，`i` 是字面量 | **编译期拒** | `_walk_expr` 的 `Guard` 那一支（`tools/lomentc.py:4299`，判 `cap.lo <= v <= cap.hi`） |
| `guard cap[i]`，`i` 非字面量 | **运行期 trap** | `_Ir.stmt` 的 `Guard` 那一支（`:7559`）→ `@__loment_abort`（`:143`） |
| **`a[i]` 数组下标** | **什么都没有** | `_Ir.expr` 的 `Index` 那一支（`:6833`）发射 `getelementptr inbounds` —— 切片 `:6976`、数组 `:6990` |
| **`p + k` 指针算术** | **什么都没有** | 同上 |

`inbounds` 在 LLVM IR 里**恰是"越界即 UB"的标记**。于是下面那两格：

* 走 **clang**（`docs/212` §4 那条链）⇒ 编译器**有权假设不越界** ⇒ 干净的 UB（可被误编译）；
* 走 **`lomelf`**（包内栈机）⇒ 它不实现 `inbounds` 语义 ⇒ **静默踩相邻字节**。

**两条路都不是 trap。**

**实测（2026-10-15，在新工作树上跑的）**：一份

```rust
fn probe() -> u32 {
    let a: [u32; 4] = [1, 2, 3, 4];
    let x: u32 = a[10];
    return x;
}
```

的单元，`loment ir` **不报错**，发射出来的是

```
%t5 = getelementptr inbounds [4 x i32], ptr %a.addr, i32 0, i32 10
```

—— **下标 `10` 落在 `[4 x i32]` 上，还带着 `inbounds`**。
这一条不是读代码读出来的，是**跑出来的** —— §4.4 的证据等级因此与本文别处不同。

> **这就是"没被标注的地板"的本地实例**（§1.2）：C5 那句话读起来像覆盖**全部越界**，
> 而它实际覆盖的是**能力域那一格**。Rust 那块地板十一年没人标注；
> **这一块地板在本仓，而且它已经被一句话盖住了。**

⚠ **别说"越界没有 trap"** —— 运行期的挂点**不止一处**：除零（`_Ir.binop`，`:7096`）、
`panic`（`_Ir.builtin`，`:7274`）、根表容量（`_Ir.roots_push`，`:6804`）、
`guard`（`_Ir.stmt`，`:7559`）都走 `@__loment_abort`（`:143`）。
**缺的不是"陷阱"这个装置，是"内存访问的边界"这个挂点。**

**E028–E030（§5.1）就是来把这块地板标出来的。** 这一条比 §8 里任何一格都硬 ——
它不需要新主张，只需要**把一句已经写下的话的覆盖面说准**。

## 5. 设计

### 5.0 七级 —— 用户 2026-10-15 重定的形状

本文初稿是**三个部件**（检查器 / 报错器 / 保障器）。用户 2026-10-15 把它重定成
**七级**，而这不是"多了四级"，是**换了问题**：

> 初稿问的是「**怎么证明这块内存能碰**」；
> 七级问的是「**碰错了之后，系统还能不能活**」。

七级分成**两段**，两段性质根本不同：

| 段 | 级 | 时机 | 干什么 | 住在哪 |
|---|---|---|---|---|
| **梯子**（进程内） | 1 **检查器** | 平时 | 静态拒 | 编译期 |
| | 2 **管理器** | 法医 | 详细输出**所有**内存（占地极大） | 运行期，**有状态** |
| | 3 **保障器** | 内存溢出时 | **尝试拉回**（两个入口，§5.3） | 运行期 |
| | 4 **拒绝器** | 保障器拉不回 | **拒绝一切有问题的指令** | 运行期 |
| | 5 **崩溃器** | 实在不行 | **退出所有 Loment 进程**（全 Loment 公用） | 运行期 |
| **地板**（进程外） | 6 **重启器** | 进程死了 | **用 C 写的**，重启最小子集 | 不在任何 Loment 进程里 |
| | 7 **最小子集** | 重启之后 | 从这里**编译出全量 Loment** | 公用 |

**梯子的方向和别处相反**：它是**降级**，不是升级 —— 每一级都是上一级失效之后的**退路**。
这与 `docs/210` 那条四层梯不同：那个是**按能力分层**，这个是**按退路分层**。

**前史四条全打中（§1 之外的第二组）**：

| 级 | 前史 | 是谁 |
|---|---|---|
| 3 / 4 | **恢复块**（Recovery Blocks）：接收测试失败 ⇒ 回滚 ⇒ 试下一个副本 | **Randell 1975**《System Structure for Software Fault Tolerance》 |
| 5 | **crash-only software** —— 唯一的停机方式是崩溃，恢复就是重启 | **Candea & Fox**, HotOS'03 / OSDI'04 |
| 6 | **MINIX 3 的 reincarnation server** —— 驱动崩了由 RS 重起，驱动是用户态进程 | **Herder 等**, EuroSys'06 / DSN'07 |
| 7 | **Reflections on Trusting Trust** —— 你编出来的东西的可信度等于编它的那个东西 | **Thompson 1984**；**Diverse Double-Compiling**（Wheeler 2005） |

⚠ **第 7 级那句话（"全量 loment 太大不可信"）不是修辞** —— 它说的正是 Thompson 那道题。
而**本仓已经有这块地板的实物**：`loment/build/selfhost_driver.ll`（46 KB 自举种子），
加上「**两份实现逐字节一致**」那条判据 —— **那本来就是一次 Diverse Double-Compilation**，
只是从来没人把它当"**信任地板**"命名过、量过、印进产物过。

⇒ 按 §1.2 那条教训：**Rust 的地板十一年没被标注；这一套的地板是主动标出来的，
而且下面还垫了两级。**

**第 2 级是唯一可开关的一级**（§11.3）：它占地极大，所以**必须**由源码显式打开。

⚠ **初稿的"报错器"不在用户这一版里。** 它那一格（§5.2：跨时间轴的见证 ——
"这块内存在 S12 被释放，你在 S47 用了它"）**没有消失，只是换了宿主**：
第 2 级「详细输出所有内存」在正常情况下做的正是这件事，第 3/4 级的判决也要说得出"凭什么"。
**这一处是本文的推断，不是用户的裁定** —— 若要把报错器重新立成一级，说一声。

### 5.2 报错器（诊断，跨时间轴）

内存错误有一条别的错误没有的性质：**时间错位** —— 错在很久之后才被观察。
所以报错器要发的**不是**"这里错了"，而是**一份见证**（witness）：

> 这块内存在 **S12** 被释放（`free` 站点 id），你在 **S47** 用了它。

**前史必须自报**：这件事 ASan 在做（`freed by thread T0 here`）、Valgrind 在做（两块堆栈）。
**Loment 的差别只有一处，但它是决定性的**：见证**在产物里**（块头带 owner + `free` 站点 id），
**不靠一个插桩的运行期** —— 于是它在**没有插桩的档**下也在，且**离线可读**。

**第二件活，是 Rust 那条教训的直接兑现**：报错器必须能说
「**这个站点我证不了，因为 X**」。
`docs/225` §4③ 已经点名这一格是**空白**（「`κ` 的可操作诊断 —— 把'为什么证不出来'做成能读的东西」）。
**一个只报"错"、不报"证不了"的报错器，就是把地板重新藏起来。**

### 5.3 保障器（运行期，四格）

用户 2026-10-15 选定：**按站点分配**。四格与 LGC 的四层梯**同构**：

| 格 | 什么条件落进来 | 产物里插什么 | 成本 |
|---|---|---|---|
| **g0** | 编译期证得（域内 + 界是常量） | **什么都不插** | **0** |
| **g1** | 界是编译期常量、地址动态 | 一条常量比较 | 1 次比较 |
| **g2** | 界动态（域给了 `hi`） | 界检查 + `@__loment_abort`（`tools/lomentc.py:143`） | 1 次比较 |
| **g3** | 都算不出 | **不发任何东西 —— 改判成编译期拒**（§11.2） | 0（代价是一个诊断） |

**两条纪律**（第 2 条**已被 2026-10-15 的裁定改写**，见 §13）：

1. **四格落的是指令，不是组件**（§11.2）：比较 / `llvm.trap`，没有表、没有位图、
   没有叶子以外的代码。照 `docs/210` §4.5 的先例（`l3 == 0` 就不发收集器），
   **`g3 == 0` 是常态而不是特例**。
2. ⚠ **"默认档不开"那条不成立了。** 用户 2026-10-15：「**只有管理器可开关，其余全部强制启动**」
   —— 于是 g1/g2/g3 与 E028–E030 **默认就在**。**代价见 §13**，那不是一句"违反 LLS"。

#### 保障器的**两个入口**（用户 2026-10-15 定：两个都要）

上面 g0–g3 那张表只是**入口 B 的机制**。保障器有两个入口，**机制与代价完全不同**：

| 入口 | 触发 | 动作 | 机制 | 代价 |
|---|---|---|---|---|
| **A：内存用尽** | `alloc` 分配不出 / 活集撞上 arena 上限 | **回收、压实、回退前沿** | **接 LGC** —— 第 3 级的入口 A 就是 `docs/210` §2.6「自适应收集器」换一个**触发点**（按分配量 ⇒ 按紧急度） | 一次回收的时间；**不需要块内元数据** |
| **B：缓冲越界** | 块头 / 金丝雀 / 影子表明写穿了块边界 | **隔离被踩块、从影子重建、弃用该块** | g0–g3 四格 + **每块的边界元数据** | **要元数据 ⇒ 有状态** |

⚠ **两个入口不能共用一个代价模型**，必须分开计账、分开声明
（§7 的 `safety_ladder` 要**分两栏**）。

#### 入口 B 的准备（2026-10-15 调研，**不是设计**）

**① 检测那一半：元数据早就有了。** §5.3 那张表里入口 B 的代价写的是
「要元数据 ⇒ 有状态」。**查过之后，这句只对一半成立**：

`alloc` 在**块头**写的就是这一块的**总长**（`store i32 %need, ptr %wp`，载荷从 `+8` 起），
而 `free` 正是靠 `p - 8` 把它读回来的（`%hi = sub i32 %d32, 8`）。

⇒ **对一个 `alloc` 直接发出来的指针 `p`，它的界就是 `load32(p - 8) - 8`** ——
**一次 load + 一次比较，不需要任何新元数据**。那正好落在 g2 那一格
（"界动态、但拿得到"），不是 g3。**所以 §5.3 那格写贵了。**

**② 真正卡住的是两件事，都不是元数据：**

* **怎么知道一个指针"是 `alloc` 发出来的"。** 它可能来自栈上的数组 / 切片的
  `{ptr, i64}` / `ptr_add` 派生的**内部指针**。**内部指针最麻烦**：`ptr_add(p, k)`
  之后那个指针的 `p - 8` 已经不是块头了，读出来是**块里的数据**。
  这一格今天**没有类型可依**（`alloc(N)` 无类型、`ptr` 不带来源）——
  它是 `docs/210` §4.2 那条"块内只能保守扫"的**同一个洞**。
* **响应那一半才有状态**：「隔离被踩块、从影子重建、弃用该块」—— "从影子重建"要一份
  影子。§11.2 的"按级给"正是为这一格写的（它**允许有状态**），
  但**那份状态今天一个字节都没有**。

**③ 所以 B 的第一刀应该是**：只对**能证明是 `alloc` 直接发出、且没过 `ptr_add`** 的
指针发 g2 检查。**保守地不发**比"对派生指针乱发"安全 —— 后者会把块里的数据当块长读，
而那个后果比不检查更坏。

⚠ **②里"怎么知道来源"那一条今天没有答案**，而它是 B 能不能立起来的前提。
**先解它，再解响应** —— 反过来做就是先造一份没人用得上的影子。

#### 入口 A 的落地（2026-10-15，参考实现）

**是什么**：`alloc` 真的分配不出时（空闲链表没有够大的块、前沿也走不动），
**先 `collect` 一次再试**，还不行才 `abort`。今天 `boom` 是**直接 `abort`** —— 那是
"运行期灾难"；这一格要的是"**先试着拉回**"。

**怎么落的**：`tools/lomentc.py` 的 `_heap_with_lms_rescue(text)` ——
**一份变换，不是另抄一份**。照 `_arena_indirect`（hosted 那一份的来路，见 `_IR_GC_HOSTED`）
同一条路数：那 200 行分配器在两处实现里必须同源，手抄必漂。
三处局部改写，**每一处都先 `assert` 命中**，改不动就当场炸：

1. `floop` 的两个 phi 各加一条入边（从 `rescue` 回来）；
2. `boom` 不再直接 `abort` —— 先看这一次试过没有，没试过就收一次、重读空闲链表头、
   跳回 `floop`；**试过才死**（只许重来一次，否则一份没有垃圾的程序收了又收、出不去）；
3. **每一条成功返回前**清掉重试标记（sealed 两条、hosted 三条）—— 不清的话
   "这一次"用掉的那次重试会留给下一次分配，那是**假的能力**。

⚠ **两个条件缺一不可**，这是这一级**明写的边界**：

* `lms` 开着（它属于 LMS 第 3 级，不是回收档的事）；
* **这份产物里真的有收集器**（`gc_auto` / `gc_auto_alpha`）——
  **`gc_manual` 下没有东西可收，"拉回"在那里是一句空话**，所以那一格一个字都不加。

判据：`lomentc_test::test_lms_entry_a_rescue_needs_both_lms_and_a_collector`（网格
3 档 × 2）+ `_TIER_CHOOSES` 新增两格过 clang（**手写 IR 只有过 clang 才算合法**）。

⚠ **写这条判据时当场踩了 L0 那个坑**：第一版探针用 `alloc(64)`（**字面量**尺寸），
而 `gc_auto_alpha` 会把这种 `alloc` **静态提升到栈上** ⇒ 产物**根本不需要堆** ⇒
`__loment_alloc` 一个字节都不发，"分配不出"无从谈起 —— alpha 那一格**静默为空**，
看起来像"入口 A 没生效"，实际是**测的那件事不在场**。改走 `const` 名就取消提升资格。
**这是 `docs/210` §2.2 那条诊断教训的又一实例。**

### 5.4 拒绝器（保障器拉不回时）

**用户 2026-10-15 的定位**：「在保障器无法拉回时激活，**拒绝一切有问题的指令**」。

这是 Randell 那条恢复块的**下一格**：保障器是"试着重做"，拒绝器是"**不做了，但也不让它继续**"。

**它拒的是"指令"，不是"进程"** —— 这个区别是要紧的：第 5 级（崩溃器）赔进去的是**进程**，
第 4 级赔进去的是**那一条指令**。所以它买到的能力是**带着一个已知坏指令继续跑**。

**它的判据只能来自第 2/3 级** —— 拒绝器不自己发现错误（它没有那个本事）。
⇒ **第 4 级严格依赖第 3 级或第 2 级在场**，这给 `lms` 那一维加了一条**隐含的偏序**（§11.3）。

**它长什么样（提案，未证）**：一条被拒的指令 ⇒ 那一条 `load`/`store` **变成一个 trap**，
控制流**从它继续**（不是 `abort`，是"这一步不做，往下走"）。

⚠ **这一条是本文里唯一会改变程序语义的级** —— 别的级都是"拒"或"死"，只有它是"**跳过**"。
所以它的判据最难写：要能证明"跳过之后程序没有做出更坏的事"。**今天没有这条判据。**

### 5.5 地板：崩溃器 / 重启器 / 最小子集

这三级的性质与前四级**根本不同** —— 前四级是**一个进程内的降级**，这三级是
**跨进程、甚至跨语言**的。用户说得明确：**「全 Loment 公用」**。

#### 崩溃器（第 5 级）

「在实在不行的时候激活，**退出所有 Loment 进程**」。

⚠ **它有一条硬边界，必须写死**：`no_std` 档下只有 syscall，**杀不了别的进程** ——
"退出所有 Loment 进程"在 `no_std` 下**表达不出来**。这一条不许沉默（§13 的零沉默）。
可表达的形态是：自己 `exit`，**让 OS 收尸**（进程组 / 父进程是重启器）。

前史：**crash-only software**（Candea & Fox）—— 唯一的停机方式是崩溃。

#### 重启器（第 6 级）—— **用 C 写的**

「**用 C 语言写的**，重启 Loment 最小子集，**因为全量 loment 太大不可信**」。

**"用 C 写"这句话是这一级的一半**，三条理由：

1. **C 是另一条实现线** —— 仓里已有 C 表层语法（`lctrans`），所以这不是引入新东西；
2. **它必须不依赖它要重启的那个东西** —— 一个用 Loment 写的重启器，在 Loment 崩了之后
   还能不能跑，是**它自己要回答的问题**（循环）。**用 C 写就把这个循环切断。**
3. 前史：**MINIX 3 的 reincarnation server**（RS）—— 驱动是用户态进程，被 kill 之后由 RS 重起。

⚠ **它的信任地位与"最小子集"合起来才是地板** —— 单独一个 C 重启器**不解决 Thompson 那道题**：
**编它的那个 C 编译器**又怎么信？所以地板的准确陈述是
「**重启器 + 最小子集 + 编它们的那些工具链**」，**不是一个文件**。
这一点必须写清，否则它会变成一块**没被标注的地板**（§1.2）。

#### 最小子集（第 7 级）

「公用，**Loment 在重启后从这里编译出全量 loment**」。

**本仓已经有实物**：`loment/build/selfhost_driver.ll`（46 KB 自举种子，`.gitattributes` 标了
`-diff`，由 `tools/loment_seed.py --emit` 生成）。而「**两份实现逐字节一致**」
（`loment_p8_test` / `loment_potato_emit_test`）**本来就是一次 Diverse Double-Compiling**。

⇒ **这一级要做的新事不是造它，是给它一个名字与一个数** ——
「这份产物是从最小子集编出来的；最小子集是这 N 个字节、它的哈希是 H」，
而这是**不读源码可判的**（`docs/229` §4.2「内部缺席」的同族）。

⚠ **边界**：最小子集**能自己编出全量**这件事，今天**没被证明过** ——
仓里的自举链证明的是"**种子 == 参考实现的产物**"，**不是**"种子能自己长出参考实现"。
这两件事不同，别混。

## 6. 与 LGC 的关系：同一张图的两个方向

`docs/210` §6.2 当年**关闭**了一条路，理由是：

> `Obs*` 回答的是「这个单元能把数据**送到**哪些空间」（**外向**许可）；
> 回收要问「哪些指针还**摸得到**这块内存」（**内向**可达）。
> **同一条图上相反的方向。**

**那句"箭头反了"，正是本文的地基**：

| | **LGC** | **本文（安全）** |
|---|---|---|
| 管什么 | 谁**归还** | 谁**能碰** |
| 图上的方向 | **内向**（哪些指针摸得到这块） | **外向**（这块能送到哪些空间） |
| 依据 | 可达性 | 许可 |
| 产物 | `gc_ladder` | **`safety_ladder`**（§7） |
| 档 | `gc` 一维：`gc_manual` / `gc_auto` / `gc_auto_alpha` | **`lms` 一维：`lms_close` / `lms_open`** —— 两维**正交**（§11） |

**所以"与 LGC 并列的第二套内存架构"不是硬凑** —— 它是**同一条图的另一个方向**，
而 Loment 已经在图上跑了一半。

**两块砖头各自在哪一侧，也就清楚了**：

* `capability` / `guard` / `excluded` 长在**外向**那一侧（许可）⇒ 属于**本文**；
* 根表 / L0–L3 / 标记清扫长在**内向**那一侧（可达）⇒ 属于 **LGC**；
* `free` 的借出标记（`docs/210` §2.8）**两边都摸** —— 它是两条线唯一的交界点，
  所以它是**最该有交叉判据的地方**（§7）。

## 7. 产物：`safety_ladder`，与 `gc_ladder` 的交叉

形制照 `gc_ladder`（Potato v10，`docs/210` §5 第一行）**逐字同构**：

```
safety_ladder = { g0, g1, g2, g3, total_sites }
```

**自洽式**（由**两份独立校验器**各自判得，照 `tools/potato.py` + `loment/tools/lompotato.lomt` 的先例）：

```
g0 + g1 + g2 + g3 == total_sites
```

**然后是新东西 —— 交叉判据**：

> `total_sites(safety)` **≠** `total_sites(gc)`（一个是内存访问站点数，一个是 `alloc` 站点数），
> 但**每一个 `alloc` 站点必然至少是一个安全站点** ⇒

```
total_sites(safety) >= total_sites(gc)
```

这是一条**可判的交叉不等式**。而它买到的**不是自洽**，是**下面这一格**：

### `#362` 就是交叉判据能抓住的那一类

`#362`（`security` + `priority: urgent`，2026-10-14 开，**今天仍开着**）说的是：
L0 静态提升把一个 `alloc` 提到**栈**上（`%NAME.buf`），
于是根表那一格存的是**栈地址**、`markroots` 跳过它、`propagate` 只走堆
⇒ **只经由它可达的堆对象被当垃圾收掉** ⇒ use-after-free。

用本文的语言说：

> **回收层的一个决定（L0 提升），改掉了安全层的一个事实（那块内存还在不在管辖内）——
> 而今天没有任何判据看得见这件事。**

**交叉判据是那个"看得见"**：一个 `alloc` 站点从 g0 挪到 g3（或反过来），
**在两张梯子上必须同时兑现**。今天它们各记各的，于是**一个系统可以静默地破坏另一个系统**。

**这是全文最硬的一条主张**，因为它有一个**已归档的实例**，不需要造：

* 同一份源，`gc_auto` 下正常、`gc_auto_alpha` 下丢对象（因为 **L0 只在 alpha 发**）；
* 也就是说**档位之差可以是一个安全之差** —— 而 `gc` 维今天只有一个取值、没有一条安全断言。

**判据的形状**（§9 第 2 条）：#362 那段最小复现（**`origin/main`** 的
`tools/loment_elf_test.py:1226` 已有 `test_gc_alpha_keeps_an_object_behind_a_young_written_edge`）**必须被交叉判据判出来**。
⚠ **注意 L0 会取消资格**（尺寸走 `const` 名、或加一次 `as u64` 就提不上去）——
写这条判据时要**先确认 `.buf` 行数**，否则测的不是这件事。

## 8. 疯狂的那几格

按"能不能证伪"排序。

### 8.1 **拒，而不是退化**

`docs/210` §4.1 的孪生格。今天「越界」是一个**运行期事故**（§4.4：要么 UB，要么静默踩内存）；
E028 之后，**界得住的那些**变成**编译期的一个诊断**。

**诚实边界**：界不住的还是界不住 —— 但那正是 g1/g2/g3 存在的理由。
**"能拒"与"能兜"是两件事，本文不把前者说成后者。**

### 8.2 **地板是可数的**

§1.2 那句「没被标注的地板才是丑闻」的**落地形态**。
产物里除了 `safety_ladder`，还要有**每一格 g2/g3 的"为什么"**：
这个站点**为什么**证不出来（域没给 `hi`？地址是派生指针？界依赖输入？）。

⇒ **"这份产物有多少处安全我证不了"变成一个数**，而 `docs/225` §4③ 把这一格记成空白。

**对比 Rust**：`#164250` 的地板（"每个 `Drop` 都诚实"）**从来不在任何产物里**。
本文的地板**印在产物里，一处一行**。

### 8.3 **回收的一个决定，在安全的账上当场兑现**

§7 的交叉判据，`#362` 是实例。**这一格没人做过** ——
GC 与安全历来是两个世界（一个在运行期、一个在编译器；一个管堆、一个管指针），
**没有人把两条账摆在同一张桌上对**。

### 8.4 **常态是"没有一条检查"**

若一份程序 `g0 == total_sites`，产物里**一条安全指令都没有**（§5.3 纪律 1）。
于是「**这份程序不需要任何安全检查**」是**一个可判的事实**，不是一种期待 ——
与 `docs/210` §4.5（`l3 == 0` ⇒ 产物里没有收集器）**同一条形状**，
也正是 `docs/229` §4.2 那条「**内部缺席**作为一等可验收主张」在安全轴上的复本。

### 11.2 **LMS 不需要运行期** —— 全程无状态（2026-10-15 裁决）

> ⚠ **本节已被 §5.0 的七级与 §13 的裁定收窄。** 它今天**只对第 1 级（检查器）成立** ——
> 第 2 级管理器（占地极大）与第 3 级入口 B（要每块元数据）**必然有状态**。
> 正确的读法是**按级给**：「**每一级声明自己的状态预算**」，而不是"LMS 无状态"。
> 下面这一节留着，是因为它对**第 1 级**的论证仍然完全成立，且是一份可追溯的记录。

**裁决：LMS 不引入运行期组件，一行都不引入。** 这不是"够用就好"省出来的结论，
是一条**设计约束**。

**先把问题换个问法** —— 该问的不是"要不要 runtime"，是「**要不要状态**」：

* **有状态**的（影子表、边界位图、空闲链表）是**可以被写坏的东西**；
* **无状态**的（一条 `cmp`、一个 `llvm.trap`、一个叶子函数）是**指令**。

LGC 的运行期**有状态** —— 所以它需要 `docs/229` §4.2 那条「内部缺席」来告诉外面有没有。
**LMS 全程无状态，于是它没有可以缺席的东西**，那条标注也就不需要。

**三条理由，都对着仓里已有的东西**：

1. **Rust 那次两处缺陷，一处就在状态里。** `#164243`（thread-local + `process::exit()`
   的 double free）是**运行期状态被改到一半**；`#164250` 是检查器的判决**事后无人可复核**。
   自带影子表的 LMS **两个坑都能踩**；全程内联比较的 LMS 两个都不沾 ——
   因为 `cmp idx, hi` 里的 `hi` **就在产物里**，而 `load shadow[p>>3]` 的界**看不见**。
   **所以不要运行期不是省成本，是让保证变强。**
2. **它把"`lms_open` 撞 `no_runtime`"这个问题消掉，而不是回答它。** 没有运行期就不冲突。
   一个问题消失比一个问题被"先划窄"处理更好 —— 这通常是方向对了的信号。
3. **今天的 `guard` 已经是这个形状**：`_has_guard` 决定发不发，`@__loment_guard`
   是**按需发射的叶子代码**、不带任何状态（`tools/lomentc.py:576`、`:2772`）。
   LMS 顺着它长，跨度是零。

**于是 `CORE_CONFLICTS` 里不为 `lms` 加任何一行。**

#### g3 从「影子 / 陷阱」改成「**编译期拒**」

关键事实：**Loment 的堆是定长静态 arena**（`@__loment_heap` 是 `[65536 x i8]`），
栈帧也是编译器自己排的 ⇒ **地址可以是动态的，界几乎总是常量**。
所以 g1/g2 的覆盖面**比 §5.3 那张表写的宽**（至少到"arena 级保守界"这一层，纯常量比较）。
真正落进 g3 的只剩一类：**指针过了 `BOUNDARY_BUILTINS` 之后** ——
而那**恰好是 Potato v7 已经在数的那张表**（`tools/potato.py:51`，2026-10-15 上是六个名字：
`syscall4` / `syscall6` / `syscall7` / `ptr_add` / `ptr_sub` / `str_ptr`）。

⇒ **g3 的规模是一个可数的数**（≈ 那张表里被调用的站点数），不是一个"运行期本体"。
⚠ 那张表**会随语言长**（`syscall7` 就是后加的）—— 所以写判据时**别把数字写死**，
要对着表算。

| | §5.3 原稿 | **裁决后** |
|---|---|---|
| g3 | 影子 / 陷阱（保障器**本体**） | **编译期拒**（照 `docs/210` §4.1、`docs/216` §D3 的 `gc_strict` 形状） |
| 产物里的 `g3` | 一个组件发不发 | **一个诊断的计数** |
| 代价 | 运行期成本 | **拒掉本来能编的程序** |

**代价明写**：`lms_open` 会拒掉**任何拿 `syscall` 返回地址直接解引用**的程序。
这是 `gc_strict` 已经认过的同一条代价（`docs/216` §D3），**但它是可见的** ——
编译期诊断 + `g3` 这个数 —— **不是运行时的**。

⚠ **若将来确实要留一条运行期兜底，它必须是一个单独的取值**（如 `lms guard`），
**不许藏在 `open` 里**。让 `open` 偷偷带一个运行期进来，正是会把 `no_runtime`
那句话变成空话的形状 —— 而那是本仓最不肯让的一格。

### 11.4 七级怎么装：**档 + 七个细开关 + 四个官方组合**（"办法"）

**三个装置，全部是仓里已有的 —— 零新语法。**

#### ① 细粒度：七个 `set choose` 开关（`docs/182` §2）

**实测（2026-10-15）**：`set choose X { 体 }` + `choose X` ⇒ 体被**摊进模块**；
`choose close X` ⇒ 体**在解析之前就被抹掉**（报的是"调用未定义的函数"，
因为那段 token **根本没进 parser**）。而且**"关掉 = 不依赖"是字面为真的**。

```rust
set choose lms_check   { … }   // 1 检查器
set choose lms_manage  { … }   // 2 管理器
set choose lms_guard   { … }   // 3 保障器
set choose lms_reject  { … }   // 4 拒绝器
set choose lms_crash   { … }   // 5 崩溃器
set choose lms_restart { … }   // 6 重启器
set choose lms_seed    { … }   // 7 最小子集
```

⇒ **七级每一级都真的能单独开关。**

#### ② 官方组合：`chooseset` 文件 + 入口一行 `addin`（`docs/182` §1.4）

仓里有现成例子（`loment/examples/addin/`）。**四个组合各一个文件**：

| 组合 | 开哪几级 | 一句话 |
|---|---|---|
| `addin lms_daily` | 1 + 4 | 平时用 |
| `addin lms_manage_only` | 2 | 只做全内存可见 |
| `addin lms_forensic` | 1 + 2 + 3 + 4 | 法医排查 |
| `addin lms_full` | 1…7 | **全量**（= 什么都不写时的默认） |

#### ③ 总闸：核心维 `lms` 取**档名**，进 Potato 的一个具名字段

于是「**这份产物是哪一档**」是**不读源码可判的** ——
这是 `docs/229` §4.2「内部缺席」在安全轴上的复本。

#### 叠加规则（**这一条是新的，要写下来**）

> **档铺默认值；显式写的开关覆盖它；而"显式写的那个"才算"写了"。**

落点在**预扫期**（`_apply_switches` 第一趟**之前**）：

1. **预扫**扫 token 流，找**核心维 `lms` 的取值**（`choose lms_forensic`）；
2. 用**编译器里的一张表**（档 → 七个开关的初值）**初始化** `SwitchTable`
   —— **不记定义行**：它们不是"写的"，是"默认的"。**这一步是关键** ——
   记了定义行，用户再写一次同一个开关就会被判成"写了两遍"（`SwitchTable` 那条规则）；
3. `_collect_switches` 照常跑：用户**显式**写的 `choose lms_x` / `choose close lms_x`
   **覆盖**第 2 步的初值，而且**只算一次定义**；
4. 一个 `lms_*` 都没写时，档取 `CORE_DEFAULTS["lms"]` = **`lms_full`**。

⚠ **那张"档 → 七开关"的表必须在编译器里，不能只在题解文件里** ——
因为**档要先于开关落定**（开关决定"解析前抹不抹"），而 `set choose` 的**定义在另一个
单元里，那时还没读到**。⇒ 它是**新的一张登记表**，两套实现各一份、逐字节一致
（同 `CORE_DIMS` 的纪律），进 §11.1 那张清单。

⚠ **顺序错了会静默**：第 2 步若放在 `_collect_switches` **之后**，"档铺的初值"就会
**盖掉**用户显式写的开关 —— 而这只在"用户写了与档不同的值"时才看得出来。
这正是 §11.1 第 8/9 处那一类"**漏了不报错**"的形状，所以**要一条判据钉住它**（§9）。

**隐含偏序**（§5.4）：拒绝器**依赖**保障器或管理器在场。⇒
`addin lms_daily`（1+4）里**第 4 级没有它的判据来源** ——
**这是四个组合里唯一一处要在文件里写清"为什么它可以只有 1+4"的地方**，
否则它会看起来像一个 bug。

## 13. 强制启动：对 LLS 的一次**明说的**越界（2026-10-15 用户裁定）

**用户原话**：「**只有管理器可开关，其余全部强制启动，虽然违反了 lls 但为了安全不得不这样做**」。

**这一节把它标出来** —— 照 §1.2 那条教训：**越界本身不是丑闻，没被标注的越界才是**。

### 13.1 违反的到底是哪一条

**不是一条，是三条**，而且分量差得很远：

| # | 违的是哪条 | 分量 | 能不能保住 |
|---|---|---|---|
| 1 | **LLS §4「Loment 由开关定义，不由缺什么定义」** | **标准级** —— 要一次**语言版本**变更 | ❌ 保不住（这就是"强制"的定义） |
| 2 | **`docs/229` §3.2「默认档逐字节不变 —— **不可绕过**」** | 硬约束 | ❌ 保不住（同上） |
| 3 | **`runtime` 那一维买到的「默认档一个 `@__loment_` 都没有」** | 判据级 | ✅ **可能保住** —— §13.2 |

⚠ **第 2 条要在 `docs/229` 里也留一行** —— 它不是本文能自己翻过去的：
那是另一份文档写着"不可绕过"的约束。"绕过一条写着不可绕过的约束"这件事
**必须在被绕过的那一份上留痕**。

### 13.2 第 3 条**可能**保住 —— 这一条值钱

`lomentc_test.py:3100` 的 `test_runtime_is_forced_in_and_absent_by_default` 断言的是：

```python
# 默认档：这段运行期**一点痕迹都没有**
assert "@__loment_" not in ir_off, ir_off
```

**"强制启动安全"不等于"必须有 `@__loment_` 符号"** —— 保障器 / 拒绝器 / 崩溃器的落点
可以全是**内联指令 + LLVM 内建**（`icmp` / `br` / `llvm.trap`），**一个命名符号都不发**。
于是这一条**可以继续成立**。

⇒ **这是一条设计约束，不是巧合**：**梯子的每一级都不许引入新的 `@__loment_` 符号。**
（第 2 级管理器**例外** —— 它占地极大、有状态，本来就不属于"零符号"那一档。）

⚠ **但产物仍然变了** —— 每条内存访问多一条比较。**这条躲不掉**，它就是"强制启动"的字面意思。

### 13.3 会红的东西（**估的数，不是跑的数**）

⚠ **下面这些数字是从判据名字与断言里数出来的，不是跑出来的** ——
真要落地前必须**真跑一遍**（§9 那条"红的判据也能告诉你修得不够"）。

| 面 | 量 | 说明 |
|---|---|---|
| 判据总数 | **833** | `tools/*_test.py` 的全部 `def test_` |
| 名字里明写"默认"的判据 | **8** | 其中 `lomentc_test.py:3100` 会**直接反转** |
| 断言里出现"逐字节" | **36 / 22 / 5** | `loment_p8_test` / `loment_elf_test` / `lomentc_test` |
| `CORE_CONFLICTS` 里 `no_runtime` 那两条 | **2** | 若崩溃器算运行期，这两条的口径要重排 |
| 生成物 | 种子 + 发布清单 + SHA256SUMS | 全部要重算 |

**为什么"双实现逐字节"那一族（36 处）不会红**：两份实现**一起改**，所以它们仍然相同 ——
这正是那条教训：**孪生只证"一致"，不证"对"**。
真正会红的是**钉死了旧值**的那些夹具，而它们**必须逐条去改，不许放宽**。

### 13.4 这一节尤其要守的一条

* **不主张"为了安全"这四个字能免掉上面那张表。** 它是**理由**，不是**豁免**。
  该改的夹具要改，该留的痕要留（§13.1 末那条）。

## 14. 落地顺序（2026-10-15，本文自己定的）

**次序不是我挑的，是用户那条裁定锁死的**：

> **默认 = `lms_full`（七级全开）。**

⇒ **七级全部存在之前，「默认全量」翻不了** —— 否则默认档要么编不过，要么更坏：
**默认档静默地少装几级**。所以次序只有一种：

```
逐级落地（每级 = 实现 + 它自己的开关 + 判据）… → 七级齐 → 才翻 CORE_DEFAULTS["lms"] = "lms_full"
```

### 14.1 每一级的"落地"各是什么

| 级 | 实现落在哪 | 判据 | 规模 |
|---|---|---|---|
| **1 检查器** | 两套实现各自的**检查器**（E028–E030） | 一对程序（改了才红） | 一格 |
| **2 管理器** | 「全内存可见」的**产物** —— ⚠ **今天还没定义**（§5.0 只给了定位） | 待定 | **未定** |
| **3 保障器 A**（用尽） | **接 LGC**：自适应收集器换触发点（§5.3） | 一对程序 | 一格 |
| **3 保障器 B**（越界） | 每块的**边界元数据** | 待定 | **未定** |
| **4 拒绝器** | **跳过一条指令**的控制流（§5.4） | **最难**：要证"跳过之后没更坏" | **未定** |
| **5 崩溃器** | `@__loment_abort` 的扩展（**不发新符号**，§13.2） | 一对程序 | 一格 |
| **6 重启器** | **一个 C 程序**（另一条实现线，不是本仓的一个文件） | 待定 | **不在本仓** |
| **7 最小子集** | **已有实物**（`loment/build/selfhost_driver.ll`）—— 要做的是**给它名字与数** | 待定 | 窄 |

⚠ **"未定"那四行是**：它们连**做法**都还没定（第 2 级尤其 —— "详细输出所有内存"
在今天不是一句可实现的话）。**先做能做的，别为它们编造设计。**

### 14.2 中间态（**写明：这是临时的，且不进发行版**）

七级未齐之前，`lms` 那一维现有的两个取值 `lms_close` / `lms_open` 是**临时的中间态**：

* `lms_open` = 「把**已经存在的**那几级全装上」；
* 它们**不是** §11.3 那四个档 —— 四个档要等七级齐（档名指着还不存在的级，
  就是个空承诺）。

**翻档的那一刻**（= 七级齐的那一刻）三件事一起做：

1. `CORE_DIMS["lms"]` 换成四个档名，`CORE_DEFAULTS["lms"] = "lms_full"`；
2. 「档 → 七开关」那张表进两套实现（§11.4 的叠加规则）；
3. **`lms_close` / `lms_open` 删掉** —— 它们是被这四个档取代的中间态，**不留兼容**。

### 14.3 为什么不留兼容

本仓的既有教训（`docs/216` §D6、`docs/229` §3.2）：**默认档那一条是承重墙**，
而"为了平滑过渡留一个旧值"**正是把承重墙拆成两半的形状**。
所以中间态**只在开发通道存在、不进发行版** —— 照 `docs/231` §1.3 的渠道闸先例
（写得出、却拿不到，比写不出来更坏，所以关在发行版外面）。
