## 0. 三句话

1. **数学上**：一般程序的“极限状态”通常不存在，`T^n` 的符号闭包不可判定；
   “程序不需要计算所有终点”不等于“停机问题解决”。这些是死路，先把它们写死。
2. **工程上**：对**封闭、有界、循环形**的程序，状态空间有限 ⇒ 轨迹最终一定进入周期
   （鸽笼原理）。所以可以做的是：**运行时检测一个小周期、把代表状态存成快照、下次启动
   在指纹匹配时直接恢复、不匹配就整份回退**。这是“启动即稳态”能落地的那一半。
3. **新颖面上**：快照、循环加速、超优化、部分求值**都有前史**，没有一块砖是新的。
   可能站得住的只有一处：**把稳态做成语言产物里一份可审计的证书** ——
   用 Loment 已有的虚拟钟（`tick`）、`gc_ladder`、精确根表、热更新安全点把它做出来。
   这是“可判”这条线（`docs/229` §4.2）的延长，不是“性能怪兽”的叙事。

## 1. 把提案的数学逐条改判

### 1.1 状态转移不是全函数，极限点通常不存在

提案写的是

```
S_{t+1} = T(S_t, I_t)
S^* = lim_{t→∞} S_t
```

两处要改：

- `T` 不是 `Σ → Σ`，是 `Σ × I → Σ`。`I_t` 是外部输入（`read`、时钟、随机源、调度）。
  只要 `I_t` 不被约束，`S^*` 就不存在，连“收敛”这个词都没有定义。
- 即使没有外部输入，程序通常也**不收敛到一个点**。确定性有界系统满足的是
  **最终周期性**：

```
∃ k, P ≥ 1 : S_{t+P} = S_t     (∀ t ≥ k)
```

  也就是一个 **ω-极限环**，不是一个不动点。不动点 `S^* = T(S^*)` 只是 `P = 1` 的特例。
  把“极限点”当默认，是把一类特例当成了通例。

**改判后的正确对象**：一个**商状态**上的周期，而不是单个具体状态上的定点。

### 1.2 折叠定理 = 循环加速，一般不可判定

提案的“折叠定理”：

```
M(T^n(S_0)) = T'(S^*),  ∀ n ≥ k
```

要求符号化地算出 `T^n`。这在文献里叫**循环加速（loop acceleration）**：
把 `while` 循环的传递闭包算成一个闭式。结论是：

- 对**仿射循环**（变量是整数、赋值是线性式、守卫是 Presburger 公式），可判定；
- 对带数组、指针、堆、外部调用的一般循环，**不可判定**；
- Loment 的 `while` 可以改数组、可以 `alloc`、可以调 `syscall`，所以一般情形没有闭式。

**最现成的窄类**是 `domain:for`（`docs/315`）。
它的循环变量是有限形状的下标，域状态是 `(tick, 实例号, 计数)`（`docs/308` §2.6），
律是算术的。所以**域控制面**的传递闭包可以算；**循环体的内存效果**仍然要执行。
换句话说：能折叠的是“守卫与虚拟钟”，不是“循环体”。其他计数循环要经过分析才可能
落进这一类；本文不预判。

### 1.3 “停机问题解决”是假的；你做的是见证 + 守卫

提案最后一句：

> 停机问题解决：程序不需要计算所有终点，开发者可以给予程序一个假设终点，并在运行时不断更新终点。

这句话把两件事混了：

| 说法 | 实际是什么 | 能不能成立 |
|---|---|---|
| “解决停机问题” | 判定任意程序是否终止 | **不能**。图灵 1936；不存在这样的判定器 |
| “给一个假设终点，运行时更新” | **候选不变式 + 运行时验证**（speculative invariant + guard） | **能**，而且工程上很常见（JIT 的推测优化 + 去优化就是同一形状） |

后者不判定任何东西。它只做三件事：**开发者猜一个商投影与周期 → 运行时看它是否重复 →
重复就用、不重复就回退**。程序的结果永远正确（回退到冷路径），只是优化可能白做。
这不是“解决停机”，是“**把证明换成见证**”。

### 1.4 三条“死穴”的逐条改判

| 提案的说法 | 事实 | 改判 |
|---|---|---|
| **动态内存**：Loment 是纯静态内存、无动态 GC 爆发，所以状态空间有限 | **不准确**。Loment 有 `alloc`；默认 `gc_manual` 是一个 **64 KiB 的 `.bss` bump 堆**，`gc_auto` / `gc_auto_alpha` 是标记-清扫 + 精确根 + 块内保守扫（`docs/210`、`docs/225` §0） | 状态空间**确实有限**，但理由是**堆有界（64 KiB）+ 栈帧静态**，不是“没有 GC”。有限不等于小：`2^(64 KiB × 8 位)` 是一个天文数字 |
| **外部中断**：LSPE 的能力域能保证外部输入不破坏状态机 | **不准确**。域是**权威谓词**（“这个下标在不在域里、这个实例还新不新”），不是**值谓词**。域里的 `read()` 照样返回任意字节 | 只能把状态分成“外部影响”和“内部决定”两半；**末点必须落在没有 IO 的那一半**，或者显式声明输入稳定假设，由监视器检查（不能证明） |
| **编译器黑盒**：Loment 后端是手写的，直接操纵 LLVM IR，用 phi 做不动点合并 | **半对**。IR 是文本 LLVM 子集；原生产物走 `lomelf`（栈机、今天没有优化器，`docs/212`）；C 档把 IR 交给 clang `-O3`（`docs/298`）。`phi` 是 SSA 的合流点，不是不动点算子 | 真正的杠杆不是“phi 合并”，是**帧布局可知 + 根表精确 + 堆是一个 64 KiB 全局**。这三样让**快照/恢复**可做，不让**符号闭包**可做 |

## 2. 能落地的那一半：四层 + 一个守卫

把“末点运行”拆成四个可分别证伪的东西。默认全部关闭；只有写了 `settle` 的单元才带上。
**本节用 `S0`–`S3` 编号**，以免与 `gc_ladder` 的 `L0`–`L3`（`docs/210`）撞号。

**适用面（先写死）**：末点只对“进入稳态后还要跑很久”的循环有意义。
有界计数循环（`while i < n`）的 `i` 是**进度**，不是周期状态：它要么被排除出投影
（但如果它可观察，排除就不忠实），要么这个循环根本没有稳态。所以第一版语料应是
**事件循环 / 服务循环 / DSP 帧循环**，不是 `for i in 0..n`。

### 2.1 S0 · Settle：声明末点 + 监视器 + 证书

**末点（settle point）**：程序里一个由开发者声明的点，声明“从这里开始，状态投影进入周期”。
它是**稳态点**，不是退出点；也不是反向执行（反向执行是 `docs/207` 的另一条线）。

拟议形状（与 `tick;` / `lgc end;` 同一条“显式状态语句”的风格）：

```rust
fn pump(n: u64) -> u64 {
    let req: u64 = 0;
    while req < n {              // 真实稳态循环通常是 while true / accept
        settle(assume = 1);      // 拟：假定这段循环每轮回到同一投影
        guard lane(req % 16);    // 域状态：tick / 实例 / 计数
        handle(req);             // 稳态工作
        req = req + 1;           // 进度计数：可观察，所以必须进投影
    }
    req
}
```

> 这个例子是**有界**的，只为让代码能跑完；它说明的是“投影里必须包含 `req` 这一类
> 可观察进度”，而不是“计数循环有稳态”。真正的收益在 `while true` 的服务循环上。

- `settle;` = 让编译器为**最内层循环**埋一个监视器，周期用默认值 1。
- `settle(assume = P);` = 开发者给一个**候选周期**。它是提示，不是承诺。
- 监视器只看**投影后的状态**，不看整个堆（见 §3）。
- 监视器**不分配**：它复用 GC 的根遍历与块扫描，把哈希写进固定大小的 scratch
  （`.bss` 里的一段，大小在编译期定）。`settle` 会**强制发精确根表** —— 即使
  `gc_manual` 今天不要求它（见 §4.5）。

**证书**：

```
C = (π_id, P, h, env_fp, regime, witness)
```

| 字段 | 是什么 |
|---|---|
| `π_id` | 投影的编号（编译器生成的规范编码，进 Potato） |
| `P` | 观察到的周期 |
| `h` | 一个周期上的投影哈希 |
| `env_fp` | 环境指纹（编译器 / Potato / 目标 ABI / 域集 / 端口集 / 时间源 / 线程数） |
| `regime` | 监视强度：`once` / `periodic` / `continuous` |
| `witness` | 见证序列（若干个连续哈希；`once` 时是 `P + 1` 个） |

证书是**证据**，不是证明。它回答的是“我观察到它重复了”，不是“它永远会重复”。
这条分界与 LSPE 的“证据等级”同一条纪律（`docs/262`）。

### 2.2 S1 · Snapshot：快照 + 指纹 + 全有或全无

在末点把**代表状态**序列化成一份 `.lomsnap`：

```
头：magic / 版本 / env_fp / π_id / P / 校验和
体：全局标量 + 堆镜像（按偏移，不存绝对地址）+ 域状态（tick / 实例号 / 计数）
尾：证书 witness
```

三条硬规则：

1. **存偏移，不存绝对地址。** 恢复时按新的堆基址重定位；这样 ASLR 与不同装载地址都不影响。
2. **指纹不匹配就整份拒绝。** 不尝试“部分恢复”，也不做“尽量恢复”。拒绝路径 = 冷启动，
   与没写 `settle` 的程序逐字节同一条路。
3. **外部面不进快照。** 文件描述符、socket、进程句柄、真实时钟、随机源都不序列化；
   它们只进指纹。v1 只支持 `sealed` / 无外部端口的程序；`hosted` 要恢复，必须显式提供
   一个 `reacquire` 钩子，否则编译期拒。

**恢复算法**：

```
读头 → 校验和 → env_fp 匹配? ──否──> 冷启动
                              │是
                              ▼
              重定位堆镜像 → 恢复全局/域状态 → 跳到末点 → 继续
```

### 2.3 S2 · Specialize：稳态特化

拿到“稳态的形状”之后，编译器可以做三类**普通**优化：

| 优化 | 依据 | 边界 |
|---|---|---|
| **守卫/虚拟钟折叠** | `domain:for` 的域状态是算术的（`docs/308` §2.6） | 只折叠控制面；体照跑 |
| **不变量外提 + 冷路径剥离** | 证书的周期 + 投影：稳态下热分支可证固定 | 与 f1/f2 同一条流水线（`docs/298`） |
| **稳态体超优化** | 稳态体是一段固定区域，可以交给带**翻译验证**的超优化器 | v1 不做；v2 只对直线段做，且每条改写要过验证器 |

**超优化不是“因果律武器”。** Massalin 1987、Bansal & Aiken 2006、STOKE 2013 都是
“搜索更短的指令序列”，它们**不证明收敛**，只改进循环体。而且超优化器天然可能出错，
所以必须配翻译验证（Pnueli 1998）或一个可信的等价检查器；没有验证器的超优化不能进产物。

### 2.4 S3 · Tail re-entry：尾点回环

把循环尾直接接到一个**跳过序言**的入口：

- 冷路径：`prologue → loop head → body → back edge`
- 稳态路径：`restore → loop head'（无初始化）→ body → back edge`

这是代码布局 + 状态恢复，不是新语义。对“整个程序就是一个循环”的形态（服务器、
事件循环、DSP、控制回路）收益最大；对一次性程序收益为零。

### 2.5 “假设终点”的正确形式：商投影，不是单个状态

开发者能给的**不是**一个字面状态（他不可能写出 64 KiB 堆的每个字节），而是一个
**等价关系**：

```
π : Σ → Ω          投影（可计算、有规范编码）
π(s) = π(s')  ⇒  s 与 s' 在声明的输入类下可观察行为相同
```

- `π` **太细**（例如包含整个堆的每个字节）⇒ 几乎不重复，证书发不出来。
- `π` **太粗**（例如只包含一个计数器）⇒ 可能把可观察状态抹掉，恢复后行为错。

所以核心工程问题是：**找一个既够粗、又对可观察行为忠实的商**。这不是新问题，
它是抽象解释（Cousot & Cousot 1977）与互模拟（bisimulation）的同一个问题。
Loment 的特殊之处是：它**已经有一块天然的商** —— 域状态 `(tick, 实例号, 计数)`
（`docs/308` §2.6）+ `gc_ladder` 给出的分配层 + 精确根表。把这三样拼起来，
就得到一个**编译器能算、产物能写、运行期能核**的候选投影。

## 3. 状态投影：哪些状态可以进快照

| 面 | 内容 | 进快照？ | 依据 |
|---|---|---|---|
| **域面** | `tick`、每个域的实例号、每个消耗域的计数 | **进** | `docs/308` §2.6：每轮结束的**域状态**是这三样的函数；有限、算术、已有虚拟钟 |
| **堆面** | 末点**仍可达**的堆对象（L0 在栈、L2 在纪元；L1 已 `free` 的不在，仍活的要进） | **进** | 64 KiB `.bss` arena；精确根表 + 块内保守扫（`docs/210` §2.4） |
| **全局标量** | 模块级 `u64` / `i32` 等 | **进** | 静态布局，偏移稳定 |
| **外部面** | fd / socket / 进程句柄 / 端口 | **不进**，只进指纹 | 不能跨进程复制；v1 要求 `sealed`，`hosted` 要 `reacquire` |
| **真实时间** | `clock_gettime(CLOCK_MONOTONIC)` | **不进** | `docs/309` §2.5：PE/内核上还可能回 0；恢复后从当前时钟继续 |
| **随机源** | 任何 `rng` / `getrandom` | **不进** | 非确定；恢复后的随机流不可能与冷启动相同 |
| **线程** | 线程数 / 锁状态 | **不进** | `docs/284` §8 已写死单线程前提 |

**完备性义务**：末点处每一个可达状态都必须被分类为三者之一：

```
in_snapshot      —— 进快照
recompute        —— 能从快照 + 不变式重算（例如循环变量可由 tick 推出）
external         —— 外部面，恢复时必须重取或拒绝
```

只要有一个可达状态**落不进**这三类，编译器**拒绝** `settle`。这是“宁拒勿猜”
（`docs/188`）的同一条纪律。它比“尽量恢复”强，也比“尽量恢复”可解释。

## 4. 拟议的语言与产物形状

### 4.1 语句

| 写法 | 含义 |
|---|---|
| `settle;` | 标记末点；周期默认 1；由 `choose settle` 决定监视强度 |
| `settle(assume = P);` | 带候选周期；`P` 必须是编译期整数 |
| `settle(regime = once);` | 只监视第一个周期；最便宜 |
| `settle(regime = periodic);` | 每 N 轮抽查一次（N 由编译器定，进 Potato） |
| `settle(regime = continuous);` | 每轮都核；最强，最贵 |

`settle` 是上下文关键字；不写就是没有这个特性，产物一个字节不变。

### 4.2 维度

新增第九维 `choose settle`：

```
choose settle_off          // 默认：不产生任何 settle 代码
choose settle_monitor      // 埋监视器，发证书，不写快照
choose settle_snapshot     // 监视 + 写 .lomsnap
```

与既有维度同一条纪律：**每维全程序恰好一个取值，只有根单元能写**（`CORE_DIMS` /
`CORE_DIM_OF`）；默认值 `settle_off` **不改变任何现有程序的字节**。

### 4.3 Potato

Potato 当前是 **v22**（`docs/147-potato-v1-spec.md`）。`settle` 是 **v23** 的新字段：

```
settle = {
  mode: off | monitor | snapshot,
  points: [ { id, period, regime, projection_hash, witness_len } ],
  snapshot: { present: bool, bytes: u64, env_fp_hash: u64 }
}
```

台阶累积：v23 要求 v22 的所有字段都在。没写 `settle` 的单元**不要求**这个字段
（与 `gc_control` / `lgc` 同一先例：用了才有，不用就没有）。

### 4.4 产物

`.lomsnap` 是一个独立文件，不是可执行文件的一部分：

- 可以随产物一起发，也可以不发；
- 恢复是**运行时可选**的：没有 `.lomsnap` 就冷启动；
- 校验和与指纹让它可以被第三方**不读源码**地核对（这正是 `docs/229` §4.2 的“可审计”）。

### 4.5 与既有机制的关系

| 既有机制 | 关系 |
|---|---|
| `tick` / `guard` / 域时律 | 提供**天然的有限商**：tick、实例号、计数 |
| `gc_ladder` | 告诉快照“每个 `alloc` 站点在哪一层”：L0 在栈、L2 在纪元、L1 已 `free` 的不在；**仍可达的**都要进堆镜像 |
| 精确根表 | 监视器与快照遍历的入口；`settle` 强制发根表（即使 `gc_manual`） |
| `lgc` | 快照期间必须**停收**（`lgc end`）；否则堆镜像会在写入中途被收集器改掉 |
| 热更新安全点（`docs/284`） | 同一个“在安全点改活帧”的机器；`settle` 复用它来恢复帧链，不另起一套 |
| LSPE 台账（`docs/262`） | 证书是一条**证据**，不是判决；进 ledger 的 evidence 面，级别是“已测”不是“已证” |

## 6. 前史先行（这一节不许跳）

`docs/207` 的教训：**先点名，再说话**。下面每一条都有人先到过；**“没检索到 ≠ 没有”**。

| 本文用到的 | 谁写过 | 写到哪儿 |
|---|---|---|
| **循环加速 / 传递闭包** | Finkel & Leroux 2002；Bozga, Iosif, Konečný 2016；Presburger 加速一系 | 仿射循环可判定；一般循环不可判定 |
| **部分求值 / Futamura** | Futamura 1971；Jones, Gomard, Sestoft | 绑定时间分割；残程序 |
| **超优化** | Massalin 1987；Bansal & Aiken 2006；STOKE（Schkufza et al. 2013）；Souper 2018；Denali 2002 | 搜索更短指令序列；不证收敛 |
| **抽象解释 / 不动点** | Cousot & Cousot 1977；Kildall 1973 | 抽象域上的最小不动点 |
| **自稳定** | Dijkstra 1974 | 从任意状态回到合法状态 |
| **快照 / 热启动** | V8 startup snapshot；GraalVM Native Image；CRIU；Firecracker snapshot/restore；DMTCP；JVM CDS/AppCDS | 把初始化后的堆/进程存下来再恢复 |
| **安全点 / 活帧重映射** | JVM safepoint；Erlang hot code loading；Loment `docs/284` | 在安全点换代码/换帧 |
| **推测优化 + 去优化** | V8 TurboFan；Truffle 的守卫失败 | 猜一个不变式，失败就回退 |
| **证据随产物走 / 翻译验证** | PCC（Necula & Lee 1996）；TAL（Morrisett 1998）；翻译验证（Pnueli 1998） | 证明/证据与产物一起走，宿主验 |
| **剖面引导 / 热体特化** | PGO；BOLT；trace JIT（Dynamo、PyPy） | 用运行期形状重编热路径 |

**自报**：**没有一块砖是新的。** 快照是 V8/Native Image/CRIU；循环加速是 Finkel–Leroux；
超优化是 STOKE；商投影是抽象解释；安全点是 JVM/热更新；守卫回退是 JIT。
**可能新的只有包装方式**：把“稳态”做成语言产物里的**一等、可审计、可回退**的证书，
并且用 Loment 自己的域时律 + `gc_ladder` + 精确根 + 热更新安全点把它落地。
**没检索到对应物；没检索到 ≠ 没有。**

## 7. 不可能性（先写死）

1. **一般程序的收敛/极限不可判定。** 不存在一个编译器能对任意程序算出 `S^*`。
2. **一般循环的符号闭包不可判定。** 带数组/堆/外部调用的 `while` 没有闭式。
3. **“停机问题解决”是假的。** 你只能观察 + 回退，不能判定。
4. **快照不能捕获外部状态。** fd、socket、真实时间、随机源、其他线程都不行；
   只能进指纹，恢复时重取或拒绝。
5. **快照不能跨编译器版本/ABI 通用。** 指纹不匹配就必须拒绝；不许“尽量兼容”。
6. **监视器不是零成本。** 它要么哈希整个活集，要么采样；采样就会漏掉两次采样之间的发散。
   所以 `regime` 必须写进产物，让“保证强度”可审计。
7. **超优化不保收敛，也不保正确。** 没有翻译验证的超优化不能进产物。
8. **一次性程序没有收益。** 快照的收益只在“启动后要跑很久”的程序上；对 hello world
   是纯开销。

## 8. 可拿掉的假设（每条：拿掉得到什么 / 代价）

| # | 假设 | 拿掉得到什么 | 代价 |
|---|---|---|---|
| 1 | “整个程序收敛” | 只要求**声明的末点**在一个投影上周期 | 开发者要选末点；选错就没有证书 |
| 2 | “编译期算出闭包” | 运行时监视 + 证书 | 只有观察到的周期，没有证明 |
| 3 | “零成本” | 有界开销 + 全有或全无回退 | 紧循环上可能不划算 |
| 4 | “整个堆都要快照” | 只快照**末点仍可达**的堆对象；L0 由栈、L2 由纪元、L1 已 `free` 的不管 | 需要 `gc_ladder` 的层信息与精确根表 |
| 5 | “外部输入也收敛” | 末点必须在 IO 域外，或显式声明输入稳定假设 | `hosted` 程序要写 `reacquire` |
| 6 | “跨版本快照” | 指纹匹配才恢复 | 编译器一改，旧快照全废 |
| 7 | “默认打开” | `choose settle_off` 默认，产物字节不变 | 要显式 opt-in |
| 8 | “监视器连续跑” | `once` / `periodic` 采样 | 保证强度下降，且必须写进产物 |

## 9. 最小可行版本（如果只做一格）

**只做“域面证书”，不做堆快照。** 理由：

- 域状态 `(tick, 实例号, 计数)` 已经是有限的、算术的、编译器已知的（`docs/308` §2.6）；
- 它不需要 64 KiB 堆镜像，也不需要跨进程恢复；
- 它可以独立成一条判据：一个 `domain:for` 循环在第一个周期后，守卫/时钟指令数下降，
  且输出与未折叠版逐字节相同。

这一格的产物是**一个折叠后的循环体 + 一张周期表 + 一条证书**，不是“启动即稳态”。
但它能在**不碰快照、不碰指纹、不碰外部面**的前提下，把“末点运行”的数学核心
（商投影 + 周期 + 见证）先跑通。堆快照是第二个实现格；跨进程恢复是第三个实现格。

## 11. 我不主张

1. **不主张“末点运行”是新的。** §6 自报：没有一块砖是新的。
2. **不主张它能解决停机问题。** §1.3 写死了：它只做见证 + 守卫。
3. **不主张一般程序有极限点。** §1.1：正确的对象是最终周期，不是不动点。
4. **不主张快照能跨版本/跨外部环境。** §7 第 4/5 条：指纹不匹配就拒绝。
5. **不主张监视器零成本。** §7 第 6 条：采样就有漏，强度必须进产物。
6. **不主张这条线该排在前面。** 它是一份研究/设计账；排序是用户的事。
7. **不主张最小可行版本能带来数量级加速。** §9 只主张“域面指令数下降 + 输出相同”，
   不主张墙钟比值（本仓门禁也不用墙钟比值，见 `#442` / PR #445 的教训）。
