# 227 · `runtime` 维兑现：从"只声明"到"**一句保证**"

> 状态: **已落地**（2026-10-09 用户裁决，2026-10-10 落成）· 上游: `docs/175` §3.4/§3.6（维度本体）、`docs/147`（Potato v9 字段）、`docs/210` §4.5（"常态是没有一个叫 GC 的组件"）
> 一句话: **`no_runtime`（默认）说"产物里没有运行期"——那就把它做成一句保证**：凡是会把那段
> 运行期拖进产物的构造，编译期点名拒。`runtime` 是它的另一半：**强制带**。

## 0. 变了什么

**2026-10-16 一处订正（issue #321）**：这条拒的**码**从 `E022` 换成了**自己的 `E031`**。
原先它并进 E022「`choose` / `addin` 写法不对」，理由是"码按修法分"（改法都是去写一行
`choose runtime`）。那条理由**数错了读者**：报的是用户写的**那个构造**（`/`、`alloc`…），
而他那一行 `choose` 是对的 —— 实测原样的输出是 `error[E022]: bad `choose` / `addin`` 配
`message: /`，用户去翻 `choose` 怎么翻都是对的。**码是用户最先读到的那个词，指错子系统
就是误导**。正文（"那句话"而不是那一格 token）2026-10-15 已经改过，这一笔补的是码与它
后面那张说明卡。本文下面提到 E022 的地方都已跟着改成 E031；**规则一个字没动**。
（码号是 31 而不是 30：`#323` 同日把 E030 用掉了 —— 类型位置上的未知名。两张卡、
两件事，撞号会让人按错的那张去改。）

`docs/175` §3.6 末尾那句"诚实账"是这一篇的起点：

> **还欠着的（诚实账）**：这一维现在**只声明、不提供**。`choose runtime` 编得过、进 Potato、
> 冲突规则在，**但运行期本身还没有**。

那句写于 2026-09-23。**"运行期本身还没有"这半早就过期了** —— 四层 GC 梯（`docs/210`）、
分配器、freestanding 文本块都在产物里。**还欠的不是内容，是开关**：`runtime` 这一维对产物
**零影响**（`lomentc.py` 里除 Potato 导出之外一处都不读它）。

这一篇把它接上，接法是**用户 2026-10-09 的裁决**：按字面做（`no_runtime` 恒为强保证），
规格该改就改 ——「我们要是不做，Loment 初衷之一**激进**就不成立」。

| | 改之前 | 改之后 |
|---|---|---|
| `no_runtime`（默认） | 产物里可能**有**运行期（用到就带） | **保证没有**；会带就编译期拒 |
| `runtime` | 什么也不做 | 产物里**一定有**那段运行期（用不到也带） |
| 库/依赖 | **一律不许**写 `choose` | 可以写，视作**需求**；根必须满足它 |
| 老程序 | 一行不改照编 | 用到除法/分配/字符串拼接的，**根单元要补一行** `choose runtime` |

## 1. 运行期是哪一段

**运行期 = `_IR_RUNTIME` + `_IR_HEAP`**（`tools/lomentc.py`）：

* `_IR_RUNTIME` —— `memcmp` / `memset` / `memcpy` / `abort` / `llvm.trap`；
* `_IR_HEAP` —— 分配器（bump + 空闲链表）与它的三个全局。

**刻意不含**两样东西，各有理由：

* `@__loment_caps`（能力域描述表）—— **它是核**（M35–M43，内核线的跨线契约），不是运行期。
  判据不落在"有没有 `@__loment_` 前缀"上，就落在这两段的**发射闸门**上。
* `_IR_GC`（根表 + 收集器）—— 归 **`gc` 维**。这一维与 `gc` 维**正交**：`runtime` + `gc_manual`
  （"要运行期、但内存我自己管"，`docs/175` §3.6 明说合法）能表达"带分配器、不带收集器"。

## 2. 规则

### 2.1 触发是一张 **token 表**，不是一个 AST 遍历

`tools/lomentc.py` 的 `_RUNTIME_SITES`：

| token | 点名 |
|---|---|
| punct `/` | 除法 |
| punct `%` | 取模 |
| ident `alloc` / `free` | 分配 / 归还 |
| ident `str_concat` / `str_eq` | 拼串 / 串比较 |
| ident `panic` / `guard` | panic / 能力域守卫 |

**为什么长在 token 流上**：与 `_l0_promotable` 同一个理由（`docs/210` §2.2）—— 自举侧手上
**只有** token 流，规则写在 token 上，两个实现才可能逐字节一致。事实由**解析器**在
`parse()` 末尾算出来存在 `Module.rt_sites` 上（与 `Func.deref` 同一个位置）。

**它是保守的**：一个叫 `alloc` 的用户函数也会被算进来。多报的代价是一次点名拒，漏报的代价
是"保证了产物里没有运行期而它其实有" —— 两边不对称，所以往保守那边偏（§7 判据 B 把这笔
保守账钉成可证伪的）。

### 2.2 默认档也拒

这一维**不写就是 `no_runtime`**，所以"老程序一行不改照编"这条从今天起**不再成立**。
凡用到上表任一构造的程序，**根单元**要写一行 `choose runtime`。

**这是明写的代价，不是漏掉的一格**（§3）。判据在 `loment_rule_parity` 里：
`choose-no-runtime-div`（走算术）与 `choose-no-runtime-alloc`（走分配）——
两条负例各钉一边，因为参考实现的两个触发是**分开判**的（`@__loment_` 与 `@__loment_alloc`）。

### 2.3 `runtime` 是"强制带"，**但不是"强制带分配器"**

`choose runtime` 一定让 `_IR_RUNTIME` 进产物（`lomentc.py` 的 `if rt_on or "@__loment_" in text_all:`），
**`_IR_HEAP` 仍按需**。

**理由是一处会伤到人的副作用**：`_IR_HEAP` 含 `[65536 x i8]` 的零初全局。一个只会除法的
裸机引导程序（`loment/examples/bootprobe.lomt`）若被强制装上分配器，镜像里会凭空多 64 KiB
的 .bss —— 那不是"兑现承诺"，那是**给承诺加税**。而"用得到分配器"这一半由 §2.2 管着：
`no_runtime` 下写 `alloc` 是拒的，所以**产物里有分配器 ⇒ 根写过 `choose runtime`**，
保证不破。

## 3. 代价（明写）

1. **默认档不再向后兼容**：调用方要补一行。仓里动了 **233 份 `.lomt`**（`loment/` 91 + `lompi/` 142；绝大多数是补那一行），
   另加 `.claude/skills/loment/SKILL.md` 的三段示例。
2. **产物逐字节不变**：这条是量过的，不是推的 —— 那 233 份里凡"本来就用得到运行期"的，
   补 `choose runtime` 之后 IR **一位都没动**（脚本逐份比过，88/88 + 全仓 0 差异）。
   变的只有**两个方向**：本来不用而声明了的（多了那段）、本来用着而没声明的（现在报错）。
3. **姊妹仓（内核线）也要补**：它们手上的纯 Loment 产物凡用到上表构造的，根单元都要补
   一行。按 `CLAUDE.md` §3 的口径，这是**语言面的**变更（不动 `lom/`），但要**知会 compat 线**。
4. **文档里的代码块是一类调用方**：`SKILL.md` 的 rust 样例由判据**真的编译**
   （`loment_dist_test`），所以那几段也补了 —— 文档不能静默腐烂这条纪律，这次从"挡回归"
   变成了"挡规格漂移"。

## 4. 为这一维动的一条既有规则：**库可以声明需求**

改之前（`lomentc.py` 的 `check()`）：依赖里有 `choose` 就报「库不许 `choose`」。

**这条按字面做不下去**，而且卡得很死：`loment/lib/proc.lomt` 要除法，于是

* 当**根单元**编译（语料判据把每一份 `.lomt` 都当根编，`loment_p8_test:1330`）→ 默认档要拒它；
* 当**依赖**被 `loment/tools/lomc.lomt` 等 `use` → 库不许写 `choose`。

**两面堵死。** 新规矩把方向反过来，而且它本来就是那句老报错自己写的（"库该声明**能力需求**，
由项目决定"）：

| # | 规则 | 报什么 |
|---|---|---|
| 1 | 依赖可以声明核心模式，视作**需求** | 根的取值与它不一致 ⇒ 报，两边都点名 |
| 2 | 依赖用了拖运行期的构造却**什么都没写** | 报（"库该声明它的需求"） |

第 2 条是**保证不破的必要条件**：没有它，一个用了除法却不表态的库会在根写着 `no_runtime`
的时候**静默**把运行期带进产物。

自举侧同一件事的落点在装载器（`loment/selfhost/driver.lomt` 的 `load_file`）：依赖写下的
核心 `choose` **抹成等长空白**（`blank_tok`，行号不动）再拼进合并单元 —— 不抹的话检查器会
当成"这一维写了两次"。

## 5. 两个实现**达成保证的路子不同**，而它们在一格上确实不同（诚实账）

参考实现读**根单元的 token**，所以它必须额外立两条**依赖义务**（§4）才看得见依赖带来的
运行期；自举侧走的是另一条路 —— 装载器把**所有单元拼成一整块 token** 之后才交给检查器，
于是依赖里那个 `/` **本来就在眼前**。两条路都成立，而且自举侧那条**更宽**：它连深度 > 1
的依赖也看得见，参考实现那两条只覆盖 `resolve_deps` 交上来的那批。

**真正不同的只有一格**：依赖声明了一个它**用不上**的核心模式（比如一个不除法的库写着
`choose runtime`），而根不满足它。参考实现报（规则 1），自举侧不报。

**这一格为什么没在自举侧补上**：装载器**判不了**。`load_file` 早先试过在 `depth == 1` 时
回头读根那一层的 token —— 行不通，因为 `toks` 是**共享暂存**，每个单元进来就
`lex(slot, nb, toks)` 把它重写一遍（`load_file` 头顶那句"递归会复用 toks"就是这个意思）。
等依赖那一层跑到时，根的 token 早没了，扫到的其实是**依赖自己的**声明。要判得给根留一份
token、或把它的文本长度一路传下来 —— 另一轮的事。

**这一格为什么不算失败**：它不影响**产物**。根写着 `no_runtime` 而依赖的代码拖了运行期的
情形，**两边都拒**（参考实现靠规则 2，自举侧靠合并流上的那条 E031）；§7 判据 B 在全仓
310 份上核过"被拒 ⟺ 产物真带运行期"，**0 例外**。

> **改这条负例时的教训**（`loment/selfhost/neg_dep_choose`）：它原来测的是"库不许 `choose`"
> —— 那条规则没了之后它就**不再违法**，于是 `loment_p8_test` 里那句断言变成"没被拒"。
> 负例要改成**两边都判得住**的形状（依赖用了除法却不声明），而不是把断言删掉：删掉等于
> 把"跨单元的那条判据"一起删掉。**负例的形状要为规则服务，不是反过来。**

## 6. 连带：`lomelf` 的标签表（**两笔撞了同一个常量**）

种子长大了（driver/codegen/checker 各多了一段），`loment_genesis_test::test_seed_fits_lomelf_table_caps`
报出准数：**种子要 16421 条，超 `TB_LBL_MAX = 16384` 37 条**。

当时按 `docs/200` 的修法抬到 **20480**（16421 + 25%，先量后抬）。**但这项处置最终没有留下** ——
合并 `origin/main` 时撞上 `docs/212` 那笔：它**同一天**独立撞了同一张表（余量当时只剩 9），
抬的是 **32768**。两笔在同一个常量上正面相遇，正确解不是"挑一个"，是**取大的那个再重算全部
生成物**：`TB_LBL_MAX = 32768`，整条表区后挪 393216。测量与教训记在 `docs/200` §7/§8。

`genesis`（预编译二进制）必须跟着 `python tools/loment_genesis.py --emit` 重建 —— **改源码
常量对它无效**，这一条在两次里都咬过人（症状是自举第一步报 `标签表满了`，而那个 `lomelf`
正是 genesis）。

> **这一条为什么必须写在这里**：它不是"顺手改的别的东西"，是**这一维的代价本身** ——
> 兑现 `runtime` 要往自举编译器里加代码，加代码就长大，长大就撞容量。链条是直的。

## 8. 我不主张

1. **不主张这条规矩"更安全"。** 它买到的**不是安全**，是**可判**：产物里有没有运行期
   从此是一句能验的话，而不是一种期待。安全性一个字没多。
2. **不主张保守的触发表是完整的。** 它是**下界**（`alloc`/除法/… 一定触发），不是精确解；
   一个走 `sys_alloc` 的程序仍然没有语言层的运行期，那是对的。
3. **不主张自举侧与参考实现完全等价。** §5 那处不对称是**明写的**，不是没想到。
4. **不主张这一维已经"装完了"。** 值名只说"有没有"（`docs/175` §3.6 的刻意选择），
   明天装线程/宿主服务时，§1 那段"运行期是哪一段"要重新划 —— 判据（A/C）跟着走。
5. **不主张默认档的这次破坏是免费的。** 代价在 §3，逐条列着；要不要接受它是**用户**的事，
   这次是接受了。
