# 146 · Loment 能力域的形式语义（M44）

> 状态: 规范草案 · 关联: docs/145 P4（M35–M43）· 实现: `tools/lomentc.py` 的 `Guard`
> 一句话: **guard 通过 ⇒ 索引在域内；审计条目数 = guard 通过次数。** 这两条是编译期与运行期
> 共同保证的，不依赖模型、不依赖调用者自觉。

## 1. 定义

一个能力域是四元组

```
D = (space, lo, hi, revocable)      space ∈ 标识符,  0 ≤ lo ≤ hi,  revocable ∈ {true, false}
```

Loment 里由 `capability <name> : <space>[<lo>..<hi>] [revocable]` 声明。编译单元导出
`CapDomain` 表（Rust）/ `@__loment_caps` 常量表（IR），内核与 Potato 形式对象读同一份。

## 2. guard 语句的语义

```
guard <cap>(e);
```

1. 求值 `e` 得 `idx`；
2. 若 `idx ∉ [lo, hi]` → **trap**（IR：`@__loment_abort`；Rust：`panic!`），**不产生任何其他副作用**；
3. 否则在审计表 `__LOMENT_AUDIT[cap]` 上加一。

## 3. 静态规则（编译期）

| 情形 | 结果 |
|---|---|
| `e` 是整型字面量且 `idx ∉ [lo, hi]` | **编译错误**（`能力 X 域 [lo..hi]，索引 idx 越界`） |
| `e` 是整型字面量且 `idx ∈ [lo, hi]` | 放行（运行期检查仍生成，可被优化掉） |
| `e` 非字面量 | 放行，运行期检查 |
| `<cap>` 未声明 | 编译错误 |
| `<cap>.space` 命中某条 `excluded "<space>: ..."` | 编译错误（M41） |

## 4. 健全性断言（可核对，非形式化证明）

- **S1（域内）**：任何一次成功返回的 `guard`，其 `idx` 必属于 `[lo, hi]`。理由：字面量在编译期已判，
  非字面量在运行期判并 trap。
- **S2（审计保真）**：`__LOMENT_AUDIT[cap]` 等于该编译单元内 `guard` 通过次数之和。
  理由：只在通过分支上加一，且无其他写入点。
- **S3（无副作用越界）**：越界路径只执行 trap，不写任何用户可见状态。

这三条由 `tools/lomentc_test.py` 的 P4 用例与 M43 模糊测试（120 组随机 `(lo,hi,idx)`）核对。

## 5. 明确未覆盖的部分（诚实边界）

- **没有形式化验证**：以上是"实现级断言 + 测试核对"，不是机器检查的证明。
- **没有信息流分析**：`guard` 只约束**索引**落在域内，不约束数据从哪来、到哪去。
- **撤销（revocable）只有表示**：`revocable` 标志进域描述表与 Potato 形式对象；
  **真正的撤销语义由内核在运行期实施**（P7/M37 待做）——语言侧目前只保证"声明存在且可读"。
- **A1–A4 的 Loment 表达（M40）与信任自适应域宽（M42）** 需要内核能力域模型对齐，排在 P7。
- **guard 不是授权**：它检查索引，不检查"当前主体是否有该能力"；主体-能力的绑定在内核侧。
