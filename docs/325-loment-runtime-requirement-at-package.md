# 325 — 运行期需求从"每个模块"上移到"包"，并把除法从触发表里拿掉

用户 2026-11-09 的裁决：**"目前所有库都必须基于 runtime，这是不被允许的"**。
这一份做两件事：

1. 把**没有技术依据的那一格**去掉 —— 整数除法/取模不算"拖运行期"；
2. 把剩下的需求**上移一层**：写在 `pkg.lomp` 的 `runtime()` 里，由编译器在
   `no_runtime`（默认档）下报错；店里 248 个模块各写一行的 `choose runtime` 撤掉。

## 1. 除法不再触发

`_RUNTIME_SITES` 里原先有 `/` 与 `%`，理由是"除法要一个除零陷阱"。
**这条理由与实现不符**：整数除法发的是裸 `udiv`/`sdiv`（`lomentc.py` 的
`emit_llvm`），产物里一个 `@__loment_*` 都不多；`no_runtime` 那条保证的判据正是
"产物里没有 `@__loment_*`"（`docs/227` §2.1 的原文）。于是这两个 token 是**比保证
更严**的一格，只带来一个后果：任何做除法的库都被迫声明运行期。

两个实现同步删（`tools/lomentc.py` 的 `_RUNTIME_SITES` / `loment/selfhost/checker.lomt`
的 `chk_rt_site`）。规则等价表把那条负例换成 `panic`，预算仍是 **128/128**。

## 2. 需求写在包清单里

`pkg.lomp` 增加一个函数（与 `name()` / `version()` 同一种形状，零语言改动）：

```rust
pub fn runtime() -> str { return "runtime"; }
```

编译器在装载时读它（`_pkg_manifest`，用词法器扫，不引第二种格式）：

* 模块**自己**写了 `choose runtime` / `choose no_runtime` ⇒ 以它为准；
* 没写 ⇒ 取同包 `pkg.lomp` 的值，记进 `mod.chooses`，并记下来源（`rt_from_pkg`）。

于是同一份清单同时管两件事：

| 场景 | 行为 |
| --- | --- |
| 包里某个模块**当根单元**编译（`loment test`、孪生判据） | 清单的值就是默认档 —— 不必再写一行 `choose` |
| 程序**用**这个包里的模块 | 清单的值是**需求**：根是 `no_runtime` ⇒ 报，正文点名包 |

报错沿用那条既有消息的前缀（E022 的分类靠它锚），只在中间补一句
"（需求来自包 `X` 的 `pkg.lomp`）"，并且**同一个包只报一次** —— 一张 `use` 图里
`calendar` 会带进 `mem`，两条说的是同一件事。

## 3. 落地范围

- `lompi/store/*/*/pkg.lomp` 全部加 `runtime()`（12 个包）。
- `lompi/store/**/*.lomt` 里 **248 行** `choose runtime` 撤掉 —— 需求的唯一来源是清单。
- 自举侧：删掉 `/` `%` 触发；装载器读根单元所在包的清单，根自己没写这一维时在合并
  单元末尾补一行 `choose runtime`（与参考实现的注入同义）；依赖那一半本来就由
  合并流上的 E031 判得住，不需要额外机制。

## 4. 诚实账：为什么 12 个包今天都写 `runtime`

去掉除法之后重新数：**每个包里至少有一个模块的真代码用的是 `alloc`** —— 而
`alloc` 真的要那段运行期（`@__loment_alloc` + 堆全局，`docs/227` §2.3）。
所以今天没有一个包能诚实地写 `no_runtime`。这不是没查，是查过之后的结果：

| 包里"真代码"用到运行期构造的模块数（2026-11-09） |
| --- |
| std 26/141、world 10/22、dev 9/15、lowlevel 3/12、math 3/9、system 2/12、baremetal 1/6、engineering 1/4、science 1/6、host 1/8、internet 0/8、os 0/7 |

`internet` 与 `os` 的真代码是**纯的**，但它们的**自检**要 `alloc` 造缓冲 ——
而语言今天没有栈上数组（`let buf: [u8; 64]` 不存在），自检又必须留在模块里。
这是唯一挡在"包可以没有运行期"前面的东西。

**要走到那一步，前提是二者之一**（都记在这里，别把今天的标注当成终点）：

1. 栈上定长数组（自检不再需要 `alloc`）；
2. "库的自检不进产物" —— 依赖单元里的 `test_*` 既不发射、也不计入运行期需求。

第 2 条在参考实现一侧不大（发射器按函数名跳过 + 需求表按函数跨度过滤），
但自举侧是**合并 token 流**，模块边界已经没了（`driver.lomt` 的装载器注），
要靠文本级标记才做得住 —— 那是另一轮的事。

## 5. 判据

- `lomentc_test::test_pkg_manifest_carries_the_runtime_requirement`：五格
  （清单要运行期 + 根不满足 ⇒ 报并点名包；根满足 ⇒ 放行；清单 `no_runtime` + 纯模块
  ⇒ 默认档放行；清单 `no_runtime` + `alloc` ⇒ 报；模块当根 ⇒ 清单作默认档）。
- `loment_rule_parity`：除法那条负例换成 `panic`，**128/128**。
- 孪生：全店模块两边逐字节一致（清单注入不改变 IR）。
