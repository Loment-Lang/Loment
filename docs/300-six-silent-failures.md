> 状态：**已落地**（2026-11-04）· 上游 issue：#656 · #657 · #663 · #674 · #703 · #718
> · 相关：`docs/205`（0.1.5 的目标）· `docs/253` §11（LMS 预算）· `docs/258`（容量决策）
> 一句话：这六条**不是六个 bug**，是同一个形状的六处 —— **失败没有形状**：
> 退 0 当成成功、说了一句**假理由**、或者一句话都不说。
> 代码变更是用来把失败**变成可读的事件**的，判据是用来钉住"它以后也读得出来"的。

## 1. #674：写失败被当成成功

驱动把 IR / Potato / `--print-command` 的名字写在 stdout 上，`write_all` 的返回值
**从来没被看过**：

```rust
fn write_all(fd: u64, p: ptr, n: u64) -> u64 { ... }   // 短写时返回"写了多少"
```

`loment build > /dev/full`（盘满、配额用尽、管道另一头已关）于是**退 0**、一句话没有 ——
一份被截断的产物，构建系统认定它成功了。**静默截断比报错坏得多**：报错能被看见，
截断只会在下游变成一个"为什么我的程序少了一半"。

修法是一条 `write_checked`：短写就点名是哪一条流（`the IR` / `the object` /
`the command name`），说明可能是盘满/配额/管道，并退非零。判据用 `/dev/full` ——
Linux 的"永远 ENOSPC 的写端"，不需要真写满盘，也不需要 root。

**这一笔不动的**：`--diag-out /dev/full` 那种"诊断流写不出去"。那一条无论写没写出去，
退出码都已经是 1 —— 失败**有形状**（只是下游拿不到明细），与"成功但产物不存在"不是同一
档。诊断流的写是 `wdiag*` 一串零散的 `write_all`，要把它变成一条失败路径就得让每个
写出点都能回传"没写出去"，那是另一笔。

## 2. #657：失败的九条路径没有结构化诊断

`comefor` / `byuse` 展开失败时有九支并列的 `if`，每支只往 stderr 写一句话。
于是 `--json` / `--short` 的读者（启动器）拿到的是**一个空文件配一个非零退出码** ——
那正是"差错系统存在"要避免的组合：有失败，但没有**可解析的失败**。

九支现在同形：先 `wdiag_at(...)` 进结构化流，再 `fail(m)` 给人看。
`#657` 里剩下的 OOM / 用法 / `--diag-out` 打不开三条**故意**不写诊断：
前两条发生时诊断设施本身还没成立，第三条写进去会循环（打不开的是它自己要写的那个文件）。

**登记在案的缺口**：`expand_comefor` 只回**种类**（`re == 5`），不回 token 下标，
所以这条诊断的 `line` 是 `0`（渲染器见 0 不印行号），而参考实现给的是 `4:5`。
判据把 `line == 0` **钉住**，哪天把 token 带回来它就红，逼着改成真行号。

## 3. #663 + #656：诊断缓冲既会写穿、又会静默截断

缓冲原先 **8 KiB = 1024 格**，没有上限检查。第 1025 条写到偏移 8192 —— 那是紧挨着的
**检查器 arena 的第一个字节**，而它的头 104000 字节是符号表。于是从第 1025 条起，
检查器**一边写诊断一边改自己还在读的表**。它不崩，所以一直没人发现。

`#656` 是同一处的另一面：参考实现一条都不丢，自举侧静默只留"前 64 条"，
没有人知道一共几条。

现在：容量是**一个常量**（`switches.lomt` 的 `ERR_CAP = 4096`），写它的两个模块
（`sw_err` 与 `checker.lomt` 的 `sym_pub`）共用 `err_max()` —— "能写多少"与"分到多大"
是同一个数；满了**丢掉**（写入别人的活数据比丢弃坏得多），由 `chk_pub` 数进一格，
驱动器说出来：

```
loment: 304 more diagnostics were dropped (the buffer holds 4096): split the unit, or fix the first ones
```

### 3.1 修这条时踩到的第二缺陷（判据抓的）

`tyt` 块的最后 16 字节是四个格子，**偏移相对 `tyt` 起点**：

| 相对 `tyt` | 相对 `oc`（= `tyt + 4096`） | 用途 |
|---|---|---|
| 4096 | 0 | 诊断偏移格（`chk_pub` 专用） |
| 4100 | 4 | 运行期站点数（`#321`） |
| 4104 | 8 | 丢弃数（`#656`） |

第一版把 `ERR_DROP = 4104` 直接加到 `chk_pub` 手上的 `oc` 上 —— 落到块外 4 KiB 处，
而 arena 到 `oc + 16` 就结束了。**缓冲第一次满的那条输入当场 SIGSEGV**（退出码 139、
一条诊断都没有），而那正是这条判据喂的输入。判据没红在"报文不对"，红在"根本没有报文"。
修法是加一个 `ERR_DROP_OC = 8`，并在注释里写死"相对谁"。

这顺带说明了为什么这条判据值得花 150 秒：**容量边界不是算术，是要跑一次的**。

## 4. #703：参考实现把常量式说成"不是整型"

`expr_type` 对整数字面量返回 `None`（"由上下文定宽"），所以**整条常量式**（`(1 + 1)`）
也是 `None`。`as` 那一格把 `None` 当成"不知道类型"，于是：

```
(1 + 1) as u64      ->  as 只能作用于整型/布尔 (得到 None)
(x + 1) as u64      ->  OK
```

报文给的理由是**假的**，而且自举侧（`checker.lomt` 按 `chk_ty_is_int`）一直放行它 ——
同一份源码，参考拒、打包版能编。这是一处**孪生分歧**。

修法只动 `as` 那一格：`_is_int_const` 只认整数字面量与整型算子（`+ - * / % << >> & | ^`
与一元 `-`），**不动 `expr_type` 本身**（它返回 `None` 另有用处：绑定与实参按上下文定宽）。
常量式仍然**在 i32 上算、再按目标放宽 / 环绕** —— 与自举侧逐字节一致；
"在 i64 上算"看似更聪明，但会换掉孪生那一侧的产物。

补充一条实测：issue 里记的"自举侧也拒 `-1 as i32`"是**旧构建**上的现象 ——
2026-11-04 用当前树复测，`-1 as i32` / `(0 - 1) as u64` / `(1 + 1) as u64`
在自举侧**都收**（rc=0）。所以这一修是**把参考对齐过去**，不是"两边一起新放行"。

## 5. #718：0 字节是一个**合法长度**

`lvm.lomt` 的 `read_file` 把"打不开"与"读到 0 字节"都回成 `0`，调用方于是用
`n <= 0` 判失败 —— 一份**空 IR 文件**被报成「读不了输入」。它读得了，只是里面没有
`_start`，而那本来是另一句话（同一条路径上 T0/T2 一直报对）。

现在错误码分开：打不开回 `-1`，空文件回 `0`。判据两面都钉：空文件说得出"没有 `_start`"、
缺文件仍说"读不了输入" —— 修的是**把两者分开**，不是把报错换成另一句。
