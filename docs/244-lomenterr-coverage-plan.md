## 0. 现状：先把"已经不漏"的那一格钉住（实测）

写计划之前先量，否则"减少静默"会变成一句口号。三件实测出来的事：

| 事实 | 数字 |
|---|---|
| 错误码 | **27 个**（E001–E023 原生 + E024–E027 命令声明那条线） |
| 说明卡 | **27 × 2**（中英各一套，键集相等由判据钉着） |
| **编译器能说的诊断模板** | **102 种，全部有分类 —— 0 条落到 E0999** |
| 报错器自己那部分 | 默认英文、**全 ASCII**（936 控制台下不花） |

第三条是本轮新钉的：`loment_err_test::test_every_message_the_compiler_can_print_has_a_code`
扫 `tools/lomentc.py` 里 `errs.append(...)` / `LomError(...)` 的调用点，把**诊断模板**
枚举出来逐条过 `classify()`。**模板是上界，运行时消息是它的实例化** —— 上界覆盖了实例化
一定覆盖，反过来不成立（跑一遍语料只碰得到其中一部分，而**碰不到的那些恰恰最容易漏**）。

所以"分类"这一层已经闭合，而它**不是**静默的主要来源。下面按"静默有多深"排。

## 1. 更多的错误：语言面今天**能产生但什么都不说**的六处

按"用户看到什么"排，最坏的在前。

### 1.1 运行期 trap：进程直接死，一个字都没有

除零、`guard` 越界、`panic`、空指针 —— 今天的行为是**一个信号**（SIGFPE / SIGSEGV /
`ILL`），终端上只有 shell 的一句 `Illegal instruction`。这是整套系统里**最大的一块静默**：
写 Loment 的人撞到的第一个真 bug 很可能就是这个，而报错器**一个字都帮不上**。

设计早在 `docs/182` §10.4 写好了（往程序里链一份报错器 + `choose close lomenterr` 的运行时
那一半），**一行没实现**。它要动链接器与运行库，所以排在最后 —— 但它是**唯一**能让"运行期
有话说"的路径。

**代价**：高（要动两条运行路径）。**判据**：一个除零的程序跑起来，stderr 上出现
`error[E0xx]` 那一段，而不是信号。

### 1.2 一个解析错**中止整轮检查**

`docs/182` §6.8 记过：解析器一遇到语法错就停，于是后面所有诊断都出不来。用户得"改一处、
再编一次"地爬。这不是"少报一条"，是**一次只给一条**。

**代价**：中（解析器要能**恢复到下一个顶层项**继续）。**判据**：一份含三处语法错的源，
一次报出三条。

### 1.3 没有 warning 这一档

`lomentc` 里**一条 warning 都没有** —— 未使用变量、不可达分支、`excluded` 声明了却没用、
`capability` 声明了从不 `guard`：一律不说。这些**不是错误**，所以不能塞进错误通道；
但它们正是"用户写了没用的东西"的那一类，而今天**完全静默**。

`docs/191` §2 实测过：8 门语言里 5 门有 warning 档（clang / Rust / C# / GHC / PHP），
而且 Rust 的 `#[warn(unused_variables)]` 那套**是可关的**。这一格抄得动，但它要动
**诊断记录的形状**（`DIAG_FIELDS` 要多一个 `severity`），而那是跨两个实现 + Potato 的事。

**代价**：中高（动诊断协议）。**判据**：一个声明了没用的局部变量，`--check` 上报一条
warning 而**退出码仍是 0**。

### 1.4 语义诊断没有列号

`check()` 的消息形如 `"12: 文本"` —— **只有行，没有列**。所以插入符是**推**出来的
（"消息里那个在本文件里唯一出现的词"），而推不出来时只能划整行。

这一格是 `docs/191` §结论里"输在根上"的那一条：CPython 不是猜得准，是**根本不用猜**
（PEP 657 给每个 AST 节点带 `end_col_offset`）。**代价**：中（`check()` 一路要带 span）。
**判据**：`--json` 里出现 `col` 非 0，且插入符位置**不再依赖消息文本**。

### 1.5 `--max` 之外的"停手"没有理由

编译器在某个上限上停下来时（若有），报错器不知道。这一格今天**没证据说存在**，
列在这里只是提醒：真要加"停手"，必须像 `--max` 那样**明说还剩多少**。

### 1.6 编译器自己的异常

参考实现抛 Python 异常时会打**traceback** —— 那是给实现者看的，不是给用户看的。
`loment_cli_test` 有一条判据挡着"解析错不许打 traceback"，但别的路径没有全覆盖。

## 2. 减少静默：分三层，只有第三层还没做

| 层 | 内容 | 状态 |
|---|---|---|
| **L1 分类** | 每条消息落到一个码 | **已闭合**（本轮加判据钉住） |
| **L2 渲染** | 未知码 / 坏 JSON 行 / 缓冲截断 / 上限 | 已有，且都**明说**（`docs/182` §15） |
| **L3 系统** | §1 那六处 —— 根本**没有消息** | **未做** |

L1、L2 已闭合的意思是：**在"有话要说"的前提下，它从不少说**。剩下的静默全在 L3 ——
那些情形下**没有话**，而不是"有话说了一半"。

## 3. 更详细：一条诊断还能多说什么

按"对用户的价值 / 代价"排：

| # | 加什么 | 抄自 | 代价 |
|---|---|---|---|
| 1 | **第二处位置**（重名、未声明时的"另一处在这"） | clang 的 `note: 'X' declared here` | 低 —— 卡片的 `h_sect` 已经在，只要扫出第二处 |
| 2 | **机器可应用的编辑**扩展到拼写建议之外（类型不匹配、实参个数） | Rust 的 `rustfix` | 中 —— 要每一类都知道"改成什么" |
| 3 | 卡片里加**一对例子**（一行对 / 一行错） | Elm 的对话式报错 | 低 —— 纯数据，27×2 张各加两行 |
| 4 | `loment explain E022` 打进**渲染器**（现在只在 `lomcli`） | rustc 的 `--explain` | 低 |
| 5 | 诊断带**类型推导链**（`X 不是 Y，因为字段 a 是 Z`） | TypeScript 的 `because` 链 | 高 —— 要结构化的类型信息，今天没有 |

## 4. 落地顺序（每步独立可交付 + 判据）

1. **§3#1 第二处位置** —— 低代价、立刻能看见（`docs/182` §16 就欠着这一条）。
2. **§1.4 语义诊断带列** —— 它同时是 LSP 波浪线变准的**前置条件**（今天 `character: 0..200`）。
3. **§1.2 解析错不中止** —— 把"改一处编一次"变成"一次看完"。
4. **§1.3 warning 档** —— 动诊断协议，与 0.1.5-alpha1 的"零静默"目标同向，但影响面最大。
5. **§1.1 运行期 trap** —— 最大的一块，也最贵；`docs/182` §10.4 的设计在那儿等着。
6. §3 里剩下的按需。

## 5. 明确**不做**的

* **不把 E0999 消掉**：它是**响亮的**退路。真正要做的是让它在正常路径上永不出现（判据已钉），
  而不是删掉它 —— 删了以后新的未分类消息会**静默**变成别的东西。
* **不为没写的 warning 造一个假的严重性层级**（`docs/191` §4 已经拒过一次）。
* **不在这一轮动 `lom/*.lom`**：那是跨线契约（`CLAUDE.md` 那条冻结阈值）。
