## 1. 怎么测的

**夹具**（都在 `.tmp-cwork/`，未入库）：一份 `.lomt` → `potato_from.front_door` →
`lomentc.load` → `resolve_deps` → `check` → `emit_llvm` → `lomelf.compile_ll` → 写 ELF →
在 WSL 里跑，读退出码与 stdout。

**对照面**：数值类一律与**一场独立的 C 编译**比 —— `clang -O1 -ffreestanding -nostdlib`
（`docs/186` §1 那条原判据）与 WSL `gcc -O0` 都用了。**不是手算、不是拿译文自己比自己**
（`docs/186` §1 那条"要与独立算出的期望值对一次"）。

**装的 `loment` 0.1.4 CLI 走不了这条路**：自举侧只认 `choose write grammar loment`，
非原生写法一律退 **1** 并说"请用参考实现"（`docs/189` §4.1 已声明的在制品）。
所以编译器这条路走 `tools/`；**自举侧相关的那两条**（`doc` 退 0 给错文档、LSP 死）
另用**仓内 `loment/build/dist` 的自举产物**复测过 —— 那份 `loment version` 报
`commit d80ab09`，就是 HEAD。

## 2. 项目：拆法不是风格，是**唯一能跑的那种**

```
loment/examples/cproject/
    main.lomt       宿主。原生 Loment：use、跨单元调用、类型转换、输出
    bitkit.lomt     叶子。C 拼法：位运算 / CRC-32 / varint
    numkit.lomt     叶子。C 拼法：数论 / 排序网络 / 控制流
```

跑出来 `bits=533 nums=917 total=1450`（退出码 170）。三个数都是在 Python 里照 C 语义
**另写一份**算出来对过的。

**为什么宿主不能也用 C 拼法**（四条一起，逐条实测）：

| 想在 C 拼法的单元里做 | 结果 |
|---|---|
| 被 `use` | **可以** —— 前门发出来的就是 `pub fn` |
| 自己写 `use` | **静默消失**（对象、`skipped` 都不留痕）→ **#121** |
| 调别的单元的函数 | 拒，报"本单元没有的函数"（Stage A 不跨单元）；`docs/186` §9 留的 `pub extern fn` 口子在 C 拼法里**没有写法** |
| 两种整型之间转换 | **做不到**：无隐式转换，`(T)x` 又在子集外 → **#125** |

⇒ **C 拼法的单元只能是叶子**。所有 `use`、跨单元调用、跨类型转换都得由原生那一层承担。
"每个单元都用 C 拼法"今天做不到 —— 这是这一轮关于形状的**结论**，不是抱怨。

## 3. 缺陷（38 条，按类别）

### 3.1 静默错：产物编得过、跑得动，**数不对**（7 条）

这一类按本仓红线最重（`docs/186` §4："少一个就是'这个程序少算了一步'，而它照样能编过"）。

| # | 一句话 | 对照面 |
|---|---|---|
| #118 | 函数内 `static` 被丢掉，值不跨调用保留 | clang 12 / 译文 11 |
| #119 | 循环体里同名声明 → 步进改到被遮蔽的名字上，**死循环** | gcc 27 / 译文不终止（timeout 124）|
| #120 | C 的**块作用域**没保住：`if`/`while` 体里的声明重绑外层 | clang 1 / 译文 2 |
| #123 | `int`/`unsigned` 混算原样照发，按有符号算 | gcc 7 / 译文 8 |
| #130 | 变量叫 `true`/`false`：声明改名、引用没改，读到的是**布尔字面量** | gcc 5 / 译文 1 |
| #131 | 非简单左操作数（负字面量、减法、移位）的比较**按无符号**做 —— `(-1) < 0` 为假，而同一单元的 `(-1) == -1` 为真 | gcc 1 / 译文 0 |
| #133 | `int` + `long` 混算，结果**取决于操作数顺序** | gcc 1 / 译文 0 |

另有两条宽度类（#132 超 32 位字面量静默截断、#124 `bool→int` 投影缺括号导致**译文解析不过**），
分类上属"①/⑤"，一并挂在那里。

**`docs/186` §6.3 那处论证**（"`static` 收下并丢掉是保义的"）只覆盖**文件作用域**的
`static` 函数；局部 `static` 说的是**静态存储期**，与链接无关 —— #118 就是它。

## 4. 为什么现有判据照不到

逐条都能指到一个**具体没被喂过的形状**（issue 里每条都写了），汇总成三类：

1. **语料只用一种形状**：`loment/ctrans/*.c` 四份**一行一个函数、函数之间还有空行**
   （⇒ #122）、**全程只用一种整型**（`numeric.c` 文件头自己写着，⇒ #123/#125/#133）、
   **`static` 出现 0 次**（⇒ #118）、**没有一处拿负值或减法结果去比较**（⇒ #131）、
   **每个函数各占一行**（⇒ #122/#129）、**没有原型**（`grep -c 'int [a-z]*(int [a-z]*);'` = 0，⇒ #153）。
2. **两条入口各测一半**：`loment_ctrans_test` 在**库层面**调 `from_c` 并读 `rep.skipped`
   （所以 #126/#129 那类"scanner 根本没匹配上"它看不见）；走 `front_door` 的判据
   （`loment_grammar_test`）喂的是能翻的源。⇒ #121/#146。
3. **只钉"范围"不钉"内容"**：`test_out_of_subset_is_loud` 的断言是
   `"switch" in msg` 与 `"带正文的" in msg or "1 个" in msg` —— 它的 docstring 复述了
   `docs/186` §4 那句"报得出是哪个函数"，**断言里没有函数名**（⇒ #154）。

还有一类是**判据根本不存在**：#139（两份文件同名 `module`）—— 既有的多模块判据用的是
**两个不同名**的模块；#115/#116/#142/#144 那四条入口面缺陷，**没有一条判据把一份带声明的源
喂给 LSP / fmt / doc**。
