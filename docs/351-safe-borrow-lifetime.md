# 351 · 安全域借用生命周期：第一个联合检查系统

> 状态: **设计稿（2026-11-18）**；期 A / 期 B 均未实装。路线在 §9，九条借用 issue 的
> 排期也在那里。
> 上游: `docs/299`（借用区域）· `docs/306`（域代数与时律）· `docs/314`（域块）·
> `docs/315`（域循环与虚拟钟）· `docs/318`（借用生命周期域，十种）· `docs/320`
> （权能时序安全）· `docs/253`（LMS）· `docs/262`（LSPE）· `docs/210`（LGC）
> 一句话: 借用区域、域时律、安全权限今天各判各的；本页把它们接进**同一个域形状**，
> 由一个联合检查器同时回答"这块内存能碰多久、现在还能不能碰、谁能碰"。

---

## 0. 用户裁定（2026-11-18）

> 安全域借用周期可以在任意一个时域内借用生命周期，并直接通过域检查器和借用检查器
> 联合检查，这也是第一个联合检查系统。

落实成三句话：

1. **形态**：新的域形状，借用发生在**一个时域之内**（`epoch` / `decaying` / `cyclic` …
   任取其一），时域给出窗口，借用给出区域。
2. **强度**：**编译期证明 + 运行期台账**。静态证得出来的写进证明；静态证不出的
   （动态下标、`extern fn` 写、跨块的时窗推进）交给一张运行期借用账本，拒绝时点名。
3. **路线**：九条借用 issue（#1541–#1565 里的九条）与本域作为一条线规划，分 PR
   按依赖顺序落地（§9）。

**这一页与 `docs/318` §7 的分界**：那一页写"不做运行时借用计数（`RefCell` 那种）"，
理由是把编译期错误变回运行期错误。本域是**有意的例外**：它只在**时窗**这一轴上
做运行期账 —— 静态那部分一个字节都不放过，运行期只补"时域是动态的"那一格（§3.4）。
两者不冲突：`docs/318` 的十种域仍然零运行期。

## 1. 缺口的准确形状

今天有三套寿命，各自健全，彼此之间**没有接线**：

| 寿命 | 归属 | 回答什么 | 判据 |
|---|---|---|---|
| **区域**（`docs/299`） | 借用检查器 | 借用能不能比来源活得长 | E012 / E041 / E007 |
| **时律**（`docs/306` §4–§5） | 域检查器 | 第 k 个实例还在不在 | `tick` / `guard@k` / 过期守卫 |
| **权威**（`docs/306` §3、`docs/318` R2） | 域检查器 | 这块地址现在归谁 | 能力/极性/写权限 |

于是下面这段代码今天**通过**：

```rust
fn f(xs: &[u32]) -> u32 {
    let mut total: u32 = 0;
    domain ep : epoch(1) {
        let r: &u32 = &xs[0];
        tick();                 // 纪元 1 结束
        total = total + *r;     // 区域说 xs 活得够长；时域说 r 已经过期
    }
    return total;
}
```

三句话今天都说不出来：

1. **"这个借用只在纪元 1 里有效"** —— 区域只知道 `xs` 的来源，不知道 `epoch(1)`；
2. **"这块地址在窗口结束前不许换主人"** —— 时律只知道实例号，不知道谁在借它；
3. **"这次访问要同时过两关"** —— 两个检查器之间没有一条联合规则。

`docs/318` 的十种借用域解决的是第 1 句的**一半**：域给区域起名字，区域 ⊆ 域。
它没有时轴 —— 十种形状的时律都固定成 `regular`。`docs/320` 解决的是第 2 句的
**一半**：对象代与撤销代给权能加了时间，但它管的是"权能还认不认对象"，不管借用。

## 2. 新域：`safe_borrow(x[, 时律])`

```rust
domain sb : safe_borrow(xs, epoch(1)) {
    let r: &u32 = &xs[0];
    s = s + *r;                 // 读：过 J1 + J2
    // tick();                  // E041：窗口还开着，不许推过它
    // xs[0] = 1;               // E041：共享借用下不能写（沿用 R2）
}
// tick();                      // 窗口在这里结束；r 不许带出（J1）
```

* **形状**：`safe_borrow(SRC)`（无时轴，等价于今天的 `borrow(SRC)` 加运行期账本）
  或 `safe_borrow(SRC, LAW(N))`，`LAW` 取 `docs/306` §5 的时律词表
  （`epoch` / `far` / `sliding` / `decaying` / `growing` / `consumed` / `cyclic` /
  `generational` / `adaptive`）。只收**带参数的**律；`regular` 没有窗口，写它就等于
  省略第二个实参。
* **来源**：一个**已经可见**的名字（形参 / 局部 / 结构体字段路径），与 R1 同一条。
* **窗口**：`LAW(N)` 在进入块时把"当前实例"记下来；窗口 = 这个实例的存活期。
  对 `epoch(N)`、`consumed(N)`、`generational(N)` 是"实例号是 N"；对 `decaying(N)`、
  `sliding(N)`、`growing(N)` 是"从进入起 N 个 tick"；`cyclic(N)` 是一个周期；
  `adaptive(N)` 取实现当前给出的预算（与 `docs/313` §4 的状态表同源）。
* **区域**：就是 `SRC` 的区域，来源与 `docs/299` 完全同一套（形参借用 / 局部借用 /
  结构体字段携带的区域 / 函数摘要的出参来源）。
* **不新增语法词**：`safe_borrow` 是形状名（与 `borrow` / `window` 同一张表），
  第二个实参复用 `parse_law_tail` 的词表。

### 2.1 联合规则

四条规则，J1/J2 在编译期，J3 编译期 + 运行期，J4 是分工条款：

| # | 规则 | 谁判 | 违反 |
|---|---|---|---|
| **J0** | 来源可见（与 R1 同条，复用） | 域检查器 | E041 |
| **J1** | **区域 ⊆ 窗口**：块内产生的借用不得活过窗口；块结束（含 `return` / `?` / `break` / `continue`）后借用不可再用 | 借用检查器出区域，域检查器出窗口，联合比 | E041 |
| **J2** | **写权 ⊆ 两边**：写要求 `borrow_mut` 域（R2）**且**时域允许（安全域不能降级成危险域，`docs/306` §3） | 域检查器 | E041 |
| **J3** | **一个实例一把独占借**：同一 `LAW(N)` 实例上不允许两把独占 `safe_borrow`（嵌套同名即违例）；共享可以多把 | 编译期能判就编译期，否则运行期账本 | E041 / 运行期 `loan` 拒绝 |
| **J4** | **静态证不出就下沉**：动态下标、`extern fn` 触到的借用范围、跨块的时窗推进，必须有一条运行期检查；没有检查点时**编译期拒**，绝不静默放行 | 联合检查器 | E041（缺检查点）/ 运行期 `loan` |

J1 与 `docs/318` R1 的差别：R1 只要求"域不比来源活得长"，J1 还要求
"**借用不越过窗口**" —— 窗口可能比来源短得多（`epoch(1)` 可以在 `xs` 活着时结束）。

J3 的编译期那一半今天就能判：同一函数内嵌套的 `safe_borrow` 块，形状与参数都是
编译期常量，实例号相同即拒。跨函数的实例号来自运行期，落进账本。

### 2.2 与十种形状的关系

`safe_borrow` 不替代任何一种：

| 既有形状 | 与 `safe_borrow` 的关系 |
|---|---|
| `borrow(x)` / `borrow_mut(x)` | `safe_borrow(x)` 的静态部分与它们相同；差别是**多了窗口与账本** |
| `epoch`（域形状） | 那一格管"域内借用不能带出"；本域管"借用不能越过时窗"，两者可嵌套 |
| `loan(x) to y` | 移交一次所有权；`safe_borrow` 不移交，只借用 |
| `session(x)` | 线性移交；可与 `safe_borrow` 并存（窗口内移交，窗口外不可用） |

## 3. 运行期台账

### 3.1 账本形状

一个**按线程**的定长表，进产物时是 `.loment.loan` 段里的一段静态内存：

```
entry { site: u32, base: ptr, len: u64, mode: u8, inst: u32, gen: u32 }
```

* `site`：源码里 `safe_borrow` 的编号（编译期定，诊断与拒绝都用它点名）；
* `base` / `len`：被借范围（`SRC` 的地址与长度；标量取 1）；
* `mode`：0 = 共享，1 = 独占；
* `inst`：进入时记下的实例号（`epoch` 类）或目标 tick（`decaying` 类）；
* `gen`：账本自身的代数，`close` 时清掉，防止旧句柄复用。

**默认容量 `LG_CAP = 16`**。上界由编译期算：同一函数里 `safe_borrow` 的最大嵌套深度
就是同时打开的条数上限，取 `max(16, 深度)` 并把数写进产物（`--print llvm` 可见）。
账本满时**拒绝**（点名"账本已满"，不是静默丢弃）—— 与 `#656` 的"丢也要有个数"同一条纪律。

### 3.2 三个操作

```rust
lg_open(site, base, len, mode, inst)    // 进块
lg_close(site)                          // 出块（所有出口）
lg_tick()                               // 每个 tick / 回边（窗口推进）
lg_check(site, idx)                     // J4 的检查点
```

* `lg_open` 满 → 拒绝（上一条）；
* `lg_close` 必须是**后进先出**：不匹配说明控制流篡改了账本 → 拒绝并点名 site；
* `lg_tick` 扫开着的条目：`epoch` 类若是本实例则续期，已经推过窗口的条目变成
  `stale`；`stale` 上再 `lg_check` 或再开同名实例 → 拒绝；
* `lg_check` 判三件事：条目还开着、`idx` 落在 `[base, base+len)`、条目不是 `stale`。

### 3.3 拒绝的形态

一条 `llvm.trap` 加一行点名（与 `docs/255` 的 `lvm trap` 同一形状）：

```
loan: safe_borrow(xs, epoch(1)) 的窗口已结束（site 3，行 12）
```

退出码沿用 trap 的 132。**拒绝不产生副作用**：检查在读写之前。账本自身坏了
（LIFO 失配、代数不匹配）单独一条消息："loan 账本损坏（site N）"，同样 132。

### 3.4 什么时候下沉

静态能证明的四类**不下沉**（零开销）：

1. 借用来源是形参、窗口是 `epoch(常量)`、块内没有 `tick`；
2. 区域里的访问都是常量下标，且下标已在域内；
3. 块内没有 `extern fn` / `syscall*` 触到 `SRC`；
4. 没有 `return` / `break` / `?` 带出借用（J1 已静态拒）。

其余进账本。**判据钉住"没有 `safe_borrow` 的单元逐字节不变"**，所以下沉是纯增量。

## 4. 联合检查器的分工

```
          ┌─────────────────── 联合检查器 ───────────────────┐
区域环境 ──┤ J1 区域 ⊆ 窗口    J4 下沉决策    J3 冲突计数      ├── 账本（编译期对象）
（docs/299）└────────────────────────────────────────────────┘
时律状态 ──┘        │ 静态违例 → E041（点名域、值、行）
（docs/306）        └ 未决义务 → Potato 的 lspe.per_kind["Loan"]
```

* **编译期台账**：每个 `safe_borrow` 站点一条义务（`proved` / `undecided`），
  进 `lspe.per_kind` —— 这就是 `docs/262` §8 的台账，不新开一种账。
  `--lspe-mode=strict` 下 `undecided > 0` 即拒。
* **运行期台账**：§3 的表。两本账用同一套 site 编号，`loment err` 能按 site 对账。
* **冲突时谁说话**：同一条违例若两边都能判（例如块内 `tick` 推过窗口），
  由联合检查器统一发一条 E041，消息点名"域 + 律 + 行"，不叠两条。

## 5. 诊断

全部并入 **E041**（`docs/299` §5 的家族），消息必须点名 **形状 / 值 / 律 / 行**：

```
E041: safe_borrow 的窗口在块内被 tick 推过：xs（epoch(1)，行 9）
E041: 块结束时借用仍活着：r 借自 xs，窗口 epoch(1) 已结束（行 12）
E041: 共享 safe_borrow 里不能写 xs（行 10）
E041: 同一 epoch(1) 实例上已有独占借用：sb@4（行 7）
E041: 动态下标 xs[i] 没有账本检查点（J4，行 11）
```

运行期的拒绝是**运行时消息**（§3.3），不是诊断码；诊断码只出现在编译期。

## 6. 与既有机制的分工

| 机制 | 管什么 | 与本域的交界 |
|---|---|---|
| 区域（`docs/299`） | 借用不越过来源 | J1 的左半边；本域补上"不越过窗口" |
| 借用域（`docs/318`） | 区域的名字与准入 | `safe_borrow` 是第 11 种形状，R1/R2 照旧 |
| 时律（`docs/306`） | 实例还认不认 | J1/J3 的右半边；`tick` 是窗口的事件 |
| 权能时序（`docs/320`） | 对象代与撤销代 | 对象代变 → `lg_check` 失败（账本里的 `gen`） |
| LGC（`docs/210`） | 运行期回收 | 账本只读 `base/len`，不阻止回收；`free` 时账本条目变 `stale` |
| LMS（`docs/253`） | 访存点检查/拒绝/退出 | 账本检查与 LMS 检查各判各的，两个都可拒 |
| LSPE（`docs/262`） | 义务与证据 | `per_kind["Loan"]` 就是编译期账本 |

## 7. 明确不做

* **不做引用计数**（`RefCell` 那种）：账本记的是**区域**，不是每个值上的计数器；
* **不允许域跨函数传递**：窗口是块的（与 `docs/318` §7 同一条）；
* **不引入 `'a`**：区域仍走 `docs/299` 的省略规则；
* **不改十种既有形状的任何字节**：`safe_borrow` 是纯增量，判据钉住"不写它就逐字节相同"；
* **不做并发账本的原子化**：账本按线程；跨线程借用在 `thread_spawn` 那一层拒
  （线程参数是 `u64`，借用要显式转换，那条转换是 `ptr` 逃生舱，责任在写的人）。

## 10. 自举侧镜像与成本

* 检查器：`chk_sbd`（token 级），复用 `chk_life` 的 `CHK_LV`（来源）与 `chk_bdom`
  的律表；J1 的比较是"两个窗口号"的比较，不需要 AST。
* 代码生成：`dom_stmt` 认第 11 种形状，块前后发 `lg_open` / `lg_close`；
  `tick` 的发点已经存在（`CG_CLOCK` / `CG_TICKX`），加一条 `lg_tick` 调用。
* 账本本身用 **Loment 写的运行期支持**（与 LGC 根表同一块内存），不做成内建：
  它就是 `loment/rt/` 里的一个模块，两个实现都调它。
* 成本：加一个形状 ≈ 自举编译 +5s（`project_selfhost_change_costs` 的实测），
  账本是新的一小段运行期代码，不碰既有路径；容量上限先按 `LG_CAP = 16` 钉住。
