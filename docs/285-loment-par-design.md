## 0. 三个零

"全自动"在这门语言里不是一句形容词。它拆成三句可检查的话，缺一句就不成立：

| 零 | 它拒绝什么 | 它怎么被检查 |
|---|---|---|
| **零注解** | `par` 关键字、`#[par]`、`Send`/`Sync`、`async`/`await`、手写分块、线程池参数 | 唯一的旋钮是**根单元**的 `choose par_*`；没有第二处（§5） |
| **零猜测** | "大概不冲突就并行"；用"跑一遍没出错"当证明 | 每个并行站点都有一份被消解的证明义务（§3）；证不出就是串行 |
| **零沉默** | 悄悄不并行、悄悄降级、悄悄把收集器关掉 | 每个串行站点在产物与报告里都有理由（§6.4） |

一句话：

> **全自动不是"全都并行"，是"不用你标"。**

这条区分不是修辞。它决定了后面每一条设计：我们不造一个更强的分析器，我们造一门
**让并行性可以被证明、被拒绝、被看见**的语言。

## 1. 先把不可能写死

### 1.1 完全性不可能

**定理（三选二）**。对含 `ptr` 与 `extern fn` 的语言，不存在翻译器 `T` 同时满足：

- **(E) 等价**：对每个程序 `P` 与每个输入，`T(P)` 的可观察行为等于 `P`；
- **(T) 完全**：对 `P` 中每个"在某个输入上确实独立"的循环，`T` 都会并行；
- **(Z) 零注解**：`T` 不需要任何注解。

**证明思路**。独立性是"对输入的全称量化"，而含 `ptr`/FFI 的语言里，精确的别名与依赖判定
是不可判定的（Rice 定理的直接后果）。于是对任意 `T`，总存在一对只差运行时别名关系的程序：

```rust
fn step(p: ptr, q: ptr, n: u32) -> u32 {
    let i: u32 = 0;
    while i < n {
        store8(p, 0, 1);       // 与下一句可能冲突，也可能不冲突
        let v: u32 = load8(q, 0);
        i = i + v;
    }
    return i;
}
```

`p` 与 `q` 是否别名由调用方（甚至由 FFI 返回值）决定，定义点看不到。若 `T` 并行它，
存在一个输入让它算错（违反 E）；若 `T` 一律不并行，则它同时拒绝了一整类真正独立的程序
（违反 T）。要两者兼得，只能让用户把别名关系写出来——违反 Z。

**所以三选二。我们选 E + Z，放弃 T。** 但放弃不是沉默：放弃的部分必须**可量、可见、可查**
（§6.4 的报告与产物）。这就是"零沉默"的由来。

### 1.2 收益不可能

即使独立性证对了，并行也不等于更快：

- 收益取决于机器（核数、缓存、NUMA、内存带宽），而编译器看不到它；
- 收益取决于输入（同一个循环在 4 次迭代与 4 亿次迭代上是两件事）；
- 收益不是单调的：任务创建、同步、假共享、分配器争用都能让它变慢；
- 同一份产物在不同机器上是最优粒度的可能性，本来就不存在。

所以 `par_auto` **不承诺加速**。它承诺的是语义等价（§3.2），并把"哪些站点真的并行了"
写进产物（§6.1）。"并行"是一个**语义事实**，不是一个性能数字。

### 1.3 于是我们拿掉哪五条假设

| 假设 | 拿掉它的代价 | 本设计的替代 |
|---|---|---|
| 编译器能从任意代码里发现效果 | 精度：`ptr` 与 FFI 只能保守 | 整单元足迹推断 + **不透明**标记（§4.1） |
| 编译器知道机器 | 最优粒度与宽度都算不出 | 编译期只判"值不值得"；宽度运行期定（§4.4） |
| 编译器看得见整个程序 | 跨 `extern` 没有保证 | 保证是**单元内**的；外部是明确的不透明边界（§4.1） |
| 并行是免费的 | 资源会无界 | 结构化 fork-join + 栈池 + 预算（§4.6） |
| 非确定性可以接受 | 丢掉一类算法 | 自动并行只做**确定性**；非确定性走 `thread_spawn`（§3.6） |

这五条就是本文全部工程量的来源。它们都不是"待补的洞"，是**明写的价**。

## 2. 一等公民，与"最后一个"

### 2.1 什么叫一等公民

本文用五条判据。一条语义只有同时满足这五条，才算**一等公民**，否则它是库、是诊断、
是后端的优化：

1. **有维**：它是 `CORE_DIMS` 里的一维，每程序一值，进 Potato（`tools/lomentc.py:1534`）。
2. **有语义**：取值改变程序**是什么**——可观察行为，或它对世界的可审计承诺；
   只改变快慢的不算。
3. **有判据**：两份实现逐字节一致；一条**差分**判据证明行为等价；一条**负例**判据证明
   该拒绝时真的拒绝。
4. **有产物**：不读源码可判；两份链接器核它（`docs/274` §1 的"产物记录"与"带牙检查"）。
5. **不可省**：拿掉它会改变某个已存在程序的语义；它不是语法糖。

`par` 五条都满足（§5–§6）。这也解释了为什么 GC 是一等公民而 `Rc<T>` 不是：
前者改了"谁归还"的语义，后者只是一个库。

### 2.2 八维，五轴

`LLS` §4 的正文今天只列了五维（`mode` / `gc` / `runtime` / `port` / `vm`），
`lms` 与 `lspe` 是之后加的；权威表是 `CORE_DIMS`（`tools/lomentc.py:1534`）。
这是 LLS 的一处文档债，本文不顺手改它。按代码数，今天是**七维**；`par` 是**第八维**。

把这七维按它们回答的问题归类，只有五个轴：

| 轴 | 它回答的问题 | 维 | 今天的取值 |
|---|---|---|---|
| **权** | 产物能碰到什么、被什么约束 | `mode` · `port` · `lms` | `std`/`no_std` · `sealed`/`hosted` · 四档 |
| **命** | 内存活多久、谁归还 | `gc` | `gc_manual`/`gc_auto`/`gc_auto_alpha`/`no_gc` |
| **机** | 什么在跑、怎么跑 | `runtime` · `vm` | `runtime`/`no_runtime` · `vm`/`no_vm` |
| **记** | 事后能证明什么 | `lspe` | `lspe_open_admin`/`lspe_close_admin` |
| **时** | 事情按什么次序发生 | **`par`** | **`par_manual`/`par_auto`/`par_auto_alpha`** |

前四轴都是**状态**谓词：能碰到什么、什么还活着、什么在跑、留下了什么记录。它们可以逐单元、
逐站点、逐产物地**组合**——每个单元各自答对，合起来仍然答对。

**时是唯一一个不组合的轴。** 两个各自正确的单元，并发起来可以错。所以它是最后一轴：
它把前四轴的局部保证**收口**成全局保证。收到这里，剩下的一切语义问题都变成"五轴怎么组合"
的问题，而不是"还有哪一种问题"。

### 2.3 为什么第六轴不存在

这是一条**判据**，不是一句口号：

> 两个确定性程序的可观察差异，只可能落在五件事上：**可达、存活、运行、记录、顺序**。
> 任何新提案必须给出一对程序：它们在这五件事上完全一样，却在某项上不同。给不出，
> 它就不是一个新轴，而是五轴的组合。

拿本项目已经规划的东西当证据，逐条投影：

| 提案 | 投影到哪 | 为什么不是新轴 |
|---|---|---|
| 热更新（0.1.5.1，伞 #1146） | **机 + 时** | 换的是"什么在跑"与"什么时候换"，两者都是已有轴 |
| 分布式执行 | **权 + 时** | 多出来的是端口与次序，不是新的观测维度 |
| 持久化 | **命 + 机** | 活过进程的是内存与承载它的机器 |
| DGT（0.1.5.2，伞 #1196） | **不是维** | 它是**编译期图类值**，是类型系统里的一种值，不是整程序承诺 |

这条判据也是可证伪的：只要有人拿出一对在五轴上完全相同、却可观察地不同的程序，
本文的闭合主张就错了，`par` 就不是最后一个。**把反驳的入口写在这里，而不是藏起来。**

### 2.4 "最后"是宪法，不是定理

要诚实：§2.3 是一个**定义**（可观察差异 = 五轴），不是一个数学定理。它靠三样东西执行：

1. **举证责任**（§2.3 的那对程序）。写进 LLS，成为提第九维的人要先付的成本。
2. **版本规则**。LLS §6.4：标准的版本**就是**语言的版本，一个数。闭合写在标准里，
   所以它不是一条博客承诺；破它要一次 LLS 大版本。
3. **门禁预算**。这是最硬的一条：矩阵今天已经 **240 格**（`docs/274` §1 的矩阵那一条），
   每一维按合法取值再乘。再进一维，孪生逐字节判据的墙钟与判据数都要重新量；
   而逐字节孪生是本项目的中心判据（LLS §5.1 第 2 条）。**第九维买不起，不是因为
   它不可能，是因为它比它买到的东西更贵。**

所以"最后一个"的完整含义是：

> **八维之后，语言不再增加新的"承诺种类"；它仍然可以增加取值、库、诊断、实现与性能。**

我们没有冻结语言。我们冻结的是**它能作出的承诺的种类**。这是两件不同的事。

### 2.5 写进 LLS 的那句话

落地时在 `standard/LLS.md` §4 末尾加一条（英文，与 LLS 同语言）：

> **4.6 The table is closed.** The eight dimensions above are the complete set. A ninth is
> not a feature request; it is a new axis of observable commitment, and the burden of proof
> is a pair of programs that differ in none of *reachability, lifetime, execution, record,*
> and *order*. If such a pair cannot be exhibited, the feature is a combination of the eight —
> it belongs in a value, a library, or a diagnostic. This clause is itself part of the frozen
> surface: removing it costs §6.2 and a new edition of this standard.

`docs/274` §2 的联动表加最后一行（§附录 C）。这一条与 `CORE_DIM_ORDER` 的末尾追加一起，
把"最后"变成两处可核对的登记，而不是一段宣言。

## 3. 语义

### 3.1 足迹

每个函数有一个**足迹** `Φ(f) = (R, W)`：它可能读的**位置**与可能写的位置。位置有六种：

```
place ::= local(f, slot)          函数帧里的槽
        | heap(region, range)     区域里的一段
        | cap(space, lo..hi)      能力域覆盖的外部状态
        | audit(cap)              __LOMENT_AUDIT[cap] 那一格
        | world(port)             世界端口（syscall / extern）
        | unknown                 说不清（`ptr` 的默认）
```

推断规则（读 / 写；`Φ(e)` 是表达式的足迹）：

| 语句 | 读 | 写 |
|---|---|---|
| `x = e`（局部） | `Φ(e)` | `local` |
| `a[i]` | `heap(region(a), i)` | — |
| `a[i] = e` | `Φ(e) ∪ heap(region(a), i)` | `heap(region(a), i)` |
| `alloc(n)` | — | 新区域 ∪ 分配器状态 |
| `free(p)` | — | `heap(region(p))` ∪ 分配器状态 |
| `guard c(i)` | `cap(space, i)` | **`audit(c)`** ∪ 可能的 trap |
| `extern f(...)` | `world(*)` | `world(*)`，且 `opaque` |
| `syscallN(...)` | `world(*)` | `world(*)`，且 `opaque` |
| `load8(p)` | `heap(unknown)` | — |
| `store8(p, v)` | `Φ(v)` | `heap(unknown)` |
| `thread_spawn(...)` | — | `world(*)`，且 `opaque`，且整单元置"有非结构线程" |

**`guard` 是一个写**，这是最容易看漏的一格：`docs/146` §2 规定它通过时在
`__LOMENT_AUDIT[cap]` 上加一，§4 的 S2 又要求"审计条目数 = 通过次数"。两个针对**同一个
能力**的 `guard` 因此不是独立的，除非运行期给每个任务一本分账（§7.4）。这一条是本设计
从已有语义里**读出来**的，不是新增的。

`ptr` 是默认的 `unknown`：只要一个位置不能归到上面五种，它就是 `unknown`，与一切相交。
这是系统语言的价：**精度换健全**。

### 3.2 可观察轨迹与"保序"

一个程序的**可观察轨迹** `τ(P)` 是：

1. 世界效果的序列（`syscall` / `extern` 的实参与结果，按发生次序）；
2. **语言级异常退出**的序列（`guard` 越界、LMS 的拒绝/崩溃、分配失败）；
3. 进程的最终退出码。

内存本身不在轨迹里——它只有通过世界效果才被看见。这与能力域的定义一致：
观察是**外向**的（`docs/146` §1），不是"内存里有什么"。

**`par_auto` 的全部语义就是一句**：

> 对同一输入，`τ(par_auto 的 P) = τ(par_manual 的 P)`，逐事件相同。
> 不同的只有它用了几条线程、以及这些线程怎么排。

这条比"stdout 一样"强：它要求**世界效果的次序**一样。一个先打印后写文件的程序，
并行版不能反过来。它也比"结果一样"弱：它不要求内部调度一样——调度不可观察。

### 3.3 独立与数据竞争

两条事件**独立**，当且仅当：

```
W1 ∩ (R2 ∪ W2) = ∅  ∧  W2 ∩ (R1 ∪ W1) = ∅
∧ 两者都不 opaque
∧ 两者不写同一个共享资源（分配器前沿；同一格的审计表；同一把锁）
```

**数据竞争**是一对冲突事件在调度里没有次序。`par_auto` 不靠运行期检测器发现竞争；
它**构造**的调度里根本没有竞争——这是静态证明的直接后果。这也是它相对于
"跑一遍 + race detector" 的差别：后者是抽样，前者是合同。

### 3.4 失败：顺序里最早的那一个

并行会改变"哪个错误先发生"吗？在朴素实现里会：任务 B 先崩，但程序顺序里任务 A 更早。
那是一个**可观察差异**，而且是最难查的一类。

规则：**语言级异常退出按顺序程序的全序取最小**。哪个任务先崩不重要，报告的是
**顺序上最早**的那一个。实现上不贵：

- 每个任务带自己的序号；
- 一个任务异常时，置一个"最小序号"的原子位；
- join 时对序号小于它的任务等完（它们最多跑完自己那一段），再报最小值。

硬件故障（段错误、SIGFPE）**不在等价域内**：那是未定义行为，顺序版本身也没有语言定义的
行为。这句话要明写，否则承诺会变成"任何崩溃都保证一致"，那是假的。

### 3.5 分配：每任务一片，总量不缩

并行分配不能共用一个 bump 前沿（那是共享写）。设计：

1. 每个任务领一片**区域**（arena 的一段，或 `no_runtime` 下的静态缓冲）；
2. 任务内 `alloc` 只推自己的前沿，不碰共享状态；
3. join 时区域归还池子；
4. 一片用完时**回落到共享分配器**（加锁），而不是直接失败。

第 4 条是**资源等价**：一个顺序版装得下的程序，并行版也必须装得下。否则"同一输入"
下并行版先 OOM，就违反了 §3.2 的轨迹相等。回落的代价是那一段变慢，不是变错。

`gc_auto` 下 join 就是天然的**安全点**：所有任务停在这里，收集器可以跑。这是 §5 里
`gc_auto × par_auto` 那条划窄的**解**，也是 `par` 反过来欠 GC 的债（§7.1）。

### 3.6 不做非确定性

**没有 `par_loose`。** `par_auto` 是确定性的。想要非确定性的人有 `thread_spawn`
（`par_manual` 下原样可用，`docs/245`）。这是有意的拒绝：

- 非确定性不是"更快的并行"，它是**另一条轴**——同一输入的可观察轨迹变成一个集合；
- 一个把非确定性作为默认的语言，会让"并行化改变了行为"永远无法证伪；
- 这条拒绝也给 §2 的闭合主张减负：`par` 只承诺**一个**轨迹，不承诺一个集合。

## 4. 从程序到调度

### 4.1 足迹推断（整单元，不动函数签名）

推断是**整单元**的：从被调方到调用方做不动点，递归用不动点收敛。它**不写进函数签名**——
零注解。跨单元时：

- **源码库**（lompi 的 store、`deps/`、内置库）在单元内，足迹可见；
- **`extern fn`** 是 `opaque`：编译器只知道"它可能碰世界"，不知道碰哪；
- **链接进来的目标文件**同理。

这与 `docs/206` §2 的四条"不证"一致：借用不跨函数、没有字段级移动、移动集不分分支。
足迹推断**不假设**那些东西；它自己算，算不出的就是 `unknown`。

### 4.2 依赖图

每个候选站点建一张图 `G`。节点是迭代（静态界）或块（动态界）；边有四类：

| 边 | 含义 |
|---|---|
| flow | 写 → 读（真依赖） |
| anti | 读 → 写 |
| output | 写 → 写 |
| resource | 共享资源（分配器、审计格、锁、世界） |

边由 §3.3 的独立性逐一判。仿射下标（`a[i]`、`a[i + c]`）用整数线性判定；
非仿射、`unknown`、`opaque` 一律连成一条链——**链就是串行**。

这张图是 **DGT** 的用武之地：计划中的 `digraph<K>`（编译期图类值 + 静态验证，
`0.1.5.2`，伞 #1196）正好提供"节点 / 边 / 无环 / 拓扑序 / 割"这五个查询。
DGT 的最终形状若与计划不同，本设计退回到**内部图**，只要求同样五个查询；
产物里记的是图的摘要，不是图本身（大小与泄漏都不合适）。

### 4.3 三个判决

每个站点落到三档之一，并带一个**理由码**：

| 判决 | 含义 | 机制 |
|---|---|---|
| `p0` | 串行 | 链、`opaque`、越界、太短 |
| `p1` | 静态并行 | 编译期定任务数，静态 fork-join（S1 要求界已知；S2 起块范围可在运行期算） |
| `p2` | 动态/投机并行 | 运行期队列或投机（后者只在计划档） |

理由码是**稳定的词表**，不是随手的字符串（报告与判据都匹配它）：
`loop-carried` · `non-affine-index` · `unknown-place` · `opaque-call` · `world-effect` ·
`alloc-escapes` · `shared-alloc` · `guard-audit` · `atomic-shared` · `early-exit` ·
`fp-reduction` · `too-small` · `unknown-trip-count` · `nested-budget` · `manual-thread` ·
`no-runtime-mechanism`。

### 4.4 代价模型：只判"值不值得"

编译期用**静态量**估工：站点的工作量（IR 指令数 × 迭代数或块大小）与任务开销常量比较。
规则：

- **确定性**：不使用墙钟、不探测机器、不读环境。同一份源在同一版本下必须产出同一份
  IR 与同一份 `par_ladder`——这是逐字节孪生判据的前提。
- **宽度运行期定**：产物里带的是**策略**（编译期定几块、要不要队列），不是核数。
  程序启动时从环境读宽度。于是同一份产物在不同机器上都是可复现构建，
  而并行宽度随机器变——**宽度不是语义**。
- **`no_runtime` 下**宽度上限是一个编译期常量 `PAR_CHUNKS`（静态栈池的大小），
  不读环境。超出的站点落 `p0`，理由 `no-runtime-mechanism`，**明写**，不静默。

### 4.5 机制阶梯（维不命名机制）

`par_auto` 承诺的是语义，不是机制。机制有三阶，按能力往上长：

| 阶 | 机制 | 需要 | 产物记 |
|---|---|---|---|
| 1 | 静态 fork-join | 只复用 `thread_spawn` 那串机器码 + 静态栈池 | `p1` |
| 2 | 动态工作队列 / 工作窃取 | 一个运行期调度器 | `p2` |
| 3 | 投机（TLS）与回滚 | 计划的 `par_auto_alpha` | `p2` |

这一条是 **LLS §4.2 的直接后果**："取值只说有没有，不说哪一档。" 所以没有
`par_workstealing` 这种取值；机制是**实现**，阶是**产物里的数**。

缺哪一阶，不是冲突，是**少并几个站点**——而少并的每一个都在报告里说得出理由。
这是"零沉默"用在机制上。

### 4.6 代码形状

- **任务入口是编译器生成的函数**，恰好一个整数实参（块描述符的地址），
  与 `thread_spawn` 的入口同形（`docs/245` §3：入口是写死的调用边，不走间接调用）。
- **描述符**放在静态槽里；`no_runtime` 下栈从静态 `.bss` 池里切，**不碰堆**。
- **join 复用 `done` 那套**：原子计数 + `futex_wake`（`docs/245` §3 已经写好、已经逐字节钉住）。
- **结构化**：只有 fork-join 作用域，没有游离任务。join 是安全点（§3.5）。
- **纯 Loment 任务之间不走 C ABI**：内部调用约定由编译器拥有，可以传
  `(base, lo, hi)` 三元组，不需要把数组复制进任务，也不需要先把切片类型做出来
  （`docs/143` §7 里切片仍是"待定"）。

### 4.7 报告：零沉默的那一半

`--par-report` 按站点打印一行，确定性文本：

```
12:5  p0  loop-carried    out[i] 读 out[i-1]（距离 1）
18:5  p1  -               1024 次迭代，切 4 块
24:5  p0  guard-audit     guard disk 的审计格是共享写
```

报告不是诊断错误（程序仍然正确），所以它不是"编译失败"；它是**这条合同的账**。
词表固定，判据在语料上逐行钉住文本——否则"零沉默"会退化成"偶尔打印点什么"。

## 5. 开关：`par`

### 5.1 取值

| 维 | 取值 | 默认 | 选什么 |
|---|---|---|---|
| `par` | `par_manual` | **是** | 程序自己管并行（`thread_spawn`）；编译器**不加**任何并行 |
| | `par_auto` | | 保序全自动并行：证得出的并行，证不出的串行并给出理由 |
| | `par_auto_alpha` | | 计划的激进档：在 `par_auto` 之外允许投机与回滚（LLS §4.5） |

命名与 `gc` **同形**，这是有意的：`gc_manual` 是"程序自己管归还"，`par_manual` 是
"程序自己管并行"；`gc_auto` 与 `par_auto` 都是"语言接管，但语义不变"；
`alpha` 都是"激进的那一档，只有自动"。LLS §4.2 说取值说"有没有"不说"哪一档"，
`gc` 的档名是那条规则的**明写例外**（档是独立选择的）；`par` 照抄这个例外。

默认是 `par_manual`，因为 LLS §4.1 第 3 条：**默认档不许改变任何已存在的程序**。

### 5.2 冲突

按 `docs/274` 的形状，每条都要点名两个取值与理由：

| 对 | 类别 | 理由 | 什么时候能开 |
|---|---|---|---|
| `gc_auto` × `par_auto` | **划窄**（有实测成因） | `@__loment_maybe_collect` 在"起过线程"标志非零时**整个不跑**（`loment/selfhost/codegen.lomt:8072`，参考实现同形；标志在 `thread_spawn` 前被置 1，`codegen.lomt:3981`）。`par_auto` 起线程 ⇒ 自动回收静默停 ⇒ 与顺序版行为不同 | §3.5 的安全点：join 是天然停点。判据是"活集 N KB，`par_auto` 下照样收"，与 `docs/210` §2.6 那对程序同形 |
| `gc_auto_alpha` × `par_auto` | **划窄**（更长的路） | 同上，且 alpha 的回收靠"把分配前沿往回卷"，而并行任务各分配各的；共享前沿卷不得 | 每任务前沿 + 合并规则 + 卡表按任务分片；排在 S3 之后 |
| `par_auto` × `no_runtime` | **不冲突** | 机制第 1 阶只复用 `thread_spawn` 的机器码，不需要运行期；动态队列那一阶不可用，站点落 `p0` 并记 `no-runtime-mechanism` | — |
| `par_auto` × `no_std` | **不冲突** | 同上：核里已有 clone / futex / 栈 | — |
| `par_auto_alpha` × `hosted` | **不是维冲突，是站点规则** | 投机不能跨不可回滚的外部效果；每个 `extern` / `syscall` 是投机区的边界 | alpha 落地时写进站点规则 |
| `par_auto` × 同单元的 `thread_spawn` | **检查器规则**（新码） | 无 `join` 的无结构线程，其效果与之后的一切重叠；分析要么全串行、要么不健全 | 有 `thread_join` 或结构化作用域时 |

两条关于第三、四行的澄清，因为它们容易被误读成"漏了一条冲突"：

- **运行期不是 `par_auto` 的定义前提**。`thread_spawn` 已经证明"起线程"可以完全由编译器
  发机器码完成、不要运行期（`docs/245` §3）。`par_auto` 的第 1 阶走同一条路。
- **`no_std` 不是"没有线程"**。`thread_spawn` 今天就不受 `mode` 管；`par_auto` 同理。

### 5.3 目标限制

`par_auto` 在**没有线程原语的目标**上**点名拒绝**，不静默退化成"全串行"：

- PE/Windows：`thread_spawn` 已经是"响亮地拒绝并点名"（`docs/245` §3 的
  `test_pe_refuses_thread_spawn`）；`par_auto` 沿用同一形状。
- aarch64：后端会发射但从未在真机/模拟器上执行（LLS §5.3 已记）；在它有线程原语与
  一条执行判据之前，`par_auto` 拒绝。

这条与 `docs/274` §1 的"最坏一格"同一条纪律：**写得出、却什么也拿不到，比写不出来更坏。**

### 5.4 发行渠道

`par_auto_alpha` 是**计划值**，走 `docs/269` 给 `no_gc` 的那条路：先进 LLS §4.5，
渠道拒；等它有一条能跑的判据，再进 `CORE_DIMS`。`par_manual` 与 `par_auto` 从第一版起
就在核心表里。

`CORE_DIM_ORDER` 把 `par` **追加在末尾**（`lspe` 之后）。理由与 `lms` 当初一样：
两个实现比的是字节，错误文本里两个取值的先后由这个元组决定；追加在尾部不动任何既有配对的
先后（`tools/lomentc.py:1593`）。

## 6. 产物与判据

### 6.1 `par_ladder`

Potato 加两个字段（版本号随字段走，形状照 `docs/216` D4 的 `gc_ladder`）：

```
par        = "par_manual" | "par_auto" | "par_auto_alpha"
par_ladder = { p0, p1, p2, total_sites }
```

自洽式（两条校验器各自独立判得，v10 的 `MUTATORS_V10` 同形）：

1. `p0 + p1 + p2 == total_sites`；
2. `p2 > 0` ⇒ 该单元的 `runtime` 不是 `no_runtime`（第 2 阶需要调度器）。

`total_sites` 是单元里**候选站点**的数（S1 只数 `for` 循环；后续加块）。
默认档（不写 `choose`）的 **IR 逐字节不变**；Potato 多一个版本化的字段，
这是 `v9 → v10 → v11` 已有的形状，不是新例。

### 6.2 IR 标记与链接器

IR 多一行 `; loment-par: <value>`（不写标记 = `par_manual`，与 `; loment-mode` 的缺省
同义；所以默认档的 IR 一个字节不变）。两份链接器核：

| 声明 | 核什么 |
|---|---|
| `par_manual` | 产物里出现任务/调度器符号 ⇒ **点名拒** |
| `par_auto` 且 `p1 + p2 > 0` | 必须出现任务/调度器符号 |
| `par_auto` 且 `p1 + p2 == 0` | 不得出现（没有站点就不要背调度器） |

这与 `no_gc` 核 `@__loment_collect`、`no_std` 核宿主层是同一条"带牙检查"：
**编译器是那句话的作者，能核一份外来 IR 的只有链接器**（`docs/273` §3）。

### 6.3 判据（每条都要先在未修的实现上跑红）

| # | 判据 | 它证明什么 |
|---|---|---|
| 1 | `loment_par_test::test_loop_carried_is_p0` | 有链的循环**一个并行站点都不许有**（负例；图里必须看得见那条边，不能只靠"跑对了"） |
| 2 | `loment_par_test::test_independent_loop_is_equal` | `par_manual` 与 `par_auto` 的输出、退出码、世界效果次序逐项相同 |
| 3 | `loment_par_test::test_worker_count_is_observed` | 测试用运行期钩子数到 ≥2 个任务真的跑过（确定性的计数，不是墙钟比值） |
| 4 | `loment_elf_test::test_par_manual_carries_no_scheduler` | 两份链接器的带牙检查（§6.2） |
| 5 | `loment_choose_matrix_test::test_both_implementations_emit_the_same_ir_on_every_legal_par_cell` | 矩阵新增的格：两份实现逐字节一致 |
| 6 | `loment_par_test::test_guard_audit_survives_parallelism` | 并行循环里 N 次 `guard` ⇒ 审计表 == N（§3.1 的共享写） |
| 7 | `loment_par_test::test_trap_is_the_sequential_minimum` | 两个任务各自 trap，报的是顺序上最早的那一个（§3.4） |
| 8 | `loment_par_test::test_allocation_equivalence` | 顺序版装得下的活集，并行版也装得下（§3.5） |
| 9 | `loment_par_test::test_thread_spawn_is_refused_under_par_auto` | 同单元的无结构线程被点名拒（§5.2） |
| 10 | `loment_par_test::test_report_is_stable` | 报告文本在语料上逐行固定（零沉默不是"偶尔打印"） |
| 11 | `loment_choose_matrix_test::test_par_conflicts_name_both_values` | 两条冲突都点名两个取值、理由非空（`docs/274` §1 第 4 格） |
| 12 | `loment_par_test::test_the_axis_table_is_closed` | `CORE_DIM_ORDER` 等于八维的冻结元组，且 LLS §4 逐项相等；第九维只能走 §4.6 |

判据 1 是**关键的那条**：孪生判据只证明"一致"，不证明"对"（`docs/158` §4）。
一个把有依赖的循环并行掉的编译器，可能在测试输入上碰巧算对；只有"图里必须有那条边"
这条负例能证明它**保守在该保守的地方**。两条一起才够。

### 6.4 第一次落地的最小面

S1 只做**一种**循环形状：

- `for i in lo..hi`，界是**编译期常量**；运行期界在 S2 加，证不出下界的落 `p0`
  （`unknown-trip-count`，不猜）；
- 循环体无 `return`、无 `while`、无嵌套循环；
- 下标是仿射的（`a[i]`、`a[i + c]`）；
- 无 `alloc` / `free` / `str_concat`、无 `extern` / `syscall`、无 `guard`、无 `atomic_add`；
- 工作量过阈值。

它窄，但它**真的跑**：`p1 > 0`、产物里有任务函数、测试钩子数到多个任务、
输出与 `par_manual` 逐项相同。**不做"只声明、不生效"的一格**——`docs/274` §1 的
"最坏一格"就是 `vm` 当初的形状（`tools/lomentc.py:1558` 的注释原话），不重演。

## 7. 与其它一等公民的交互

### 7.1 `gc`：`par` 欠的那笔债

今天 `gc_auto` / `gc_auto_alpha` 与线程是**互斥的**：`maybe_collect` 见到线程标志就
整个不跑（`loment/selfhost/codegen.lomt:8072`），因为收集器没有 stop-the-world 协议。
`par_auto` 会起线程，所以：

- **S1/S2**：`gc_auto × par_auto` 划窄拒绝（§5.2），理由是实测的，不是猜的；
- **S3**：`par` 用结构化 join 提供**安全点**——任务边界上所有 mutator 都停着，
  收集器可以跑。这不是"顺手修 GC"，是 `par` 的语义本来就要求 join 是一个全局停点。
  这一阶的判据是"活集 N KB，`par_auto` 下照样收"，与 `docs/210` §2.6 那对程序同形；
- **S3 之后**：alpha 的"卷前沿"要改成每任务前沿 + 合并，才谈得上解禁。

注意这笔债的方向：不是 GC 欠并行，是**并行欠 GC 一个停点**。

### 7.2 `runtime` / `vm`

- `no_runtime`：只有机制第 1 阶；`p2` 恒为 0（§6.1 的第 2 条自洽式会抓住伪报）。
- `vm`：VM 必须实现同一份**可观察轨迹**（§3.2），包括 §3.4 的最小失败。`vm` 今天本身
  是"只声明"的一格，所以 `vm × par` 这一格**明写为待补**，不假装有。VM 真做时，
  矩阵必须加这一格——否则 `docs/274` §1 的"最坏一格"成立。

### 7.3 `lms`

- 每任务一片区域让"谁能碰"更容易证：任务的区域是它自己的，跨任务的写必须经过共享内存；
- `lms_crash` / `lms_reject` 是**语言级异常退出**，走 §3.4 的最小次序；
- `lms_reject` 的台账要按任务序号在 join 处**合并**，否则同一份程序的台账次序会随调度变
  ——那是可观察差异（§7.4）。

### 7.4 `lspe` 与 `guard` 审计

`guard` 的审计格是共享写（§3.1）。`par_auto` 的解法不是原子加，而是**每任务一本分账**，
join 时按任务序号合并：

- 计数是整数加，结合、交换、精确 ⇒ S2（"审计条目数 = 通过次数"）原样成立；
- 台账的**次序**由任务序号定，所以与顺序版一致；这是 `lspe` 能接受并行而不改语义的原因；
- 代价是 join 时一次合并，不是每次 `guard` 一条原子指令。

若不做分账，含 `guard` 的循环就是 `p0`，理由 `guard-audit`——**说出来，而不是悄悄串行**。

### 7.5 `port` / `extern`

`extern` 是 `opaque`：它的效果是 `world(*)`，与一切相交。于是：

- 循环体里的 `extern` 把循环切成串行段（或整段 `p0`）；
- `par_auto_alpha` 的投机**不能跨** `extern` / `syscall`：不可回滚的效果没有 rollback；
- 这不是缺陷，是零注解的价：没有注解，编译器就没有办法知道"C 函数是纯的"。

### 7.6 多语法前端

`par` **不加关键字**，只加一个 `choose` 取值。六个表层语法（`docs/188`）都只是拼写，
`choose par_auto` 是 L1 文本，前端不需要知道它——语义在检查器与代码生成里。
这是零注解买到的额外好处：**没有语法构造，就没有"每个读 L1 源的入口都要各学一遍"的账**。
若 VS Code 扩展对 `choose` 取值有补全，补一格；没有就不为一个值造入口。

### 7.7 库

库不写 `choose`（`docs/143` §3.2）。库能做的是**暴露自己的足迹**：被推断出来的
`Φ` 就是它的"我要什么"；根单元写 `par_auto` 是"这个项目给什么"。
一个内部含 `thread_spawn` 的库是 **par 敌对**的：整个单元落 `par_manual`，或在
`par_auto` 下被点名拒（§5.2）。这条让生态有一个明确的信号：**要自动并行，就别藏无结构线程。**

## 8. 代价与不做的事

**明写的代价**：

- 指针重的代码会大量落 `p0`。这是系统语言的价：`docs/206` 已经把"证到哪儿为止"写下来了，
  这里不假装证得更多。
- 编译期成本：整单元不动点 + 逐站点建图。自举侧要新开一个 `par.lomt` 模块，不要往
  `codegen.lomt` 里塞——那棵树有固定容量（SLOT / 标签表），越界是段错误不是报错；
  种子要按 `docs/159` / `docs/176` 重生成，机械产物单独一条提交。
- 代码体积：每个并行站点多一个任务函数与一块静态描述符；`no_runtime` 下还有静态栈池。
  `p1` 的站点数由产物钉着，涨了看得见。
- 矩阵：`par` 的合法格乘进门禁，孪生逐字节的墙钟要重新量（§2.4）。
- 报告文本是新的稳定面：它进判据，就也会被用户脚本匹配，改词表要当冻面改。

**明确不做**：

| 不做 | 为什么 |
|---|---|
| 承诺加速 | §1.2；并行 ≠ 更快，承诺了就是假话 |
| 并行 FP 归约 | 浮点加法不结合；顺序版与树形版结果不同。`fp-reduction` 是一个**理由码**，不是缺陷 |
| 跨 `extern` / `syscall` 并行 | `opaque`，且投机不可回滚（§7.5） |
| 非确定性 | §3.6；要它请走 `thread_spawn` |
| SIMD / GPU | 任务级并行是这一维；指令级是后端的另一件事，不改语义 |
| 分布式 | 它是 `权 + 时` 的组合（§2.3），该是库或另一条线，不是第九维 |
| `async`/`await` | 那是一种**手写**的调度约定；与零注解相斥 |
| 运行期竞争检测器 | 竞争在静态被排除；检测器是抽样，不是合同 |

## 9. 分阶段

每一阶都必须有**可跑的行为差或产物差**，不许有"只声明"的阶。

| 阶 | 内容 | 出口判据 |
|---|---|---|
| **S1** | `par` 维 + 足迹推断 + 依赖图 + 报告 + 静态 fork-join；只做 §6.4 那一种循环 | 判据 1–5、9–11 绿；`par_auto` 的产物有任务函数且输出相等 |
| **S2** | 整数归约、嵌套、运行期界、工作窃取（机制第 2 阶）；`PAR_CHUNKS` 让位给运行期宽度 | 判据 2–3 在归约与动态界上绿；`p2 > 0` 的产物带调度器 |
| **S3** | 每任务区域 + 安全点；解禁 `gc_auto × par_auto`；审计分账合并；分配等价 | 判据 6、8 绿；`docs/210` §2.6 那对程序的并行版通过 |
| **S4** | `par_auto_alpha`（计划值）：投机 + 回滚；`extern`/`syscall` 为边界 | LLS §4.5 的登记 + 渠道拒 + 一条回滚判据；没有就不进核心表 |
| **S5** | 关闭轴：LLS §4.6、`docs/274` 的联动行、矩阵补格、闭合判据 | `CORE_DIM_ORDER` 与 LLS 的表逐项相等；第九维的提案必须交 §2.3 的那对程序 |

## 10. 未决

1. **代价阈值**。`too-small` 的界是一个启发式；它必须确定、可复现，但多少才值？
   先用一个保守常量，S2 用一组合成程序族量它，不拿墙钟比值当门禁。
2. **失败的最小次序**在最坏情况下要等低序号任务跑完。可接受吗？先按"正确优先"，
   S2 再量它的上限。
3. **`guard` 分账与 `lspe` 台账的"来源"**：合并后的台账是否仍满足 `docs/262` 对来源链的
   要求？要读 `docs/262` 的字段定义再定，不能凭"整数加没问题"就下结论。
4. **`lms_crash` 与并行**：崩溃器是"退出进程"，最小次序规则要求先等低序号任务；
   两者如何共存，S3 再定。
5. **指针足迹的精度**：逃逸分析做到什么程度？S1 只做"同一函数内 `alloc` 且不逃逸"，
   其余 `unknown`。再往上要一整条分析，不能顺手加。
6. **`PAR_CHUNKS` 的默认值**：`no_runtime` 下没有环境可读；默认几块？
   这是机制参数，不是语义，但要有判据钉住它不漂。
7. **DGT 的最终形状**：五个查询（节点/边/无环/拓扑/割）够不够？若 DGT 最终不是
   `digraph<K>`，内部图要独立成一条判据。
8. **PE / aarch64 的线程原语**：没有它，`par_auto` 在那两个目标上是拒绝，不是退化。

## 附录 A · 四个例子

**A.1 独立（`p1`）**

```rust
fn scale(a: [i64; 1024], k: i64) -> [i64; 1024] {
    let out: [i64; 1024] = a;
    for i in 0..1024 {
        out[i] = a[i] * k;
    }
    return out;
}
```

读 `a[i]`、写 `out[i]`，两个下标都是 `i`；不同迭代的位置不相交；无分配、无外部调用。
图无跨迭代边 ⇒ `p1`。

**A.2 链（`p0`，`loop-carried`）**

```rust
fn prefix(a: [i64; 1024]) -> [i64; 1024] {
    let out: [i64; 1024] = a;
    for i in 1..1024 {
        out[i] = out[i - 1] + 1;
    }
    return out;
}
```

`out[i - 1]` 读的是上一迭代写的格 ⇒ flow 边（距离 1）⇒ 链 ⇒ `p0`。
报告必须打出这条边；只靠"跑出来对了"不算证过。

**A.3 归约（整数 `p1`，浮点 `p0`）**

```rust
fn total(a: [i64; 1024]) -> i64 {
    let s: i64 = 0;
    for i in 0..1024 {
        s = s + a[i];
    }
    return s;
}
```

`+` 在 `i64` 上（按模 2^64 回绕）结合且交换 ⇒ 树形归约，`p1`。
换成 `f64` 就是 `p0`，理由 `fp-reduction`：浮点加法不结合，树形与顺序结果不同。

**A.4 审计（`p0` 直到分账）**

```rust
fn audited(a: [i64; 1024]) -> [i64; 1024] {
    let out: [i64; 1024] = a;
    for i in 0..1024 {
        guard disk(i % 4);
        out[i] = a[i];
    }
    return out;
}
```

`guard` 写 `__LOMENT_AUDIT[disk]`（§3.1）；每迭代都写同一格 ⇒ 共享写 ⇒
S1/S2 为 `p0`（`guard-audit`）；S3 分账合并后为 `p1`，且审计计数仍等于通过次数。
