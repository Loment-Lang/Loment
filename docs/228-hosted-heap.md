## 0. 先说这一步**不是**什么

`docs/225` 的口径纠正是：Loment 的运行期与 Java 的不是一类东西，比完之后真正没人在做的
**只剩三处**。**S1e 不在那三处里** —— 它是**每个语言都有、只有 freestanding 的没有**的那一项。
所以这一篇不产生独特性，它把一项欠账还上，好让 `docs/219` §8b 里 S1d→S2（zlib）那条线往前走。

同时它**不是**"把 65536 改大一点"。下面 §1 说明为什么。

---

## 1. 现状：64 KiB 不是"一个配置项"，是**五处各自写死的假设**

| 处 | 行 | 形状 |
|---|---|---|
| arena 本体 | `:282` | `@__loment_heap = internal global [65536 x i8] zeroinitializer` |
| 前沿容量 | `:218` | `%fits = icmp ule i32 %nxtoff, 65536` |
| `free` 反算基址 | `:237` | `%base = ptrtoint ptr @__loment_heap to i64` |
| 收集器的**标记表** | `:4971` | `@__loment_mark = internal global [8192 x i32]` —— 而 **8192 = 65536 / 8**，按块头`偏移 >> 3` 索引（**`docs/231` 之后它是 `[1024 x i8]` 的位图，口径未变**） |
| 收集器的**根扫边界** | `:5043` `:5086` | `icmp ult i64 %rdo, 65536` / `%wdo` |

要害在第四行：**标记表的行数与它的索引口径里，写着 arena 的大小**。所以"把 64 KiB 改成
1 MiB"不是改一个常量，而是**同时**改表的口径 —— 那一步在 §4 的 B1，不在这里。

第三行是第二个要害：`free` 拿不到 `%p` 属于哪个 arena，它靠 `ptrtoint - 基址`**反算偏移**。
只要 arena 仍是**一段连续内存**，这条就照旧；一旦多段（§4 的 B2），它就得换成指针或
`(段, 偏移)`——那时改的是**地基**。**A 不动地基**。

## 2. 闸门：为什么挂 `choose hosted`，而不是"所有程序"

`docs/219` §6.1 已经把 `hosted` 定义成"往下链宿主的库"（`docs/222` §4.4），把 `sealed`
定义成"底下没有东西"。于是：

- **`sealed`**（默认）承诺的是"这份产物**不依赖外面**"。而一次 `mmap`/`malloc` 是
  **运行期**对外面的依赖 —— 它比"链接期依赖一个 .so"更弱不了。给它加 OS 那一步，
  等于把 `sealed` 的定义改掉。
- **`hosted`** 说的本来就是"往外链"。`loment_hosted_test` 那条判据链的是**真的 `libz.so`**
  （`tools/loment_hosted_test.py:390`）—— 这一档的产物**从来就不封闭**。

⇒ 闸门不是"一个性能选项"，它是**那条保证的一部分**：`sealed` 的继续逐字节不变，
`hosted` 的才往外要。`docs/219` §8b S1e 原文写的是"前沿从 64 KiB 静态数组换成 `brk`/`mmap`"
（**所有**程序），没有闸门；**加闸门是这一步与那一行原文的差**，理由就是上面这一条。

## 3. A 的形状

### 3.1 要谁

**`malloc`**，不是 `brk`/`mmap`。两条理由：

1. **可移植**：`brk` 与 `VirtualAlloc` 是**两份平台代码 + 一张平台表**；而 `malloc` 在
   ELF 与 PE 两侧都在（`docs/221` 那条 PE 线）。`hosted` 的产物本来就是 C 工具链链出来的
   （`loment_hosted_test.py:9` 那三处注释里 ③ 明写"按 sealed 链 lomelf 就全错"）。
2. **不留内核面**：raw syscall 要把 syscall 号写进产物 —— 那是在 `sealed` 之外**又开一张
   平台表**，与 `docs/219` §5「端口表」那套记账面重复。宿主已经有一个分配器，用它。

⇒ S1e 原文的 "`brk`/`mmap`" 是**未加闸门**那一版的形状（`sealed` 没有宿主，只能自己发
syscall）。加了 `hosted` 闸门之后，"OS 那一层"的正确接口**就是宿主的分配器**。这一条差异
写在这里，免得以后有人拿行号说"你和文档不一致"。

### 3.2 形状

- `@__loment_heap` 从 `[65536 x i8]` 变成 **`ptr`（基址）**；
- 新增 `@__loment_arena()` —— **惰性**、只问一次（`malloc` 返回空就落 `__loment_abort`）；
- 每个用到 arena 的函数在入口处 `%hb = call ptr @__loment_arena()`，之后所有
  `getelementptr [65536 x i8], ptr @__loment_heap, i32 0, i32 %X`
  → `getelementptr i8, ptr %hb, i32 %X`；
- `free` 的 `ptrtoint ptr @__loment_heap` → `ptrtoint ptr %hb`；
- 前沿容量：`icmp ule i32 %nxtoff, %N`（`%N` = 编译期常量）。
- **偏移模型一个字节都没动**：空闲链表的 `next` 仍是 i32 偏移、前沿回退仍是前沿回退、
  拆分仍是拆分。换掉的只有"arena 从哪来"与"它有多大"。

### 3.3 大小与它写在哪

arena 大小是**编译期常量** `1048576`（1 MiB），**并写进产物**：

```
; loment-heap: platform 1048576
```

原因与 `; loment-port: hosted`（`:6990`）同一条：**构建那一侧要知道这件事，而它不该去读源码**
（读源码要它懂 Loment 的词法；IR 本来就是构建的输入）。而且它让 §5 的 A2/A5 两条判据
落在**字节**上，不落在"我们觉得它应该会"上。

### 3.4 不静默

`hosted` + `gc_auto` 落在 §4 的 B1（仍是静态 64 KiB）。**它不发 `platform`，发
`; loment-heap: static 65536`** —— 于是"这一份没吃到 A"是被**量出来**的，不是被默认掉的
（`docs/205` §0.2 那条"零沉默"）。`hosted` + `gc_auto_alpha` 走不到这里：它早就被
`CORE_CONFLICTS` 点名拒了（`:1246`）。

## 7. `hosted` × GC / LMS 的判决表（`#1025`）

`port: hosted` 把 arena 从静态 64 KiB 换成宿主的 `malloc` 一块。GC 与 LMS 原来都假设
"arena 是我们的"，所以每一对要给出**判决**：合法、划窄（narrowing），还是矛盾。
理由挂在**需求**上，不挂在"这一对看着不顺眼"上。

| 对 | 判决 | 需求 / 理由 | 开出的条件 |
|---|---|---|---|
| `hosted` × `gc_manual` | **合法** | 分配器与 free 链都在 arena 里；宿主只提供一块内存 | —— |
| `hosted` × `gc_auto` | **合法** | 标记-清扫**不搬移**；根表按 arena 偏移索引，已在 `docs/230` 换成平台 arena | —— |
| `hosted` × `gc_auto_alpha` | **划窄** | L2 是**前沿回卷**，而外部库把指针放进它自己的结构（`z_stream`），那些指针在 Loment 的栈之外 | **一个不回卷前沿的 L2** —— 今天没有这一档，所以先划窄 |
| `hosted` × LMS g1 | **合法** | 界来自 `alloc(<编译期常量>)`，在平台 arena 上仍是那个常量；检查照发 | —— |

**g1 在 hosted 上的意思**：**同一套检查，界还是那个常量**。它不因为 arena 来自 `malloc`
而失效 —— 失效的是"L0 静态提升"（没有静态 buffer 可提），不是界本身。判据
`loment_choose_matrix_test::test_hosted_and_lms_compose` 真链真跑一份越界写 + 越界读的
hosted 产物：拒绝器把两条跳过、界内那一半算出 1。

**判据**：`loment_choose_matrix_test::test_hosted_and_lms_compose`（g1 照发、越界被拒）、
`test_every_legal_hosted_cell_runs`（`gc_manual` / `gc_auto` × lms 开/关四格**真链真跑**）、
`test_conflicting_pairs_are_refused_with_the_pair_named`（`gc_auto_alpha × hosted` 的
诊断必须写成**划窄**并说出"不回卷前沿的 L2"这个开出条件）。

**资源归属**：arena 是**一块** `malloc`，Loment 的 `free` 是这块**里面**的空闲链；宿主的
`malloc` 是**另一个**分配器。两者对 arena 的字节不会各说各话（Loment 从不把整块还回去，
进程退出由 OS 收）。宿主库自己 `malloc` 出来的内存**在 arena 之外**，GC 与 LMS 都看不见
它 —— 那是宿主的账，不是 Loment 的。
